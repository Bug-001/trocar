# Release notes — 2026-10-09

## Engines decrypt connections to IP-literal upstreams (every platform)

**What changed.** The collector's engine used to verify the upstream's certificate against
Node's own default hostname ('localhost') whenever the agent's connection carried no SNI —
and no client sends SNI to an IP address (RFC 6066: the extension is DNS names only). An
agent pointed at a relay by its bare IP therefore never got decrypted: every call was
forwarded untouched and the flow row said `upstream-cert` / `ERR_TLS_CERT_ALTNAME_INVALID`
whatever the certificate. The engine now verifies against the real host of the connection —
the SNI when the client sent one, the destination address otherwise — so an IP-literal
upstream with a matching certificate (IP SAN) is decrypted and recorded like any other.
No settings change; nothing new appears on the board except the calls that used to be
labelled `upstream-cert` now being captured.

**Why.** Found live by the macOS collector's smoke run (RFC 4.9's acceptance), where the
mock upstream is an IP literal by necessity; the same gap was latent on every platform.

## The macOS collector exists (proxy mode) — not yet switched on

**What changed (for the curious; nothing ships to `on`/`off` yet).** `src/collector/arch/darwin/**`
now implements the macOS half of the per-process collector (RFC 4.9): a per-user daemon
(LaunchAgent, no root, no helper process), asight's own pinned mihomo kernel each agent's
proxy entry points at, the same engine and records as Linux and Windows. The smoke run on
the macOS test machine is green end to end — the real daemon, the real pinned kernel, real Claude Code
and Codex captured through it (decrypted rows with pids from the socket table, marker-verbatim
bodies (the full byte-identity cell is MA3's deferred seven-harness one), the system-proxy follow, kill -9 of either half recovering, byte-identical `off`).
`asight on`/`off` on macOS still drive the old capture until the remaining acceptance
cells (the seven-harness end-to-end among them) pass and the switch is flipped.

**Why.** D31/D43: capture recognises agent processes, never touches the system proxy or
the machine's traffic; the flip checklist is in RFC 4.9 §4.
