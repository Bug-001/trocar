# 2026-11-11

## Hermes

- **A Hermes certificate setting written with a variable is read the way Hermes reads it.** A provider's `ssl_ca_cert`
  in Hermes's `config.yaml` may be written as `${NAME}` or `${env:NAME}`, and Hermes takes NAME from its `.env` files
  as well as from the environment it starts with. trocar read only that environment and only `${NAME}`. So a NAME set in
  `~/.hermes/.env` was missed: `install` did not add trocar's certificate to the file it names, and trocar read the
  connection, which Hermes then refused. trocar now also reads `~/.hermes/.env` and the `.env` in
  `$HERMES_MANAGED_DIR`, each over the environment as Hermes loads them. A NAME set only where trocar does not look
  makes trocar pass that connection on without reading it, and say which variable it could not see.

## Replay

- **An open session with nothing new no longer fills the browser console with errors.** Each refresh of a session still being written asked for the bytes past what the board held, and the server's "nothing past the end" answer was logged by the browser as a failed request, twice every 1.5 s. The board now asks from its last held byte, so a quiet refresh is an ordinary answer; real read failures still show.
- **A session whose first read has not reached its steps shows how many model calls it has, and no longer says it has only the main thread.** Before its steps are read, the replay desk showed an empty strip where the step number goes and, under the tracks, "This session has only the main thread", which it could not know yet. It now shows the call total there and leaves the track row empty until the session's threads are read.
- **After trocar's reader restarts, a session you opened before opens from its saved answer.** While a restarted
  reader re-indexed, it answered such a session as "re-indexing", wrote that over the saved answer, and rebuilt it
  once the re-index ended. Now the saved answer stands: on a session of 8,000 model calls the first answer came in
  about 1 s instead of 2.6 s.
- **A session trocar stopped reading for lack of memory is not retried on every refresh.** Each refresh and each
  follow started the read again, and it stopped again. It now waits until there is room; a session you open is read
  as soon as there is.

## Off

- **`trocar off` says a file you put back by hand is as it was.** When trocar wrote into one file in more than one
  command (Claude Code's settings get install's certificate key and then `on`'s proxy keys; or `on` ran twice) and you
  put the file back to how it was before those writes, `off` judged the later writes as changed: it kept their backups,
  and a row said trocar's text was no longer in the file. Every such entry now counts as already undone, and the
  backups that held only trocar's own bytes are removed. A backup that holds an edit you made between trocar's writes is
  still kept.

## Install

- **`trocar install` says a plug-in or a setting it found already in place is intact.** Run again, install leaves alone a
  file that already holds what it would write; it changed no byte, but its receipt said "trocar's plug-in, placed"
  for DeepSeek dsh and pi (and the same for a config key), as if it had written them again. Those now say intact, as
  Kimi's launch command already did; a carrier is placed only when install wrote one of its parts.
- **The one-line install in the README pastes into zsh.** It ended in a `# macOS, Linux` comment, which zsh (the
  macOS shell) passes on to `sh` unless interactive comments are on, so the pasted line failed with
  `sh: #: No such file or directory`. The README's shell lines carry no comments now; installing, the board, what
  trocar captures, every command and the license each have a page under `docs/`.
- **`trocar install` and `trocar update` run from a shell without your CA variable keep the private CA.** Z-Code's
  merged certificate bundle, the login entry that starts trocar's daemon, and Claude Code's certificate setting (when
  `CLAUDE_CODE_CERT_STORE=bundled`) were written from the shell you ran them in. Without `NODE_EXTRA_CA_CERTS` (or
  `ZCODE_AGENT_CA_CERT`) set there, they lost the CA it named: Z-Code's and Claude Code's requests failed their
  certificate check, and the daemon no longer trusted a company relay. On Linux the same held for a certificate file
  install placed again, and for a value only a running agent had. Install now remembers each such variable it saw;
  a shell that does not set it keeps that file while it is there, a value you set replaces it, and an empty one
  removes it. On an install from 0.2.x, the first update still reads only its own shell.

## Windows

- **trocar no longer takes a replaced file for the one it had open.** An NTFS file id can be larger than a JavaScript number holds
  exactly, so a file and the one saved over it could look like the same file. trocar now compares the exact id. If the file it
  writes captures to is replaced, it opens the new file and records that, instead of writing into the old one. The index, the
  sealed-file readers and the settings it watches also notice a file replaced by another.
