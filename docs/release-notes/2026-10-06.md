# Release notes — 2026-10-06

## Collector captures on the board

**What changed.** With no `--source`, `asight serve` now also reads the per-user process collector's
`~/.asight/collector/capture-<date>.ndjson` (only when that directory exists). The collector's
`flows/`, `audit/` and `replays/` subdirectories are not envelopes and are never shown.
`asight etl <dir>` now accepts a directory: it ingests the directory's top-level `*.ndjson` in name
order in one run, and each call's `raw_ref` names the file that call was read from.

**Why.** The collector writes one capture file per day under `~/.asight/collector/` (RFC 4.6 §记录),
and the board's default roots never reached it, so Claude Code traffic captured by the collector
never appeared on the board (spec 4.4:129).

**Impact.** Run `asight serve` with no arguments to see collector-captured Claude Code sessions next
to the older captures. Run `asight etl ~/.asight/collector` to load them into DuckDB. Existing
single-file `asight etl <ndjson>` runs are unchanged.

**Known limits.**
- The board resolves block bodies from an index built when `asight serve` starts. A call captured
  after that is listed, but its block bodies do not open until the board restarts. A collector
  directory created after the board started becomes a root at the next restart.
- An incremental `asight etl <dir>` (without `--rebuild`) can skip a call whose request started
  before midnight UTC and was written after a later call of the same session had already been
  ingested. Re-running with `--rebuild` recomputes it correctly, but `--rebuild` clears the whole
  database first, so re-run it for every source that shares that database.
