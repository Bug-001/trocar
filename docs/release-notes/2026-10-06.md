# Release notes — 2026-10-06

## Per-user process collector: six more agents and autostart

**What changed.** `asight collector install` now also writes the trust entries of OpenCode (a plugin), DeepSeek
`dsh` (a plugin and a sentinel row in its patch file), Kimi Code (a launch shim and one sentinel `PATH` line in your
shell rc), Hermes and Codex (a sentinel block atop their `.env`) and Z-Code (`network.caCertFile`); agents whose entry
replaces their trusted roots get a per-agent combined bundle that keeps the CAs they already used. Install lists every
file first, including a per-user systemd unit, which it enables `--now`; the unit carries the `NODE_EXTRA_CA_CERTS` of
the install shell so the daemon can verify a relay with a private CA. `status` names, for each running agent it does
not decrypt, why and what to do; every failure, every install note and every agent still trusting the collector CA (except under `--purge-data`)
after uninstall leaves a line in `flows/`.

**Impact.** Agents started before install stay untrusted until restarted (Kimi: until started as `kimi` from a new
shell). Codex is wired but not yet run end to end (it waits for the WebSocket recorder). `--no-unit` keeps the old
start-it-yourself behaviour.

## Collector captures on the board

**What changed.** With no `--source`, `asight serve` now also reads the per-user process collector's
`~/.asight/collector/capture-<date>.ndjson` (only when that directory exists). The collector's
`flows/`, `audit/` and `replays/` subdirectories are not envelopes and are never shown.
`asight etl <dir>` now accepts a directory: it ingests the directory's top-level `*.ndjson` in name
order in one run, and each call's `raw_ref` names the file that call was read from.

**Why.** The collector writes one capture file per day under `~/.asight/collector/` (RFC 4.6 §记录),
and the board's default roots never reached it, so Claude Code traffic captured by the collector
never appeared on the board (spec 4.4:129).

**Impact.** Run `asight serve` with no arguments to see collector-captured Claude Code sessions next
to the older captures. Run `asight etl ~/.asight/collector` to load them into DuckDB. Existing
single-file `asight etl <ndjson>` runs are unchanged.

The collector now picks the daily file by the UTC date at which it writes the envelope, not by the
request's start time (`ts` is still recorded). A call that starts before midnight and ends after it
goes into the new day's file, so, barring a clock step back, an earlier day's file never grows after
a later one exists, and an incremental `asight etl <dir>` matches a full rebuild across midnight. For a directory where an
earlier file can still grow (such as `~/.asight`, with several captures), an incremental run that
would have to skip a record refuses instead and asks for `--rebuild`.

A running board follows a live capture: a call captured after `asight serve` started opens with its
exact bytes. When a block is not in its index, the board indexes only what was appended since it
last looked, then answers.

**Known limit.** A collector directory created after the board started becomes a root at the next
restart.

## Symlinked capture files show on the board

**What changed.** A `*.ndjson` capture in a source directory that is a symlink to a file (on some
machines `~/.asight/codex-capture.ndjson` links to `~/.atrace/codex-capture.ndjson`) is now listed on the
board, the same as a regular file. A file reached from two roots (a link in one, its target in
another) is read once. The board, the block resolver and `asight etl <dir>` follow one rule. A link
that points nowhere is not a capture file: it is skipped (the resolver notes it as `broken-symlink`
in its internal scan, which nothing displays yet) instead of failing every capture in that
directory.

**Why.** The board's file scan used `isFile()`, which is false for a symlink, so the sessions in a
linked capture never appeared, while the block resolver did read it.

**Impact.** Sessions from a linked capture (such as Codex captured by the old relay tee) appear after
upgrading; nothing to do.

## The board and `asight etl` say what they did not read

**What changed.** When a file in a capture source is not read, the board now shows it in a line next
to the session list, with the reason. Examples: a link that points nowhere, a compressed file, a
`*.ndjson` that is not a regular file, or a session folder with no `meta.json`. Each file's count of
lines that do not parse is shown too. Other entries (config files, the CA, folders) are counted on
that line and listed when you hover over it. `asight etl <dir>` prints the same list to stderr.

**Why.** These entries used to be dropped without a word, so a broken or compressed capture looked
like no capture at all (RFC 4.4:83).

If the session list itself cannot be read (for example a capture directory the server may not list),
the board now shows the server's reason instead of "No sessions captured yet". A single capture file
it may not open is listed as not read, and the other sessions still show.

A running board no longer loses a call it happens to read while the collector is still writing it.
Before, that call was counted as a bad line and never shown; now the board says a file ends in an
incomplete line and shows the call once the line is whole. A last record that is complete but has no
trailing newline is shown as well.

**Impact.** If the line appears, the files on disk are untouched; it names what to check. Nothing to
do otherwise.

## The board says why a captured request is incomplete

A request the collector stored only in part now says why on the board, instead of showing an empty context. The board reads the labels the collector has written since #21:
- 「请求体已截断」: the body was cut at the 64 MiB capture cap, and only its first N bytes are stored.
- 「请求体不完整」: the capture did not get the whole body. Either it never finished uploading (the upstream answered first, e.g. 413 / 401, or the connection was aborted), or the collector lost the request's HTTP framing and stopped storing it (the rest may still have reached the upstream).

The reason appears in the raw panel and at the top of the context window, including for a call whose body is not loaded on the current page. A call whose stored prefix cannot be parsed shows a notice with that reason. Before, it drew an empty window, which read as "the model saw nothing". Captures without these labels (v0, legacy MITM) keep the old "truncated / corrupt capture" wording.

## 看板按进程认 harness,按各 harness 自己的键分 session(D37)

- **改了什么**:新增读取侧 harness 表 `src/dissect/harnesses.mjs`(七个 harness 的 session 键、lane / 父 / 压缩提示、观测者效应)。看板的 harness 改取自记录的 `proc.agent`;只有没有 `proc` 的旧记录才按 User-Agent 推断,agent chip 上标「· 推断自 UA」。session 按各 harness 自己的键分组(dsh、Z-Code、OpenCode、Kimi、Hermes 的键第一次被认出),从不按 pid 或连接分。限于扁平源:分片源仍只按 Claude Code 的头分文件;Kimi / Hermes 没有键的调用仍归控制面。
- **为什么**:D37 要求三条轴(harness / 线格式 / 厂商)分开认,harness 不能由 UA 臆断;观测者效应要能按 harness 标出来,这张表是第一步(写进 DuckDB、在看板标注随后跟上)。
- **对你的影响**:旧抓包里 Claude Code 的 harness 值从 `claude-code` 变成 3.2 的 id `cc`,chip 显示不变,只多了「· 推断自 UA」。D37 之前生成的 `meta.json` 同样显示为推断。

## Per-user process collector: Claude Code on Linux

**What changed.** New commands: `sudo asight setup-helper` installs the capability helper once per
machine; `asight collector install | start | on | off | status | uninstall` run as the user. Install
first lists every file it will change (a symbolic link as link → target), then mints a collector CA
under `~/.asight/collector/ca/` (in no trust store), sets Claude Code's
`env.NODE_EXTRA_CA_CERTS` in `~/.claude/settings.json`, and records every change in
`~/.asight/collector/install-manifest.json`. If you already gave Claude Code a CA (in the install
shell, a running Claude Code, `~/.claude.json`, settings or managed settings), the key points at
`~/.asight/collector/ca/extra-cc.pem` instead: your CA's certificate blocks plus the collector CA,
never a private key. `start` runs the daemon; `on` steers the connections of trusted Claude Code
processes to it and records them as `capture-<date>.ndjson`, which `asight serve` shows.

**Why.** RFC 4.6 (D31, D36, D37④): capture by process, with no system proxy, base URL or VPN change,
and trust given to the agent alone, never to the login environment.

**Impact.** Linux only. asight does not count on a Claude Code process that was running before install
picking up the new `NODE_EXTRA_CA_CERTS` (a test-machine check saw `claude -p` do so; the other modes are
unverified), so `status` lists it as untrusted (`config-after-start`, with a hint to restart it) and its
connections go direct, unrecorded, until it is restarted. A process whose start time cannot be read is
treated the same way (`start-time-unknown`). The
daemon verifies upstreams with Node's default store, so a relay with a private CA needs the same
`NODE_EXTRA_CA_CERTS` in the environment that starts the daemon. `asight collector uninstall` puts
the settings file back key by key (byte-identical when you have not edited it since), removes the CA,
and keeps captures unless `--purge-data`.

Capture failures are never silent: every failure the collector owns — install and uninstall steps,
helper and engine errors, heartbeats, attach, envelope writes, agents judged untrusted — leaves a line
with its reason in `~/.asight/collector/flows/` (deleted with the captures by `--purge-data`), and
`asight collector status` prints the recent ones, from disk when the daemon is not running. An install
refused before it wrote anything (nothing installed yet, or run as root) has no collector directory to
write into: the command's output is its only report.

**Known limits.**
- (Superseded above: install now enables a systemd user unit.) A helper that dies is not restarted; `status`
  says why, `on` fails, and connections go direct until the daemon restarts.
- The engine port is chosen at install. If another program holds it later, `start` refuses and
  nothing is steered; uninstall and install again to pick a new port.
- (Superseded above: six more agents are wired; Codex's end-to-end run follows.)
- `install` replaces L-07's `installUser` / `uninstallUser` and its placeholder systemd unit
  (`ExecStart=/usr/bin/false`), which are gone.

## Collector failures are on disk, with a closed code (D38)

**What changed.** Every collector failure is now a `flows/` event line `{ts, event, where, code, reason}`
whose names come from one closed set (`src/health/codes.mjs`); the engine's and the WebSocket recorder's
failures moved there from the separate `failures/` directory, which is gone. New records: the daemon's
own start and stop (`daemon-start` / `daemon-stop`, with the signal — SIGHUP and SIGQUIT now stop it
cleanly), a crash, a lost record (`log-gap`), an unusable CA (`ca-invalid`, checked at start and daily:
the daemon then never steers and says "CA unusable", not "not installed"), agents becoming trusted or
exiting, a process two harnesses claim, negative-cache entries, a helper that does not answer
(`loader-timeout`, 2 s) or exits (its exit reason and last stderr lines), and — every 5 s, without anyone
running `status` — links lost behind the daemon's back (`state-mismatch`), connections the kernel let go
direct by reason (`kernel-drops`), and a trusted agent whose trust file changed (judged again). A Claude
Code settings file that cannot be read or does not parse is named as such instead of reading as "no
settings". Install reports every block of your CA file it did not carry over (by type and position) and
writes its notes as `install-note` events; uninstall writes `uninstall-note` events, and when it cannot
undo something it exits 1 and keeps the install manifest. `asight collector status` judges the daemon
from its lock (pid, start time, boot id, refreshed every second): running, not running, or stuck.

**Why.** D38 : a capture failure must leave a record and be visible; RFC 4.6 §记录.

**Impact.** Run `sudo asight setup-helper` again after upgrading: the helper protocol is now 2 (an old
helper is refused with `helper-version-mismatch`, and nothing is steered). A Claude Code launched with
the asight CA in its environment but whose settings name another CA it may have applied at start is
now untrusted (passthrough) rather than decrypted.

**Known limits.** The kernel-side counters and refusals are not yet exercised on a real kernel (end-to-end tests written, not run).

## The board shows capture health (D38)

**What changed.** A new indicator in the top bar, `#caphealth`, is never empty: `✓ 采集中 · 自 T 起`,
`⚠ N` (failures of the last 24 h and conditions holding now), `○ 采集关`, `✗ 采集器没在跑 · 最后记录于 T`
(with the signal, e.g. SIGHUP), `✗ 采集器没响应`, `– 未安装 · 残留 N 项`, `? 健康读不出`, `? 未刷新`. It has
its own 1.5 s poll, independent of "live". Clicking it opens 采集健康 in the ⚙ session-less group:
failures by reason, what holds now, the daemon, each agent's last capture and failure, the last
install / uninstall, the old capture, the raw journal. An empty board says capture is failing when it
is. It all comes from `GET /api/capture-health`, read from disk only — the board can say the daemon is
not running. `asight collector status` prints the same payload. A WebSocket call that is incomplete
says so where it is shown (不完整 / 已截断 / 未解码 / 非逐字). The record store marks a day closed when
the day changes (the sealer can then seal it), never writes to an earlier day when the clock goes
back, and reopens a capture file renamed or deleted under it.

The old MITM / reverse proxy now record their failures in `~/.asight/logs/mitm-events.ndjson`: an
agent refusing the CA's certificate (each handshake — TLS 1.3 refusals used to leave the socket
open forever), an upstream cut mid-response (the client's response is ended, an `error:true`
envelope keeps what arrived), a stream that cannot be decompressed, a capture file that cannot be
written (no more crash loop; the file is created 0600), a LaunchAgent that did not load, the Clash
steer going missing, `shard --watch` failing; start and stop are lines too. `/control/status` shows
`CA ✗` / `CA ?` and whether `NODE_EXTRA_CA_CERTS` points at the asight CA.

**Why.** D38 : a capture failure must be recorded and visible on the board.

**Impact.** The running old MITM writes its events file only after it is restarted; until then the
indicator shows `? 旧采集 · 没有事件记录(重启后才有)`. `asight desktop on` and `asight monitor on` exit
1 when a LaunchAgent did not load.

**Known limits.** Some connection-row codes of RFC 4.6 §记录 are not written by the engine yet (the
expected class: policy, not-trust-path, …; `not_captured` on a refused-leaf row); the F-group checks for
them are `todo`. `asight monitor on`, `desktop on` and `uninstall` were tested at the library level only.

## 封存原始日志(D35):采集日志可缩到原始的几个百分点,逐字节无损

**改了什么**:新增 `asight raw` 命令族。已关闭的采集分片可以封存成 `<流名>.<段号>.sealed`(按记录字节级增量 + 独立 brotli 帧 + 索引尾);看板、`asight etl`、「回源逐字」面板都直接读封存文件,看到的记录、`raw_ref` / `text_ref`、DuckDB 表都和封存前一样。原文件只在每条记录与整个文件都被证明能逐字节还原之后才删。
- `asight raw seal <分片>`:只封带关闭标记(`<分片>.closed`)的分片,按 session 分文件,写到 `~/.asight/sessions/<session>/`;`asight serve --source <分片所在目录>` 会把它们当作该目录的一部分读入。
- `asight raw seal --legacy <文件|目录>`:D35 之前的文件(如 `~/.asight/sessions/`)。有 `asight shard --watch` 在跑、有进程持有文件、文件在静默窗口(默认 10 秒)里还在变,都会拒绝并说明原因;默认**保留原文件**,加 `--delete-original` 才删,且删前逐字节比对、比对后再确认原文件没变。旧根 `~/.atrace/asight/` 一律拒绝(先迁进 `~/.asight`)。先跑 `--dry-run` 看会封什么、会拒绝什么。
- `asight raw verify <封存文件|目录> [--against <原文件>]`:解码封存副本,与原文件逐字节比较。
- `asight raw export <session|文件.sealed>`:还原成普通 NDJSON(`~/.asight/export/`,0600)。
- `asight raw journal`:每一次拒绝、失败、删除及原因的持久记录(`~/.asight/raw/journal.jsonl`)。

**为什么**:原始 NDJSON 每次调用都重写整段对话,体积随调用数平方增长(作者机器上约 70 GB,对比 Claude Code 自己的约 1.5 GB)。

**对你有什么影响**:不运行 `asight raw` 就什么都不变。运行后磁盘占用大幅下降;封存文件同样含明文与凭据,仅属主可读,`asight doctor` 会检查封存文件和导出目录的权限。看板读不全某个文件时,会在顶部提示条(与上面「说出没读的文件」是同一条)标明哪个文件、多少条、为什么,不再显示成一个看似正常、实则少了记录的看板;看起来是采集数据却没被读的文件(压缩的采集、改了名的封存文件)也会列出来。raw journal 写不进去时,那条记录会打到终端。

基准(合成 2.5 GiB 分片,Apple M5、Node 22):封存 26.8 秒、峰值内存 421 MB;随机读 1,000 个 `raw_ref` 冷 p95 9.6 ms、热 p95 9.9 ms。合成数据的压缩比(1.29 %)不能代表真实数据。

## 封存:删原文件之前的比对工具,以及第三轮审查的修复

**改了什么**:
- 新增 `asight raw compare <目录> [--list]`:删原文件之前,逐 session、逐 control 类比对看板 / ETL / 回源面板经原文件读到的与经封存副本读到的——记录次序、每条记录的字节、每个 id 的回源结果。它比对的正是 `--delete-original` 会删的那些原文件(用删除时同一个判断),`--list` 逐个列出,好和 `--dry-run` 的清单对照;有差异、读不全、或一条都没比到时退出码 1,并写进 raw journal。它取代此前「起两个 `asight serve` 再 `curl` 比哈希」的做法(那样两边都是空字符串,永远相等)。
- `--delete-original` 只删**已经有**封存副本、且逐字节比对通过的原文件;还没有副本的拒绝并提示「先封存」,不再一次运行里封存又删除。`--dry-run --delete-original` 逐个列出会删哪些、拒绝哪些。删除中途失败时,记录与输出都写明原文件是否已经删了。
- 封存后看板读一个 session 的次序和封存前一样(calls → probes → other;以前删原文件后变成 calls → other → probes,影响大 session 只显示最近若干条时选中的是哪些)。
- `asight shard --watch` 在删原文件之后新写的 `calls.ndjson` 会被封成下一个段;旁边那个旧段是旧记录唯一的副本,不再被当作「这份文件的早先版本」而拒绝,也不再提示删掉它;`raw verify` 对它单独校验。
- 带着原文件与封存副本一起复制出来的目录(备份、恢复、换盘),只要复制时保留了文件时间(`cp -p` / `cp -a`、`rsync -a`、`ditto`),不再把每条记录读两遍;没保留时间的复制(如普通 `cp -R`)仍会读两遍,但看板会逐个文件标出「记录可能出现两次」。
- `asight raw seal --legacy` 不封存的文件(如中断的 resplit 留下的 `*.premigrate`、`.resplit-tmp/`)逐个列出并写进 journal;`meta.json` 等已知标记只计数。
- `asight raw export <session>` 改为输出到目录 `~/.asight/export/<session>/`,每个封存段一个文件(以前拼成一个文件,末行没有换行的流会和下一个流的首行粘在一起)。
- 两个封存器同时往一个目录写时不会互相覆盖段文件,也不会删掉对方正在写的临时文件;被 kill 留下的 `.sealing` 锁会在下一次封存该目录时清掉并记入 journal;`asight shard --rebuild-meta` 对坏行的计数在封存前后一致,并单独打印坏行数,读不全的封存段记入 journal。
- `asight raw verify` 对「文件后来变长、副本只含它前面一段」的情况显示 `ok (prefix)`,不再是普通的 ok。
- 读不了的目录(权限)在看板顶部横幅里点名,不再当作无关目录略过;raw journal 写不进去之后,下一次写成功时先补一条「中间丢了几条」的记录;raw journal 本身读不了时 `asight raw journal` 报错,不再显示为空。
- 删原文件这条路径(`--delete-original`)再收紧:每删一个之前先在 raw journal 里写一条「正在删 X」,journal 写不进去就一个都不删;另一个 `asight raw seal` 正在同一棵目录上跑时拒绝;删的时候持有该文件的封存锁;原文件在比对之后被改写、连大小和修改时间都改回去,也认得出来(看 ctime),不删;读不了的目录、原文件、封存段都点名拒绝(写进 journal,不再报一屏错误栈,也不再说成「还没有副本」);中断的封存留下的空段在删除前先清掉(写进 journal)。
- `asight raw compare` 比对的范围改成与 `--delete-original` 完全相同的那批文件(包括 session 目录里额外的流、不是 session 的子目录;不包括符号链接);会删却没比对到的,单独列出并让 compare 失败;汇总里「not covered」按文件数计。

**对你有什么影响**:已经用上一版封存(保留原文件)的副本仍然有效,不需要重封;删原文件前先跑 `asight raw compare`。删完原文件后请用这一版的 `asight serve`:旧版看板读封存段的次序与原文件不同。
## Honest labels for incomplete or changed context (D37)

- **What changed**: every call on the board now says, where it is shown, what asight cannot vouch for: a partial / stitched / server-edited context, the observer effect of asight's own capture on that agent, an upstream host whose cache semantics are unknown, and which bytes of the record are cut or not decoded. Records no dissector reads raise a 「未识别」 banner with their count, also inside an otherwise readable session; a session that mixes wire formats (e.g. Hermes with an auxiliary model) shows every call, each read by its own wire. Request keys that are not context blocks are listed with their verbatim bytes. OpenAI-wire calls (Codex, OpenCode, Kimi, Z-Code, Hermes Chat) now ship locators instead of whole request bodies, like Claude Code calls. In DuckDB, `calls` gains `wire_format / vendor / transport / context_state / observer_effect`; `sessions.harness` comes from the capturing process and `sessions.provider` summarizes the main lane's wire. Cache labels follow the vendor (the upstream host), not the wire.
- **Why**: invariant 4 — nothing that is not verbatim or complete may look as if it were; D37 reads the harness, the wire and the vendor separately.
- **What it means for you**: dsh calls (the Anthropic wire to DeepSeek) and every harness's control-plane traffic now load into DuckDB instead of being quarantined; quarantined records say why (`unsupported-wire-format:<name>`, `ws-handshake`, `no-adapter:<wire>`). An older DuckDB store gains the new columns on the next `asight etl`; run `--rebuild` to fill them for rows already there. DeepSeek reached through its Anthropic endpoint shows 「厂商缓存语义未知」 until a real capture settles its cache semantics (3.3 OPEN).

## Codex WebSocket sessions on the board (D37)

- **What changed**: sessions Codex sends over WebSocket (its default transport, recorded by the per-process collector one envelope per call) now render on the board. Each call shows the context the model actually ran with, rebuilt across the calls of the same connection by `previous_response_id`; blocks inherited from an earlier call's reply open their verbatim bytes from that call's record (a block locator may now name `resp.messages.<j>`, `resp.raw` or `req_extra_messages.<k>`; old locators are unchanged). A rebuilt call is badged 跨记录拼接; one whose predecessor is not in the capture is badged 不完整, names the missing response, and gets no cache ground-truth claim. The warm-up (`generate:false`) is in the probe lane, not counted as a turn; an interrupt sent while a call was open is listed on that call; reply messages that cannot be read are counted on the call. A tail-bounded view still rebuilds its calls from the whole session.
- **Why**: Codex's default transport sends only the new input after the first message, so without stitching the board showed nothing of Codex's context (D37 ②③); invariant 4 requires the stitched and the incomplete to be said where they are shown.
- **What it means for you**: nothing to do. Codex WebSocket sessions recorded by the collector appear under Codex. (Until below, DuckDB quarantined them with their reason; it now loads them.)


## The reply, with a locator per piece (gate G1)

- **What changed**: the raw panel lists each call's reply as captured — the whole decoded stream of an HTTP call, every server message of a WebSocket call — and each piece opens its verbatim bytes from the raw record. A piece that cannot be opened says why in place: a JSON reply the collector stored parsed (no byte-verbatim text, gate G16), a message kept as base64 or omitted past the per-call cap, an exchange that failed before any reply. Bytes that were compressed on the wire and are shown decompressed get their own badge, 「↺ 解码后逐字」.
- **Why**: 4.6 R2 checks the reply against what the upstream sent; the board must be able to show exactly those bytes (invariant 4: what is not shown verbatim says so).
- **What it means for you**: nothing to do. The reply locators use the field-qualified `text_ref` grammar (`…::resp.raw::<s>-<e>`, `…::resp.messages.<j>::<s>-<e>`) that is still awaiting your review (gate G1).

## Every harness's sessions in DuckDB

- **What changed**: `asight etl` now loads OpenAI Responses calls (Codex and OpenCode over HTTP), Codex over WebSocket, and Chat Completions (Kimi's default; OpenCode, Hermes and Z-Code can use it), besides the Anthropic wire. Each harness's own session key names its sessions (the dsh, OpenCode, Z-Code headers; Kimi's and Hermes's body keys), never the process or the connection. A WebSocket call's blocks are its stitched context, and blocks that live in an earlier call's reply point at that reply's bytes; a call whose predecessor was not captured is `context_state = 'partial'` with no cache ground truth and names the missing response in `calls.extra`. Usage maps per wire (DeepSeek's cache hit/miss split preferred; `cache_write` stays NULL where the wire reports no writes). `parent_session_id` is written from the harness's own parent signal (dsh, OpenCode, Codex — a Codex parent thread id is resolved to its session) and, for Claude Code, from the subagent prompt match; compaction comes from the harness's header first. A Chat request's `reasoning_content` is a thinking block on the board and in DuckDB. A message on a WebSocket that is no call is quarantined as `not-a-call:<wire>`.
- **Why**: the board read seven harnesses while DuckDB still read only Claude Code's wire; 3.1 #2, 3.2 AC-2b and 3.4 #2b / #3 were open.
- **What it means for you**: run `asight etl <dir> --rebuild` once to load what was quarantined before. Records that were keyed by Claude Code's header although another harness sent them now key by that harness's own header.

## Sessions without any session id are grouped by guess, and say so (gate G11)

- **What changed**: Hermes on a custom endpoint and Kimi without a body key send no session id. Their calls used to sit in the control view; they are now sessions on the board and in DuckDB, grouped by the hash of the system prompt and a 30-minute gap — never by process or connection — with keys like `synth-hermes-<hash>-<first call time>`. The chip says 「按推测归组」; in DuckDB `native_id` is NULL, `native_id_confidence` is `low` and `sessions.extra.session_key` is `synthesized`. Also fixed: an Anthropic request whose `system` is a plain string made `asight etl` abort.
- **Why**: 3.4 requires every inference call to belong to a session, with a synthesized key where the harness gives none, and the guess to be visible.
- **What it means for you**: the rule (30 minutes, the first system text) is a default awaiting your review and a check on a real capture (gate G11).

## `asight shard` files every harness's sessions; inference without a header key goes to `_unkeyed/` (gate G12)

- **What changed**: the sharder read only Claude Code's session header, so a sharded source put every dsh, OpenCode and Z-Code call — and every Codex call without a Claude Code header — into `control/`. It now reads each record's own harness header from the same table as the board, and a line that does not parse is keyed by any header key of the table. Inference calls whose session key is not a header (Kimi's body key, Hermes's guessed key) go byte-for-byte to `_unkeyed/calls.ndjson` instead of `control/`; the board lists and opens those sessions from there, and a call no key can be found for still shows in the control view. `asight shard` prints how many went to `_unkeyed/`. A header value that is literally `control` or `_unkeyed` is parked in `_badsid/`.
- **Why**: 3.4:21 requires one key table for the sharder and the board, and forbids such calls in `control/`.
- **What it means for you**: to move calls already filed under `control/` into their sessions, shard the capture again into a NEW directory and serve that one (re-sharding into the old directory would append every line a second time); the shards are copies, the capture is untouched. The directory name `_unkeyed` is a default awaiting your review (gate G12). The `asight raw seal` sealer still files by the four pre-D37 headers.
