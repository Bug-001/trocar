# Release notes — 2026-10-07

## `asight on` / `off` / `status` / `uninstall` are a two-state switch

**What changed.** `asight on` starts capture (the first `on` is the install), `asight off` takes every trace of
asight off your agents' path, `asight status` says per agent whether it is captured and why not, `asight uninstall`
also deletes asight's own files (captures and logs stay). Name an agent (`asight off claude`) to switch only that
one; `claude`, `dsh`, `kimi` and `zcode` are accepted for `claude-code`, `deepseek-dsh`, `kimi-code` and `z-code`.
Every command that changes something lists what it changed (each file, its backup, how to undo it, which processes
to restart) and takes `--json`; it keeps a copy of a file of yours in `~/.asight/backup/` before it changes it, and
`off` puts back only asight's own part (never the whole file). `on` never restarts an agent, Desktop or a running
capture. In a terminal `on` asks before the first install; not in a terminal it prints the plan and stops (exit 2)
unless you add `--yes`.

`off` works when asight itself is broken — no daemon, no source tree, no `node_modules`: `~/.asight/bin/asight-off`,
one file that needs only `node`, is written by every `on`, and `asight doctor` checks it is current. After `off`,
connections the collector still relays end at the next response boundary (a WebSocket at its turn's end);
`off --now` cuts them at once. The only thing of its own that asight adds to your traffic is the
`Connection: close` header line that ends such a connection; the call that carries it is labelled 「asight 加的」
on the board.

On Linux `on` / `off` drive the per-process collector. On macOS there is no collector yet, so they drive the old
capture (the Claude Desktop Clash rule, the resident MITM, the CA-trust primer): `on` plans, backs `Script.js` up
first and records each step; `off` takes the old capture out whole — the Clash block (only the block), the MITM
(drained for up to 10 s, the connections it had to cut are counted), `com.asight.monitor`, `com.asight.env`, the
Claude Code CLI steer and the old CA — and `uninstall` then removes asight's own files. The web switch's "off"
on such a platform is `asight off`.

**Why.** One way to start and one way to stop, that holds even when asight is the thing that broke (RFC 1.6, D39).

**Impact.** BREAKING. `asight on` used to be the old Claude Code CLI steer, `off [--remove-ca]` its undo and
`uninstall` the old half-uninstall: the steer is `asight monitor on --no-autostart` / `monitor off --remove-ca`.
`asight on --proxy …` is a usage error (exit 2) that says so. `asight test` is gone (it was `doctor`; `npm test`
has the name). An unknown command is exit 2 with the usage on stderr (it was exit 0). The autostart unit now runs
`asight daemon`; units written before still run `asight collector start`, which keeps working as a hidden alias —
the next `asight on` rewrites the unit text (a daemon-reload, never a restart). The old spellings `install`,
`collector install|on|off|status|uninstall|start` and `verify` (now an item of `doctor`) are hidden aliases, not
listed in help. Exit codes: 0 done · 1 not done or a problem · 2 usage error, nothing touched · 3 `status` / `doctor`
could not judge · 70 the daemon crashed. `on`, `off`, `uninstall` and `asight daemon` refuse to run as root;
`sudo asight setup-helper` is the only command that needs it.

## `asight help`, and the commands in four sections

**What changed.** `asight help` lists the commands in four sections (common, data, maintenance, the old capture),
starts with 「开 `asight on` · 关 `asight off` · 状态 `asight status`」 and says which generation `on` / `off` drive on
this platform; `asight help <command>` and `asight <command> --help` say one command. `monitor`, `shard`,
`setup-helper` and `daemon` are in it now (they were missing). `npm run serve`, `etl` and `demo` call
`bin/asight.mjs`, so the same defaults and arguments apply everywhere.

**Impact.** The README's Commands section is the same list, and the README no longer says what the code stopped
doing: credential headers are stored verbatim (files 0600; `asight doctor` checks them), not `<redacted>`; the old
steer is `monitor on`; `--remove-ca` takes the trust entry out and leaves the CA files.

## `asight doctor` says what it could not check

**What changed.** An empty capture, or none at all, is exit 3 (无法判定), not a pass; a capture file others can
read is exit 1 with 「采集文件可被他人读取」 and the `chmod` line; the backups in `~/.asight/backup/` are checked
too; `doctor` reports a stale or missing `asight-off`, backups no manifest names, what `status` knows, and the VPN /
proxy software it finds (read-only; it starts nothing and goes nowhere). `asight verify` is `doctor`'s check of the
old CA.
