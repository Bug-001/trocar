# 2026-10-30

## Command line

- **Harnesses are listed in the order of the names table.** The harness table of `trocar status`, the receipts of
  `on` and `off` when you name harnesses, and the `Known:` line of a mistyped name now list them as `claude-code,
  codex, opencode, kimi-code, deepseek-dsh, hermes, z-code`. Before, these listed `hermes` third. `trocar` and the
  standalone `trocar-off` now read the harness names from one table, so they cannot disagree.

## Capture

- **DeepSeek `dsh` is decrypted on macOS and Windows.** `dsh` connections through trocar were forwarded
  without capture when `NODE_EXTRA_CA_CERTS` was unset (`var-missing`) or named a file without the trocar root
  (`ca-not-in-file`). The trocar plugin that `install` puts in `dsh` adds the trocar root inside the
  process, so trocar no longer looks at that setting to decide; it still uses the files it names to check the
  upstream's certificate, so when it cannot read that setting or its file the connection is still forwarded and
  judged again on the next one.
- **pi is the eighth harness.** `trocar install`, `on`, `off`, `status` and `uninstall` take `pi` as a harness name.
  On Linux `install` puts one extension, `trocar-ca.js`, in pi's `extensions/` folder (`~/.pi/agent`, or
  `PI_CODING_AGENT_DIR`), which pi loads by itself; it adds the trocar root inside pi and nothing else. On macOS and
  Windows `install` puts a different extension there, `trocar-pi-extension.js`: it adds the root and reads the switch
  file once when pi starts, so a pi you start while capture is on goes through trocar and a pi started before `on`
  does not, even after pi's `/reload`. A pi started with `--no-extensions`, or with settings that leave the extension
  out, does not run it and is not decrypted. Capture of pi has not been shown end to end on any OS yet.
- **Z-Code keeps the CAs you added when trocar sets its `caCertFile`.** On macOS and Windows `install` points
  `network.caCertFile` in `~/.zcode/cli/config.json` at a bundle trocar writes, and that key replaces Node's
  default roots. The bundle held Node's roots and the trocar root only, so a private CA you added through
  `NODE_EXTRA_CA_CERTS`, `ZCODE_AGENT_CA_CERT` or the desktop app's CA setting stopped counting: Z-Code could not
  reach a host signed by it, with trocar on or off. The bundle now also holds the certificates of those files, as
  `install` finds them in its own environment and in Z-Code's settings. A file it cannot read, a relative path and a
  block that is not a certificate are named in the install receipt. Run `trocar install` again to rebuild the bundle.
- **A host whose certificate did not verify is no longer reported as a program refusing trocar's certificate.**
  When trocar stops decrypting a program's traffic to one host, `trocar status --failures` and the board now say
  why: the program refused trocar's certificate, the host's certificate did not verify with the program's own
  trust, or the handshake with the host did not finish.
