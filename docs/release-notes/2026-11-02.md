# 2026-11-02

## The board
- **A session that was never read before finishes loading while you watch it.** Opening such a session showed
  "Reading this session for the first time · 0 %" and stayed there, unless new calls came in or it was the newest
  session. Opening it now starts the read, and the percentage climbs until the session is fully read.
- **The traffic list shows the newest calls first.** Calls were listed oldest first, and calls whose times and
  capture order disagreed were out of order. They are now sorted by time, newest first.
- **Settings › Storage loads faster once the board has read your capture.** Its counts now come from the same in-memory
  index the other pages use, so the index is no longer read again segment by segment. The first open after the index is
  rebuilt (for example right after an update) is not faster yet: it can take more than a minute, and the overview may say
  that storage could not be read until it finishes.

## Capture
- **Plain `http://` requests sent through trocar's proxy work again, and an agent's own are captured.** A program
  an agent starts inherits the agent's proxy settings, for example a network login helper run from inside an
  agent, and its plain `http://` requests used to be refused. trocar now passes them on, taking out only what was meant
  for trocar itself (its proxy password, which is never recorded), and records an agent's own like the rest of its
  traffic.

## Status
- **The board and `trocar status` agree on which forms are installed.** A form found only through a command (such as
  the `codex` or `dsh` command line) used to be "not routed" on the board, because the daemon looked for the command on
  the login service's PATH. Each `install`, `on`, `off` or `uninstall` you run now records your PATH, and every part of
  trocar looks commands up on it.
- **Routes show only the API host trocar read.** A direct hop used to name the first host trocar knows for the
  harness, with `:443`, as if you had configured it. It now names the host your agent's own config sets. When the
  config sets none, it says "the API host it uses".
- **An agent whose only provider runs on this machine is "not captured".** When every API address in the agent's own
  config is on this machine, such as a local relay, its model calls never pass through trocar. Before, status said
  "captured" for it.
- **No carrier on record is reported as a certificate problem.** It used to show as "not routed".
- **Forms and Routes say what they mean.** The certificate column says how the certificate reaches the agent ("reads
  your user trust store"). The proxy column shows trocar's port. `(was: …)` appears only when a value was recorded.
  The text shows trocar once per route, and the reasons a hop could not be read appear as words. A route row names
  the process the door saw on that form, or says "new processes". Forms that are outside the supported scope are no
  longer listed.
- **Claude Desktop's route without trocar goes through the system proxy**, as the app does.
