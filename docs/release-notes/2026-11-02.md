# 2026-11-02

## The board

- **A session that was never read before finishes loading while you watch it.** Opening such a session showed
  "Reading this session for the first time · 0 %" and stayed there, unless new calls came in or it was the newest
  session. Opening it now starts the read, and the percentage climbs until the session is fully read.
- **The traffic list shows the newest calls first.** Calls were listed oldest first, and calls whose times and
  capture order disagreed were out of order. They are now sorted by time, newest first.
- **Settings › Storage loads faster once the board has read your capture.** Its counts now come from the same in-memory
  index the other pages use, so the index is no longer read again segment by segment. The first open after the index is
  rebuilt (for example right after an update) is not faster yet: it can take more than a minute, and the overview may say
  that storage could not be read until it finishes.
- **A link to a step no longer shows "Follow latest" on while that step loads.** A replay link that names a step
  (`step=` in the address) showed "Follow latest" pressed until the session's calls arrived, then the chip turned
  itself off and the desk stayed on the named step. "Follow latest" is now off from the moment such a link opens,
  and going back to the session's address without a step turns it on again, even before the named step arrived.
- **The request view and the "Logged only" label show the class a call was recorded under**, also for classes you
  added. They used to work out a class of their own for any class that was not built in. A call recorded before
  classes existed now says it has no recorded class, instead of showing a guessed one.
- **One rule decides which calls failed.** A model call over HTTP that got no status (the connection ended before
  an answer) now counts as failed on the board and in `trocar query session`, as it already did in the overview's
  failed count. A Codex call over a WebSocket has no HTTP status, so the overview no longer counts it as failed; the
  session view still marks one whose reply says it failed. The index and the session views are rebuilt once after
  the update.
  A call answered with a status below 400 other than 200 (201, 204, a redirect) is no longer marked failed on the
  replay rail or in the stats.
- **The stats card computes less token usage in one go.** Before the per-segment usage files exist, `overview`
  now works out usage for at most 10 MiB of newest calls (was 16 MiB): each call now goes through the same
  extraction the session view uses, which costs more per byte, and the smaller budget keeps the first open as fast
  as before. `coverage` still says how far it got; the background worker fills in the rest.
- **On the capture page and the capture log, selecting text never folds a row, and Technical details stay open across
  refreshes.** A row opens and closes from its head button, with a click, Enter or Space; a click or a drag inside an
  open row leaves it open. While a row is open the rows keep their order, so the row you are reading does not move
  when a refresh brings new counts.
- **The overview keeps what you opened while it refreshes.** Technical details you opened stay open, the text you
  selected stays selected and the focused control keeps focus when the overview reads new numbers. Switching the stats
  window dims the old numbers until the new window answers, instead of swapping in a blank card. Clicking a problem
  item opens the capture page with that agent's row already expanded. The rest of the page stays usable while the ⓘ
  beside the failure list is open.
- **The Settings pages (Storage, Prices, Appearance) now use the same components as the capture pages.** An open
  Technical details or files section stays open after you change a level or switch the window, and the keyboard
  focus stays on the control you used.
- **The Sessions page keeps your place while the list refreshes.** The highlighted row, the scroll position, a text
  selection and an open menu all stay as they are when new sessions arrive, and going back from a session lands on the
  row you opened. Choosing 24 hours, 7 days or All no longer adds a step to the browser's Back.
- **On the traffic pages, what you are reading stays put while more rows load.** The traffic table and a host's list of
  requests are rebuilt on the board's new framework and look the same. The request you have open, the details you
  expanded and the text you selected now stay where they are when the next page of rows arrives. On a narrow window a
  host's rows no longer run past the right edge.

## Capture

- **Plain `http://` requests sent through trocar's proxy work again, and an agent's own are captured.** A program
  an agent starts inherits the agent's proxy settings, for example a network login helper run from inside an
  agent, and its plain `http://` requests used to be refused. trocar now passes them on, taking out only what was meant
  for trocar itself (its proxy password, which is never recorded), and records an agent's own like the rest of its
  traffic.

## Installing and updating

- **The board is now built with React from `web/`, and the daemon serves the built copy in `src/web/board/`.** It looks
  and works the same as before. The built board is part of the repository and of the npm package, so every way of
  installing trocar gets the same board and nothing is built on your machine.
- **A git install and `trocar update` no longer fetch the development tools.** The install lines in the README use
  `npm install --omit=dev`, and `trocar update` does the same; trocar still has no runtime dependencies.
