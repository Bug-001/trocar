# 2026-10-21

## Fewer false alarms, a steadier board, and a lighter background reader

### Capture: problems are reported only when something really went wrong

- **No false "refused trocar's certificate".** A connection that an agent opened and then closed without sending
  anything (a spare connection kept ready, then not used) is no longer reported as the agent rejecting trocar's
  certificate. Only a close that comes right after trocar's certificate counts as a rejection.
- **No false "asked for trocar's proxy settings file and was refused".** When Claude Desktop opened a connection to
  trocar's PAC port and closed it before trocar had worked out whose it was, the connection was reported as a program
  not shown to be yours being refused. Nothing was refused: it had already left. Such connections are now only counted
  (`left` in the collector engine's ingress counters), not reported; a refusal is recorded only for a
  program that is still connected.
- **Failures say which side left.** When a connection ends before any data was forwarded, its record now says who
  went first (the agent or the server) and what trocar was waiting for at that moment, such as the server's handshake
  or your proxy's reply. Such connections no longer count as decrypted or passed through in `trocar status`.
- **Agents are no longer refused at the proxy auto-config door while they start programs.** On macOS a program that
  is just starting briefly shares its parent's connections. trocar now looks again a few milliseconds later, so the
  agent's own connection is recognised and captured. A connection trocar still cannot place is forwarded or refused
  with a single record. It is no longer answered with a request for proxy credentials that trocar never takes.
- **A server that cannot be reached is not your proxy being down.** "Your upstream proxy cannot be reached" is now
  reported only when trocar cannot reach your proxy itself, including a SOCKS5 proxy that closes during its greeting.
  A server that is down or unreachable is no longer reported as your proxy being down.
- **Unreadable evidence is retried.** When trocar could not read a process's details, it no longer remembers that
  as a fixed answer. It reads again on the next connection.
- **Forwarding by design is not a problem.** Connections that trocar forwards on purpose without recording them are
  counted under their reason and are no longer shown as problems.
- **`trocar status` after `trocar update`.** Agents that were still being captured after an update (or after an
  `off` then `on`) were listed as "started before capture was on" with a hint to restart them. `status` now uses the
  same rule as the collector, so it shows them as captured.
- **`on` keeps a record of every run.** On macOS and Windows every `on` that changes something, including one that
  fails, leaves a record of its result. That record names only the agents this run actually switched on.
- **Stopping the collector finishes cleanly.** `trocar update`, or anything else that stops the background process,
  no longer cuts the old process short when a second stop signal arrives. It finishes its stop, so the next start no
  longer reports that the last run did not stop cleanly.
- **`trocar status` counts every open connection.** Its Connections line counts every connection open through trocar
  right now. Connections of agents you turned off that are still closing are mentioned on the same line.
- **Failures are listed under the agent they happened to.** The Capture log and `trocar status --failures` list a
  certificate refusal or a connection failure under its agent, not under the capture service.
- **Every network finding is put in words.** The Capture page says what each network finding means (a different exit,
  a system proxy set by a proxy auto-config file, a process name that is not on the list, and so on) instead of
  showing its code.
- **Plain English everywhere.** Messages about trocar's proxy settings file (PAC) no longer speak of a "door". The
  remaining messages about an old Node version, running as root, a port that is already taken and an unsupported
  system are in plain English.
- **Install paths with non-ASCII characters** (for example a home folder with Chinese characters) are recognised by
  `off` and `uninstall` on macOS and Windows.

### The board: the replay stays on screen

- **A failed refresh no longer blanks the session.** The last good view stays on screen with a line that says it is
  out of date. The board then tries again after a growing pause (up to 30 seconds), not in a tight loop.
- **Following latest follows the live end.** New steps of a growing session stay in view, and following no longer
  stops on its own when a new step arrives.
- **Each step shows its reply.** The context window ends with the step's reply: its text, thinking and tool calls.
  The newest replies no longer wait for a later request to carry them.
  The reply's text, thinking and tool calls are rows like the request's blocks above them, under one Reply
  header that gives the stop reason; the newest text opens by itself, and a row opens with Enter or Space.
- **Very large live sessions open, and never run the background reader out of memory.** A session is read call by
  call within a bounded amount of memory, and the reader measures its memory while it reads: a session that does not
  fit shows its newest calls and says so ("Showing only the latest N / M calls"), however much more each call costs
  than estimated. A live session with thousands of calls and dozens of sub-agents used to leave its replay blank, or
  show "This session failed to load" with a page of native stack. A live session of about 9 300 calls shows its
  newest 4 500 or so, and its first open after a quiet spell takes about 10–20 seconds while it is read from the
  start; later refreshes are quick.
- **A session that cannot be read says so in one sentence.** "This session could not be read." with Retry; the
  reason is under Technical details, never in the body.
- **Refreshes are small.** Answers are compressed, and steps outside the current page carry only what the timeline
  draws: following a live session of thousands of calls downloads about 1 MB per refresh instead of about 16 MB.
- **One stalled tab no longer blocks the board.** A tab that stopped reading its answer is let go after a minute, so
  other reads go on. When the background reader fails, the Capture log says why in one line (for example "heap limit
  reached"), not a native stack.
- **The background query reader gives memory back.** It stays warm while the board is open or you are querying, and
  leaves after two minutes with nothing asked. The next query starts a new one.
- **Costs show again on the replay.** The replay shows estimated costs again and asks for the price table once, not
  on every refresh. Built-in unit prices follow the current list prices for each model generation (for example
  Opus 5.5 at $4 / $20 per million tokens), so estimates for current models are no longer about 3-4× too high.
- **Every step of a long session can be opened.** The early steps of a long session load when you open them (Home, a
  link to a step, or a call near the start). "Load this step" shows that it is loading, and says so when the step
  cannot be loaded on its own; a failed load leaves the button usable.
- **Follow latest behaves.** Turning it on lands on the newest reply. It turns off as soon as you move away from the
  last step, and End or f brings back the newest step's content, even on a finished session.
- **The replay reads less and keeps your place.** It pauses in a background tab, waits longer between refreshes when
  a session is slow to read, and no longer waits for the previous session's read when you switch sessions. A refresh
  that brings nothing new for the current step no longer redraws it, so your text selection and scroll stay put.
- **Quieter replay.** A failed refresh shows one short line, with the full reason under Technical details, and Follow
  latest shows as paused. How a call reached trocar is no longer shown as a warning on every step. A failed call's
  raw reason is under Technical details. Long replies scroll inside the raw panel instead of printing over the next
  row. Long paths keep the file name, removed files strike only their name, and outline jumps respect reduced motion.
- **Readable tool results.** Tool results and other JSON blocks can be shown as readable text, marked as decoded,
  with the exact bytes one click away.
- **Sessions that are not captured.** A link to a session that is not captured says so, links back to Sessions and
  stops re-reading.
- **Sub-agents and sessions have names.** Sub-agent rows are named by their task (what they were asked to do),
  not "subagent: task", and say "1 call". Sessions get a title from their first prompt, marked as taken from the
  captured request. Opening the sub-agent list no longer pushes the context window off the screen; the list scrolls in
  its own area. Sessions with few steps draw narrow bars, and the step bar stays on one line at 1280 px.
- **More on each step.** While following, the step's previous call comes along, so the window can mark what is new.
  Request parameters such as model, max_tokens and stream show their values in the raw panel. Capture labels are plain
  English (for example "Reply never finished", "Via trocar's local proxy").
- **The board never hangs on a read.** Every read gives up after 60 seconds, and leaving a screen cancels its reads.
  A screen that is still loading says so instead of showing an empty page.
- **A slow first read is not missing data.** When trocar has to build its index while reading, the replay, Overview,
  Sessions and Storage call it slow, not capture files that were not read in full. Storage says in one grey line
  that the page was slower because of it, and lists those files apart from real problems.
- **Overview.** Cards appear at once and fill in as answers arrive; switching the time range updates at once and
  never shows numbers for another range. Cost and cache figures include the parts of a large session read so far and
  say how many model calls they cover; cost reads "at least ≈ $X" when part of it could not be priced. An agent with
  only network traffic in the window links to its traffic instead of an empty session list.
- **Tidier screens.** Technical details show each key next to its value again, without stray commas or a huge empty
  box. The grey band at the bottom of every screen is gone, breadcrumbs wrap on narrow screens, and session rows and
  traffic request rows no longer overlap on a phone.

### Queries hide credentials

- `trocar query calls` and the board's request detail no longer show the values of credential headers
  (Authorization, x-api-key, Cookie, Proxy-Authorization). Add `--reveal <header>` to `--ref` to see one. `trocar raw`
  still prints the stored bytes, and the capture files are unchanged.
- The Storage total now counts a `raw` or `collector` folder you moved to another disk and linked back.

### The Capture page, the Capture log and Storage say each thing once

- Each agent's expand lists every changed file once, with what trocar wrote there in words (a setting, a block of
  variables, a file trocar created); undo commands appear once, in Technical details.
- Technical details show one path line per distinct route, a finding's reason before its code, relayed connections
  only while some are still open, and "capture after logout" only when it is unknown.
- The service row says the failure count once, and that sentence links to the Capture log. A row with a switch no
  longer also says "on".
- The Capture page and the Capture log fit a phone: names and sentences break between words, nothing overlaps the
  switch or the count, and the page never scrolls sideways.
- The Capture log says "metadata only" once per page, shows first and latest times in local time like the time
  column, and puts the connections not recorded by design under one heading.
- Storage lists each read problem once, under the Disk card's files. Each class row explains what the class is and
  what Log only keeps, Stored shows the class's share of the window, and `other` says it holds whatever no other class
  matched.
