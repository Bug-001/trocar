# 2026-11-01

## Capture

- **A host whose certificate does not verify is said to be the host's problem.** When a network intercepts TLS for a
  while, as a sign-in page or captive portal does, the host's certificate fails the program's own check. trocar
  then passes that program's traffic to the host on unread, and the program checks the real certificate itself.
  `trocar status` used to say the program "does not trust the certificate" and that a restart would not help. It
  now says the host's certificate did not verify, names the two usual causes (a network that intercepts TLS, or a
  host that uses your own CA), and gives `trocar on <agent>` as the way to try again now. A host that refuses
  trocar's handshake is worded the same way: it most likely wants a client certificate.
- **Capture comes back within minutes once the network is fixed.** When trocar can step aside without failing the
  program's connection, trying to decrypt that host again costs the program nothing. Those retries now start after
  30 seconds and wait at most 5 minutes. Before, every retry waited 10 minutes at first and up to an hour. A retry
  that would fail one of the program's connections, such as a program that refuses trocar's certificate, still
  waits 10 minutes at first and up to an hour.
- **`trocar on <agent>` retries now.** Running `trocar on` for an agent that is already on makes trocar try again
  to decrypt every host it had paused for that agent. Its next connection to each of them is decrypted. `on`
  prints one note for each such host and records the change in the capture log.

## The board
- **The board opens again from browser history or a bookmark.** The page kept its key only for the tab that
  `trocar board` opened, so the same address opened later from history, a bookmark or a new tab showed
  "This page cannot read the board without its key" every time. The browser now keeps the key for the board's
  address. If the key stops working (it was replaced), the page drops it and asks you to run `trocar board` again.
