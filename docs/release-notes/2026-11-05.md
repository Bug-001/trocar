# 2026-11-05

## The board

- **Titles are there when the list opens.** The session list, the Overview's recent sessions, `session` and the replay
  head now read one small title table, so a list no longer waits for a large read and no longer shows a title as still
  coming. "Title not read yet" is gone, and "Untitled session" is now "No prompt captured": a fact about the session.
- **A title that cannot be read says so.** When the records that decide a title cannot be read this time, the row says
  "Prompt could not be read" in muted text, the same as a row with no title, and the next read tries again. A title
  already known stays. One such session no longer stops the list: the rest of it is answered, and the answer's `errors`
  has one entry for that session.
- **A new version re-reads behind what you see.** After an update, a session you open shows the answer it already has
  and catches up in the background, under "Updating to this version". The session list and `trocar status` do not wait
  for that read.

## Query

- **`title_source` in `trocar query sessions` is `wire`, `unread` or `null`.** `pending` is gone. A session with a
  title is always `wire`; `unread` has `title: null` and an `errors` entry; `null` means no prompt was captured. A session
  whose calls are all subagent calls takes the first subagent's task as its title, until a main call appears.
- **While a session is updated to this version, `trocar query` answers what its head lists.** `session --head`,
  `lane --pack` and `lane --tail` through the daemon are the files on disk, and `session --since <mark>` is an empty
  answer on that mark with `pending`, so a client keeps the answer it holds until the switch. `trocar query lane` no
  longer waits in the terminal: it prints at once, with `pending`.
