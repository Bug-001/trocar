# 2026-11-05

## Rules

- **`trocar rules` writes, tries, lists and removes rules, offline.** `rules add` checks a rule and adds it switched off,
  `rules test` runs it on captured records and sends nothing, and `rules`, `rules <name>` and `trocar query rules` say
  what each rule is and what it would cost. `rules disable`, `rules rm` and `rules off` stop rules. Every step has
  `--json`. A rule's regexes and scripts run in a separate process, never in the daemon. A script there cannot send a
  signal, open a thread, start a process, load an addon or reach trocar's control routes.
- **trocar now needs Node 22.15 or newer.** A rule process keeps a script to a list of Node's own modules and to ES
  modules, and the hook that does it starts there. A script's dependencies have to be ES modules too, so bundle any
  CommonJS ones first.
- **A script is held to what one process can fairly take.** It is stopped if it holds more than 1024 sockets and timers,
  keeps opening more than 5 connections a second, grows its slot file past the limit, keeps using more than a quarter of
  a CPU core between requests, or its main thread sticks with no task on it. It cannot rename the globals the rule
  process depends on, and however it ends, the process ends at once. On Windows a script path has to name its drive.
- **`trocar help rules` is the manual.** It says everything needed to write, try, list and remove a rule: every
  field, how to write a condition, the ten actions and where each one can stand, what each kind of rule makes the agent
  wait for, what a script receives and may do, and three complete examples that `trocar rules add` takes as they are.
  It opens with the warning that matters most to an agent: a hold on your own harness stops you at your next model
  call. `trocar rules enable` still refuses every rule in this version, and the manual says so.
