# 2026-11-07

## Install and uninstall

- **On Linux, the Z-Code desktop app is captured when its CA setting names a certificate file of your own.** The desktop
  setting `httpProxyCaCertPath` (in `~/.zcode/v2/setting.json`) reaches the app's agent as `ZCODE_AGENT_CA_CERT`, which
  wins over the `network.caCertFile` that `install` writes, so the desktop was passed on unread (status said
  `desktop-ca-override`). `install` now appends a marked trocar block to the end of the file that setting names, and to
  the file a `ZCODE_AGENT_CA_CERT` in the install shell names, and leaves the setting alone; `uninstall` takes the block
  out by its marks. A file that is not yours (another user's, read-only, or inside a package manager's or the system's
  tree) is left alone, and the receipt says so and why.

## Capture

- **On Linux, a Z-Code started with `ZCODE_HTTP_PROXY` is no longer taken to trust trocar through `caCertFile`.** Z-Code
  takes its network settings as one group, from the environment or from its config: with `ZCODE_HTTP_PROXY` set (yours, or
  the desktop's from its proxy setting) it does not read `caCertFile`. trocar now judges such a process only by
  `ZCODE_AGENT_CA_CERT` and `NODE_EXTRA_CA_CERTS`, and passes it on unread, with the reason in `status`, when neither
  carries trocar's root; before, it was judged by `caCertFile`, which that process does not read.
