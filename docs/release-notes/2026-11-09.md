# 2026-11-09

## Uninstall

- **`trocar uninstall` says what it does in a few lines.**
  - The plan lists each of your files it takes trocar out of. Several files in one folder share one line, with their count.
  - Then one sentence covers what trocar deletes of its own, and one line covers what is kept and its size.
  - The receipt says it is done and what was kept.
  - Every file, key, backup and process is still printed with `trocar uninstall --details`.
  - `--json` is unchanged.
- **The uninstall question no longer says "Nothing was changed" just above itself.** An interactive `trocar uninstall` used to print "Nothing was changed. Run it with --yes to do it." right before `Proceed? [y/N]`. Now only `--dry-run` says that.
- **After `trocar uninstall --purge-data`, running `trocar uninstall` once more leaves nothing behind.** On Linux, when another account still uses the capability helper, the README asks you to run `uninstall` a second time. That run used to start a new record under `~/.trocar/collector/flows/`, which you then had to delete by hand. A clean run no longer creates that folder. A failure or a warning is still written there, and the folder is made for it.
- **A refused `trocar uninstall` says why in one line, then the steps.** When capture is still on for an agent, a program may still be using trocar, or trocar's service does not answer, it says so in one line, adds "Nothing was changed.", then lists each step, in order. The full sentence is in `--details` and in the JSON `message`.

## All capture commands

- **`--details` on `install`, `on`, `off`, `status`, `uninstall`, `doctor` and `update`.** The short default text of each command is coming in the next changes, and `--details` will keep printing everything it leaves out. Until those land, every command but `uninstall` prints what it printed before.

## Status and doctor

- **`trocar status` is one short screen.** The first line says how many agents are captured and which one needs a restart. The table names each agent with a short reason and no process numbers. Under it are only the lines that ask something of you or are not right, such as the certificate or a service that is not running, then the problem count and whose they are (`46 in the last 24 hours, 34 of them pi's`), and the board's address.
- **`trocar status --failures` is a table of what happened.** Each row has when, how many times, the agent, and one sentence with what to do. Problems that say the same for the same agent are one row. The codes, programs and hosts are in `trocar status --failures --details`.
- **`trocar doctor` lists only what needs you.** The headline counts the problems and says which agent needs a restart. Capture failures are one line that points at `trocar status --failures`. Notes are counted in the last line and printed with `trocar doctor --details`, together with every process number, command and what the last install noted.
- `--details` prints what each of these commands printed before, and `--json` is unchanged.

## Board

- **After an update that re-indexes your capture files, a session you never opened shows up long before re-indexing ends.** The capture files are re-indexed newest first. A session grouped by its own session key answers from the capture files already re-indexed. It says that older capture files are still being re-indexed, and that it may lack calls until that ends. Sessions grouped by an inferred key, and Kimi Code's side chains, still wait for the whole re-index.
