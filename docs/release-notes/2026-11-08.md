# 2026-11-08

## Certificates

- **On macOS, trocar's signing helper refuses a start time outside its own clock window.** It signs the
  intermediate certificate the collector uses, and it took that certificate's start time from whoever asked. It now
  refuses a start more than an hour before its own clock or more than five minutes after it. trocar's own collector
  asks for ten minutes before now, so nothing changes for it. An installed helper is replaced by the next
  `trocar install` you run in a terminal (macOS asks for your login password once, to let the new helper use the key).
## Linux

- **`trocar uninstall` no longer fails while the capability helper is installed.** The helper is one per machine, so
  another account's trocar may still use it. A script-channel uninstall used to exit 1, keep your install record and
  your captured records, and print a line that removed the helper even when another account still needed it. It now
  removes everything of yours as usual (the collector, its login entry, the proxy entries, the install record, and
  the records with `--purge-data`), keeps only trocar's code and the PATH item, and exits 0. The receipt says the
  helper stays and gives the `sudo ... setup-helper --remove` line to run if no other account uses trocar, then
  `trocar uninstall` once more.
- **`sudo trocar setup-helper --remove` checks the other accounts first.** It looks in every other account's home for a
  trocar install record (it only checks that the file is there) and removes nothing while it finds one, or while it
  cannot read a home. It names those homes and exits 1.
## Status

- **`trocar status` draws the Claude desktop app's route as it goes while its proxy settings address is refused.** When
  the app's setting still holds trocar's proxy settings (PAC) address from before this install's key, trocar refuses
  the app's request for it, and the app connects directly. The Routes block drew it through trocar; versions before the
  key drew it through your system proxy. It now draws it direct, marked inferred, and `status --json` gives that form
  `entry_intact: false` and `connected: false`, as the summary already said it was not captured. The board's
  technical details mark that hop inferred too: a hop is marked when the edge that reaches it is inferred, as
  `trocar status` already did.
## Status

- **A fresh install no longer reads "failing" from the install before it.** `trocar uninstall` keeps the capture
  records, including the failure log, so installing again used to show that log's failures as this install's for up to
  24 hours. Health now counts failures from this install's start when it began within the last 24 hours, and
  `trocar status` says which window it shows ("since this install, 2 h ago" or "in the last 24 hours"). The older
  records are not deleted: they stay in `~/.trocar/collector/flows/`.
## On

- **`trocar on` keeps the hosts you bypass in your login environment out of trocar.** `on` writes a `NO_PROXY`
  beside the proxy it sets: the local hosts, then the bypass list already in that file. It now adds the `NO_PROXY`
  of your login environment too: on Windows the one in your user or machine environment (System Properties ›
  Environment Variables), which it was meant to read but did not, so traffic to those hosts went through trocar; on
  macOS the one set with `launchctl setenv NO_PROXY …`, which apps you start from the Dock inherit.
