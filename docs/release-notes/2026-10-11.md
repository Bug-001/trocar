# Release notes — 2026-10-11

## macOS runs the per-process collector: `asight on` flips to it

**What changed.** On macOS, `asight on` no longer drives the old capture: it runs the new per-user
process collector (RFC 4.9), the same generation Linux and Windows have. A Mac user running `asight on`
now sees the plan first — the bundled kernel it will run (`asight-forwarder`, from the
`asight-kernel-darwin-x64` / `-arm64` package; loopback only, no TUN, never the system proxy, nothing
written into your VPN), one row per agent group with the upstream the kernel will dial for it, Codex's
WebSocket, the Gatekeeper precheck, and the autostart LaunchAgent (`com.asight.collector` in
`~/Library/LaunchAgents`, `RunAtLoad` + `KeepAlive`; logout stops it — no linger on macOS) — and, after
the usual confirmation, the proxy and trust entries written in the agents' own config files with the
prior values recorded. The first install's combined trust bundles now carry the keychain-administered
roots (the anchors your enterprise proxy's certificate chains to), so a replace-semantics entry such as
Codex's `SSL_CERT_FILE` verifies against the real world on day one, not from the first daily rebuild.
The forms that reach further are opt-in, each named with what it touches: `asight on <harness>
--opt-in <form>` — Kimi / OpenCode's launch shims and their one marked PATH line in the zsh rc files
(reference-counted, so `off kimi-code` does not break opencode), and Claude Desktop's certificate in
the login keychain (`security add-trusted-cert` in the user domain; the OS's own authorization dialog
carries the consent, a declined dialog is your own no; found and removed by the certificate's SHA-256
fingerprint, never its common name). `asight off` runs the same undo as on Linux: the LaunchAgent booted
out **before** the daemon is stopped (launchd's `KeepAlive` really does pull a killed daemon back), the
plist removed (launchd rescans that directory at every login), every entry and opt-in item taken out —
and also whatever the old capture left on the machine (the Clash block, the old LaunchAgents, the
keychain CA), through the same legacy arm `off` has on Linux. `asight status` is the new per-agent
table (a harness name other than `claude-code` is no longer a usage error), `asight daemon` passes the
gate, and `asight help`'s first screen says macOS drives the per-process collector.

**Why.** The macOS collector is built: the pinned kernel with the Gatekeeper precheck, the LaunchAgent
autostart, the wiring of 4.9 §4 末's flip checklist (the autostart undo is launchd's, not systemd's;
the install path reads the OS roots; `launchd-register-failed` reaches the records with launchctl's
words, not systemd's; the opt-in writers landed) — and the machine's own acceptance (MA group) is what
retires the old capture, per D39⑥. The one question every command asks — `hasNewCollector(platform)` —
now answers yes for `darwin`, so every gated command dispatches to the new collector instead of the old
capture.

**Impact.** macOS only; Linux and Windows are unchanged. The old capture keeps working on your Mac for
the transition (1.6 §4): its own commands (`capture`, `mitm`, `desktop`, `monitor`, `shard`) run as
before, `asight off` / `uninstall` also take out whatever it left, and the login-environment variable
it set (`com.asight.env`) is not removed while the old capture is still on — taking it out alone would
stop macOS Claude Desktop's capture (0.0 §过渡期遗留). The web switch's "off" on macOS is no longer
`asight off` — like on Linux and Windows, it only takes the old CC-CLI steer out and the switch's
status says so (「只管旧 CC-CLI steer,不等于 `asight off`」). Exit codes and command shapes are
unchanged: the not-implemented refusal (exit 1) remains for platforms that have none of the three
collectors. The old capture's tests now drive it through the `hasNewCollector: () => false` seam, the
same one `asight daemon` has always had — the old capture stays live on real Macs until D39⑥ retires
it, so its behaviors keep their tests.

## The old capture is retired: the collector is the only capture (D39⑥ executed)

**What changed.** The v0→product transition capture — the base_url reverse proxy (`capture`), the
MITM (`mitm`), the Clash Verge steer (`desktop`) and the CC-CLI steer (`monitor`) — is deleted
(`feat/retire-legacy`). The per-process collector serves Linux, Windows and macOS, so every
`asight on` / `off` / `status` / `uninstall` / `daemon` drives it; a platform with none of the three
is refused by the collector's own loader (`not supported yet`), not by a CLI gate. `asight off` and
`asight uninstall` no longer undo what the old capture left on a machine, and the `--remove-ca` flag
is accepted but inert. `asight shard` stayed (it is the raw layer's session ingestion, not a capture
source) and moved from the retired help section to 数据. The board's 监测 toggle still steers only
the old CC-CLI steer — labelled 「只管旧 CC-CLI steer,不等于 `asight off`」 — until the 4.4 control
plane is reworked; its `on` arms a boot item that ran `asight capture`, which no longer exists, so
treat the toggle as read-only history until then.

**Why.** D39⑥ retired the old commands per platform once that platform's collector passed its
machine acceptance; with macOS flipped (the section above) all three are in, the operator declared
every machine a test machine, and the transition code came out by the roots. What the old capture
wrote is still read (source truth): the board lists its captures beside the collector's, its event
log still feeds 采集健康, and `asight doctor --only old-ca` still answers.

**For a machine an old capture is still installed on.** `off` no longer cleans it — do it by hand
(prose in the README's *The old capture is retired*): `launchctl bootout` of `com.asight.mitm` /
`com.asight.monitor` / `com.asight.env`, `security delete-certificate -c 'atrace local MITM CA'` from
the login keychain (Linux: `certutil -D -d sql:$HOME/.pki/nssdb -n asight-ca`), and
`launchctl unsetenv NODE_EXTRA_CA_CERTS`; the CC-CLI steer in `~/.claude/settings.json` and the
Clash block in Verge's `Script.js` revert the way they were written.
