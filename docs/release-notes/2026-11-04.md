# 2026-11-04

## The board

- **A title still being read says so.** Right after the board starts, the session list and the Overview's recent
  sessions showed "Untitled session" for sessions whose title had not been read yet, and real titles only on the next
  refresh. Those rows now show "Title not read yet" in muted text until the title arrives; "Untitled session" is kept
  for sessions that have no title. `trocar query sessions` gives such a row `title_source: "pending"`.
- **A replay you leave stops reading.** Leaving the replay right after moving to another step could still send that
  step's read a moment later. The step's reads now wait until you come back.
- **Each part of a Codex reply opens to its own bytes.** When a reply had two or more text parts, none of them
  could be opened to the bytes captured for it, and a one-part reply opened the whole message instead of its text.
  Each part of a reply, over WebSocket or HTTP streaming, now opens to exactly its own captured bytes, and is marked
  verbatim on the board. When a streamed reply splits one item's data over several lines, a part that shares that item
  with others still cannot be opened, and the board says why. Each session is read again once, the first time you open
  it after updating.
- **Codex reasoning that carries its full text shows as reasoning.** A reasoning step that came with its text, not
  only a summary, was shown as JSON text, and in the request as a user message; with an empty text list it
  was not shown at all. It is now one reasoning block from the model, with its summary and its text, and opens to
  the bytes of that whole reasoning item. Each session is read again once, the first time you open it after updating.
  Reasoning with no readable text is marked "no plaintext" rather than "encrypted": the wire may carry a signature,
  ciphertext or nothing at all.

## Install and uninstall

- **The install plan names every file of the undo.** It named `~/.trocar/bin/trocar-off` alone, as "the undo that
  works without this source tree". On Windows install also writes `trocar-off.cmd` beside it, and a script install has
  no source tree. The plan now names each file, as "the undo that works even when trocar itself is broken".
- **The plan says what install leaves alone.** When an agent's certificate setting already names a file of yours, or
  names a file that is not yours, install leaves it as it is and records that. The plan now lists these under
  "Left as they are:", with the reason, and `--json` gives them as `left`, apart from `planned`. A Set up from the board
  lists only what it changes: not a file it leaves alone, and not a certificate block already in place for the current
  root (a block for an older root is replaced, so it is listed).
- **A setting naming trocar's own file in another letter case is trocar's.** On Windows and macOS such a setting was
  read as your own file, and install added a certificate block to trocar's own bundle. When install merges the
  certificate files your settings name into trocar's bundle, it now skips any file under `~/.trocar`, not only under
  `~/.trocar/collector`.
- **The uninstall receipt reads the same on Windows.** Directories end in `\` instead of `/`, and a file trocar
  created for its setting says what was taken out before saying the file is gone.

## Status

- **Capture times read right after a restart.** `trocar status`, its `--failures` list and the board's capture log
  counted each connection at the moment it opened, and took a group's first and last time from the order the lines
  were written. Connections are recorded when they close, so after the collector restarted, a group could show a last
  time earlier than its first, and groups and "last failure" times could be out of order. Each connection now counts at
  the moment it closed (when it was last seen), every group runs from its earliest to its latest time whatever order
  its lines are in, and the list is ordered by the latest time. A long connection that opened more than 24 hours ago
  but closed within the last 24 hours now counts in the 24-hour window.

## Command line

- **`--json` is one line into a pipe.** Every `--json` document is now a single line when it goes into a pipe or a
  file, and two-space indented at a terminal, so a script can read it line by line.
- **A refusal is a document too.** A command run with `--json` that stopped with only a message on stderr left
  stdout empty. It now prints an error document with that message, and exits with the same code as before.
- **`trocar query <name> --help` describes one query.** It prints what the query answers, each of its parameters, and
  its exit codes, and it does not run the query. An unknown name gets the same refusal as without `--help`.
- **`trocar help --json` gives the whole command line as one document.** That is every command with its usage, options
  and exit codes, and every query with its parameters. `trocar help <command> --json` and `trocar <command> --help --json`
  give one command, `trocar query <name> --help --json` one query, and `trocar query --json` all the queries.
- **`trocar board --json` gives the board's address as a document** and opens no browser, so a script can reach the
  board without one popping up.
