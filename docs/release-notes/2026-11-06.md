# 2026-11-06

## The board

- **The replay page is the new desk.** It is laid out in two splits: the main area and the right sidebar, and inside
  the main area the scope and the reading column. The sizes you drag are remembered. The scope's Whole session strip
  is the time axis. The right sidebar has the tabs Overview, Resources and Rules (Rules only when something is
  registered) and a button that collapses it. Overview has one row per chapter, the current one open, with its Tools,
  System prompt, Prompts, Sub-agents and Jump to change. A resource name opens that block in the context window. The
  left outline and the separate panel of raw data are gone: what only that panel showed is in Call details, folded after the
  reply in the context window; what the capture changes in the agent is shown there unfolded. Below 1200 px the
  sidebar becomes a row at the bottom whose panel rises over the desk; below 900 px the track names fold and their
  controls (the problem pager, the track folds) move into the Tracks menu; below 600 px only the whole-session strip
  and the reading column remain.
- A price nobody knows is never shown as $0 or as "no unit price": while the price table loads or cannot be read, the
  session info says so, and a sub-agent row shows no cost until one of its calls is priced.
- **A changed prefix is a cache break only when the cache was mostly missed.** A step whose earlier content changed but
  still read at least 30% of its input from the cache now says what changed and how much still hit; it is no longer
  flagged, counted as a break or given an extra-cost estimate. The context window still marks where it changed.
- A failed call's cache button says **call failed**, and the session info names the **costliest break** (the break that
  cost the most extra), not the most expensive step.
- **A replay link with `call=<record id>` opens on that call.** A main-conversation call opens on its step; a call of
  another track opens on the step nearest in time with the call in the drawer; an id the session does not have opens
  step 1 and says so, once the whole session is read. Follow is off, and until you move the address stays the
  link, so a reload opens the same call.
- **Call details lists the usage keys trocar doesn't count.** A reply's usage can carry keys outside the cache and token
  counts (a vendor's own counter, a relay's note, the split of a cache write by lifetime). They now appear under
  **Usage keys not in the counts**, each with its value.
- **Resources says when an agent's records hold no resource information, or only some.** A session whose agent
  keeps no resource records says so instead of listing nothing, and one where only some calls kept them says the
  list is that part.
- **The session info's cost row names each reason a call has no price, once.** A call with no unit price and a call
  that returned no usage each get their own line, instead of two lines that blamed a missing usage on the price.
- **The main track's side list of content types says when some don't fit.** It now lists the largest shares first, and
  a last line reads **+N more** when the smallest don't fit; the hover still lists every type.
- **The tracks keep one order for a session's lanes.** A sub-agent or background lane that the board learned about late
  no longer sits after lanes that started after it.
- **The session info layer names a declared parent or fork.** When the agent's first captured call names the
  session it was started from (a sub-agent's parent, or the session a fork came from), the ⓘ shows it as a link.
  The link opens that session when trocar has it, and says it is not in the session list otherwise. An agent that
  never says shows "Parent or fork: this agent doesn't say"; when trocar can't tell, "not known".
- **A host's request list names every column.** The marks column (log only, length only, failed) is headed **Notes**,
  and each row's words sit on one line.
