# 2026-11-06

## Linux

- **`trocar status` says whether each agent is set up.** On Linux, each agent in `trocar status` and on the board now
  carries `setup`: ready, needed (with the reason) or unknown. An agent installed after trocar is listed too.
- **`trocar on <agent>` refuses only the agent that is not set up.** If the certificate entry trocar installed for an
  agent is missing or was overwritten, `trocar on` leaves that agent off with `setup-needed` and names the two
  commands: `trocar install`, then `trocar on <agent>`. `trocar install` (or Set up) puts that entry back, and undoing it later
  restores the value the agent had left there. The other agents named in the same command still turn on.
- **Set up on the board works on Linux.** It adds only what that agent is missing and needs no `sudo`; when it cannot put an entry back
  (for example the file is now a link to nothing), it refuses with `setup-needed` and the reason, and changes nothing.
- **An agent counts as installed when its own files or command are there.** On Linux, `trocar status` and `trocar on` now
  decide whether an agent is installed from its own install folder, config folder or command on your PATH (the PATH of
  the terminal you last ran trocar from), not from whether trocar would have something to write for it. Claude Code and
  Codex also count when only their VS Code extension is installed, including one that VS Code's Remote - SSH put on this
  machine; trocar then sets them up in the same files as their command-line versions (Codex once it has its own
  `~/.codex` folder). An agent that is
  installed but has nothing trocar can set up (for example Codex before its first run, or Kimi Code without the PATH
  line its installer adds) shows `setup` needed, and `trocar on`
  leaves it off with `setup-needed`. The board's Set up for such an agent says why it cannot set it up and changes nothing,
  instead of saying there is nothing to set up.
- **`trocar install` writes nothing for an agent that is not installed.** On Linux, `trocar install` used to add its
  certificate entry or plugin for every agent it knows, so an empty home got `~/.claude/settings.json`,
  `~/.config/opencode/plugins/trocar-ca.js`, `~/.dsh/cordis.patch.yml` and `~/.pi/agent/extensions/trocar-ca.js`. It now
  sets up only the agents whose own files or command are there, and lists only those as installed. Run `trocar install`
  again after installing a new agent. What it set up for an agent you later removed stays until `trocar uninstall`. Set up on
  the board refuses an agent that is not installed with `setup-needed` and changes nothing.
- **The board and the terminal agree on an agent whose folder you moved.** On Linux, when you point an agent at another
  folder with its own variable (`CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `DSH_HOME`, `HERMES_HOME`, `PI_CODING_AGENT_DIR`,
  `XDG_CONFIG_HOME`, `XDG_DATA_HOME`), trocar now remembers that variable's value from the terminal you last ran it in,
  next to your PATH. The board's status and Set up, which run in the background service without your shell's variables,
  now look in the same folder as `trocar status` and `trocar on`.
- **trocar says when Kimi Code's VS Code extension is not captured.** On Linux the extension's calls cannot be captured:
  VS Code uses its own certificate list there, which only your login environment can extend, and trocar does not change
  that environment. When the extension is installed (also by Remote - SSH), `trocar install`, `trocar on` and
  `trocar status` now say so for Kimi Code, and `trocar status --json` lists it under `setup.uncaptured`.

## All platforms

- **A certificate entry trocar cannot read is no longer reported as overwritten.** When the file holding it cannot be
  read (for example its permissions changed), `setup` is now `unknown` with the reason, and `trocar on` turns the agent
  on with a note instead of refusing it as `setup-needed`.
