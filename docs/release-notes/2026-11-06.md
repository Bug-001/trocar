# 2026-11-06

## The board

- **The Sessions project filter and the project name on the replay header now work.** A session's project is the
  working directory its own requests state. After the update, the title list is rebuilt once in the background.
- **`codex exec` sessions now say they came from the command line.** Each harness now has its own rule for its entrypoint. The rule used to look for `cli` in any user agent, and `codex exec` sends `codex_exec`, so those sessions showed no entrypoint. The index rebuilds once in the background after the update.
- **Session titles no longer come from injected blocks.** A title and a sub-agent's task now skip tagged blocks a
  harness places at the start of a prompt; when a prompt holds nothing else, an attached file's text is used, and
  otherwise the title stays as it was. The outline and the turn cards are unchanged. After the update, sessions are
  re-read once in the background.
- **A record that failed to read once no longer stays marked unreadable.** After one failed read, the board and
  `trocar query session` kept reporting the record unreadable even once it read again, and its blocks could point back
  to a later record. The next open now answers as if the session had been read in one go.
- **Agents that send no session id are no longer merged into one session.** pi on the Anthropic Messages and Chat
  Completions APIs, Hermes on a custom endpoint, and Kimi without a body key send no session id. Agents running at once
  with the same system prompt, such as the agents of a workflow, were grouped into one session, and every switch between
  them showed as a compaction. Now each call joins the conversation whose history it continues, so each agent is its own
  session and compactions no longer appear at every switch. After the update the index rebuilds once in the background.
  A session that held several agents keeps its id for the first of them and the others get new ids; this applies to pi,
  Hermes and Kimi Code sessions that carry no session key.
- **A session without a session id no longer splits after a pause.** When pi, Hermes or Kimi Code sent no session id
  and the agent paused for more than 30 minutes, its next call started a new session, often titled by the compaction
  summary it opened with. A call whose history continues the session's last call now joins it for up to 24 hours after
  that call. The other guesses still look back 30 minutes only. Sessions regroup by themselves after the update.
- **Kimi Code sessions show the agents Kimi opens as background lanes.** Kimi sends one session key for the main
  conversation and the agents it starts. Their calls used to sit in the main lane, and each switch read as a
  compaction. Now each history with another system prompt is a background lane of its own, and the main lane marks
  only Kimi's own compaction. On Kimi's Anthropic-compatible API every call still sits in the main lane. Sessions are
  re-read once in the background after the update.
- **pi sessions on Gemini are no longer glued into one.** The Gemini API's history and system prompt were not read,
  so every keyless pi call on Gemini within 30 minutes of the last joined one session. Now each conversation is its
  own session. The index rebuilds once in the background after the update.
