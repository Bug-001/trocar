# 2026-11-06

## Capture

- **Kimi Code's PATH line goes where your shell always runs it.** trocar's line in your shell rc came right after the
  Kimi installer's own PATH line. When that line sat inside an `if`, a `case`, a loop or a function, trocar's line landed
  inside it too and ran only when that block did, so `kimi` could miss its launch shim and not be captured. The line now
  goes at the end of the rc file. A line already in your rc stays where it is until you run `trocar off`,
  `trocar uninstall` and `trocar install`.
  `kimi` is not captured in these shells, and `status` reports a running `kimi` that did not start through its shim:
  - a shell that leaves the rc before the end (`exec fish`, `exec tmux`, or a top-level `return` or `exit`). This is new:
    those lines used to be fine when they came after the installer's line;
  - an rc whose last line is unfinished (a trailing `\`, an unclosed block or heredoc);
  - a shell where a function adds Kimi's folder only after the rc has been read.
