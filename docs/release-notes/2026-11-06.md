# 2026-11-06

## The board

- **The replay page is the new desk.** It is laid out in two splits: the main area and the right sidebar, and inside
  the main area the scope and the reading column. The sizes you drag are remembered. The scope's Whole session strip
  is the time axis. The right sidebar has the tabs Overview, Resources and Rules (Rules only when something is
  registered) and a button that collapses it. Overview has one row per chapter, the current one open, with its Tools,
  System prompt, Prompts, Sub-agents and Jump to change. A resource name opens that block in the context window. The
  left outline and the separate panel of raw data are gone: what only that panel showed is in Call details, folded after the
  reply in the context window; what the capture changes in the agent is shown there unfolded. Below 1200 px the
  sidebar becomes a row at the bottom whose panel rises over the desk; below 900 px the track names fold and their
  controls (the problem pager, the track folds) move into the Tracks menu; below 600 px only the whole-session strip
  and the reading column remain.
- A price nobody knows is never shown as $0 or as "no unit price": while the price table loads or cannot be read, the
  session info says so, and a sub-agent row shows no cost until one of its calls is priced.
- **A changed prefix is a cache break only when the cache was mostly missed.** A step whose earlier content changed but
  still read at least 30% of its input from the cache now says what changed and how much still hit; it is no longer
  flagged, counted as a break or given an extra-cost estimate. The context window still marks where it changed.
- A failed call's cache button says **call failed**, and the session info names the **costliest break** (the break that
  cost the most extra), not the most expensive step.
- **A replay link with `call=<record id>` opens on that call.** A main-conversation call opens on its step; a call of
  another track opens on the step nearest in time with the call in the drawer; an id the session does not have opens
  step 1 and says so, once the whole session is read. Follow is off, and until you move the address stays the
  link, so a reload opens the same call.
- **Call details lists the usage keys trocar doesn't count.** A reply's usage can carry keys outside the cache and token
  counts (a vendor's own counter, a relay's note, the split of a cache write by lifetime). They now appear under
  **Usage keys not in the counts**, each with its value.
- **Resources says when an agent's records hold no resource information, or only some.** A session whose agent
  keeps no resource records says so instead of listing nothing, and one where only some calls kept them says the
  list is that part.
- **The session info's cost row names each reason a call has no price, once.** A call with no unit price and a call
  that returned no usage each get their own line, instead of two lines that blamed a missing usage on the price.
- **The main track's side list of content types says when some don't fit.** It now lists the largest shares first, and
  a last line reads **+N more** when the smallest don't fit; the hover still lists every type.
- **The tracks keep one order for a session's lanes.** A sub-agent or background lane that the board learned about late
  no longer sits after lanes that started after it.
- **The session info layer names a declared parent or fork.** When the agent's first captured call names the
  session it was started from (a sub-agent's parent, or the session a fork came from), the ⓘ shows it as a link.
  The link opens that session when trocar has it, and says it is not in the session list otherwise. An agent that
  never says shows "Parent or fork: this agent doesn't say"; when trocar can't tell, "not known".
- **A host's request list names every column.** The marks column (log only, length only, failed) is headed **Notes**,
  and each row's words sit on one line.
- **A Set up, on or off click no longer holds the board's reads while the OS asks you to trust trocar's root.** The
  click now runs apart from the board's reads, so the sessions list and the replay keep answering while the dialog is
  open. A click whose process stops midway is reported as failed and is not run again.
- **The Sessions project filter and the project name on the replay header now work.** A session's project is the
  working directory its own requests state. After the update, the title list is rebuilt once in the background.
- **`codex exec` sessions now say they came from the command line.** Each harness now has its own rule for its entrypoint. The rule used to look for `cli` in any user agent, and `codex exec` sends `codex_exec`, so those sessions showed no entrypoint. The index rebuilds once in the background after the update.
- **A failed call is no longer blamed on the provider.** In `trocar query lane` and `session`, a failed call or one with no usage could say `provider-contradiction`, because its missing counts read as zeros. It now says nothing. Sessions are re-read once in the background after the update.
- **Session titles no longer come from injected blocks.** A title and a sub-agent's task now skip tagged blocks a
  harness places at the start of a prompt; when a prompt holds nothing else, an attached file's text is used, and
  otherwise the title stays as it was. The outline and the turn cards are unchanged. After the update, sessions are
  re-read once in the background.
- **A record that failed to read once no longer stays marked unreadable.** After one failed read, the board and
  `trocar query session` kept reporting the record unreadable even once it read again, and its blocks could point back
  to a later record. The next open now answers as if the session had been read in one go.
- **Agents that send no session id are no longer merged into one session.** pi on the Anthropic Messages and Chat
  Completions APIs, Hermes on a custom endpoint, and Kimi without a body key send no session id. Agents running at once
  with the same system prompt, such as the agents of a workflow, were grouped into one session, and every switch between
  them showed as a compaction. Now each call joins the conversation whose history it continues, so each agent is its own
  session and compactions no longer appear at every switch. After the update the index rebuilds once in the background.
  A session that held several agents keeps its id for the first of them and the others get new ids; this applies to pi,
  Hermes and Kimi Code sessions that carry no session key.
- **The Storage page and Overview no longer fail because the disk is slow.** Measuring what trocar takes on disk reported no progress, so on a busy machine a healthy query worker could be treated as stuck: the page showed an error and kept showing it for a minute. It now reports progress as it goes.
- **A write counter a vendor does not report now shows as a dash, not 0.** On wires with no cache-write counter, such as DeepSeek and OpenAI Responses, the board and `trocar query` said 0, which reads as a measured zero, and the cost of a cache break was priced from it. Sessions are read again once in the background after the update, so old sessions are corrected too.
- **A read that races a seal no longer reports a record as unreadable.** When a capture file was sealed between a read looking for it and opening it, the read failed for that file, or that record, until the next read. It now reads the sealed copy, which is always in place by then.
- **System prompt rows say what they are.** In the replay's context window a system block's tag read "unknown". It now
  reads "instructions" (or "system reminder"), and the block's own name, such as "identity" or "billing header", comes
  after it. Sessions are re-read once after the update.
- **A cache break after a model or provider switch now says so.** When a step's model or provider differs from the step its cache is compared with, the board names that as the cause, not an earlier block changing or a provider-side miss. A provider-side miss is now suggested only for providers whose cache numbers are understood and only when they reported writing nothing. The cache details of a DeepSeek step that read nothing from its cache say the cache is best-effort, and those of an OpenAI prompt under 1,024 tokens say it is below the minimum cacheable length. Sessions are re-read once in the background after the update.
- **A session without a session id no longer splits after a pause.** When pi, Hermes or Kimi Code sent no session id
  and the agent paused for more than 30 minutes, its next call started a new session, often titled by the compaction
  summary it opened with. A call whose history continues the session's last call now joins it for up to 24 hours after
  that call. The other guesses still look back 30 minutes only. Sessions regroup by themselves after the update and are
  re-read once in the background.
- **Kimi Code sessions show the agents Kimi opens as background lanes.** Kimi sends one session key for the main
  conversation and the agents it starts. Their calls used to sit in the main lane, and each switch read as a
  compaction. Now each history with another system prompt is a background lane of its own, and the main lane marks
  only Kimi's own compaction. On Kimi's Anthropic-compatible API every call still sits in the main lane. Sessions are
  re-read once in the background after the update.
- **pi sessions on Gemini are no longer glued into one.** The Gemini API's history and system prompt were not read,
  so every keyless pi call on Gemini within 30 minutes of the last joined one session. Now each conversation is its
  own session. The index rebuilds once in the background after the update.
