# 2026-11-03

## The board

- **The keyboard list closes when you leave the replay.** Pressing `?` on the replay opens the list of its keys. Going
  back or following a link to another page while that list was open left it over the next page, listing step keys
  where there are no steps. It now closes when you leave the replay.
- **A confirmation closes when you leave its page.** A confirmation left open on Settings > Storage, Capture or the
  Overview stayed over the next page after Back or a link, and its OK went to a page that was already gone. Every
  dialog, confirmation and popover now closes with the page it was opened on; a confirmation closed this way counts as
  Cancel and changes nothing.
- **Opening a session no longer reads its summary twice.** The first read of a session whose summary file was not yet
  written came back without a version tag, so the next refresh read the whole summary again. That first read now
  carries the file's tag, and the next refresh of an unchanged session is answered "not modified".

## Installing and removing

- **The marks trocar leaves in your agents' files name commands that exist.** The marked lines and blocks
  (Codex's and Hermes's `.env`, the DeepSeek `cordis.patch.yml` row, the Kimi `PATH` line, a block in your own
  certificate file) used to say `trocar collector uninstall` removes them. New ones name `trocar uninstall`, or
  `trocar off` for a proxy block. What an earlier version wrote is still found and removed the same way, and
  `install` and `on` do not rewrite an entry only because its mark has the old words.
- **A command to paste is printed whole, on a line of its own.** The `sudo ... setup-helper` line of `trocar on` (helper
  missing) and the `sudo ... setup-helper --remove` line of `trocar uninstall` (helper still installed) were folded at
  80 columns, so a paste ran `sudo` alone. In `--json`, they are the row's `command`: `blocked[].command` for `on`,
  `left[].command` for `uninstall`.
- **Receipts show every path in your home as `~/...`.** The macOS install receipt printed the PATH and login-item
  rows as absolute paths while the rest said `~/`. The line to run if trocar itself breaks now reads
  `~/.trocar/bin/trocar-off` too. A `sudo` line keeps the absolute path, and a Windows line keeps its quoted
  `C:\Users\...` path. In `--json`, `standalone` is still the absolute path.
- **On Windows, the line to run if trocar itself breaks works in PowerShell.** It was printed as
  `"<node.exe>" "<path>\trocar-off"`, which PowerShell rejects ("Unexpected token") before running anything. It now
  reads `cmd --% /c @"C:\Users\...\.trocar\bin\trocar-off.cmd"` and runs unchanged in Windows PowerShell (the 5.1
  that comes with Windows) and cmd, with the node a script install placed or, when there is none, the `node` on PATH;
  a path with spaces, `&`, `(` or `^` works, options such as `--now` are passed on and the exit code comes back.
  `install` writes `trocar-off.cmd` next to `trocar-off`; it finds node the way `trocar.cmd` does. A path containing a
  defined `%NAME%` variable still breaks in both shells.
- **On Windows, `trocar` returns its exit code to PowerShell.** `trocar.cmd`, the command a script install puts on
  PATH, returned 0 to PowerShell and to `cmd /c` whatever trocar's exit code was, so a failed `on` or `doctor`
  looked like a success to a script. It now returns trocar's code in PowerShell, cmd and `cmd /c`. When the install
  script is not run in a terminal, the next step it prints is a line that runs in PowerShell and cmd, also when your
  home folder has a space in its name.
- **`trocar uninstall` names what it kept.** Its last line said "Delete the captured records" even when only trocar's
  own record (`~/.trocar/collector/flows/`) was kept. It now lists what is kept, which is what `--purge-data` deletes,
  and says nothing about it when nothing is kept.
- **The refusal of an older install record fits the screen.** `trocar install` and `trocar on` printed it as one long
  line with absolute paths. Like `uninstall`, they now fold it at 80 columns, show `~/...` and print each command on
  a line of its own.
- **A command to copy is indented deeper than a list.** A command now starts four spaces in, deeper than the items a
  label lists (two in), so `~/.trocar/bin/trocar-off` as one of trocar's own files and as the line to run if trocar
  breaks no longer look alike. A folded item continues six spaces in, past the command's column.
- **`trocar on` says each route once, and its last lines do not run together.** With `--yes`, the route line was
  printed in the plan and again in the receipt; it is now in the receipt only (a `--dry-run` still shows it). It
  reads `route: codex -> ...`, no longer `codex: route codex -> ...` with the name twice. A label that lists files
  (`Already in place, not rewritten:`, `trocar's own files:`) prints one path a line under it, two spaces in;
  before, the second path on the line folded to the left edge. The closing `Status: trocar status` and `Remove trocar: trocar uninstall` are now
  on a line each: folded together, they read as one sentence. A route too long for one line is never folded: it drops
  where each hop came from (`[...]`) first, then shortens to `agent -> trocar -> <next hop> -> ...`. The proxy setting
  it came from is a sentence of its own below it.
- **`sudo trocar setup-helper` says what it installed.** It printed `installed <path> (<path> <capabilities>)`. It
  now prints one sentence, "Installed the capability helper `<path>` with the capabilities `<capabilities>`."
- **A path in your home no longer pushes a row's text down.** A row of the install plan or of a receipt was laid out
  as if `~/` were your whole home path, so a path that fits once shortened, such as
  `~/.trocar/collector/plugins/dsh/index.js` in the `cordis.patch.yml` row, went to a line of its own six spaces in.
  It now stays in the row's text column. A first word too long for that column (the systemd link that enables the
  collector) goes on its own line six spaces in, like a later one, with the rest of the row back in its column.
- **Every install plan row says what changes there.** On macOS, the Kimi Code and pi rows gave only a directory. They
  now say what trocar puts there, in the receipt's words ("trocar's launch command", "trocar's plug-in"). A key is
  named in words ("its certificate setting network.caCertFile"), and DeepSeek's loader file says it gets the line that
  loads trocar's plug-in, where it showed `*.insert`.
- **The install plan names every file install changes.** When `NODE_EXTRA_CA_CERTS` (or another setting trocar reads)
  names a certificate file of yours, install appends its certificate block to that file, but the plan did not list
  it. It does now, once per file. The folder DeepSeek's plug-in goes into is its own row too.
- **Each row of `trocar on`'s plan says what changes there**: the proxy setting, trocar's proxy block, trocar's routing
  plug-in. A Codex row showed only `~/.codex/.env`, and OpenCode's plug-in file was not named at all. `--json` gives
  each row's proxy keys in `keys`.
- **The Linux plan mentions backups only when it changes a file of yours.**
- **`trocar on` asks about "new since you last said yes" only when you said yes before.** The first `on` after an
  install listed `~/.codex/.env` as new since an earlier yes there never was, right under the same row of the plan. Now
  each setting is one row; when an earlier yes exists, the rows it did not cover end with
  "(new since you last said yes)".
- **A second `trocar uninstall` no longer lists `user-path.json` as removed.** Every uninstall first recorded your
  `PATH` in that file and then deleted it. Uninstall no longer records it, and `uninstall --dry-run` writes nothing.
- **`trocar uninstall` no longer refuses because of an agent that has already exited.** With the collector running,
  it took the list of agents still holding a route from the collector, which is up to 10 seconds old, so an agent
  closed just before was still named and uninstall refused. It now checks that list against the current process list
  and refuses only for an agent still running. When the process list cannot be read, it keeps the collector's list
  and says that the list may be out of date, and why.
- **A size stays with what it measures.** In the uninstall receipt, `(3.2 KB)` could fold onto a line of its own under
  `~/.trocar/collector/flows/`. A size and its unit are now never split, and a size in brackets folds with the path it
  belongs to.
- **The route line of `trocar on` keeps an IPv6 hop, and never folds.** When the route was too long, dropping where
  each hop came from also dropped a hop written in brackets, such as `[::1] (direct)`. That hop now stays. A route still
  too long after the last shortening stays one line instead of folding `-> ...` to the left edge.
- **`sudo trocar setup-helper --remove` lists the leftover copies it removed one a line.** It printed them as one long
  warning. They now follow a sentence, each on its own line two spaces in, as `setup-helper` without `--remove` does.
- **`trocar off` without an install record says what it would do to each file on that file's line.** The words were
  listed once each, four spaces in, where a command to copy goes. Each file is now one item, followed by what would be
  done to it, inside 80 columns.

## Status

- **`trocar doctor` folds a step you take in an application.** A step such as "No action needed: ... its calls to
  <hosts> are not recorded" was printed on one line however long it was. It now folds inside 80 columns; a command
  to copy still stays whole on its line.
- **`status --failures` prints the command in a reason whole.** On Linux, the reason of a stopped or wrong-version
  capability helper ends with the `sudo ... setup-helper` line, and `--failures` cut it after 100 characters. The
  reason is still shortened, with each command in it said as "the line below" ("the lines below" for two), and each
  command is printed whole on a line of its own below it, two spaces deeper than the reason. When the reason is too
  long, the part that says what to do with the command ("install it once per machine with the line below") stays
  whole and the words before it are cut, at a word boundary, with `...`. A reason that starts with its command keeps
  the words after it.
- **`status --failures` never cuts a path out of a reason.** The reason of a missing capability helper read
  "capability helper not found at... install it once per machine with the line below": the path was cut. A reason
  whose shortening would drop a path is now printed whole, the path on its own line when it does not fit.
- **On Linux, the helper has one name.** Messages called it the capability helper, the capture helper, the redirector
  helper or the kernel helper. They now all say capability helper. A problem that Windows can report too says
  "trocar's helper is not running", which is also true on a new install where the helper never ran.
- **A helper problem that was fixed no longer keeps capture health at "failing".** On Linux, after the capability
  helper was installed and `trocar on` succeeded, `trocar status` still said failing for up to a day. The record of
  the failure stays (`status --failures`, `--json` `failures.groups`) as a note. The same is true when trocar's CA
  or `agents.json` is usable again. If the problem comes back, it counts again.
  A restart that finds the problem gone (the helper installed, then a reboot or `trocar install` again) ends it too.

## Removing a script install

- **On Linux, a capability helper still installed keeps everything `uninstall` would need next time.** The code, the
  `trocar` launcher and the PATH item stay, so `trocar uninstall` still runs from a new terminal after the
  `sudo ... setup-helper --remove` line. With `--purge-data`, no captured record is deleted in that run; before, the
  records were deleted and the run still exited 1.
- **On Windows, `uninstall` really removes `~\.trocar\app` and `trocar.cmd`.** The step that was to remove them after
  the command exits never ran, and the receipt still listed them as removed. They now go within a second of the
  command exiting, with no window shown. The receipt lists them in `--json` as `scheduled`, not `removed`, and says
  they go once the command exits.
- **On Windows, the PATH item is taken out by `uninstall` and added only once.** It stayed in your user Path after
  `uninstall`, and each `install` added it again. A receipt says it was taken out only when it was.
- **After trocar removed itself, the receipt names no trocar command.** Its last line said to run
  `trocar uninstall --purge-data`, which was just removed. It now names the kept folders to delete by hand.
