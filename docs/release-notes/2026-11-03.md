# 2026-11-03

## The board

- **The keyboard list closes when you leave the replay.** Pressing `?` on the replay opens the list of its keys. Going
  back or following a link to another page while that list was open left it over the next page, listing step keys
  where there are no steps. It now closes when you leave the replay.
- **A confirmation closes when you leave its page.** A confirmation left open on Settings > Storage, Capture or the
  Overview stayed over the next page after Back or a link, and its OK went to a page that was already gone. Every
  dialog, confirmation and popover now closes with the page it was opened on; a confirmation closed this way counts as
  Cancel and changes nothing.
- **Opening a session no longer reads its summary twice.** The first read of a session whose summary file was not yet
  written came back without a version tag, so the next refresh read the whole summary again. That first read now
  carries the file's tag, and the next refresh of an unchanged session is answered "not modified".

## Installing and removing

- **The marks trocar leaves in your agents' files name commands that exist.** The marked lines and blocks
  (Codex's and Hermes's `.env`, the DeepSeek `cordis.patch.yml` row, the Kimi `PATH` line, a block in your own
  certificate file) used to say `trocar collector uninstall` removes them. New ones name `trocar uninstall`, or
  `trocar off` for a proxy block. What an earlier version wrote is still found and removed the same way, and
  `install` and `on` do not rewrite an entry only because its mark has the old words.
- **A command to paste is printed whole, on a line of its own.** The `sudo ... setup-helper` line of `trocar on` (helper
  missing) and the `sudo ... setup-helper --remove` line of `trocar uninstall` (helper still installed) were folded at
  80 columns, so a paste ran `sudo` alone. In `--json`, they are the row's `command`: `blocked[].command` for `on`,
  `left[].command` for `uninstall`.
- **Receipts show every path in your home as `~/...`.** The macOS install receipt printed the PATH and login-item
  rows as absolute paths while the rest said `~/`. The line to run if trocar itself breaks now reads
  `~/.trocar/bin/trocar-off` too. A `sudo` line keeps the absolute path, and on Windows the line is unchanged
  (`node "C:\Users\...\.trocar\bin\trocar-off"`). In `--json`, `standalone` is still the absolute path.
- **`trocar uninstall` names what it kept.** Its last line said "Delete the captured records" even when only trocar's
  own record (`~/.trocar/collector/flows/`) was kept. It now lists what is kept, which is what `--purge-data` deletes,
  and says nothing about it when nothing is kept.
- **The refusal of an older install record fits the screen.** `trocar install` and `trocar on` printed it as one long
  line with absolute paths. Like `uninstall`, they now fold it at 80 columns, show `~/...` and print each command on
  a line of its own. A folded sentence keeps its first line's indent everywhere (`off` too), so a command, indented
  two spaces, never sits beside a folded sentence at the same indent.
- **`trocar on` says each route once, and its last lines do not run together.** With `--yes`, the
  `codex: route ...` line was printed in the plan and again in the receipt; it is now in the receipt only (a
  `--dry-run` still shows it). The closing `Status: trocar status` and `Remove trocar: trocar uninstall` are now
  on a line each: folded together, they read as one sentence.
- **`sudo trocar setup-helper` says what it installed.** It printed `installed <path> (<path> <capabilities>)`. It
  now prints one sentence, "Installed the capability helper `<path>` with the capabilities `<capabilities>`."

## Status

- **`status --failures` prints the command in a reason whole.** On Linux, the reason of a stopped or wrong-version
  capability helper ends with the `sudo ... setup-helper` line, and `--failures` cut it after 100 characters. The
  reason is still shortened, at a word boundary, with each command in it said as "the line below" ("the lines below"
  for two), and each command is printed whole on a line of its own below it. A reason that starts with its command
  keeps the words after it.
- **On Linux, the helper has one name.** Messages called it the capability helper, the capture helper, the redirector
  helper or the kernel helper. They now all say capability helper. A stop that Windows can report too says trocar's
  helper.
- **A helper problem that was fixed no longer keeps capture health at "failing".** On Linux, after the capability
  helper was installed and `trocar on` succeeded, `trocar status` still said failing for up to a day. The record of
  the failure stays (`status --failures`, `--json` `failures.groups`) as a note. The same is true when trocar's CA
  or `agents.json` is usable again. If the problem comes back, it counts again.
  A restart that finds the problem gone (the helper installed, then a reboot or `trocar install` again) ends it too.

## Removing a script install

- **On Linux, a capability helper still installed keeps everything `uninstall` would need next time.** The code, the
  `trocar` launcher and the PATH item stay, so `trocar uninstall` still runs from a new terminal after the
  `sudo ... setup-helper --remove` line. With `--purge-data`, no captured record is deleted in that run; before, the
  records were deleted and the run still exited 1.
- **After trocar removed itself, the receipt names no trocar command.** Its last line said to run
  `trocar uninstall --purge-data`, which was just removed. It now names the kept folders to delete by hand.
