# asight · RFC 4.4 — 本地服务(看板的 HTTP 面与控制面)

> **服务意图(A2)**:把具名查询([3.5](3.5-query-layer.md))的文档通过 loopback 交给自建前端;看板是 `asight query` 的 HTTP 外壳,不是第二条读路径(D59),由守护进程托管(D66)。
> **受众**:人(核对数据只读、控制面的门与不被外部网页读到)+ agent(据此实现守护进程的 HTTP 面与控制面)。
> **前置**:查询集与文档形状在 [3.5](3.5-query-layer.md) 与 [1.6](1.6-cli.md) §4.1 / 附录 C;记录与段在 [4.2](4.2-storage-etl.md);守护进程与它的控制面在 [4.6](4.6-process-collector.md)。
> **决策**:D11(服务端执行查询、HTTP 返 JSON)· D26(控制面的写只调 CLI 同一批函数)· D59 · D61(守护进程登录自启)· D63(查询归守护进程的工作进程)· D64(看板的性能线)· D65(装的生命周期)· D66(看板归守护进程)。

## Goal
守护进程在 `http://127.0.0.1:<port>` 上托管看板:静态文件 + `GET /api/<名字>`(具名查询的文档)+ `GET /control/status` 与 `POST /control/*`,外加挡住别的网页读你语料的 Host / Origin 门和每用户口令。**没有别的东西**。`asight install` 之后看板一直在(守护进程每次登录都起来,D61);`asight board` 只是把带口令的网址印出来并打开浏览器([1.6](1.6-cli.md) §4.3)。

## 前置定义(Definitions)
- **数据面** = `GET /api/<名字>`,参数来自 query string,文档逐字段等于 `asight query <名字>`(验收 V80)。
- **静态面** = 前端目录内的文件(`src/web/`),加一份**共享模块白名单**:浏览器与 CLI 必须用同一个事实的那几个模块,守护进程按它们在仓库里的路径发出去(都从内存里发)。白名单只收**零依赖的纯模块**(只有常量与纯函数,不 import `node:*`、不读盘、不联网),现在是 `src/cli/words.mjs`(`FAILURE_WORDS` 与 `failureBrief`:采集失败的闭集词与一组失败的那一句,命令行与看板同一句,0.1 §2 一个外部事实只写一处)与 `src/off/token-header.mjs`(口令头名;`src/off/control-client.mjs` 与守护进程的控制端点都从它 import,所以头名只写一处)。**MUST**:白名单是数据(一张表),不是每加一个模块就改一处路由;表外的路径一律 404;表里的模块 MUST NOT import `node:*`,且对 import **闭合**——表里模块 import 的每个模块也在表里(浏览器会去取每一个 import;守卫测试逐个读它们的 import 并断言两条)。网址就是它在 `src/` 下的相对路径(`/cli/words.mjs`、`/off/token-header.mjs`):前端目录 `src/web/` 发在 `/`,页面里 `../../../cli/words.mjs` 这类相对 import 在浏览器里解析出来的正是这个网址(依据 = 本条「按它们在仓库里的路径」+ 浏览器的相对网址解析)。这样前端不必把这两个事实抄第二遍(违 0.1 §2),也不必为了读它们开一个数据面端点。
- **控制面** = `GET /control/status` + `POST /control/*`,每个写端点只调 CLI 同一批函数(D26)。
- **门** = Host allowlist + Origin 校验,三个面都过;数据面与控制面另要每用户口令(D26③)。
- **stamp** = 一个名字的答案所依赖的那些**文件的身份**的摘要(不是文档本身的摘要),答案里读了 `now` 的名字再加一个**分钟刻度**;住查询层,是 ETag 的值。

## Plan(选定方案 + 取舍)
**选定(D66)**:**看板归守护进程**。守护进程的事件循环只做四件事:① 从内存里发静态文件;② 用 stat 算出的 stamp 直接答 304,**不唤工作进程**;③ 把 `GET /api/<名字>` 原样转给查询工作进程,与 `GET /query` 同一条路(D63:字节转发,守护进程既不 parse 也不 stringify 大文档);④ 把 `/control/*` 转给工作进程,由它调 CLI 同一批函数。工作进程在页面加载时 fork,页面还在轮询期间一直活着,页面走了之后闲几分钟退出(D63①)。**D63① 不破**:查询仍不在守护进程自己的循环里算,它每条请求的份额仍是 ≤ 5 ms([1.6](1.6-cli.md) §4.1)。
**外壳只做三件事**:把 query string 变成查询参数、把文档的字节交出去、挡住跨源读取。**MUST NOT** 在外壳里写第二套取数逻辑、第二套分页、或任何缓存真相。
**备选(未选)**:① **单独一个 `asight serve` 前台进程**——不选:前台进程要用户自己起,看板就不是「装完就在」,而守护进程已经为 `on` 跨开关机而登录自启(D61),再加一个要自启、要收尾、要开关的常驻件是多一份状态;② **另起一个专门的后端进程**——同上,且没有任何新能力;③ 浏览器内查询引擎(D11 的 (B))——装载与内存代价大、把存储细节推向前端,记为 Extension;④ 只读看板、在改状态处印出要敲的命令——未选(开关要能真开关)。
**端口**:看板的端口与门的端口一起持久在 `~/.asight/collector/ingress.json`,所以网址稳定、可以收藏(口令在 fragment 里)。**端口由 `install` 选**(第一次选,之后沿用;从 9800 起往上取第一个空着的端口,到 9899 为止,这一段是 `ingress-config.mjs` 里的一个常量;一段都占满时 `install` 把这一项记成 pending 并说原因),守护进程只读、从不另选——与门的端口同一条规矩([4.11](4.11-collector-model.md) §3 ①),所以 `install` 之后不跑别的命令看板就在(验收 12)。守护进程的 `/status`(控制端点)回答带看板监听的端口与状态(`board:{port, state, reason}`,`state` ∈ `serving` · `port-taken` · `no-port`),`asight status` 据此印 Board 一行、给出 `--json` 的 `board`,地址不带口令([1.6](1.6-cli.md) §3.5 · C.3 · V90)。口令只在控制端点的 `GET /board` 上答(`{port, state, reason, token}`;控制端点本来只有本用户够得到,[4.6](4.6-process-collector.md) §控制面):`asight board` 经它取口令,所以印出的永远是守护进程手里正在核对的那一份,口令文件被换过也对得上(依据 = 1.6 §3.5「口令只由 `asight board` 印」+ 本节「口令不进 status」)。
**取舍**:外壳越薄,`query` 与看板越不可能漂移;CLI 与看板只有一个实现要测(V80)。

## 服务形状
- **零依赖 · loopback · 守护进程托管**:只用 `node:http/fs/path`,`listen(port, '127.0.0.1')`。所有响应 `content-type: application/json; charset=utf-8`(静态文件按扩展名)+ `cache-control: no-store`(条件 GET 走 ETag,不走 HTTP 缓存)。
- **反 DNS-rebind 门 MUST 覆盖数据面**(2026-07-18 对抗评审实测,**必拒**违反):只设在某一类路径上不算。`Host` 不在 allowlist(`127.0.0.1:<port>` / `localhost:<port>`)或带跨源 `Origin` → 403,什么都不读。
- **门的次序(每个请求都走这一条链)**:Host / Origin → 口令 → 名字 → 方法 → 参数。① Host / Origin 不合格 → 403;② 没带或带错口令 → 403;③ 不认识的名字 → 404;④ 方法:数据面与 `GET /control/status` 上非 `GET` → 405,`/control/` 下不是三个写端点的非 `GET` 也一律 405(那些写根本没有端点,§控制面);⑤ 畸形参数 → 400。**前两步没过之前不读任何文件**(验收 2 与 8 注入 fs 断言零读)。
- **每用户口令(D26③)**:32 个随机字节的 base64url,存在 `~/.asight/collector/board.token`(0600)里,**持久**——守护进程重启仍是同一个口令,所以看板的网址可以收藏;守护进程托管看板时读它,文件不在就生一个(只有守护进程写它)。`asight board` 印的网址把它放在 **fragment** 里(`#t=<口令>`):fragment 不随请求发出去,不进服务、代理或任何日志;页面读 `location.hash`、`history.replaceState` 抹掉它,收在 `sessionStorage`。每个 `/api/*` 与 `/control/*` 请求用**同一个头名常量**(`CONTROL_TOKEN_HEADER`,住 `src/off/token-header.mjs`;两个秘密不同,头名只写一处)带它,它同时就是 CSRF 口令。**静态面不门口令**——页面得先加载才知道口令,所以前端目录里 **MUST NOT** 有任何采集到的数据(它就是一份静态包)。口令文件随 `uninstall` 一起撤。带了口令的 `curl` 也读得到数据面,没带就读不到——这正是 D26③ 要的(环回不分系统账号)。
- **条件 GET(ETag / `If-None-Match`)**:每个 `GET /api/<名字>` 回 `ETag: "<stamp>"`;请求带的 `If-None-Match` 与它相同 → **304、空体、零语料读、不唤工作进程**。stamp **只由 `stat` 算**(大小 + mtime + ctime),**MUST NOT** 先算出文档再 hash(那只省带宽,不省一分计算);**答案里读了 `now` 的名字,把 `floor(now / 60 s)` 也折进 stamp**(依据:不变式 4 与本节下面那句「漏了一个依赖 = 看板永远显示陈旧数据」——时钟就是这些名字的一个依赖,而把它当依赖并不要求读任何语料,所以 stamp 仍然只是几十次 `stat` 加一次 sha1)。它住**查询层**:每个名字在 `QUERIES` 里与 `params` / `run` 并列一个 `stamp(ctx)`;外壳只比字符串——否则外壳就持有了第二份「这个文档依赖什么」的意见,两份一定漂(也违「外壳只做三件事」)。每个名字的来源:

  | 名字 | stamp 算哪些东西的身份 |
  |---|---|
  | `sessions` `session` `calls` `block` `segments` `traffic` `overview` | `raw/` 里的段名单 + 每个段的 `<段>.ndjson` 与它的封存文件 |
  | `classes` | 上行那些 + `~/.asight/classes.json` + `~/.asight/logs/classes.ndjson` + **分钟刻度**(它的 `counts` 把 24 h / 7 d 对着 `now` 算);`disk` 读整个 `~/.asight`,它的陈旧同样以这一个分钟刻度为上限(依据:本节陈旧上限——给 `disk` 单独算整棵树的身份要遍历全部文件,一次 304 就不再只是几十次 `stat`) |
  | 任何名字,给了**相对**的 `--since` / `--until`(`24h` 这类)时 | 该名字上面那些 + **分钟刻度**(窗口的两端跟着 `now` 走;给的是绝对时间时不加,窗口不动) |
  | `pricing` | 价格文件(内置的那份,或 `ASIGHT_PRICING` 指的那个) |
  | `status` `doctor` | **不带 ETag**:它们读的是机器此刻的实况(进程、信任库、守护进程),不是盘上的语料,永不 304 |

  漏了一个依赖 = 看板永远显示陈旧数据而且什么都不报(违不变式 4),所以验收 9 要每个依赖各一个用例。一次 304 只花几十次 `stat` 加一次 sha1,不读记录、不返体。

  **陈旧上限**:只因为时钟走了而过期的答案,最多陈旧**一个分钟刻度(≤ 60 s)**——下一次轮询(`status` 5 s、别的名字 3–30 s)落在新刻度上,stamp 就变了,于是「一条新记录都没有、但记录正在滑出 24 h 窗」这件事照样会被看到。刻度取 60 s 是因为看板上没有一个数的精度细于一分钟(相对时间、窗口端点都按分钟显示),取更细只会让 304 白白失效。
- **live-poll**:传输无状态,每个请求独立返当前快照;前端轮询驱动「空 → live 无缝转正」([1.5](1.5-states-aesthetics.md))。间隔:

  | 看什么 | 名字 | 间隔 |
  |---|---|---|
  | 采集健康(卡片与每个 agent 的行) | `status` | **5 s**,窗口重新获得焦点时立即一次;**标签页隐起来时暂停**。它没有 ETag,是最贵的一次轮询(枚举进程 + 一次守护进程往返),所以不得更快:看板开着轮询时守护进程仍要守住 D62④ |
  | 会话列表 | `sessions` | 3 s(没有新记录就是 304) |
  | 打开着的会话的尾巴 | `session` | 1.5 s(stamp 是语料级的,别的会话追一条也会打掉 304,代价是一次温查询;per-session stamp 记在 Extensions) |
  | 其余 | `classes` `pricing` `segments` `traffic` `overview` | 打开时、窗口状态变时、每 30 s |
- **第一次点开会话不落在冷路径上(D64①)**:页面一加载,守护进程就 fork 工作进程并让它跑那一页要的 `sessions`——用户还在看首页时工作进程已经温了;工作进程在页面轮询期间不退。
- **只读**:数据面 MUST NOT 写记录、不删、不改。唯一会落盘的是可删可重建的段索引 `~/.asight/index/`([4.2](4.2-storage-etl.md));写侧只有守护进程(追加)与封存器(无损替换)。服务改写源 = 违不变式 2 → **必拒**。
- **永不 originate 上游请求**:D30 的修改与重发经守护进程的控制端点,不走看板这一面。
- **路径安全**:静态只发前端目录内的文件,拒 `..`;读哪些记录文件由查询决定,不由请求里的路径决定。
- **人类标题的来源(保真边界)**:会话显示名可以来自被测 harness 自己的本地存储(如 `~/.claude/projects/.../*.jsonl`),它**不是采集到的线上字节**,查询文档里就地标明来源([3.5](3.5-query-layer.md) 的 `sessions`)。
- **provider 中立**:响应只讲 [3.2](3.2-normalized-model.md) 的 canonical 词汇,provider 原生字段只在 `extra` 里。
- **健壮性**:看板这一面出的 `uncaughtException` / `unhandledRejection` 记日志但不弄倒守护进程(仪器要在长采集里活着)。**端口起不来不拦采集**:守护进程照常转发 agent 流量,这件事进 `status` 与一条带原因的持久记录(D38),`asight board` 印出原因;不偷偷换端口。
- **Linux 的已知缺口**:驱动模式下不带名字的 `off` 仍让守护进程排空后退出(D62⑥),守护进程一走看板也就没了,直到下一次 `on`。macOS / Windows(代理模式)不受影响——那里的 `off` 从不请守护进程退出。缺口记在 backlog 那条做完三个平台同形。

## 控制面(D26)
- **默认可用,门是同一条链**(D26①):`GET /control/status` 与 `POST /control/*` 与数据面一起在,过同一个 Host / Origin 门和同一个口令;没有另一个要操作者先打开的开关。写仍然只出于操作者在页面上的点击(不变式 1 · D30):控制面 **MUST NOT** 自己推导出任何改动。
- **守护进程以 root 跑时整个控制面不挂**:`on` / `off` 本来就拒绝 root([1.6](1.6-cli.md) §1.5),数据面只读所以照旧;`GET /control/status` 回 `{control:false, user, root:true, harnesses:[]}`,页面据此说明为什么没有开关;三个写端点不挂,落到 405。比让每个端点各自拒绝更省、更清楚。
- 四个端点,就这些:

  | 端点 | body | 调谁 | 回执 |
  |---|---|---|---|
  | `GET /control/status` | — | 什么都不写 | `{control:true, user, root:false, harnesses:[{harness, desired, setup}]}`;`setup` 的取值与来源见 [1.6](1.6-cli.md) 附录 C.3 |
  | `POST /control/classes` | `{kind:'set'\|'add'\|'rm'\|'reset', class?, keep?, host?, path?, harness?, rule?}` | `src/classes/table.mjs : edit(op, {home})` —— `asight classes` 的同一个写者,op 的形状就是这个 JSON | C.2 的 `classes` 回执 |
  | `POST /control/harness` | `{harness, on, confirm?}` | `src/cli/on-model.mjs : runModelOn(…)` / `src/off/orchestrate.mjs : runOff(…)` —— `asight on` / `off` 调的同一个函数(**不是**它们的 argv 外皮) | C.2 的 `on` / `off` 回执 |
  | `POST /control/setup` | `{harness, confirm?}` | `install` 的同一个函数,只补这个 harness 缺的证书载体(幂等,V67) | C.2 的 `install` 回执 |
- **先计划后确认**(1.6 §1.4,由构造满足):
  ```
  POST /control/harness {harness:'codex', on:false}
    → 409 {need:'confirm', plan:[{path, how, harness}…], receipt:<dry-run 的回执>, plan_id:<planned 的 sha256>}
  POST /control/harness {harness:'codex', on:false, confirm:'<plan_id>'}
    → 200 <C.2 的真回执>
  ```
  计划**不是重新推导的**,就是 dry-run 回执自己的 `planned[]` 字节。`plan_id` 对不上(两次请求之间机器变了)→ 409 带**新**计划,一个字节都不改;这是浏览器给 CLI 协议加的唯一一样东西(一次 sha256)。`POST /control/setup` 与 `/control/classes`(改动类的 op)走同一套。
- **没有 `install` / `uninstall` / 自启 / 证书整装 / 提权助手的端点**(D55① · D61 · D53 · D65③):不是「挂着但拒绝」,是**根本没有**,所以 405 的只读规则继续覆盖它们。`POST /control/setup` 是唯一与装有关的写:它只补这个 harness 缺的那几项,且只在 `status` 说这个 harness 需要时才在页面上出现(D65④)。
- **调的就是 CLI 那批函数**:不构造 argv、不另写一套校验(`ClassArgError` / `QueryArgError` → 400,与数据面同一处);`io` 是缓冲区,CLI 自己的文字进回执的 `notes`,不上守护进程的 stdout。备份与事件由那些函数自己写(D39③),端点 **MUST NOT** 预建或清理 `~/.asight/backup/` 里的东西;端点只在传下去的 op 上加 `source:'board'`,于是每次改动在日志里都认得出是从看板来的。
- **Set up 的三件实话**(就地写进回执与页面):根已经被信任时不弹框(V67:只补缺的载体);真要弹框时,OS 的框**不能**归因于网页里的一次点击,没有图形会话时可能根本不弹 → 回执如实记 pending,并给出要在终端里跑的 `asight install`;**MUST NOT** 在后台替用户改刚装好的程序的文件(D43 · D65④)。

| 落点 | 文件 : 符号 | 承担本单元的什么 |

## 验收(可跑 check)
- 上表十三条,都在 `npm test` 里。
- 速度:看板的每个请求就是对应查询的耗时([1.6](1.6-cli.md) §4.1 的目标),外壳自身不引入额外的整文件读取或缓存层;看板上的交互按 **D64** 量(打开会话 ≤ 0.5 s、换 step ≤ 50 ms、其余按钮与面板 ≤ 0.5 s,p50 与 p95 都算),达不到就按 D64⑥ 报出来。
- 工作进程:页面加载时 fork 并热起来,页面轮询期间不退;守护进程自己的循环每条请求 ≤ 5 ms(D63①)。

## Edge cases
- **没有数据**:每个端点返空文档(`page.has_more:false`),不 500、不返空字符串。
- **索引被删**:请求照样成功(重建),只是慢。
- **同一台机器上几个系统用户共用 `127.0.0.1`**(D36 引出):环回不分用户,A 的服务在端口上开着时 B 能读到 A 的逐字语料(含活凭据)。**已定**(D26③):每用户一份持久口令(0600,`~/.asight/` 下),`asight board` 印出带它的网址;没带口令的 `/api` 与 `/control` 请求一律 403;端口照旧。
- **端口被占**:看板这一面起不来,采集照常;原因进 `status` 与一条持久记录(D38),`asight board` 照实说,不换端口。
- **还没 `asight install`**:守护进程没在跑,看板也就不在;`asight board` 说要先 `asight install`(D65②)。这台机器上早先采过的数据在 `install` 之后照样能翻(`uninstall` 默认留 `raw/`)。
- **`uninstall` 之后**:看板随守护进程一起消失;页面上最后一次轮询失败,显示终局状态而不是一直转。

## Risk / 回滚
数据面是纯读:出问题就不开看板,`asight query` 照样能用,数据零影响。控制面只调 CLI 那批函数并先回计划:出问题就不点,改状态照样走 CLI。看板这一面挂在守护进程上,所以它的错**MUST NOT** 弄倒转发:每条路由各自收敛异常,端口起不来只少一个看板。

## OPEN
无。

## Extensions
- 浏览器内查询引擎(D11 的 (B)):判据触发才做,前端契约不变。
- **SSE / WebSocket 推送代替轮询:不做**。一次 304 只花几十次 `stat` 加一次 sha1,省下的那点开销换来的是一个**有状态的外壳**(谁订阅了什么),违「外壳只做三件事」,而守护进程的循环更不该长出订阅表。判据:304 的轮询在剖析里真成了瓶颈。
- **一个 `/api/version` 一次返回所有 stamp(每 tick 1 个请求而不是 3 个):不做**。那会是 CLI 不印的第 12 个文档(D24:没有看板专用文档),要合法就得占一个查询名字。判据同上。
- **per-session stamp**(只看那个会话自己的行):语料级 stamp 会被别的会话的追记录打掉;剖析要求时再做。
