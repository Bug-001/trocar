# asight · RFC 4.4 — 本地服务(只读 HTTP 外壳)

> **服务意图(A2)**:把具名查询([3.5](3.5-query-layer.md))的文档通过 loopback 交给自建前端;看板是 `asight query` 的 HTTP 外壳,不是第二条读路径(D59)。
> **受众**:人(核对只读边界与不被外部网页读到)+ agent(据此实现 `src/server.mjs`)。
> **前置**:查询集与文档形状在 [3.5](3.5-query-layer.md) 与 [1.6](1.6-cli.md) §4.1 / 附录 C;记录与段在 [4.2](4.2-storage-etl.md)。
> **决策**:D11(服务端执行查询、HTTP 返 JSON)· D26(看板只读,改状态只经 CLI)· D59。

## Goal
`asight serve [--port <port>]` 起一个零依赖单进程服务:`GET /api/<名字>` 返具名查询的文档,外加前端静态文件,以及防止别的网页读到你的语料的 Host / Origin 门。**没有别的东西**。

## 前置定义(Definitions)
- **数据面** = `GET /api/<名字>`,参数来自 query string,文档逐字段等于 `asight query <名字>`(验收 V80)。
- **静态面** = 前端目录内的文件(`src/web/`)。
- **门** = Host allowlist + Origin 校验,数据面与静态面都过。

## Plan(选定方案 + 取舍)
**选定**:服务端执行查询、HTTP 返 JSON(D11)。外壳只做三件事:把 query string 变成查询参数、把文档序列化、挡住跨源读取。**MUST NOT** 在外壳里写第二套取数逻辑、第二套分页、或任何缓存真相。
**备选(未选)**:① 浏览器内查询引擎(把数据灌进浏览器)——装载与内存代价大、把存储细节推向前端,记为 Extension;② 服务端写接口(改设置、开关采集)——D59③ 删掉:看板只读,改状态只经 CLI(`asight classes` / `asight on` / `off`),看板在该处印出要敲的命令。
**取舍**:外壳越薄,`query` 与看板越不可能漂移;CLI 与看板只有一个实现要测(V80)。

## 服务形状
- **零依赖 · 单进程 · loopback**:只用 `node:http/fs/path`,`server.listen(port, '127.0.0.1')`(`--port`,默认见 `src/paths.mjs`)。所有响应 `content-type: application/json; charset=utf-8`(静态文件按扩展名)+ `cache-control: no-store`。
- **反 DNS-rebind 门 MUST 覆盖数据面**(2026-07-18 对抗评审实测,**必拒**违反):只设在某一类路径上不算。`Host` 不在 allowlist(`127.0.0.1:<port>` / `localhost:<port>`)或带跨源 `Origin` → 403,什么都不读。
- **只读**:服务 MUST NOT 写记录、不删、不改。唯一会落盘的是可删可重建的段索引 `~/.asight/index/`([4.2](4.2-storage-etl.md));写侧只有守护进程(追加)与封存器(无损替换)。服务改写源 = 违不变式 2 → **必拒**。
- **永不 originate 上游请求**:D30 的修改与重发经守护进程的控制端点,不走本服务。
- **路径安全**:静态只 serve 前端目录内文件,拒 `..`;读哪些记录文件由查询决定,不由请求里的路径决定。
- **人类标题的来源(保真边界)**:会话显示名可以来自被测 harness 自己的本地存储(如 `~/.claude/projects/.../*.jsonl`),它**不是采集到的线上字节**,查询文档里就地标明来源([3.5](3.5-query-layer.md) 的 `sessions`)。
- **provider 中立**:响应只讲 [3.2](3.2-normalized-model.md) 的 canonical 词汇,provider 原生字段只在 `extra` 里。
- **live-poll**:传输无状态,每个请求独立返当前快照;前端轮询驱动「空 → live 无缝转正」([1.5](1.5-states-aesthetics.md))。
- **健壮性**:`uncaughtException` / `unhandledRejection` 记日志但不倒(仪器要在长采集里活着);`EADDRINUSE` 明确报错退出,不静默半死。

## Out-of-scope
查询取什么([3.5](3.5-query-layer.md))、记录形状([3.2](3.2-normalized-model.md))、存储与封存([4.2](4.2-storage-etl.md))、采集([4.1](4.1-capture-sources.md))、前端渲染(2.x)、改状态的命令([1.6](1.6-cli.md))。

## 影响面
前端的唯一取数通道。改门、改路由形状 = 改前后端接缝,要同时改 [1.6](1.6-cli.md) §4.1 与前端。

## 验收(可跑 check)
- 上表七条,都在 `npm test` 里。
- 速度:看板的每个请求就是对应查询的耗时([1.6](1.6-cli.md) §4.1 的目标),外壳自身不引入额外的整文件读取或缓存层。

## Edge cases
- **没有数据**:每个端点返空文档(`page.has_more:false`),不 500、不返空字符串。
- **索引被删**:请求照样成功(重建),只是慢。
- **同一台机器上几个系统用户共用 `127.0.0.1`**(D36 引出):环回不分用户,A 的服务在端口上开着时 B 能读到 A 的逐字语料(含活凭据)。**推荐默认**:按用户随机端口 + 按用户随机 token,写进 `~/.asight/`(0600),看板 URL 带它。见 OPEN。
- **端口被占**:报一行并退出,不换端口(用户下次自己给 `--port`)。

## Risk / 回滚
外壳是纯读:出问题就不开看板,`asight query` 照样能用,数据零影响。

## OPEN
- **同机多用户的隔离**:按用户随机端口 + token 是推荐默认,**未定**;定之前文档里就写明「同机其他用户能读到」(不变式 4)。

## Extensions
- 浏览器内查询引擎(D11 的 (B)):判据触发才做,前端契约不变。
- SSE / WebSocket 推送代替轮询:仍是同一组文档。
