# asight · RFC 5.1 — asight 的另一面(预留:自动适配 + 主动干预)

> ⚠️ **预留单元 · 非 v1 · 不落代码**。本文件**只**做三件事:圈定 asight 的第二形态(「另一面」)、把 OBSERVE-only 重定为**模式边界**(承 [00-overview](00-overview.md) **D16**)、**预留架构缝**使未来可能而今不破。**任何主动发请求 / 改包的实现 MUST NOT 依据本文件动手**——须先开**专门下游 build-RFC** 并拿到**被测软件消费者的显式授权**。在那之前,主动干预一切能力 = **必拒**(承不变式 1)。
> **受众**:人(定方向、把关不变式)+ agent(据「预留缝」在改采集/适配/schema/服务时**不把观测形态焊死**、也**不偷偷长出主动能力**)。
> **前置**:观测形态全套 = [1.x](1.1-product-definition.md)–[4.x](4.4-server.md);采集缝 = [4.1](4.1-capture-sources.md);适配契约 = [3.1](3.1-adapter-contract.md);归一化 = [3.2](3.2-normalized-model.md);服务 = [4.4](4.4-server.md)。

## 为什么有这一面

今天的 asight 是**透明示波器**——把 agent 真正发给大模型的每一比特按步回放、拆解(意图 ①②)。漂亮,但**只看不动**。真正反哺 agent 开发工作流的那一步,是让它从「看」走到「用」:任何人做一款 agent 软件,把流量导进 asight,就能

- **① 自动适配(auto-adapt)**:asight 从**原始流量**自动侦测 provider 线格式 + harness 约定,少写 / 免写手工 adapter 就点亮面板。**仍是观测**——只是更聪明的观测,**不破 OBSERVE-only**。
- **② 主动干预(active intervention · "agent 界 burpsuite")**:在被测 agent 与上游之间**拦截**一条消息、**改**它、**注入 / 重发**——给一个 debugger agent 一套实在的接口,快速定位性能 / 行为 / 上下文问题,甚至做受控实验。**这一步破 OBSERVE-only**,是本文件的核心张力。

两者是同一愿景的两面(承 [00-overview](00-overview.md) **D16**、[1.1](1.1-product-definition.md):65 早已预告的「基于流量的注入/改写须走新 RFC」),故合并预留、不拆分单独立项。

## 模式边界(D16 · 不变式 1 的重定)

OBSERVE-only 从**绝对律**改为**模式边界**——但**今天的护栏一格不松**:

- **观测模式(observe · 默认 · v1 全部 · 唯一已建)**:恒 OBSERVE-only——永不 originate 请求、永不注入 / 改写流量、永不用被测程序 token 发起调用。模式内任何「主动发请求 / 改包」= **必拒**(不变式 1 在此模式内**原样生效**)。这是 asight 至今的全部,且**默认永远是这个模式**。
- **主动模式(active · 第二形态 · 未 v1)**:可拦截 / 改 / 注入 / 重发 + auto-adapt。它是**独立、显式、消费者授权、非默认**的能力,**MUST** 满足下述**四道门**才可能存在;不满足即回落必拒。

**为什么这条线不能软**(把它写死,免得日后被「顺手加个小改包」侵蚀):
1. **信任边界**:被测程序把流量交给 asight 是为了「被看」,不是「被替它说话」。主动发声越过了这个默认授权——故须**消费者(被测软件的开发者)显式、就事、可撤销地授权**,不是 asight 单方开关。
2. **token 安全**:主动模式**仍 MUST NOT 用被测程序的 token 冒名发起请求**(承不变式 1 的这一条**不随模式松动**);要发,用调用方自证的凭据,且 UI/记录里**标明这是 asight 主动发的、非被测程序原生流量**。
3. **源真相不被污染**:被拦下 / 被改 / 被注入的消息,**原始 bytes 仍是逐字源真相**(不变式 2);主动模式 MUST **两份都存**——原始 + 改后 + 一条 intervention 事件,**MUST NOT** 用改后覆盖原始、**MUST NOT** 让人误把注入的当成被测程序原发。
4. **模式隔离**:观测模式的纯粹性 MUST NOT 被主动模式污染——**独立源类型 + 独立服务 / 进程 / 模式 + 授权门**;观测产品里 MUST NOT 留任何「回放即重放到上游」的口子(承 [4.4](4.4-server.md):34)。

## 预留的架构缝(标 where it plugs · 不建 mechanism)

下面每条只**预留接缝**——让未来的 build-RFC 有地方插,同时约束**今天改这些层时不要把观测形态焊死、也不要偷偷长出主动能力**。

- **采集缝([4.1](4.1-capture-sources.md) · 最关键)**:今天所有采集源(MITM / base_url 反代 / relay-tee)是**被动**的——只 tee 字节、永不 originate。主动模式 = 一个**新的 active-relay 源类型**:它坐在被测 agent ↔ 上游之间,能 hold / modify / inject。**预留约束**:① 它是**独立源类型**,与被动源**不共代码路径**(被动源 MUST 保持「永不 originate」平凡成立);② 它**默认关**,开启须消费者授权门;③ 它 MUST 复用同一**统一原始信封**(D10)吐记录,外加 intervention 元数据。**今天改 4.1 采集源接口时,MUST NOT 假设「源必被动」到无法容纳未来 active 源**——但也 **MUST NOT** 现在就给被动源加 originate/inject 能力。
- **适配缝([3.1](3.1-adapter-contract.md) · auto-adapt)**:自动适配 = 在 adapter 契约上加一层**自动侦测启发式**(从原始流量猜 provider 线格式 + harness 约定,回落到手工 adapter)。**仍 OBSERVE-only**,可作 3.1 的 Extension 独立推进(见该文件 Extensions)。**预留约束**:auto-detect MUST 只读、只猜、可被人工 adapter 覆盖;侦测结果是**派生推断**,UI 标「自动推断,可能不准」(承不变式 4)。
- **归一化缝([3.2](3.2-normalized-model.md))**:主动模式产生新事件类型——一次**被改 / 被注入 / 被拦**的调用。**预留**:未来加一张 `interventions`(或 `calls.intervention` 标)记 {原始 ref, 改后 ref, 动作, 授权凭据 ref, 时刻},**原始与改后各存一份**(源真相不丢)。今天的 schema **无须**加这些字段,但**加字段 / 改 schema 时 MUST 留意**别把「一次 call 恒等于一次被动观测」写成无法扩展的硬假设。
- **服务 / 模式缝([4.4](4.4-server.md))**:观测 server 是**只读、拉不推、不 originate**(4.4:15/32/34)。主动模式 = **独立服务 / 进程 / 模式**,**MUST NOT** 在只读观测 server 上开重放到上游的口子。**预留约束**:4.4 的只读契约**不变**;主动能力另起门户。
- **授权门(横切)**:主动模式的每个「改 / 注入 / 发」动作 MUST 经**消费者显式授权**(就事、可撤销、可审计),且**记录**该授权。授权 MUST 来自被测软件的**开发者本人**,不是 asight 内部配置项。

## Non-Goals(本预留单元内 · 越界即自我否决)

- **不实现任何主动能力**:本文件 0 行落地;主动模式须专门 build-RFC。
- **不弱化观测模式**:观测模式的 OBSERVE-only 护栏**一格不松**;本预留 MUST NOT 被当作「现在可以试着改个包」的许可。
- **不发明伪授权**:不把「配置里打个勾」当消费者授权;授权是外部、显式、可撤销的。
- **不碰 token 冒名**:任何模式都 MUST NOT 用被测程序 token 冒名发起请求(不变式 1 此条无模式豁免)。

## 触发条件(何时把预留变成 build-RFC)

当出现**明确的消费者场景 + 授权模型 + 安全评审**三者齐备时,开一个下游 **build-RFC**(类比 [D7](00-overview.md) 自演化的「单独立项」),在其中:① 定 active-relay 源的具体机制与授权门;② 定 intervention schema;③ 过 OBSERVE-only 模式隔离的对抗性验收(证明观测模式纯粹性未被污染);④ 定改包 / 注入的伦理与安全边界(授权上下文 = 开发者调试自己的 agent,**非**对第三方 agent 的未授权干预)。**触发前**,本文件是方向锚 + 接缝约束,不是实现许可。

## 安全与伦理(先写死,免得日后含糊)

主动改包 / 注入是**双刃**能力——等价于对一个 agent 的中间人操纵。合法使用面 = **开发者对自己的 agent 做受控调试 / 实验**;越界面 = 对**非自己授权**的 agent 流量做拦截改写(= 攻击)。故授权门 MUST 绑定「被测软件消费者本人」,记录 MUST 可审计,且本能力**默认不存在**(须显式 build + 授权双解锁)。这与本项目的安全立场一致:双用途能力须清晰授权上下文。
