# asight · RFC 2.2 — 步头 · 提问卡 · 调用详情卡

> **服务意图(A2)**:意图 ①(看懂 agent 行为)与 ②(上下文与缓存工程)。回放台中栏顶上一行**步头**:这是第几步、什么时候、哪个模型;这一步的缓存、内容组成、估价各藏在一个按钮后面,悬停、聚焦或点击才展开。对话段里每条提问一张**提问卡**,一眼看出这一轮做了什么。子 agent 与后台调用的一次调用,在调用抽屉里是一张**调用详情卡**。本单元还拥有一个算数模块 `core/metrics.mjs`:缓存判定、缓存断开、多花、估价都只在这里算,步头、会话信息按钮、时间轴、总览页都用它。
> **受众**:人(核对每个数从哪来、哪些是估的、哪些是结构估计,而没有冒充线上真相)+ agent(据此实现步头、三个弹出层、提问卡头、调用详情卡与 `core/metrics.mjs`)。
> **前置**:回放台布局、步的编号(「第 N 步」只指主对话)、弹出层约定、键盘、窄屏在 [1.2](1.2-shell-layout.md);中栏只放步头与 `#ctxwin`、提问卡的折叠(D12)在 [1.4](1.4-central-board.md);块行、变化线、两个对比步(缓存对比步 / 内容对比步)、保真标的证明规则、调用保真行在 [2.3](2.3-context-window.md);lane 种类的词、归行与花费分桶在 [2.1](2.1-track-widget.md);调用抽屉的外壳在 [2.6](2.6-detail-panel.md) §B;词表与标记在 [1.5](1.5-states-aesthetics.md);用量真相在 [3.3](3.3-cache-model.md) Tier 1;服务端补充 `sessions` 的 `title_source` / `usage` 可为 null / 按步的用量字段 / `cacheBreak.refGi` / `flagged` 在 [4.4](4.4-server.md)。决策:D12(折叠记忆)、D14(单价是可编辑配置,估价不进归一化模型)、D17②(段权重与增长)、D18c(看板 v2 成为产品看板)、D37(按厂商计价,仍是 GAP)。

## Goal

回放台中栏只放两样东西:步头与这一步的整个上下文([1.4](1.4-central-board.md))。步头一行讲清「第几步 · 第几次提问 · 什么时候 · 哪个模型」,外加三个小按钮:

- **缓存**:这一步的缓存是什么情况(一句话)、四个用量数、断开时多花多少;
- **组成**:这次请求的内容多大、四段各占多少、比对比的那一步多了多少、主要多在哪;
- **≈ $**:这一步的本地估价,以及按哪个单价算的。

数字和判断都在按钮后面,不占中栏的地方(命不命中不值得在这么紧凑的空间里占篇幅,一个悬停展开的按钮就够)。

对话段的每条提问一张提问卡,卡头一行:提问的开头 · 「调用 N 次工具 · 思考 · 工具结果」 · 「N 块」;点开就是这一轮的块([2.3](2.3-context-window.md))。子 agent 与后台调用的一次调用在调用抽屉里是一张调用详情卡:它是哪类调用、回了什么、用了多少、估价多少、输入是哪些块。

步头、提问卡与调用详情卡都只读、不拥有真相:块的字节归 [2.3](2.3-context-window.md),用量真相归 [3.3](3.3-cache-model.md),原始回复与请求参数归 [2.6](2.6-detail-panel.md) §A。

## 前置定义(Definitions)

- **步头**:回放台中栏的第一个子元素(`#stepbar`,吸顶)。只描述当前这一步,不写会话级统计(会话统计在 [1.2](1.2-shell-layout.md) 会话头的信息按钮里)。
- **三个按钮**:步头上的「缓存」「组成」「≈ $」。每个是一个弹出层按钮,行为按 [1.2](1.2-shell-layout.md) §弹出层(悬停 300 ms、聚焦、点击打开,Esc 与点外面关闭,`role="dialog"`,里面的链接可聚焦)。按钮上的字是这一步的一个短状态;解释、数字、链接都在弹出层里。
- **对比按钮**:步头上的「对比 ▾」菜单按钮(不是悬停弹出层),选内容对比步([2.3](2.3-context-window.md))。
- **提问卡**:对话段里以一条人类提问开头、延续到下一条提问前的一组块(分组函数 `messageTurns()`,哪一块是提问由服务端的 `flat[].query` 定,[1.4](1.4-central-board.md))。本单元定卡头写什么;卡体是 [2.3](2.3-context-window.md) 的块行;折叠按 D12([1.4](1.4-central-board.md) §折叠语义)。
- **调用详情卡**:主对话以外的一次调用(子 agent、后台调用、token 计数)在调用抽屉([2.6](2.6-detail-panel.md) §B)里显示的内容。种类与它的词来自 [2.1](2.1-track-widget.md) 的 lane 种类表(`labels/replay.mjs : LANE_KIND`)。
- **动作摘要**:提问卡头上「调用 N 次工具 · 思考 · 工具结果」这一段,由这一轮各块的 canonical `kind` 数出来(`tool_use` / `server_tool_use` 的个数,有没有 `thinking`,有没有 `tool_result`)。是从块派生的摘要,不是新事实。
- **缓存判定**:`core/metrics.mjs : cacheState(step, ref)`,按固定先后给出一步的缓存状态(8 种,见 §缓存判定);`isBreak(step, ref)` 为真 = **缓存断开**。`ref` = 这一步的缓存对比步([2.3](2.3-context-window.md))。
- **估价(花费)**:Σ(canonical 用量 × 本地单价)。是本地估算,不是账单,不是线上事实(D14,§花费)。
- **多花**:一次缓存断开比起"照常复用缓存"大约多花的钱,`core/metrics.mjs : breakCost(step, ref, priceRow)`(§多花怎么算)。是估算,而且它的前提(前面没变 / 变了)是结构估计。
- **结构估计**:看板侧按块的结构(块键与看板侧前缀哈希)比出来的结论;权威值是 查询层按相邻调用 `content_hash` 算出的散度点([3.5](3.5-query-layer.md),[3.2](3.2-normalized-model.md))。

## Plan(选定方案 + 取舍)

**选定:中栏顶上只留一行步头,数字收进三个按钮;提问卡保留;调用详情卡进调用抽屉;命中、估价、断开、多花只在一个模块里算。**

- 步头是一行,不是一张卡。它和窗口之间没有别的东西([1.4](1.4-central-board.md) 的中栏白名单)。
- 缓存的状态句、四个用量数、多花,只在「缓存」按钮里出现一次;原始数据面板不再列用量([2.6](2.6-detail-panel.md) §A)。
- D17② 的段权重与增长 Δ 算法不变,两个 MUST 标跟着数字一起进「组成」按钮。
- 提问卡按原设计保留(沿用既有设计,中栏放整个上下文),只把 emoji 和英文换成中文词。
- 子 agent 的一次调用在调用抽屉里看,没有它自己的回放。
- `core/metrics.mjs` 是唯一算命中、估价、断开、多花的地方;步头、会话信息按钮([1.2](1.2-shell-layout.md))、时间轴的问题道与花费视图([1.3](1.3-timeline-tracks.md))、总览页的统计([1.7](1.7-overview-dashboard.md))都调它。

**备选(未选)**:
① 重设计稿里钉在中栏顶上的「步骤卡」(进来 / 模型 / 问题带 / 用量四段)——否决:中栏堆这么多东西没有重心,看不出要表达什么。
② 段权重条、增长行、缓存行写在窗口头上(旧版本单元的做法)——同上,中栏只放整个上下文。
③ 卡自己渲染块的全文(把摘要和逐字揉进一条渲染路径)——卡一改文案就可能改掉块的字节,直接威胁 AC-1,还把 [2.3](2.3-context-window.md) 的职责撕进来。
④ 卡直接读 provider 原生字段拼摘要——加一个 provider 就要在卡里加分支,违反不变式 3([0.0](0.0-overview.md) §核心不变式;需 RFC 才放行)。

**取舍**:数字退到按钮后面,换来中栏只有上下文;代价是要多一次悬停才看到缓存与估价。问题道([1.3](1.3-timeline-tracks.md))上的旗与会话信息按钮把"哪一步该看"指出来,所以不会漏看。

### 步头的 MUST

## Definitions

- **turn(轮)**:主轨消息流里,从一条**人类 user-text 消息(query)**起、到下一条 query 止的一段,携带其间 assistant 的 call-turn(thinking / tool_use / text)与回应它的 tool_result(`messageTurns`)。turn 是主轨卡的单元。
- **call-turn card(摘要卡)**:包住一步的**digest 信封**——头(身份 + query 预览)+ 动作摘要 + metrics(token / 花费 / cache-hit)+ 折叠控件;逐字块内容坐在卡 body 里、由 [2.3](2.3-context-window.md) 渲染。
- **lane-call 详情卡**:非 main 轨的一次 call(lane ∈ {subagent, monitor, aux, probe},见 [3.2](3.2-normalized-model.md) `calls.lane`)的点开卡(`openDetail`)——按 lane 类型差异化呈现其输入(原文)+ 输出 + 度量。
- **动作摘要(action summary)**:`N tool · think · result` 形态的一行,由该轮块的 canonical `kind` 计数派生(`tool_use`/`server_tool_use` 计数、`thinking` 有无、`tool_result` 有无;`t.acts`)。**派生自逐字块、非新真相**。
- **花费(cost)**:`Σ(canonical usage 角色 × 本地单价)` 的**本地估价**,非线上事实(见下「花费」节)。

## 卡结构(跨 provider)

**主轨 turn 卡**(`.cwturn`)——三件、折叠原位:
1. **头(`.cwturnhd`)**:折叠箭头(▾/▸)+ query 预览 + 动作摘要(`.qk`)+ 块数徽标(`.cwturnn` = 该轮块数)。有人类 query 的轮以 `🗣` 起、纯上下文/工具结果轮以 `⋯` 起并标 `(context / tool results)`。
2. **body(`.cwturnbody`)**:该轮的逐字块序列,**由 [2.3](2.3-context-window.md) 渲染**;折叠态 `display:none`。
3. **折叠态(D12)**:点头切换该 turn 的记忆态(按 anchor `content_hash` 存持久集,localStorage);默认**最新一轮展开**、其余收起;**跨 scrub / 重载存活**(不再 scrub 即重置),compaction 新 hash 自然回默认;+ 全展/全折便捷。

**lane-call 详情卡**(`openDetail`,按 lane 差异化):
- **monitor(🛡 安全检查)**:`verdict: clear/flagged`(flagged 红 / clear 绿)+ "reviewed call #1 → #k" + **该 call 的确切输入消息(原文)**,其中重复的 `<transcript>` 体**原位折叠**(只折可复现的大块,保结构可见)+ monitor system 规则折叠。verdict 文本 = 该 monitor call 的 assistant 输出块(逐字),卡只做 clear/flagged 轻解析。
- **probe(👁 count_tokens 量尺)**:measured N tokens + "payload ≈ 某 call 附近的 message_count / system chars / tool_count / 线上字节"。标注"一把尺,不是一轮——无模型输出、不计费"。
- **aux 家族**(notify / titlegen / quota / 通用):按子类给一行 lead(活动摘要 / 生成的标题 / keep-alive ping 且回复丢弃 / 通用模型+输出)+ persona + 输入(原文)折叠。
- **subagent**:独立上下文流的一次 call,点开进其自身的卡/回放(血缘归 [3.4](3.4-session-identity.md))。

> **跨 provider(适配缝)**:动作摘要的 `kind`、lane 分类、usage 角色**全来自 canonical**([3.2](3.2-normalized-model.md));Codex/DeepSeek 的 session 落进同一 canonical 后,卡形状/渲染路径**零改**即点亮(AC-3)。往卡里塞任一 provider 专属分支 = **需 RFC 才放行**(不变式 3)。

## 花费(本地估价 · 保真边界)

- **算法**:`cost = Σ_role (canonical_usage[role] × price[provider, model, role])`,角色取 [3.2](3.2-normalized-model.md) `usage` 的 `input_uncached / cache_read / cache_write / output`(估价函数 `costOf`/`usd`,`PRICING` 四价:input / output / cache-write / cache-read)。board 把 `costOf(model, 中立 canonical usage)` 接入**右下 raw 面板**(主线每步常驻)+ **off-main 详情卡**(monitor / notify / titlegen = billed;probe「量尺·不计费」/ quota「回复丢弃」按 §Edge cases 各自如实标、不冒充成本);无 usage → 显 `?`,不填 `$0`。单价读 `/api/pricing`(可编辑配置 `pricing.json` / `ASIGHT_PRICING`,承 D14),前端 `PRICING` 表为视图层资产。
- **保真边界(必拒隐瞒)**:花费**不是线上事实**——provider 不在 wire 上返回金额;它是 asight 用**本地、可编辑的单价表**乘 canonical usage 估出的。卡上花费 MUST 就地标"≈ 本地估价"(承不变式 4);MUST NOT 让人误读为账单真相。单价表是**配置/视图层资产**,非归一化模型的一列——**cost MUST NOT 进 [3.2](3.2-normalized-model.md) 冒充采集到的真相**(逐字源真相,必拒)。
- **跨 provider**:单价表按 `(provider, model)` 扩展(Anthropic/OpenAI/DeepSeek 各自 $/Mtok,cache-read/write 折扣不同);**D37**:上式与此处的 `provider` 读作**厂商**(`calls.vendor`,按上游 host;dsh 走 Anthropic 线格式但按 DeepSeek 计价),不认识的厂商不估价、标「单价未知」;看板载荷要带每个 call 的 vendor;DeepSeek `cache_write=NULL`(无写缓存概念,承 [3.2](3.2-normalized-model.md))→ 该项按 NULL 略过,不填 0 冒充。

## schema-税 · 段权重(承 D17② · 保真边界)

卡上/上下文头一枚 metric——把该步**重发的上下文按 assembly 段拆权重**:`tools · system · history · task` 四段各占多少**字节 /(估)token** + 一条迷你堆叠条 + culprit 一行。兑现研究基底痛点 #5「tool/MCP schema 税」:每请求在任何 user 消息前先吃掉多少窗口(真实 CC session 实测:tools 段早期占比可达 **53%**、中位 ~10%),常规输出里不可见。

- **段划分(render-time 投影,不入 schema)**:`tools`/`system` = 同名 section;messages 段再二分——`task` = 最新人类 user-text 轮及其在途动作(承 [2.3](2.3-context-window.md) turn 分组 / `messageTurns` 末轮),`history` = 其前全部块。history/task 是对 messages 段的**渲染期二分**,**MUST NOT 往 [3.2](3.2-normalized-model.md) 加列**(不变式 3)。
- **字节 = 内容真数(D15 后 tools 可测)**:段字节 = 该段各块 **verbatim 内容的 UTF-8 字节和**(`flatBytes` + `TextEncoder`)。它是**模型可见的内容字节**,与 `calls.request_bytes`(含 JSON scaffolding)**同量级但非逐位相等**——故读出的是**段间占比**(谁在 user 消息前吃满窗口),非绝对 wire 总额。**D15 起 tools schema 逐字采集** → tools 段权重首次可从真实字节测量;**D15 前旧 trace** 的 tools 段仅元数据估算,就近标(不变式 4)。
- **token = 估算(char/4 proxy · 必标)**:provider 只回**整包** token、不回按段 token;故段 token 是 asight 的本地字符代理估算,DOM MUST 就近标「≈tok 估算 / 字节=内容真数」。整包 token 才是真数(usage)——卡 MUST NOT 让人误读段 token 为线上事实。
- **culprit 一行**:堆叠条下给「最大段 = tools(N 字节,X%,每步重发)」,把「谁在 user 消息前吃满窗口」点出来。**逐块级归因(哪个 block 撑爆)→ [2.3](2.3-context-window.md)**;跨步增长曲线 → [1.3](1.3-timeline-tracks.md)。

## 上下文增长 Δ(承 D17② · 保真边界)

上下文头一行 growth Δ:`重发前缀 Δ = X 字节(vs 上一 call)` + **点名增量主导段**(如「+34K,mostly history」)。兑现研究基底痛点 #4「成本超线性涨却无法归因到某一步」。`growthLine(tax,prevTax,brk)` = 相邻两 call 段字节差、取 |Δ| 最大段为主导。**诚实上限(承 [1.1](1.1-product-definition.md))**:asight **点元凶(诊断),裁剪归 harness**——文案 MUST 是「增量来自 X」而非「应删 X」,就近标「诊断非裁剪(裁剪归 harness)」。**compaction 换血**(`brk.cause==='compaction'`)MUST 标「整窗重写,非线性追加」,MUST NOT 报一个巨大 Δ 误导成逐块新增。首 call 无 Δ。逐块级归因 → [2.3](2.3-context-window.md)。

## 保真边界一览(卡上哪些非逐字 · UI 必标)

| 卡上元素 | 保真等级 | 真相在哪 |
|---|---|---|
| 花费(cost) | **本地估价**(非 wire 事实) | 无线上金额;canonical usage × 本地单价 |
| query 预览 | **truncated + cleaned**(剥 `<system-reminder>`、截 ~90 字) | 完整逐字块一次展开可达([2.3](2.3-context-window.md)) |
| 动作摘要 `N tool · think · result` | **summarized**(块 kind 计数派生) | 逐字块在 body([2.3](2.3-context-window.md)) |
| monitor `verdict: clear/flagged` | **derived**(输出块轻解析) | 输出块原文逐字(卡内 monmsg) |
| token / cache-hit | **verbatim usage**(真相,非估) | canonical `usage`([3.3](3.3-cache-model.md) Tier 1) |
| schema-税 段权重(D17②) | **字节=内容真数(非逐位 wire)/ 段 token=char-proxy 估算** | 段字节从 verbatim 内容重算;段 token 无线上真相 |

> token 与 cache-hit 是**真数**(来自真实 usage),**不**是保真边界——卡 MUST 显示真值、MUST NOT 二次臆算(cache 数字取真实 usage,不 byte-diff 猜)。

## 验收(可跑 check)

- **既有闸(MUST 保持绿)**:`test/web/dashboard-render.mjs`——渲染闸在多个 playhead 位断言 messages 分组成 `.cwturn` 卡且 raw 面板含 usage(canonical read/new-cache/fresh/out),并跑 AC-1 逐字断言(服务端烘好的窗口与原始采集逐字一致)。本模块任何改动 MUST NOT 让这些转红。
- **本模块 NEW 测试(在渲染闸内扩,针对固化真实/样本 trace)MUST 断言**:
  1. **动作摘要正确**:构造含 ≥1 `tool_use` + `thinking` + `tool_result` 的一轮 → 卡头动作摘要 == `N tool · think · result`(N=工具计数)、块数徽标 == 该轮 `items.length`。

  3. **花费标注保真边界**:卡上花费 DOM 携"≈ 本地估价"标记;花费值 == canonical usage × 本地单价(可复算);且 `cost` **不出现在** [3.2](3.2-normalized-model.md) 任一表列(grep DDL 断言)。

  5. **lane 差异化**:monitor 卡 verdict(clear/flagged)== 其输出块解析;probe 卡显 measured tokens、标"不计费";aux 卡显 model+输出。各按 `calls.lane` 正确分流。
  6. **适配缝(AC-3)**:喂一条 Codex 或 DeepSeek 样本 → 卡形状/渲染路径不变即点亮;**卡 DOM 里不出现任一 provider 原生字段名**(如 `cache_creation_input_tokens`、`prompt_cache_hit_tokens`)——只出现 canonical 语义。
  7. **schema-税段权重(D17②)**:`segTax(flat)` 把上下文拆 tools/system/history/task 四段——tools-schema 巨大的构造 trace → culprit==tools 且 tools 段 >50%;四段百分比和 ≈100;含旧轮 + 末轮的 messages → history/task 两子权重皆 >0。渲染:`.cwtax` 堆叠条 + culprit 一行在上下文头、`.cwsecw` 段权重在段 header;token 估算带「字节=内容真数 / ≈tok 估算」保真标(DOM 可断言)。实测真实 session tools 段 6–53%(早高晚低,history 增长)。
  8. **上下文增长 Δ + 块级首现(D17②)**:`growthLine(tax,prevTax,brk)`——首 call 无 Δ;有 prevTax → 显 `re-sent Δ` + 主导段 + 「诊断非裁剪」标;`brk.cause==='compaction'` → 显「compaction rewrote history · not a linear append」。`ctxBlock(b,i,prevKeys)`——新块(key 不在 prevKeys)带 `◆ new`,复用块与首 call 无标。渲染:非首 step 的 `#ctxwin` 含 `.cwgrowth`。

## Edge cases

- **无人类 query 的轮**(纯 tool_result 续跑):以 `⋯ (context / tool results)` 起,不误标成 query 轮。
- **超长 query / transcript**:预览截 ~90 字;lane 卡里重复大块(monitor 的 `<transcript>`)**原位折叠**而非描述替代,保结构可见。
- **interrupted / 半包 call**([3.1](3.1-adapter-contract.md) 的 error 行):卡如实标"⚠ interrupted",不显伪造 usage/花费。
- **probe/keep-alive**:probe 是量尺(无输出、不计费)、quota 是 `max_tokens:1` 回复丢弃——花费/输出 MUST 如实标"不计费 / 已丢弃",不混入主轨成本。
- **缺 usage**(某 provider 某步未返 usage):token/cache-hit/花费显 `?` 或留空,MUST NOT 填 0 冒充真数。

## Risk / 回滚

卡是**纯读渲染**(归一化行 → DOM),无副作用;用固化真实 trace 跑渲染闸做回归,改坏即回退上一绿点。花费单价表改动只影响估价显示、可独立回退,且因标了"本地估价"不污染真相层。

## Extensions

- 卡上更多可选 metric(reasoning token 单列、duration、stop_reason),照 canonical 列加、不加 provider 分支。
- 花费:接入单价表编辑 UI + 跨 provider 成本对比(挂 ② 的跨 session 分析,[3.5](3.5-query-layer.md))。**单价表 = 可编辑配置(D14)**:provider 只回 token usage(无 $ 单价),单价是外部可变量 → 存**可编辑配置**(如 `pricing.json`),cost = `usage × 单价` 派生,**MUST NOT 入归一化模型**(cost 是本地估算,非源真相)。
- 新 harness/provider:canonical 落齐即复用同一卡,零改前端(承 AC-3)。
