# asight · RFC 3.1 — 适配层契约(★★ 产品的心脏)

> **服务意图(A2)**:跨切意图「适配层通用」(AC-3)——它是让整套产品 harness-无关的**接缝**;同时喂 ①(产出 blocks 供回放)与 ②(产出 canonical usage / cache_events 供叠加)。
> **受众**:人(核对这道缝是否真解耦)+ agent(据此实现每个 adapter)。
> **前置**:输出目标 = [3.2](3.2-normalized-model.md) 的表;采集源(怎么拿到 bytes)见 [4.1](4.1-capture-sources.md),与本层**正交**。

## Goal
定义每个 `(provider × harness)` 都实现的**统一 adapter 接口**:吃一条原始捕获记录,吐 [3.2](3.2-normalized-model.md) 的归一化行。加/换 harness = 加一个 adapter,**不碰前端主干、不碰其它 adapter**。

## Definitions
- **adapter**:把某 (provider×harness) 的原始流量归一化的模块。与**采集源**正交——源管"怎么拿到 bytes"(MITM/反代/relay-tee,见 4.1),adapter 管"bytes 什么意思"。
- **原始记录**:采集源写出的**统一信封**——**canonical 定义单一权威在 [4.1](4.1-capture-sources.md) §统一原始信封**(承本文件命名):核心 `{ts, endpoint, method, req_headers(脱敏), req_body(逐字), resp(SSE 重建或 JSON body)}` + 观测元数据 `{id, ts_request/ts_response_start/ts_response_end, duration_ms, is_llm_call, capture, auth_mode}`(见 D10)。字段名以本文件(`req_headers/req_body/resp`)为准,4.1 定义完整形状、adapter 据此单一消费——**MUST NOT 两处各定义一套**。

## Plan(选定方案 + 取舍)
**选定**:一个 `Adapter` 接口 + 一个 registry;记录进来,由 `detect` 认领,认领者解析。
**备选(未选)**:① 单个巨型 if/else 解析器(provider 分支混在一处)——违反"适配缝不漏进前端/彼此"(不变式 3([0.0](0.0-overview.md) §核心不变式)),加 harness 就改核心;② 每 provider 一个完全独立的管线到独立表——丢掉归一化,前端要认三套。
**取舍**:registry + 统一输出契约 = 加 harness 是"加一个文件实现接口",核心与前端零改动。

## 接口契约(每个 adapter MUST 实现)

| 方法 | 输入 → 输出 | 说明 |
|---|---|---|
| `detect(record)` | record → bool | 认领本记录是否属本 (provider×harness)。判据用**线上稳定信号**(endpoint / header / 系统提示标记),见 3.4。 |
| `parseSession(record)` | record → `{native_id, parent, fork_of, forked_at, entrypoint, title?, extra}` | 归一化 session 身份 + 血缘;判定规则权威在 [3.4](3.4-session-identity.md)。**`lane` 不在此**——它是 per-**call** 属性(见 `parseCall` + [3.2](3.2-normalized-model.md) `calls.lane`),同一 session 交错 main/subagent/monitor/aux/probe 各 call。 |
| `parseCall(record)` | record → `{class, control_kind?, lane, endpoint, model, stream, usage(canonical), stop_reason, duration_ms, error, compaction?, unmapped_count, extra}` | `class` ∈ {llm, control}(D9);`control` 调用再出**归一化** `control_kind`(config/account/registry/telemetry/other)——端点级判定在 adapter,前端只读类目。**`lane` ∈ {main｜subagent｜monitor｜aux｜probe} = per-call 分类**(承 demo `isSub`/`isMonitor`/小模型判据 → [3.2](3.2-normalized-model.md) `calls.lane`;每 call 分,非每 session)。usage MUST 映射到 [3.2](3.2-normalized-model.md) 的 canonical 角色;provider 字段名不外泄。 |
| `parseBlocks(record)` | record → 有序 `[{section, role, kind, content_hash, text_ref, faithfulness, cache_control?, volatile?, resource_ref?, extra}]` | **assembly order**(tools→system→messages);把 Codex `instructions`→system、`input[]`→messages 归一化。`content_hash` MUST 为**全内容抗碰撞 hash = sha-256 over 块「逐字序列化字节」**(采集所见原始序列化,**非 key 规范化**;承 **D19**)、各 adapter 一致——是 [3.2](3.2-normalized-model.md) 去重 PK,碰撞=丢块(**必拒**)。**键序规范化(`canonJSON`)仅供 [3.3](3.3-cache-model.md) `divergence_cause` 分类(判 json-key-reorder/tool-array-reorder),MUST NOT 进 `content_hash`**——否则 key-reorder 类 cache-break 会塌进去重、变不可见。bounded-prefix 只许用于内存态启发式(见 [4.3](4.3-parse-index-cache.md))。 |
| `parseResources(record)` | record → `[resource_event]` | 文件/dir/link/mcp/skill/tool/**scaffold** 的 enter/evict/reinject/load,+ **`event='seen'`** 只见其名的路径(names-only、metadata 保真;承 demo `extractResources`/`extractSeenPaths`,见 D8)。 |

- 三层归属(§3.2 心智模型):adapter 是 **server-side 分析层**,坐在采集(4.1)与存储(4.2)之间。访问模式:**只读**原始 NDJSON 记录,**写**归一化行;MUST NOT 改原始。
- 依赖:输出契约 = [3.2](3.2-normalized-model.md);被 [4.2](4.2-storage-etl.md) ETL 调用。
- **adapter = dissector(D25 · 「Wireshark for agents」)**:这个「原始 bytes → canonical blocks」的接口**就是** dissector;加 harness = 写一个 **JS-module dissector**(非嵌入式 DSL)。**board 与 ETL MUST 共用同一 dissector**——历史遗留双解析器(board `analyze.linearContext` 只吃 v0 `request` 对象、ETL `parseBlocks` 吃 D10 `req_body` 串)导致**产品 D10 capture 在 board 渲成空**;step-1 由 CC dissector 的 board-intake `hydrateForBoard`([src/view/assemble.mjs](../../src/view/assemble.mjs))补上 D10→blocks(tools 逐字 `input_schema`,`test/view/assemble-d10.test.mjs` 钉)。**step-2 已落地(2026-07-16)**:单一 CC dissector 模块 [src/dissect/cc.mjs](../../src/dissect/cc.mjs) = **唯一** CC block 模型源(声明式 `CC_SECTIONS` 分类/布局 + `dissectBlocks(req)` 装配序走查 + 共享 `resourceRef`/`isVolatile`/`blockKind`/`faithfulness`/`sysLabel`/`parseBashReads`);`linearContext`(board)与 `parseBlocks`(ETL,叠加 D19 逐字字节 span)双双退成它的**投影**,消解双解析器(`test/dissect/cc.test.mjs` 钉「两投影 block-for-block 一致」)。provider 专属(response 形状 / turn 判定 / tool 抽取)全落各自 dissector,**不进 [3.2](3.2-normalized-model.md) 共享 schema**(DB 语义无关 = 持久块存,承 D25)。Phase 4 = Codex/DeepSeek 各写一个同形 dissector,board/ETL 投影不动。

## 深度优先拆积木(§3.3)
三个 adapter 各是可独立构建/验证的积木,按此序:
1. **CC adapter**(有真实数据,先建;大半逻辑可从 demo `capture.mjs`/`analyze.mjs` 提炼)→ 验证 AC-1/AC-2 通路。
2. **Codex adapter**(Responses API;`instructions`+`input[]`→归一化;显式 fork/thread)。**已落地(2026-07-16 · Phase 4)**:`src/dissect/openai.mjs` = OpenAI/Codex dissector,与 CC dissector 同形(声明式 `OPENAI_SECTIONS` + `boardFlat`/`dissectBlocks` + `normResp`/`canonUsage`),把 Responses(`instructions`→system、`input[]`→messages:message/function_call/function_call_output/reasoning、`tools[]`→tools)映射进**同一跨-provider block 词表**(text/tool_use/tool_result/thinking),board 零改动即渲 Codex;encrypted reasoning→`opaque`(不变式 4);usage 从 SSE `response.completed` 重建(`--raw-sse`);session 身份 = `session-id`/`thread-id` 头(=`prompt_cache_key`)。经真实 `codex_exec` + gpt-5.5 抓包验证(`test/dissect/openai.test.mjs` · AC-1)。采集路由:codex → asight `capture` tee → SSH 隧道 → bestony(mini-codex relay)。
3. **DeepSeek adapter**(Chat Completions;`reasoning_content` 字符串→reasoning 块;harness 标记 LOW,**先对真实抓包核对再硬编码**)。

每个建成即用 AC-3 验证:新增该 adapter,归一化行产出,**前端 `git diff` = 0**。

## Invariants（MUST）
- adapter MUST NOT 丢失/改写原始记录(逐字源真相)。
- usage MUST 全部落 canonical;每块 MUST 带 `faithfulness`;非 verbatim MUST 标(opaque=Codex 加密 reasoning;metadata=旧 v0 trace 的工具定义[pre-D15]、only-seen 名字、非 LLM 响应体——**D15 后 tools schema 逐字=verbatim,纳入 AC-1**,per-block badge 区分)。
- 未被任何 adapter `detect` 认领的记录 MUST 落"未识别"隔离区并计数,MUST NOT 静默丢弃。
- **未映射字段 MUST 可见、MUST NOT 静默丢**(承不变式 2、4([0.0](0.0-overview.md) §核心不变式)):每个 `parse*` MUST 记住它**消费了原始对象的哪些键**,与原始对象实际出现的键做差集,把**未消费的剩余原样塞进该行的 `extra` JSON**,并把未消费键数累加进 `parseCall` 的 `unmapped_count`。判据是"canonical 列 + `extra` 能重构原始对象的键集";漏进 `extra` 也算漏 = 违反。**永不为了'干净'而丢字段**——不认识就进 `extra`,不是删掉。

## Out-of-scope
采集机制(4.1)、表 DDL(3.2)、前端(2.x)、cache 语义(3.3)。

## 验收(可跑 check）
- 实现 CC + 第二个 adapter,各喂真实记录 → 归一化行产出且 AC-1/AC-2 过;**前端主干 `git diff` = 0**(AC-3)。
- 喂一条无人认领的记录 → 进隔离区 + 计数,不崩不丢。
- **未映射兜底**:对真实记录,`canonical 列的键 ∪ extra 的键 == 原始对象的键`(逐层验),`unmapped_count` = extra 键数;人为往记录塞一个新字段 → 它出现在 `extra` 且 `unmapped_count` +1,无一静默丢。

## Edge cases
- 多 adapter 都 `detect=true`:registry MUST 定义优先级 / 报冲突,不静默二选一。
- 流中断/半包(承 demo 的错误记录):`parseCall` 产出 `error` 行,不当成功。
- Codex reasoning 加密(opaque)、CC 工具定义(**D15 后 verbatim;仅 pre-D15 老 trace = metadata**,带 per-block badge):`faithfulness` 如实标,回放 UI 据此提示"非逐字"(仅对真正非 verbatim 的块)。

## Risk / 回滚
每个 adapter 一个 `git commit` 积木;失败回退上一绿点(`git revert`)。adapter 是纯函数(记录→行)→ 可离线用固化的真实记录做回归,零副作用。

## Extensions
新 harness:实现本接口 + 在 3.4 加身份判定 + 在 4.1 选采集源;不改前端、不改他 adapter。

**自动适配(auto-adapt · [5.1](5.1-intervention.md))**:在本契约上加一层**自动侦测启发式**——从原始流量猜 provider 线格式 + harness 约定,少写/免写手工 adapter 就点亮面板。它**只读**(更聪明的观测),与拦截 / 修改能力(D30)互不依赖,可独立推进。**约束**:auto-detect MUST 只读、只猜、可被人工 adapter 覆盖;侦测结果是**派生推断**,UI MUST 标「自动推断,可能不准」(承不变式 4);`extra`/`unmapped_count`(见 D7 钩子)是它的天然信号源。

**D7 自演化钩子**:`extra` + `unmapped_count` 不只是保真兜底,更是下游自演化设施(D7,单独立项)的**触发输入**——新 agent/API 一来,它没认识的字段自动浮进 `extra` 并被计数;设施据 [3.2](3.2-normalized-model.md) 的 `unmapped_fields` 视图看到"哪些字段还没接、多常见",据此自动起草映射/新列/新 adapter 并部署测试。本层只**保证信号可见且可查**,不实现自演化本身。
