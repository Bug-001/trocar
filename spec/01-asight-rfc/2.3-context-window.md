# asight · RFC 2.3 — 忠实上下文回放部件(★ 招牌)

> **服务意图(A2)**:意图 ①(逐字回放某步的完整上下文——这是 AC-1 逐字 diff 的**落点**)+ 兼作意图 ② 的**宿主**(块级「缓存标记」/「每次都变 · 不影响缓存」、前缀变了时的**变化线**;数值真相来自 [3.3](3.3-cache-model.md),缓存状态在步头的「缓存」按钮里,归 [2.2](2.2-call-turn-card.md))。
> **受众**:人(核对"这就是模型这一步真收到的每一比特")+ agent(据此从 [3.2](3.2-normalized-model.md) 的 `call_blocks`/`block_contents` 渲染,**不回退到 provider 专属分支**)。
> **前置**:块数据 = [3.2](3.2-normalized-model.md)(`call_blocks` 有序 + `block_contents` 去重 + `text_ref` 回源);块语义 / `faithfulness` 由 [3.1](3.1-adapter-contract.md) 的 adapter 定;cache 徽章 / 断点真相由 [3.3](3.3-cache-model.md) 定;中栏白名单、落点与提问卡的装配 = [1.4](1.4-central-board.md);步头、缓存判定与「对比」菜单 = [2.2](2.2-call-turn-card.md);词与标记 = [1.5](1.5-states-aesthetics.md) §看板词表 · §标记;「第 N 步」的编号 = [1.2](1.2-shell-layout.md) §编号:步与调用;承 demo `linearContext`/`ctxBlock`/`ctxBody`/`rawContentText`。

## Goal
把一条 call 的上下文摊平成**一列有序 block 卡**,严格 assembly order **tools → system → messages**,每块一卡(role/kind/预览 + 保真标 + 缓存标记),点开即逐字看该块全文。这个窗口(回放台中栏的 `#ctxwin`,[1.4](1.4-central-board.md))**就是**模型这一步真收到的每一比特——**无"不在列表中"、无另开的 raw 列**;窗口 = 真相本身。它是 AC-1 逐字 diff 的落点。承 demo v11 单窗口验证,泛化到跨 provider(承 3.1/3.2)。

看板 v2 成为产品看板(D18c)起再加两条:窗口只在**有证据**时才说「逐字」;这一步的前缀和缓存对比步不同时,才画一条**变化线**说从哪里起变了。要求是:这一步的前缀和上一步不一样了,才说什么地方变了。

## 前置定义(Definitions)
- **block 卡(`.cblk`)**:一个 `call_blocks` 行的可视卡;默认折叠(只显头),点开懒填全文体。
- **段(section)**:`tools | system | messages` 三段之一(归一化;Codex `instructions`→system、`input[]`→messages,承 [3.2](3.2-normalized-model.md))。每段一个段头:段名与块数归 [1.4](1.4-central-board.md),大小与保真归本单元。
- **提问卡**(原「turn 分组」):messages 段内按"人类提问 ▸ 到下一条提问之前的块"聚成的可折叠卡(承 demo `messageTurns`/`.cwturn`);装配与折叠记忆归 [1.4](1.4-central-board.md),卡头归 [2.2](2.2-call-turn-card.md)。
- **保真标(faithfulness marker)**:块**不能证明逐字**时就地贴的可见标记(见 [3.2](3.2-normalized-model.md) 枚举 `verbatim|metadata|opaque|summarized|omitted|truncated`;判法见 §保真标:证明规则)。
- **证得逐字**:块有 `text_ref`,且 `faithfulness` 缺省或为 `verbatim`;工具块要 `verbatim:true` 且有 `text_ref`。
- **缓存标记 / 每次都变**(原「cache 徽章」):块上的「缓存标记」(请求在这一块声明的 `cache_control` 位置)与「每次都变 · 不影响缓存」(`volatile` 块),从 canonical 列渲染。
- **缓存对比步**:服务端比缓存用的那一步——同一 lane 里前一个没失败的调用。
- **内容对比步**:用户选来比内容的那一步;默认就是缓存对比步。
- **变化线**:这一步的前缀和缓存对比步不同时,画在第一个变了的块前面的一条线。
- **调用保真行**:一条调用整体的保真事实(上下文缺了前序、没采全……),在窗口顶上说一次。
- **窗口行**:这一步没有一块能回到原始字节时,在窗口顶上说一次。
- **未下发态**:这一步的正文不在当前这一页时,窗口显示的那一态。

## Plan(选定方案 + 取舍)
**选定**:**单一忠实窗口 + 逐字懒加载 + 徽章从 canonical 列渲染**。窗口只持有块的**元信息**(section/role/kind/preview/faithfulness/cache_control/volatile/resource_ref);全文在点开时经 `text_ref` 回 NDJSON 源**懒加载**。看板 v2 起再定三件:
1. **保真按证明规则标**:证得逐字的块不写字;一段全部证得时,段头写一次「以下逐字」;其余每块写自己的可见标。(Q9 选 c;证明规则见下。)
2. **窗口里的缓存只剩变化线**:前缀变了才画,说从哪里起、和第几步不同、原因;命中多少、过期重建、服务商一侧的矛盾、失败等状态都在步头的「缓存」按钮里([2.2](2.2-call-turn-card.md))。
3. **两个对比步分开**:变化线对的是缓存对比步;块上的「新」和移除的块对的是内容对比步。

**备选(未选)**:① **双栏**(左渲染视图 + 右原始 JSON 列)——demo v0 试过,注意力撕裂,且"渲染视图 + 独立 raw"结构诱导"渲染即真相"误判;② **每块预存全文进前端**——违反 [3.2](3.2-normalized-model.md)"本表不存全文、`text_ref` 回源"、且 `content_hash` 去重失效、内存爆;③ **每块一个绿色「逐字」标**(本单元旧写法)——一屏上百个同样的标,把真正要看的非逐字标淹掉;旧实现还在缺 `faithfulness` 时默认当逐字,没有证据也写了「逐字」;④ **每一步都画缓存标记槽、写缓存状态**(旧写法与 v2 原型)——否决:命不命中不值得在这么紧凑的空间里占篇幅;⑤ **和参考步相同的段折成一行、画水位线**(重构提议)——沿用既有设计,中栏放整个上下文,保持平铺。
**取舍**:窗口零全文冗余 + 逐字锚(`text_ref`)不飘 → 展开的每一个字符都可回到源 bytes,AC-1 天然成立。证明规则让「逐字」只在有证据时出现;代价是块正文打开后回来的不是逐字时,段头的「以下逐字」要当场撤回(§保真标)。

## 部件结构(承 demo)

### 有序摊平:tools → system → messages(必拒乱序)
读 `call_blocks`(按 `seq`)→ 依次渲染。demo `linearContext(request)` 现解析出此序;**产品改从 [3.2](3.2-normalized-model.md) 的 `call_blocks.seq` 读**(见「跨 provider 泛化」)。assembly order MUST 与线上装配序一致——**乱序即谎报 AC-1**。守卫:`test/dissect/cc.test.mjs`「dissectBlocks walks tools → system → messages with contiguous seq」+ `test/web-v2/ctxwin.test.mjs`(段序与 `data-bi` 递增,[1.4](1.4-central-board.md) 验收 #1)。

### block 卡:折叠头 + 懒展开体
- **头(`.cbh`)**:`role` 徽 · `kind` tag(如 `def`/`thinking`/`action · <tool>`/`observation · error`/`say`/`system-reminder`)· **preview**(≤90 字符、折空白;承 demo `preview=slice(0,90)`)· 缓存标记 / 每次都变 · **「新」(D17②)** · 字符数(写「字符」)· 保真标(只在不能证明逐字时)。头的这些词是服务端的 `flat[].head{role, tag, label}` 与 `flat[].preview`,原样当数据显示;系统块的名字 = 服务端的 `flat[].label`,也当数据显示。前端 MUST NOT 按 provider 分支另起名字(不变式 3;守卫 `test/web-v2/no-provider-branches.test.mjs`)。
- **「新」(承 D17②)**:该块 `content_hash`/key **不在内容对比步**的键集里(且非 `volatile`)→ 块左边一条安静的墨色竖线 + 「新」——它是本步新增的内容(= 重发 Δ 的组成),与步头「组成」按钮里的增长 Δ([2.2](2.2-call-turn-card.md))呼应;复用块**不标**,保持安静。这一 lane 的第一次调用不标(没有对比步);内容对比步的块还没送到时也不标——两种情况都不是"全都是新的"。demo `ctxBlock(b,i,prevKeys)`。逐块级「哪个块最重(段内占比)/ ↺复用×N」是 Extensions(承 draft),v0 先给最锋利的「新 vs 复用」二分。守卫:`ctxwin.test.mjs`。
- **体(`.cbc`)**:折叠态空,首次展开时 `ctxBody` 懒填(承 demo `toggleCtxBlock` 的 `dataset.filled` 门);**verbatim 全文**经 `rawContentText` 从源块还原(text / tool_use 的 `name(input)` / tool_result / thinking …)。**tools 段体 = 逐字 schema(D15,新 trace)**——展开见完整 `description` + `input_schema`;**D15 前的旧 trace 回落元数据摘要**(见保真标)。v2 落在 `replay/blocks.mjs : fillBody()`:取回失败时正文写原因、下次打开重取(守卫 `test/web-v2/block-load.test.mjs`)。

### 段头 + messages 分提问卡(承 D17②)
tools/system 段:块平铺。messages 段:按提问卡分组、可折叠,默认展开最新一张(承 demo `turnOpen`/`lastTurnCall`;D12 折叠记忆归 [1.4](1.4-central-board.md))——长会话不淹没当前步。和对比步相同的段 MUST NOT 折成一行(中栏放整个上下文;守卫 `ctxwin.test.mjs`,[1.4](1.4-central-board.md) 验收 #8)。

段头 = 段名 · 块数([1.4](1.4-central-board.md))· **大小** · **保真**(本单元):
- **大小** = 段内各块 `flat[].bytes` 之和(内容的 UTF-8 字节,不含请求的 JSON 外壳),写成「11 KB」,悬停「这一段各块内容的字节数之和」。段里有 `metadata` 工具块(D15 前的旧 trace)时,大小前加「≈」,悬停「工具定义只存了元数据,大小是估算」(承旧「D15 前旧 trace 仅元数据估算,就近标」)。
- **「以下逐字」**:段里每一块都证得逐字时写一次;有一块没证得就不写。
- **◐**:只在窗口行出现时写;这时段头不写别的保真字。
- 原来段头上的「段权重读出」(`N 字节 · X% of call · ≈M 估tok`,messages 再分 history / task)搬进步头的「组成」按钮([2.2](2.2-call-turn-card.md)),那里的两条 MUST 说明(字节 = 内容真数、token 按字符估;诊断,不裁剪)随之搬过去;D17② 的算法与 `segTax` 不变。

### 保真标:证明规则(保真边界 · 必拒隐瞒)
承不变式 4([0.0](0.0-overview.md) §核心不变式):凡块非逐字,UI MUST 就地标,MUST NOT 让人误以为看到完整线上真相。看板 v2 起「逐字」本身也要有证据。

**证明规则(MUST)**:
- 一块**证得逐字** ⇔ 有 `text_ref`,且 `faithfulness` 缺省或为 `verbatim`。工具块 ⇔ `verbatim:true` 且有 `text_ref`。
- 证得的块不写可见字,只带 `data-ff="verbatim"` 与读屏文字(「<行头>,逐字」)。一段里每块都证得时,段头写一次「以下逐字」。
- 其余每块写自己的可见标,一块最多一个([1.5](1.5-states-aesthetics.md) §标记):已知的非逐字值、未知值、缺值、`unaddressable` 都算。**MUST NOT 在没有证据的块上写「逐字」**:旧 `faithOf()` 在非工具块缺 `faithfulness` 时默认当逐字(有没有 `text_ref` 都一样),这条默认作废。
- 块正文打开后,`/api/block` 回来 `status ≠ ok` 或 `fidelity ≠ verbatim` 时,这一块当场补上可见标,它所在的段当场撤掉「以下逐字」。唯一的例外:调用带 `wire.reqEncoding` 时回来的 `fidelity:'decoded'`——那是解压后的确切文字,调用保真行已经说过一次,不撤。
- 模型这一步的回复用同一规则:`respRefs[].ref` 能回源逐字之前标「◐ 解析后的回复」,永不没凭据就写逐字;渲染归 [2.6](2.6-detail-panel.md) §A。

守卫:`test/web-v2/fidelity-marks.test.mjs`(验收 #2)。证明规则见下。

逐值(词在 `labels/replay.mjs`,按 [3.2](3.2-normalized-model.md) 的闭集与 `/api/block` 的 `fidelity` 取;一块同时有几条时,按下表从上往下取第一条):
- **`verbatim`(tools 段 · D15 默认)**:采集逐字存完整 `description` + `input_schema`(承 `capture.mjs`);adapter([3.1](3.1-adapter-contract.md) `linearContext`)派生 `descChars`/`props` 供折叠头显示、`verbatim=true`;体展开渲染完整 schema。有 `text_ref` 时它证得逐字:块上不写字,只带 `data-ff`(仍纳入 AC-1);没有 `text_ref` 时按下面「不能回源」标。
- **`metadata`(tools 段 · 仅旧 trace 回落)**:D15 之前的 trace 只有 `name + type + input_schema_props(参数名) + description_chars`,**schema 文本不留**。此时 `verbatim=false`,块上写可见的「◐ 只有元数据」;体里写工具名、参数名、「描述 N 字符(schema 文本没有存)」,再加一句「只有元数据:完整的 JSON schema 没有被采集,模型收到的是完整 schema」。**必拒**把它渲染得像逐字 schema。
- **`opaque`**:加密 reasoning(Codex `encrypted_content`)/ `redacted_thinking` → 块上写「◐ 加密,没有明文」,体显占位(demo:`[redacted_thinking]`),MUST NOT 冒充空文本或伪造明文。
- **`summarized`/`omitted`/`truncated`**:源侧被客户端摘要 / 省略 / 截断的块 → 就地标其性质:「◐ 客户端的摘要,不是原文」/「◐ 源头省略了」/「◐ 源头就截断了」。
- **未知值**(不在上面的枚举里):「◐ 保真未知」,值本身进技术细节。
- **打开后回来的不是逐字**:`status ≠ ok` →「◐ 取不到字节」,体写原因,定位串进技术细节;`fidelity:'reserialized'` →「◐ 重新序列化过,不是线上字节」;`fidelity` 为空或是别的值 →「◐ 保真未知」。
- **没有 `text_ref` / `unaddressable`**:「◐ 不能回源」,服务端给的原因进技术细节;体是块里内联带来的文字,上方一行「这段文字是块里带来的,不是从原始采集里逐字切出来的」。窗口行出现时,这一标不逐块重复(窗口级的事说一次,[1.5](1.5-states-aesthetics.md) §标记),读屏文字照带。
- **显示剪裁 ≠ 源截断(需分清)**:展开体超阈值(demo 20000 字符)剪 + 「…(共 <N> 字符,这里只显示前 20000)」——但**全文仍在 NDJSON 源可回**;这与 `faithfulness=truncated`(源本身就没抓全,「◐ 源头就截断了」)是**两码事**,UI 措辞 MUST 区分"仅显示折叠、点击/回源看全" vs "线上真相本就不全"。剪裁是显示控件,不是保真标([1.5](1.5-states-aesthetics.md) K-07)。守卫:`test/web-v2/render-verbatim.test.mjs`「a text over 20 000 chars is clipped with the marker and is otherwise a prefix of the source」+ `fidelity-marks.test.mjs`(`truncated` 一例)。

### 调用保真行(必拒隐瞒)
一条调用整体的保真事实,在 `#ctxwin` 顶上**可见地**说一次(不藏进悬停,不逐块重复):行首「◐」,各事实用「 · 」隔开。这一行存在时,步头带 ◐([2.2](2.2-call-turn-card.md))。这一行的字段在每一步上都有(分页外的步也有),所以未下发态上方照样显示。把跨记录拼接、缺了前序记录的上下文显示成完整 = **必拒**([0.1](0.1-engineering-rules.md) §5,D37);守卫 `test/web-v2/fidelity-marks.test.mjs`(验收 #8)。

| 事实 | 来源 | 行里的话 |
|---|---|---|
| 跨记录拼接缺了前序 | `wire.contextState:'partial'` + `wire.contextMissing` | 「上下文不完整:缺前面的记录(<contextMissing>)」,`contextMissing` 原样当数据 |
| 不完整,但没有 `contextMissing` | `wire.contextState:'partial'` | 由下面「请求」或「消息」那一条说;两条都没有时写「上下文不完整」+「原因未知」 |
| 由前几条记录拼出 | `wire.contextState:'reconstructed'` | 「由前几条记录拼出」 |
| 服务端改过上下文 | `wire.contextState:'server_edited'` | 「服务端改过上下文,这里不是模型收到的全部」 |
| 请求没采全 | `reqIncomplete{truncated, partial}` | 「请求:」+ `truncated`「在采集上限处截断」、`partial`「没收全」;`partial` 的码与服务端的 `text` 进技术细节 |
| 消息没采全(WebSocket) | `wsIncomplete{partial, truncated, undecoded, nonVerbatim}` | 「消息:」+「这条连接前面的消息缺了」/「有消息超过上限,只存了大小」/「有消息没解压出来」/「有消息只存了大小」;`text` 进技术细节 |

### 缓存标记 · 每次都变(意图 ② 的块级钩子)
- **「缓存标记」**:`call_blocks.cache_control` 非空(看板上是 `flat[].cc`)→ provider 声明的显式缓存位置(Anthropic `cache_control`);可缓存前缀存到**含本块**为止(承 demo tooltip)。悬停写声明的值(当数据)与「缓存怎么处理这个标记,各服务商不同」。不叫「缓存断点」([1.5](1.5-states-aesthetics.md) §看板词表)。
- **「每次都变 · 不影响缓存」**:`call_blocks.volatile=true` → 该块每 call 变 bytes 却被排除出 cache key(CC 的 `x-anthropic-billing-header` nonce:`cch=…`/`cc_prev_req=…`,cache-hit 仍 ~100%)。
- **两个标 MUST 从 canonical 列(`cache_control`/`volatile`)渲染,MUST NOT 在前端重嗅 provider 专属正则**(如 billing-header 匹配)——那属 adapter([3.1](3.1-adapter-contract.md))职责。demo 已守此缝:provider 检测在分析层 `linearContext`(填 `b.volatile`/`b.cc`),前端 `ctxBlock` 只读 `b.volatile`/`b.cc`;产品把检测**下沉进 CC adapter**、前端保持只读 canonical 列。**破此缝(往通用视图塞 provider 分支)= 需 RFC 才放行**(不变式 3)。守卫:`no-provider-branches.test.mjs`「wire words: cached_tokens and the billing "cch=" marker are caught」与「src/web/v2 outside mock/ carries no provider, tool, harness-id or host literal」+ `ctxwin.test.mjs`(验收 #3)。

### 变化线(取代 cache-break 标记槽与 why 行)
- **何时画(MUST)**:`cacheBreak.cause ∉ QUIET_CAUSES`(`append`、`first-call`、`volatile-nonce-only`;`replay/analysis.mjs` 的那一份清单,问题道 [1.3](1.3-timeline-tracks.md) 也读它)。失败的步也画——它说的是内容变了,不是缓存。别的时候不画;锚 `#cachebrk` 也只在线存在时有。
- **画在哪**:第一个变了的块 `flat[cacheBreak.idx]` 前面(服务端 `cacheBreak()` 算的位置,跳过 volatile 块)。**窗口只负责"在哪画",不自算断点**:位置来自 [3.3](3.3-cache-model.md) 的同一套结构定位,数值真相取真实 usage、非 byte-diff。**必拒**在本部件用纯 byte-diff 臆测断点(demo v11 已证会撒谎)。那个块在一张折着的提问卡里时,线也在那张卡里;打开一步时落在线上归 [1.4](1.4-central-board.md)(落点)。
- **写什么**:「从这里起和第 K 步不同 · <原因> · 结构估计」。K = 缓存对比步(§两个对比步),按 [1.2](1.2-shell-layout.md) §编号:步与调用 写成主对话的第 K 步。<原因> 用 [2.2](2.2-call-turn-card.md) §缓存判定那张原因词表(`labels/replay.mjs`,键是 `src/view/analyze.mjs : CAUSE_META` 的闭集),不显示服务端的英文 `causeLabel`。线的悬停与读屏文字再写「第一个不同的块:<行头>」。
- **压缩**(`cause:'compaction'`):「从这里起和第 K 步不同 · 对话被压缩:以下整段重写 · 结构估计」;压缩是推断出来的(`steps[].compactionInferred`)时加「推测」([1.5](1.5-states-aesthetics.md) K-13)。
- **「结构估计」(MUST)**:线上必带,悬停「按块的结构比对得出,不是服务商真实的缓存边界;权威值是 查询层的散度点」(承 [3.2](3.2-normalized-model.md):128「结构估计,非真实边界」与[3.5](3.5-query-layer.md))。自动缓存的服务商(这一步没有一块带 `flat[].cc`)时「结构估计」旁再写「结构参考,非真实边界」——这条规则与守卫归 [1.4](1.4-central-board.md)(验收 #12)。
- **不写**:首个不同字节的偏移(服务端 `byteOffset` 今天是 UTF-16 下标,不是字节,D17①);归属与修法(`attribution` / `fixHint`);任何缓存状态(读写多少、复用、过期重建、服务商一侧的矛盾)。这些在步头的「缓存」按钮里([2.2](2.2-call-turn-card.md))。
- **线下的移除列表**:内容对比步里有、这一步没有的块(`keyDiff().removedBlocks`,volatile 不算),有一块以上时在线下写「第 K' 步里有、这一步没有的块:N 个 ▸」(K' = 内容对比步),默认收起;展开后每块一行,行头与保真标同正常块,正文按它在内容对比步里的 `text_ref` 回源。压缩时这就是被换掉的历史。
- **承 D17①「为什么 + 是不是你的锅」**:「为什么」(原因)留在线上;「是不是你的锅」(归属)进「缓存」按钮。原因 MUST 从 canonical 列读(看板上是 `cacheBreak.cause`,查询层里是散度点的原因,[3.2](3.2-normalized-model.md)),窗口 MUST NOT 自跑 byte-diff / provider 正则(承上「不自算断点」)。
- 守卫:`ctxwin.test.mjs`(验收 #7:线的位置等于服务端的 `cacheBreak.idx`);前端不跑 byte-diff 靠收尾审查。原因与写法的取舍见下。

## 两个对比步(本单元定义;词见 [1.5](1.5-states-aesthetics.md) §看板词表)

### 缓存对比步
- **是哪一步**:服务端比缓存用的那一步——同一 lane 里前一个没失败的调用。服务端今天的规则:多 lane 路径(Anthropic 线)按 `analyze()` 给的 `chainsPrefix`(失败的调用不前移),平 lane 路径按 `prevFlatOf`(只在调用不是 `error`、`status` 为空或 200 时前移)。
- **确切指针** = `cacheBreak.refGi`([4.4](4.4-server.md) §看板 v2 需要的补充)。`cacheBreak.refGi` 之前,前端按同一规则推:`replay/analysis.mjs : cacheRefOf()` 在这一步所在的 `lanes[].calls` 里往前找第一个 `error` 不为真、`status` 为空或 200 的调用。按字段在不在判断,不按版本。
- **谁用它**:变化线的「第 K 步」;步头「缓存」按钮与 ≈ 多花(`breakCost`,[2.2](2.2-call-turn-card.md));问题道的旗([1.3](1.3-timeline-tracks.md))。
- lane 的第一次调用没有缓存对比步(`cacheBreak.firstCall`)。

### 内容对比步
- **是哪一步**:用户选来比内容的那一步;默认 = 缓存对比步;参考步可选任意步。
- **怎么选**:步头的「对比 ▾」菜单按钮(不是悬停):默认项 / 选一步…;不是默认时按钮写「对比第 K 步 ×」,「新」的图例写第 K 步。控件归 [2.2](2.2-call-turn-card.md);放在步头。选定的步存在回放台状态里(`replay.mjs` 的 `diffRef`),跨 scrub 保留,直到按 ×;playhead 走到第 K 步本身时,这一步按默认比。
- **它管什么**:块上的「新」;变化线下的移除列表;「组成」按钮里的增长 Δ([2.2](2.2-call-turn-card.md))。
- **它的块不在当前这一页时**:取回那一页(`ensurePage()`);送到之前不标「新」、不画移除列表(不是"全都新",也不是"没有新")。

### 步间 diff
现状(承 demo,v2 已补齐):窗口对**内容对比步**做块级 key 集差(`replay/analysis.mjs : keyDiff()`)——「新」标本步新增块(`content_hash`/key 不在对比步)+ 变化线下列出移除的块;对比步可选任意步。demo 时代的两个局限已补上:① 参考步**硬钉上一步**;② **只标加项、不标移除**——compaction/改写下被删/重写的 message 块**不在本步**故不可见,漏报真实变更。
**规则**:**移除感知 + 任意参考步**的步间 diff。数据 = **两步 `call_blocks` 有序 `content_hash` 集差**(added = 本步有而参考步无;**removed = 参考步有而本步无**)——**廉价**(hash 集合运算,**零字节读**,承 [4.2](4.2-storage-etl.md) 去重存储 + D24)。参考步默认缓存对比步、可选任意步。**MUST NOT** 前端跑 byte-diff 臆测(承本节「不自算断点」);removed 块的全文按需 `text_ref` 回源。compaction 下 removed 集 = 被换血的历史,显式列出(在变化线下)。守卫:`test/web-v2/analysis.test.mjs`「keyDiff: added and removed key sets; volatile blocks never count; a compaction pair removes blocks」+ `ctxwin.test.mjs`(验收 #6);不跑 byte-diff 靠收尾审查。

## Edge cases
- **空 / 无请求步**(probe 或中断的 call):不崩;没有请求与请求解析不出两态及其措辞归 [1.4](1.4-central-board.md)(白名单 ⑥⑦)与 [1.5](1.5-states-aesthetics.md) K-05。
- **超长块**:显示剪裁 + 全量字符数标;全文回源可得(见保真标一节的"显示剪裁 ≠ 源截断")。
- **compaction**:整窗自然换血(内容变即整列换)——是**同一 session 内换血、不是 fork**(承 [3.4](3.4-session-identity.md));变化线落在第一个变了的块前(tools+system 幸存,通常是首个 message 块;保留了第一条提问的压缩落得更后,`cacheBreak.idx`)。
- **首 call `cache_read>0`**:跨 session 暖前缀(tools+system 跨会话字节相同),如实显示、不当异常(承 [3.3](3.3-cache-model.md));`first-call` 是安静原因,不画变化线,说法在「缓存」按钮里([2.2](2.2-call-turn-card.md))。
- **`tool_result.is_error`**:行头带服务端 `head.tag` 里的 `· error`(承 demo `blockHead`,今天在 `src/view/blockmeta.mjs : blockHead()`)。
- **块头 tag 的词**:`head.tag` 里的 kind / role 是 harness 无关的闭集,`labels/replay.mjs` 给一张词表(英文,D58①;指令 / 对话 / 工具调用 / 工具结果 / 系统提醒 / 错误 这些语义各一个词);不认识的值进技术细节,外面写「原因未知」;这张表进 `labels-complete` 断言(2026-10-08 审查;原「映射留 Extensions」作废)。
- **巨量块(500+)**:折叠 + 懒填 + 提问卡分组扛住;视口虚拟化留 Extension。
- **失败步之后**:缓存对比步跳过失败的那一步,变化线写更早的第 K 步;失败的步本身内容变了也画线(缓存上它不算断开,[2.2](2.2-call-turn-card.md))。
- **只差 volatile 块**:`volatile-nonce-only`,不画变化线,volatile 块不标「新」。
- **`cacheBreak.refGi` 之前前端与服务端不一致**:服务端多 lane 路径另跳过没有请求的调用,前端规则只看 `error` / `status`;两者不一致时以 `cacheBreak.refGi` 的 `refGi` 为准,`cacheBreak.refGi` 落地后前端规则自动退场(按字段在不在)。
- **缓存对比步不在当前这一页**:变化线照样能写 K(只要编号,`lanes[].calls` 与 `steps[].error` / `status` 在每一步上都有);移除列表与「新」要等内容对比步那一页送到。
- **跳到 `#cachebrk` 落空**:这一步没有变化线(过期重建、命中偏低这类缓存断开没有内容变化)→ 按 [1.4](1.4-central-board.md) 的落点走。
- **打开的块取正文失败**(网络、5xx):正文写原因、下次打开重取(不记住失败),该块补「◐ 取不到字节」,所在段撤回「以下逐字」。
- **窗口行的原因不止一种**:服务端的 `unaddressable` 原因去重后全部进技术细节;窗口行的句子不变。

## Risk / 回滚
本部件是**纯渲染函数**(归一化行 → DOM),用固化真实记录回归;失败回退上一绿点。**最大风险 = 徽章 / 保真回退到前端嗅 provider 特征**(违反不变式 3/4,必拒;守卫 `no-provider-branches.test.mjs` 与 `fidelity-marks.test.mjs`)——回滚策略:徽章降级为**只读 canonical 列**(`cache_control`/`volatile`/`faithfulness`),宁可少显不可前端瞎猜。
- **证明规则的撤回**:段头先写「以下逐字」、正文回来不是逐字再撤。按今天的 `classifyFidelity()`,带 `text_ref` 的块回来只会是 `verbatim` 或 `decoded`,所以撤回只在服务端定位与回源结果不一致时发生;它 MUST 当场发生,不等下一次重画(`fidelity-marks.test.mjs`)。回滚:证明规则只能收紧(更少地写「逐字」),不能放宽回旧的默认。
- **变化线说错第几步**:`cacheBreak.refGi` 之前靠前端规则;回滚是只画线不写 K,不回到每步都写缓存状态。
