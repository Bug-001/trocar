# asight · RFC 2.3 — 忠实上下文回放部件(★ 招牌)

> **服务意图(A2)**:意图 ①(逐字回放某步的完整上下文——这是 AC-1 逐字 diff 的**落点**)+ 兼作意图 ② 的**宿主**(块级 cache 断点 / per-call nonce 徽章、cache-break 标记槽;数值真相来自 [3.3](3.3-cache-model.md))。
> **受众**:人(核对"这就是模型这一步真收到的每一比特")+ agent(据此从 [3.2](3.2-normalized-model.md) 的 `call_blocks`/`block_contents` 渲染,**不回退到 provider 专属分支**)。
> **前置**:块数据 = [3.2](3.2-normalized-model.md)(`call_blocks` 有序 + `block_contents` 去重 + `text_ref` 回源);块语义 / `faithfulness` 由 [3.1](3.1-adapter-contract.md) 的 adapter 定;cache 徽章 / 断点真相由 [3.3](3.3-cache-model.md) 定;承 demo `linearContext`/`ctxBlock`/`ctxBody`/`rawContentText`。

## Goal
把一条 call 的上下文摊平成**一列有序 block 卡**,严格 assembly order **tools → system → messages**,每块一卡(role/kind/预览 + 保真标 + cache 徽章),点开即逐字看该块全文。这个中央窗口**就是**模型这一步真收到的每一比特——**无"不在列表中"、无另开的 raw 列**;窗口 = 真相本身。它是 AC-1 逐字 diff 的落点。承 demo v11 单窗口验证,泛化到跨 provider(承 3.1/3.2)。

## Definitions
- **block 卡(`.cblk`)**:一个 `call_blocks` 行的可视卡;默认折叠(只显头),点开懒填全文体。
- **段(section)**:`tools | system | messages` 三段之一(归一化;Codex `instructions`→system、`input[]`→messages,承 [3.2](3.2-normalized-model.md))。每段一个 header。
- **turn 分组**:messages 段内按"user 查询 ▸ 该回合动作"聚成可折叠 turn(承 demo `messageTurns`/`.cwturn`)。
- **保真标(faithfulness marker)**:块非逐字时就地贴的标记(见 [3.2](3.2-normalized-model.md) 枚举 `verbatim|metadata|opaque|summarized|omitted|truncated`)。
- **cache 徽章**:块级 ⟐ `cache bp`(声明断点)/ ↻ `per-call nonce`(volatile 块),从 canonical 列渲染。

## Plan(选定方案 + 取舍)
**选定**:**单一忠实窗口 + 逐字懒加载 + 徽章从 canonical 列渲染**。窗口只持有块的**元信息**(section/role/kind/preview/faithfulness/cache_control/volatile/resource_ref);全文在点开时经 `text_ref` 回 NDJSON 源**懒加载**。
**备选(未选)**:① **双栏**(左渲染视图 + 右原始 JSON 列)——demo v0 试过,注意力撕裂,且"渲染视图 + 独立 raw"结构诱导"渲染即真相"误判;② **每块预存全文进前端**——违反 [3.2](3.2-normalized-model.md)"本表不存全文、`text_ref` 回源"、且 `content_hash` 去重失效、内存爆。
**取舍**:窗口零全文冗余 + 逐字锚(`text_ref`)不飘 → 展开的每一个字符都可回到源 bytes,AC-1 天然成立。

## 部件结构(承 demo)

### 有序摊平:tools → system → messages(必拒乱序)
读 `call_blocks`(按 `seq`)→ 依次渲染。demo `linearContext(request)` 现解析出此序;**产品改从 [3.2](3.2-normalized-model.md) 的 `call_blocks.seq` 读**(见「跨 provider 泛化」)。assembly order MUST 与线上装配序一致——**乱序即谎报 AC-1**。

### block 卡:折叠头 + 懒展开体
- **头(`.cbh`)**:`role` 徽 · `kind` tag(如 `def`/`thinking`/`action · <tool>`/`observation · error`/`say`/`system-reminder`)· **preview**(≤90 字符、折空白;承 demo `preview=slice(0,90)`)· cache 徽章 · **块级首现标(D17②)** · 字符数。
- **块级首现标(承 D17②)**:该块 `content_hash`/key **不在上一 call**(且非 `volatile`)→ 头带 `◆ new`——它是本步新增的内容(= 重发 Δ 的组成),与上下文头的 growth Δ 呼应;复用块(cache-可复用前缀)**不标**,保持安静。demo `ctxBlock(b,i,prevKeys)`。逐块级「哪个块最重(段内占比)/ ↺复用×N」是 Extensions(承 draft),v0 先给最锋利的「新 vs 复用」二分。
- **体(`.cbc`)**:折叠态空,首次展开时 `ctxBody` 懒填(承 demo `toggleCtxBlock` 的 `dataset.filled` 门);**verbatim 全文**经 `rawContentText` 从源块还原(text / tool_use 的 `name(input)` / tool_result / thinking …)。**tools 段体 = 逐字 schema(D15,新 trace)**——展开见完整 `description` + `input_schema`;**D15 前的旧 trace 回落元数据摘要**(见保真标)。

### 段 header + messages 分 turn 折叠(承 D17②:段权重读出)
tools/system 段:块平铺。messages 段:按 turn 分组、可折叠,默认展开最新 turn(承 demo `turnOpen`/`lastTurnCall`)——长会话不淹没当前步。

**段 header 除段名外带「段权重读出」**(承 D17②,是 [2.2](2.2-call-turn-card.md) 卡上 schema-税条的**逐段展开落点**——头给摘要,段 header 给逐段明细,同一 `segTax` 真相两处一致,demo `.cwsecw`):
- 每段 header 显 `N 字节 · X% of call · ≈M 估tok`。**字节 = 段内各块 verbatim 内容 UTF-8 字节和**(内容真数);**token 标「≈估」**(char/4 proxy,provider 不回按段 token,不变式 4)。
- **messages 段 header 再分 `history / task` 两子权重**(承既有 turn 分组:task=末轮、history=其前)。
- **tools 段 D15 后字节可测(verbatim)**;D15 前旧 trace 仅元数据估算,就近标。

### faithfulness 就地标(保真边界 · 必拒隐瞒)
承不变式 4([0.0](0.0-overview.md) §核心不变式):凡块非逐字,UI MUST 就地标,MUST NOT 让人误以为看到完整线上真相。逐值:
- **`verbatim`(tools 段 · D15 默认)**:采集逐字存完整 `description` + `input_schema`(承 `capture.mjs`);adapter([3.1](3.1-adapter-contract.md) `linearContext`)派生 `descChars`/`props` 供折叠头显示、`verbatim=true`;体展开渲染完整 schema。卡带绿色 `verbatim` 标(纳入 AC-1)。
- **`metadata`(tools 段 · 仅旧 trace 回落)**:D15 之前的 trace 只有 `name + type + input_schema_props(参数名) + description_chars`,**schema 文本不留**。此时 `verbatim=false`,体里写 `description: N chars (schema text not retained)` + `⚠ metadata only`,卡带 `metadata` 标。**必拒**把它渲染得像逐字 schema。
- **`opaque`**:加密 reasoning(Codex `encrypted_content`)/ `redacted_thinking` → 显占位(demo:`[redacted_thinking]`),MUST NOT 冒充空文本或伪造明文。
- **`summarized`/`omitted`/`truncated`**:源侧被客户端摘要 / 省略 / 截断的块 → 就地标其性质。
- **显示剪裁 ≠ 源截断(需分清)**:展开体超阈值(demo 20000 字符)剪 + `… (N chars total)`——但**全文仍在 NDJSON 源可回**;这与 `faithfulness=truncated`(源本身就没抓全)是**两码事**,UI 措辞 MUST 区分"仅显示折叠、点击/回源看全" vs "线上真相本就不全"。

### cache 徽章(意图 ② 的块级钩子)
- **⟐ `cache bp`**:`call_blocks.cache_control` 非空 → provider 声明的显式断点(Anthropic `cache_control`);可缓存前缀存到**含本块**为止(承 demo tooltip)。
- **↻ `per-call nonce`**:`call_blocks.volatile=true` → 该块每 call 变 bytes 却被排除出 cache key(CC 的 `x-anthropic-billing-header` nonce:`cch=…`/`cc_prev_req=…`,cache-hit 仍 ~100%)。
- **徽章 MUST 从 canonical 列(`cache_control`/`volatile`)渲染,MUST NOT 在前端重嗅 provider 专属正则**(如 billing-header 匹配)——那属 adapter([3.1](3.1-adapter-contract.md))职责。demo 已守此缝:provider 检测在分析层 `linearContext`(填 `b.volatile`/`b.cc`),前端 `ctxBlock` 只读 `b.volatile`/`b.cc`;产品把检测**下沉进 CC adapter**、前端保持只读 canonical 列。**破此缝(往通用视图塞 provider 分支)= 需 RFC 才放行**(不变式 3)。
- **cache-break 标记槽**:窗口在"首个相对上一 call 分歧块"前留一条 marker(承 demo `cacheMarker`,锚 `#cachebrk`),标"以上 N 块是复用的 KV-cache 前缀 / 缓存过期重建 / 整窗重算"。**窗口只负责"在哪画",不自算断点**:数值(read/create)与真相判据(真实 usage,非 byte-diff;跳过 volatile)来自 [3.3](3.3-cache-model.md)。**必拒**在本部件用纯 byte-diff 臆测断点(demo v11 已证会撒谎)。
  - **深化(D17① · 「为什么 + 是不是你的锅」)**:marker 附一条 **why 行**,渲染 [3.3](3.3-cache-model.md) 归一化 `divergence_cause`(`compaction`/`tool-array-reorder`/`json-key-reorder`/`content-changed`/`volatile-nonce-only`/…)+ 归属配色(无害/复核/你的锅)+ 可执行 `fix_hint` + 块内 `divergence_byte_offset` 定位。**cause/offset 从 canonical `cache_events` 列读**([3.2](3.2-normalized-model.md)),窗口 MUST NOT 自跑 byte-diff / provider 正则(承上「不自算断点」)。why 行 MUST 就近标 **`结构估计`**(结构推断,非 provider 真实边界;不变式 4);`append`/首 call 属正常轮次,**不**画 why 行。

## 跨 provider 泛化(承 3.1/3.2)
demo 只跑 Anthropic,且每步 `linearContext(call.rec.request)` **现解析**原始请求。**产品改从 [3.2](3.2-normalized-model.md) 归一化行渲染**:`call_blocks`(有序 `content_hash` + `cache_control` + `volatile` + `resource_ref`)+ `block_contents`(`section`/`role`/`kind`/`preview`/`faithfulness`/`text_ref`)。section/role/kind 已由 adapter 归一(Codex `instructions`→system、`input[]`→messages、加密 reasoning→`opaque`)。→ **加 provider 只加 adapter,本部件零改**(AC-3)。

**本部件新测 MUST 断言**:
1. **AC-1 逐字(必拒违反)**:从 [3.2](3.2-normalized-model.md) 的 `call_blocks`+`block_contents`+`text_ref` **重建**窗口全文,与 NDJSON 源该 call 的 system/messages 块逐字 `diff = 0`(metadata 块除外**且**已标 faithfulness)。
2. **保真标存在(必拒隐瞒)**:tools 段每卡带 faithfulness 标——**新 trace = `verbatim`**(展开见完整 `input_schema`,纳入 AC-1)、**旧 trace = `metadata`** + `schema text not retained` 字样;`opaque` 块显占位、不显空文本;任一非 `verbatim` 的 `faithfulness` 值都渲染出**可见**标记。**必拒**把旧 trace 的元数据冒充逐字、或把新 trace 的逐字误标 metadata。
3. **徽章从 canonical 列(不变式 3)**:构造 `call_blocks.cache_control≠null` → ⟐ 出现;`volatile=true` → ↻ 出现**且不误触发** cache-break(承 demo `cacheBreak` 跳 volatile);`grep` 前端渲染代码**无** provider 专属正则(billing-header 等)驱动徽章。
4. **顺序**:窗口块序 == `tools→system→messages` == `call_blocks.seq`。
5. **跨 provider(AC-3)**:喂一条 Codex 归一化行(`instructions`→system、encrypted reasoning→`opaque`)→ 同部件渲染、opaque 标出、**前端主干 `git diff = 0`**。
6. **步间 diff · 移除感知 + 任意参考步(2026-07-16 planned)**:构造 step B(参考)与 step A,A 相对 B **既有新增块又有移除块**(如 compaction 换血或 message 删除)→ 断言窗口 **同时**列出 `added`(◆new)**与** `removed`(参考步有、本步无),且集合 = 两步 `call_blocks` 有序 `content_hash` 的集差;断言参考步**可指定为非上一步**的任意步;`grep` 渲染代码**无** byte-diff / provider 正则驱动该 diff(移除块全文按需 `text_ref` 回源)。

## Edge cases
- **空 / 无请求步**(probe 或中断的 call):显 `No request captured for this step`(承 demo),不崩。
- **超长块**:显示剪裁 + 全量字符数标;全文回源可得(见保真标一节的"显示剪裁 ≠ 源截断")。
- **compaction**:整窗自然换血(内容变即整列换)——是**同一 session 内换血、不是 fork**(承 [3.4](3.4-session-identity.md));cache marker 落首个 message 块(tools+system 幸存)。
- **首 call `cache_read>0`**:跨 session 暖前缀(tools+system 跨会话字节相同),如实显示、不当异常(承 [3.3](3.3-cache-model.md))。
- **`tool_result.is_error`**:观测块标 `· error`(承 demo `blockHead`)。
- **巨量块(500+)**:折叠 + 懒填 + turn 分组扛住;视口虚拟化留 Extension。

## Risk / 回滚
本部件是**纯渲染函数**(归一化行 → DOM),用固化真实记录回归;失败回退上一绿点。**最大风险 = 徽章 / 保真回退到前端嗅 provider 特征**(违反不变式 3/4,必拒)——回滚策略:徽章降级为**只读 canonical 列**(`cache_control`/`volatile`/`faithfulness`),宁可少显不可前端瞎猜。

## 步间 diff(从 Extensions 升为 planned)
现状(已建 · 承 demo):窗口对**上一 in-lane 步**做块级 diff——`◆ new` 标本步新增块(`content_hash`/key 不在上一步)+ cache-break marker 标复用前缀断点 + growth Δ。**局限**:① 参考步**硬钉上一步**(不能选任意参考步);② **只标加项、不标移除**——compaction/改写下被删/重写的 message 块**不在本步**故不可见,漏报真实变更。
**升级(planned)**:**移除感知 + 任意参考步**的步间 diff。数据 = **两步 `call_blocks` 有序 `content_hash` 集差**(added = 本步有而参考步无;**removed = 参考步有而本步无**;reordered = 位置变)——**廉价**(hash 集合运算,**零字节读**,承 [4.2](4.2-storage-etl.md) 去重存储 + D24)。参考步默认上一步、可选任意步。**MUST NOT** 前端跑 byte-diff 臆测(承本节「不自算断点」);removed 块的全文按需 `text_ref` 回源。compaction 下 removed 集 = 被换血的历史,显式列出(补当前「◆new 只加项」的盲区)。
