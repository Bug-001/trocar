# asight · RFC 3.5 — 查询层(前端 ↔ DuckDB 契约)

> **服务意图(A2)**:意图 ①②——前端一切视图的数据都经此层从 [3.2](3.2-normalized-model.md) 取。
> **受众**:人(核对每个视图都有对应查询)+ agent(据此实现查询 API / 查询集)。
> **前置**:表在 [3.2](3.2-normalized-model.md);传输方式(服务端 API vs 浏览器内 DuckDB-Wasm)是 **OPEN**,待 [4.4](4.4-server.md) 定。

## Goal
定义**哪些视图靠哪些查询**、查询接口的形状,使前端只读 [3.2](3.2-normalized-model.md) 的表、走 SQL(不手搓字符串匹配)。

## Plan(选定方案 + 取舍)
**选定**:一组**具名只读查询**(view/参数化 SQL)作为前端与 DuckDB 之间的唯一契约;前端不拼裸表名/裸列。
**备选(未选)**:前端直发任意 SQL——灵活但把 schema 细节漏进前端(违反适配缝不漏进前端)、难演进。
**取舍**:具名查询集 = schema 变更只改查询层一处,前端稳定。

**OPEN（待 4.4 定,记 TODO 遍历至闭合)**:查询在**服务端执行(HTTP 返 JSON)** 还是**浏览器内 DuckDB-Wasm**。判据:个人仪器单机 → 服务端最简;大 session 客户端 SQL 免往返 → Wasm。不阻塞本层其余设计。

## 查询集(视图 → 查询)
| 前端视图 | 查询 | 读哪些表 |
|---|---|---|
| session 选择器 / fork 树(1.2) | 列 sessions + 血缘树 | `sessions` |
| 排轴 / 时间轴(1.3) | 某 session 的 calls 按 seq + 每 call 的类型构成 | `calls`, `call_blocks`(聚合 section/kind 占比) |
| 中央回放:某步上下文(1.4/2.3) | 某 call 的有序 blocks + 内容/faithfulness/cache_control | `call_blocks` ⋈ `block_contents` |
| cache 叠加(1.3) + call card(2.2) | 某 session 每 call 的 cache_events + usage;cache-break = 相邻 call 的 content_hash 序列 diff | `usage`, `cache_events`, `call_blocks` |
| 资源管理器(2.4) | 某 session 的 resource 生命周期 | `resource_events` |
| 跨 session 分析(② 招牌) | "所有 session 里哪些文件进过上下文"、"各 provider cache 命中分布"、"三家 break_kind 对比" | 全表聚合 |
| 未映射告警面(保真兜底 / D7 输入) | `unmapped_fields` 视图:各 provider/harness 尚未 surface 的 `extra` 键 + 频次 | `calls`/`sessions`/…的 `extra` 聚合(见 [3.2](3.2-normalized-model.md)) |

## 访问模式（MUST）
- **只读**;写只经 ETL(4.2)。
- cache-break 用 SQL 对相邻 call 的 `content_hash` 序列做 diff(承 3.2 去重设计),不在前端逐块比全文。
- 大结果**分页/惰性**(承 D6 虚拟化);查询层给出游标/limit 契约。

## Out-of-scope
表结构(3.2)、ETL 填数(4.2)、传输/服务(4.4)、部件渲染(2.x)。

## 影响面
所有前端部件(2.x)的取数;改查询契约 = 改前后端接缝。

## 验收(可跑 check)
- 每个上表视图都有一条具名查询,在真实 CC 数据上跑出正确结果。
- cache-break 查询产出的散度点与 3.3 的 `structural_divergence_seq` 一致。
- 跨 session 分析查询("三家 break_kind 对比")在含≥2 provider 的库上返回可对比结果。

## Edge cases
- 空/超大 session:分页契约兜底。
- 缺字段(DeepSeek `cache_write=NULL`):聚合查询 MUST 容 NULL(用 `hit`/`miss` 而非 `write`)。

## Risk / 回滚
查询层是纯读;改查询不动数据,可即时回退。传输 OPEN 决策(4.4)前,先以最简服务端查询打通,不阻塞。

## Extensions
更多分析查询(cache 工程对比、跨 harness 行为模式);传输方式定案后收敛 OPEN。
