# asight · RFC 3.5 — 查询层(具名查询 + 段索引)

> **服务意图(A2)**:意图 ①②——前端与脚本一切视图的数据都经此层取。
> **受众**:人(核对每个视图都有对应查询)+ agent(据此实现查询集)。
> **前置**:原始记录与段索引在 [4.2](4.2-storage-etl.md);读出来的字段语义在 [3.2](3.2-normalized-model.md);用户可见的名字、参数与速度目标在 [1.6](1.6-cli.md) §4.1(**权威**,本单元不重复列);HTTP 外壳在 [4.4](4.4-server.md)。
> **决策**:D59(读数据只有 `asight query` 一个核心,看板是它的 HTTP 外壳)· D63(这份代码跑在守护进程的查询工作进程里,两个壳先问它)。

## Goal
定义**哪些视图靠哪个具名查询**、查询函数的形状,使前端只按**名字**取数:它既不知道数据在明文段还是封存件里,也不拼路径、不解析原始记录。

## Plan(选定方案 + 取舍)
**选定**:一组**具名只读查询**,每个 = 一个纯函数 `(params, ctx) → 文档`,直接读原始记录([4.2](4.2-storage-etl.md) 的段 + 段索引)。`asight query <名字>` 与 `GET /api/<名字>` 调同一个函数、返同一个文档([1.6](1.6-cli.md) §4.1,验收 V80)。
**备选(未选)**:① 先把记录摊进一个分析库再查 —— 多一条写路径、一份要维护的派生真相,而速度诉求由段索引 + 回源就能满足(D59);② 前端直发任意查询语言 —— 把存储细节漏进前端(违「适配缝不漏进前端」)。
**取舍**:具名查询集 = 存储变化只改查询层一处,前端稳定;派生层只剩可删可重建的段索引。

## 查询集(视图 → 查询)
名字、参数与分页键的权威在 [1.6](1.6-cli.md) §4.1 与附录 C;这里只记每个视图靠谁、读什么。

| 前端视图 | 查询 | 读什么 |
|---|---|---|
| session 选择器 / fork 树(1.2) | `sessions` | 段索引的 session 键 + 时间 + 条数;血缘与 fork 判定按 [3.4](3.4-session-identity.md) 在读取侧算 |
| 排轴 / 时间轴(1.3) | `session` | 该会话的记录按步排;每步的块构成按 [3.1](3.1-adapter-contract.md) 的 dissector 解出 |
| 中央回放:某步上下文(1.4/2.3) | `session`(页内)+ `block` | 有序块 + 回源逐字字节 + `faithfulness`([4.2](4.2-storage-etl.md) §回源指针) |
| cache 叠加(1.3) + call card(2.2) | `session` | 每步的 usage 与 cache 事实;cache-break 的散度点由查询对相邻调用的 `content_hash` 序列算出([3.3](3.3-cache-model.md)),**前端不逐块比全文** |
| 资源管理器(2.4) | `session` | 资源生命周期:flat 事件在查询里折成 per-resource 段 + loads,部件只渲染折叠结果 |
| 跨会话分析(② 招牌) | `calls` | 任何类别的调用列表(类别、host、路径、状态码、大小、保存级别、记录 id) |
| 存了什么(D60③ · [2.6](2.6-detail-panel.md)) | `classes` | 类别表 + 每类在 24 h / 7 d / 全部的条数与大小 + 盘上占用,全部出自段索引 |
| 原始层状态 | `segments` | 每段的状态(`writing` / `closed` / `sealed`)、记录数、大小、封存比、封存的问题 |
| 费用 | `pricing` | 价格表与它的来源 |
| 采集健康 | `status` / `doctor` | 分别调 `src/cli/status.mjs` 的 `statusDoc()` 与 `src/cli/doctor.mjs` 的 `doctorDoc()` |

`segments` 只列 `~/.asight/raw/` 的段(段是唯一的记录位置,[4.1](4.1-capture-sources.md) §记录 id 与升级)。

## 访问模式(MUST)
- **只读**。查询唯一会写的是可删可重建的段索引 `~/.asight/index/`([4.2](4.2-storage-etl.md));不需要先跑别的命令。
- **谁执行它**(D63):守护进程按需 fork 一个低优先级的**查询工作进程**,`asight query` 与 `GET /api/<名字>` 都先经它(于是两边共用同一份温缓存);没有守护进程应答时谁问谁就在自己进程里跑同一份代码,文档逐字节相同——所以查询 **MUST NOT** 把守护进程当前置条件。**还没有工作进程时守护进程立刻说「没有温的工作进程」**,问的人就地答(冷查询 MUST NOT 比本地慢),工作进程在背后被同一条查询热起来;装配这类「为下一次查询建的东西」只在工作进程里建、且在答案发出之后(一次性的 CLI 进程紧接着就退出,不替它付这笔钱),缓存命中与不命中的文档 MUST 逐字节相同。
- **缓存按依赖失效,不答陈旧**(D63 · D62③):工作进程缓段索引行与会话装配,每次请求按源文件的 (大小, mtime, ctime) 核对。一个会话的答案只依赖**它自己的记录表**:别的会话添了记录 **MUST NOT** 使它的已装配结果作废(否则采集着就没有「附近的查询」);反过来,会话 X 新添的记录 MUST 出现在 X 的下一次查询里。
- **读不全不静默(D38)**:某段读不出、某行坏了,照样给出文档,读不到的列进 `errors: [{where, reason}]`。工作进程崩了或超时同理:查询照样答(重新 fork 或走本地那条),并留下一条带闭集 `code` 的记录。
- **分页**:大结果按游标分页(承 D6 虚拟化),契约在 [1.6](1.6-cli.md) §4.1(`--limit` / `--after`、文档里的 `page.next` / `page.has_more`)。`session` 的游标单元是**全局调用序号**:全部调用恒回时间轴要的轻量 meta,**重载荷(请求体、逐字块、响应文本)只回窗口内的调用**,窗口外的标 `paged_out:true`(保真边界 · 不变式 4:不静默丢)。
- **内存有界**:查询流式读记录、不把一整段读进内存;回源按偏移或帧解码(有界 LRU)。

## Out-of-scope
记录字段语义([3.2](3.2-normalized-model.md))、存储与封存([4.2](4.2-storage-etl.md))、HTTP 与静态文件([4.4](4.4-server.md))、部件渲染(2.x)、用户可见的输出版式([1.6](1.6-cli.md) §1.1)。

## 影响面
所有前端部件(2.x)与 `asight query` 的取数;改查询名、参数或文档形状 = 改前后端接缝,同时要改 [1.6](1.6-cli.md) §4.1 与附录 C。

## 验收(可跑 check)
- 上表每个视图都有一条具名查询,在真实采集数据上跑出正确结果。
- `asight query <名字>` 与 `GET /api/<名字>` 逐字段相等([1.6](1.6-cli.md) V80)。
- 速度目标见 [1.6](1.6-cli.md) §4.1(冷启动进程、附录 D 的参考数据)。
- 删掉段索引后结果不变、只是慢([4.2](4.2-storage-etl.md) 验收 7)。

## Edge cases
- 空数据:每个查询返空列表 + `page.has_more:false`,不报错、不建空壳文件。
- 超大会话:分页契约兜底;查询不把整段读进内存。
- 缺字段(DeepSeek 没有 `cache_write`):聚合 MUST 容缺(用 `hit` / `miss` 而非 `write`)。
- 正在写的段:查询读到它已索引到的偏移为止,半行不当记录。

## Risk / 回滚
查询层是纯读:改查询不动数据,可即时回退;结果可疑时删段索引重建,源零损失。

## Extensions
更多分析查询(cache 工程对比、跨 harness 行为模式)——新增一个名字 = 加一个模块 + 一行注册,前端与外壳不改。
