# asight · RFC 5.1 — 拦截 / 修改 / 重发(agent 界的 Burp Suite)

> **状态**:方向已定(**D30**),机制待设计,**尚无代码**。本文件取代原「5.1 主动模式(预留)」:D16 的观测 / 主动模式划分已取消。
> **前置**:采集 = [4.1](4.1-capture-sources.md)(重设计方向见 **D31**);统一信封 = [4.1](4.1-capture-sources.md) §统一原始信封;归一化 = [3.2](3.2-normalized-model.md);服务 = [4.4](4.4-server.md);写通道的安全门 = D26。

## Goal

asight 不只看清 agent 发给模型的每一比特,还能**改**:拦下一条请求、改它的上下文再放行;或把一条历史请求改完再发一次。用途是调试和受控实验,比如「这一步换掉某块上下文,模型会怎么答」。

## 已定(D30)

1. **不分模式**。拦截、修改、重发是采集器本身的能力,不是另一个产品形态。
2. **授权 = 本机操作者**。运行 asight 的人在本机显式打开、随时可关。没有操作者的显式操作或显式配置的规则时,asight 原样转发,不主动发请求、不改包。
3. **凭据**。允许带着 agent 自己的凭据转发改后的请求,也允许重发历史请求;只限操作者触发的这两类动作。
4. **源真相与标注**。原始请求、改后请求都逐字存,外加一条 intervention 事件(谁、何时、改了什么、依据哪条规则);MUST NOT 用改后覆盖原始。看板 MUST 就地标明哪些请求被改过、哪些是 asight 发起的。(不变式 2、4)
5. **审计**。每次修改、重发都留可追溯的记录,操作者能查看和导出。

## 待设计(OPEN)

- **拦截点**:放进 D31 的按进程截流守护进程,请求在转发前可以被扣住。扣住期间 agent 在等,要有超时和默认放行,避免把 agent 卡死。
- **交互**:参考 Burp——拦截开关 + 待放行队列(逐条编辑后放行)、自动替换规则(match & replace)、重发面板(Repeater)。
- **schema**:`interventions` 表或 `calls.intervention` 标记,记 {原始 ref, 改后 ref, 动作, 规则或操作者, 时刻}。
- **响应**:只改请求,还是也允许改模型的回复;改了怎么标。
- **重发的代价**:重发会真实消耗用户额度;用订阅类 OAuth 凭据频繁重发可能触发 provider 风控。UI 要提示,重发要能限速。
- **入口**:修改、重发会向上游发请求,属于写操作,不能走只读数据面([4.4](4.4-server.md));入口放在控制面一类的写通道,带同样的 Host / Origin / CSRF 门(D26)。

## 自动适配(auto-adapt · 原 5.1 保留部分)

从原始流量自动猜 provider 线格式与 harness 约定,少写或不写手工 dissector。它只读、只猜、可被手工 dissector 覆盖;猜测结果在 UI 标「自动推断,可能不准」(不变式 4)。可作为 [3.1](3.1-adapter-contract.md) 的 Extension 独立推进。

## 安全边界

这是对 agent 流量的中间人修改能力。合法用途 = 操作者调试、实验**自己机器上、自己账号下**的 agent;不用于拦截或修改不属于操作者的流量。单机、单用户、只绑 loopback 的边界不变(Non-Goals)。
