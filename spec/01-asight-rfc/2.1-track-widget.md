# asight · RFC 2.1 — 轨道部件

> **服务意图(A2)**:意图 ①(多条并行 lane 在同一时间基上定位每一步、click 跳看板同刻 → 看懂 agent 行为)为主;意图 ②(cache 叠加轨 / 资源轨都是本部件的实例 → 看懂上下文/缓存工程)为其复用底座。这是 2.x 里最底层的**通用轨道原语**,上面所有 track 皆其实例。
> **受众**:人(在轨上定位任意一步、读"审到第几步")+ agent(据此实现渲染 / 命中 / 抽样,加 lane 只加 kind→皮肤映射)。
> **前置**:共享时间轴 / 排轴布局在 [1.3](1.3-timeline-tracks.md)(本部件消费其 `xOf` 轴与轨道位);lane 语义(`calls.lane`)在 [3.2](3.2-normalized-model.md);click 落点的下游(中央看板 scrub / card / 逐字窗)在 [1.4](1.4-central-board.md) / [2.2](2.2-call-turn-card.md) / [2.3](2.3-context-window.md);subagent 血缘在 [3.4](3.4-session-identity.md)。

## Goal

一套**与 provider/harness 无关**的轨道部件:一条 lane 内按 `xOf(ts)` 把每个 call 定位成一个 **tick**(点事件)或 **pbar**(单值柱,高度=量级);整条轨可 hover/click 取**最近 call**(不止渲染出的点);click→选中并把中央看板跳到同刻;monitor/probe 轨 hover→高亮"审到会话第几步"的 bracket。**为何独立成件**:cache 叠加轨、资源轨、监测轨、子 agent 轨、probe 轨——形态各异但交互同构;抽出一个 kind 驱动皮肤的原语,加一种轨只加一行 kind→样式,不碰前端主干(承不变式 3)。

## 前置定义(Definitions)

- **lane(车道)**:一条时间平行轨,承一路同类 call。归一化 `calls.lane`(见 [3.2](3.2-normalized-model.md)):`main`(会话骨,即 anchor)/ `subagent` / `monitor` / `aux` / `probe`。
- **anchor(锚轨)**:`main` 车道;它的 call 时间戳序列 `anchorTs` 定义**整块时间基**——其余所有轨都投影到这条轴上。
- **tick**:一个 call 在轨内的点标记(`.tick`,9px 圆点),`left = xOf(ts)`。
- **pbar**:probe 轨里的单值竖柱(`.pbar`),`left = xOf(ts)`、`height ∝ ctx`(该步被 count_tokens 量到的完整上下文大小)。
- **审查 bracket**:monitor/probe hover 时,在会话骨上刷出的"这一步覆盖到第几个 turn"的方括号(`turnsReviewed(ts)` = `anchorTs` 中 ts ≤ 该 call 的 turn 数)。

## Plan(选定方案 + 取舍)

**选定**:**一个通用 lane-track 原语 · kind 驱动皮肤 · 抽样渲染 + 全量命中**。
- 形态由 `lane.kind` 决定皮肤(色/形),不由 provider/harness 决定:tick 分色 monitor=粉红(`--pink`)/ aux=灰(`--dimmer`)/ subagent=琥珀(`--amber`)/ notify=绿 / titlegen=青 / quota=暗;probe 独用蓝(`--cyan`)竖 pbar 且高=ctx;flag→红光(`.tick.flag`)、interrupted→红小点(`.errtick`)。
- 定位统一走 `xOf(ts)`(见「时间基」),一条轨 = 一个 `.railbody`。
- **probe 轨最多渲染 300 个 tick**(`MAX=300, step=ceil(n/MAX)`,每 `step` 取一),但**整条 railbody 的 hover/click 命中全量 `lane.calls`(取 x 最近)**,计数标真值——于是 691 个 probe 只画 ~300 点、却每个都可达(见「保真边界」)。

**备选(未选)**:① **每 call 一个 DOM 节点全量渲染**——691+ probe(或上万 tick)直接灌进 DOM,滚动/hover 卡死(D6 已选虚拟化,正为治此);② **每种 lane 各写一套专用轨部件**——harness/provider 专属渲染分支漏进前端主干(**违反不变式 3 · 需 RFC 才放行**)。

**取舍**:通用部件 + kind→皮肤 → 加 harness / 加 lane 只加一行样式映射,**前端主干 git diff = 0**(直服 AC-3);抽样渲染 + 全量命中 → 高吞吐下每个 call 仍可选中,代价是**视觉非 1:1**——就地标"抽样显示 / 计数真值"(保真边界)。

## 部件构成(落地细节 · 承 demo)

**① 时间基 `xOf(ts) → [0,1)`**。以 anchor(`main`)的 call 时间戳 `anchorTs` 为节点做**分段线性**插值:落在第 `i`、`i+1` 个 turn 之间 → `(i+frac)/n`;早于首 turn → `0`,晚于末 turn → 钳到 `(n-1)/n + 0.999/n`。**关键**:轴不是线性墙钟,而是**会话自身的事件时间**——于是任一轨的 tick 恰好落在它"发生在哪个 turn 前后"的位置下方,多轨天然对齐。`left`/`height` 以 `%`/`px` 定位,不动 DOM 数量。

**② 轨渲染 `renderTicks(lane)`**。非 probe 轨:`lane.calls` 逐个出 `.tick`,`left:(xOf*100)%`,title 带 icon/时间/ctx 或"⚠ interrupted"。probe 轨:抽样后出 `.pbar`,`height=max(1, round(ctx/peakCtx*24))`px——**柱高即上下文规模**,一眼看出上下文随会话涨缩。

**③ 整条命中 `nearestX(e)`**。`railbody` 上 mousemove/click 把光标 x 归一到 `[0,1]`,遍历**全量** `lane.calls` 取 `|xOf(c.ts) − f|` 最小者。即使该 call 是被抽样跳过、未画出的 pbar,也能命中并打开。**这是"抽样显示但全量可达"的机制核心**。

**④ 选中 + 跳看板 `selectTick(lane,i)`**。pin `selTick={laneId,i}`、加 `.sel`;若 monitor/probe → 画审查 bracket,否则清;并把中央看板 `playhead = nearestByTs(anchor, c.ts)`、`follow=false`,重渲会话骨 + 逐字上下文窗 + outline。**→ 轨 tick 是通往中央看板的导航控件**(下游 [1.4](1.4-central-board.md) / [2.2](2.2-call-turn-card.md) / [2.3](2.3-context-window.md));并 `openDetail` 弹出该 lane-call 的原始输入/输出面板。

**⑤ 审查 bracket `highlightRange(lane,i)`**(仅 monitor/probe)。`k=turnsReviewed(ts)`,把会话骨前 `k` 条 bar 标 `.reviewed`、`#reviewbracket` 宽设 `k/n`。回答"这个安全监测 / probe 这一刻覆盖到会话的第几步"。

**⑥ 折叠 / 分组**(与 [1.3](1.3-timeline-tracks.md) 协作)。多条短 subagent 轨(如 review/eval fan-out)默认收进一条折叠组轨,避免淹没会话;每轨可单独 collapse。分组**布局策略**属 1.3,本部件只提供单轨的收合渲染与命中。

**⑦ overview+detail brush 部件**(承 [1.3](1.3-timeline-tracks.md) 的 D13 导航,DOM/手势落在本件)。两部分:
- **overview 概览条渲染**:横跨全 `[0,N)`;`N≤OVW_BARCAP`(≈60)逐 call 出缩略柱(高 ∝ `total_input`),否则桶降采样出 streamline 折线并挂「采样显示」标注(承保真边界)。overview 自有一套 `xOfOv(i)=i/N` 定位,与 detail 的 view 轴解耦。
- **brush + view 窗**:模块态加 `view={lo,hi}`(整步,`0≤lo<hi≤N`,初始 `{0,N}`=全窗)。detail 的 `xOf` 由固定 `(i+frac)/n` 改为**读 view 的** `xOfView(ts)=(pos(ts)-lo)/(hi-lo)`(`pos(ts)`=原分段线性步位),越界钳 `[0,1)`;柱/tick/pbar/cache 格/坐标轴 MUST **全部**经此同一 `xOfView`(锁步,承 1.3 /N 收敛)。brush DOM 盖在 overview 上,`left=lo/N`、`width=(hi-lo)/N`;Pointer Events:**拖体 = 平移**(`lo,hi` 同增减、宽守恒)、**拖左/右 handle = 缩放**(改单边,`hi-lo≥1`),`setPointerCapture`,钳 `[0,N]`,拖动即 `setView` → 重渲 detail(承 divider 同款防御:shim 无 `setPointerCapture` 时 try/catch 静默)。`setView` 单一入口改 `view` 并触发 detail 重渲 + brush 位置回写(**brush 位置 = detail 视窗**恒一致)。
- **playhead 在 overview 恒可见**:overview 上按 `playhead/N` 画标;`selectTick`/scrub 到 `view` 外的步时 SHOULD `setView` 平移含之(follow;承 [1.4](1.4-central-board.md))。

## 保真边界(承不变式 4,[0.0](0.0-overview.md) §核心不变式 · 必拒隐瞒)

- **probe 抽样显示**:渲染的 pbar 数 ≤ 300 ≠ probe 真数。**MUST** 用 `lane.calls.length`(全量)标计数(轨头 `.rc` + stats 的 👁 计数),UI **MUST NOT** 让人以为只有 ~300 次;hover/click **MUST** 命中全量。规则:**抽样只降视觉密度,绝不降计数真值与可达性**。
- **tick/pbar 是派生投影**:位置/柱高是 `ts`/`ctx` 的可视化投影,**非逐字 bytes**。本部件是**导航索引**,不承 AC-1 逐字回放——逐字上下文在 [2.3](2.3-context-window.md)、逐字 usage/原文在 [2.2](2.2-call-turn-card.md) 与 detail 面板。
- **审查 bracket 是结构估计**:`turnsReviewed` 按**墙钟 ts** 数 turn(ts ≤ 该 call 的 main 步数),是"覆盖范围"的**结构近似**,**非解析自 monitor payload 的 `<transcript>`**;真·逐字审查内容在 detail 面板逐字展开。UI 若把 bracket/`call #1→#k` 呈现为精确边界,**MUST** 就地标"近似(按时序)"。

## 验收(可跑 check · 具体测试要求)

沿用已提交的 headless render gate(DOM shim 下驱动真实 render 管线,断言各面板 + AC-1 逐字)。现有 gate 只覆盖会话骨 / cache 带 / 逐字窗 / outline / 资源;**本模块须新增对 `#rails` 轨道部件的断言**——照该文件既有手法(在 in-scope harness 里直接调内部函数、读回 HTML/状态,不依赖真实 DOM 事件):

- **AC-轨渲染**:喂一条含 `monitor`/`aux`/`subagent`/`probe` 多 lane 的 fixture,调 `renderTicks(lane)`;非 probe 轨的 `.tick` 数 = `lane.calls.length`,且每个 `left%` 与 `xOf(c.ts)*100` 一致(轨-会话对齐)。
- **AC-抽样不降真值(保真边界)**:构造 `probe.calls.length > 300`(如 691),`renderTicks` 出的 `.pbar` 数 ≤ 300;**同时**断言轨头计数 / stats 👁 用**真数(691)**而非 300 —— 即"抽样显示 vs 计数真值"分离。
- **AC-全量可达**:取一个**被抽样跳过、未渲染**的 probe 下标,用其 `xOf(ts)` 反推 railbody 命中 x → `nearestX` 应解析回该(或最近)全量下标,`selectTick` 能 pin 并 `openDetail`。证明"每个 call 可达,不止渲染的 ~300 点"。
- **AC-跳看板**:`selectTick(lane,i)` 后 `selTick` 已 pin 且 `playhead === nearestByTs(anchor, c.ts)`——轨→中央看板同刻联动。
- **AC-审查 bracket**:monitor/probe 轨 `highlightRange(lane,i)` 后,`#reviewbracket` 宽 % === `turnsReviewed(ts)/anchor.calls.length`;**且** aux/subagent 等非 monitor/probe 轨 hover **不**触发 bracket(kind 门控正确)。

- **AC-brush 重标定(D13)**:渲染 overview + brush;程序化 `setView({lo,hi})` 到子区间后,断言 detail 主柱数 `=== hi-lo`、每柱/tick `left%` 走 `xOfView`(= `(pos−lo)/(hi−lo)`)、cache 格与 ticks 同轴锁步(逐行仍列对齐);brush DOM `left%≈lo/N`、`width%≈(hi-lo)/N`。**平移不变宽**:`setView` 平移后 `hi-lo` 守恒。`N>OVW_BARCAP` 时 overview 出「采样显示」标注。拖拽手势(pointerdown/move/up)在 shim 下可跳过,核心断言走 `setView` 直调 + 重渲后的 DOM/状态。

> 注:现 DOM shim 的 `querySelectorAll` 返回 `[]`,故新测 **SHOULD** 直接调 `renderTicks`/`nearestX`/`selectTick`/`highlightRange`/`setView` 并断言返回串与模块状态(`selTick`/`playhead`/`view`),与既有 AC-1 段直调 `linearContext`、point-4 段直调 `viewResource` 同法。

## Edge cases

- **空轨**:`lane.calls.length===0` → `railbody` 命中 guard 直接 return,不挂事件、不出 tick。
- **ts 越界**:早于/晚于会话窗 → `xOf` 钳到 `[0, (n-1)/n+0.999/n]`,不溢出轨。
- **单/极短会话**:`n` 小 → `xOf` 仍除 `n`,tick 挤在轨左侧但可命中(nearest 仍解析)。
- **同刻突发**:多 tick 撞同一 x → 视觉重叠;`nearestX` 仍解析出单一最近 call(交互不歧义),视觉重叠可接受。
- **interrupted call**:无 ctx → `.errtick`(红小点)、pbar 高走 `max(1,…)` 兜底,不塌成 0 高不可点。
- **probe 恰 ≤ 300**:`step=1`,不抽样,渲染 = 全量。
- **Codex/DeepSeek lane**:同一部件、kind 驱动,**无 provider 分支**(适配缝守在 3.1/3.2,不漏进本件)。

## Risk / 回滚

纯渲染 + 交互部件,**不采集、不发请求、不写源**——OBSERVE-only(不变式 1)平凡成立。`MAX=300` 是密度调参:改它只变渲染密度,**不动计数真值与可达性**(二者恒全量),故非保真风险。回滚 = rev 本部件渲染函数;上游 `calls.lane`/`ts` 数据与其余面板不受影响。加 kind→皮肤 = 加行可回退;加 lane 枚举须先过 spec 闸(见影响面)。

## Extensions(预留,不在 demo 已实现范围)

- **基础缩放/平移 = v1(D13 已改定,见部件 ⑦ + [1.3](1.3-timeline-tracks.md))**:overview+detail brush 导航把"缩放(拖 handle)+ 平移(拖体)"纳入 v1,detail 经 `xOfView` 对 view 窗重标定。**仍属 Extension** 的是:缩放时**抽样密度随视窗自适应变深**(现 `MAX=300` 是全窗固定采样,收窄视窗后可提采样精度/换语义层级)、以及 brush 上的**框选取词/区间导出**。
- 更细 lane 皮肤(现 demo 已有 `notify`/`titlegen`/`quota` 等 CC 行为子类色标,但 [3.2](3.2-normalized-model.md) 的 canonical `lane` 只到 `aux`)——**已定(D8)**:子类是**渲染期投影**(前端侧 子类→皮肤 映射),schema 保粗 `lane`、不加 CC 子类枚举;照此扩皮肤。
- pbar 之外的第二可视通道(如按 cache 命中率给 tick 描边),挂进同一 kind→皮肤表,不改交互主干。
