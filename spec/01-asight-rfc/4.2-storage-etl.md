# asight · RFC 4.2 — 存储(原始层按段存 + 封存 + 段索引)

> **服务意图(A2)**:同时服务 ①(逐字回放)与 ②(cache 叠加)——它定义**采集到的字节落在哪、怎么被压实、怎么被定位回去**。
> **受众**:人(核对派生层不覆盖源、崩溃不丢数)+ agent(据此实现写路径、封存器与段索引)。
> **前置**:源信封(怎么拿到 bytes、NDJSON 长什么样)= [4.1](4.1-capture-sources.md);记录→归一化块的纯函数 = [3.1](3.1-adapter-contract.md);读取侧的模型 = [3.2](3.2-normalized-model.md);cache 真相规则 = [3.3](3.3-cache-model.md);身份/血缘判定 = [3.4](3.4-session-identity.md);谁读这些文件 = [3.5](3.5-query-layer.md)。
> **决策**:D27(家目录)· D34(体积预算)· D35(封存格式)· D59(读数据只有 `asight query`,派生层只剩可重建的段索引)· D60(按大小切段、守护进程自动封存)。

## Goal
定义原始层:守护进程把信封追加到**段**文件、段关闭后被**无损封存**、读取侧靠**段索引**随机定位某条记录与某块字节。原始 NDJSON 是唯一源真相;**派生层只有可删可重建的段索引**(不变式 2([0.0](0.0-overview.md) §核心不变式),**必拒**违反)。

## 前置定义(Definitions)
- **段(segment)**:一个 append-only 的 NDJSON 文件 `~/.asight/raw/<段>.ndjson`(0600),一行一次上游往返(HTTP 请求,或 WebSocket 上的一次逻辑调用,D37)。段名 = 开段时刻的 UTC `YYYYMMDDTHHMMSSZ`,撞名加 `-2`、`-3`。**分流归属(承 D20)**:写路径是纯 tee,只按时间切段,**不按 session 预分流、不取 session 键**;session 归组与血缘判定都在读取侧([3.4](3.4-session-identity.md))。
- **封存件**:`~/.asight/raw/<段>.sealed`,一个段一个,格式见 §封存格式。一个段的长期副本只有一份:明文,或封存件。
- **记录 id** = `<段>:<行号>`(行号从 1 起,opaque 行也计),封存前后不变。旧位置([4.1](4.1-capture-sources.md) §旧位置)的记录保持它们原有的 ref 形状,**MUST NOT 重编号**。
- **段索引**:`~/.asight/index/` 里每段一个文件,读取侧第一次读到该段时建。它只是加速器,**可删、丢了就重建**,MUST NOT 成为新的真相源。
- **块字节引用 `text_ref`** = `<记录 id>` + 块在该记录某个字段里的字节区间,见 §回源指针。

## 写路径(段的生命周期)
- 守护进程**启动时总是开新段**,不续写旧段(前一次运行的段状态不可知)。
- 每条信封追加一行;**追加后段 ≥ 128 MB 就关闭**并开下一段。按大小切,不按日期——一天的量差几个数量级(D60)。
- 守护进程停下时关闭当前段。崩溃留下的半行(没有结尾换行)**原样保留**,封存也逐字节保留;索引项标「无换行」。
- 守护进程把当前段名写进自己的锁文件 `~/.asight/collector/lock` 的 `segment` 字段。**「关闭」的判据**:`~/.asight/raw/` 里的一个段,只要它不是某个活着的守护进程的当前段(锁里的 pid 与该进程启动时间都对得上才算活着)、又还没有封存件,它就是关闭的。**没有关闭标记文件**:标记文件会在崩溃后留下谎言,而锁 + 封存件已经足够。
- `flows/<日期>.ndjson`、`audit/`、`replays/` 不是记录流,照旧按日期分文件。

## 自动封存(D35 · D60②)
- 关闭的段进封存队列;守护进程启动时把 `~/.asight/raw/` 里所有关闭的明文段也放进去(上次崩溃留下的)。
- **一次一个**,在 `child_process.fork` 出来的封存 worker 里做,**MUST NOT 阻塞守护进程的事件循环**。
- 全局锁 `~/.asight/raw/seal.lock`(pid + 进程启动时间,陈旧判定同 `op.lock`)让守护进程与 `asight raw seal` 互斥。
- **封存流程(MUST)**:同目录建临时文件(open 时即 0600)→ 写入并 fsync → 逐条解码**全部**记录与原行比 sha256、再按行号重拼整段比长度与整文件 sha256 → rename 成 `<段>.sealed` → fsync 目录 → **才**删明文 → fsync 目录。任何时刻崩溃都只留下明文,或两者并存;校验不符就保留明文并报告。
- **失败不静默(D38)**:明文留着,`collector/flows/` 一条 `failure`(`where:'raw'`、`code:'seal-failed'` + 一句原因)+ `~/.asight/raw/journal.jsonl` 一行;下次守护进程启动**重试一次**,不循环重试;`asight status` 报出条数。
- **旧位置只读**:守护进程不搬、不自动封存旧位置的文件(别的进程可能还在写)。`asight raw seal <file>...` 封指名的文件:文件 10 分钟没变才封,否则拒绝并说原因;封存件放原文件旁边;同样逐条核对后才删明文。

## 封存格式(D35)
- **记录编码**:关键帧(行字节本身),或增量 = (指向**同一封存件**里更早一条记录的回指, ops)。ops 只有两种字节操作、不解析 JSON、与 provider 无关:`COPY(offset,len)` 从前驱拷贝、`INSERT(字面字节)`。从一条记录沿回指到关键帧 MUST ≤ 16 步。编码器启发(SHOULD,不属格式):前驱 = 同文件前 32 条里公共前缀最长的那条;增量 ≥ 本条 50% 或链将超 16 时出关键帧。
- **分帧**:编码流切成约 4 MiB(编码后)的独立帧,各自 brotli(quality 9、lgwin 24)压缩,每帧可单独解码。一条记录 MUST NOT 跨帧;比 4 MiB 大的记录单独成帧。v1 用 brotli:发布基线 Node 20 的 `node:zlib` 没有 zstd。
- **文件布局**:头(magic、格式版本)· 帧 · 索引尾 · 定长尾标(索引尾的偏移与长度、magic)。索引尾含帧表(每帧的偏移、压缩长度、解码后长度)、记录表(每条:行号、帧号、帧内偏移与长度、类型、回指、行的 sha256、有无换行)、来源段表(段名 + 封存时测得的整文件 sha256 与长度,原段因此能逐字节还原),和一个校验和(头 + 三张表的 sha256)。索引约为原始的 0.03%。
- **读**:记录 id → 查记录表 → 解码所需帧(至多沿回指 16 步)→ 重建行 → 校验 sha256 → 切字节。解码后的帧进有界 LRU(约 8 帧)。读者跳过或认不出的文件 MUST 报告,MUST NOT 折叠成空。
- **并存期**:明文与封存件并存时(崩溃后),读者只用其一并保持一致:封存件声明的来源段与现存明文的字节一致(前 `length` 字节的 sha256 相同)就用封存件;否则读明文并报告。

## 段索引(D59 的全部派生层)
- 每段一个索引文件,**第一次读到时建**:记每行的字节偏移与长度,外加查询要过滤的少量取自信封的键(时间、harness、host、`traffic_class`、`is_llm_call`、session 键、调用 id)。索引不存记录全文,看全文一律回源。
- **失效与增量**:明文段按 (大小, mtime) 失效,正在写的段**按已索引到的偏移增量补**,只追加不重算;封存件按 (大小, mtime) 一次建完。
- 索引坏了、删了、版本不符 → 重建,**MUST NOT** 因此拒绝回答查询。`asight query segments` 印每段的时间范围、大小、封存与否。

## 回源指针(`text_ref` · AC-1 的技术兑现)
- 形态:`<段>:<行号>::<start>-<end>`(默认是请求体 `req_body` 的字节区间),或带字段段 `<段>:<行号>::<field>::<start>-<end>`,`field ∈ resp.raw | resp.messages.<j> | req_extra_messages.<k>`。区间是该字段文本的 JS 字符串下标。
- **重建 = 定位记录(封存件经索引解码并校验 sha256)→ 取该字段 → `slice(start,end)`**。AC-1:每个块的字节与源逐字 diff = 0。
- **按块字段比,不比整包字节**:请求体三个顶层字段(tools/system/messages)的 JSON key 顺序是 SDK 细节;真相是 assembly order 下每块内容的字节。
- 字段值不是文本(`{b64}`、`{omitted_bytes}`、`{raw_chars}`)时回源报「无文本」,**MUST NOT 臆造字节**。
- 块内容的指纹 `content_hash` MUST 是全内容 sha-256 over 块的**逐字序列化字节**(采集所见,非 key 规范化;算法钉在 [3.1](3.1-adapter-contract.md),承 D19):它是 cache-break 比对的依据,前缀 hash 或 32-bit hash 会把不同的块并成一个。键序规范化只供 [3.3](3.3-cache-model.md) 的成因分类。

## 源文件上允许的动作(必拒不变式,承不变式 2([0.0](0.0-overview.md) §核心不变式))
只有三种:① 写路径追加;② 同设备 rename 整个文件或目录(D27③),记录字节不动;③ 封存器把一个关闭的段无损换成封存件(§自动封存的顺序)。截断、改写、搬进外部 chunk store、按 session 重组一律**必拒**。读路径(`asight query` / `serve`)只读,唯一会写的是 `~/.asight/index/`。

## 保真边界(承不变式 4([0.0](0.0-overview.md) §核心不变式),必拒隐瞒)
源 NDJSON 本身已有非逐字之处,读取侧 MUST 原样承接 `faithfulness` 标记:
- **工具定义逐字(D15)**:采集逐字存完整 tools schema;D15 之前的旧记录只有元数据,UI 每块标 `verbatim` / `metadata`。
- **请求头逐字**:含 `authorization` / `x-api-key` / `cookie`([4.1](4.1-capture-sources.md) §凭据处置);保护手段是文件 0600 + `asight doctor`。
- **响应在采集侧重建**:SSE 已在采集点重建成 `resp.{usage,text,tool_calls}`,读取侧不复解。
- **截断 / opaque**(超长内容、Codex 加密 reasoning):标 `truncated` / `opaque`,UI 就地标注。
- **只记日志的类别**:`body_retention:'log'` 的调用没有体,标「只记日志」,MUST NOT 读成空体([4.6](4.6-process-collector.md) §类别与保存级别)。
- **非 LLM 调用(D40)**:请求体与 LLM 同等逐字。D40 之前的 `{raw_chars, verbatim:false}` 记录标「采于 D40 之前,只存了长度」。

## 验收(可跑 check · 明确测试要求)
1. **段与轮转**:写够 128 MB 后换段;两次启动写进不同的段;段名撞了加 `-2`;停下时当前段关闭。记录 id 与写入顺序一致(`test/collector/record-store.test.mjs`)。
2. **半行**:杀掉写者留下半行,之后的读与封存都逐字节保留它,索引标「无换行」。
3. **封存往返(D35)**:封存前后,每条记录的字节、顺序、记录 id 与每个 `text_ref` 解出的字节都相同;明文只在全部记录校验通过后才删;中途崩溃只留明文或两者并存。
4. **自动封存**:守护进程关段后,封存件出现、明文消失,事件循环没有被阻塞(关段到封存完成期间照常接收请求);启动时把上次留下的关闭明文段补封;封存失败留 `failure` + journal 各一条,`status` 报得出,下次启动只重试一次。
5. **「关闭」的判据**:活着的守护进程的当前段不被封存;锁里 pid 已不在或启动时间不符时,它的段算关闭;`~/.asight/raw/` 里没有关闭标记文件。
6. **旧位置**:守护进程不碰旧位置的文件;`asight raw seal <file>` 对 10 分钟内改动过的文件拒绝并说原因;封存件落在原文件旁边。
7. **段索引可弃**:删掉 `~/.asight/index/` 后每个查询的结果不变(只是慢);正在写的段追加后,增量补索引的结果与整段重建逐字段相同。
8. **源不可变**:`asight query` / `serve` 跑前后,每个段文件的 inode、大小、mtime 不变;对源路径调用 rename / unlink / truncate 的只有 `src/raw/` 与写路径(测法 = stub `node:fs` 跑各命令,记下调用的路径)。

## Edge cases
- **目录迁移**:同设备 rename(D27③)——段索引按段名与 (大小, mtime) 失效,迁移后重建,不丢记录。
- **空段**:开了没写过的段关闭时直接删,不留空壳,也不封存。
- **超大单行**:比帧还大的记录单独成帧;读者按记录流式解码,内存有界。
- **撞名**:同一秒内重启两次 → `-2`;`raw/` 里已有同名封存件时,新段用下一个后缀,两个写者永不互相覆盖。
- **半包 / error 记录**:`error:true` 的信封照样是一条记录,不当 200。

## Risk / 回滚
段索引是一次性可弃投影:逻辑错 → 删 `~/.asight/index/` 重建,源零损失(不变式 2 的直接红利)。封存器出错 → 明文留着,`journal.jsonl` 写明原因,人可以把封存件删掉重来。

## OPEN
- **旧根**:封存器永不碰 `~/.atrace/asight/`(D27① 永久可读);旧数据只经操作者显式的 D27③ rename 进 `~/.asight` 之后才可能被 `asight raw seal` 指名封存。**【两个入口都按真实路径拒绝旧根下的文件,符号链接也认得出;拒绝写进 raw journal】**

## Extensions
- 封存帧改用 zstd(level 3、窗口 ≥ 2^22):不再支持 Node 20 后换,实测更小也更快(D35)。
- 冷热分层:很老的封存件搬到别的卷(仍只有一份长期副本)。
- 索引加更多过滤键:只要它仍可从段重建,读取侧零改动。
