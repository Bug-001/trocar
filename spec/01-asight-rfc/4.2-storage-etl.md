# asight · RFC 4.2 — 存储 + ETL(源真相 → 分析投影的管道)

> **服务意图(A2)**:同时服务 ①(把 blocks/calls 落表 → 供逐字回放)与 ②(把 usage/cache_events 落表 → 供 cache 叠加)——它是让"逐字源真相"变成"可 SQL 查询的分析投影"的**唯一写路径**(承 D5)。
> **受众**:人(核对派生层不覆盖源、增量不丢数)+ agent(据此实现 ETL orchestrator + DuckDB 落盘)。
> **前置**:源信封(怎么拿到 bytes、NDJSON 长什么样)= [4.1](4.1-capture-sources.md);记录→归一化行的纯函数 = [3.1](3.1-adapter-contract.md);落哪组表 = [3.2](3.2-normalized-model.md);cache 真相规则 = [3.3](3.3-cache-model.md);身份/血缘判定 = [3.4](3.4-session-identity.md);谁读这些表 = [3.5](3.5-query-layer.md)。

## Goal
定义把**原始 NDJSON(源真相)**变成 [3.2](3.2-normalized-model.md) 那组 DuckDB/Parquet 表(`sessions / calls / block_contents / call_blocks / usage / resource_events / cache_events`)的**管道**:注册表分发到 [3.1](3.1-adapter-contract.md) 的 adapter、块内容去重、铸造回源指针、**增量**追加、落盘。**派生表永远可从源重建;源 NDJSON 永不被本层改写**(不变式 2([0.0](0.0-overview.md) §核心不变式),**必拒**违反)。

## 前置定义(Definitions)
- **源 NDJSON**:采集源([4.1](4.1-capture-sources.md))写出的 append-only 记录,一行一次 HTTP。产品的**唯一源真相**。**分流归属(承 D20)**:采集源是纯 tee、只按物理源写 append-only 信封流,**不按 session 预分流**;**per-session 归组 / 血缘 = 本层(ETL)用 [3.4](3.4-session-identity.md) 线上信号做**。demo 的 `~/.atrace/projects/<cwd-slug>/<session-id>/{calls,probes,other}.ndjson` + `control/<class>.ndjson` 预分流布局(承 `sessions.mjs`)是 **v0 shortcut**(采集侧分流耦合了身份判定);产品把该归组移入本层,采集只出统一信封流。信封字段见 [4.1](4.1-capture-sources.md) / demo `TRACE_SCHEMA.md`。
- **ETL**:读源 → 分发 adapter → 去重 + 铸指针 → upsert 进表。**纯转换 + 幂等**:同一批源两次跑得同一组表。
- **增量 watermark**:每源流已消费到的位置(记录数 / 字节偏移),使新 append 只处理新行,不全量重解。
- **回源指针(`text_ref` / `raw_ref`)**:表里不存全文([3.2](3.2-normalized-model.md) Invariant);存一个能**逐字定位回源 NDJSON**的锚。`raw_ref` → 某记录;`text_ref` → 记录内某块的字段。**AC-1 靠它闭环**。
- **分析投影**:DuckDB/Parquet 表。**可丢弃、可重建**;它 MUST NOT 成为新的真相源。

## Plan(选定方案 + 取舍)
**选定**:**增量 orchestrator** —— 顺序读 append-only 源 → registry 按 `detect` 认领 → 调 adapter 的 `parse*` 出归一化行 → `block_contents` 按 `content_hash` **insert-if-absent** 去重、`call_blocks` 只写整型/hash 映射 → 铸 `text_ref/raw_ref` → 事务 upsert 进 DuckDB → 前进 watermark。ETL **不含任何 provider 解析分支**(那是 [3.1](3.1-adapter-contract.md) 的;把 provider 分支塞进 ETL = 破"适配缝不漏进主干",**需 RFC**)。

**备选(未选)**:① demo 现状——`analyze.mjs` 每次 poll 全量 in-memory 重算(normResp/linearContext/lane/extractResources/cacheBreak)。原型足够、但正是 D5 要治的**反复解析卡顿**:一条几百 call 的 session 每次都从零摊平。② 每次全量重建表(无 watermark)——简单但大 session 下 O(全史) 重扫,增量诉求(D5)落空。
**取舍**:orchestrator + adapter 纯函数 + 增量 watermark = 解析只发生一次、跨 session 查询走 SQL([3.5](3.5-query-layer.md));demo 的 `analyze.mjs` 逻辑**原样搬进 adapter/ETL**,只是从"渲染时算"挪到"入库时算一次"。

## 管道形状(源 → 表)
demo 的 `analyze.mjs` 已实证每一步的归一化逻辑;产品把它从"渲染时 in-memory"落成"入库时一次 + 增量"。各阶段与目标列的对应:

| ETL 阶段 | demo 原型(`analyze.mjs`) | 落进([3.2](3.2-normalized-model.md)) | 责任层 |
|---|---|---|---|
| 认领 + session 身份 | `sessionIdOf` / `isSub` / lane 切分 | `sessions`(native_id/血缘/confidence,判定见 [3.4](3.4-session-identity.md)) | adapter `detect`+`parseSession` |
| call 元 + usage 终值 | `normResp`(SSE 取 `message_delta` 终值 / JSON 取 body)、`ctxTokens` | `calls`、`usage`(canonical 角色) | adapter `parseCall` |
| 上下文摊平(assembly order) | `linearContext`(tools→system→messages,带 `volatile`/`cache_control`/`resKey`) | `call_blocks` + 去重后的 `block_contents` | adapter `parseBlocks` → **ETL 去重** |
| 资源生命周期 | `extractResources`/`addRes`(file/dir/link/mcp/skill,enter/evict/load) | `resource_events`(flat 行) | adapter `parseResources` |
| cache 事实 | `cacheBreak`(跳 `volatile`、首 call idx=0、compaction 首个 message 断) + `normResp.usage` | `cache_events`(见 [3.3](3.3-cache-model.md) 两层) | adapter + ETL |
| lane / compaction | lane(main/subagent/monitor/aux)、bigDrop/preamble 推断 compaction | `calls.lane`、`calls.compaction` | adapter |

> **关键澄清(缝的位置)**:demo `analyze.mjs` 把 adapter 逻辑 + ETL 编排 + 渲染三者揉在一个文件。产品**拆缝**:**bytes→行的纯解析归 [3.1](3.1-adapter-contract.md);编排/去重/铸指针/增量/落盘归本层(4.2);表形状归 [3.2](3.2-normalized-model.md);读归 [3.5](3.5-query-layer.md)。** 本层 MUST 只**读**源、**写**派生表,MUST NOT 反向改源(**必拒**)。

## 回源指针:`text_ref` / `raw_ref`(AC-1 的技术兑现)
表不存全文;重建靠指针逐字回源。ETL **铸造**这对锚(demo 尚未有——它把全文留在内存;这是产品 ETL 新增的责任):
- `raw_ref` = `<session_id>/<stream_file>#<record.id>`(如 `…/calls.ndjson#req_00042`)——定位一条源记录。
- `text_ref` = `raw_ref` + **块在该记录里的 JSON 路径**,如 `$.request.system[2].text`、`$.request.messages[14].content[3].text`。
- **重建 = 解析该 NDJSON 行 → 走 JSON 路径 → 取字段 bytes**。这就是 AC-1 的重建算法:由 `call_blocks`⋈`block_contents.text_ref` 拿回每块字段,与源逐字比,**diff=0**。
- **按块字段比,不比整包字节**:请求体三个顶层字段(tools/system/messages)的 JSON key/byte 顺序是 SDK 细节、模型不读(承 `analyze.mjs` 注释);真相是 assembly order 下**每块内容的字节**。AC-1 的"逐字"锚在块字段级。

## content_hash 去重(ETL 拥有 insert-if-absent)
- adapter 产出每块的 `content_hash`([3.1](3.1-adapter-contract.md) `parseBlocks`);**去重写入是 ETL 的事**:`block_contents` 按 `content_hash` insert-if-absent,`call_blocks` 只存 `(call_id,seq,content_hash)` 映射(承 [3.2](3.2-normalized-model.md) 取舍)。同内容跨百 call 只存一次 → cache-break 退化成"相邻 call 的 hash 序列 diff"(SQL,[3.5](3.5-query-layer.md))。
- **`content_hash` MUST 是全内容抗碰撞 hash = sha-256 over 块「逐字序列化字节」**(采集所见原始序列化,**非 key 规范化**;承 **D19**、算法钉死在 [3.1](3.1-adapter-contract.md)):它是去重主键,碰撞 = 两个不同块被并成一条 → **派生层丢块**(违反不变式 2,**必拒**)。**键序规范化只供 [3.3](3.3-cache-model.md) 成因分类,MUST NOT 进 hash**(否则 json-key-reorder cache-break 塌进去重、变不可见)。⚠ demo 的 `blkKey`/`hash` 是 32-bit、且只 hash **前 4096 字符**(`blkHashText(b).slice(0,4096)`)——作 cache-break 启发式够,作**去重主键不安全**(两个前 4096 字符相同、尾部不同的长块会被误并)。产品 MUST 换成全内容强 hash。

## 增量(watermark · append-only · 迁移安全)
- 源是 append-only(demo `appendFileSync`)→ 增量 = 记每个源流已消费的**记录数/字节偏移**,只 parse 新行,adapter 幂等 upsert。watermark **MUST 以 `session_id` 为键**,不以路径为键——因为源目录会**改名迁移**(demo `ensureLocation`:slug 从 `_unresolved` 升级为真实 slug 时 `renameSync` 整个 session 文件夹)。以路径为键会在迁移后重复摄入或丢新行。
- 增量结果 MUST 与"全量重建"**逐位一致**(幂等性验收,见下)。watermark 只是加速,不是真相;损坏时 MUST 能丢弃派生表 + watermark、从源全量重建(见 Risk)。
- 多源流:`calls.ndjson`(真推理,主源,喂全部 7 表)是本层焦点;`probes.ndjson`(count_tokens 上下文尺寸测量)喂 `calls.lane='probe'` 的轻量测量序列(承 demo server `series`);`other.ndjson` / `control/<class>.ndjson` 非会话推理,**不进 3.2 会话表**(control 是 session-LESS,归 [4.1](4.1-capture-sources.md) 分类,本层至多留原样待查)。

## 派生不覆盖源(必拒不变式,承不变式 2([0.0](0.0-overview.md) §核心不变式)
- 源 NDJSON = 唯一真相;DuckDB/Parquet = **可重建投影**。ETL **只 append/upsert 派生表,永不写源目录**。任何"回写源 / 有损改写源记录"的设计 = **必拒**。
- 表里**不留全文**(存 `text_ref`)——既省空间,又强制"看全文=回源",杜绝派生层与源漂移。

## 保真边界(承不变式 4([0.0](0.0-overview.md) §核心不变式),必拒隐瞒)
源 NDJSON 本身已有非逐字之处,ETL **MUST 原样承接 `faithfulness` 标记、MUST NOT 假装重建出线上真相**:
- **工具定义 = 逐字(D15 · 已落地)**:采集**逐字存完整 tools schema**,`block_contents.faithfulness='verbatim'`、`text_ref` 回源得完整 schema,**纳入 AC-1**([3.2](3.2-normalized-model.md) AC-1)。demo 已移除采集侧 `summarizeRequest` 的 tools 降解、摘要上移 adapter([3.1](3.1-adapter-contract.md)),见 [4.1](4.1-capture-sources.md) §验收#3。⚠ **仅 D15 之前的旧 trace** 还只有 `name / input_schema_props / description_chars`(`faithfulness='metadata'`)——adapter 向后兼容、UI 每块标 `verbatim`/`metadata` 诚实区分。
- **凭证脱敏**:`request_headers.authorization='<redacted>'`(承 `verify.mjs`)——源即已脱敏,本层不"复原"。
- **响应在采集侧重建**:SSE 已在采集点([4.1](4.1-capture-sources.md))重建成 `response.{usage,text,tool_calls}`;本层消费该信封,不复解 SSE 流。重建保真度是 [4.1](4.1-capture-sources.md) 的验收面。
- **截断/opaque**(超长内容按显示上限、Codex 加密 reasoning):`faithfulness` 取 `truncated`/`opaque`,UI 就地标注,MUST NOT 冒充 verbatim。

- `resource_events` 从 flat 行折回"per-resource 段 + loads"的聚合:[3.2](3.2-normalized-model.md) schema 是 **flat**(`enter|evict|reinject|load`),故**本层只写 flat 行**;折叠归下游([2.4](2.4-resource-explorer.md) §影响面提出、建议在 [3.5](3.5-query-layer.md) 定聚合责任方)。本层不预折叠。

上游:[4.1](4.1-capture-sources.md) 供源、[3.1](3.1-adapter-contract.md) 供解析纯函数。下游:所有派生表([3.2](3.2-normalized-model.md))由本层写,[3.5](3.5-query-layer.md) 及全部前端部件([2.x](2.4-resource-explorer.md))读。改 ETL 的去重/指针/增量语义 = 动源→表的接缝,MUST 走[0.1](0.1-engineering-rules.md) 的 grep-spec 自对照闸。

## 验收(可跑 check · 明确测试要求)
已提交的闸(承接、不重造):

本模块(4.2)**新增测试 MUST 断言**(把上面从 in-memory 推进到持久化 + 增量):
1. **AC-1 落库往返(必测)**:对真实/固化 CC session 建库后,**仅由 `call_blocks`⋈`block_contents.text_ref` 重建某 call 的上下文,回源 NDJSON 逐字 diff=0**(metadata 块除外且已标 `faithfulness`)。这是把 `dashboard-render.mjs` 的 AC-1 断言从"内存 flat"升级到"DuckDB 表 + text_ref 回源"。
2. **幂等 / 增量一致**:同源跑两次 → 表逐位相同;分两批 append 增量摄入 → 与一次全量摄入**产出同一组表**。
3. **去重生效**:`count(block_contents) < Σ(每 call 块数)`(承 [3.2](3.2-normalized-model.md) schema check);同内容跨 call 只一行。
4. **源不可变**:ETL 跑前后对源目录做 `cmp`/mtime 校验,**源 NDJSON 零字节改动**。
5. **重建等价**:丢弃派生表 + watermark → 从源全量重建 → 与增量态等价(证"派生可丢弃")。

## Edge cases
- **目录迁移**:`_unresolved`→真实 slug 的 `renameSync`(demo `ensureLocation`)——watermark 以 `session_id` 为键,迁移不重摄/不丢。
- **空 / 超大 session**:空 → 无行,不建空壳;超大 → 增量只碰新行,`call_blocks` 行数 = Σ块数但 `block_contents` 去重后远小(承 [3.2](3.2-normalized-model.md) Edge)。
- **半包 / error 记录**:源含 `error`(承 demo 错误记录)→ adapter 出 `calls.error` 行(非成功),ETL 照写,不当 200。
- **compaction 行**:CC 无显式标、由 message_count 骤降推断(confidence medium,[3.4](3.4-session-identity.md));ETL 只持久化 `calls.compaction`,**MUST NOT 误建 fork**(compaction≠fork,[3.4](3.4-session-identity.md) 关键区分)。
- **未认领记录**:无 adapter `detect` → 落"未识别"隔离区 + 计数([3.1](3.1-adapter-contract.md) Invariant),MUST NOT 静默丢。
- **未映射字段**:adapter 的 `extra`/`unmapped_count` 原样入表(承 [3.2](3.2-normalized-model.md) 保真兜底 + D7 钩子);ETL MUST NOT 丢弃 `extra`。

## Risk / 回滚
派生表是**一次性可弃**投影:任何 ETL 逻辑错 → `DROP` 表 + 清 watermark + 从源 NDJSON 全量重建,**源零损失**(不变式 2 的直接红利)。ETL 编排是幂等纯转换 → 可用固化真实源做离线回归。增量 watermark 损坏 → 退化为全量重建,慢但不丢真相。每个可独立验证的积木(去重 / 指针 / 增量)一个 commit,失败回退上一绿点。

## Extensions
- Parquet 分区(按 session / provider)+ 冷热分层,承大跨 session 分析。
- 更多源流接入(Codex relay-tee、DeepSeek 反代的 NDJSON)——只要 [4.1](4.1-capture-sources.md) 出统一信封、[3.1](3.1-adapter-contract.md) 有 adapter,本层编排零改。
- `content_hash` 算法在 [3.1](3.1-adapter-contract.md) 全局钉死(全内容强 hash),各 adapter 一致 → 跨 provider 块级去重也成立。
- 解析/索引/缓存性能层([4.3](4.3-parse-index-cache.md))在本管道之上做增量物化视图 / 惰性建索引。
