# asight · RFC 4.5 — 跨平台 onboard + 分发 / release

> **这是什么**:把这台单机研究仪器从「只在作者的 Mac 上手起」变成**可在各类 Unix(macOS + Linux)一键装、跑、卸**、并经 **npm/npx + GitHub Release** 分发的工具。装:跨平台 onboard 契约(`TrustStoreInstaller`)· 支持平台矩阵 · 分发形态(D23)· release 自动化 · 边界守卫。
> **受众**:人(核对「单机 / 单用户 / loopback / 改包只出于操作者意图(D30)四条边界在分发后仍不破」)+ agent(据此实现跨 OS onboard + release 流水线)。
> **Source-decision**:承 [0.0-overview](0.0-overview.md) **D22**(跨平台采集/onboard 可移植性)+ **D23**(分发/release 策略)+ D1(个人研究仪器 + 产品化留缝)+ D4(可插拔采集源)。
> **不含 → 去哪查**:采集源机制 → [4.1](4.1-capture-sources.md);本地服务的 loopback/只读边界 → [4.4](4.4-server.md);技术栈(Node/`.mjs`/`@duckdb/node-api`)→ D18。

---

## Goal

让 asight 在 **macOS 与 Linux** 上都能:① 一条命令装起(`npx asight` 或全局装)· ② onboard(生成 CA、装进**用户级**信任库、steer 被测 harness)· ③ 采集→存储→查询→看板端到端跑通 · ④ 一条命令干净卸载(零残留)。Windows 走**同一接口**预留,非 v1。分发经 **npm 主渠道** + **GitHub Release 挂 tarball**,由 **GH Actions 打 tag 触发**。

**贯穿约束(分发后仍 MUST 成立)**:每个安装是**单机 · 单用户 · loopback · 改包只出于操作者意图(D30)** —— 分发**只是把同一台单机仪器复制到更多机器**,**MUST NOT** 借此长出多用户 / 云端分享 / 对外暴露(Non-Goal + [4.4](4.4-server.md) 只绑环回;违反=**必拒**)。

## Definitions

- **可移植缝**:整条链 `采集源 → D10 信封 → adapter → DuckDB → server → 前端` 中,**只有最前面两处碰 OS**:① **onboard/证书**(装信任库)、② **steer**(把流量引到采集源)。信封往后全是纯 Node(`@duckdb/node-api` 各平台有 prebuilt)→ **平台无关,零改**。
- **`TrustStoreInstaller`**(D22 · 跨 OS onboard 接口):把「装/验/卸采集 CA」抽象成平台中立契约,`process.platform` 分派实现。
- **支持平台矩阵(v1)**:`darwin`(arm64/x64)· `linux`(x64/arm64);`win32` 走同接口**预留**。
- **分发形态(D23)**:npm/npx 主渠道 + GitHub Release tarball 副本;**预编译单文件二进制(SEA)= Extension**(见文末)。

## `TrustStoreInstaller` 契约(平台中立原则 · D22)

```
interface TrustStoreInstaller {
  install(caPath): void          // import-only 装进「用户级」信任库,绝不碰全机锚点
  verifyUserTrustOnly(): boolean  // 断言 CA 在用户级库、且无全机信任标志(§验收 gate)
  uninstall(): void               // 对称移除,干净可逆、零残留
}
```

**平台中立原则(必拒违反)**:CA 仅 **import-only** 装进**用户级**信任库,**绝不全机弱化 TLS**。这是 [4.1](4.1-capture-sources.md) 采集安全#3 从 macOS 措辞泛化后的形态——精神("绝不让整机 TLS 变弱")跨 OS 不变,机制按 OS 落。

| OS | 用户级装法(import-only) | 验证 | 移除 | 必拒(全机锚点) |
|---|---|---|---|---|
| **darwin** | `security add-certificates -k login.keychain-db` **+ `NODE_EXTRA_CA_CERTS` 环境变量**(见下,keychain 对 node 客户端**不生效** · 2026-07-21 实测更正) | `security find-certificate` 命中 login keychain + 无 trust settings | `security delete-certificate` + 撤 env | `add-trusted-cert -r trustRoot`(全机) |

> **darwin 信任机制更正(2026-07-21 实测 · 推翻上表旧陈述「Claude Code 直读 keychain 零 trust settings 生效」)。** 经真机 CONNECT+TLS 实测:node 版 claude-code(CLI + Desktop 内嵌)**只**认 `NODE_EXTRA_CA_CERTS` 指向的 CA 文件 —— 默认 bundle 失败、`--use-system-ca`(读 keychain)失败、`NODE_EXTRA_CA_CERTS` 通过。`security add-certificates` 装进 login keychain 对 node **不生效**(它不读 keychain 信任)。故 darwin 采集信任 MUST 由 **`NODE_EXTRA_CA_CERTS`** 兑现:GUI Desktop 从**登录会话**继承该 env,故用**登录时 `launchctl setenv`** 的一次性用户级 LaunchAgent(`com.asight.env`)设置;keychain 装入仍保留(供 curl/openssl 等 keychain 消费者 + 对称移除)。**采集持久化**:MITM 由用户级 LaunchAgent `com.asight.mitm`(RunAtLoad+KeepAlive)常驻,node 路径 MUST 用**稳定 profile 符号链**(非 `/nix/store/` 哈希路径,GC 即失效)。二者与 Clash steer 一起由 `asight desktop on/off` 对称装/卸、`asight uninstall` 全清(**绝不留孤儿** · 2026-07-21 事故教训)。**平台中立原则不破**:仍只碰用户级、绝不全机弱化 TLS。
| **linux** | `certutil -d sql:$HOME/.pki/nssdb -A -n asight-ca -t C,,`(用户 NSS 库;缺库先 `mkdir -p ~/.pki/nssdb` + init) | `certutil -L -d sql:$HOME/.pki/nssdb` 命中 + `/etc/ssl` 未被写 | `certutil -D -d sql:$HOME/.pki/nssdb -n asight-ca` | 写 `/etc/ssl/certs` · `update-ca-certificates` · `trust anchor`(全机) |
| **win32(预留)** | CurrentUser `Root` store(`certutil -user -addstore Root`) | CurrentUser 命中 + LocalMachine 未写 | `certutil -user -delstore Root` | LocalMachine\Root(全机) |

> **依赖前提**:`atrace-mkca` 用 **OpenSSL**(三平台皆可)生成 CA/叶证。Linux 的 `certutil` 来自 `libnss3-tools`(Debian/Ubuntu)/ `nss-tools`(Fedora)——onboard「测试」按钮 MUST 先探测其存在,缺则给出**装它的一行提示**而非静默失败。

## steer 的可移植性(承 [4.1](4.1-capture-sources.md))

- **`base_url` / `HTTPS_PROXY` 反代路径 = 跨平台**(纯 env + 纯 Node 反代)。CC-CLI / DeepSeek-CLI 全平台走此路,**不碰证书信任库、不依赖 Clash** → **Linux 上今天即端到端**。
- **Clash steer = macOS-Desktop 专属实现之一**,非跨平台契约。Claude Desktop 仅 mac/win,**Linux 无 Desktop harness** → Linux 只需反代路径即覆盖其全部 CC 采集。Windows-Desktop 的 steer 待预留落地时定。**已落地(2026-07-17)**:macOS 版 = `asight desktop {on|off|status}`(经 Verge 全局 Script 命令式 splice · 耐 regen · 非 darwin 显式拒绝),见 [4.1:61](4.1-capture-sources.md) 产品落地注。

## 分发 / release(D23)

**(A · 选定 · 默认)npm/npx 主渠道**:发布 `asight` 到 npm,用户 `npx asight`(免装即跑)或 `npm i -g asight`。
> **⚠ 阻断(2026-07-18)**:npm 包名 **`asight` 已被他人占用**(`asight@0.2.26` = eunomia-bpf/agentsight,同 bin 名、同「AI agent 可观测性」品类)。**发布名 MUST 先另选**(scoped `@<user>/asight` 或改名),否则 `npx asight` 装到的是别家软件——对一个要用户装 MITM CA 的工具,这是供应链风险,不只是命名冲突。同步改 `package.json` `name`/`bin` + README + [0.0-overview](0.0-overview.md) D23。另:当前 `package.json` 为 `private: true`、`version: 0.0.0`、**无 `license` 字段且仓库无 LICENSE 文件** → 公开即「保留所有权利」,任何人不得合法使用/fork,**发布前 MUST 补 LICENSE**(并加进 `files`)。
- **为何最省**:Node CLI 跨平台白送(Node 消化 OS 差异);`@duckdb/node-api` **各平台有 prebuilt**,`npm install` 按当前平台自动选对 `.node` → **无需我们自打二进制**。这正是 npm-first 比自打二进制干净的根因。
- **GitHub Release 挂 tarball**:每次 tag 同时 `npm publish` + 把 `npm pack` 产物 attach 到 Release,给不想过 npm registry 的用户一个直下入口。

**(B · release 自动化)GitHub Actions**:tag `v*` 触发 workflow —— `test`(node:test 全绿)→ `github-release`(建 GitHub Release + 传 `npm pack` tarball)→ `publish-npm`(`npm publish --provenance`)。**私有阶段**:`publish-npm` 默认**关闭**,只有仓库变量 `PUBLISH_NPM == 'true'` 才跑;现在只在私有仓库里出 Release 做测试,准备公开时再打开(开启条件见 `release.yml` 头注释:改包名、去掉 `private`、`NPM_TOKEN`、仓库公开)。matrix 只为**测试**跨 `macos-latest` / `ubuntu-latest`(证 onboard 两实现在真 OS 上过 gate),**发布产物是平台无关的 npm 包**(prebuilt 由 duckdb 分发,不进我们的包)。

**(C · 版本 / 卸载)**:`asight --version` 报版本;`asight uninstall`(或 `atrace-off` + `TrustStoreInstaller.uninstall()`)一步复原——**关闭=旁路 + CA 移除,零残留**(承 [4.1](4.1-capture-sources.md) Risk/回滚)。

**(D · 开机自启 · D26)**:透明监测「开」可选把采集+serve **加入用户级开机自启**——**用户级 LaunchAgent**(macOS `~/Library/LaunchAgents/com.asight.monitor.plist`)/ 用户 systemd unit(linux,预留),**绝不写全机启动项**(与「CA 仅用户级」同精神)。装/撤**对称**:监测「关」移除该自启项。label `com.asight.monitor` 与 demo 的 `com.atrace.serve` 区分,互不覆盖。控制入口 = [4.4](4.4-server.md) 的 opt-in 控制面(网页开关直接对应底层命令),或 CLI `asight monitor {on|off}`。

## 验收(可跑 check)

1. **跨 OS onboard gate(D22 · 承 [4.1](4.1-capture-sources.md) §验收5)**:每个 `TrustStoreInstaller` 实现在 **throwaway 信任库**(临时 NSS 库 / 临时 keychain,**MUST NOT 碰真实库**)上跑 `install → verifyUserTrustOnly → uninstall`,断言:装后命中**用户级**库、**全机锚点未被写**、卸后干净。host-specific,类 relay-tee 的 **X 标** flagged 子单元。
2. **分派正确**:`process.platform` 选对实现;不支持平台(v1 的 win32)`install` **显式 throw** 带「预留 · 未实现」文案(不静默 no-op)。
3. **Linux 端到端(反代路径)**:offline 起 mock 上游 + 反代,发 `/v1/messages`,证收发 byte-for-byte 不变(复用 [4.1](4.1-capture-sources.md) `run-selftest` harness,平台无关)。
4. **单机边界不因分发松动**:装完起 server 仍只绑 `127.0.0.1`(承 [4.4](4.4-server.md) server gate);非环回接口连不上。
5. **零残留**:`uninstall` 后 CA 不在任何信任库、env steer 复原、被测程序直连。

## Extensions

- **预编译单文件二进制(SEA / `pkg`)**:产 `asight-{darwin,linux,win}-{arch}` 挂 Release,下载即跑、无需 Node。**坑(记明)**:`@duckdb/node-api` 是**原生插件(.node)**,塞进单文件要按平台单独 bundle 正确的 prebuilt + 运行期解包——fiddly,故 v1 走 npm(prebuilt 自动)、二进制留此。
- **Windows onboard 落地**:`win32` 的 `TrustStoreInstaller`(CurrentUser Root store)+ Windows-Desktop steer;走同接口,补 gate。
- **包管理器渠道**:Homebrew tap(mac/linux)/ 其他;皆在 npm 主渠道稳定后。
- **`atrace-mkca` 依赖自检向导**:onboard「测试」按钮探测 OpenSSL / `certutil` 存在,缺则给一行安装提示(降委派代价,承 [1.1](1.1-product-definition.md) 六要素#5)。**已落地(2026-07-16)**:CLI `asight doctor`(`src/capture/selftest.mjs` · 纯函数)— 依赖探测(openssl 全平台 + certutil 仅 Linux,缺给一行 `apt/dnf` 提示)+ [4.1](4.1-capture-sources.md):61 的「测试」四问;仅凭据泄漏硬失败(exit≠0),①②④ 供人核对。
