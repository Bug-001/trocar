# asight · RFC 4.5 — 跨平台安装 + 分发 / release

> **这是什么**:把这台单机研究仪器变成**可在 macOS、Linux、Windows 上一键装、跑、卸**、并经 **npm/npx + GitHub Release** 分发的工具。装:支持平台矩阵 · 信任面的平台中立原则 · 分发形态(D23)· release 自动化 · 边界守卫。
> **受众**:人(核对「单机 / 单用户 / loopback / 改包只出于操作者意图(D30)四条边界在分发后仍不破」)+ agent(据此实现跨 OS 安装 + release 流水线)。
> **Source-decision**:承 [0.0-overview](0.0-overview.md) **D23**(分发/release 策略)+ D1(个人研究仪器 + 产品化留缝)+ D55 · D57(证书由 `install` 装、`uninstall` 撤:每台机器自己生成的根装成用户级根,根够不到的形态由证书载体补,`on` / `off` 只管引流)。
> **不含 → 去哪查**:采集源机制 → [4.1](4.1-capture-sources.md);本地服务的 loopback/只读边界 → [4.4](4.4-server.md);技术栈(Node/`.mjs`,无原生依赖)→ D18。

---

## Goal

让 asight 在 macOS、Linux 与 Windows 上都能:① 一条命令装起(`npx asight` 或全局装)· ② `asight install` 在本机生成根、装进用户级信任库(OS 的框即同意),根够不到的形态放证书载体;`asight on` 只接引流(D55 · D57)· ③ 采集→存储→查询→看板端到端跑通 · ④ 一条命令干净卸载(零残留;Linux 采集器的能力助手是整机的(D36),另要一步 sudo 移除,见 §C)。分发经 **npm 主渠道** + **GitHub Release 挂 tarball**,由 **GH Actions 打 tag 触发**。

**贯穿约束(分发后仍 MUST 成立)**:每个安装是**单机 · 单用户 · loopback · 改包只出于操作者意图(D30)** —— 分发**只是把同一台单机仪器复制到更多机器**(D36:或同一台机器上几个系统用户各装一套,共用一个不存状态的能力助手,每套仍只服务一个用户),**MUST NOT** 借此长出多用户 / 云端分享 / 对外暴露(Non-Goal + [4.4](4.4-server.md) 只绑环回;违反=**必拒**)。

## Definitions

- **可移植缝**:整条链 `采集器 → D10 信封 → 段与段索引 → 具名查询 → server → 前端` 中,**只有采集器的 `arch/<os>/`**(引流、进程身份、自启、控制面、根的密钥保管与用户级信任库;见 [4.6](4.6-process-collector.md) / [4.8](4.8-win-collector.md) / [4.9](4.9-macos-collector.md))碰 OS。信封往后全是纯 Node、无原生插件 → **平台无关,零改**。
- **支持平台矩阵(v1)**:`darwin`(arm64/x64)· `linux`(x64/arm64)· `win32`。Windows 采集器见 [4.8](4.8-win-collector.md),`install` 把根装进 `CurrentUser\Root`,Windows 的确认框即同意;macOS 采集器见 [4.9](4.9-macos-collector.md),`install` 把根装进登录钥匙串的用户信任,系统的密码框即同意;两者的模型见 [4.11](4.11-collector-model.md)(D55 · D57)。
- **分发形态(D23)**:npm/npx 主渠道 + GitHub Release tarball 副本;**预编译单文件二进制(SEA)= Extension**(见文末)。

## 信任面的平台中立原则(必拒违反 · D55 · D57)

采集器 CA 由 `install` 装、`uninstall` 撤,从不随 `on` / `off`(D55①)。根每台机器自己生成;macOS / Windows 把它装成**用户级**根(macOS 登录钥匙串的用户信任、Windows `CurrentUser\Root`;整机一项,按指纹认,OS 的框即同意),根的私钥不能导出(D57②)。根够不到的形态,证书交给它自己读的东西:配置键、安装目录包装、插件,由描述符选([4.11](4.11-collector-model.md) §2);登录环境不加任何变量(D56⑨)。Linux 的证书载体见 [4.6](4.6-process-collector.md) §身份与信任。装与按指纹撤都在 `arch/<os>/`;**管理员域与机器级信任库不做**(macOS 管理员域)。**绝不全机弱化 TLS**:这是 [4.1](4.1-capture-sources.md) 采集安全#3 的平台中立形态,精神跨 OS 不变,机制按 OS 落。


> **D55· D57**:代价写明——证书在时,本用户所有读用户级信任库的程序都信任这张 CA;私钥每台机器自己生成(D55⑤)。macOS / Windows 上私钥拿不走,但本用户名下的程序能借 asight 的签名助手(macOS)或直接调用这把密钥(Windows)签出被信任的证书,也能删掉它;怀疑被用过时,`uninstall` 再 `install`(D57②)。Linux 的私钥是 0600 的文件,被偷的后果到 `uninstall` 为止。


## 分发 / release(D23)

**(A · 选定 · 默认)npm/npx 主渠道**:发布 `asight` 到 npm,用户 `npx asight`(免装即跑)或 `npm i -g asight`。

> **`npm install` / `npx` 只放代码与 `asight` 这个命令(D65①,必拒违反)**:包里**没有 lifecycle 脚本**;装包不生成根、不碰信任库、不注册登录自启、不起守护进程、不写任何 agent 的配置。依据:**npm ≥ 7 不跑卸载脚本**(npm 文档 "A note on a lack of npm uninstall scripts"),所以装包阶段装上的任何东西,卸包时永远撤不回来 → 违「卸载不留残」(不变式 5([0.0](0.0-overview.md) §核心不变式));`--ignore-scripts` 很常见,行为会按机器而异;全局装可能以 root 跑,那是另一个用户的信任库与自启(D36);信任与自启要的是 OS 自己的框(D55① · D61),不许从一次包安装里弹出来。机器上的状态**全部**由 `asight install` 装、`asight uninstall` 撤(§C · §D)。**看板随 `install` 一起到位**(D65② · D66):看板由守护进程托管,而 `install` 注册自启并把守护进程拉起来,所以装完就一直在;`asight board` 只是印出带口令的网址并打开浏览器,没有要用户自己起的服务进程。`install` 之前 `asight board` 就说要先跑 `asight install`。
> **⚠ 阻断(2026-07-18)**:npm 包名 **`asight` 已被他人占用**(`asight@0.2.26` = eunomia-bpf/agentsight,同 bin 名、同「AI agent 可观测性」品类)。**发布名 MUST 先另选**(scoped `@<user>/asight` 或改名),否则 `npx asight` 装到的是别家软件——对一个要往 agent 的配置里写信任入口的工具,这是供应链风险,不只是命名冲突。同步改 `package.json` `name`/`bin` + README + [0.0-overview](0.0-overview.md) D23。另:当前 `package.json` 为 `private: true`、`version: 0.0.0`、**无 `license` 字段且仓库无 LICENSE 文件** → 公开即「保留所有权利」,任何人不得合法使用/fork,**发布前 MUST 补 LICENSE**(并加进 `files`)。
- **为何最省**:Node CLI 跨平台白送(Node 消化 OS 差异);读取侧只用 Node 自带能力(文件 + JSON),**没有要为每个平台编译的 `.node`** → **无需我们自打二进制**。这正是 npm-first 比自打二进制干净的根因。
- **GitHub Release 挂 tarball**:每次 tag 同时 `npm publish` + 把 `npm pack` 产物 attach 到 Release,给不想过 npm registry 的用户一个直下入口。

**(B · release 自动化)GitHub Actions**:tag `v*` 触发 workflow —— `test`(node:test 全绿)→ `github-release`(建 GitHub Release + 传 `npm pack` tarball)→ `publish-npm`(`npm publish --provenance`)。**私有阶段**:`publish-npm` 默认**关闭**,只有仓库变量 `PUBLISH_NPM == 'true'` 才跑;现在只在私有仓库里出 Release 做测试,准备公开时再打开(开启条件见 `release.yml` 头注释:改包名、去掉 `private`、`NPM_TOKEN`、仓库公开)。matrix 跑 `macos-latest` / `ubuntu-latest` 两个 OS 的测试(辅助,不是门也不是「全量测试过了」的凭据),**发布产物里的主包是平台无关的纯 JS npm 包**。**合入的门不靠 Actions**:门是本机的 `npm test`(全新 HOME)加该单元自带的实验室检查,结果写进 PR 正文([0.1](0.1-engineering-rules.md) §4);这里的 workflow 只在有 Actions 额度时是多一道检查。

**(C · 版本 / 卸载)**:`asight --version` 报版本;`asight uninstall` 一步撤掉证书与 asight 自己,采集数据默认保留(D39)。什么时候拒绝、按什么顺序撤、哪些例外保留,见 [1.6](1.6-cli.md) §3.6;macOS / Windows 的撤法见 [4.11](4.11-collector-model.md),Linux 见 [4.6](4.6-process-collector.md) §安装清单与卸载。Linux 采集器的卸载分两级(D36):`asight uninstall` 按用户撤销、不要 sudo;能力助手是整机的,另由一步 sudo 移除,移除前报告本机还有哪些用户的实例在用它。两级都做完才算零残留。

**(D · 开机自启 · D39 · D61)**:`asight install` 注册**用户级**自启并拉起守护进程,`asight uninstall` 撤销;`on` / `off` 不碰自启(D61:开关跨开关机不变),**绝不写全机启动项**(与信任面的平台中立原则同精神)。装/撤对称:Linux = 用户级 systemd 单元(`arch/linux/unit.mjs`);macOS = 用户级 LaunchAgent `~/Library/LaunchAgents/com.asight.collector.plist`([4.9](4.9-macos-collector.md) §4);Windows = 计划任务 `\asight\collector`([4.8](4.8-win-collector.md))。控制入口 = CLI `asight install` / `uninstall`([1.6](1.6-cli.md))。

**(E · 原生部件 · macOS / Windows · D57)**:macOS 的签名助手(`asight-sign-helper`)、读启动环境的 `procenv` 和列本用户 TCP 套接字的 `socktable` 是预编译好的通用二进制(ad-hoc 签名),随仓库提交,测试钉住 sha256;`scripts/build-darwin-native.sh` 只在一次专门的提交里重编,同一提交改钉住的值;`npm pack` 只拷贝,不重编。`install` 把它们拷进 `~/.asight/collector/bin/`;已装的签名助手哈希不同时,只在交互运行的 `install` 里替换([4.11](4.11-collector-model.md) §3 ⑮)。Windows 的安装目录包装在 `install` 时用系统自带的 `csc.exe` 编译。

**(F · 安全网:卸包与 `npx` 缓存 · D65⑤)**:用户没先 `asight uninstall` 就 `npm uninstall`(或 `npx` 的缓存被清),机器上会留下一个指向不存在的代码的自启项。要的三件事:自启项经 `~/.asight/bin/` 里的一个小启动器起;启动器发现包不在了就跑独立的 `asight-off`(别把 agent 留在一扇死门上)并把自启项退役,而不是崩着被反复重拉;`install` 拒绝从 `npx` 缓存路径注册自启。记为阶段 5 的分发项,本轮不做。

## 验收(可跑 check)

1. **单机边界不因分发松动**:装完起 server 仍只绑 `127.0.0.1`(承 [4.4](4.4-server.md) server gate);非环回接口连不上。
2. **零残留**:先 `off`、再 `uninstall` 之后,HOME 与 OS 状态等于 `install` 之前的快照:CA 不在任何信任库、私钥不在、各 harness 的证书项与代理入口撤净、被测程序直连;没 `off` 时、或还有持有者时,`uninstall` 拒绝、快照不变。macOS / Windows 另核对:根的密钥不在;Kimi 的真程序放回原处(包装已被官方安装器盖掉时只删 `.asight-real`);证书文件里带标记的一段撤净,用户之后加的内容留着。采集器:Linux 上按用户卸载与移除能力助手两级都做完后零残留;撤不掉的入口连同它的改前副本、它指向的合并包与安装清单保留到下次卸载(D39③);Linux 上还有加载过合并包的 agent 活着时,要等它退出再跑一次按用户卸载;OpenCode 的 npm install 残留只报不删;细项见 [4.6](4.6-process-collector.md) 验收 S10。

## Extensions

- **预编译单文件二进制(SEA / `pkg`)**:产 `asight-{darwin,linux,win}-{arch}` 挂 Release,下载即跑、无需 Node。**坑(记明)**:单文件要跟着 Node 运行时按平台各打一份、随 Node 版本重打,故 v1 走 npm、二进制留此。
- **包管理器渠道**:Homebrew tap(mac/linux)/ 其他;皆在 npm 主渠道稳定后。
