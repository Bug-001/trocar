# asight · RFC 4.5 — 跨平台安装 + 分发 / release

> **这是什么**:把这台单机研究仪器变成**可在 macOS、Linux、Windows 上一键装、跑、卸**、并经 **npm/npx + GitHub Release** 分发的工具。装:支持平台矩阵 · 信任面的平台中立原则 · 分发形态(D23)· release 自动化 · 边界守卫。
> **受众**:人(核对「单机 / 单用户 / loopback / 改包只出于操作者意图(D30)四条边界在分发后仍不破」)+ agent(据此实现跨 OS 安装 + release 流水线)。
> **Source-decision**:承 [0.0-overview](0.0-overview.md) **D23**(分发/release 策略)+ D1(个人研究仪器 + 产品化留缝)+ D43⑥(采集器 CA 默认不进信任库;**D55 起**改为 `install` 装进用户级系统信任库(首选,够不到的再用增量信任变量、配置键))。
> **不含 → 去哪查**:采集源机制 → [4.1](4.1-capture-sources.md);本地服务的 loopback/只读边界 → [4.4](4.4-server.md);技术栈(Node/`.mjs`/`@duckdb/node-api`)→ D18。

---

## Goal

让 asight 在 macOS、Linux 与 Windows 上都能:① 一条命令装起(`npx asight` 或全局装)· ② `asight on`(生成采集器 CA、写各 harness 的信任入口与引流;不往任何信任库装 CA,D43⑥;**D55 起**改为由 `install` 装进用户级系统信任库,见 [0.0](0.0-overview.md) D55)· ③ 采集→存储→查询→看板端到端跑通 · ④ 一条命令干净卸载(零残留;Linux 采集器的能力助手是整机的(D36),另要一步 sudo 移除,见 §C)。分发经 **npm 主渠道** + **GitHub Release 挂 tarball**,由 **GH Actions 打 tag 触发**。

**贯穿约束(分发后仍 MUST 成立)**:每个安装是**单机 · 单用户 · loopback · 改包只出于操作者意图(D30)** —— 分发**只是把同一台单机仪器复制到更多机器**(D36:或同一台机器上几个系统用户各装一套,共用一个不存状态的能力助手,每套仍只服务一个用户),**MUST NOT** 借此长出多用户 / 云端分享 / 对外暴露(Non-Goal + [4.4](4.4-server.md) 只绑环回;违反=**必拒**)。

## Definitions

- **可移植缝**:整条链 `采集器 → D10 信封 → adapter → DuckDB → server → 前端` 中,**只有采集器的 `arch/<os>/`**(引流、进程身份、自启、控制面、点名项的平台落点;见 [4.6](4.6-process-collector.md) / [4.8](4.8-win-collector.md) / [4.9](4.9-macos-collector.md))碰 OS。信封往后全是纯 Node(`@duckdb/node-api` 各平台有 prebuilt)→ **平台无关,零改**。
- **支持平台矩阵(v1)**:`darwin`(arm64/x64)· `linux`(x64/arm64)· `win32`。Windows 采集器见 [4.8](4.8-win-collector.md),默认不往任何证书库装 CA,用户按形态点名时才装进 `CurrentUser\Root`(D43⑥,4.8 §2.4;**D55 起**由 `install` 装、Windows 的确认框即同意);macOS 采集器见 [4.9](4.9-macos-collector.md)。
- **分发形态(D23)**:npm/npx 主渠道 + GitHub Release tarball 副本;**预编译单文件二进制(SEA)= Extension**(见文末)。

## 信任面的平台中立原则(必拒违反 · D43⑥)

采集器 CA 由 `install` 装、`uninstall` 撤,从不随 `on` / `off`(D55①)。按每个形态描述符的 `cert` 字段取阶梯上第一个够得到的:(a) **用户级**系统信任库(macOS 登录钥匙串的用户信任设置、Windows `CurrentUser\Root`;整机一项,按指纹认,OS 的框即同意)→ (b) 登录环境里的增量信任变量 → (c) 该 harness 自己的证书配置键 → (d) 改被测程序([4.6](4.6-process-collector.md) §身份与信任「信任注入」)。装与按指纹撤都在 `arch/<os>/`;**管理员域与机器级信任库不做**(macOS 管理员域)。**绝不全机弱化 TLS**:这是 [4.1](4.1-capture-sources.md) 采集安全#3 的平台中立形态,精神跨 OS 不变,机制按 OS 落。


> **D55**:代价写明——证书在时,本用户所有读系统信任库或读这些增量变量的程序都信任这张 CA,私钥被偷的后果到 `uninstall` 为止;私钥每台机器自己生成(D55⑤)。见 [0.0](0.0-overview.md) D55。


## 分发 / release(D23)

**(A · 选定 · 默认)npm/npx 主渠道**:发布 `asight` 到 npm,用户 `npx asight`(免装即跑)或 `npm i -g asight`。
> **⚠ 阻断(2026-07-18)**:npm 包名 **`asight` 已被他人占用**(`asight@0.2.26` = eunomia-bpf/agentsight,同 bin 名、同「AI agent 可观测性」品类)。**发布名 MUST 先另选**(scoped `@<user>/asight` 或改名),否则 `npx asight` 装到的是别家软件——对一个要往 agent 的配置里写信任入口的工具,这是供应链风险,不只是命名冲突。同步改 `package.json` `name`/`bin` + README + [0.0-overview](0.0-overview.md) D23。另:当前 `package.json` 为 `private: true`、`version: 0.0.0`、**无 `license` 字段且仓库无 LICENSE 文件** → 公开即「保留所有权利」,任何人不得合法使用/fork,**发布前 MUST 补 LICENSE**(并加进 `files`)。
- **为何最省**:Node CLI 跨平台白送(Node 消化 OS 差异);`@duckdb/node-api` **各平台有 prebuilt**,`npm install` 按当前平台自动选对 `.node` → **无需我们自打二进制**。这正是 npm-first 比自打二进制干净的根因。
- **GitHub Release 挂 tarball**:每次 tag 同时 `npm publish` + 把 `npm pack` 产物 attach 到 Release,给不想过 npm registry 的用户一个直下入口。

**(B · release 自动化)GitHub Actions**:tag `v*` 触发 workflow —— `test`(node:test 全绿)→ `github-release`(建 GitHub Release + 传 `npm pack` tarball)→ `publish-npm`(`npm publish --provenance`)。**私有阶段**:`publish-npm` 默认**关闭**,只有仓库变量 `PUBLISH_NPM == 'true'` 才跑;现在只在私有仓库里出 Release 做测试,准备公开时再打开(开启条件见 `release.yml` 头注释:改包名、去掉 `private`、`NPM_TOKEN`、仓库公开)。matrix 只为**测试**跨 `macos-latest` / `ubuntu-latest`(证全量测试在两个真 OS 上过),**发布产物里的主包是平台无关的 npm 包**(prebuilt 由 duckdb 分发,不进我们的包)。**合入的门不靠 Actions**:门是本机的 `npm test`(全新 HOME)加该单元自带的实验室检查,结果写进 PR 正文([0.1](0.1-engineering-rules.md) §4);这里的 workflow 只在有 Actions 额度时是多一道检查。

**(C · 版本 / 卸载)**:`asight --version` 报版本;`asight uninstall` 一步复原证书:要求采集全部下线(每个 harness 已 `asight off`、清单里没有 `on` 写的项、没有守护进程承载连接),否则什么都不改、退出 1(`collectors-online`),从不代做 `off`(D55⑥);成立后停掉空闲的守护进程(由自启管理者管着时经它停,不被拉回:Linux 的 systemd 用户单元、macOS 的 launchd、Windows 的计划任务),撤证书(证书配置项、登录环境载体、插件、合并包、信任根按指纹),一律删 CA 私钥,再删 asight 自己的东西(自启、运行目录、安装清单、改前副本、独立撤销程序),**零残留**,采集数据默认保留(D39;开关模型见 [1.6](1.6-cli.md))。Linux 采集器的卸载分两级(D36):`asight uninstall` 按用户撤销、不要 sudo;能力助手是整机的,另由一步 sudo 移除,移除前报告本机还有哪些用户的实例在用它。两级都做完才算零残留,细项见 [4.6](4.6-process-collector.md) §安装清单与卸载。四处例外如实写明:信任根的移除被拒或待定时,那张根留着(私钥已删,它已失效),`status` / `doctor` 报「孤儿 asight 根」与移除命令;撤不掉的入口(已解析不了、成了链接),连同它的改前副本、它指向的合并包与安装清单,保留到下次卸载(D39③);还有加载过合并包的 agent 活着时,第一次按用户卸载保留该合并包(已去掉 asight CA)并报告,等它退出后再跑一次才零残留;OpenCode 为 asight 的插件做的 npm install 在其配置目录写的文件,卸载只报不删。

**(D · 开机自启 · D39)**:`asight on` 启用**用户级**自启,不带参数的 `asight off` 停用(4.6 §开关语义),**绝不写全机启动项**(与信任面的平台中立原则同精神)。装/撤对称:Linux = 用户级 systemd 单元(`arch/linux/unit.mjs`);macOS = 用户级 LaunchAgent `~/Library/LaunchAgents/com.asight.collector.plist`([4.9](4.9-macos-collector.md) §4);Windows = 计划任务 `\asight\collector`([4.8](4.8-win-collector.md))。控制入口 = CLI `asight on` / `off`([1.6](1.6-cli.md))。

## 验收(可跑 check)

1. **单机边界不因分发松动**:装完起 server 仍只绑 `127.0.0.1`(承 [4.4](4.4-server.md) server gate);非环回接口连不上。
2. **零残留**:先 `off`、再 `uninstall` 之后,HOME 与 OS 状态等于 `install` 之前的快照:CA 不在任何信任库、私钥不在、各 harness 的证书项与代理入口撤净、被测程序直连;没 `off` 时 `uninstall` 拒绝、快照不变。采集器:Linux 上按用户卸载与移除能力助手两级都做完后零残留;撤不掉的入口连同它的改前副本、它指向的合并包与安装清单保留到下次卸载(D39③);还有加载过合并包的 agent 活着时,要等它退出再跑一次按用户卸载;OpenCode 的 npm install 残留只报不删;细项见 [4.6](4.6-process-collector.md) 验收 S10。

## Extensions

- **预编译单文件二进制(SEA / `pkg`)**:产 `asight-{darwin,linux,win}-{arch}` 挂 Release,下载即跑、无需 Node。**坑(记明)**:`@duckdb/node-api` 是**原生插件(.node)**,塞进单文件要按平台单独 bundle 正确的 prebuilt + 运行期解包——fiddly,故 v1 走 npm(prebuilt 自动)、二进制留此。
- **包管理器渠道**:Homebrew tap(mac/linux)/ 其他;皆在 npm 主渠道稳定后。
