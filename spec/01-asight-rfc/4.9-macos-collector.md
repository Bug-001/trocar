# asight · RFC 4.9 — macOS 后端(4.11 的 darwin 一面 · D47:引擎即代理)

> **状态**:采集器模型(install / on / off / uninstall、两类入口、上游五步、解密判定、持有者)在 [4.11](4.11-collector-model.md)(**D57**)。**本单元只写 macOS 后端**:按 `lsof` / `ps` 认进程、`procenv` 读启动环境、签名助手与钥匙串里的根密钥、登录钥匙串的用户信任、`scutil` 读系统代理、LaunchAgent、控制面。引擎、记录与两种 OS 共用的门在 [4.6](4.6-process-collector.md);引擎的代理入口(CONNECT / SOCKS5、拨上游、负缓存、记录格式)照 [4.8](4.8-win-collector.md) §5。
> **前置**:D31(按进程、不碰系统代理与整机流量)· D36(按用户运行)· D38(失败不静默)· D39(二元开关)· D40(全解密)· D43 / D49(系统代理只读感知)· D47(引擎自任代理、accept 时刻的套接字身份)· D51(按名字认进程)· D55(证书归 install)· D57。
> **标注**:[本机] = 在开发机上做的回环实验(临时目录、只听回环、跑完即停)。[MacVM] = 在 macOS 实验室跑。本单元验收编号 **MA1…** 只在本单元内有效。

## 0. 为什么不用 Network Extension / Endpoint Security

| | Network Extension 透明代理 / 滤器 | EndpointSecurity | 代理模式(本单元) |
|---|---|---|---|
| 权限 | 系统扩展:Apple Developer Program 账号 + 带 network-extension entitlement 的签名 + 公证,用户在系统设置里手动批准 | 专属 entitlement(实际只发给 MDM) | 零特权、零系统件、零开发者账号 |
| 出错形态 | 扩展崩在系统网络栈里,不是 fail-open | 同左 | 引擎死 → launchd 重拉守护进程;重拉期间 agent 连接被拒、重试即到,`status` 如实报 |
| 覆盖 | 全机流量的过滤点,与 D31④「其余连接的字节不经过 asight」相逆 | 同左 | 只有被配置去用它的 agent 经过它 |
| 认进程 | 有,但为全机过滤而设计 | 有 | 引擎在 accept 时刻对套接字定点提问(§5.3) |

## 1. 结构

`src/collector/arch/darwin/`。core 与 harness 描述符不点平台(4.11 §2);只有 arch 与 `daemon.mjs` 的接线点平台。

| darwin 文件 | 做什么 |
|---|---|
| `redirector.mjs` | 共享门核心 `core/engine/door-redirector.mjs` 的 darwin 薄衣:只带 `directCount`(`lsof` 的已建立连接表);身份问守护进程交进来的 `identify`(= `registry.match`,与 Windows 同一份名单,4.6 §识别进程) |
| `procinfo.mjs` | 定点每 pid 事实(§5.3):`ps -p <pid> -o pid=,ppid=,uid=,comm=,lstart=,args=` 一行 + `lsof -p <pid> -Fn` 的第一条 `ftxt`(真执行文件);启动环境经 `procenv` 读、cwd 取 `lsof -a -p <pid> -d cwd -Fn`、父进程取 `ps` 的 `ppid` 与它的 `lstart`(§5.2)。按 pid + 启动时间缓存,一个进程只读一次;不扫全机(D47) |
| `socktable.mjs` | 定点 4 元组 → pid:`lsof -nP -Fpcn -iTCP@<addr>:<port>`,本地端等于引擎 peer 的那行就是 agent 自己的套接字。无候选集、无去抖(D47);预算 250 ms 内是慢不是坏,超了答 null;读不出 = 一次 `socktable-unavailable` |
| `custody.mjs` + 签名助手 | 4.11 P1 的 `keychain` 保管(§6.1) |
| `root-store.mjs` | 4.11 P3:登录钥匙串的用户信任(§6.2);argv 只写在 `src/off/root-store.mjs` 一处,独立撤销程序也用它 |
| `policy.mjs` | 读托管偏好 plist 里描述符声明的键(4.11 §3 ⑩),以用户身份,只读 |
| `upstream.mjs` | 只剩系统代理的读取与盯守:`scutil --proxy`(§2) |
| `wrapper.dash.tmpl` | 安装目录包装的 darwin 模板(4.11 P8):`/bin/dash` 脚本,不用 `/bin/sh` |
| `autostart.mjs` | LaunchAgent(§4) |
| `control-path.mjs` | unix domain socket(`$TMPDIR` 下随机名)+ `control.json`(0600) |
| `netfacts.mjs` | `ps` / `lsof` / `scutil --proxy`;给 1.6 §9 的 `archFacts` 填真实现 |

- **两个原生部件**(4.11 §3 ⑮):签名助手 `asight-sign-helper`(Swift)与 `procenv`(C),源码在 `arch/darwin/native/`,预编译的通用二进制随仓库提交,测试钉住 sha256;`npm pack` 只拷贝,不重编;重编是一次专门的提交,同时改钉住的值(`scripts/build-darwin-native.sh`)。`install` 把它们拷进 `~/.asight/collector/bin/`。
- **不建常驻助手**:`ps` / `lsof` / `scutil` / `security` 都是普通命令,按问即跑(`execTool`),定点单问开销在预算内([本机] 实验②:定点 `lsof` 约 28–30 ms)。
- **已删**:入口写撤与 `ingress.json` 的读写搬进 core(`core/proxymode/entries.mjs`、`core/ingress-config.mjs`,两种 OS 共用一份);`forms.mjs`、`route-plan.mjs`、点名项(`optin.mjs`)、PATH shim、`harness/darwin/*.mjs` 与 `plugins/darwin/*` 都删掉。harness 的 darwin 数据(路径、键、形态)写在基底描述符的 `proxyMode` 里,用 `perOs({ darwin, win32 })` 区分(4.11 §2)。
- **接线**:`loadArch('darwin')`、`daemon.mjs` 的平台表。wiring 构造零副作用:不读不写任何入口文件、不起 watcher;门在 `on` 请求开它时才开(4.6 §代理模式的门),守护进程在引擎存在后把 `bindDoors` 槽绑到 `engine.listen({groups})` / `engine.closeGroups`。

## 2. 系统代理与上游的 darwin 读取器

上游的规则只有一份:4.11 §1 的五步,按连接取(4.11 §3 ⑥)。本节只写 macOS 上的读法。

- **第 3 步 · 进程环境**:读 agent 的启动环境(`procenv`,§5.2);大小写的先后按描述符 `proxy.env`。值等于 asight 的某一扇门就跳过,沿 `ppid` 往上找父进程,父进程的启动时间晚于子进程(pid 已被复用)或父进程已退出时停下,算「不知道」(4.11 §1 第 5 步)。
- **第 4 步 · 系统代理 = `scutil --proxy`**:`HTTPSEnable` + `HTTPSProxy` + `HTTPSPort` 给 https 的上游;`ProxyAutoConfigEnable` 开着 = PAC:asight 不执行 PAC,跟随系统代理的形态 `not-routed`(Claude Desktop 的入口不写,4.11 §3 ③)。
- **绕过表方言 `scutil`**:`ExceptionsList`(数组)逐项进表;`<local>` 与裸主机名按 4.8 §2.2 `translateBypass` 的 `no-proxy` 风格同款语义。
- **系统代理变化**:守护进程每 5 s 读一次 `scutil --proxy`,变了写一条 `netenv-change`;之后的新连接按新值取上游。不写入口,不碰任何 VPN(4.7)。
- **持久环境变量**:macOS 没有这一项(`persistentEnv` 答空;4.11 §3 ⑤)。

## 3. 引擎的门

照 [4.6](4.6-process-collector.md) §代理模式的门。darwin 的一处差别:PAC 组的门(`auth:false`)在 accept 时只放行 `ps` 给出的 `uid` 等于守护进程的进程,别的拒绝并记录(4.11 §3 ③)。

## 4. 开与关(launchd)

- 次序、排空与 `--now`、按 harness:照 4.11 §3 ①② 与 [1.6](1.6-cli.md) §1.3。
- **自启 = LaunchAgent**(`~/Library/LaunchAgents/com.asight.collector.plist`,`RunAtLoad` + `KeepAlive`)。launchd 会重拉被杀的进程,所以**不建监管父进程**;引擎崩 = launchd 重拉守护进程(这是已接受的代价,0.0 D47)。
- **`on`**:LaunchAgent 没装就装上(`launchctl bootstrap gui/<uid> <plist>`),停用了就 `launchctl enable gui/<uid>/com.asight.collector`。
- **`off`**:`launchctl disable gui/<uid>/com.asight.collector`,**不 `bootout`**(4.11 §3 ②)。守护进程按 4.11 §3 ② 排空:持有者都退出、也没有开着的连接之后,自己以退出码 0 退出;停用之后 launchd 不再把它拉回。
- **`uninstall`**:`launchctl bootout gui/<uid>/com.asight.collector`(斜杠形式,一个参数),再删 plist。
- **图形会话**:`install` 要在用户的图形登录会话里跑:登录钥匙串的授权框与签名助手的密码框只在那里出现。只经 ssh 登录时,要框的那几项停在 `pending`,`status` 给出原样命令。
- **登出**:LaunchAgent 随图形会话,登出即停,下次登录拉起;`status` 如实标注。
- 入口的写入与撤销只走通用机制(`prior_value`、改前备份、逐键逐块撤,4.11 P5),不为任何别的采集机制开并存特例。

## 5. 引擎的代理入口与进程事实

### 5.1 入口

入口协议(CONNECT / SOCKS5、健康探测 204、407)、拨上游(direct / http / socks5,一条连接只拨一次,凭据只进前导)、负缓存的键、同一记录格式(`capture:'proxy'`):照 [4.8](4.8-win-collector.md) §5.1、§5.2、§5.5、§5.6。

### 5.2 进程的环境、cwd 与父进程

- **启动环境 = `procenv <pid> <name>…`**:它用 `sysctl(KERN_PROCARGS2)` 读同用户进程的启动参数与启动环境,只答调用方点名的变量(描述符的 `proxy.env`、证书来源、`CODEX_HOME` 这类目录覆盖变量),从不把整个环境交出来。读的是进程**启动时**的环境:进程启动后在自己里面改的变量读不到(Claude Code 把 settings 的 `env` 盖在进程环境上,所以它的证书来源按 4.11 §3 ⑧ 的先后另读 settings)。别的用户的进程、读不到的进程答「不知道」,不答空。
- **cwd** = `lsof -a -p <pid> -d cwd -Fn`(4.11 §3 ⑨ 的项目 settings 按它找)。
- **父进程** = `ps` 行的 `ppid`,再读父进程的 `lstart`;上游第 3 步沿它往上找(§2)。
- 三样都按 pid + 启动时间缓存,一个进程只读一次。

### 5.3 身份:accept 时刻、从套接字读(0.0 D47)

引擎的门收下连接,peer 4 元组**就是** agent 的出站套接字(中间没有内核):两问定点、无扫描——

1. **谁**:`lsof -nP -Fpcn -iTCP@<peer addr>:<peer port>`,本地端等于 peer 的那行答 pid;无行、多行、慢、读不出 → null,连接 splice `untracked`(`pid-unresolved`),绝不猜(4.8 W4)。
2. **是什么**:该 pid 的 `ps -p` 行(命令行、`lstart`、`ppid`、`uid`)+ `lsof -p <pid> -Fn` 第一条 `ftxt`(真执行文件:argv[0] 是裸词或被空格截断时 `ps` 给不出路径,实测 2026-10-12)。`identify`(= `registry.match`)按名单判,判序照 4.8 §5.3:`uid` 与守护进程不同 → `other-user`;不在名单上 → 只转发(`not-an-agent`,另一条折叠的 `process-unknown`);名单上的 agent 连到别家的门照判,按它自己的 harness(4.8 W79)。

peer 进程按定义活着(它刚连上),一连接两问即全部成本(定点约 28–30 ms + 约 15 ms,[本机] 实验②)。

### 5.4 判定与持有者

- **解密判定** = [4.11](4.11-collector-model.md) P11,按描述符判;darwin 只供事实(§5.2、§5.3)。pid 的判定按 pid + 启动时间记,pid 复用的新进程不继承旧进程的判定。
- **持有者的进程表**(4.11 P12;判定见 `src/off/proc.mjs` 与 `src/off/signature.mjs`,D50④):一条 `ps -Axo pid=,ppid=,uid=,lstart=,args=` 加一条 `lsof -a -u <uid> -d txt -Fpn`,执行文件取每个进程第一条 `txt` 记录(名字以它为主来源;`ps` 的首词遇空格被截断、经 PATH 启动时只是裸名)。`lsof` 读不出与 `ps` 读不出一样,算进程表读不出,不算「没有进程」。`lsof` 的输出可能超过 1 MiB,读全(实测 2026-10-13)。
- **引擎验上游**(4.11 §3 ⑭):描述符写 `base:'os'` 的形态,darwin 的系统根 = `tls.getCACertificates('system')`(钥匙串管理的信任锚,含用户级根)∪ `getCACertificates('bundled')` ∪ `security find-certificate -a -p /System/Library/Keychains/SystemRootCertificates.keychain` 的导出(`src/off/os-roots.mjs` 的 `darwinRoots`),去掉 asight 根。绝不用固定的 `/etc/ssl/cert.pem`。某个来源读失败而别的来源给出了根时,记 `system-roots-partial`(带原因);解析不了的证书丢掉、计数(`system-roots-unparsable`);来源答「一张都没有」不算失败。

## 6. 证书(darwin)

### 6.1 根的密钥:登录钥匙串 + 签名助手(4.11 P1)

- **密钥**:P-256,在登录钥匙串里,`kSecAttrIsExtractable=false`、`kSecAttrIsSensitive`(R3-M1)。钥匙串的访问控制把它绑在签名助手的代码哈希上,只有签名助手能用它。
- **动词**:`create`(生成密钥并自签固定形状的根)· `exists` · `issue`(给调用方的公钥签一张中间证书)· `remove`。`issue` 自己拼中间证书:pathLen 0、只用于服务器认证、7 天、颁发者是根;不收调用方给的待签内容(4.11 CM3)。
- **图形会话**:签名助手要在用户的图形登录会话里跑。只经 ssh 时它答 `CSSMERR_CSP_NO_USER_INTERACTION`(R3-M3),后端答「不可用」;钥匙串锁着也一样。这时门只转发,记 `cert-intermediate-unavailable`(4.11 §3 ⑬)。
- **更新签名助手**(4.11 §3 ⑮):先用新文件名写入、再改名,从不原地覆盖(原地覆盖会被系统 SIGKILL,R3-M2)。已装的助手哈希不同时,只在交互运行的 `install` 里替换,并当场 `issue` 一次,让钥匙串的密码框在前台出现,不落到后台守护进程上。
- **剩余风险**:本用户名下的任何程序都能借签名助手签出被信任的证书,也能删掉密钥,只是拿不走私钥(4.11 §1)。

### 6.2 用户级根(4.11 P3)

- **装**:`security add-trusted-cert -r trustRoot -k <登录钥匙串> <根>`,不带 `-p`(不限用途)、不带 `-d`(不进管理员域)。系统弹框要登录密码;没有图形会话时这一项停在 `pending`,`status` 给出原样命令。
- **撤**:`security remove-trusted-cert <根>`,再 `security delete-certificate -Z <sha1>`。
- 从不写系统钥匙串、管理员域或任何机器级的信任库。

### 6.3 合并包

macOS 上只有 Z-Code 的合并包:Node 自带的根(`tls.rootCertificates`)+ asight 根,不含系统根(4.11 §1 install 第 4 条)。`darwinRoots` 只给引擎验上游用(§5.4)。

### 6.4 安装目录包装

照 4.11 P8;darwin 的包装是 `wrapper.dash.tmpl` 渲染出的 `/bin/dash` 脚本。前提里的「一个原生可执行文件」在 macOS 上指 Mach-O。

## 7. 守护进程、自启、控制面

守护进程本身跨 OS(4.6 / 4.8 §7):按用户运行、拒绝 root / euid 0、`op.lock` 的 darwin 判活(`ps -o lstart=`,1.6 R12)。**自启** = §4 的 LaunchAgent;**控制面** = unix domain socket + `control.json`(0600,随机名 + token,先核 token)。**Node 下限 22.15**(依 MA5:钥匙串里另加的根只在 `getCACertificates('system')` 里):`on` 与守护进程的 nodePreflight 低于它就拒绝,给 `doctor` 的修法。**守护进程锁的身份** = `ps -o lstart=` 的启动时间 + `sysctl kern.boottime` 当 boot_id,与 `off` 的 `psIdentity` 同一读法(依 D38⑥)。**每次启动**:先问签名助手 `exists`,密钥不在就记 `cert-key-missing`、门只转发、`status` 提示再跑一次 `asight install`;密钥在就签一张中间证书(要图形会话,§6.1)。
