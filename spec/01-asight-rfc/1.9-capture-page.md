## Goal

采集页回答一个问题:**我的每个 agent 都在被记录吗?没有的话,为什么,该怎么办?** 采集记录(子页)回答:**最近 24 小时采集出过什么错?**

两条硬约束:

1. 页上每个元素都有真实来源:`/api/status` 今天就有的字段、[4.4](4.4-server.md) §看板 v2 需要的补充 里的 `status` 的 `changed[]`、[1.6](1.6-cli.md)加的字段,或固定文字。做不到的控件不画([1.5](1.5-states-aesthetics.md) §数据规则)。
2. D38:采集服务的状态永不留空;失败带原因、看得到;不当告警(D38⑦)。

D31⑧ 说的「设置面板」落在这一页(D18c):每个 agent 的状态、asight 为它改了什么、本机网络环境、点名项,都在这里。

## 前置定义(Definitions)

- **采集页**:`#/capture`,侧栏「采集」下的「agent」子项。**采集记录**:`#/capture/log`,同组的「采集记录」子项。
- **采集服务**(看板词表):采集守护进程加引擎([4.6](4.6-process-collector.md))。界面上不说「守护进程」。
- **旧采集**(看板词表):过渡期的旧 MITM 与反代([4.1](4.1-capture-sources.md) §过渡期)。它的记录不带 harness。
- **检测到的 agent**:本页认得出的 agent,即下文「行从哪来」各来源的并集。没出现在任何来源里的 harness 没有行,也不写「没装」(没装的不显示)。
- **期望态**与**实际**:期望态是用户要它开还是关(`state.json`);实际是它的进程此刻有没有经过 asight、被记录。两者分开说:开关说的是期望,「被采集」说的是此刻的实际。
- **缓存的判词**:1.6 的 `asight status` / `doctor` / `on` 写进 `~/.asight/netenv.json` 的每个 harness 的结论(`netenv.topology[h]`)。它是那一刻的结论,不是实时的。
- **技术细节**:每块里收起的一节(`core/ui.mjs : techDetails`),放原因码、pid、路径、拓扑、命令。正文不出现这些([1.5](1.5-states-aesthetics.md) 看板词表)。

## Plan(选定方案 + 取舍)

**选定**:一张 agent 表(第一行是采集服务,之后每个检测到的 agent 一行)、一个旧采集块、一张本机网络环境卡、一块「asight 在这台电脑上做的改动」;采集记录另成一页。每个 agent 一行一个控件:开关,或(缺安装环节的东西时)Set up(§开关)。

**备选(未选)**:

- 原型的一行里又有开关、又有做同一件事的按钮(还有「重启」「单独开启…」):一个动作只留一个入口;重启、点名、提权没有端点,按「做不到的控件不画」只写状态与命令。
- 页头一句「6 个 agent:3 个在采…」:否决,这类话不出现在标题或小标题里;计数去总览页([1.7](1.7-overview-dashboard.md))。
- 采集服务停了时页顶一条横幅加「重新开启采集」:看板没有拉起采集服务的接口;全站不设横条([1.2](1.2-shell-layout.md))。这件事写在采集服务那一行。
- 给看板的 harness 表里每一个都列一行、写「没装」:否决,没装的不显示。
- 每个改动旁一个「撤掉」:否决,撤不撤完全取决于该 agent harness 的开关。
- 本页另开一条读路取实时判词:本页只读 `/api/status` 与 [1.6](1.6-cli.md) 写下的缓存,不绕过具名查询(不变式 3)。

**取舍**:能做的就给控件(开关、Set up),做不到的只说事实与命令——能做的事不丢一条命令让人自己去做。装与卸留在命令行(D55① · D61①),所以页面上不出现它们的按钮。
