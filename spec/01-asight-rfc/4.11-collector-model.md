## Goal

- 一份模型管 macOS 和 Windows:`install` 装根和根够不到时的证书载体,`on` / `off` 只管连接走不走门,解密按进程名认、只解密验过信任的形态。
- 模型的每一部分都是通用原语;harness 只在描述符里用数据选原语。加 harness 不写机制代码。
- Linux 不在本单元:照 [4.6](4.6-process-collector.md)。

## 1. 模型

> **定稿,此后不改。** 本节是模型正文,之后任何 PR 都不改它。与原稿的四处差别记在 §3 开头;标题层级随本单元下移一级。
> 各类事实现在住在别处:路径、键、进程名、主机写在描述符里(`src/collector/harness/<name>.mjs`,0.1 §2);每格状态(含本节的「未测」)记在实验室的逐格记录里(D45),不在本节;实验室测到一个「未测」项,改那条记录,不改本节。结果改变设计时,§3 加一条,点名它取代本节哪一句。会动的规范只有 §2 和 §3。

依据：四轮实验室实验；逐格结果和证据记在实验室的逐格记录里；标「未测」的是推断。规则来自 D43、D55、D56，定稿记在 D57。Linux 见 4.6。

几个词：
- **门**：asight 在本机开的代理端口，一组 agent 共用一个。
- **开关文件**：asight 自己目录里的文件，每个 harness 一个，写着门的地址；这个 harness on 时建，off 时删。

### install（装一次）

总规则：只加，不改。登录环境里不加任何变量。用户已经让某个设置指向一个证书文件时，在那个文件末尾追加一段带标记的 asight 证书，设置本身不动；只对用户自己的文件这样做，包管理器或系统自带的证书文件不碰，`status` 说明。install 记下自己加了什么，uninstall 只撤这些。

1. **生成 asight 根证书**：在本机生成；不限主机名；只能往下签一层中间证书；装上以后到 uninstall 都不换。证书上标「只用于服务器认证」：Windows 因此不认它签的代码，macOS 不因此收窄。私钥不能导出：
   - macOS：登录钥匙串里的密钥，只由 asight 的签名助手使用；助手在用户的图形登录会话里运行，只签固定形状的中间证书。
   - Windows：不可导出的 CNG 密钥，有 TPM 就放进 TPM。
   - 守护进程每次启动检查这把密钥还在；不在就报出，提示重新 install。
2. **中间证书**：守护进程每次启动新做一张，有效期 7 天，签发满 6 天时再做一张；私钥只在内存里，由根签。门给出叶证书时总是一并给出中间证书。签不出中间证书时（macOS 没有图形登录会话，例如只有 ssh 登录），门只转发、不解密，留一条带原因的记录，`status` 报出。
3. **把根装成用户级根证书**。
   - macOS：登录钥匙串的用户信任，不限用途；系统弹框要登录密码。
   - Windows：`CurrentUser\Root`；系统弹「是 / 否」框。
   - 只靠这一条就够的：Claude Code 的所有形态（含 Claude Desktop 和它的 Code 标签）、Codex、Hermes、OpenCode 的所有形态，以及 Kimi 的 VS Code 扩展。
4. **根够不到的，证书交给它们自己读的东西**：
   - Z-Code：`~/.zcode/cli/config.json` 的 `network.caCertFile` 指向 asight 的合并包（Node 自带的根 + asight 根）。这个键会替换掉默认的根，所以不能只放 asight 根。用户已经设了自己的文件时，按总规则在那个文件末尾追加。
   - Kimi：第 5 条的包装在启动 Kimi 时加上 `NODE_EXTRA_CA_CERTS`，只在它没设时才加；用户已经设了时，按总规则在那个文件末尾追加。
   - DeepSeek：第 6 条的插件在进程里加上 asight 根。
   - 用户设了 `CLAUDE_CODE_CERT_STORE=bundled` 的 Claude Code：`~/.claude/settings.json` 的 `env` 加 `NODE_EXTRA_CA_CERTS`，只在 settings 和 install 所在的环境里都没有它时才加；有时按总规则在那个文件末尾追加。
   - 用户设了 `SSL_CERT_FILE` 的 Codex、自己设了 `ssl_ca_cert` 的 Hermes 路由：按总规则在那个文件末尾追加（Codex 这一项未测）。
5. **Kimi 安装目录里的包装**：把 Kimi 的真程序挪进同目录的 `.asight-real`，文件名不变，原位放一个包装。
   - 没有开关文件时，只加上第 4 条的证书变量，其余原样执行真程序：参数、输入输出、退出码一字不差。
   - 有开关文件时，再把用户原来的代理记进 `ASIGHT_PRIOR_PROXY`（没有就写 `none`），把代理指向门。
   - 接住所有启动方式：各种 shell、绝对路径、编辑器起的 `kimi acp`、`kimi web`。
   - Kimi 自己的升级落在真程序上，不碰包装。重跑官方安装器会盖掉包装：`status` 按哈希报出，再跑一次 install 补上。
   - Windows 未测三项：包装加证书变量；`ASIGHT_PRIOR_PROXY` 这个名字和 `none`；官方安装器盖掉包装。
6. **DeepSeek 插件**：`~/.dsh/cordis.patch.yml` 里加一行加载它。它在进程里加上 asight 根；每个请求读一次开关文件：在就交给门，不在就交回 dsh 原来的走法。

同用户的剩余风险：本用户名下的任何程序都能借 asight 的签名助手（macOS）或直接调用这把密钥（Windows）签出被信任的证书，也能删掉它，只是拿不走私钥；怀疑被用过时，uninstall 再 install。

### uninstall

- 有任何 harness 还开着，或还有 on 期间启动、仍连着门的进程（含仍在用 asight PAC 的 Claude Desktop），就拒绝，并说出是哪些。
- 倒序撤：Kimi 包装的哈希还是 asight 放的那个时，把真程序原样放回；不是时（官方安装器已盖掉）不放回，只删 `.asight-real`。删插件和加的配置项；证书文件里按标记删掉自己那一段，用户之后加的内容留着；撤根证书（系统同样弹框）；最后删根的密钥和 asight 的证书文件。

### on / off：只管连接走不走门

共同规则：
- 不碰证书。改用户文件之前，先备份到 `~/.asight/backup/`。
- **门只在代理链里插一环**。门往外连时，用这个 agent 没有 asight 时本来会用的代理，按下面的先后取第一个有的：
  1. asight 的钩子交给门的值：在进程里改代理变量的钩子（Kimi 包装、OpenCode 插件）把用户原来的值写进 `ASIGHT_PRIOR_PROXY`，没有就写 `none`；DeepSeek 插件不改变量，在连门时带上 dsh 自己的代理（macOS 实测，Windows 未测）。
  2. on 时在这个 agent 配置里记下的用户原值（例如 Hermes `.env` 里用户自己的代理行）。
  3. 这个 agent 进程环境里的代理变量，大小写的先后按这个 agent 自己的规则。macOS 读它的启动环境，Windows 读它的当前环境；值等于门的跳过，沿创建它的进程一级级往上找（这一步 Windows 实测，macOS 未测）。
  4. 系统代理，只对本来就跟系统代理的 agent，连同绕过列表；系统代理是 PAC 时 asight 不执行它，如实标出。
  5. 都没有才直连。第 3 步找不回来（父进程已退出、中间隔着 Git Bash）时算「不知道」，不算「没有」：不论这个 agent 跟不跟系统代理，都取系统代理，没有系统代理才直连；`status` 报「窗口里的代理没接上」。
- `status` 按 harness 显示这条链：agent → 门 → 上游，上游从哪来；asight 写的代理值和用户原来的值并排列出。
- asight 写代理变量时大小写两种都写；写 `NO_PROXY` 时写「本机回环 + 用户原来的值」，同样两种大小写。
- off 不杀、不重启 agent。on 期间启动、off 后还在跑的进程仍连着门：门只转发，不解密、不记录，`status` 报还剩几个。

#### 第 1 类：在 agent 自己的配置里写代理（on 写，off 删）

| harness · 形态 | 系统 | 写在哪 | 何时生效 |
|---|---|---|---|
| Claude Code · 命令行、VS Code 扩展 | mac、win | `~/.claude/settings.json` 的 `env` | 下次启动 claude |
| Codex · 命令行、VS Code 扩展、app | mac、win | `$CODEX_HOME/.env` 里一段，含 `NO_PROXY`；Windows 上必须写 `NO_PROXY`，不写时系统代理绕过列表里的主机不经门 | 下次启动 codex，包括它的后台进程（用户重启，asight 不杀） |
| Hermes · 全部形态 | mac、win | Hermes 目录的 `.env` 里一段，放在用户自己的代理行之后 | 下次启动；dashboard 和 gateway 要重启它们自己 |
| Z-Code · 命令行（自带程序、Node 版）、桌面版 | mac、win | `~/.zcode/cli/config.json` 的 `network.httpProxy` | 下一个会话，app 不用重启 |
| OpenCode · 全部形态 | mac、win | 它的插件目录里一个 asight 插件，只在开着时放 | 下一个 OpenCode 实例；v2 在跑的后台服务下一次 `run` 就生效，不用重启。长会话（ACP）：1.x 到会话结束都不变；v2 下一轮生效，只有会话中途 on 过的，off 后到会话结束仍走门 |
| Kimi · VS Code 扩展 | mac、win | VS Code 用户设置 `http.proxy`，并加进 `settingsSync.ignoredSettings` | 未测 |
| Claude Desktop（含 Code 标签） | mac、win | 用户级配置库（mac `~/Library/Application Support/Claude-3p/configLibrary`，win `%LOCALAPPDATA%\Claude-3p\configLibrary`）里当前生效那一条的 `egressProxyPacUrl`；没有生效的条目时 asight 建一条只含这一键的并设为生效，off 时删掉它、生效项恢复原样（只含这一键时 app 仍是 Anthropic 账号模式：win 实测，mac 未测） | 下次启动 app；不要管理员 |

Claude Desktop 的 PAC 由 asight 守护进程在本机 http 地址提供，回环地址和用户的绕过列表直连，其余「先走门；门不通走这个 app 没有 asight 时本来的走法」：用户的固定系统代理，没有才直连。off 后守护进程在同一地址继续提供 PAC，内容只剩这个 app 本来的走法，直到 app 重启（在跑的 app 何时重新取 PAC，未测）。

#### 第 2 类：开关文件（on 建，off 删；不碰任何用户文件）

| harness · 形态 | 系统 | 谁读它 | 何时生效 |
|---|---|---|---|
| Kimi · 命令行、ACP、web | mac；win 除 web 外（web 未测） | install 放的包装 | 下次启动 kimi |
| DeepSeek · 全部形态 | mac、win | install 放的插件 | 下一个请求，不用重启；正在进行的请求照常走完 |

### 解密

引擎按进程名认出 agent（D51），只解密预设名单里在实验室验过信任的形态（D51④；每个形态的进程名在描述符的 `processes` 里（证据见实验室逐格记录））。没验过的，或者这个进程没带上证书（比如 install 之前就在跑），只转发、不解密，留一条带原因的记录，`status` 提示重开。靠证书变量信任的进程（Kimi、bundled 的 Claude Code），引擎先读它环境里那个变量指的文件，里面没有 asight 根（例如用户 install 之后才设的文件）就同样只转发、留记录。

### 没覆盖的

- 范围外：Kimi 桌面版；WSL 里的 Codex。
- Claude Desktop 登录后的模型回合两个系统都未测：Anthropic 账号模式下、未登录时测过路由（mac、win）和信任（mac）；回合是在第三方推理模式下测的。
- Claude Desktop：它的进程连 Anthropic 自己主机（claude.ai、更新、下载）的流量按 D40 也解密，未测；其中有钉证书的，会断登录、更新或 Code 标签的下载。
- Claude Desktop：asight 守护进程停了、PAC 取不到时，mac 上 app 直连、绕过用户的系统代理；win 未测。
- Claude Desktop：用户的系统代理本身是 PAC 时，PAC 里写不出用户的上游；机器上有托管配置时配置库不生效（读代码得知，未测），`status` 说明。
- Claude Desktop @mac：门不通时 Code 标签里的 claude 能否退到用户上游，未测（win 实测能）。
- Z-Code 的网络设置整组取自一处（环境变量或配置），三种情况不采，`status` 说明：用户在 `~/.zcode/v2/setting.json` 设了代理（盖过 cli 配置，还让 `caCertFile` 失效，mac 实测；on 不写那里）；用户环境里有 `ZCODE_HTTP_PROXY`（`caCertFile` 不生效，不信门）；用户环境里有 `ZCODE_AGENT_CA_CERT`（配置的 `httpProxy` 被忽略，直连，win 实测）。
- Z-Code：`caCertFile` 换掉默认根后，用户靠 `NODE_EXTRA_CA_CERTS` 或 `NODE_USE_SYSTEM_CA` 加的根（例如公司根）还算不算，未测；不算时 asight 关着 Z-Code 也连不上那些主机。
- Z-Code 网页版没试：发行版没有这个模式。
- OpenCode：插件加载之前发出的请求（`models.opencode.ai`）不经门（win 实测）。
- OpenCode 1.x：用户原本没有任何插件时，asight 插件会让它每次启动去 npm 装依赖，并在配置目录留下 `package.json` 和 `node_modules`，off 后还在；npm 不通时 mac 多等约两分半，win 卡住不发请求。
- Kimi：解析到另一份安装（npm 版）的 `kimi` 不经包装。
- Kimi VS Code 扩展：整个扩展宿主都走门，按进程名分不出 Kimi 的连接，只解密 Kimi 主机的办法没定；win 上带中间证书的链未测。
- Windows 窗口代理：Git Bash 里起的 Claude Code，门找不回窗口里设的代理。
- Windows 窗口代理：起 Claude Code 的窗口已关（例如 `start` 起的），门找不回窗口里设的代理；Codex 不受影响。
- Windows 窗口代理：agent 启动后窗口里改了代理值，门用的是新值。
- 只在某个终端里设的 `NO_PROXY`：on 时读不到，Claude Code、Codex、Hermes 配置里 asight 写的值会盖过它，那些主机改走门再走用户的代理，内网主机可能连不上。
- 只在 install 看不到的终端里设的 `NODE_EXTRA_CA_CERTS`：用户设了 `CLAUDE_CODE_CERT_STORE=bundled` 的 Claude Code 会改用 settings 里 asight 加的值，用户自己的证书文件（例如公司根）不再生效。
- Codex @win：用户在窗口里设了 `HTTPS_PROXY` 时，系统代理绕过列表里的主机直连、不经门；asight 写的 `NO_PROXY` 能否改变这一点未测。
- 根的密钥 @mac：签名助手更新后是否不弹登录密码框（要 Developer ID 签名）未测；钥匙串锁着时能否签名未测。
- 没跑：Cursor、Windsurf 等 VS Code 衍生版；真实的 ACP 编辑器（Zed、JetBrains）；Hermes 预编译的桌面版（DMG、MSIX）；OpenCode TUI 和桌面版的长会话在 on / off 时的表现。
