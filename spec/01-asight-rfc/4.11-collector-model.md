# asight · RFC 4.11 — 采集器模型(macOS · Windows)

> **这是什么**:macOS 与 Windows 上采集器怎么装、怎么开关、怎么解密的唯一权威:模型正文(§1)、实现它的通用原语与描述符格式(§2)、模型空白处的裁定(§3)。加 harness 只填描述符数据。
> **受众**:agent(实现 `install` / `uninstall` / `on` / `off`、守护进程与各操作系统后端;加 harness)。
> **Source-decision**:D43 · D47 · D51 · D55 · D56 · D57。模型正文(§1)定稿后不改。§2 的原语按「模型里的各部分设计得尽量通用,新来的 harness 能迅速兼容」取舍。
> **不含 → 去哪查**:Linux(驱动模式、证书、撤销顺序)→ [4.6](4.6-process-collector.md);引擎、记录、D51 认进程、门的共用契约 → [4.6](4.6-process-collector.md);Windows 后端(身份与环境读取、助手动词、CNG 保管、`CurrentUser\Root`、系统代理读取、自启、控制面)→ [4.8](4.8-win-collector.md);macOS 后端(lsof / ps 身份、procenv、签名助手、钥匙串信任、scutil、LaunchAgent、控制面)→ [4.9](4.9-macos-collector.md);系统代理怎么读 → [4.7](4.7-netenv.md);命令与回执 → [1.6](1.6-cli.md);每个 harness 的具体值 → 描述符 `src/collector/harness/<name>.mjs`。

## Goal

- 一份模型管 macOS 和 Windows:`install` 装根和根够不到时的证书载体,`on` / `off` 只管连接走不走门,解密按进程名认、只解密验过信任的形态。
- 模型的每一部分都是通用原语;harness 只在描述符里用数据选原语。加 harness 不写机制代码。
- Linux 不在本单元:照 [4.6](4.6-process-collector.md)。

## 1. 模型

> **定稿,此后不改。** 本节是模型正文,之后任何 PR 都不改它。与原稿的四处差别记在 §3 开头;标题层级随本单元下移一级。
> 各类事实现在住在别处:路径、键、进程名、主机写在描述符里(`src/collector/harness/<name>.mjs`,0.1 §2);每格状态(含本节的「未测」)记在实验室的逐格记录里(D45),不在本节;实验室测到一个「未测」项,改那条记录,不改本节。结果改变设计时,§3 加一条,点名它取代本节哪一句。会动的规范只有 §2 和 §3。

依据：四轮实验室实验；逐格结果和证据记在实验室的逐格记录里；标「未测」的是推断。规则来自 D43、D55、D56，定稿记在 D57。Linux 见 4.6。

几个词：
- **门**：asight 在本机开的代理端口，一组 agent 共用一个。
- **开关文件**：asight 自己目录里的文件，每个 harness 一个，写着门的地址；这个 harness on 时建，off 时删。

### install（装一次）

总规则：只加，不改。登录环境里不加任何变量。用户已经让某个设置指向一个证书文件时，在那个文件末尾追加一段带标记的 asight 证书，设置本身不动；只对用户自己的文件这样做，包管理器或系统自带的证书文件不碰，`status` 说明。install 记下自己加了什么，uninstall 只撤这些。

1. **生成 asight 根证书**：在本机生成；不限主机名；只能往下签一层中间证书；装上以后到 uninstall 都不换。证书上标「只用于服务器认证」：Windows 因此不认它签的代码，macOS 不因此收窄。私钥不能导出：
   - macOS：登录钥匙串里的密钥，只由 asight 的签名助手使用；助手在用户的图形登录会话里运行，只签固定形状的中间证书。
   - Windows：不可导出的 CNG 密钥，有 TPM 就放进 TPM。
   - 守护进程每次启动检查这把密钥还在；不在就报出，提示重新 install。
2. **中间证书**：守护进程每次启动新做一张，有效期 7 天，签发满 6 天时再做一张；私钥只在内存里，由根签。门给出叶证书时总是一并给出中间证书。签不出中间证书时（macOS 没有图形登录会话，例如只有 ssh 登录），门只转发、不解密，留一条带原因的记录，`status` 报出。
3. **把根装成用户级根证书**。
   - macOS：登录钥匙串的用户信任，不限用途；系统弹框要登录密码。
   - Windows：`CurrentUser\Root`；系统弹「是 / 否」框。
   - 只靠这一条就够的：Claude Code 的所有形态（含 Claude Desktop 和它的 Code 标签）、Codex、Hermes、OpenCode 的所有形态，以及 Kimi 的 VS Code 扩展。
4. **根够不到的，证书交给它们自己读的东西**：
   - Z-Code：`~/.zcode/cli/config.json` 的 `network.caCertFile` 指向 asight 的合并包（Node 自带的根 + asight 根）。这个键会替换掉默认的根，所以不能只放 asight 根。用户已经设了自己的文件时，按总规则在那个文件末尾追加。
   - Kimi：第 5 条的包装在启动 Kimi 时加上 `NODE_EXTRA_CA_CERTS`，只在它没设时才加；用户已经设了时，按总规则在那个文件末尾追加。
   - DeepSeek：第 6 条的插件在进程里加上 asight 根。
   - 用户设了 `CLAUDE_CODE_CERT_STORE=bundled` 的 Claude Code：`~/.claude/settings.json` 的 `env` 加 `NODE_EXTRA_CA_CERTS`，只在 settings 和 install 所在的环境里都没有它时才加；有时按总规则在那个文件末尾追加。
   - 用户设了 `SSL_CERT_FILE` 的 Codex、自己设了 `ssl_ca_cert` 的 Hermes 路由：按总规则在那个文件末尾追加（Codex 这一项未测）。
5. **Kimi 安装目录里的包装**：把 Kimi 的真程序挪进同目录的 `.asight-real`，文件名不变，原位放一个包装。
   - 没有开关文件时，只加上第 4 条的证书变量，其余原样执行真程序：参数、输入输出、退出码一字不差。
   - 有开关文件时，再把用户原来的代理记进 `ASIGHT_PRIOR_PROXY`（没有就写 `none`），把代理指向门。
   - 接住所有启动方式：各种 shell、绝对路径、编辑器起的 `kimi acp`、`kimi web`。
   - Kimi 自己的升级落在真程序上，不碰包装。重跑官方安装器会盖掉包装：`status` 按哈希报出，再跑一次 install 补上。
   - Windows 未测三项：包装加证书变量；`ASIGHT_PRIOR_PROXY` 这个名字和 `none`；官方安装器盖掉包装。
6. **DeepSeek 插件**：`~/.dsh/cordis.patch.yml` 里加一行加载它。它在进程里加上 asight 根；每个请求读一次开关文件：在就交给门，不在就交回 dsh 原来的走法。

同用户的剩余风险：本用户名下的任何程序都能借 asight 的签名助手（macOS）或直接调用这把密钥（Windows）签出被信任的证书，也能删掉它，只是拿不走私钥；怀疑被用过时，uninstall 再 install。

### uninstall

- 有任何 harness 还开着，或还有 on 期间启动、仍连着门的进程（含仍在用 asight PAC 的 Claude Desktop），就拒绝，并说出是哪些。
- 倒序撤：Kimi 包装的哈希还是 asight 放的那个时，把真程序原样放回；不是时（官方安装器已盖掉）不放回，只删 `.asight-real`。删插件和加的配置项；证书文件里按标记删掉自己那一段，用户之后加的内容留着；撤根证书（系统同样弹框）；最后删根的密钥和 asight 的证书文件。

### on / off：只管连接走不走门

共同规则：
- 不碰证书。改用户文件之前，先备份到 `~/.asight/backup/`。
- **门只在代理链里插一环**。门往外连时，用这个 agent 没有 asight 时本来会用的代理，按下面的先后取第一个有的：
  1. asight 的钩子交给门的值：在进程里改代理变量的钩子（Kimi 包装、OpenCode 插件）把用户原来的值写进 `ASIGHT_PRIOR_PROXY`，没有就写 `none`；DeepSeek 插件不改变量，在连门时带上 dsh 自己的代理（macOS 实测，Windows 未测）。
  2. on 时在这个 agent 配置里记下的用户原值（例如 Hermes `.env` 里用户自己的代理行）。
  3. 这个 agent 进程环境里的代理变量，大小写的先后按这个 agent 自己的规则。macOS 读它的启动环境，Windows 读它的当前环境；值等于门的跳过，沿创建它的进程一级级往上找（这一步 Windows 实测，macOS 未测）。
  4. 系统代理，只对本来就跟系统代理的 agent，连同绕过列表；系统代理是 PAC 时 asight 不执行它，如实标出。
  5. 都没有才直连。第 3 步找不回来（父进程已退出、中间隔着 Git Bash）时算「不知道」，不算「没有」：不论这个 agent 跟不跟系统代理，都取系统代理，没有系统代理才直连；`status` 报「窗口里的代理没接上」。
- `status` 按 harness 显示这条链：agent → 门 → 上游，上游从哪来；asight 写的代理值和用户原来的值并排列出。
- asight 写代理变量时大小写两种都写；写 `NO_PROXY` 时写「本机回环 + 用户原来的值」，同样两种大小写。
- off 不杀、不重启 agent。on 期间启动、off 后还在跑的进程仍连着门：门只转发，不解密、不记录，`status` 报还剩几个。

#### 第 1 类：在 agent 自己的配置里写代理（on 写，off 删）

| harness · 形态 | 系统 | 写在哪 | 何时生效 |
|---|---|---|---|
| Claude Code · 命令行、VS Code 扩展 | mac、win | `~/.claude/settings.json` 的 `env` | 下次启动 claude |
| Codex · 命令行、VS Code 扩展、app | mac、win | `$CODEX_HOME/.env` 里一段，含 `NO_PROXY`；Windows 上必须写 `NO_PROXY`，不写时系统代理绕过列表里的主机不经门 | 下次启动 codex，包括它的后台进程（用户重启，asight 不杀） |
| Hermes · 全部形态 | mac、win | Hermes 目录的 `.env` 里一段，放在用户自己的代理行之后 | 下次启动；dashboard 和 gateway 要重启它们自己 |
| Z-Code · 命令行（自带程序、Node 版）、桌面版 | mac、win | `~/.zcode/cli/config.json` 的 `network.httpProxy` | 下一个会话，app 不用重启 |
| OpenCode · 全部形态 | mac、win | 它的插件目录里一个 asight 插件，只在开着时放 | 下一个 OpenCode 实例；v2 在跑的后台服务下一次 `run` 就生效，不用重启。长会话（ACP）：1.x 到会话结束都不变；v2 下一轮生效，只有会话中途 on 过的，off 后到会话结束仍走门 |
| Kimi · VS Code 扩展 | mac、win | VS Code 用户设置 `http.proxy`，并加进 `settingsSync.ignoredSettings` | 未测 |
| Claude Desktop（含 Code 标签） | mac、win | 用户级配置库（mac `~/Library/Application Support/Claude-3p/configLibrary`，win `%LOCALAPPDATA%\Claude-3p\configLibrary`）里当前生效那一条的 `egressProxyPacUrl`；没有生效的条目时 asight 建一条只含这一键的并设为生效，off 时删掉它、生效项恢复原样（只含这一键时 app 仍是 Anthropic 账号模式：win 实测，mac 未测） | 下次启动 app；不要管理员 |

Claude Desktop 的 PAC 由 asight 守护进程在本机 http 地址提供，回环地址和用户的绕过列表直连，其余「先走门；门不通走这个 app 没有 asight 时本来的走法」：用户的固定系统代理，没有才直连。off 后守护进程在同一地址继续提供 PAC，内容只剩这个 app 本来的走法，直到 app 重启（在跑的 app 何时重新取 PAC，未测）。

|---|---|---|---|

### 解密

引擎按进程名认出 agent（D51），只解密预设名单里在实验室验过信任的形态（D51④；每个形态的进程名在描述符的 `processes` 里（证据见实验室逐格记录））。没验过的，或者这个进程没带上证书（比如 install 之前就在跑），只转发、不解密，留一条带原因的记录，`status` 提示重开。靠证书变量信任的进程（Kimi、bundled 的 Claude Code），引擎先读它环境里那个变量指的文件，里面没有 asight 根（例如用户 install 之后才设的文件）就同样只转发、留记录。

### 没覆盖的

- 范围外：Kimi 桌面版；WSL 里的 Codex。
- Claude Desktop 登录后的模型回合两个系统都未测：Anthropic 账号模式下、未登录时测过路由（mac、win）和信任（mac）；回合是在第三方推理模式下测的。
- Claude Desktop：它的进程连 Anthropic 自己主机（claude.ai、更新、下载）的流量按 D40 也解密，未测；其中有钉证书的，会断登录、更新或 Code 标签的下载。
- Claude Desktop：asight 守护进程停了、PAC 取不到时，mac 上 app 直连、绕过用户的系统代理；win 未测。
- Claude Desktop：用户的系统代理本身是 PAC 时，PAC 里写不出用户的上游；机器上有托管配置时配置库不生效（读代码得知，未测），`status` 说明。
- Claude Desktop @mac：门不通时 Code 标签里的 claude 能否退到用户上游，未测（win 实测能）。
- Z-Code 的网络设置整组取自一处（环境变量或配置），三种情况不采，`status` 说明：用户在 `~/.zcode/v2/setting.json` 设了代理（盖过 cli 配置，还让 `caCertFile` 失效，mac 实测；on 不写那里）；用户环境里有 `ZCODE_HTTP_PROXY`（`caCertFile` 不生效，不信门）；用户环境里有 `ZCODE_AGENT_CA_CERT`（配置的 `httpProxy` 被忽略，直连，win 实测）。
- Z-Code：`caCertFile` 换掉默认根后，用户靠 `NODE_EXTRA_CA_CERTS` 或 `NODE_USE_SYSTEM_CA` 加的根（例如公司根）还算不算，未测；不算时 asight 关着 Z-Code 也连不上那些主机。
- Z-Code 网页版没试：发行版没有这个模式。
- OpenCode：插件加载之前发出的请求（`models.opencode.ai`）不经门（win 实测）。
- OpenCode 1.x：用户原本没有任何插件时，asight 插件会让它每次启动去 npm 装依赖，并在配置目录留下 `package.json` 和 `node_modules`，off 后还在；npm 不通时 mac 多等约两分半，win 卡住不发请求。
- Kimi：解析到另一份安装（npm 版）的 `kimi` 不经包装。
- Kimi VS Code 扩展：整个扩展宿主都走门，按进程名分不出 Kimi 的连接，只解密 Kimi 主机的办法没定；win 上带中间证书的链未测。
- Windows 窗口代理：Git Bash 里起的 Claude Code，门找不回窗口里设的代理。
- Windows 窗口代理：起 Claude Code 的窗口已关（例如 `start` 起的），门找不回窗口里设的代理；Codex 不受影响。
- Windows 窗口代理：agent 启动后窗口里改了代理值，门用的是新值。
- 只在某个终端里设的 `NO_PROXY`：on 时读不到，Claude Code、Codex、Hermes 配置里 asight 写的值会盖过它，那些主机改走门再走用户的代理，内网主机可能连不上。
- 只在 install 看不到的终端里设的 `NODE_EXTRA_CA_CERTS`：用户设了 `CLAUDE_CODE_CERT_STORE=bundled` 的 Claude Code 会改用 settings 里 asight 加的值，用户自己的证书文件（例如公司根）不再生效。
- Codex @win：用户在窗口里设了 `HTTPS_PROXY` 时，系统代理绕过列表里的主机直连、不经门；asight 写的 `NO_PROXY` 能否改变这一点未测。
- 根的密钥 @mac：签名助手更新后是否不弹登录密码框（要 Developer ID 签名）未测；钥匙串锁着时能否签名未测。
- 没跑：Cursor、Windsurf 等 VS Code 衍生版；真实的 ACP 编辑器（Zed、JetBrains）；Hermes 预编译的桌面版（DMG、MSIX）；OpenCode TUI 和桌面版的长会话在 on / off 时的表现。

## 2. 原语与描述符

本节是规范。每个原语只定义一次;harness 只通过描述符数据(§2.3)在原语里选。每个 harness 的具体值(路径、键、进程名、主机)只写在描述符里,本单元不抄(0.1 §2)。

### 2.1 四个角色

| 角色 | 做什么 | 从不做 |
|---|---|---|
| **命令行**:`install`、`on`、`off`、`uninstall`,和独立的 `asight-off`(`src/off`,只用 `node:*`) | 对用户文件、agent 文件的每一次写,对清单的每一次写。请守护进程开门、关门,并读回结果。 | 读或改流量。 |
| **守护进程**:每个用户一个,macOS 是 LaunchAgent,Windows 是计划任务 | 门(D47)。PAC。接受连接时认进程(D51)。解密判定。上游链。每次启动签中间证书。跟踪持有者。记录。 | 写 agent 文件。往信任库写证书。 |
| **钩子**:由 `install` 放,OpenCode 的由 `on` 放 | 在 agent 自己的进程树里:加 asight 根,把连接交给门。 | 读或改字节。连门以外的地方。写 agent 配置。 |
| **操作系统后端**(`arch/<os>/`) | 密钥保管。用户级根证书库。按 pid 的进程事实:名字、启动时间、父进程、环境、cwd、套接字的所有者(uid / SID)。给持有者判定用的进程表。系统代理读取。持久环境变量和托管策略的读取(win:以用户身份用 `reg.exe` 读注册表;mac:托管偏好 plist)。core 要用的平台事实由它给,core 不写操作系统名:`envCaseInsensitive`、`pathKey(p)`、`persistentEnv(names)`。自启。控制通道。生成包装。 | 任何 harness 知识。守卫:`arch/` 与 `core/` 的代码里没有 harness id,`core/` 的代码里没有操作系统名字面量(注释不算);插件模板在 `src/collector/harness/templates/`(CM27)。 |

### 2.2 原语

**P1 密钥保管**(操作系统后端;一个接口):

```
custody = {
  kind: 'keychain' | 'cng' | 'file',
  create({ subject }) → { rootDer, fp256 }   // 在后端里生成密钥,并自签固定形状的根
  exists() → boolean
  issueIntermediate({ spkiDer, serial, notBefore }) → certDer   // 后端自己拼待签内容:CA:true、pathLen 0、EKU serverAuth、7 天、颁发者 = 根
  remove()
}
```

- `keychain`(macOS):签名助手 `asight-sign-helper`(Swift),预编译的通用二进制随仓库提交,测试钉住它的 sha256(§3 ⑮)。
  - 密钥:登录钥匙串,P-256,顶层设 `kSecAttrIsExtractable=false` 和 `kSecAttrIsSensitive`(R3-M1)。
  - 动词:`create`、`exists`、`issue`、`remove`。
  - 它在用户的图形登录会话里运行。经 ssh 时报 `CSSMERR_CSP_NO_USER_INTERACTION`(R3-M3),后端返回 `unavailable`。钥匙串锁着时同样返回 `unavailable`。
  - 安装先用新文件名写入、再改名,不原地覆盖:原地覆盖的文件会被 SIGKILL(R3-M2)。已装的助手哈希不同时,只在交互运行的 `install` 里替换,并当场 `issue` 一次,让钥匙串的框在前台答掉。
- `cng`(Windows):一次性的 `custody.ps1`。
  - 密钥:`ExportPolicy=None`,P-256;有 TPM 时放进 Microsoft Platform Crypto Provider,没有时放软件 KSP(R3-W1)。
  - 用 `X509SignatureGenerator` 签(R3-W2)。
- `file`(Linux):现有的 `ca/ca.key`,0600。没有 `issueIntermediate`,叶证书仍由根直接签。Linux 不变。

**P2 签发**(`core/tls`):

- 根的形状:没有名称约束,pathLen 1,EKU 只有 serverAuth(§1 install 第 1 条;M8、W6)。
- 守护进程每次启动时在内存里新生成一把 P-256 密钥,请保管后端为它签一张 7 天的中间证书;这张满 6 天时签下一张。
- 重签失败(钥匙串锁着、没有图形会话、密钥不在)时,继续用当前这张,记一条 `cert-intermediate-unavailable`,每小时重试;当前这张到期后门只转发,直到签出新的。
- 叶证书的到期不晚于它的中间证书。换中间证书时清掉叶证书缓存。
- TLS 总是发「叶 + 中间」(§1 install 第 2 条;t4-nointer、t2d)。
- 保管后端返回 `unavailable` 或密钥不在时,没有签发器:门只转发,记 `cert-intermediate-unavailable` 或 `cert-key-missing`。
- `cert.mjs` 收一个 `sign(tbs)` 回调,所以 mac / win 上根的私钥从不进 Node。

**P3 用户级根证书库**(操作系统后端;命令行参数只写一处,在可独立运行的 `src/off/root-store.mjs`,采集器导入它):

- `add(rootDer)`:
  - mac:`security add-trusted-cert -r trustRoot -k <登录钥匙串>`,不带 `-p`(不限用途,M7、M8);
  - win:`certutil -user -addstore Root`。
- `has(fp256)`。
- `remove(fp256)`:
  - mac:先 `remove-trusted-cert`,再 `delete-certificate -Z`;
  - win:`certutil -user -delstore Root <指纹>`。
- 操作系统弹的框就是同意。从不写机器级信任库。

**P4 证书载体**(`install` 写,清单阶段 `install`):一条规则加四种。

- **规则 U:用户自己的文件。** 描述符 `userCertFiles` 列出的某个设置已经指向一个文件时,`install` 在这个文件末尾追加一段带标记的 PEM(清单 `text` / `pem-block`),设置本身不动。
  - 只对本用户拥有、可写、不在包管理器目录或系统目录里的文件这样做。
  - 不满足时跳过这个文件,`status` 报 `not-users-file`。
  - `uninstall` 按标记逐字节删掉这一段,用户之后加的内容留着(M5、W4)。
- `root`:只用 P3。每个形态的底线。
- `config-key` `{ file: <loc>, format, keys, semantics, when?: <cond> }`(位置和条件都是数据,§2.3):
  - `replace`:键指向每个 harness 一份的合并包,内容是 Node 自带的根加 asight 根(Z-Code;R3-M6、R3-W3);
  - `add`:键指向 `asight-ca.pem`(bundled 的 Claude Code);
  - 只在键没设时写。键已设时按规则 U。
- `wrapper`:P8。
- `plugin`:P9。

**P5 代理入口**(`on` 写,清单阶段 `on`)。第 1 类写进 agent 自己的配置,第 2 类是开关文件。

每种入口的接口相同:`write(ctx, doorUrl)` / `undo` / `check`。每次写:

- 只为至少一个**装着的**形态(描述符 `present`,§2.3)用到的入口写;一个 harness 没有装着的形态时不写入口,`status` 说它没装;
- 先备份到 `~/.asight/backup/`;
- 带哨兵标记;
- 按描述符给的名字,两种大小写都写;
- `NO_PROXY` 按 P6 写;
- 把被替换的值记成 `prior_value`(上游第 2 步);
- 目标文件不在时按入口的 `absent`:`create` 就建,`not-routed` 就不写并写明原因(§3 ㉑)。

每次撤销都逐键(或逐段):一个键或一段还是 asight 写的值时,才恢复记下的原值;用户在 `on` 期间改过的,照用户的留着(D48②)。只有用户什么都没改时,才按整个文件的字节比对。

| 种类 | 写什么 | 清单项 |
|---|---|---|
| `json-key` | JSON / JSONC 文件里的键;值是门的地址,或 PAC 地址(`value: 'pac-url'`)。两个可选的数据字段让它盖住 GUI 的情况,不用每个 app 一种:`arrayItems`(asight 往数组里加的一个元素,例如 VS Code 的 `settingsSync.ignoredSettings` 加 `http.proxy`)和 `select`(文件是一个元文件选中的那一条:`{ dir, meta, idKey, createIfNone }`;Claude Desktop 的配置库是 `_meta.json` 和 `appliedId`;没有生效的条目时,建一条只含这一键的并设为生效) | `json-key`(加 `json-array-item`;建了条目时,再加 `owned-file` 角色 `config-entry` 和元文件上的 `json-key`) |
| `dotenv-block` | 一段,放在用户同名键的行**之后**;不注释任何一行 | `text` / `dotenv-block` |
| `plugin-file` | agent 插件目录里一个 asight 拥有的文件,门的地址写死在里面(内容来自 P9 的 `opencode-plugin` 模板) | `owned-file` 角色 `plugin` |
| `switch-file` | `~/.asight/collector/switch/<harness>`(0600),内容是门的地址 | `owned-file` 角色 `switch` |

**P6 `NO_PROXY` 合并**:

- 值 = 本机回环(`localhost,127.0.0.1,::1`)∪ 用户原来的值。
- 用户原来的值 = `on` 之前写入处已有的值(两种大小写合并),加上 `arch.persistentEnv(['NO_PROXY'])` 读到的(§3 ⑤)。core 不写操作系统名。
- 合并时不分大小写去重,保持原来的顺序。两种大小写都写(R3-M8、R3-W5)。

**P7 上游链**(`core/proxymode/chain.mjs`,所有 harness 共用一个函数):

```
upstreamFor({ desc, form, facts /* pid, start, env, parentOf */, recordedPrior, systemProxy }) → { url | null, source, bypass }
source ∈ 'hook' | 'config-prior' | 'process-env' | 'system-proxy' | 'direct' | 'unknown'
```

各步照 §1 on / off 共同规则的 1–5:

1. **hook**:进程环境里的 `ASIGHT_PRIOR_PROXY`(`none` = 没有代理),或 CONNECT 头 `X-Asight-Upstream`(一个代理地址;agent 自己对这个主机本来就直连时是 `none`——钩子连门之前先套用 agent 自己的绕过规则)。只有认出的进程所在形态用的是会发这个头的钩子(今天只有 `cordis-plugin`)时才认这个头;别的进程带来的一律不认,记一条。入口剥掉这个头,从不记它的值。没有 `X-Asight-No-Proxy`。
2. **config-prior**:`on` 记下的 `prior_value`。
3. **process-env**:按描述符 `proxy.env` 的先后。值等于 asight 某一扇门的跳过,沿 `parentOf` 往上找。
4. **system-proxy**:只对跟系统代理的 agent(`proxy.systemProxy`),连同绕过列表。asight 从不执行 PAC:系统代理是 PAC 时,跟系统代理的形态不写入口(`not-routed`),`status` 写明原因。
5. **direct**:都没有才直连。

第 3 步找不回来时,结果是 `unknown`:有系统代理就用系统代理,没有才直连,记 `prior-proxy-unknown`。

每一个来源都过 `isAsightDoor(url)`(本机回环加 asight 的凭据)。

操作系统后端的读取器是 `proc.envOf(pid, names)`、`proc.cwdOf(pid)` 和 `proc.parentOf(pid) → { ppid, startedAt }`:

- mac 用 `procenv` 读启动环境(M2),用 `lsof -a -p <pid> -d cwd -Fn` 读 cwd;
- win 用助手动词 `proc-env` 读 PEB 里的环境和当前目录(W2;读一次 PEB 两样都有)。
- 结果按 pid 加启动时间缓存,进程活着期间只读一次:忙的 agent 只花一次读取,不是每个连接一次(单一助手通道)。

**P8 安装目录包装**(通用;描述符 `{ kind: 'wrapper', command, binDir: <loc>, certVar, layout: 'native-binary' }`):

- **前提**(`install` 时检查;不满足就跳过这个载体,`status` 报 `not-users-file` 并写明原因):目标是一个原生可执行文件(Mach-O / PE,不是脚本,也不是 npm 的 `.cmd` / `.ps1` / sh 启动脚本),在本用户拥有、不在包管理器目录里的文件夹里,并且 agent 自己的更新按文件名换掉这个文件。最后这一条由描述符的 `layout: 'native-binary'` 声明;Kimi 的是实测的(M4、W3)。启动脚本会被包管理器重写的命令行,用 `plugin`,否则不支持。
- **install**:
  - 解析出 `<binDir>/<command>[.exe]`;
  - 它已经是 asight 的包装(哈希一致)时什么都不做;
  - 在同一卷内改名,把真程序挪到 `<binDir>/.asight-real/<同名>`,文件名不变,Kimi 的自动更新于是落在它上面(M4、W3);
  - 写包装,记下两个 sha256。
- **各系统的包装**:
  - mac:由 `arch/darwin/wrapper.dash.tmpl` 生成的 `/bin/dash` 脚本(M4:用 dash,不用 `/bin/sh`);
  - win:`install` 时用系统自带的 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 从 `arch/win32/wrapper.cs` 编译出的小程序,与 W3 的做法相同。
  - Smart App Control 开着时不放包装,`status` 报 `smart-app-control`。
- **运行时**:
  - 没有开关文件:只在 `certVar` 没设时设上它,然后用一字不差的参数、标准输入输出和退出码执行真程序。
  - 有开关文件:再设 `ASIGHT_PRIOR_PROXY`(agent `proxy.env` 里第一个设了的值,没有就是 `none`),并把描述符给的代理变量名指向门。
- **撤销**:包装的哈希还是 asight 的,才放回真程序;不是时只删 `.asight-real`。
- **status**:哈希变了报 `entry-changed`,命令是 `asight install`。

**P9 插件模板**按**宿主的插件接口**分,不按 harness 分,放在 `src/collector/harness/templates/`(和描述符放在一起的数据,在 `core/` 之外):

- `opencode-plugin`(代理入口,阶段 `on`):
  - 导入时设 `ASIGHT_PRIOR_PROXY`(没有就是 `none`),两种大小写都指向写死的门地址;
  - 还对非回环的 https 地址包一层 fetch:TUI 和 VS Code 形态要这一层;
  - 同时导出 1.x 的具名导出和 v2 的默认导出,不导出 `effect`,导入即生效(R3-M7、R3-W4)。
- `cordis-plugin`(DeepSeek,阶段 `install`;由 `cordis.patch.yml` 里一行加载):
  - 在进程里加 asight 根;
  - 包住 dsh 自己的 undici dispatcher。每个请求按 `install` 时写死的**绝对路径**读一次开关文件:
    - 文件在:用 ProxyAgent 交给门,CONNECT 带 `X-Asight-Upstream`,值是 dsh 对这个主机本来会用的代理,dsh 本来直连时是 `none`;
    - 文件不在:用 dsh 原来的 dispatcher。
  - 加不上根时从不交给门(§3 ⑦;R3-M6、R3-W3、W8)。

**钩子契约**(管 P8 和 P9;Linux 的插件规则见 [4.6](4.6-process-collector.md)):

- 钩子可以给自己的进程加 asight 根;
- 可以把自己的连接交给门,并记下原来的值;
- MUST NOT 读或改请求、响应的字节,MUST NOT 连门以外的任何地方,MUST NOT 写 agent 配置;
- 没有开关文件、或它的插件文件不在时,除了加 asight 根(或在证书变量没设时设上它),表现与没有 asight 相同。

**P10 PAC**(`core/proxymode/pac.mjs`):

- 守护进程在 PAC 这一组门的端口上(`auth:false`)应答 `GET /asight.pac`。
- 内容:
  - 回环地址和用户的绕过列表 → `DIRECT`;
  - 其余 → `PROXY <门>; <本来的走法>`,本来的走法是用户的固定系统代理,没有就是 `DIRECT`;
  - `off` 之后只剩 `<本来的走法>`。
- PAC 的门不带凭据,所以接受连接时只放行对端进程属于本用户的(mac 按 uid,win 按 SID,与 D51 认进程读的是同一组事实);别的拒绝并记录。
- 下面四种情况不写入口(`not-routed`,§3 ③):
  - 系统代理本身是 PAC;
  - 用户当前生效的条目里已经有自己的出口代理或 PAC;
  - 机器上有托管配置(一个 `{policy}` 拦截项,§2.3);
  - 本来的走法要凭据(沿用现在的 `entryGate`:只有地址的门不能把用户代理的凭据借出去)。

**P11 代理模式的解密判定**(`core/proxymode/verdict.mjs`)。下面各条都成立才解密;少一条就只转发,并记原因:

1. D51 按名字认出了进程,而且这个形态在本系统上 `verified`(否则 `not-verified`);
2. 主机不在形态的 `forwardOnlyHosts` 里(否则 `not-verified`,带上主机);
3. 进程的启动晚于这个形态的载体的 `installed_at`(否则 `config-after-start`);
4. 形态的信任点名了来源时:按 **agent 自己的先后**(§2.3 `trusts`)走这些来源,第一个设了的来源指向的文件里有 asight 根(`required` 的来源没设时 `var-missing`;文件里没有根时 `ca-not-in-file`);
5. 签发器在(否则 `cert-intermediate-unavailable`);
6. 没有拦截项命中。

D51④ 的 `trust-rejected` 仍是兜底。

**P12 持有者与排空**(`core/proxymode/holders.mjs`;判定用的是`src/off/proc.mjs`、`src/off/signature.mjs` 和 `undo.mjs` 的 `mayHaveRead`):

- **持有者**是 `off` 之后还可能用门的活进程(pid 加启动时间):
  - harness h 的进程(按 D51 认),在 h 的 on 期间 `[on_at, off_at)` 启动的;入口会被运行中的 agent 重读的(入口数据 `rereads: true`:Z-Code 的下一个会话、OpenCode v2 的后台服务),`off_at` 时还活着的 h 的任何进程;
  - 门在 h 的 on 期间认出过的任何进程(接受连接时记下 pid 加启动时间);
  - Claude Desktop 按同一条算:取 PAC 就是读入口。
  - 不算持有者:每个请求都重读开关文件的钩子(`cordis-plugin`)。`off` 后它的下一个请求走 dsh 原来的路,开着的连接按 [1.6](1.6-cli.md) §1.3 逐条排空。
- 是否活着按进程表轮询判定(排空期间每 10 秒一次),从不按开着的连接数:闲着的持有者也算。
- `off` 之后,只有没有 harness 开着、没有持有者活着、也没有开着的连接时,守护进程才退出。
- 清单的 `liveness.<h>` 记 `identity`、`rereads`、`on_at`、`off_at`,守护进程不在时命令行用进程表算出同一张表(可独立运行)。
- 用到它的地方:`off` 的回执和 `status`(「还剩 N 个」,带 pid)、[1.6](1.6-cli.md) §1.4 的排空、`uninstall` 的拒绝。

**P13 清单 v3**(已有,扩展):

- **阶段**:`install` | `on`。
- **种类**:
  - `json-key`;
  - `text`,格式 `dotenv-block`、`line`、`pem-block`(新);
  - `owned-file`,角色 `bundle`、`plugin`、`wrapper`(新)、`switch`(新)、`config-entry`(新)、`asight-ca`;
  - `json-array-item`,现在有真正的撤销;
  - `system-root`;
  - `root-key`(新;存保管句柄和 fp256,最后撤)。
- **`liveness.<h>`**:保留 `identity` 和 `rereads`,新增 `on_at` 和 `off_at`(P12);mac / win 上去掉 `until` / `until_environ`(合并包的持有者)。
- **删掉**:`login-env`、`NO_UNDO_YET`、`classifyV2`;`optin-*` 各种类;`legacy-*` 各种类。
- **改文件只走忠实编辑这一条路**:文本编解码(LF / CRLF / BOM,非 UTF-8 拒绝)、JSONC / BOM、带重试的持久改名、环境变量名族。

### 2.3 描述符(每个 harness 一个文件,所有系统共用)

Linux 保留它的字段(`trust`、`inject`、`layers`)。代理模式只读 `proxyMode` 和共用字段。没有按系统分开的覆盖文件;系统不同的路径用 `_common.mjs` 的 `perOs({ darwin, win32 })` 写成数据。

**`proxyMode` 里没有函数。** 描述符指向的每个地方都是三种封闭的数据之一,由 core 的一个读取器(`core/proxymode/sources.mjs`)读,托管策略再加每个系统一个读取器。所以新 harness 只是数据,第八个 harness 的守卫(CM27)才证明得了东西:夹具里夹带不进机制。

```js
// <loc>  一个路径:{ base: 'home' | 'appSupport' | 'localAppData' | 'cwd' | 'abs', path, env?: '<OVERRIDE_VAR>', glob? }
//        `env`:能改掉这个目录的变量(CLAUDE_CONFIG_DIR、CODEX_HOME、HERMES_HOME),由命令行在 install / on 时
//        用用户的环境解析,记进清单;`cwd`:agent 进程的 cwd(proc.cwdOf);
//        系统不同时包在 perOs({ darwin, win32 }) 里。
// <src>  一个设置:{ env: NAME }
//               | { file: <loc>, format: 'json' | 'jsonc' | 'yaml' | 'dotenv', keys: [...] }   // keys 里的 '*' 匹配任何键
//               | { policy: { darwin: { domain, key }, win32: { key, value } } }               // 托管配置(plist / 注册表)
// <cond> { src: <src>, equals?: value }   // 没有 `equals` 时 = 「设了」

// src/collector/harness/<name>.mjs(形状;值只在代码里)
export default {
  name, runtime,
  processes,            // D51 的进程名:唯一来源;逐格记录只是证据(0.1 §2)
  hosts,                // 这个 harness 的 API 主机(宿主型形态的解密集从它起算,§3 ⑫)
  proxy: {              // 已有(1.6 §9.7),照用:
    env,                //   agent 自己的先后 → 上游第 3 步、钩子的原值
    systemProxy,        //   { http, ws } → 上游第 4 步(跟系统代理的)
    restart,            //   「何时生效」的 status 文字按下面的入口写
    /* files, schemes, unsupported, branches, measured:不变 */ },
  proxyMode: {
    forms: [ { id, os: ['darwin','win32'], route: '<routeId>', cert: '<certId>' | 'root', trust: '<trustId>' | 'root',
               present: [ <loc> | { command } ],                 // 其中任何一个存在 = 这个形态装着;只为装着的形态写入口
               verified: { darwin: true | {reason}, win32: true | {reason} },   // D51④:实验室验过信任
               hostTree?: true,                                  // 进程里还跑着别人(VS Code):只解密 `hosts`;回执和 status 写明所有扩展都经门(harness-note)
               forwardOnlyHosts?: [host…] } ],                   // 实验室格 PASS 之前只转发的主机(Claude Desktop 自己的主机)
    routes: { <routeId>: { kind: 'json-key' | 'dotenv-block' | 'plugin-file' | 'switch-file',
                           file?: <loc>, dir?: <loc>, format?, proxyKeys?, noProxyKeys?, template?,
                           value?: 'door-url' | 'pac-url', arrayItems?: [ { keys, value } ],
                           select?: { dir: <loc>, meta, idKey, createIfNone: true },
                           absent: 'create' | 'not-routed',      // 目标文件不在时
                           rereads?: true,                        // 运行中的 agent 会重读它(P12 持有者)
                           auth?: false, takesEffect: '<status 里「何时生效」的中文>' } },   // 用同一个 routeId 的形态共用一扇门(入口组)
    certs:  { <certId>: { kind: 'config-key', file: <loc>, format, keys, semantics: 'replace' | 'add', when?: <cond> }
                      | { kind: 'wrapper', command, binDir: <loc>, certVar, layout: 'native-binary' }
                      | { kind: 'plugin', template: '<宿主的插件接口>', dir: <loc>, loader: { file: <loc>, format, keys } } },
    trusts: { <trustId>: { base: 'os' | 'node',                  // agent 默认的根,门验上游时用(§3 ⑭)
                           sources: [ { from: <src>, semantics: 'add' | 'replace', required?: true } ],   // 按 agent 自己的先后列
                           when?: <cond> } },
    userCertFiles: [ <src> ],                                    // 规则 U:可能已经指向用户自己文件的设置
    blockers:      [ { at: <src>, when?: <cond> } ],             // 设了就不写这个形态的入口;status 点名 `at`
    effects?:      [ { id, paths: [<loc>], when: '<中文>' } ],    // off 之后还留着的已知影响(OpenCode 1.x 的 npm 残留)
  },
}
```

**校验**(`harness/index.mjs`,加载时就拒绝,新 harness 错了当场报出):

- 每个种类都来自上面的封闭集合;`proxyMode` 里没有函数;
- 每个 `form.route`、`form.cert`、`form.trust` 都找得到;每个形态的 `present` 不为空;
- 环境变量式的代理名两种大小写都有;
- `switch-file` 入口要求有一个形态的证书是 `wrapper` 或 `plugin`(读开关文件的钩子);
- `value: 'pac-url'` 的入口必须是 `auth:false`;
- 每个 `verified` 的值是 `true`,或者带原因;
- 每个**写入目标**(入口文件、`config-key` 的文件、包装的 `binDir`、插件目录、加载行所在的文件)都在用户的 home 或 agent 的安装目录下;只读的地方(`blockers`、`policy`、`/Library` 或 `ProgramData` 下的托管设置)可以在任何地方。

### 2.4 加一个 harness

1. 写 `processes`(D51 的名字)、`forms` 和每个形态的 `present`,依据实验室的普查。
2. **入口**:agent 从它自己拥有的文件读代理时,用第 1 类:`json-key`(设置需要时带 `arrayItems` / `select`)、`dotenv-block`;有插件目录时用 `plugin-file`。否则用第 2 类 `switch-file`,再配一个钩子载体。
3. **证书**:实验室表明根够得到这个 agent 时,用 `root`。否则依次选:
   - `config-key`(`replace` → 合并包,`add` → `asight-ca.pem`);
   - 不行就 `wrapper`(命令行是用户自己文件夹里的一个原生可执行文件,agent 的更新按文件名换掉它,即 P8 的前提);
   - 再不行就 `plugin`(宿主的插件接口已经有模板)。
4. **信任**:写 `trusts`(基底,以及哪些设置能遮住或带上信任,**按 agent 自己的先后**),再写 `userCertFiles`、`blockers`、`effects`。
5. 写 `proxy.env` 的先后、`systemProxy` 和 `takesEffect` 的文字。
6. **实验室**:每个形态一行 cells;跑哪些由描述符的形态 × 系统生成。还没有流程脚本的形态,在矩阵里记 UNT 并带指针,直到有了为止。

不写机制代码。只有 P1–P13 都够不到这个 agent 时才允许加新原语,PR 要写明现有的为什么加宽不了(0.1 §6 第 15 条)。守卫 CM27。

### 2.5 不做

改系统代理、接管整机流量、写登录环境或全系统的 `HTTPS_PROXY` 一类代理变量(D43)。
