# asight · RFC 1.11 — 设置(存储 · 价格 · 外观)

> **服务意图(A2)**:给 D40⑥(每个 agent 的每一类流量存全部还是只记日志,各占多少盘)和 D14(估价 = 用量 × 本地单价)一个看板入口;外观页给 [1.5](1.5-states-aesthetics.md) 的明暗双态一个开关。它们不直接回答意图 ①(看懂 agent 行为)或 ②(上下文与缓存工程),而是两者的支撑:存下了什么、钱按什么价算,决定了回放与总览里看到的东西有多全、估价有多准。
> **受众**:人(想知道 asight 占了多少盘、要不要少存一些;想知道某个估价按什么单价算、哪些模型没有单价;想切明暗);agent(据此实现 `src/web/v2/settings/**`,只读 `classes`、`segments`、`pricing` 与 `overview`(`api.get(<name>)`),只写 `POST /control/classes`(写的界面归 PR 5 的 C9),不碰 harness 分支)。
> **前置**:外壳、路由、页头规则、弹出层约定、agent 标识与图标 = [1.2](1.2-shell-layout.md);看板词表、标记、状态矩阵、数据规则、主题 token = [1.5](1.5-states-aesthetics.md);逐条请求的保存标注 = [2.6](2.6-detail-panel.md) §C;端点 `GET /api/classes`、`POST /control/classes`、`GET /api/pricing` 与新增的 `overview` = [4.4](4.4-server.md);`classes` 与 `overview` 的具名查询 = [3.5](3.5-query-layer.md);价格匹配规则 `priceMatch()` = [2.2](2.2-call-turn-card.md);决策 D14、D26、D40(0.0)。`asight classes` 的命令形状 = [1.6](1.6-cli.md)。

## Goal

设置区有三页,各回答一个问题:

- **存储**(`#/settings/storage`):「asight 占了多少盘、每天长多少?每个 agent 的每一类流量存全部还是只记日志,各占多少?」——并能在看板上改。
- **价格**(`#/settings/prices`):「估价按什么单价算?哪些模型没有单价?」——只读;补单价靠编辑单价文件,页面给出可以直接粘贴的一行。
- **外观**(`#/settings/appearance`):「跟随系统、亮,还是暗?」

保存设置的方向(D40⑥):每个 harness 保存什么按类可调——哪些类存全部、哪些类只记日志;界面同时显示各类占的大小,人才调得动。整个看板的两条要求也管本单元:统计句不进标题和小标题(会干扰人),界面上的每个字都要接得上真实数据(接不上线的文字与不干净的尾巴一律砍掉)。所以本单元每个元素都写明来源;总量、每天增量这些数放在卡片里,不放在页头。

**D40⑥ 的看板入口在此改为「设置 · 存储」**(D18c 修订 D40⑥):原来是 [2.6](2.6-detail-panel.md) §D 的 `⚙ session-less` 组里的「保存什么」;级别词仍是 D40⑥ 的「全部 / 只记日志」;写仍经 D26 opt-in 控制面的 `POST /control/classes`,不经采集守护进程的 socket。2.6 §D 改为一行指向本单元。

## 前置定义(Definitions)

- **设置区**:侧栏的「设置」一项,下有三个子页:存储 · 价格 · 外观([1.2](1.2-shell-layout.md) §侧栏)。
- **保存级别**:D40⑥ 的两级。`full` 界面上叫「全部」(请求与响应的体逐字存,每个方向 64 MiB 上限);`log` 叫「只记日志」(存元数据与请求 / 响应头,不存体,只记体的字节数)。
- **一格**:保存什么表里的一个 (agent, 流量类别) 交点:它的级别与它在所选时间窗里占的存储字节。
- **流量类别**:D40 的七类闭集 `llm` · `token-count` · `session-sync` · `telemetry` · `files` · `account` · `other`,界面词 模型调用 · token 计数 · 会话同步 · 遥测 · 文件 · 账户 · 其他(`core/classes.mjs : CLASS_NAME`)。
- **截至时刻(`as_of`)**:段索引里最新一条调用的时间。按类的数字只算到这里。
- **技术细节**:默认收起的一块等宽键值区(`core/ui.mjs : techDetails()`,[1.5](1.5-states-aesthetics.md));路径、原因码、服务端原文、命令都放这里。
- **单价表**:`pricing` 文档的 `models[]`,每项 `model`(模型名包含的字,即家族键,如 `opus`)与四个数 `input` · `output` · `cache_write` · `cache_read`,单位是 `unit`(美元 / 百万 token;`src/query/named/pricing.mjs`;依据:[1.6](1.6-cli.md) C.5 与 [1.5](1.5-states-aesthetics.md) §数据规则)。

## Plan(选定方案 + 取舍)

**选定**:设置区三个子页,各一屏。存储页两张卡:「磁盘」(总量、每天增量、读不全的文件、「磁盘上的文件」技术细节、指向采集页的一行)和「保存什么」(**七类一行,一行一个级别**;每个 harness 的拆解在弹出层「看这类流量 ›」后面的流量表里——级别按类别存,不按 harness × 类别,D60③)。级别在设置文件读得出时画成分段控件;读不出时写成文字,改法(`asight classes set <类别> <full|log>`)放技术细节。把 `llm` 或 `token-count` 改成「只记日志」前先确认。价格页两张卡:「单价」(只读表)和「没有单价的模型」(出自 `overview`,每个模型一行,带会话数和「复制模板」)。外观页一个三选一的分段控件。

**备选(未选)**:
1. 「保存什么」留在会话选择器的 `⚙ session-less` 组里,切入 `ctrlmode` 栅格(2.6 §D 原样)——control mode 整体退役(C-10),会话之外的东西各进自己的侧栏区;保存设置属于「设置」。
2. 级别词改为「存内容 / 不存内容」(重构文档的提议)——`log` 级仍存头与元数据,会被读成隐私开关;沿用 D40⑥ 的「全部 / 只记日志」(N-13)。
3. 页头写「asight 共占用 317 MB,每天约增加 5.9 MB」「1 个模型没有单价」(视觉设计稿的做法)——否决:统计不进标题和小标题;这些数进卡片。
4. 保留 agent × 类别的二维格子(原型的做法)——级别按类别存(D60③),56 个控件里 49 个会写同一个值;表收成七行,每个 agent 的数在流量表里看得到。
5. 表上方再列一张「占得最多的(每天)」——数和表里的一样,只是又排了一次序,还多出一处能改级别的地方;砍掉。
6. 在页面里改单价——没有写单价的端点;加一个就要扩 D26 列举的控制端点,要过 RFC(Extensions)。改单价 = 编辑单价文件,页面给可粘贴的一行。
7. 改任何级别都直接生效,不确认(2.6 §D 原样)——把模型调用改成只记日志,之后的回放就没有上下文,点错代价大;只对 `llm`、`token-count` 两类改成只记日志时先确认(N-12)。

### 保存什么卡

**一个级别只属于一个类别(D60③)**:级别按类别存,不按 harness × 类别;所以表是**七行七个控件**,没有二维格子。每个 harness 各自的条数与字节在弹出层「看这类流量 ›」后面的流量表里([1.10](1.10-traffic.md),它按 (agent, host) 给每类计数),不是可改的轴(依据:[1.6](1.6-cli.md) C.5 的 `classes` 没有按 harness 的计数与 [1.5](1.5-states-aesthetics.md) §数据规则)。

#### 表的行与列

- **行** = `/api/classes.classes[]` 的七类,按所选时间窗存下的字节从大到小排;行头是类别词(`CLASS_NAME`,`token-count` 写「token 计数」)。不在词表里的类(服务端以后加的)照原样显示 id,[1.5](1.5-states-aesthetics.md) 的标签完整性测试会先红。
- **列**:类别 · 级别 · 规则 · 次数 · 存下 · ⓘ。
- **规则列**(只读):这一类的 host 正则,有 path 正则时接在后面(来源 `classes[].rule{host, path}`);等宽显示,太长时截断并带 `title`。改规则不在本页(命令行的 `asight classes`,[1.6](1.6-cli.md));本页只改级别。
- **合计行**:前端对所选时间窗的 `classes[].counts[<窗>]` 求和(C.5 的 `classes` 没有单独的合计字段;一个数不存两份)。

#### 一行

| 部分 | 显示 | 来源 | 没有 / 读不到时 |
|---|---|---|---|
| 级别 | 设置文件读得出:分段控件「全部 \| 只记日志」,当前级别是选中项;否则文字「全部」或「只记日志」 | `classes[].keep`;没有这一项 = 默认 `full` | — |
| 次数 · 存下 | 「2 140 次 · 88 MB」,数字本身是信息按钮,打开这一行的弹出层 | `classes[].counts.<h24\|d7\|all>.{calls, bytes}`(依据:[1.6](1.6-cli.md) C.5 与 [1.5](1.5-states-aesthetics.md) §数据规则) | 这个窗里确实没有调用 → 「0」 |
| 改动中 | 「正在改…」,控件 `aria-busy="true"`,这期间的点击不发请求(不用 `disabled`) | 本页状态 | — |
| 回执 | 见 §改级别 | `POST /control/classes` 的回答 | — |

`classes[].keep` 说的是**现在的设置**;数字是**已经存下的**,可能部分按旧级别存;C.5 没有按级别分的条数,所以页面不把两者拆开写。改动只影响之后开始的调用(表注行常驻这句)。

#### 一行的弹出层

点、聚焦或悬停数字打开([1.2](1.2-shell-layout.md) §弹出层;里面只有文字和链接)。一行一个事实,值为 0 或没有的不写:

1. 「存下 Z(压缩保存前的大小)」。
2. 「看这类流量 ›」→ `#/traffic?class=<c>&window=<window>`([1.10](1.10-traffic.md));按 agent 的拆解就在那张表里(它按 (agent, host) 给每类计数),本弹出层不重复一份。

线上的请求 / 响应字节、按类的压缩保存后估计、按级别分的已存条数都**不画**:C.5 的 `classes` 没有这几个字段(§影响面「C.5 还没有字段的几件事」);压缩保存比只有全局一个,写在「磁盘上的文件」(依据:[1.5](1.5-states-aesthetics.md) §数据规则)。

#### 改级别

- **能改的条件**:`classes` 的 `errors[]` 里没有指向整个设置文件的条目(§设置文件有问题;依据:[1.6](1.6-cli.md) C.5 与 [1.5](1.5-states-aesthetics.md) §数据规则),且 `GET /control/status` 没有说这台机器上控制面没挂(守护进程以 root 跑,[4.4](4.4-server.md) §控制面)。**MUST**:不满足时不画任何级别控件,也不画灰掉的控件;级别写成文字,改法放技术细节。守卫:`test/web-v2/settings.test.mjs`;状态矩阵 K-25 归 [1.5](1.5-states-aesthetics.md)。
- **怎么发**:点分段控件的另一项 → `POST /control/classes` → `src/classes/table.mjs : edit()`,带看板口令([4.4](4.4-server.md) §控制面),体 `{kind:'set', class, keep}`([4.4](4.4-server.md) 的端点表);写的界面归 PR 5 的 C9。按 [4.4](4.4-server.md) 的写入协议,一次改动 = 一个不带 `confirm` 的计划请求 + 一个带 `plan_id` 的确认请求;点分段控件就是操作者对这份只改这一类级别的计划的确认,只有 `llm` / `token-count` 改成只记日志时先弹确认框;取消或 Esc 不发确认请求。计划过期就重新给计划,不照旧写(不变式 1 · D30)。一次只改一类(依据:[4.4](4.4-server.md) 计划—确认协议与不变式 1)。
- **先确认**:只在把 `llm` 或 `token-count` 改成「只记日志」时弹确认框(`core/ui.mjs : confirmDialog()`)。标题「改成只记日志?」;正文先说后果:
  - `llm`:「之后的模型调用只记日志:不存请求和回复的内容,这些调用不进回放。已经存下的不受影响。」
  - `token-count`:「之后的 token 计数只记日志:不存请求和回复的内容,回放里只剩次数,看不到数出的 token 数。已经存下的不受影响。」
  - 按钮「取消」与「改成只记日志」;**初始焦点在「取消」**;Esc 等于取消;取消不发确认请求,级别不变。改回「全部」、改别的类别,都不确认。
- **回执**,写在那一行里,下一次读完 `/api/classes` 后消失:

| 回答 | 回执 | 技术细节 |
|---|---|---|
| 200,`before.keep` ≠ `after.keep` | 「全部 → 只记日志 · 之后开始的调用生效」(从 C.2 `classes` 回执 `{class, before, after, changed, undo}` 的 `before.keep` / `after.keep` 取;`before` 为空 = `full`) | — |
| 200,`before.keep` === `after.keep` | 「本来就是只记日志」 | — |
| 409 计划过期 | 「机器上的设置变了,这是新的改动计划」+ 新计划 | 服务端的 `error` 原文 |
| 403 | 不写回执:按 [1.5](1.5-states-aesthetics.md) K-30,整页只剩「用 `asight board` 打开看板」那一句 | —(依据:[1.5](1.5-states-aesthetics.md) §影响面:各屏复用 1.5 的状态分支) |
| 400 | 「没改成」 | 服务端的 `error` 原文 |
| 404 / 405 | 「看板现在以只读方式运行,没改」 | HTTP 状态 |
| 连不上 | 「连不上 asight 服务,没改 · 重试」 | 错误原文 |

每个回答之后都重读一次 `/api/classes`,显示服务端现在的级别,不显示页面猜的级别。

#### 设置文件有问题

来源 `/api/classes` 的 `file`(设置文件路径)与 `errors[]`(读不出、解析不了、某一格写错了都进这里,`where` 是 `classes.json`,带闭集 `code` 与 `reason`;指向整个设置文件的那条另带 `fatal: true`,即 `src/classes/table.mjs : readTable()` 自己给的标记,前端不另抄一份码表,D38;C.5 的 `classes` 没有另一个 `settings` 子文档;`fatal` 依据:D38 闭集码 + [0.1](0.1-engineering-rules.md) §2 一个事实只写一处):

- `errors[]` 里有指向整个设置文件的一条(读不出或解析不了)→ 表注行「保存设置读不出:修好之前,每次调用都按「全部」保存」;不画级别控件;技术细节:`file`、每条 `reason` 原文、「修好或删掉这个文件后刷新」。(与总览页事项 O7、采集页的同类条件同一句话,[1.7](1.7-overview-dashboard.md) · [1.9](1.9-capture-page.md)。)
- 只有指向单个类别的条目 → 表注行「保存设置里有 N 处写错了:这几处按「全部」保存」;控件照画;技术细节逐条列 `reason` 原文。前端不解析这些串。
- `file` 指的文件不存在(`errors[]` 里没有关于它的条目,每类的 `keep` 都是内置值)→ 不写问题;技术细节写「还没有设置文件:每一类都按「全部」保存」。

#### 最近的修改

保存什么卡里一行「最近的修改:<类别词> <级别> · <来源词> · <相对时间>」(来源词按 `cli` / `board` / `file`)(悬停给绝对时间),来源 `/api/classes` 的 `last_change`。没有 → 「还没有修改」。**完整的修改日志不在看板上**:它在 `~/.asight/logs/classes.ndjson`,用 `asight classes`([1.6](1.6-cli.md) §4.2)看——C.5 的 `classes` 只给最近一条,为一个收起的小列表再开一份历史字段不值(D24 · 代码从少)。

#### 表注行

保存什么卡的表注行(都在卡里,不在页头),按出现的条件:

| 文字 | 来源 | 何时 |
|---|---|---|
| 「改动只影响之后开始的调用;已存的数据不删」 | 固定文字(与报告的 `note` 同义;不变式 2) | 一直在 |
| 「按类的数字截至 13:58」 | `/api/classes.as_of` | 有数时 |
| 「还没有调用」 | `as_of === null` | 段索引是空的 |

| 「按类的数字读不到」 | `/api/classes` 的 `errors[]` 里有读不出的段(D38) | 读不全时 |
| 「这台机器上改不了级别,这里只显示」 | `/control/status` 回 `root:true` | 守护进程以 root 跑([4.4](4.4-server.md) §控制面) |

## 保真边界(不变式 4)

本页的数不全是测出来的,MUST 就地标明:

1. **按类的数字截至 `as_of`,不是实时**:表注行「按类的数字截至 T」;时间窗的起点晚于 `as_of` 时写「—」与原因,不写 0。守卫:`test/web-v2/settings.test.mjs`。
2. **没有库、库太旧、库读不出 ≠ 0**:不写任何数,表注行写原因(K-24 的词),命令在技术细节。守卫:`test/web-v2/settings.test.mjs`(原「without an analytics store every number says…」改写)。
3. **没记大小的调用不算 0**:C.5 的 `counts` 只有 `calls` 与 `bytes`,没记大小的调用数没有来源(§影响面 的推迟);落定之前不写「起」,缺的数写「—」,不写 0。守卫:`test/web-v2/settings.test.mjs`。
4. **封存比是估计**:只出现在「磁盘上的文件」的压缩保存比一段,带「估计」与它的算法说明(全局一个比值)。守卫:同上(原「the numbers follow the window, and the sealed size is marked as an estimate」改写)。
7. **「每天约增加」是 24 小时存下的记录行字节**,带 ≈;库太旧时写「—」与原因。守卫:`test/web-v2/settings.test.mjs`。
8. **估价是本地估算**:价格页表注行「…是本地估算,不是账单」;匹配规则与写缓存只有一个价写在技术细节。守卫:`test/web-v2/settings.test.mjs`。
9. **单价文件里写坏的行会被静默忽略**:服务端不报告(`loadPricing()`),页面无从得知——记为已知缺口(1.11-03,Extensions),不在页面上说「单价文件没问题」之类的话。守卫:收尾审查。
10. **控制面不隔离同机别的用户**(D26③):页面不写「只有你能改」「已隔离」之类的话。守卫:收尾审查。

## Edge cases

- **页面开着时控制面不再挂**(守护进程重启后以 root 跑,[4.4](4.4-server.md) §控制面):下一次改动回 405,回执「看板现在以只读方式运行,没改」,随后重读,控件消失。
- **页面开着时有人用命令行改了同一格**:页面显示的是上一次读到的级别;点切换时服务端照常改,回执里的「旧 → 新」取自服务端回执的 `before.keep` / `after.keep`,重读后显示真值。
- **认不出 agent 的调用**:在流量表里记作未识别的 agent;级别按类别算,与它是哪个 agent 无关。
- **一格的调用数为 0、库在**:写「0」。这是真的 0,不是缺失。
- **24 小时里没有调用,库也是新的**:`as_of` 早于 24 小时前时页面分不清这两种情况,所以写「—」与那句说明,而不是 0。
- **没有可读的封存文件**:「磁盘上的文件」写「封存比:没有可读的封存文件」。
- **模型名为空的调用**:「没有模型名」一行,不给模板。
- **单价文件整份解析不了**:服务端静默用默认值,`source` 是 `'default'`,页面会说「用的是 asight 自带的默认单价」——这句仍然是真的(用的确实是默认),但看不出文件坏了(1.11-03,Extensions)。
- **有的服务商没有写缓存的概念**:单价行仍要四个数;写缓存填什么都不影响这类调用的估价(它们的 `create` 为 null,`costOf()` 按 0 乘)。
- **剪贴板不可用**:模板显示在选中的等宽框里。
- **`localStorage` 不可用**(无痕窗口、被禁):外观的选择对当前页面生效,刷新后回到跟随系统,页面就地说明。
- **很窄的窗口**:表格框横向滚动,agent 列固定;页面本身不横向滚动([1.2](1.2-shell-layout.md) §窄屏)。

## Risk / 回滚

- 三页都是现有端点(加 `overview`)上的纯函数加一个 `POST`;出问题可以单独退回上一个绿点,不碰服务端数据。改级别的写路径与守卫(4.4 #16)不变。
- 确认框多一步点击;只对两类改成只记日志时出现,改回全部不确认。若后续决定不要确认,删掉 `needsConfirm()` 的调用即可,其余不动。
- 每行只留一组数,按 agent 的数要跳到流量表看;表格换来在 1440 px 下放得下。
- 借 `overview` 的原因码:`overview` 与 `classes` 读同一批段索引、用同一套版本检查,两者的结论一致;若将来分开演化,改为给 `/api/classes` 加原因码(Extensions)。
- 本机别的系统用户的进程也能改这里的级别(D26③:环回不分系统账号)。本单元不加隔离,也不声称已隔离。

## Extensions

- **在页面里改单价**:需要一个写单价文件的控制端点,扩 D26 列举的控制面端点,要过 RFC;改价同样只影响估价,不碰存储。
- **`/api/pricing` 回它读的路径(文件不存在时也回)与写坏的行**:页面就能说「单价文件放在 <路径>」与「第 N 行没被采用:<原因>」(1.11-03;4.4 跟进)。
- **C.5 `classes` 的缺字段**:§影响面「C.5 还没有字段的几件事」逐项加进 C.5 之后,本页再画对应的数;动手前先走 grep-spec 自对照。
- **按类删已存数据**:[4.6](4.6-process-collector.md) OPEN;做成之前看板不提供。
- **按模型筛会话**:会话元数据带上用到的模型之后,「没有单价的模型」的每一行可以链到会话库。
- **按缓存时长分价**:服务端给出规范的 5 分钟 / 1 小时写缓存拆分后,单价表加一列。
- **按服务商定价**:单价表按 `wire.vendor` 分(D37 的已记缺口)。
