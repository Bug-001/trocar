# asight · RFC 4.1 — 可插拔采集源

> **服务意图(A2)**:跨切「适配层通用」(AC-3)的**最上游**——采集源是「拿到 bytes」的那一端,把三家真实流量喂进 ①(逐字上下文/回复供回放)与 ②(真实 usage 供 cache 叠加)。也是 [1.1](1.1-product-definition.md) 六要素#5「委派代价」的承载点:把采集委派给 MITM/relay,须配 onboard + 每源一个「测试」兜底。
> **受众**:人(核对四问——**是否真在抓 · 抓得对 · 凭据没漏 · 没弱化全机 TLS**)+ agent(据此实现采集源 + onboard 脚本)。
> **前置**:输出 = **统一原始信封**,交 [3.1](3.1-adapter-contract.md) adapter 解释、[4.2](4.2-storage-etl.md) 存储;身份信号见 [3.4](3.4-session-identity.md);采集安全的**单一权威 = 本文件 §采集安全**。与 adapter **正交**:源管「怎么拿到 bytes」,adapter 管「bytes 什么意思」。

## Goal
定义一个**可插拔采集源接口**:无论用哪种机制拿到字节(MITM / base_url 反代 / relay-tee),都向下吐**同一个统一原始信封**,使 asight 其余层对「用哪种源、抓的哪个 harness」**无感**。为每个 harness 选**最便宜、最不侵入**的源(承 [00-overview](00-overview.md) D4)。**观测唯一**:采集源永不 originate 请求、永不改写流量、永不用被测程序 token 发起调用(不变式 1([0.0](0.0-overview.md) §核心不变式),**必拒违反**)。

## Definitions
- **采集源(capture source)**:拿到字节的机制 + 把它写成统一信封的模块。三机制:MITM / base_url 反代 / relay-tee。
- **统一原始信封(envelope)**:一次上游交互的归一记录形状 `{ts, endpoint, method, req_headers(脱敏), req_body, resp}`(承 [3.1](3.1-adapter-contract.md));三源共用,只在 `capture` 标签上不同。
- **采集目标 host(capture-target host)**:明确列入、允许 TLS-解密的 host(demo:`api.anthropic.com`,env `ATRACE_TARGET_HOST`)。其余一律盲隧道。
- **采集点(steer point)**:把被测流量精准引到采集源的地方——Clash 规则 / `base_url` / relay 配置,**非整机系统代理**。

## Plan(选定方案 + 取舍)

**选定**:**可插拔多源,每 harness 选最便宜源**;机制随 harness 走,信封统一。
- **CC-Desktop → 只能 MITM**:Desktop 内嵌 claude-code **强制覆写 `ANTHROPIC_BASE_URL`、且不认 `~/.claude/settings.json` env**(其 `HTTPS_PROXY` 来自 macOS 系统代理 = VPN),故 base_url 反代抓不到 → 在 **Clash 路由层**只把「Desktop 的 claude-code → api.anthropic.com」精准 steer 进 MITM。
- **CC-CLI / DeepSeek-CLI → base_url 反代**:听 `base_url`/`HTTPS_PROXY`(settings.json env),用零解密的反向代理最省。
- **Codex → relay-tee**:已经 OpenAI-via-本地-relay,在既有 relay 上加 tee 即可(**细节 TODO**,见 Extensions)。
- **OpenCode → relay-tee(2026-07-18 端到端实测通过)**:OpenCode 的内建 `openai` provider 认 `baseURL`(`~/.config/opencode/opencode.json` → `provider.openai.options.baseURL`),故**零新机制**——把 baseURL 指向既有 `asight capture` tee(实测 `http://127.0.0.1:8991/models-proxy` → SSH 隧道 → mini-codex)即完成 steer,**不碰证书、不碰代理管理器、不碰系统代理**,与 Codex 同源同信封。实测:一次真实 agentic 会话(读文件 → 写回归测试 → 跑 `python3 -m unittest` → 修 bug → 复验)采到 **13 个 LLM call**,上下文 44k→91k bytes 单调增长,`session-id` 头天然分组;9810 上以 **🟣 OpenCode** 渲出 52 block / 9 tool(逐字 schema)。**注意其线格式是 Responses**(不是 Chat Completions),且 UA(`opencode/…`)**不含 `openai`** —— 命中靠 `detect()` 的端点判据,见 [00-overview](00-overview.md) D25 实测复核。

**备选(未选)**:① **MITM 一切**——要给每个 host 签叶证 + 扩大 TLS-解密面,违「只解密列入的目标 host」(采集安全 必拒);② **反代一切**——CC-Desktop 强制覆写 base_url,反代对它无效,漏采一个 harness。
**取舍**:机制随 harness 分化,但**向下的信封统一** → 上层(3.1/4.2/前端)对源无差别,「适配缝」在采集端也不漏(不变式 3,**需 RFC 才放行**才能破)。

## 统一原始信封(三源共用契约)

采集源的唯一产物。字段由采集侧的纯函数 `buildRecord`/`summarizeRequest`/`safeHeaders`/`detectAuthMode`/`makeSseReconstructor` 产出,三源(反代/MITM/relay-tee)复用同一 builder:

| 字段 | 含义 | 保真度 |
|---|---|---|
| `id` `ts_request` `ts_response_start` `ts_response_end` `duration_ms` | 记录 id + 时序 | verbatim(采集侧生成的观测元数据) |
| `method` `endpoint` | 请求行(`/v1/messages` vs `count_tokens` vs 控制面) | verbatim |
| `is_llm_call` `capture` `auth_mode` | 派生标签:是否真推理 · 源类型(`mitm`/反代/relay-tee)· 凭据模式(`api-key`/`oauth`,**仅标签不含密钥**) | 派生(非线上字段) |
> `is_llm_call` **provider-agnostic**(是否真推理 → `req_body` 逐字):识别三家 v1 harness 的推理端点 = Anthropic `/v1/messages`(排 `count_tokens`)· OpenAI **Responses**(Codex,经采集 tee 为 `/codex/responses`)· OpenAI/DeepSeek **Chat Completions**(`…/chat/completions`)。仅端点识别,**非** provider 解析(解析在 [3.1](3.1-adapter-contract.md) adapter / D25 dissector)。落地 `src/capture/envelope.mjs::isLlmCall`。
| `req_headers` | 请求头 | **保真边界:脱敏** — `SECRET_HEADERS`(authorization/x-api-key/cookie/proxy-authorization)→ `<redacted>`;其余逐字。**MUST NOT 让凭据入 trace**(不变式 4 + 采集安全,**必拒**) |
| `req_body` | 请求体 | **产品 MUST 逐字保真**(承 [3.1](3.1-adapter-contract.md) 信封 `req_body(逐字)` + 不变式 2)。**D15 已落地**:`summarizeRequest` 现存 `tools` **逐字**(完整 `description`+`input_schema`),摘要(name/param 名/desc 长)上移到 adapter([3.1](3.1-adapter-contract.md) `linearContext` 派生);`system`/`messages` 一直全保真。**残留保真边界**:① D15 之前的**旧 trace** 仍是 tools 元数据(UI 就地标 `metadata` vs 新的 `verbatim`,adapter 向后兼容);② JSON 重序列化非原始 bytes(块字段级逐字,承 [4.2](4.2-storage-etl.md) §42);③ 非 LLM 调用只存 `{raw_chars}`。见「保真边界」与 §验收#3 |
| `resp` | 响应 | JSON 走 `{status,kind:'json',body}`;SSE 走 `kind:'sse'` 的**重建体**(`makeSseReconstructor`:按 `content_block_*`/`message_delta` 重装 text/thinking/tool_use/usage)。**保真边界:SSE 为重建非原始帧**;`ATRACE_KEEP_RAW_SSE=1` 另存 `raw_sse` 原始事件。压缩响应先在观测侧 `decodeBody`(br/gzip/deflate)再重建 |

**中断也记(承 demo `recordError`/`upstream.on('error')`)**:上游连接失败无响应时,采集源 MUST 仍写一条 `error:true` 信封(`resp.kind:'error'`),否则失败的一步在时间轴上**隐形**。

> **信封字段名对齐(给整合者)**:[3.1](3.1-adapter-contract.md) 用 `req_headers/req_body/resp`;demo 记录用 `request_headers/request/response`。产品 MUST 收敛到一套 canonical 字段名(建议采 3.1 命名);本模块负责定义,adapter 据此消费。

## 三个采集源(机制 · demo 落地)

1. **base_url 反代(reverse proxy · `proxy.mjs`)**:零依赖 HTTP 反代,`ANTHROPIC_BASE_URL`/`HTTPS_PROXY` 指向它 → 转发到真 API。**透明契约**:仅改 `HOP_BY_HOP` 头 + `Host`(HTTP 中继本就要管的),**req_body 逐字转发、resp 逐字回流客户端**;所有记录发生在**解码 side-copy(tee)**上,永不影响客户端收到的字节(`up.on('data')` 里 `res.write(chunk)` 先于观测)。egress 经上游 VPN(CONNECT+TLS,`ATRACE_UPSTREAM_PROXY`/7897)或直连。
2. **MITM(`atrace-mitm.mjs`)**:CONNECT 代理。`host === TARGET_HOST` → 用 **atrace CA 签的叶证** TLS-终止、解密、记录、经上游 VPN 转发真 API;**其余 host 一律盲隧道**直通 7897,不解密不记录。`connectToRealApi` 经 VPN 打 TLS 到真 API,`node` 自身发起 egress 故**不匹配 Clash 规则 → 无路由环**。CC-CLI 经 settings.json `HTTPS_PROXY` 直达此 MITM;CC-Desktop 经 Clash 精准 steer 到此 MITM。
   - **产品落地(2026-07-17 · 承 D20 纯 tee)**:`src/capture/mitm.mjs`(`createMitmProxy`,demo `atrace-mitm.mjs` 移植:注入 `connectUpstream`/`blindTunnel` 得离线 harness、`store.route` 换成纯 `onEnvelope`——**只写 append-only D10 信封流、不按 session 预分流**,消解 demo 采集侧分流的 v0 shortcut)+ CLI runner **`asight mitm --port <p> --out <ndjson>`**(复用 onboard 的 `api.anthropic.com` 叶证 + 上游 7897)。CC-Desktop 的 Clash `atrace-mitm` proxy 指向此产品 MITM,输出与反代 tee **同一 D10 信封**(仅 `capture:'mitm'` 别),故与 Codex 采集**汇进同一源目录**(见 [4.4](4.4-server.md) 目录源)→ 一个 9810 并列渲染两 harness。gate = `test/capture/mitm.test.mjs`(选择性解密 + 盲隧道)。
3. **relay-tee(Codex · TODO)**:Codex 已经本地 relay,在 relay 上加 tee 吐同信封。**本 RFC 单元的显式缺口**(承 [00-overview](00-overview.md) 模块地图「Codex relay-tee 细节 TODO」);落地前 Codex 采集不完整,须在 UI 标注。

## 采集安全(违反=必拒)

1. **选择性解密(必拒)**:MITM MUST 只 TLS-解密**明确列入的采集目标 host**(`ATRACE_TARGET_HOST`),其余 host **盲隧道透传**(`atrace-mitm.mjs` 的 `host === TARGET_HOST` 分支)。扩大解密面 = 必拒。
2. **精准 steer,不动整机系统代理(必拒)**:在采集点(Clash 规则 / `base_url` / relay)精准引流;`clash/atrace-merge.yaml` 用 `AND((PROCESS-PATH-REGEX claude-code),(DOMAIN api.anthropic.com))` 只圈「Desktop 的 claude-code → anthropic」,别的一切不碰。MUST NOT 把整机系统代理路由进 MITM(Non-Goal)。
3. **CA 仅装用户级信任、绝不全机弱化 TLS(必拒 · 平台中立原则 · D22)**:`atrace-mkca`(OpenSSL,全平台)生成 root CA(RSA-3072/10y)+ `api.anthropic.com` 叶证,私钥 0600 存 **`~/.asight/ca`**(**D27** 2026-07-20 起;旧装机的 `~/.atrace/ca` MUST 仍被识别复用——**MUST NOT 因目录改名而重新生成 CA**,那会让用户 keychain 里已信任的 root 变成孤儿、并诱导其信任第二张 root。**CA 主体名 `CA_CN` 冻结不改**:keychain 认证书内容不认路径,故搬目录安全、改 CN 必拒)。onboard 经跨 OS `TrustStoreInstaller` 接口 **import-only** 装进**用户级**信任库,**绝不**碰全机锚点。per-OS:**macOS** = `security add-certificates -k login.keychain-db`(Claude Code 直读 keychain,零 trust settings 也生效),MUST NOT `security add-trusted-cert -r trustRoot`;**Linux** = `certutil -d sql:$HOME/.pki/nssdb -A -n asight-ca -t C,,`(用户 NSS 库),MUST NOT 写 `/etc/ssl/certs` / `update-ca-certificates` 等全机锚点;**Windows(预留)** = CurrentUser `Root` store,MUST NOT LocalMachine。移除对称(`security delete-certificate` / `certutil -D`),干净可逆。

## onboard / 证书 / 代理配置

每源 ship 一对**开/关**脚本 + 一个**「测试」**兜底(1.1 六要素#5「把委派代价压到最小」)。**onboard 的 OS-触碰部分(装/验/卸证书)全走跨 OS `TrustStoreInstaller` 接口(D22),`process.platform` 分派;v1 落 darwin + linux**(详见 [4.5](4.5-distribution.md)):
- **CLI(反代/MITM · 全平台)**:`atrace-on` 写 `settings.json` env(`HTTPS_PROXY`→MITM、`NO_PROXY=127.0.0.1,localhost`);`atrace-off` 把 `HTTPS_PROXY` **指回上游 VPN/直连** 使登录仍连通、但不解密不记录——**关闭=旁路,零残留**。此路径**不碰证书信任库、不依赖 Clash** → **Linux 上今天即可端到端**(反代是纯 Node)。
  - **⚠ 实测反证(2026-07-18 · 对抗评审)**:「Linux 今天即端到端」**当前不成立 —— 这条唯一的跨平台采集路被接错了**。`asight on` 写的是 `settings.json` 的 **`HTTPS_PROXY`**(= 让 harness 把本地端口当 **HTTP 代理**,对 https 目标先发 **CONNECT**),但 `asight capture` 是**base_url 反向代理**(直接读 `req.url` 转发),**不处理 CONNECT** → harness 发 CONNECT、反代不认,采集拿不到字节。二者语义不匹配:要么 `on` 改写 **`ANTHROPIC_BASE_URL`** 指向反代(反代语义,推荐 · 跨平台纯 Node),要么 capture 端补 CONNECT/MITM(那就等于 MITM 源、需要 CA)。**在改对之前,Linux 端到端 = 未验证**;4.5 的「Linux v1 可用」同受影响。另:Linux `TrustStoreInstaller` 的 `certutil -A` **从未在任何机器上真跑过**,且缺 `~/.pki/nssdb` **不存在时的初始化**(`certutil -N`)——首次使用会失败。
- **Desktop(MITM+Clash · 仅 macOS)**:`atrace-desktop on` 把 `atrace-merge.yaml` 装进 Verge 全局 Merge(订阅更新不会抹掉),reload mihomo;无需重启 Desktop、不改系统代理。**Clash steer 是 macOS-Desktop 的一种 steer 实现,非跨平台契约**(D22);Linux 无 Claude Desktop、其唯一 CC harness 是 CC-CLI(走上条反代)。
  - **产品落地(2026-07-17)**:`asight desktop {on|off|status}`(`src/capture/desktop-steer.mjs` + bin `desktop` case,macOS-only,非 darwin 显式拒绝 · D22)。**耐久机制修正**:实测 Clash Verge Rev 2.5.1 的全局 **Merge = 纯 RFC-7386 深合并、不展开 `prepend-rules`/`prepend-proxies`**(伪指令原样漏进运行时 config → mihomo 忽略未知键 → demo 的 Merge.yaml steer 在此**失效**);故改走**全局 Script**(`profiles/Script.js`,`enable_builtin_enhanced`)——它在**每次 enhance/regen**(订阅/配置更新、重启)对**已装配的最终 config** 跑,命令式 `config.proxies.unshift(atrace-mitm)` + `config.rules.unshift(AND((PROCESS-PATH-REGEX claude-code),(DOMAIN api.anthropic.com)))` → **既跨 regen 存活、又可靠生效**;并 hot-reload mihomo(经 `/tmp/verge/verge-mihomo.sock` PUT `/configs`,mihomo 校验失败保留旧 config → VPN 不会因坏改断)一次即时生效。steer 目标 = 产品 MITM(`asight mitm`,`--port` 须与之一致,默认 `ASIGHT_MITM_PORT||9899`)。**off 对称**:恢复 Script.js 原样(备份 `.atrace-bak`)+ 清运行时 splice + reload,零残留;顺带清掉 demo 遗留的 Merge.yaml 失效块。**永不动系统代理**(4.1:14/54 · 必拒)。gate = `test/capture/desktop-steer.test.mjs`。
- **证书(per-OS · `TrustStoreInstaller`)**:首次 `atrace-mkca`(OpenSSL,全平台)生成 CA/叶证;`install()` **import-only** 装进用户级信任库——macOS `security add-certificates`·login keychain / Linux `certutil` 用户 NSS 库(`~/.pki/nssdb`);`atrace-on` 经 `verifyUserTrustOnly()` 检测 CA 已在库且**无全机信任**,缺则提示(import-only 文案)。
- **「测试」按钮**回答四问(是否真在抓 / 抓得对 / 凭据没漏 / 没弱化全机 TLS)——即 §验收 的可跑 check 的 UI 化。**已落地(2026-07-16)**:CLI `asight doctor`(`src/capture/selftest.mjs`,纯函数、离线可单测 `test/capture/selftest.test.mjs`);凭据没漏 = redact 防火墙(header 必 `<redacted>`)为硬红线,其余三问供人核对(承 §受众:人)。

> **保真边界(UI MUST 就地标注)**:① `req_headers` 的 secret 字段显 `<redacted>`(非逐字,故意);② SSE 的 `resp` 是**重建**非原始帧(除非开 `KEEP_RAW_SSE` / CLI `--raw-sse` → `resp.raw_sse` 存逐字事件)。**重建器是 Anthropic 事件形状**;对其不识别的 provider(OpenAI **Responses**/Codex)重建结果为空,故该 provider 采集 **MUST 开 `--raw-sse`**,否则事件丢失(违不变式 2)——其 blocks 由 [3.1](3.1-adapter-contract.md) OpenAI dissector 从 `raw_sse` 重建;③ `tools` 现逐字采集(D15),但 **D15 之前的旧 trace** 仍只有元数据 → UI 每块标 `verbatim`/`metadata` 区分;非 LLM 调用只有 `{raw_chars}`;④ Codex relay-tee 未落地前其采集**不完整**。这些 MUST NOT 让人误以为看到的是完整线上真相(不变式 4,**必拒隐瞒**)。

## 验收(可跑 check · 具体测试要求)

**已委托的门禁(每次跑,承 demo)**:
- `test/web/dashboard-render.mjs`:headless DOM shim 驱动真实 render 管线,断言各面板填充**且中央上下文窗口 byte-verbatim(AC-1)**——采集信封是这条链的原料源,回归它保护 AC-1 不被采集侧悄悄降解。

**本模块新增测试 MUST 断言**:
1. **源等价性(envelope parity)**:同一条上游交互,经反代 / MITM / relay-tee **产出字段等价的信封**(同 `endpoint/method/req_body/resp/usage`),差异**只在 `capture` 标签** → 兑现「适配缝在采集端也不漏」。
2. **每源过 byte-transparency**:MITM 与 relay-tee 目前**无 offline harness**,新测须补(如给 MITM 加 mock TLS 上游),各自跑 `cmp` 证收发逐字节不变。
3. **verbatim `req_body`(D15 · 已落地)**:`summarizeRequest` 的 tools 降解**已移除**——`tools` 逐字存(完整 `description`+`input_schema`),摘要上移到 adapter([3.1](3.1-adapter-contract.md) `linearContext` 派生 `descChars`/`props`/`verbatim` 标),raw NDJSON 真为源真相(不变式 2)、tools 纳入 AC-1(gate 断言 `linearContext` 的 `desc`/`schema` 与请求逐字相等 + UI 标 `verbatim` 且展开见 `input_schema`)。**向后兼容**:旧 trace(只有 `description_chars`/`input_schema_props`)adapter 回落派生、`verbatim=false`、UI 标 `metadata`——诚实区分,不冒充。**权衡(已知代价)**:tools 每 call 送、demo 无去重 → 新 trace 增大;产品靠 [3.2](3.2-normalized-model.md) `content_hash` 去重(同 tools 前缀跨百 call 只存一次)化解。
4. **选择性解密(采集安全)**:向 MITM 打一个**非目标 host** 探针,断言信封里**没有它的任何明文**(走了盲隧道、未解密未记录)。
5. **CA 仅用户级信任、无全机信任(跨 OS 契约 · D22)**:每个 `TrustStoreInstaller` 实现的 gate 断言——CA 命中**用户级**库且**无全机信任标志**。macOS:`security find-certificate` 命中 login keychain 且无 trust settings(未 `add-trusted-cert -r trustRoot`);Linux:`certutil -L -d sql:$HOME/.pki/nssdb` 命中且全机锚点(`/etc/ssl`)未被写。测试 **MUST NOT 变更真实信任库**(host-specific,类 relay-tee 的 X 标切成 flagged 子单元;`install`/`uninstall` 走临时 throwaway NSS 库/keychain 验证幂等)。
6. **中断可见**:模拟上游断连,断言产出 `error:true` 信封而非静默丢步。

## Edge cases
- **压缩响应**(br/gzip/deflate):观测侧 `decodeBody`/decoder tee 解压后重建,**客户端仍收原始压缩字节**(承 demo tee)。
- **非目标 host 经采集点**:盲隧道透传,零解密零记录(采集安全#1)。
- **CC-Desktop 强制覆写 base_url**:反代无效 → 必走 MITM+Clash 精准 steer(不动系统代理)。
- **路由回环**:MITM 自身 egress 由 `node` 发起,不匹配 Clash 的 `PROCESS-PATH-REGEX claude-code` → 无环(承 `atrace-merge.yaml` 注释)。
- **非 LLM / 控制面流量**(`count_tokens`、telemetry、registry):信封 `is_llm_call=false`,**保真边界:req_body 只存 `{raw_chars}` 元数据**;UI 标「非逐字」。
- **并发多 session 同 harness**:采集源只吐信封不判身份;归并靠 [3.4](3.4-session-identity.md) 的线上信号,与本层正交。

## Risk / 回滚
- 采集源是**旁路观测**,关闭 = `atrace-off` 把 `HTTPS_PROXY` 指回 VPN,被测程序直连,**零残留**;CA import-only,`security delete-certificate` 干净移除。
- 新源接入**独立**:加一个源不改信封契约 → 不碰 adapter/前端(AC-3 在采集端的对应)。每源一个 `git commit` 积木,失败回退上一绿点。
- **非显然坑**:MUST NOT 未经用户同意重启 Desktop / 重启在跑的采集(会杀会话、丢采集)。
