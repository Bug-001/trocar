# asight · RFC 4.1 — 可插拔采集源

> **服务意图(A2)**:跨切「适配层通用」(AC-3)的**最上游**——采集源是「拿到 bytes」的那一端,把三家真实流量喂进 ①(逐字上下文/回复供回放)与 ②(真实 usage 供 cache 叠加)。也是 [1.1](1.1-product-definition.md) 六要素#5「委派代价」的承载点:把采集委派给 MITM/relay,须配 onboard + 每源一个「测试」兜底。
> **受众**:人(核对四问——**是否真在抓 · 抓得对 · 凭据没漏 · 没弱化全机 TLS**)+ agent(据此实现采集源 + onboard 脚本)。
> **前置**:输出 = **统一原始信封**,交 [3.1](3.1-adapter-contract.md) adapter 解释、[4.2](4.2-storage-etl.md) 存储;身份信号见 [3.4](3.4-session-identity.md);采集安全的**单一权威 = 本文件 §采集安全**。与 adapter **正交**:源管「怎么拿到 bytes」,adapter 管「bytes 什么意思」。

## Goal
定义一个**可插拔采集源接口**:无论用哪种机制拿到字节(MITM / base_url 反代 / relay-tee),都向下吐**同一个统一原始信封**,使 asight 其余层对「用哪种源、抓的哪个 harness」**无感**。为每个 harness 选**最便宜、最不侵入**的源(承 [0.0-overview](0.0-overview.md) D4)。**观测唯一**:采集源永不 originate 请求、永不改写流量、永不用被测程序 token 发起调用(不变式 1([0.0](0.0-overview.md) §核心不变式),**必拒违反**)。

## Definitions
- **采集源(capture source)**:拿到字节的机制 + 把它写成统一信封的模块。三机制:MITM / base_url 反代 / relay-tee。
- **统一原始信封(envelope)**:一次上游交互的归一记录形状 `{ts, endpoint, method, req_headers(脱敏), req_body, resp}`(承 [3.1](3.1-adapter-contract.md));三源共用,只在 `capture` 标签上不同。
- **采集目标 host(capture-target host)**:明确列入、允许 TLS-解密的 host(demo:`api.anthropic.com`,env `ATRACE_TARGET_HOST`)。其余一律盲隧道。这是旧 MITM 的口径;[4.6](4.6-process-collector.md) 采集器按进程认目标,已信任的 agent 进程的 host 都是目标(D31;D40 起默认全部解密)。
- **采集点(steer point)**:把被测流量精准引到采集源的地方——Clash 规则 / `base_url` / relay 配置,**非整机系统代理**。

## Plan(选定方案 + 取舍)

**选定**:**可插拔多源,每 harness 选最便宜源**;机制随 harness 走,信封统一。
- **CC-Desktop → 只能 MITM**:Desktop 内嵌 claude-code **强制覆写 `ANTHROPIC_BASE_URL`、且不认 `~/.claude/settings.json` env**(其 `HTTPS_PROXY` 来自 macOS 系统代理 = VPN),故 base_url 反代抓不到 → 在 **Clash 路由层**只把「Desktop 的 claude-code → api.anthropic.com」精准 steer 进 MITM。
- **CC-CLI / DeepSeek-CLI → base_url 反代**(过渡期旧文;D37 起 DeepSeek 的 harness 是说 Anthropic Messages 的 `dsh`,走 4.6):听 `base_url`/`HTTPS_PROXY`(settings.json env),用零解密的反向代理最省。
- **Codex → relay-tee**:已经 OpenAI-via-本地-relay,在既有 relay 上加 tee 即可(**细节 TODO**,见 Extensions)。
- **OpenCode → relay-tee(2026-07-18 端到端实测通过)**:OpenCode 的内建 `openai` provider 认 `baseURL`(`~/.config/opencode/opencode.json` → `provider.openai.options.baseURL`),故**零新机制**——把 baseURL 指向既有 `asight capture` tee(实测 `http://127.0.0.1:8991/models-proxy` → SSH 隧道 → mini-codex)即完成 steer,**不碰证书、不碰代理管理器、不碰系统代理**,与 Codex 同源同信封。实测:一次真实 agentic 会话(读文件 → 写回归测试 → 跑 `python3 -m unittest` → 修 bug → 复验)采到 **13 个 LLM call**,上下文 44k→91k bytes 单调增长,`session-id` 头天然分组;9810 上以 **🟣 OpenCode** 渲出 52 block / 9 tool(逐字 schema)。**注意其线格式是 Responses**(不是 Chat Completions),且 UA(`opencode/…`)**不含 `openai`** —— 命中靠 `detect()` 的端点判据,见 [0.0-overview](0.0-overview.md) D25 实测复核。

**备选(未选)**:① **MITM 一切**——要给每个 host 签叶证 + 扩大 TLS-解密面,违「只解密列入的目标 host」(采集安全 必拒);② **反代一切**——CC-Desktop 强制覆写 base_url,反代对它无效,漏采一个 harness。
**取舍**:机制随 harness 分化,但**向下的信封统一** → 上层(3.1/4.2/前端)对源无差别,「适配缝」在采集端也不漏(不变式 3,**需 RFC 才放行**才能破)。

## 凭据处置(本节取代原「凭据脱敏」必拒条)

**决定**:采集**逐字存储**请求头,包括 `authorization` / `x-api-key` / `cookie` /
`proxy-authorization`。原先的 `<redacted>` 改写防火墙**移除**。

**理由**(两条,第二条是产品自身的一致性问题):
1. **部署面**:asight 是**单用户 · 本机 · loopback**的个人研究仪器,凭据在本机上已由文件系统保护;
   为它维护一条改写防火墙属于「节外生枝」。
2. **保真**:asight 的全部意义是展示**真正上过线的字节**,而 `<redacted>` 恰恰是对这些字节的**改写**。
   脱敏让采集在自己最核心的那一层变得**非逐字**,与不变式 2/4 的精神相抵。

**红线没有消失,是搬了家。** 字节里现在有活凭据,故唯一仍然成立的保证是「除属主外无人可读」(对文件成立;D36 起同一台机器上可能有别的系统用户,共用 `127.0.0.1` 的看板 / API 会把采集再暴露给他们,缺口见 [4.4](4.4-server.md) OPEN):

- `asight doctor` 的**硬失败(exit≠0)**从「有未脱敏的 secret header」改为
  **「有采集文件可被 group/other 读取」**(④b · `qFilePerms`;D35 起扫描面 MUST 含封存文件与默认导出目录 `~/.asight/export/`,并有测试;[1.6](1.6-cli.md) R2 的备份目录 `~/.asight/backup/` 同样在内:里面是用户配置文件的原样,常含令牌)。退出码按 [1.6](1.6-cli.md) R4:失败 = 1(文案「采集文件可被他人读取」);**零条记录、没核任何文件、有文件的权限读不出来、有采集文件没读完整 = 无法判定 = 3**,既不是过也不是失败(「核到零条」报「过」会让人以为权限已经核过);已发现的失败压过判不了。
- ③ 退化为**如实报告**:有多少条记录带凭据(**不判失败**),外加保留「空扫描不得认证任何事」守卫。

**MUST NOT**:把凭据用于任何请求 —— 不变式 1([0.0](0.0-overview.md) §核心不变式) 的 token 条款**不受本决策影响**,

## 采集安全(违反=必拒)

1. **选择性解密(必拒)**:MITM MUST 只 TLS-解密**明确列入的采集目标 host**(`ATRACE_TARGET_HOST`),其余 host **盲隧道透传**(`atrace-mitm.mjs` 的 `host === TARGET_HOST` 分支)。扩大解密面 = 必拒。(这条约束旧 MITM,随旧采集退役;[4.6](4.6-process-collector.md) 采集器的目标是识别出且已信任的 agent 进程,D40 起默认解密它的全部 host,见 D31 / D40。)
2. **精准 steer,不动整机系统代理(必拒)**:在采集点(Clash 规则 / `base_url` / relay)精准引流;`clash/atrace-merge.yaml` 用 `AND((PROCESS-PATH-REGEX claude-code),(DOMAIN api.anthropic.com))` 只圈「Desktop 的 claude-code → anthropic」,别的一切不碰。MUST NOT 把整机系统代理路由进 MITM(Non-Goal)。
3. **CA 仅装用户级信任、绝不全机弱化 TLS(必拒 · 平台中立原则 · D22)**:`atrace-mkca`(OpenSSL,全平台)生成 root CA(RSA-3072/10y)+ `api.anthropic.com` 叶证,私钥 0600 存 **`~/.asight/ca`**(**D27** 2026-07-20 起;旧装机的 `~/.atrace/ca` MUST 仍被识别复用——**MUST NOT 因目录改名而重新生成 CA**,那会让用户 keychain 里已信任的 root 变成孤儿、并诱导其信任第二张 root。**CA 主体名 `CA_CN` 冻结不改**:keychain 认证书内容不认路径,故搬目录安全、改 CN 必拒)。onboard 经跨 OS `TrustStoreInstaller` 接口 **import-only** 装进**用户级**信任库,**绝不**碰全机锚点。per-OS:**macOS** = `security add-certificates -k login.keychain-db`(**keychain 装入对 node 版 claude-code 不生效** —— 2026-07-21 实测更正,node 只认 `NODE_EXTRA_CA_CERTS`,见 [4.5](4.5-distribution.md):39 的 darwin 信任机制段;经登录环境注入该变量的 `com.asight.env` 是过渡期遗留(D37④),随旧采集退役一起移除,`asight off` / `uninstall` / `desktop off` 整体关闭旧采集时也一起撤(D39⑥),见 [0.0](0.0-overview.md) §过渡期遗留;keychain 装入仍保留供 curl/openssl 等消费者 + 对称移除),MUST NOT `security add-trusted-cert -r trustRoot`;**Linux** = `certutil -d sql:$HOME/.pki/nssdb -A -n asight-ca -t C,,`(用户 NSS 库),MUST NOT 写 `/etc/ssl/certs` / `update-ca-certificates` 等全机锚点;**Windows(预留)** = CurrentUser `Root` store,MUST NOT LocalMachine。移除对称(`security delete-certificate` / `certutil -D`),干净可逆。

## Edge cases
- **压缩响应**(br/gzip/deflate):观测侧 `decodeBody`/decoder tee 解压后重建,**客户端仍收原始压缩字节**(承 demo tee)。
- **非目标 host 经采集点**:盲隧道透传,零解密零记录(采集安全#1)。
- **CC-Desktop 强制覆写 base_url**:反代无效 → 必走 MITM+Clash 精准 steer(不动系统代理)。
- **路由回环**:MITM 自身 egress 由 `node` 发起,不匹配 Clash 的 `PROCESS-PATH-REGEX claude-code` → 无环(承 `atrace-merge.yaml` 注释)。
- **非 LLM / 控制面流量**(telemetry、registry、account、会话同步、上传下载):信封 `is_llm_call=false`;D40 起请求体与 LLM 同规则逐字,响应同 LLM;UI 不标「非逐字」,只在截断、未解码、只记日志时各标各的。D40 之前的旧记录只有 `{raw_chars}`,标「本条采于 D40 之前,只存了长度」(`raw_chars` 为 0 的除外:那是没有体的调用,如 GET `domain_info` / 列会话,没有丢任何东西,读成空体、不标)。别的 host 上的辅助模型调用是推理;**session 内的非推理调用(`probe` / `other`)的体存在采集记录里,看板只在 probe 详情里说明体在哪,不显示体**(见 [2.6](2.6-detail-panel.md) §C)。
- **大的非 LLM 体**(文件上传、更新包下载):超 64 MiB 只存前缀,标「已截断」,`body_wire_bytes` 给出线上全长;二进制存 base64,一行约是体的 4/3。
- **类别认不出**:落 `other`,默认 `full`;漏写一条模式不丢数据,只是归错类。
- **并发多 session 同 harness**:采集源只吐信封不判身份;归并靠 [3.4](3.4-session-identity.md) 的线上信号,与本层正交。

## Risk / 回滚
- 采集源是**旁路观测**,关闭 = `atrace-off` 把 `HTTPS_PROXY` 指回 VPN,被测程序直连,**零残留**;CA import-only,`security delete-certificate` 干净移除。
- 新源接入**独立**:加一个源不改信封契约 → 不碰 adapter/前端(AC-3 在采集端的对应)。每源一个 `git commit` 积木,失败回退上一绿点。
- **非显然坑**:MUST NOT 未经用户同意重启 Desktop / 重启在跑的采集(会杀会话、丢采集)。
