# asight · RFC 2.4 — 资源管理器(Resource Explorer)

> **服务意图(A2)**:意图 ②(资源随每步**进出上下文** = 上下文工程的一半,承 [00-overview](00-overview.md) 对齐闸 ② = 1.3+3.3+**2.4**)为主;兼意图 ①(这一步引入了哪个文件 / 能力 = 行为线索)。它是回放骨(2.3)之外、把「一条 session 的资源生命周期」摊平到右页的横向仪器。
> **受众**:人(看某 session 里文件 / 能力 / 目录的进出、命中、evict);agent(据 [3.2](3.2-normalized-model.md) `resource_events` 渲染右页,**不碰 provider/harness 分支**)。
> **前置**:数据源 = [3.2](3.2-normalized-model.md) `resource_events` 表(由 [3.1](3.1-adapter-contract.md) `parseResources` 填、[3.5](3.5-query-layer.md) 查);内容回源 = `block_contents`/`call_blocks`(via `resource_ref`);渲染宿主 = [1.2](1.2-shell-layout.md) 右页上部;文件内容显示在 [2.6](2.6-detail-panel.md) 右下 panel;定位跳转落到 [2.3](2.3-context-window.md) 的上下文块。

## Goal
把一条 session 里所有**被观测到进出上下文的资源**(文件 / 目录 / 链接 / MCP / skill / 自动加载的 scaffold / 只被看到名字的路径)按生命周期摊在**右页**,让人一眼答:*这个 agent 到底打开过哪些文件、哪些只是「看到名字」、什么时候被 compaction 换血 evict、现在这一步哪些还 live。* 双交互:单击卡片 → 把中央看板 scrub 到它进入的那步并高亮对应块;单击文件名 / 👁 → 右下 panel 显示该资源的**逐字内容**。v0 原型的 `lifecycleNav` / `viewResource` / `renderResourceView` 已实现此设计,数据由 `extractResources` / `extractSeenPaths` 产出——本模块把它从「CC 单 harness 原型」定成「读归一化 `resource_events` 的 provider-agnostic 部件」。

## Definitions
- **resource**:一次 call 的上下文里因 agent 动作而进入 / 驻留的外部实体——文件 / 目录 / 链接 / MCP / skill / image / document / 自动 scaffold。生命周期粒度 = `resource_events`(3.2)。
- **segment(驻留段)**:一个资源的一次 `enter → evict` 存续区间;compaction 会给所有 live 资源打 evict,之后再被引用 → 新起一段(`reinject`)。一个资源可有多段。
- **load(范围读)**:对已 resident 资源的一次带 `range` 的读(如 `Read L1–200`、`head 50`);挂在资源上,不新起段。
- **scaffold(加载态上下文)**:非 agent 显式打开、而由 harness **自动注入**的上下文(CC 的 `CLAUDE.md` / `MEMORY.md`,经 `<system-reminder>` 出现)。
- **capability(能力)**:非文件类可调用资源(MCP server / skill / image / document)。
- **only-seen name(只见其名)**:出现在**工具结果 / 散文里**、但 agent **从未 Read/Write/Edit** 的路径——**只有名字、无内容**(保真边界)。答「它真用了文件 X,还是只是瞥见了名字」。

## Plan(选定方案 + 取舍)
**选定**:右页一列**按 display-group 折叠**的生命周期清单;数据只读归一化 `resource_events`,**分组是渲染期对 `kind` 的投影**,状态(live/evicted/pend)是**播放头相对**实时算的。六组:`📂 files opened · 👁 only seen (names) · 🧠 loaded context(scaffold) · 🧩 capabilities(skill/MCP) · 🔗 dirs & links · ✂ context resets(compaction/summary)`。
**备选(未选)**:① 把资源做成时间轴上的**叠加轨**(1.3)而非右页清单——轨适合「密度/命中随步变化」,但「这条 session 一共碰过哪些文件、各自哪段 live」需要一个**可扫的名录**,轨表达不了纵览;故资源在 1.3 有轨(叠加层)、在 2.4 有名录(右页),两者互补不重复。② 把 `only-seen` 混进 `files opened`——会让「看到名字」冒充「打开过」,违反保真边界;故独立成组并标「names」。③ 在部件里按工具名(`Read`/`Bash`/`mcp__`)现算资源——**需RFC 违反**:那是 harness 专属逻辑,MUST 留在 adapter `parseResources`(3.1),部件只读归一化事件(见影响面)。
**取舍**:分组 = 渲染期对细粒度 `kind` 的**投影**(不是新增 schema 枚举),schema 保持 provider-中立的细 kind;状态播放头相对算 = 无需为每步存一份资源快照,scrub 即时反映。

## 右页结构与生命周期(substance)
渲染入口 `renderContextNav()` 做 **B 拆分**:*this context* 的 outline 留在看板(`#ctxnav`,见 [2.5](2.5-outline-nav.md)),*across the session* 的资源名录进右页(`#resexp`,标题 `resources · across the session`)。`lifecycleNav()` 生成六组,每组一个可折叠 `navGroup`(带 count)。

**分组与来源(demo → 归一化映射)**:

| display group | demo `kind` | 归一化 `resource_events.kind` | 每项显示 |
|---|---|---|---|
| 📂 files opened | `file` | `file` | 相对路径 + 状态徽标 + `#enter步` |
| 👁 only seen (names) | `seenFiles`(旁路) | `event='seen'`(D8) | 路径 chip · `seen N×` · `first @#步`(**names only**) |
| 🧠 loaded context | `scaffold` | `kind='scaffold'`(D8) | 🧠 label + `#enter步` |
| 🧩 capabilities | `capability` | `mcp` / `skill` / `image` / `document` | 🧩 label + `#enter步`(+ resKey 供定位) |
| 🔗 dirs & links | `dir` / `link` | `dir` / `link` | 图标 + 相对路径 + `#enter步` |
| ✂ context resets | events | `calls.compaction`(3.2/3.4) | ✂ `from→to msgs` / 🗜 summary + `#步` |

> `#N` 步号经 `giLocal` 把全局步序映射成**lane-局部**序显示(子 agent lane 各自从 1 数)。

**播放头相对状态(files opened)**:对每个文件,遍历其 segments 相对当前 `playhead`——
- **live**:存在一段 `enter ≤ playhead < evict`(未 evict 段 evict 视作 +∞)→ 绿 `live` 徽标。
- **✂ evicted**:最后一段已在 `#N` 被 evict → `✂#N` 徽标(evict 来自 compaction,承 [3.4](3.4-session-identity.md):compaction 是同 session 换血、**不是 fork**)。
- **pend(未来)**:`enter > playhead`,本步还没进上下文 → `pend` 灰态;`only-seen` chip 同理标 `future`。

状态随 scrub 实时翻转——这正是「资源随每步进出上下文」的可见化,直接喂意图 ②。

## 双交互(承 demo point 4)
每个卡片挂**两个正交 affordance**,MUST 不互相吞事件:
1. **单击卡片体 → 定位看板**:`data-navstep`(+ 可选 `data-navres`=resKey)→ `jumpToStepAndBlock(step, resKey)`:`setPlayhead(step)` 把中央看板 scrub 到资源**进入的那步**,再在 [2.3](2.3-context-window.md) 上下文窗按 `data-rk` 找到那个块、展开、滚动居中、高亮 2s。让「名录项 ↔ 回放骨里的实体块」双向锚定。
2. **单击文件名 / 👁 → panel 显示逐字内容**:`data-view`/`viewstep`/`viewlabel` → `viewResource(step, resKey, label)`:先 `setPlayhead(enter步)`(把资源 live 的那次 call 装进上下文),置 `viewPin`,`renderResourceView()` 在当前 call 的 flat 上下文里**按 resKey 找块**(fallback:按 `input.file_path` 或「块文本包含 label」匹配),把该块**逐字 bytes** 渲成 `<pre>`;右下 panel 头显 `📄 <path>` + `✕ call raw` 回退键(点 ✕ 清 `viewPin` 回到 call 原始面板)。

> **内容回源(产品化)**:demo 直接从内存 flat 块取 `rawContentText`;产品 MUST 经 `resource_ref → call_blocks ⋈ block_contents.text_ref` **回逐字源 NDJSON**(承 [3.2](3.2-normalized-model.md) 不变式:派生层不存全文、回源取真相)。对 Read 类,承载 bytes 的是**兄弟 `tool_result` 块**(tool_use 块只带路径);对 Write/Edit 类,内容就在 `tool_use.input`。view MUST 解析到**真正带 bytes 的块**。

## 保真边界(必拒隐瞒 · 承不变式 4)
本部件展示的多处**非逐字线上真相**,MUST 就地标注:
1. **only-seen = 只有名字、无内容**:`seenFiles` 是对**工具结果 / 散文**里路径样 token 的**启发式正则抽取**(`extractSeenPaths`:须含 `/` 或已知扩展名、剥尾标点、每文本 cap、`acceptPath` 滤版本号/代码标识符/技术名)。它 **MAY 漏 MAY 误收**,且**不含文件内容**。UI MUST 标「names / 非逐字」,MUST NOT 让它冒充「打开过」或「文件内容」。
2. **resource ledger 是派生推断,非 provider 声明**:provider 不发「资源事件」;整个生命周期是 asight **从观测到的 tool_use / result bytes 推断**的分析层(如 usage/cache 之于原始 usage)。**底层块 bytes 是逐字源真相**(回源可 diff),**这一层的 enter/evict/kind 分类是 asight 的解释**。UI SHOULD 让人可回源核对(交互 1 的定位即回源锚)。
3. **view 面板截断**:超长内容按显示上限截断(demo `clip(…, 6000)`;上下文窗 `ctxBody` 为 20000)。截断处 MUST 显 `… (N chars total)` 之类标记 = truncated 保真边界。
4. **capability 内容 = 元数据**:MCP/tool 的 schema **只存元数据**(demo `ctxBody`:`description: N chars (schema text not retained)`);view 一个 capability MUST 标「元数据 / schema 未逐字」,MUST NOT 显空 pre 冒充完整定义。
5. **scaffold 路径为重建显示**:`scaffoldPath()` 把 `CLAUDE.md`/`MEMORY.md` 拼成推测的绝对路径(用 `project_path`/`project_slug`)——是**便于人识别的重建**,非线上原样字符串。

## Out-of-scope
- **资源怎么被检出**(tool 名 → resource kind 的 harness 专属映射:`FILE_OPS`/Bash 读解析/`Skill`/`mcp__`)→ [3.1](3.1-adapter-contract.md) `parseResources`,MUST NOT 在本部件重演。
- 资源作为**时间轴叠加轨**(命中/密度随步)→ [1.3](1.3-timeline-tracks.md);本部件只做右页**名录**。
- 文件内容 pre 的渲染宿主 / 关闭态 → [2.6](2.6-detail-panel.md);跳转落点的上下文块渲染 → [2.3](2.3-context-window.md);右页外壳/边界 → [1.2](1.2-shell-layout.md)。
- 表怎么被查(SQL)→ [3.5](3.5-query-layer.md);表结构 → [3.2](3.2-normalized-model.md)。

## 影响面
- **上游**:读 [3.2](3.2-normalized-model.md) `resource_events`(+ `calls.compaction`)与 `block_contents`(view 回源);经 [3.5](3.5-query-layer.md) 「资源管理器(2.4) → `resource_events`」这行查询。
- **适配缝(需RFC 才破)**:本部件 MUST 只消费归一化字段(`kind/label/event/via/range/segments`),**MUST NOT 出现任何 harness tool-name 字面量**(`Read`/`Bash`/`Skill`/`mcp__`/`FILE_OPS`…)。加第二/三个 harness 时,资源检出在各自 adapter `parseResources` 里加,本部件**零改动**即点亮(AC-3)。破此缝(往部件塞 provider 分支)= 需 RFC。
- **下游宿主**:[2.6](2.6-detail-panel.md)(内容面板)、[2.3](2.3-context-window.md)(定位高亮)、[1.2](1.2-shell-layout.md)(右页布局)。

## 验收(可跑 check)
**已有闸(承之,MUST 保持绿)**:渲染闸已断言——① 资源落**右页** `#resexp`(含 `resources · across the session`)、**未泄进** outline `#ctxnav`(不含 `across the session/files opened/only seen`);② `files opened` 项带 `viewbtn`;③ point 4:`viewResource(...)` 后 panel 切到 `📄` 文件内容。

**本模块新增测试 MUST 断言**(加进 `dashboard-render.mjs` 的资源段):
1. **分组正确**:`resource_events` 按 `kind` 投影出的六组,count 与 fixture 里各 kind 计数一致;`only-seen` 组与 `files opened` **无交集**(一个路径若被打开就 MUST NOT 同时出现在 only-seen)。
2. **播放头相对状态翻转**:同一文件,`playhead < enter` → `pend`;`enter ≤ playhead < evict` → `live`;`playhead ≥ evict` → `✂#N`。在 ≥2 个 playhead 位置各测一次,断言 state class 随 scrub 改变。
3. **保真边界标注在位**:only-seen chip **不含内容 pre**、带 names/非逐字标;view 超阈内容出现截断标记;view 一个 capability 出现「schema 未逐字/元数据」标。
4. **双交互解耦**:卡片 `data-navstep`(→ jump)与文件名/👁 `data-view`(→ panel)是**不同** handler;模拟点名字 → panel 出 `📄` 且 playhead=enter;模拟点卡片体 → playhead=enter 且看板高亮 `data-rk` 匹配块。
5. **缝合规(静态检查)**:对本部件的渲染代码做 grep,断言**不含** harness tool-name 字面量(`FILE_OPS`/`\bRead\b`/`Bash`/`Skill`/`mcp__`)——把「资源检出属 adapter、渲染属部件」写成可跑的回归,守 AC-3 / 不变式 3。
6. **内容回源逐字(AC-1)**:view 显示的资源内容,与其 `resource_ref → block_contents.text_ref` 指向的 NDJSON 源 bytes 逐字 diff = 0(截断标记外);Read 类须解析到**兄弟 tool_result** 块。

## Edge cases
- **多段驻留**:文件 enter→(compaction)evict→再引用 reinject。segments 多段;状态取「是否有任一段覆盖 playhead」;徽标显最后一段的 evict。
- **entered-earlier / evicted 不在本 call**:view 在当前 call flat 里找不到块 → panel 显「not resolvable to a single block in this call — click the card to locate it」引导用交互 1 定位。MUST NOT 静默空白。
- **only-seen 洪水**:一次 grep 喷几百路径 → per-text cap(结果 80 / 散文 40)+ 组内前 200 + 折叠「▼ all N / ▲ fewer」;不让单结果淹没名录。
- **绝对 vs 相对同文件**:同一被打开文件的绝对/相对写法去重(路径边界后缀匹配),但**同名异目录**(`src/index.js` 开、`test/index.js` 只见)MUST 保留为不同项。
- **capability 定位**:skill/MCP 卡片把 ledger label 反解回块 resKey(`skill: X → skill::X`、`MCP: Y → mcp::Y`)才能定位到上下文块;解不出则只 setPlayhead 不高亮。
- **空 session / 无资源**:六组全空 → 显「no resources tracked yet」占位,不留空白右页。

## Risk / 回滚
- 渲染是**纯函数**(`resource_events` + playhead → HTML),用固化真实 trace 回归;改分组/状态逻辑不动数据层,可独立回退到上一绿点(render gate)。
- 检出误差(only-seen 漏/误收、kind 误分)属 adapter(3.1)范畴,回滚在那边;本部件对坏数据 MUST 优雅降级(标注 + 占位),不 throw。

## Extensions
- **only-seen 跨 session 聚合**:把「只见其名」(`event='seen'`,D8)接入跨 session「哪些文件被瞥见但从未打开」聚合(3.5 全表)。
- 资源 **diff 视图**:相邻两步「新进 / 被 evict」的资源增量,和 cache-break(3.3)对齐看「context 换血带走了哪些文件」。
- 人工纠正被误分类/误检的资源(记为下游,非 v1)。
- 更多 harness 的 resource 语义(Codex 的文件/工具、DeepSeek 的读)照 3.1 `parseResources` 加,本部件零改动。
