# asight · RFC 4.7 — 本机网络环境(D41 · VPN 感知)

> **状态**:**只写了 Windows 一半**。macOS、Linux 与 Windows 以外的产品适配待写;在那之前它们按 1.6 §6 报「不知道」加原因。
> **前置**:D28(哨兵块只剥块)· D29(经控制口生效、复核)· D31④⑤ · D38 · D39⑧⑩([1.6](1.6-cli.md) §6、§9)。使用方:[4.8](4.8-win-collector.md)(Windows 采集器的 VPN 块)。
> **需求**:机子上装了 VPN 软件时,asight 自动感知,并在 CLI 或 GUI 里显示它改了哪些地方,力求所有改动可追踪、可撤销。
> **标注**:同 4.8;[E*] 见 4.8 §0。本单元的验收编号 N1… 只在本单元内有效。

## Goal

- 只读地认出本机的代理 / VPN 软件:哪个产品、什么模式、哪个本地端口、TUN 与系统代理开没开。
- asight 往 VPN 里写东西时,只经本单元的具名写入,每一处都入账、可撤、核对生效(1.6 §6 的四条)。
- 发现 asight 写的东西被改、被抹、没生效,报出来;从不悄悄改回。

## 1. D31⑤ 的修订

- **原文**:D31⑤「不依赖、不修改用户的 VPN」。
- **冲突**:4.8 的 VPN 块要写 Clash Verge Rev 的全局脚本。D39⑧已经写了「asight 在 VPN / 代理软件里的每处改动与 agent 文件同样入账」,以 asight 会写 VPN 为前提;D31⑤ 本身没改过。
- **改为**:asight 可以写用户的 VPN 软件,但只限:
  1. 本单元列为「可写」的产品(Windows 首版只有 Clash Verge Rev);
  2. 具名写入(§4):一个哨兵块、asight 自己的规则文件、asight 自己的组的选择、刷新 asight 自己的规则提供者、把带块的运行时配置推回去;
  3. 每一处入账、先备份、回执列出、`off` 撤,读运行时核对(1.6 §6)。
- **仍不做**:不改用户的节点、组(`include-all` 的过滤例外,4.8 §3.6,单列待复核)、规则、模式、TUN、系统代理、订阅;不重启 VPN 核心;不存、不印任何凭据,控制口的 secret 只在内存里用来连它。
- **「不依赖」**:块在 asight 不在时回退到用户原来的路(4.8 §3.3);VPN 退出时块随它的运行时消失。agent 依赖的是用户自己的 VPN,不是 asight。

## 2. 探针(Windows)

只读;每项读不到写「不知道」加原因(1.6 §9.4 的闭集,另加 `not-adapted`:认出了产品或有端口在听,但还没有人读它的设置,§6;1.6 §9.4 的闭集在 CLI T13 落地时收进它,在那之前 `probe.mjs` 的 `PROBE_UNKNOWN_REASONS` 是它的来源)。`detect(facts, {products})` 是纯函数:进程快照、LISTEN 行、系统代理、网卡与 Verge 适配器的 `facts()` 由平台给(Windows 上 `arch/win32/netfacts.mjs`,Task 10),`probe.mjs` 自己不读文件、不开套接字。「不知道」的条目是 `{what, reason, product?, port?, detail?}`;进程快照读不到时 `products` 是 `null`(不知道),读到而表里一个都没在跑是 `[]`。产品自己说的(控制口的 `tun.enable`、`verge.yaml`)先于网卡列表推出来的 TUN;`sing-box.exe` 这类两个产品共用的映像,只有其中恰好一个的自有映像在跑时才算它的,否则报「不知道 · 未适配」加映像名与候选。

| 事实 | 怎么读 |
|---|---|
| 在跑的代理软件 | 助手的进程快照:映像名与路径对 §6 的产品表 |
| 本地端口与属主 | 套接字表的 LISTEN 行 → pid → 产品 |
| 系统代理 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` · `ProxyServer` · `ProxyOverride` · `AutoConfigURL`(经助手读注册表) |
| TUN | 网卡列表(.NET `NetworkInterface`)里有该产品的虚拟网卡,且默认路由经它 |
| 产品的设置 | 只读该产品的数据目录(§3);只取 §3 列出的字段 |
| 产品的运行时 | 经它的控制口 `GET /version`、`GET /configs`(只留 `mode`、`mixed-port`、`tun.enable`、`find-process-mode`)、`GET /proxies/asight-*`、`GET /providers/rules`(列表;只取 `asight-r-*` 的 `ruleCount`,别的当场丢掉。v1.19.32 没有 `GET /providers/rules/<名字>`,只有 `PUT`,读它回 405 [mihomo `hub/route/provider.go`];评审 2026-10-07)、`GET /rules`(只在内存里挑出匹配某个形态映像名或路径的 `PROCESS-*` 规则,留序号与类型,4.8 §3.4)、`GET /group/asight-*/delay`(本机探测,4.8 §3.3) |

- 从不调:`/connections`、`/logs`、`/traffic`、`/proxies`(不带名字)、`/providers/proxies`。它们含本机所有程序的连接,或节点与订阅。
- `find-process-mode` 是 `off` 时块里的进程规则全部不起作用:报 `find-process-off`(§5),asight 从不改它(不 `PATCH /configs`)。mihomo 的默认是 `strict` [源码 `config/config.go`];Verge 2.5.7 写的值 T0 读(4.8 W60)。
- 结果写 `~/.asight/netenv.json`(1.6 §6;Windows 上靠用户目录的默认 ACL,4.8 §7):产品、版本、模式、`find-process-mode`、TUN、系统代理、混合端口、控制口可用否、脚本可写否、服务模式否,与各形态经不经过它。不含 secret、订阅地址、节点名、组名(asight 自己的除外)。

## 3. Clash Verge Rev 适配器(Windows)

`src/netenv/adapters/clash-verge-rev.mjs`。

### 3.1 认出它

- 进程:`clash-verge.exe`(GUI)与 `verge-mihomo.exe` / `verge-mihomo-alpha.exe`(核心);服务模式另有 `clash-verge-service.exe`(SYSTEM)。
- 数据目录:`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\`(在跑核心的命令行 `-d` 优先)。

### 3.2 只读的字段

| 文件 | 只取 |
|---|---|
| `verge.yaml` | `enable_tun_mode` · `enable_system_proxy` · `verge_mixed_port` · `enable_service_mode`(没有就按服务进程在不在判) |
| `config.yaml` / 运行时 `clash-verge.yaml` | `mode` · `mixed-port` · `find-process-mode` · `external-controller` · `external-controller-pipe` · `secret`(只进内存) |
| `profiles.yaml` | 全局脚本那一项的文件名(`uid: Script`),当前订阅的 uid(只用来判「重新激活」是否发生过,不读订阅内容) |
| `profiles\Script.js` | asight 的哨兵块在不在、块的 sha256;块外不解析 |

- 运行时 `clash-verge.yaml` 含节点与订阅凭据。`payload` 策略(4.8 §4.1)要读它、拼块、推回;整份只在内存里,不落盘、不进日志、不进 `flows/`。

### 3.3 控制口

- 发现顺序(D29 的 Windows 写法):枚举 `\\.\pipe\` 里以 `verge-mihomo` 开头的管道(2.5.7 的名字带一段随机十六进制)→ 在跑核心命令行的 `-ext-ctl-pipe`(服务模式下核心是 SYSTEM 进程,Medium 读不到它的命令行)→ 运行时 yaml 的 `external-controller-pipe` → 运行时 yaml 的 `external-controller`(TCP,只认回环地址,secret 只进内存)。名字里的随机段不进日志与 `netenv.json`。
- **只认**:答 `GET /version`,且管道的服务端进程(`GetNamedPipeServerProcessId`)或 TCP 端口的属主是 Verge 安装目录下的 `verge-mihomo*.exe`,属本用户;服务模式下属主在 Medium 读不到,改核管道的所有者是 SYSTEM 且 `clash-verge-service` 在跑(助手现在没有读安全描述符的动词,所以实现用「属主进程在会话 0、映像名是 `verge-mihomo*.exe`、在跑的 `clash-verge-service.exe` 在 Verge 安装目录下」代替;要不要加 `pipe-owner` 动词收紧它,OPEN 4)。`judgeServer({ps, serverPid, installDirs})` 在发任何请求之前判;「Verge 安装目录」= 在跑的 `clash-verge.exe` / `clash-verge-service.exe` 所在目录加 `installDirs`;理由 `why` ∈ `owner-unreadable` · `not-verge` · `other-user`。`ASIGHT_MIHOMO_PIPE` 钉住一个端点时不做这一判(测试用)。别人开的同名管道一律不认:`payload` 会把含订阅凭据的整份配置发过去。`ASIGHT_MIHOMO_PIPE` 可钉死(测试用,永不触达真 Verge)。
- 都不答:`live` 报「不知道」加试过的位置;`off` 退出 1(1.6 §6)。

### 3.4 能写什么(具名写入)

| 写入 | 做什么 | 入账为 |
|---|---|---|
| `writeScriptBlock(block)` / `stripScriptBlock()` | `Script.js` 里插入 / 剥掉 asight 哨兵块;块外一字不动(D28) | `vpn-script-block`(文件、哨兵、块的 sha256、备份) |
| `writeRuleFile(g, lines)` / `removeRuleFile(g)` | 数据目录 `asight\route-<g>.txt` | `vpn-rule-file`(asight 自己的文件,撤 = 删) |
| `putSelect(g, name)` | `PUT /proxies/asight-sw-<g>`,`name` ∈ {`PASS`, `asight-fb-<g>`} | `vpn-runtime-select`(运行时,不备份;回执列出) |
| `refreshProvider(g)` | `PUT /providers/rules/asight-r-<g>` | 不入账(只刷新) |
| `pushPayload(runtime)` | `PUT /configs?force=true {payload}`;`payload` = 内存里的运行时配置拼入或剥掉块 | `vpn-runtime-block`(运行时,不备份;回执列出) |

- 控制口客户端(`src/netenv/mihomo/controller.mjs`)只放行上表的写与 §2 的读:路径是白名单,写的名字必须以 `asight-` 开头。别的路径直接抛错(N9)。失败的回答只带核心的**固定消息**(`Unauthorized` · `Body invalid` · `Resource not found` · `Selector update error: proxy not exist`,真核心 v1.19.32 实测),别的消息和装着它的 JSON 一律不交出去:核心拒绝一份推上去的配置时,话里带着用户自己的组名、节点名与整条规则,有的带引号、有的不带(`rules[0] [DOMAIN,x.example,<组>] error: proxy [<组>] not found`),按引号打码挡不住。所以 `pushPayload` 失败只返回 `{status, reason}`(`reason` ∈ `refused` · `controller-unreadable` · `runtime-shape` · `runtime-unreadable`)。
- 哨兵:`// >>> asight collector (managed by asight on) >>>` … `// <<< asight collector <<<`。与旧采集的 `atrace desktop capture` 块是两个块,互不碰(旧块归 1.6 §4 的 `legacy.mjs`)。
- 文本一侧(T5,W10)是三个纯函数 `insertScriptBlock()` / `stripScriptBlock()` / `scanScript()`,在 `src/off/script-block.mjs`:撤销要跑同一份剥(1.6 R3:独立副本只 import `node:*` 与 `src/off`;D28 的逐字节保证系在这一份上,不留两份),`src/netenv/mihomo/rules.mjs` 再导出,适配器只有一个入口;适配器的 `writeScriptBlock()` / `stripScriptBlock()` 在它外面加读写、备份与入账。块放在文件最后、前面隔一个换行(文件自己的 LF 或 CRLF),剥掉就是去掉这个换行与块的各行,文件逐字节回到原样;块外一字不动,块前后用户写的东西都在。哨兵行被改坏(整行不等、另一行带着哨兵字样、缺一端、嵌套)→ `ok:false` 加原因,文件不动,插入也不碰它;粘贴了两次的两个块都剥。`scanScript()` 给每个块的文本(统一成 LF,哈希不随换行风格变)。插入 = 先剥已有的再追加,所以重复插入等于一次。
- 适配器给上层(Task 8 的 `vpnblock.mjs`)的是**数据**:`applyGroups({groups:[{g,on,lines}], block})` → `{ok, exit, rows[{g,want,strategy,steps,live,now,fbNow,ruleCount,reason,state}], receipts, lines}`(`state` ∈ verified · not-live · unknown · refused);`installBlock({block, blockText, groups})` = 写块加 `applyGroups`;`removeBlock({groups})` = 全部关(读回)、剥块、删规则文件,并带 `residue`(运行时里不起作用的块、`cache.db` 的一条选择,§4);`drift({groups})` 与 `finding(code, extra)` 给 §5 的码。适配器**不写事件**:D38 的 `where`、`event`、`code` 由上层按这些返回值发。账本(`ledger`)是注入的接口,没有它任何写入抛 `TypeError`(CLI T3 的 `manifest.mjs` 落地后接线)。
- `processRulesNaming(forms)` → `{ok, rules:[{index, type, forms}], reason}`:`forms` 是 `[{id, imageNames, imagePaths}]`,只有序号、类型与形态 id 出去,组名、域名、节点名当场丢掉(N14)。
- `pickApply({blockInRuntime, serviceMode, controllerWritable, payloadAccepted})` → `{on, off}`(纯函数;各是按顺序落地的钥匙 `select` · `provider` · `payload` · `none` 的列表),入参与服务模式的取舍见 4.8 §4.1。
- `verify(g)` → `{live, now, fbNow, ruleCount, reason}`(`live`:`true` 开、`false` 关、`null` 不知道),读 `asight-sw-<g>` 与 `asight-fb-<g>` 的 `now`、提供者列表里 `asight-r-<g>` 的 `ruleCount`。
- 控制口客户端的读白名单 = §2「产品的运行时」那一行;`/connections` `/logs` `/traffic` 不在其中,Verge 与 asight 自带的 mihomo 都一样(4.8 §5.3 原有的「自带 mihomo 的 `/connections` 例外」已删)。

## 4. 入账

- 每条具名写入一项清单(1.6 R1、R2):`kind` 见上表;文件类带 `pre_sha256`、`backup`、`undo_by_hand`;运行时类带 `undo_by_hand`(「去 Clash Verge → 订阅,点当前订阅重新激活」)。
- `off`:按清单逆序撤;文件类回到 `pre_sha256` 才删备份;用户改过 `Script.js`(块外)→ 只剥块,报「已撤销,但不逐字节相同」,备份留下。
- 运行时残留(4.8 §4.3):`status` 与回执各一行,直到 Verge 重新生成运行时;不算「没撤干净」。

## 5. 漂移与码(`vpn-block-*`)

守护进程的 5 s 核对看 `Script.js`、规则文件、`verge.yaml`、`profiles.yaml` 的大小与 mtime;变了再细读。控制口每 30 s 读一次 §2 的运行时字段。

| 码 | 类 | 什么 | 命令(asight 的在前) |
|---|---|---|---|
| `vpn-block-missing` | 失败 | 期望开,`Script.js` 里没有块(用户删了,或 Verge 重置了脚本) | `asight on`(重写块;先印计划) |
| `vpn-block-changed` | 失败 | 块的 sha256 与清单不同 | `asight on`(按清单重写);想保留你改的:`asight off` |
| `vpn-block-not-live` | 失败 | 文件里有块,运行时没有(还没重新激活;或块的代码出错,返回了原配置);或块在运行时、期望为开,`asight-sw-*` 却是 `PASS`(子因 `select-reset`:Verge 重启丢了选择,或你在 Verge 里切的;守护进程不自己切回,4.8 §4.1 与 OPEN 11) | `gui`:Clash Verge Rev → 订阅 → 点当前订阅;仍不行:`asight doctor` |
| `vpn-block-unverifiable` | 失败 | 控制口读不到,不知道块生没生效 | `asight status` 看试过的位置;`gui`:Clash Verge Rev → 设置 → 外部控制 |
| `vpn-rule-file-missing` | 失败 | 期望开,规则文件不在 | `asight on` |
| `vpn-service-copy` | 提示 | 服务模式下规则文件被拷进服务目录,改原文件不生效(4.8 §4.1) | 无;asight 改用 `select` 与 `payload` |
| `clash-mode-bypass` | 失败(期望开时) | 全局或直连模式 | `gui`:Clash Verge Rev → 代理 → 规则 |
| `find-process-off` | 失败(期望开时) | `find-process-mode` 是 `off`,块里的进程规则不起作用 | `gui`:把 `find-process-mode` 改成 `strict` 或 `always`(4.8 §10.4);asight 不替你改 |
| `route-loop` | 失败 | 生成时发现进程规则匹配 asight 自己(4.8 §3.4) | `asight on`;仍有:`asight off` |

- 都写 `where:'netenv'`;放 `src/health/codes.mjs` 的 `NET_*` 块(与 1.6 共用,先落地的一方加)。
- 产品被升级、退出、换成别的产品 → 1.6 的 `netenv-changed`;asight 不自己改,`status` 印 `asight on`。

## 验收(可跑 check)

单元测试注入助手、fs、控制口;[WinVM] 同 4.8。现在都是计划。

1. **N1 只读的探针**:夹具里的 `config.yaml` 带 secret `s3cr3t`、订阅地址、节点名:`netenv.json`、`status`、`doctor` 里都没有这几个串;字段与 §2 的表相等。
2. **N2 认不出**:注入一个认不出的 LISTEN 属主:报「不知道 · 未适配」加映像名,不报「无」。
3. **N3 发现顺序**:四种来源各缺一种,`discover()` 按 §3.3 的顺序取到第一个答话的。
4. **N4 只认自己的**:注入一个答 `/version`、但服务端进程属别的用户的同名管道:不认,`live` 为「不知道」,零次 `PUT`。
5. **N5 哨兵块**:插入再剥掉,`Script.js` 逐字节相同;用户在块外加了一行之后剥:那一行还在;哨兵被改坏:`ok:false`,文件不动(D28)。
6. **N6 入账**:每个具名写入都有清单项;文件类有备份;运行时类有 `undo_by_hand`;回执行数 == 清单项数。
7. **N7 漂移**:§5 每个码一份注入事实,只触发它;`status` 的命令与表相等。
8. **N8 运行时只在内存**:`pushPayload` 前后,`~/.asight/` 下没有新文件含夹具的订阅地址;`flows/` 也没有。
