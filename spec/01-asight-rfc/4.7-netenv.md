# asight · RFC 4.7 — 本机网络环境(D41 · D43 只读)

> **状态**:**只写了 Windows 一半**。macOS、Linux 与 Windows 以外的产品待写;在那之前它们按 1.6 §6 报「不知道」加原因。**D43 起只读**:asight 不往任何 VPN / 代理软件里写东西;原有的 Verge 写入、入账与漂移码撤回。
> **前置**:D31④⑤ · D38 · D39⑧⑩([1.6](1.6-cli.md) §6、§9)· D43。使用方:[4.8](4.8-win-collector.md)(代理模式的上游 §2.2、`vpn-catches-asight` §3.4、拓扑 §10)与 1.6 §9 的拓扑和诊断。
> **需求**:机子上装了 VPN 软件时,asight 自动感知,并在 CLI 或 GUI 里显示它改了哪些地方,力求所有改动可追踪、可撤销。D43 之后不再有 with vpn 模式,感知与显示照旧;D43 之后 asight 在 VPN 里没有改动可显示。
> **标注**:同 4.8;[E*] 见 4.8 §0。本单元的验收编号 N1… 只在本单元内有效;撤回的编号留着、标「撤回(D43)」。

## Goal

- 只读地认出本机的代理 / VPN 软件:哪个产品、什么模式、哪个本地端口、TUN 与系统代理开没开。
- 把这些事实交给代理模式:每个形态的上游(4.8 §2.2)、拓扑(1.6 §9)、用户 VPN 里点名 asight 进程的规则(`vpn-catches-asight`,4.8 §3.4)。
- 从不写用户的 VPN / 代理软件:不写文件、不调控制口的写接口、不改模式、TUN、系统代理(D31⑤ · D43)。

## 2. 探针(Windows)

只读;每项读不到写「不知道」加原因(1.6 §9.4 的闭集,另加 `not-adapted`:认出了产品或有端口在听,但还没有人读它的设置,§6;1.6 §9.4 的闭集在 CLI T13 落地时收进它,在那之前 `probe.mjs` 的 `PROBE_UNKNOWN_REASONS` 是它的来源)。`detect(facts, {products})` 是纯函数:进程快照、LISTEN 行、系统代理、网卡与 Verge 适配器的 `facts()` 由平台给(Windows 上 `arch/win32/netfacts.mjs`,Task 10),`probe.mjs` 自己不读文件、不开套接字。「不知道」的条目是 `{what, reason, product?, port?, detail?}`;进程快照读不到时 `products` 是 `null`(不知道),读到而表里一个都没在跑是 `[]`。产品自己说的(控制口的 `tun.enable`、`verge.yaml`)先于网卡列表推出来的 TUN;`sing-box.exe` 这类两个产品共用的映像,只有其中恰好一个的自有映像在跑时才算它的,否则报「不知道 · 未适配」加映像名与候选。

| 事实 | 怎么读 |
|---|---|
| 在跑的代理软件 | 助手的进程快照:映像名与路径对 §6 的产品表 |
| 本地端口与属主 | 套接字表的 LISTEN 行 → pid → 产品 |
| 系统代理 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyEnable` · `ProxyServer` · `ProxyOverride` · `AutoConfigURL`(经助手读注册表) |
| TUN | 网卡列表(.NET `NetworkInterface`)里有该产品的虚拟网卡,且默认路由经它 |
| 产品的设置 | 只读该产品的数据目录(§3);只取 §3 列出的字段 |
| 产品的运行时 | 经它的控制口,只读:`GET /version`、`GET /configs`(只留 `mode`、`mixed-port`、`tun.enable`)、`GET /rules`(只在内存里挑出点名 asight 内核或引擎映像的 `PROCESS-*` 规则,留序号与类型,§3.4、4.8 §3.4) |

- 从不调:`/connections`、`/logs`、`/traffic`、`/proxies`(不带名字)、`/providers/proxies`。它们含本机所有程序的连接,或节点与订阅。
- 结果写 `~/.asight/netenv.json`(1.6 §6;Windows 上靠用户目录的默认 ACL,4.8 §7):产品、版本、模式、TUN、系统代理、混合端口、控制口可用否、服务模式否,与各形态的上游是不是它(4.8 §2.2)。不含 secret、订阅地址、节点名、组名(asight 自己的除外)。

## 3. Clash Verge Rev 适配器(Windows)

`src/netenv/adapters/clash-verge-rev.mjs`。

### 3.1 认出它

- 进程:`clash-verge.exe`(GUI)与 `verge-mihomo.exe` / `verge-mihomo-alpha.exe`(核心);服务模式另有 `clash-verge-service.exe`(SYSTEM)。
- 数据目录:`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\`(在跑核心的命令行 `-d` 优先)。

### 3.2 只读的字段

| 文件 | 只取 |
|---|---|
| `verge.yaml` | `enable_tun_mode` · `enable_system_proxy` · `verge_mixed_port` · `enable_service_mode`(没有就按服务进程在不在判) |
| `config.yaml` / 运行时 `clash-verge.yaml` | `mode` · `mixed-port` · `external-controller` · `external-controller-pipe` · `secret`(只进内存) |

- 运行时 `clash-verge.yaml` 含节点与订阅凭据:只取上表几项,整份只在内存里,不落盘、不进日志、不进 `flows/`。D43 起不读 `profiles.yaml` 与 `Script.js`(那是为 VPN 块读的)。

### 3.3 控制口

- 发现顺序(D29 的 Windows 写法):枚举 `\\.\pipe\` 里以 `verge-mihomo` 开头的管道(2.5.7 的名字带一段随机十六进制)→ 在跑核心命令行的 `-ext-ctl-pipe`(服务模式下核心是 SYSTEM 进程,Medium 读不到它的命令行)→ 运行时 yaml 的 `external-controller-pipe` → 运行时 yaml 的 `external-controller`(TCP,只认回环地址,secret 只进内存)。名字里的随机段不进日志与 `netenv.json`。
- **只认**:答 `GET /version`,且管道的服务端进程(`GetNamedPipeServerProcessId`)或 TCP 端口的属主是 Verge 安装目录下的 `verge-mihomo*.exe`,属本用户;服务模式下属主在 Medium 读不到,改核管道的所有者是 SYSTEM 且 `clash-verge-service` 在跑(助手现在没有读安全描述符的动词,所以实现用「属主进程在会话 0、映像名是 `verge-mihomo*.exe`、在跑的 `clash-verge-service.exe` 在 Verge 安装目录下」代替;要不要加 `pipe-owner` 动词收紧它,OPEN 4)。`judgeServer({ps, serverPid, installDirs})` 在发任何请求之前判;「Verge 安装目录」= 在跑的 `clash-verge.exe` / `clash-verge-service.exe` 所在目录加 `installDirs`;理由 `why` ∈ `owner-unreadable` · `not-verge` · `other-user`。`ASIGHT_MIHOMO_PIPE` 钉住一个端点时不做这一判(测试用)。别人开的同名管道一律不认:连上去就会把 secret 发过去。`ASIGHT_MIHOMO_PIPE` 可钉死(测试用,永不触达真 Verge)。
- 都不答:`live` 报「不知道」加试过的位置;`off` 退出 1(1.6 §6)。

### 3.4 不写(D43)

- 原有的具名写入(`Script.js` 的哨兵块、规则文件、`asight-sw-*` 的选择、刷新规则提供者、推送运行时)、`pickApply()`、`verify()`、`applyGroups()` / `installBlock()` / `removeBlock()` 与它们的入账撤回;代码由 4.8 计划的 Task 6r 删。
- 控制口客户端以 `createController({…, own:false})` 连用户的 VPN:只放行 §2 的读,任何写方法(`PUT` `PATCH` `POST` `DELETE`)在客户端就抛错、不发出(N9)。只有 asight 自己的内核用 `own:true`,它的端点只来自 `forwarder.lock`(4.8 §1)。
- 失败的回答只带核心的**固定消息**(如 `Unauthorized`、`Resource not found`,真核心 v1.19.32 实测),别的消息和装着它的 JSON 一律不交出去:核心的错误话里可能带着用户的组名、节点名与规则。
- `processRulesNaming(images)`- `processRulesNaming(images)`(**未定:不要这条检测时,它与 `GET /rules` 的读一起删,4.8 OPEN 24**)→ `{ok, rules:[{index, type, images}], reason}`:`images` 是 asight 的内核与引擎的映像名与路径;只在内存里挑出点名它们的 `PROCESS-*` 规则(含嵌在 `AND` / `OR` / `NOT` 里的),只有序号、类型与命中的映像→ `{ok, rules:[{index, type, images}], reason}`:`images` 是 asight 的内核与引擎的映像名与路径;只在内存里挑出点名它们的 `PROCESS-*` 规则(含嵌在 `AND` / `OR` / `NOT` 里的),只有序号、类型与命中的映像出去,组名、域名、节点名当场丢掉(N14)。点名 agent 映像的规则不挑:D43 只为它标一句(4.8 §2.1 末)。
