# asight · RFC 3.2 — 归一化模型(★★ 中心契约)

> **服务意图(A2)**:意图 ①(blocks → 忠实回放)+ 意图 ②(usage/cache_events → 真实 cache 叠加)的**共享底座**;也是"加 harness 不改前端主干"(AC-3)的技术兑现——四种线格式(D37)忠实落进同一组对象。
> **受众**:人(核对这组表能否同时承载三家)+ agent(据此实现具名查询返回的对象形状)。
> **前置**:术语见 [0.0-overview](0.0-overview.md);provider 事实来自已验证调研(见本文件末「provider→canonical 映射」)。

## Goal
定义一组**对象与 canonical 字段** + 语义,使 D37 的七个 harness、四种线格式(Anthropic Messages / OpenAI Responses over HTTP 或 WebSocket / OpenAI Chat Completions)的真实流量都能**忠实落进同一形状**。原始 NDJSON 是逐字源真相;本单元定义的是**读取侧的形状**:具名查询([3.5](3.5-query-layer.md))从段与段索引([4.2](4.2-storage-etl.md))算出它,不另存一份派生真相。

## Out-of-scope
- 记录**存在哪、怎么被定位** → [4.2](4.2-storage-etl.md);**哪个查询返回它** → [3.5](3.5-query-layer.md);**provider→对象 的解析** → [3.1](3.1-adapter-contract.md)。
- cache 语义细节(命中/断点/TTL 规则)→ [3.3](3.3-cache-model.md);session/fork 判定 → [3.4](3.4-session-identity.md)。

## Plan(选定方案 + 取舍)

**选定**:7 组对象(外加改包的 `interventions` 与 `calls` 两个标记字段,见 §干预记录),其中 **context 分成 `block_contents`(按 `content_hash` 去重的块内容)+ `call_blocks`(调用 → 块的映射)**;usage 归一化到**固定 canonical 角色**。
**备选(未选)**:① blocks-per-call 全量存(每 call 存 500 行完整块)——简单,但 append-only 语境下同一块跨百 call 重复 → 10 万+冗余行、且 cache-break 要跨行比全文;② 只给原始字节、不定 canonical 形状——每个部件各解一遍,回到反复解析(见 D5)。
**取舍**:块内容按 `content_hash` 认同一块,`call_blocks` 只带 hash 与序号 → 载荷小,且 cache-break 可由相邻 call 的 `content_hash` 序列比出,查询据此算出 `cache_events`([3.3](3.3-cache-model.md))。

## 对象与字段

> **保真兜底(承不变式 2、4([0.0](0.0-overview.md) §核心不变式))**:每个对象带一个 `extra` 字段,装 provider 原生对象里**未映射进 canonical 字段的其余字段**(无损、可直接读、日后重要就提成正式字段)。于是 **canonical 字段(已知/跨-provider)+ `extra`(其余一切)= 原始对象的完整 surface**;`raw_ref` 再给逐字回源。**未知的新 agent/API 字段永不静默消失**——它进 `extra` 且被计数(见 `calls.unmapped_count` + §未映射告警面)。

```
-- 一条 session = 某 harness 一次任务的全部上下文流(核心对象)
sessions(
  session_id TEXT PK,        -- asight 分配的稳定 id
  harness TEXT,              -- D37:cc | codex | opencode | kimi | dsh | hermes | zcode(取自 proc.agent,MUST NOT 由 UA 推;没有 proc 的旧记录才按 UA 推断、extra 记 harness_inferred,与看板同一规则);旧值 claude-code / deepseek-cli 仍可读
  provider TEXT,             -- 摘要(D37):主线调用的线格式 anthropic | openai-responses | openai-chat,主线混用时 = mixed;逐调用见 calls.wire_format;旧值 openai / deepseek 仍可读
  native_id TEXT,            -- 线上原生 id(见 3.4);Hermes 自定义端点等可能为 NULL(合成)
  parent_session_id TEXT,    -- 子 agent / 子线程的父(见 3.4)
  fork_of_session_id TEXT,   -- 分叉自哪条 session(Codex 的 fork 待线上信号,见 3.4;others best-effort)
  forked_at_seq INT,         -- 从父的第几步分叉
  title TEXT, cwd TEXT, entrypoint TEXT,
  started_at TIMESTAMP, ended_at TIMESTAMP,
  native_id_confidence TEXT, -- high | medium | low(合成 = low)
  extra JSON                 -- 未映射的 provider 原生 session 元数据(thread_id/turn_id/agent_role/installation_id…)
)

-- 一次上游调用(class='llm' = 会话推理;class='control' = 会话周边 session-less 底噪,见 D9)
calls(
  call_id TEXT PK, session_id TEXT, seq INT,   -- seq = session 内步序;session_id 对 class='control' 为 NULL(session-less)
  ts TIMESTAMP, endpoint TEXT, model TEXT, stream BOOL,
  class TEXT,                -- llm | control(见 D9);llm=会话推理路径,control=telemetry/registry/account/config 等 session-less 底噪
  control_kind TEXT,         -- NULL 除非 class='control';归一化类目 config|account|registry|telemetry|other(端点级判定在 adapter,见 3.1)
  lane TEXT,                 -- main | subagent | monitor | aux | probe(aux 子类 notify/titlegen/quota 是渲染期投影,不入 schema——见 D8)
  request_bytes BIGINT,      -- 线上请求体字节数(context_chars);D40 起信封有 body_wire_bytes 时取 body_wire_bytes.req(超过存储上限的也计全长)
  raw_ref TEXT,              -- 指回 NDJSON 源(逐字真相锚)
  wire_format TEXT,          -- D37:本调用的线格式 anthropic | openai-responses | openai-chat(按端点与 body,同一 session 可混用)
  vendor TEXT,               -- D37:厂商,查询由信封 host 派生(anthropic | openai | deepseek | moonshot | zai | openrouter …,不认识 = NULL);cache 语义与单价按它取
  transport TEXT,            -- D37:http | ws(ws = WebSocket 连接上的一次逻辑调用)
  context_state TEXT,        -- D37:complete | reconstructed(跨记录拼接、前序记录都在)| partial(缺前序记录,或服务端继承的部分还原不出)| server_edited(响应报告服务端删改了上下文);非 complete MUST 就地标
  observer_effect JSON,      -- D37:采集引起的客户端行为变化(如 CC 请求体 gzip 被关、Codex 换 rustls 并报 h2);NULL = 无已知变化
  harness TEXT,              -- D40:调用级 harness id(读取侧表 src/dissect/harnesses.mjs 的 id;由 proc.agent 映射,没有 proc 的旧记录按 UA 推断,同 sessions.harness 的规则);control 行也有,按 harness 统计大小用
  host TEXT,                 -- D40:信封 host(TLS SNI 等,见 4.1);没有时取 req_headers.host
  traffic_class TEXT,        -- D40 · D60③:类别名(可编辑的类别表,内置的是 llm | token-count | session-sync | telemetry | files | account | other;信封有就取它,D40 之前的记录由读取侧用同一张类别表推算
  body_retention TEXT,       -- D40:full | log(操作者设置只记日志)| legacy-meta(D40 之前的非 LLM,只存了长度);非 full MUST 就地标
  response_bytes BIGINT,     -- D40:线上响应体字节(body_wire_bytes.resp,超过存储上限的也计全长);没有这个字段的旧记录为 NULL = 未记录,MUST NOT 当 0
  record_bytes BIGINT,       -- D40:该记录那一行 NDJSON 的字节数(含结尾换行)= 未压缩的存储字节
  stop_reason TEXT, duration_ms INT, error TEXT,
  compaction BOOL, compaction_from INT, compaction_to INT,
  unmapped_count INT,        -- adapter 未映射字段数(健康信号 + D7 自演化触发)
  intervention_kind TEXT,    -- D33:NULL = 未经干预(绝大多数);'modify-request' | 'modify-response' | 'synthesized'。映射列,不是埋进 extra(不变式 4:改过的必须就地可标)
  intervention_ref TEXT,     -- → interventions.intervention_id;NULL 除非被干预
  extra JSON                 -- 未映射的 call/response 级 provider 字段
)

-- 去重的上下文块内容(同内容跨 call 只存一次)
block_contents(
  content_hash TEXT PK,
  section TEXT,              -- tools | system | messages(归一化;Codex instructions→system、input→messages)
  role TEXT,                 -- tool | system | user | assistant | developer | ...
  kind TEXT,                 -- text | thinking | reasoning | tool_use | tool_result | image | ...
  chars INT, preview TEXT,   -- 短预览(导航用)
  text_ref TEXT,             -- 指回 NDJSON 源里该块的完整字节(不在此存全文);字节在别的记录的回复里(WebSocket 拼接)时带字段段 resp.messages.<j>,见 4.2 §回源指针(D37 门 G1)
  faithfulness TEXT,         -- verbatim | metadata | opaque | summarized | omitted | truncated
  extra JSON                 -- 未映射的块级 provider 字段(thinking.signature、reasoning.encrypted_content、tool_use.id、image.source…)
)

-- 每次 call 的有序上下文(assembly order:tools→system→messages)
call_blocks(
  call_id TEXT, seq INT,     -- 在该 call 上下文里的位置
  content_hash TEXT,         -- → block_contents;相邻 call 的 hash 序列 diff 即 cache-break 的依据(查询算出 cache_events)
  cache_control TEXT,        -- provider 原生断点(Anthropic 有;others NULL)
  volatile BOOL,             -- 每 call 变但不入 cache key(如 CC 的 billing nonce)
  resource_ref TEXT,         -- → resource_events(文件/skill/mcp 等)
  PRIMARY KEY(call_id, seq)
)

-- 归一化 usage:固定 canonical 角色,adapter 把各家字段映射进来
usage(
  call_id TEXT PK,
  input_uncached INT,        -- 真·未缓存输入(= provider 的 cache-miss)
  cache_read INT,            -- 命中/读缓存
  cache_write INT,           -- 写缓存;provider 无此概念 → NULL(≠0)
  output INT,                -- 生成(Anthropic 含 thinking)
  reasoning INT,             -- 推理 token(多为 output 子集,概念上单列)
  total_input INT,           -- provider 给了就存,没有就算(见映射表)
  extra JSON                 -- 未映射的 usage 剩余(Anthropic cache_creation.ephemeral_5m/1h 明细、server_tool_use、service_tier…)
)

-- 资源(文件/dir/link/mcp/skill/tool/image/scaffold)的生命周期事件
resource_events(
  session_id TEXT, seq INT, resource_id TEXT,
  kind TEXT, label TEXT,     -- kind: file|dir|link|mcp|skill|tool|image|scaffold(细粒度;UI 分组是渲染期投影,见 D8/2.4)
  event TEXT,                -- enter | evict | reinject | load | seen(见 D8)
  via TEXT, range TEXT,      -- 经哪个工具进来 / 读了哪段
  extra JSON                 -- 未映射的资源级字段
)
-- event='seen'(只见其名):路径出现在工具结果/散文里、但 agent 从未 Read/Write/Edit——names-only、无内容、正则推断(`extractSeenPaths`)。
--   这类行无 resource_ref/text_ref,MUST 视作 metadata 保真度,UI MUST 标「names / 非逐字」(不变式 4)。scaffold = harness 自动注入的上下文(CLAUDE.md/MEMORY.md,经 <system-reminder> 出现)。

-- 每 call 的 cache 事实(见 3.3 的两层模型)
cache_events(
  call_id TEXT PK,
  break_kind TEXT,           -- explicit-breakpoint | automatic-prefix | automatic-disk
  hit_ratio DOUBLE,          -- cache_read / total_input
  declared_breakpoints TEXT, -- provider 声明的断点位置(Anthropic;others NULL)
  structural_divergence_seq INT, -- asight 算的"相对上一 call 首个不同块";非权威,仅结构参考
  raw_divergence_seq INT,    -- D17①:不跳 volatile 的首个不同块;raw<structural ⇔ 先变块 cache-无关
  divergence_byte_offset INT,-- D17①:首个真分叉块内、相对上一 call 同位块的首个不同字节偏移(经 text_ref 回逐字源;非 preview)。NULL=整块新增/首 call
  divergence_cause TEXT,     -- D17①:结构推断成因(见 3.3 分类表)append|volatile-nonce-only|compaction|tool-array-reorder|json-key-reorder|breakpoint-out-of-window|mid-turn-retry|model-or-route-change|unknown
  prefix_sha256 TEXT,        -- D17④:cache-相关前缀 [0,structural_divergence_seq) 的**逐字源字节** SHA256(跳 volatile)= 地面真相锚(逐字字节事实,非结构估计;见 3.3)
  cache_write_billing TEXT,  -- D17:写侧计费保真标 charged|free|none|excluded(见 3.3 保真标签);none/excluded MUST NOT 当 0 求和
  ground_truth_flag TEXT,    -- D17④:NULL|ttl-rebuild|provider-contradiction(派生自 prefix_sha256 × usage;见 3.3 地面真相验证)
  extra JSON                 -- 未映射的 cache 提示(OpenAI prompt_cache_key、prompt_cache_options…)
)
-- D17① 三列(raw_divergence_seq/divergence_byte_offset/divergence_cause)皆**结构推断**,UI MUST 标「结构估计,非真实边界」(不变式 4);数值真相仍取 usage,冲突时 usage 优先(承 [3.3](3.3-cache-model.md))。
-- D17④:`prefix_sha256` 是**逐字字节事实**(权威、可独立复算,MUST hash NDJSON 逐字源、非 preview);`ground_truth_flag='provider-contradiction'` 措辞 MUST 只把疑点指向 provider 侧,MUST NOT 断言「provider 一定错」(不变式 4)。
-- D37:跨记录拼接的 call,prefix_sha256 对按装配序拼接的各块逐字字节求 hash;context_state='reconstructed' 时仍算权威;'partial'(不论缺的是拼接前序还是服务端继承的部分)与 'server_edited' 时为 NULL,ground_truth_flag 也为 NULL;UI 标「跨记录拼接」。
```

## D37 结构性变更(七个 harness · 采全)
**结构性变更([0.1](0.1-engineering-rules.md) §4)**:需求(七个 harness、三条轴、采全与「不完整」标注)来自 D37;下面的列与信封字段按调研定,合入前在 PR 正文逐条列出。
- `sessions.harness`:取值改为七个 harness id,取自信封的 `proc.agent`(D31),MUST NOT 由 UA 推;旧值仍可读。
- 线格式按调用记:新列 `calls.wire_format`(D3 修订已规定从端点读);`sessions.provider` 退为摘要(主线的线格式,混用 = `mixed`)。辅助模型、Kimi 按模型选协议、OpenCode / Z-Code / Hermes 按 provider 模板,都会让同一 session 混用线格式。
- 厂商是一等字段 `calls.vendor`:查询由信封的 `host` 派生,看板载荷逐 call 带它;cache 语义与单价按它取([3.3](3.3-cache-model.md)、[2.2](2.2-call-turn-card.md))。MUST NOT 写进 `extra`(`extra` 只装原始对象里未映射的键,派生值会破坏键集还原、让 `unmapped_fields` 每行误报)。
- 信封(D10,权威在 [4.1](4.1-capture-sources.md))追加 `transport`、`flow_id`、`ws_frames`、`ws_ext`、`ws_raw`、`body_retention`,以及`req_extra_messages`、`partial` / `partial_reasons`、`ws_truncated`、`req_body_b64` / `req_content_encoding` / `req_encoding_error`;WebSocket 上 `req_body` = 解压后的客户端消息文本,`resp` = `{kind:'ws', messages:[…]}`(服务端消息序列),`req_headers` = 升级请求的逐字头([4.6](4.6-process-collector.md) §传输与帧级记录、§记录)。读取侧怎么读:不带 `transport` 的信封读成 `transport:'http'`;信封 `partial:true` 读成 `context_state='partial'`,dissector 可收窄([3.1](3.1-adapter-contract.md));带 `req_content_encoding` 而 `req_body` 为 `null` 时先解 `req_body_b64`;`ws_truncated`、解不出的压缩请求体不改 `context_state`,看板就地标「已截断」「压缩请求体未解码」(不变式 4)。
- 新列 `calls.transport` / `calls.context_state` / `calls.observer_effect`(见上)。block 级 `faithfulness` 不加新值:拼出来的块字节确实逐字,标 `verbatim`。看板载荷同名透出这几项(服务端烘焙,前端只读 canonical,不变式 3);「跨记录拼接 / 不完整 / 服务端删改」徽标在上下文回放 [2.3](2.3-context-window.md) 与 2.6 就地显示,观测者效应在 2.2 / 2.6。
- **已定· 承载对话的旁路调用**:不加第三个 `calls.class`(D9 不动)。别的 host 上的辅助模型调用是推理,`class='llm'`、`lane='aux'`;dsh 联网搜索打的是 `…/v1/messages`,同样是推理(`lane='aux'`)。Files API 上传仍 `is_llm_call=false`(D40 起一切非 LLM 请求体都逐字,[4.1](4.1-capture-sources.md)),按现有 `classOf()`:有该 harness 的 session 键就进该 session,没有就 `class='control'`(请求体照样逐字);引用上传的 call(`ms://`、`file_id`)经 `resource_events` 连到上传记录。**D40(2026-10-07)**:`count_tokens` 的请求体也带对话,与其他非 LLM 调用一样逐字存,默认级别 `full`。依据:非 LLM 流量不是例外;实测 91 条对 8,055 条推理,原始约 +1 %,封存时与紧跟的推理请求做增量,体积不会接近翻倍。用户可 `asight classes set token-count log` 改为只记日志。

## D40 · 非 LLM 逐字与保存级别的投影
**结构性变更([0.1](0.1-engineering-rules.md) §4)**:需求(非 LLM 逐字;按 harness × 类别的保存级别,并看得到大小)来自 D40;下面的列与取值按调研定,合入前在 PR 正文逐条列出。
- `calls` 新增 6 列 `harness` / `host` / `traffic_class` / `body_retention` / `response_bytes` / `record_bytes`(见上表),照 D37 的迁移办法 `ALTER TABLE … ADD COLUMN IF NOT EXISTS`,排在 D37 列之后。`request_bytes` 改为优先取 `body_wire_bytes.req`。
- **三个字节数是整数,不设 32 位上限**:`body_wire_bytes` 按设计超过 64 MiB 上限也计全长,段索引与查询文档里都按 JS 的安全整数带它(超过 2^53 的体不存在,单条上限 64 MiB)。
- 非 LLM 调用照旧是一条 `calls`(`src/adapters/envelope.mjs` 的 `envelopeAdapter`),不出块、不出 usage;体不进载荷,看全文经 `raw_ref` 回源(本表不存全文,见 Invariants)。
- 推算的类别:D40 之前的记录没有 `traffic_class`,读取侧用采集时的同一张类别表(`src/dissect/traffic.mjs`)推算;推理(`llm`)与 `count_tokens`(`token-count`)按端点,不靠推算;只有 D40 之前的非 LLM 行(`body_retention='legacy-meta'`)的类别是「按现行规则推算」,大小视图单列这些行并注明。
- `body_retention='log'` 的推理调用:照样一行,`context_state` 不变,不出块、不出 usage 行;看板就地标「只记日志」,不显示成空回答。
- `control_kind`(读取侧 adapter 给控制面侧栏的分组 `config|account|registry|telemetry|other`)与 `traffic_class`(采集侧按数据声明的保存类别)是两套类目。D40 不合并;以后让 `control_kind` 取自 `traffic_class` 是 Extension。

## session-less 底噪(D9)
harness 在会话周边发的 telemetry / registry / account / feature-flag 调用**无 session 归属**(CC 无 `x-claude-code-session-id`)。它们仍被逐字采集,但**不属任何会话**:落 `calls.class='control'` + `session_id IS NULL`,**不进 `sessions`**——`sessions` 保持"纯会话"语义,不为底噪合成伪会话(**备选(未选)**:合成 `sessions.kind='control'` 伪会话 / 全表 nullable——避免底噪被误当真会话)。非核心流侧栏(2.6 §C)读一个投影:
```
CREATE VIEW control_calls AS
  SELECT call_id, ts, endpoint, control_kind, error, raw_ref
  FROM calls WHERE class='control';   -- session-less;会话时间轴一律 WHERE class='llm'
```

## 干预记录(D33 · v1 只此一组字段)
改请求 / 改响应是一条**普通** `calls` 行(`class='llm'`、进会话时间轴、参与前缀比对、有 cache_events),因为 `req_body` 就是真正发给上游的逐字字节,现有管线对它零改动;只多 `calls.intervention_kind` / `intervention_ref` 两个标记。干预本身的细节落一张投影表(可从源 NDJSON 的 `intervention` 字段与审计流重建):
```
interventions(
  intervention_id TEXT PK,
  call_id TEXT,              -- 改请求 / 改响应指向 calls.call_id;重发为 NULL(重发没有 calls 行)
  kind TEXT,                 -- modify-request | modify-response | synthesized | resend
  origin TEXT,               -- operator | rule(v1 只有 operator;规则设计推迟,见 5.1)
  actor TEXT, rule_id TEXT,
  at_ts TIMESTAMP,
  target TEXT,               -- req_body | resp.body
  recover TEXT,              -- splice | inline(SSE 响应只能 inline)
  base_ref TEXT,             -- 'self' | 重发时的源 raw_ref
  base_sha256 TEXT, result_sha256 TEXT,
  n_edits INT, bytes_changed INT,
  audit_ref TEXT
)
```
重发(`replays/`)**没有** `calls` 行、**没有** cache_events 行,因此结构上就不会混进会话时间轴、血缘与 cache 分析,不靠过滤条件。重发自己的真实 usage 留在 `replays/` 源流里,v1 不为它建 DB 表(需要时再加,避免过度设计)。**v1 不建 `intervention_blocks`**(「按块看改动」):改动本来就小,界面直接渲染补丁本身;等界面确实需要再加。

## 未映射告警面(保真兜底 + D7 自演化钩子)
`extra` 里的键 = adapter 当前没认识的字段。一个 view 把它们跨库聚合,回答"哪些 provider 字段我还没 surface、多常见":
```
-- unmapped_fields:自演化设施据此决定"下一个该映射什么"
CREATE VIEW unmapped_fields AS
  SELECT provider, harness, json_key AS path, count(*) AS n
  FROM calls c, sessions s, UNNEST(json_keys(c.extra)) AS t(json_key)
  WHERE s.session_id = c.session_id GROUP BY 1,2,3 ORDER BY n DESC;  -- 示意,非最终 SQL
```
- 对**人**:一眼看到"新 agent 带了什么我没接的字段"。
- 对 **D7 自演化设施**(下游 RFC):这就是它的**触发输入**——新场景 → 未映射字段浮现 → 自动设计映射/新列/新 adapter → 部署测试。承 [0.0-overview](0.0-overview.md) D7。

## 线格式 → canonical 映射(usage 表的心脏)

| canonical | Anthropic Messages | OpenAI Responses(HTTP / WS) | Chat Completions(DeepSeek 字段) |
|---|---|---|---|
| `input_uncached` | `usage.input_tokens` | `usage.input_tokens − input_tokens_details.cached_tokens − input_tokens_details.cache_write_tokens`(没报写计数按 0 减;结果不小于 0) | `usage.prompt_cache_miss_tokens` |
| `cache_read` | `usage.cache_read_input_tokens` | `usage.input_tokens_details.cached_tokens` | `usage.prompt_cache_hit_tokens` |
| `cache_write` | `usage.cache_creation_input_tokens` | `usage.input_tokens_details.cache_write_tokens` | **NULL**(无此概念) |
| `output` | `usage.output_tokens` | `usage.output_tokens` | `usage.completion_tokens` |
| `reasoning` | `usage.output_tokens_details.thinking_tokens` | `usage.output_tokens_details.reasoning_tokens` | `usage.completion_tokens_details.reasoning_tokens` |
| `total_input` | 计算 = uncached+read+write | `usage.input_tokens` | `usage.prompt_tokens` |

> **`input_uncached` 在三条线上是同一个意思**:既不是读缓存、也不是写缓存的那部分输入,即 uncached + read + write = total(Anthropic 的 `input_tokens` 本来就不含读写;Responses 的 `input_tokens` 是总数,所以要减读也减写)。Responses 上有中转报 `cache_write_tokens` 时它从 `input_uncached` 里扣掉;没报则 `cache_write` 为 NULL、减 0。看板的 `src/dissect/openai.mjs::canonUsage` 的 `fresh` 与 `mapUsage('openai-responses')` 的 `input_uncached` 是同一个数(守卫 `test/adapters/map-usage.test.mjs`)。
> SSE 场景:Anthropic 权威 output 来自 `message_delta.usage`,cache/input 来自 `message_start`;归一化在流结束后取终值(`normResp`)。
> **D37**:列按线格式分,不按厂商。dsh 走 DeepSeek 的 Anthropic 端点,usage 按 Anthropic 列取;Kimi 的 Chat Completions 把 usage 放在 `choices[0].usage`;Hermes、Z-Code 随其 provider 模板选的线格式。`cache_write` 是否 NULL 按厂商定([3.3](3.3-cache-model.md))。**OPEN**:各厂商专属的 usage 键 mock 证明不了,首次真实抓包核对后补进本表(推荐默认:不认识的键进 `usage.extra`,不猜)。

## Invariants(MUST）
- 每 `block_contents` 由 `content_hash` 去重;`text_ref`/`raw_ref` MUST 指回 NDJSON 源,本表不存全文——**派生不覆盖源真相**(不变式 2([0.0](0.0-overview.md) §核心不变式))。
- usage MUST 落 canonical 角色;**provider 专属字段名 MUST NOT 泄漏到前端/查询层**(不变式 3)。
- 每块 MUST 带 `faithfulness`;非 verbatim 的(metadata/opaque/summarized/omitted/truncated)MUST 可被 UI 就地标注(不变式 4)。
- `cache_write = NULL` 表示"该 provider 无写缓存概念",MUST NOT 填 0 冒充。
- **canonical 列 + `extra` MUST 覆盖原始对象的全部键**:adapter 未映射的字段 MUST 落 `extra`(而非丢弃),`calls.unmapped_count` MUST 如实计数——surfacing 层无声丢字段 = 违反不变式 2/4。规则的执行方在 [3.1](3.1-adapter-contract.md)。
- **干预不得污染血缘(D33)**:`calls.intervention_kind IS NOT NULL` 的 call MUST 仍按其**线上字节**(`req_body`)参与 `content_hash` 与前缀比对;重发 MUST NOT 有 `calls` / `cache_events` 行。被干预的 call MUST 在 UI 就地标「已改」,MUST NOT 让人把改后请求当成 agent 原发(不变式 4)。
- **class 与 session_id 的一致性(D9)**:`class='control'` 的 call MUST `session_id IS NULL` 且 MUST NOT 进会话时间轴查询(`WHERE class='llm'`);`class='llm'` MUST 有 `session_id`(Hermes / Kimi 合成也算,见 3.4)。`control_kind` 的端点级判定 MUST 在 adapter(3.1),前端只读归一化类目(不变式 3)。
- **细 kind + 渲染期分组(D8)**:`resource_events.kind` 存 provider-中立细粒度、`calls.lane` 到 `aux` 为止;UI 的分组(2.4 六组)与 aux 子类文案(notify/titlegen/quota)是**渲染期投影**,MUST NOT 往 schema 加 harness 专属枚举(不加 `capability` 伞 kind、不加 CC lane 子类)。

## 影响面
下游:查询层(3.5)按此形状返回文档,所有前端部件(2.x)读它。改任一字段 = 改中心契约 → 走 grep-spec 自对照闸([0.1](0.1-engineering-rules.md) §6 第 17 条)。

## 验收(可跑 check）
- **AC-1(忠实)**:对真实 CC session,由 `call_blocks`+`block_contents`+`text_ref` 重建某 call 的上下文,与 NDJSON 源逐字 diff = 0——**含 tools schema**(D15,tools 逐字捕获后纳入 AC-1);仅真正非逐字的块(加密 reasoning=opaque、SSE 重建等,已标 faithfulness)除外。
- **AC-2(usage 真相)**:`usage` 每行与该 call 线上 usage 按 canonical 映射数值一致;三 provider 各取一例通过。
- **去重生效**:一个会话里不同 `content_hash` 的块数 < Σ(每 call 的块数)。
- **AC-I(干预还原)**:对一条被改的 call,`apply(req_body, intervention.client.edits)` 的结果与已知的 agent 原始请求逐字相等且 `sha256 == result_sha256`;改任意一个 `ins` 字节 MUST 变红;`base_sha256` 对不上(基准被换 / 源 id 重复)MUST 拒绝还原、不返回错字节。重发 MUST NOT 出现在 `calls` / `cache_events` 里(`SELECT count(*) … JOIN … = 0`)。
- **D40 字段**:见上表 #5;D40 之前的记录(`{raw_chars}`)读成 `legacy-meta`,不被读成空体或完整体。

## Edge cases
- 超大 session:`call_blocks` 行数 = Σ每 call 块数;去重后 `block_contents` 远小于之。列存可扛,建 `(call_id,seq)` 索引。
- Hermes 自定义端点(及没有 body 键的 Kimi)`native_id` 缺失 → NULL + `native_id_confidence=low`(见 3.4)。
- provider 缺字段(DeepSeek `cache_write`)→ NULL,查询/叠加须容 NULL。

## Extensions
新 provider 加行不加列:只要能映射进 canonical 角色 + 落 block/section/role/kind,就无需改 schema(schema 通用性 = 适配层价值)。
