# asight · RFC 3.2 — 归一化模型(★★ 中心契约)

> **服务意图(A2)**:意图 ①(blocks → 忠实回放)+ 意图 ②(usage/cache_events → 真实 cache 叠加)的**共享底座**;也是"加 harness 不改前端主干"(AC-3)的技术兑现——三 provider 忠实落进同一组表。
> **受众**:人(核对这组表能否同时承载三家)+ agent(据此建 DuckDB DDL 与 ETL 目标)。
> **前置**:术语见 [00-overview](00-overview.md);provider 事实来自已验证调研(见本文件末「provider→canonical 映射」)。

## Goal
定义一组 DuckDB 表 + 语义,使 Claude Code(Anthropic)、Codex(OpenAI Responses)、DeepSeek-CLI(DeepSeek)的真实流量都能**忠实落进同一形状**。原始 NDJSON 仍是逐字源真相;本表是可重建的**分析投影**。

## Out-of-scope
- 表**怎么被填**(ETL)→ [4.2](4.2-storage-etl.md);**怎么被查** → [3.5](3.5-query-layer.md);**provider→表 的解析** → [3.1](3.1-adapter-contract.md)。
- cache 语义细节(命中/断点/TTL 规则)→ [3.3](3.3-cache-model.md);session/fork 判定 → [3.4](3.4-session-identity.md)。

## Plan(选定方案 + 取舍)

**选定**:7 张表,其中 **context 用 `block_contents`(去重)+ `call_blocks`(映射)两张**;usage 归一化到**固定 canonical 角色**。
**备选(未选)**:① blocks-per-call 全量存(每 call 存 500 行完整块)——简单,但 append-only 语境下同一块跨百 call 重复 → 10 万+冗余行、且 cache-break 要跨行比全文;② 只存原始不建表——回到 demo 的反复解析卡顿(见 D5)。
**取舍**:去重把"块内容"存一次(按 `content_hash`),`call_blocks` 只存整型映射 → 省空间,且**cache-break 退化成一句 SQL:比较相邻 call 的 `content_hash` 序列**。

## 表结构

> **保真兜底(承不变式 2、4([0.0](0.0-overview.md) §核心不变式))**:每张表带一个 `extra JSON` 列,装 provider 原生对象里**未映射进上表 canonical 列的剩余字段**(无损、DuckDB 可 `json_extract` 查、日后重要就提成正式列)。于是 **canonical 列(已知/跨-provider)+ `extra`(其余一切)= 原始对象的完整 surface**;`raw_ref` 再给逐字回源。**未知的新 agent/API 字段永不静默消失**——它进 `extra` 且被计数(见 `calls.unmapped_count` + §未映射告警面)。

```sql
-- 一条 session = 某 harness 一次任务的全部上下文流(核心对象)
sessions(
  session_id TEXT PK,        -- asight 分配的稳定 id
  harness TEXT,              -- cc | codex | deepseek-cli
  provider TEXT,             -- anthropic | openai | deepseek
  native_id TEXT,            -- 线上原生 id(见 3.4);DeepSeek 可能为 NULL(合成)
  parent_session_id TEXT,    -- 子 agent / 子线程的父(见 3.4)
  fork_of_session_id TEXT,   -- 分叉自哪条 session(Codex forkedFromId;others best-effort)
  forked_at_seq INT,         -- 从父的第几步分叉
  title TEXT, cwd TEXT, entrypoint TEXT,
  started_at TIMESTAMP, ended_at TIMESTAMP,
  native_id_confidence TEXT, -- high | medium | low(DeepSeek 合成 = low)
  extra JSON                 -- 未映射的 provider 原生 session 元数据(thread_id/turn_id/agent_role/installation_id…)
)

-- 一次上游调用(class='llm' = 会话推理;class='control' = 会话周边 session-less 底噪,见 D9)
calls(
  call_id TEXT PK, session_id TEXT, seq INT,   -- seq = session 内步序;session_id 对 class='control' 为 NULL(session-less)
  ts TIMESTAMP, endpoint TEXT, model TEXT, stream BOOL,
  class TEXT,                -- llm | control(见 D9);llm=会话推理路径,control=telemetry/registry/account/config 等 session-less 底噪
  control_kind TEXT,         -- NULL 除非 class='control';归一化类目 config|account|registry|telemetry|other(端点级判定在 adapter,见 3.1)
  lane TEXT,                 -- main | subagent | monitor | aux | probe(泛化 demo 的 lane;aux 子类 notify/titlegen/quota 是渲染期投影,不入 schema——见 D8)
  request_bytes INT,         -- 线上请求体字节数(context_chars)
  raw_ref TEXT,              -- 指回 NDJSON 源(逐字真相锚)
  stop_reason TEXT, duration_ms INT, error TEXT,
  compaction BOOL, compaction_from INT, compaction_to INT,
  unmapped_count INT,        -- adapter 未映射字段数(健康信号 + D7 自演化触发)
  extra JSON                 -- 未映射的 call/response 级 provider 字段
)

-- 去重的上下文块内容(同内容跨 call 只存一次)
block_contents(
  content_hash TEXT PK,
  section TEXT,              -- tools | system | messages(归一化;Codex instructions→system、input→messages)
  role TEXT,                 -- tool | system | user | assistant | developer | ...
  kind TEXT,                 -- text | thinking | reasoning | tool_use | tool_result | image | ...
  chars INT, preview TEXT,   -- 短预览(导航用)
  text_ref TEXT,             -- 指回 NDJSON 源里该块的完整字节(不在此存全文)
  faithfulness TEXT,         -- verbatim | metadata | opaque | summarized | omitted | truncated
  extra JSON                 -- 未映射的块级 provider 字段(thinking.signature、reasoning.encrypted_content、tool_use.id、image.source…)
)

-- 每次 call 的有序上下文(assembly order:tools→system→messages)
call_blocks(
  call_id TEXT, seq INT,     -- 在该 call 上下文里的位置
  content_hash TEXT,         -- → block_contents;相邻 call 的 hash 序列 diff = cache-break
  cache_control TEXT,        -- provider 原生断点(Anthropic 有;others NULL)
  volatile BOOL,             -- 每 call 变但不入 cache key(如 CC 的 billing nonce)
  resource_ref TEXT,         -- → resource_events(文件/skill/mcp 等)
  PRIMARY KEY(call_id, seq)
)

-- 归一化 usage:固定 canonical 角色,adapter 把各家字段映射进来
usage(
  call_id TEXT PK,
  input_uncached INT,        -- 真·未缓存输入(= provider 的 cache-miss)
  cache_read INT,            -- 命中/读缓存
  cache_write INT,           -- 写缓存;provider 无此概念 → NULL(≠0)
  output INT,                -- 生成(Anthropic 含 thinking)
  reasoning INT,             -- 推理 token(多为 output 子集,概念上单列)
  total_input INT,           -- provider 给了就存,没有就算(见映射表)
  extra JSON                 -- 未映射的 usage 剩余(Anthropic cache_creation.ephemeral_5m/1h 明细、server_tool_use、service_tier…)
)

-- 资源(文件/dir/link/mcp/skill/tool/image/scaffold)的生命周期事件
resource_events(
  session_id TEXT, seq INT, resource_id TEXT,
  kind TEXT, label TEXT,     -- kind: file|dir|link|mcp|skill|tool|image|scaffold(细粒度;UI 分组是渲染期投影,见 D8/2.4)
  event TEXT,                -- enter | evict | reinject | load | seen(见 D8)
  via TEXT, range TEXT,      -- 经哪个工具进来 / 读了哪段
  extra JSON                 -- 未映射的资源级字段
)
-- event='seen'(只见其名):路径出现在工具结果/散文里、但 agent 从未 Read/Write/Edit——names-only、无内容、正则推断(承 demo extractSeenPaths)。
--   这类行无 resource_ref/text_ref,MUST 视作 metadata 保真度,UI MUST 标「names / 非逐字」(不变式 4)。scaffold = harness 自动注入的上下文(CLAUDE.md/MEMORY.md,经 <system-reminder> 出现)。

-- 每 call 的 cache 事实(见 3.3 的两层模型)
cache_events(
  call_id TEXT PK,
  break_kind TEXT,           -- explicit-breakpoint | automatic-prefix | automatic-disk
  hit_ratio DOUBLE,          -- cache_read / total_input
  declared_breakpoints TEXT, -- provider 声明的断点位置(Anthropic;others NULL)
  structural_divergence_seq INT, -- asight 算的"相对上一 call 首个不同块";非权威,仅结构参考
  raw_divergence_seq INT,    -- D17①:不跳 volatile 的首个不同块(demo rawIdx);raw<structural ⇔ 先变块 cache-无关
  divergence_byte_offset INT,-- D17①:首个真分叉块内、相对上一 call 同位块的首个不同字节偏移(经 text_ref 回逐字源;非 preview)。NULL=整块新增/首 call
  divergence_cause TEXT,     -- D17①:结构推断成因(见 3.3 分类表)append|volatile-nonce-only|compaction|tool-array-reorder|json-key-reorder|breakpoint-out-of-window|mid-turn-retry|model-or-route-change|unknown
  prefix_sha256 TEXT,        -- D17④:cache-相关前缀 [0,structural_divergence_seq) 的**逐字源字节** SHA256(跳 volatile)= 地面真相锚(逐字字节事实,非结构估计;见 3.3)
  cache_write_billing TEXT,  -- D17:写侧计费保真标 charged|free|none|excluded(见 3.3 保真标签);none/excluded MUST NOT 当 0 求和
  ground_truth_flag TEXT,    -- D17④:NULL|ttl-rebuild|provider-contradiction(派生自 prefix_sha256 × usage;见 3.3 地面真相验证)
  extra JSON                 -- 未映射的 cache 提示(OpenAI prompt_cache_key、prompt_cache_options…)
)
-- D17① 三列(raw_divergence_seq/divergence_byte_offset/divergence_cause)皆**结构推断**,UI MUST 标「结构估计,非真实边界」(不变式 4);数值真相仍取 usage,冲突时 usage 优先(承 [3.3](3.3-cache-model.md))。
-- D17④:`prefix_sha256` 是**逐字字节事实**(权威、可独立复算,MUST hash NDJSON 逐字源、非 preview);`ground_truth_flag='provider-contradiction'` 措辞 MUST 只把疑点指向 provider 侧,MUST NOT 断言「provider 一定错」(不变式 4)。
```

## 控制面投影(D9 · session-less 底噪的归宿)
harness 在会话周边发的 telemetry / registry / account / feature-flag 调用**无 session 归属**(CC 无 `x-claude-code-session-id`)。它们仍被逐字采集,但**不属任何会话**:落 `calls.class='control'` + `session_id IS NULL`,**不进 `sessions`**——`sessions` 保持"纯会话"语义,不为底噪合成伪会话(**备选(未选)**:合成 `sessions.kind='control'` 伪会话 / 全表 nullable——避免底噪被误当真会话)。非核心流侧栏(2.6 §C)读一个投影:
```sql
CREATE VIEW control_calls AS
  SELECT call_id, ts, endpoint, control_kind, error, raw_ref
  FROM calls WHERE class='control';   -- session-less;会话时间轴一律 WHERE class='llm'
```

## 未映射告警面(保真兜底 + D7 自演化钩子)
`extra` 里的键 = adapter 当前没认识的字段。一个 view 把它们跨库聚合,回答"哪些 provider 字段我还没 surface、多常见":
```sql
-- unmapped_fields:自演化设施据此决定"下一个该映射什么"
CREATE VIEW unmapped_fields AS
  SELECT provider, harness, json_key AS path, count(*) AS n
  FROM calls c, sessions s, UNNEST(json_keys(c.extra)) AS t(json_key)
  WHERE s.session_id = c.session_id GROUP BY 1,2,3 ORDER BY n DESC;  -- 示意,非最终 SQL
```
- 对**人**:一眼看到"新 agent 带了什么我没接的字段"。
- 对 **D7 自演化设施**(下游 RFC):这就是它的**触发输入**——新场景 → 未映射字段浮现 → 自动设计映射/新列/新 adapter → 部署测试。承 [00-overview](00-overview.md) D7。

## provider → canonical 映射(usage 表的心脏)

| canonical | Anthropic | OpenAI (Responses) | DeepSeek |
|---|---|---|---|
| `input_uncached` | `usage.input_tokens` | `usage.input_tokens − input_tokens_details.cached_tokens` | `usage.prompt_cache_miss_tokens` |
| `cache_read` | `usage.cache_read_input_tokens` | `usage.input_tokens_details.cached_tokens` | `usage.prompt_cache_hit_tokens` |
| `cache_write` | `usage.cache_creation_input_tokens` | `usage.input_tokens_details.cache_write_tokens` | **NULL**(无此概念) |
| `output` | `usage.output_tokens` | `usage.output_tokens` | `usage.completion_tokens` |
| `reasoning` | `usage.output_tokens_details.thinking_tokens` | `usage.output_tokens_details.reasoning_tokens` | `usage.completion_tokens_details.reasoning_tokens` |
| `total_input` | 计算 = uncached+read+write | `usage.input_tokens` | `usage.prompt_tokens` |

## Invariants(MUST）
- 每 `block_contents` 由 `content_hash` 去重;`text_ref`/`raw_ref` MUST 指回 NDJSON 源,本表不存全文——**派生不覆盖源真相**(不变式 2([0.0](0.0-overview.md) §核心不变式))。
- usage MUST 落 canonical 角色;**provider 专属字段名 MUST NOT 泄漏到前端/查询层**(不变式 3)。
- 每块 MUST 带 `faithfulness`;非 verbatim 的(metadata/opaque/summarized/omitted/truncated)MUST 可被 UI 就地标注(不变式 4)。
- `cache_write = NULL` 表示"该 provider 无写缓存概念",MUST NOT 填 0 冒充。
- **canonical 列 + `extra` MUST 覆盖原始对象的全部键**:adapter 未映射的字段 MUST 落 `extra`(而非丢弃),`calls.unmapped_count` MUST 如实计数——surfacing 层无声丢字段 = 违反不变式 2/4。规则的执行方在 [3.1](3.1-adapter-contract.md)。
- **class 与 session_id 的一致性(D9)**:`class='control'` 的 call MUST `session_id IS NULL` 且 MUST NOT 进会话时间轴查询(`WHERE class='llm'`);`class='llm'` MUST 有 `session_id`(DeepSeek 合成也算,见 3.4)。`control_kind` 的端点级判定 MUST 在 adapter(3.1),前端只读归一化类目(不变式 3)。
- **细 kind + 渲染期分组(D8)**:`resource_events.kind` 存 provider-中立细粒度、`calls.lane` 到 `aux` 为止;UI 的分组(2.4 六组)与 aux 子类文案(notify/titlegen/quota)是**渲染期投影**,MUST NOT 往 schema 加 harness 专属枚举(不加 `capability` 伞 kind、不加 CC lane 子类)。

## 验收(可跑 check）
- **AC-1(忠实)**:对真实 CC session,由 `call_blocks`+`block_contents`+`text_ref` 重建某 call 的上下文,与 NDJSON 源逐字 diff = 0——**含 tools schema**(D15,tools 逐字捕获后纳入 AC-1);仅真正非逐字的块(加密 reasoning=opaque、SSE 重建等,已标 faithfulness)除外。
- **AC-2(usage 真相)**:`usage` 每行与该 call 线上 usage 按 canonical 映射数值一致;三 provider 各取一例通过。
- **schema check**:DDL 建表成功;去重生效(`SELECT count(*) FROM block_contents < sum(call_blocks per call)`)。

## Edge cases
- 超大 session:`call_blocks` 行数 = Σ每 call 块数;去重后 `block_contents` 远小于之。列存可扛,建 `(call_id,seq)` 索引。
- DeepSeek `native_id` 缺失 → NULL + `native_id_confidence=low`(见 3.4)。
- provider 缺字段(DeepSeek `cache_write`)→ NULL,查询/叠加须容 NULL。

## Extensions
新 provider 加行不加列:只要能映射进 canonical 角色 + 落 block/section/role/kind,就无需改 schema(schema 通用性 = 适配层价值)。
