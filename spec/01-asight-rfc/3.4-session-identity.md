# asight · RFC 3.4 — session / fork / 分支识别

> **服务意图(A2)**:意图 ①(按 session 导航回放)+ 顶栏"同名 session 也可能 fork/不同分支怎么显示"(见 [1.2](1.2-shell-layout.md))。
> **受众**:人(核对血缘判定是否可信)+ agent(据此填 [3.2](3.2-normalized-model.md) 的 `sessions` 血缘列)。
> **前置**:三家线上信号强弱不同(见下表,来自已验证调研);判定逻辑在此,顶栏**视觉**在 1.2。

## Goal
给每条 session 分配**稳定 `session_id`** 并复原**血缘**(parent / fork_of),在三家差异极大的线上信号下尽量可信,并如实标 `confidence`。

## 各 harness 的身份信号(线上事实)
| 信号 | Anthropic / CC | OpenAI / Codex | DeepSeek-CLI | OpenCode(2026-07-18 实测) |
|---|---|---|---|---|
| session id | `x-claude-code-session-id` 头(高) | body `client_metadata.session_id` + `thread_id/turn_id`(高) | **无**(低,须合成) | `session-id` 头(高,已被 `SIDH` 覆盖;实测 `ses_08aa59b0…`) |
| fork / 分支 | 无显式;子 agent = 血缘(见下) | **显式 `forkedFromId` / `parentThreadId`**(高) | 无 | 无显式(低) |
| 子 agent / 子任务 | 系统提示含 `cc_is_subagent=true`;靠首条 user msg 匹配父的 Agent/Task `input.prompt` 认亲 | 独立 thread(`thread_id/rollout/prompt_cache_key`)+ SessionMeta `parentThreadId/agent_role` | 无线标记(仅表现为额外独立请求) | 无线标记 |
| compaction | 无显式;由 message_count 骤降**推断** | 显式 `ContextCompactedEvent`("CONTEXT CHECKPOINT COMPACTION") | 无标记;客户端摘要,线上仅表现为后续 messages 含摘要 | 无显式标记(低);客户端自行裁剪 |

## Plan(选定方案 + 取舍)
**选定:分级可信度 · 显式优先 · 缺失合成。**
- **Codex**:直接用显式信号建**真实 fork 树**(`fork_of_session_id=forkedFromId`、`parent_session_id=parentThreadId`),`confidence=high`。
- **Anthropic**:`native_id`=会话头;子 agent 用 `cc_is_subagent` + prompt 认亲设 `parent_session_id`(承 demo);compaction 标在 `calls.compaction`(**不是 fork**),`confidence=high`(id)/medium(compaction 推断)。
- **DeepSeek**:无 id → **合成 `session_id`**(启发式:连接/进程 + 时间窗 + 系统提示 hash),`native_id=NULL`、`confidence=low`;**先对真实抓包核对再定合成键**。

**备选(未选)**:① 只按标题/native_id 分组——同名不同分支会**错并**(用户正担心的问题);② 一律靠时间窗合成——丢掉 Codex/CC 的显式高可信血缘。
**取舍**:能拿显式血缘就用(Codex 最强),拿不到降级推断/合成并**如实标 confidence**,让 UI 区分"确证血缘"与"猜测分组"。

## 关键区分（MUST）
- **compaction ≠ fork**:compaction 是**同一条 session 内**的换血(标 `calls.compaction`);fork 是**派生出新 session**(标 `sessions.fork_of`)。二者 MUST NOT 混。
- **子 agent = parent 血缘**,不是 fork(它是父任务派生的独立上下文流,非分支重来)。
- **session-less 控制面 ≠ session(D9)**:harness 在会话周边发的 telemetry / registry / account / feature-flag 调用**无 session 身份信号**(CC 无 `x-claude-code-session-id`)。它们**不参与身份判定、不建 session**:落 `calls.class='control'` + `session_id NULL`(归宿见 [3.2](3.2-normalized-model.md) 控制面投影),顶栏/选择器(1.2)把它们归到独立 `session-less` 分组(见 [2.6](2.6-detail-panel.md) §C)。MUST NOT 为它们合成会话身份、MUST NOT 混进真 session 列表。

## Out-of-scope
顶栏/fork 树的**视觉**(1.2);session 列表查询(3.5);具体 detect 实现(3.1 各 adapter)。

## 影响面
`sessions` 血缘列、顶栏(1.2)、session 选择器、跨 session 分析(3.5)。

## 验收(可跑 check)
- Codex:从真实 `forkedFromId` 建出 fork 树,父子/分叉点正确。
- CC:子 agent 正确挂到父 session;compaction 标在 `calls.compaction` 且**未**误建 fork。
- DeepSeek:合成键把"同一次任务的连续请求"归成一条 session,`confidence=low` 显式暴露;抓真实数据核对不误并/误分。

## Edge cases
- DeepSeek 合成误并/误分 → confidence=low 暴露,允许人工纠正(记为 Extension)。
- CC `/rewind` 等终端操作(开发者侧,非 agent 动作)在线上如何表现 = **待数据决策 R**(见 [0.0-overview](0.0-overview.md) §待数据决策):待真实 `/rewind` 抓包确认后补判定(疑似 message_count 骤降)。
- 并发多 session 同 harness:靠各自 native_id / thread_id 隔离;DeepSeek 靠连接区分。

## Risk / 回滚
身份判定是纯函数(记录→血缘);用固化真实记录回归。合成规则改动只影响 DeepSeek 分组,可独立回退。

## Extensions
人工合并/拆分被误判的 session;更多显式-fork 的 harness 直接接入 fork 树。
