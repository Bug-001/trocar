# asight · RFC 3.3 — cache 抽象(★ 两层模型)

> **服务意图(A2)**:意图 ② —— 看懂 agent 的上下文/缓存工程;跨 provider 对比三家 cache 设计。
> **受众**:人(核对这抽象够不够表达三家)+ agent(据此算 [3.2](3.2-normalized-model.md) 的 `cache_events`)。
> **前置**:provider cache 事实见 [3.2](3.2-normalized-model.md) 映射表;数值真相 = 真实 response usage,非臆测(承 demo v11 教训)。

## Goal
一个 cache 模型,**用真实 usage** 表达三种截然不同的 cache 设计:Anthropic 显式断点、OpenAI 自动前缀、DeepSeek 自动磁盘——放进同一个叠加层,让人横向对比。

## Plan(选定方案 + 取舍）
**选定:两层。**
- **Tier 1 · 通用且权威**:每 call 从 canonical `usage` 得 `{cache_read, cache_write, input_uncached}` + `hit_ratio = cache_read/total_input`。三家都有,**这是叠加层的数值真相**。
- **Tier 2 · provider 能力(“在哪/为什么”)**:
  - Anthropic:**声明的 `cache_control` 断点位置**(真实,来自线上)→ `declared_breakpoints`;`break_kind=explicit-breakpoint`。
  - OpenAI:无声明断点;记 `prompt_cache_key`(路由提示);`break_kind=automatic-prefix`。
  - DeepSeek:无任何声明;`break_kind=automatic-disk`。
  - 三者都可选附 **asight 结构性散度**(`structural_divergence_seq` = 相对上一 call 首个不同块),但 **MUST 标为"结构参考,非真实边界"**。

**备选(未选)**:① 只 Tier 1(纯 usage 数字)——丢掉 Anthropic 真实断点这一独有信息、也没法解释"为什么这步没命中";② 纯结构 byte-diff 定断点——demo 已证会**撒谎**(billing nonce 每 call 变 bytes 却 100% 命中;TTL 过期时 bytes 相同却 read=0)。
**取舍**:Tier 1 保证跨 provider 数值真相;Tier 2 在 provider 真声明处给"在哪断",在自动缓存处诚实降级为"结构参考"。

## 真相规则（MUST，承 demo v11）
- **数值取真实 usage,不 byte-diff 臆测**。
- 跳过 `volatile` 块(如 CC 的 billing nonce)——bytes 变但不入 cache key。
- `cache_read>0` → 前缀真复用;`cache_read=0` 但结构前缀相同 → **缓存条目 TTL 过期、被重建**(`cache_write>0`),不是"没缓存"。
- 自动缓存(OpenAI/DeepSeek)的结构散度**非权威**:真实边界受路由(`prompt_cache_key`)、量化(1024/128)、非确定性(DeepSeek best-effort)影响;UI 就近标注。

## 前缀分叉定位（★ D17① · 深化 `structural_divergence_seq`）

把 Tier 2 的散度从「前缀在**哪**断」推到「**哪个块 / 哪个字节**断了 + 是不是你的锅」。兑现研究痛点 #2(最密簇 ~7/33、最锋利楔子):SDK 回 200、看得到没命中却永远不知道**哪个块/字节**断了共享前缀——现有工具只复述 provider 报的 cached-token 计数,无人 byte-diff 请求 N vs N-1。全程**离线派生于已采集字节**(不变式 1),复用 [3.2](3.2-normalized-model.md) 的 `content_hash` 去重与 `volatile` 标记(承 demo `analyze.mjs::cacheBreak`)。

**定位算法(over 3.2 去重,权威定义)**:对**同 lane 相邻**两个 `class='llm'` call(N−1、N),按 `call_blocks.seq` 取各自 `content_hash` 序列,逐位比较、**跳过 `volatile` 块**:
- 首个 `content_hash` 不同、且**非 volatile** 的位 = `structural_divergence_seq`(= demo `idx`)——cache 相关的真分叉点。
- 首个 `content_hash` 不同(**不跳** volatile)的位 = `raw_divergence_seq`(= demo `rawIdx`)——`raw < structural` ⇔ 一个 cache-无关块(如 CC billing nonce)先变了但被正确排除,用于「为何这个先变的块不算断点」注释。
- 无真分叉 ⇒ `structural = min(prevLen,curLen)`(纯 append,新内容是追加的尾)。
- **块内字节定位**:对首个真分叉块,经 `text_ref` 取其与 N−1 同位块的**逐字源字节**(回 NDJSON,**非 `preview`**)做字节 diff,给首个不同字节偏移 `divergence_byte_offset` + 短上下文——回答「整块换了,还是块内一个 JSON key 重排 / 一个 id 变了」。整块新增或首 call ⇒ NULL。

**保真标注(不变式 4)**:`structural_divergence_seq`、`raw_divergence_seq`、`divergence_byte_offset` 皆为**结构估计**,MUST 就近标「结构参考,非 provider 真实 cache 边界」(承本文件真相规则)。数值命中率仍取真实 usage;结构与数值冲突时 usage 优先。

## 分叉成因分类（cause taxonomy · D17①「为什么 + 是不是你的锅」）

定位到「哪个块/字节」后,据**只读判据**归因,落 `cache_events.divergence_cause`,附归属与 `fix_hint`——这是 asight 独占的锋利面(别的工具只给命中率数字),也让下游 debugger-agent 能自动点名 root-cause。

| divergence_cause | 判据(可跑) | 归属 | fix_hint |
|---|---|---|---|
| `append` | 无真分叉(structural=prev 块数),前缀 hash 全等 | 预期无害 | 无(正常轮次) |
| `volatile-nonce-only` | `raw < structural` 且真分叉落在尾部(先变块 `volatile`) | provider 排除 · 无害 | 确认该块确被排出 cache key(标 `volatile`) |
| `compaction` | **`calls.compaction=true`(analyze 的消息数骤降判据)= 权威** | harness(你) | compaction 必废前缀;评估触发阈值/时机 |
| `tool-array-reorder` | 分叉块 `section=tools` 且集合相同、序不同 | 你的锅 · 可修 | 固定 tools 数组序(消除非确定性) |
| `json-key-reorder` | 块结构规范化(键序无关)后相同、原始字节序不同 | 你的锅 · 可修 | 稳定序列化 JSON key 序 |
| `content-changed` | 共享前缀内某块**就地**变了(非上列任一) | 复核 | 查在位编辑 / 非确定性序列化;**也是"首个 message 块变但非 compaction"的归宿** |
| `breakpoint-out-of-window` | Anthropic:`declared_breakpoints` 位置 > structural,或一轮 >N 块把断点挤出可缓存窗 | 你的锅 · 可修 | 收敛单轮块数 / 重放断点位置 |
| `mid-turn-retry` | 同 seq 位重复 call + `error`/`stop_reason` 提示重试 | harness/网络 | 幂等重试、避免前缀漂移 |
| `model-or-route-change` | `model` 变 / OpenAI `prompt_cache_key` 变 | 你的锅 · 配置 | 固定路由键;换模型自然重建 |
| `unknown` | 以上皆不匹配 | 待定 | 落 `extra` 待自演化(D7) |

**compaction 判据的实测收敛(承 demo 校验 2026-07-15)**:草案曾把「首个 `messages` 块 hash 变而 tools+system 全等」也当 compaction 判据;**真实 CC session 实测该结构启发式会误报**(CC 往首个 user 轮**重注入 scaffolding**、fork 等都会改首个 message 却非 compaction)。故 compaction 判据 MUST 以 **`calls.compaction`(消息数骤降)为权威**;裸「首个 message 块变」→ `content-changed`(结构定位仍给 `divergence_byte_offset`)。demo `cacheBreak(prev,cur,{compaction})` 把 analyze 的 drop 判定作 hint 传入即此意。

**demo v0 已实现的子集**:`append` / `volatile-nonce-only` / `compaction`(经 hint) / `tool-array-reorder` / `json-key-reorder` / `content-changed`——纯从相邻两 flat 块序 + `calls.compaction` 可判。`breakpoint-out-of-window` / `mid-turn-retry` / `model-or-route-change` 依赖 provider 断点规则 / 错误 / 模型字段,判定逻辑属 adapter([3.1](3.1-adapter-contract.md)),产品补。

**保真标注(不变式 4)**:`divergence_cause` 是**结构推断**,MUST 标「推断成因」;判「无害」(`append`/`volatile-nonce-only`)MUST 有真实 usage 佐证(`cache_read>0`);结构判据与 usage 冲突时 **usage 优先**。

## 三 provider 各自怎么填 `cache_events`
| 字段 | Anthropic | OpenAI | DeepSeek |
|---|---|---|---|
| `break_kind` | explicit-breakpoint | automatic-prefix | automatic-disk |
| `hit_ratio` | cache_read/total | 同 | 同(hit/(hit+miss)) |
| `declared_breakpoints` | `cache_control` 块位置(≤4) | NULL(记 prompt_cache_key 于 notes) | NULL |
| `cache_write` 来源(3.2) | `cache_creation_input_tokens` | `input_tokens_details.cache_write_tokens` | NULL(不合成写事件) |
| `structural_divergence_seq` | 可算(且与断点对照) | 可算(标非权威) | 可算(标非权威) |

## Out-of-scope
usage 字段映射(3.2)、断点在 UI 怎么画(1.3/2.1)、cache 跨 session 分析查询(3.5)。
- **跨-run 逐步结构 diff(D17③)不在此**:本文件的分叉定位只管**同 session 相邻两 call**(N−1 vs N)。两条独立 run/session 的确定性离线逐步字节 diff(「跑通的 run vs 没跑通的」)是 D17③,归查询层 [3.5](3.5-query-layer.md) + 中央看板 [1.4](1.4-central-board.md)(复用同一 `content_hash` 序列比对原语,但对象是两 session)。
- **裁剪/优化建议不在此**:asight 只**点名**元凶块/字节/成因(诊断),是否裁剪、如何重排 tools 归 harness(承 [1.1](1.1-product-definition.md) 诚实上限)。

## 影响面
cache 叠加轨(1.3)、call-turn card 的"cache 命中"(2.2)、跨 provider 对比。改真相规则 = 改 ② 的核心判据 → 走 grep-spec 闸。

## 验收(可跑 check)
- **AC-2**:`cache_events`+`usage` 每 call 与线上 usage 数值一致;三 `break_kind` 各取一真实例,叠加层渲染正确。
- Anthropic:`declared_breakpoints` 与线上 `cache_control` 块位置吻合;billing nonce 块被判 `volatile` 不误触发散度。
- TTL 场景:构造 `cache_read=0 & cache_write>0 & 结构前缀相同` → UI 显示"过期重建"而非"未复用"。
- **AC-divergence(D17①)**:构造相邻两 flat 块序,`cacheBreak` 对每 `divergence_cause` 打出正确码——`append`(byteOffset=NULL)、`tool-array-reorder`、`json-key-reorder`(byteOffset 指向块内首个不同字节)、`content-changed`、`volatile-nonce-only`;`{compaction:true}` hint 把结构上的 `content-changed` 覆盖为 `compaction`,裸结构**不**臆断 compaction。真实 CC session 回归:`compaction` 计数 == analyze 的 `stats.compactions`(demo 已验:590 call → 3=3)。marker 渲染带 `结构估计` 保真标 + 可执行 `fix_hint`,`append` 不画 why 行。

## Edge cases
- 首 call `cache_read>0`(跨 session 暖前缀,tools+system 跨会话字节相同)——合法,如实显示,不当异常。
- DeepSeek 同输入两次 hit/miss 不同(非确定性磁盘缓存)——如实、标"best-effort"。
- OpenAI 前缀 <1024 tok → `cached_tokens=0` 即便重复——标"低于最小可缓存长度"。

## Extensions
新 provider:落 Tier 1(canonical usage)即得数值叠加;有声明断点就填 Tier 2,没有就只给结构散度。
