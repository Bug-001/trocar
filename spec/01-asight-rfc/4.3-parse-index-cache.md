# asight · RFC 4.3 — 解析 / 索引 / 缓存

> **服务意图(A2)**:意图 ①② 的**性能使能层**——让大 session 在 scrub 下,忠实回放(①)与 cache 叠加(②)仍**即时**,不因"反复解析卡顿"退化到不可用。本模块是 [00-overview](00-overview.md) **D5 的动因**(demo v0 每 poll 全量重解析的痛)与 **D6**(轻框架 + 虚拟化)的落点。
> **受众**:人(核对缓存**不会**变成第二源真相)+ agent(据此实现派生缓存 tier、失效签名、惰性计算策略)。
> **前置**:索引(去重键)= [3.2](3.2-normalized-model.md) 的 `content_hash`(**本模块承之、不另定**);cache-break-as-SQL 与分页/惰性契约 = [3.5](3.5-query-layer.md);解析动作本身(adapter)= [3.1](3.1-adapter-contract.md),持久归一化 store = [4.2](4.2-storage-etl.md);承 demo `callComp`(`step._comp`)/ `linearContext`(按需 `curFlat`)/ `cacheBreak` / `lastRenderSig`。

## Goal
在**已归一化的 store(4.2)与前端部件(2.x)之间**架一层**派生缓存 + 惰性计算**,使"某步的摊平块列表、每 call 类型构成、相对上一 call 的 cache-break"这类**贵且随渲染变**的产物**算一次复用、只算需要的、可从源重建**。核心约束:缓存是**可重建的派生投影**,原始 NDJSON(源)与 [3.2](3.2-normalized-model.md) 的去重块表(持久派生)**永不被它覆盖或绕过**(承不变式 2([0.0](0.0-overview.md) §核心不变式))。

## Definitions
- **派生产物(derived artifact)**:非源真相、可由源/store 重算的中间结构。三类:① 摊平块列表 `flat`(承 demo `linearContext` 的 tools→system→messages 有序块);② 每 call 类型构成 `comp`(承 demo `callComp`,chars 为 token 占比廉价代理);③ cache-break 散度点(承 demo `cacheBreak`,相邻 call 首个不同块)。
- **记忆化(memoization)**:把派生产物挂在其宿主对象上算一次(demo:`step._comp`、`curFlat`),命中即返、未命中即重算。
- **失效签名(invalidation signature)**:一个廉价键,数据没变则跳过整轮"重解析 + 重渲染"。承 demo `lastRenderSig = session id · 记录数 · 末条记录 ts/id`。
- **索引(index)**:跨 call 复用块的去重键 = [3.2](3.2-normalized-model.md) 的 `content_hash`;**本模块只消费,不重定义**。
- **惰性计算(lazy compute)**:只算当前视口需要的(当前 + 前一 call),不为全 session 预算(承 demo 显式 NOTE:`analyze()` 每 poll 重跑,数百 call 不可全量预算)。

## Plan(选定方案 + 取舍)

**选定:三件套 = 派生记忆化 · 承 3.2 的去重索引 · 惰性 + 虚拟化(承 D6)。**
1. **派生记忆化**:每 call 的 `flat` / `comp` / `cache-break` 算一次挂宿主对象;失效签名命中则**整轮跳过**(避免 1.5s live poll 重建上下文窗口、抹掉刚展开的块)。缓存**只装"贵且可重建"的**,miss 即从 store/源重算。
2. **索引承 [3.2](3.2-normalized-model.md)**:块内容按 `content_hash` 去重"跨 call 只存一次";**cache-break 退化成相邻 call 的 `content_hash` 序列 diff**,走 SQL(见 [3.5](3.5-query-layer.md)),**不在前端逐块比全文**。
3. **惰性 + 虚拟化(承 D6)**:摊平/差分**只对当前 + 前一 call**算(承 demo `renderContextWindow` 只 `linearContext(cur)` + `linearContext(prev)`);长 block 体默认折叠、首次展开懒填(demo `toggleCtxBlock` 的 `dataset.filled` 门 + `COLLAPSE=600` 折叠阈);超长内容**显示截断**并标(见「保真边界」)。

**备选(未选)**:
- ① **每 poll 全量重解析 + 全量预算**(demo v0 = D5 的痛):`analyze(raw)` 每 1.5s 重跑、`linearContext` 为每 call 预算 → 大 session 数百 call 卡顿,且重渲染抹掉用户刚展开的块。
- ② **把派生产物提成 DuckDB 正式列持久化**:过度具体化——`flat`/`break` 是**视图态**(随渲染策略、折叠/turn 分组而变),塞进中心契约([3.2](3.2-normalized-model.md))会让 schema 随 UI 抖动;违反"派生不进源"。

**取舍**:缓存只承载"贵且可重建"的**视图态派生**;持久层([3.2](3.2-normalized-model.md))只存**去重块内容 + 有序映射 + canonical usage**。两层靠 `content_hash`(内容对齐)与失效签名(时间对齐)咬合。**任何派生产物 MUST 可被丢弃后从 NDJSON/store 逐字重建**——这是它不成为第二源真相的凭证(必拒违反)。

## 三件套的具体机制(承 demo)

### 1 · 派生记忆化 + 失效签名
- **每 call 记忆化**:`comp`(类型构成)算一次挂 `step._comp`,二次调用返同一对象(demo `callComp` 头两行:`if(s._comp) return s._comp` … `return s._comp=c`)。产品泛化:摊平块列表 `flat`、cache-break 同此模式,key 到 `(call_id, 渲染策略版本)`。
- **失效签名跳过整轮**:live poll 先算 `sig`;`sig === 上次` → **直接 return**(只翻转 live 指示灯),不 `analyze` / 不 `render`。签名 MUST 覆盖"会改变派生结果的一切最小充分信号"(demo:session 选择 + 记录数 + 末条 ts/id);签名**过窄**(漏掉一种变更)= 缓存供旧字节 = **谎报 AC-1(必拒)**;签名过宽只损性能不损正确,SHOULD 收窄但不得为性能牺牲正确。
- **UI 局部态跨重渲存活**:展开的块集(demo `openBlocks`)、展开的 turn(`turnOpen`)在缓存命中/重渲时 MUST 存活——否则 live poll 每 1.5s 把用户正在读的块折叠回去(demo 已解决,产品 MUST 保持)。

### 2 · 索引:content_hash 去重 → cache-break 是相邻 hash 序列 diff(承 [3.2](3.2-normalized-model.md)/[3.5](3.5-query-layer.md))
- 块内容按 `content_hash` **跨 call 去重只存一次**;`call_blocks` 只存整型/hash 映射(见 [3.2](3.2-normalized-model.md))。
- **cache-break 退化成一句 diff**:相邻 call 的 `content_hash` 序列比对,首个不同位置 = 结构散度点(承 demo `cacheBreak(prevFlat,curFlat)` 比 `key` 序列)。产品走 SQL(见 [3.5](3.5-query-layer.md)),散度点须与 [3.3](3.3-cache-model.md) 的 `structural_divergence_seq` 一致,且**MUST 标"结构参考,非真实 cache 边界"**(数值真相取真实 usage,见 [3.3](3.3-cache-model.md))。
- **跳过 `volatile` 块**:cache-break 比对 MUST 跳过 volatile 块(CC billing nonce:bytes 每 call 变但不入 cache key;承 demo `cacheBreak` 内 `if(curFlat[i].volatile) continue`),否则每 call 误触发散度。
- **保真边界(承 demo 的 bounded-prefix hash)**:demo `blkKey` 对块前 **4096 字符**取 hash(O(1)/块,与块大小无关)——这对"廉价内存 cache-break 启发式"足够,但**MUST NOT** 用作 [3.2](3.2-normalized-model.md) 去重 PK(两个仅前缀相同的长块会碰撞、丢差异)。**产品的 `content_hash` = 全内容抗碰撞 hash;bounded-prefix 只许用于内存态启发式**——算法全局钉死在 [3.1](3.1-adapter-contract.md) `parseBlocks`、去重写入归 [4.2](4.2-storage-etl.md)。

### 3 · 惰性 + 虚拟化(承 D6)
- **只算当前 + 前一 call**:摊平 + 差分**不为全 session 预算**(承 demo 显式 NOTE + `renderContextWindow` 只 `linearContext(cur)` / `linearContext(prev)`)。时间轴上远处的 call 不摊平,直到 scrub 到。
- **块体懒填 + 折叠**:block 卡默认只渲头,首次展开经 `text_ref` 回源懒填全文(承 [2.3](2.3-context-window.md) 的懒加载,demo `dataset.filled` 门);>`COLLAPSE` 阈的体给"show all"折叠壳。
- **大结果分页/游标**:跨 session 聚合走 [3.5](3.5-query-layer.md) 的分页契约,不一次拉全表。

## 保真边界(必拒隐瞒 · 承不变式 2、4([0.0](0.0-overview.md) §核心不变式))
- **缓存是派生,永不覆盖源**:任何缓存条目 MUST 可丢弃后从 NDJSON/[4.2](4.2-storage-etl.md) store **逐字重建**;缓存层 MUST NOT 成为唯一副本、MUST NOT 有损改写。
- **显示截断标 `truncated`**:超长 block 体按显示上限截断(承 demo `ctxBody`:`>20000` 字符 → 截断 + `… (Nk chars total)` 标)——这是**显示态截断,非数据丢失**:源 bytes 完整、可展开回源。UI MUST 就地标"截断/非逐字";未标即让人误判"看到的是全文"(违反不变式 4)。
- **廉价代理标注**:`comp` 用 chars 作 token 占比代理(非真实 token 数),UI 呈现处 SHOULD 注明"字符占比,非 token"。
- **缓存 miss 不得供旧/错**:失效签名命中 = 数据未变才复用;**MUST NOT** 在数据已变时供旧缓存(供旧字节 = 谎报 AC-1,必拒)。

## 影响面

## 验收(可跑 check)
**既有闸(MUST 保持绿)**:

**本模块 NEW 测试 MUST 断言(缓存正确性 = 不谎报的前提)**:
1. **记忆化 ≡ 重算**:`callComp(s)` 两次调用返回**同一对象**(`===`)且其值 == 从 `s.rec.request` 全量重算 → 缓存不漂移。
2. **惰性只算 cur+prev**:spy/计数 `linearContext` 调用次数——渲染第 N 步时 == **2**(cur + prev),**MUST NOT == N**(证明未全量预算)。
3. **可从源重建(派生非源)**:清空全部缓存(`_comp` / `curFlat` / `lastRenderSig`)后重渲,窗口 bytes 与清空前**逐字 identical**(AC-1 diff = 0)——证明缓存丢弃无损。
4. **失效签名正确**:(a) 数据未变 → `sig` 命中 → **不重 `analyze`/不重渲**,且此时**已展开的块(`openBlocks`)存活**;(b) 追加一条记录 → `sig` 变 → 重算并纳入新 call。
5. **cache-break via index**:对相邻 call 的 `content_hash` 序列做 diff 得的散度点,== `cacheBreak(prevFlat,curFlat).idx`,且 `volatile` 块被跳过(billing nonce 每 call 变 bytes 却不触发散度)——与 [3.3](3.3-cache-model.md) `structural_divergence_seq`、[3.5](3.5-query-layer.md) 的 cache-break 查询一致。
6. **截断标注 + 可回源**:构造 >20000 字符的块 → 渲染体带 `… (Nk chars total)` 截断标,且回源/展开可取完整 bytes(保真边界)。

## Edge cases
- **超大 session(数百~上千 call)**:失效签名 + 惰性 cur+prev + 分页兜住;缓存内存 SHOULD 设上限(LRU 逐出远处 call 的 `flat`),逐出条目 miss 时从 store 重算(可重建 → 逐出无损)。
- **live 追加与并发**:1.5s poll 期间 store 增长——失效签名以"末条记录 ts/id + 计数"检测追加;签名相等但内容实变(极罕见 id 复用)MUST 由更强签名兜(SHOULD 用 store 的单调 offset/水位)。
- **compaction 步**:message_count 骤降触发的换血(见 [3.4](3.4-session-identity.md)),cache-break 在此步落到**首个 messages 块**(tools+system 存活),缓存 MUST 反映此结构跳变,不复用跨 compaction 的旧散度。
- **DeepSeek `cache_write=NULL`**:cache-break 是纯结构 diff、与 usage 无关,NULL 不影响本层;数值叠加容 NULL 由 [3.3](3.3-cache-model.md)/[3.5](3.5-query-layer.md) 负责。

## Risk / 回滚
本层是**纯派生**(源/store → 缓存),零副作用于源。缓存/失效逻辑改动可用固化真实记录回归(渲染闸 + NEW 测试);任一改动失败即回退上一绿点。**最大风险 = 失效签名漏检导致供旧字节**——由验收 #3/#4 的"重建 identical + 追加触发重算"守;一旦怀疑,**MUST 优先牺牲缓存命中率保正确**(禁用缓存全量重算是安全默认)。

## Extensions
- 持久化派生缓存(把 `flat`/`break` 落磁盘/DuckDB 物化视图)——仅当剖析证明重算是瓶颈,且**MUST 保留"可从源重建"**;这会触 [3.2](3.2-normalized-model.md)/[4.2](4.2-storage-etl.md) → 走 grep-spec 闸。
- DuckDB-Wasm 客户端缓存(承 [4.4](4.4-server.md) OPEN 定案后):浏览器内 SQL 免往返,缓存策略同构迁移。
- 更细的失效粒度(块级而非 call 级失效),供跨 session 大聚合增量刷新。
