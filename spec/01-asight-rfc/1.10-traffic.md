# asight · RFC 1.10 — 流量

> **服务意图(A2)**:意图 ①(看懂 agent 的行为)在模型调用之外的那一半,即 D40③ 的目的:agent 连了哪些 host、往外发了什么(遥测、上传、账户调用、意外的 host)。本单元把 D40 存下的字节变成两页:按 agent 分组的 host 表,和点进一个 host 之后的请求列表与请求详情。
> **受众**:人(想知道 agent 除了调模型还连了谁、发了什么)+ agent(据 [4.4](4.4-server.md) 的 `traffic` / `calls --host` / `calls --ref` 渲染;不写任何 provider / harness 分支)。
> **前置**:[1.2](1.2-shell-layout.md)(侧栏、路由、页头与页头区、窄屏、agent chip、键盘)· [1.5](1.5-states-aesthetics.md)(看板词表、标记、状态矩阵、数据规则)· [2.6](2.6-detail-panel.md) §C(请求详情部件:体、每侧的保真标注、凭据遮挡)· [3.5](3.5-query-layer.md)(具名查询 `traffic` / `calls`;文档形状的权威是 [1.6](1.6-cli.md) 附录 C.5)· [4.4](4.4-server.md)(`traffic` / `calls --host` / `calls --ref`、§OPEN「同一台机器上几个系统用户共用 `127.0.0.1`」)· D40 · D24 · D18c。

## Goal

只用已存的真实数据,回答两个问题:

1. 这段时间,每个 agent 连了哪些 host?发出多少、收回多少、主要是哪类请求?—— **流量表**(`#/traffic`)。
2. 点进一个 host,它具体发过什么?—— **host 页**(`#/traffic/host/<agent>/<host>`):这个 agent 发往这个 host 的请求列表,选一条看逐字的请求与响应。

两页都只读。数字来自 具名查询(D24 · D59),字节来自源记录(回源,D24)。没记下、认不出、推测出来的地方就地说清楚:不写成 0,不写成「没有」,不写成确定。

## 前置定义(Definitions)

- **流量**:agent 进程的全部网络请求,**包括模型调用**(D40 类别 `llm`)。D40① 起采集器默认解密 agent 进程的全部 TLS,所以这里看到的不只是模型端点。
- **host**:请求去的域名,取 `calls.host`(D40:信封的 `host`,即连接时的域名;没有时取请求的 Host 头)。
- **类别**:D40 的七个流量类别 `llm` · `token-count` · `session-sync` · `telemetry` · `files` · `account` · `other`。界面词取 `core/classes.mjs`:「模型调用」「token 计数」「会话同步」「遥测」「文件」「账户」「其他」。类别由服务端给(`calls.traffic_class`),前端不分类。
- **未分类**:一个 agent 在读取侧 harness 表里,三个只能靠模式认出的类别(`session-sync` · `files` · `account`)一条规则都没有时,它的 `other` 其实是「还分不了」。C.5 的 `classes` 没有这个条件的字段,所以本页**不画**「未分类」,`other` 照读「其他」;给 C.5 加字段是 Extensions 的一项(先走 grep-spec 自对照)(依据:[1.5](1.5-states-aesthetics.md) §数据规则、D24、代码从少)。
- **发出 / 收回**:请求体 / 响应体的线上字节,不含头(C.5 `traffic` 与 `calls` 行的 `sent_bytes` / `received_bytes`,D40;依据:C.5 与 [1.5](1.5-states-aesthetics.md) §数据规则)。没记下的叫「未记录」,不是 0。
- **host 页**:一个 agent 发往一个 host 的请求列表,加请求详情。同一个 host 被两个 agent 连过,就是两张 host 页。
- **请求详情**:一条请求的方法、路径、状态、头、逐字体与保真标注。部件归 [2.6](2.6-detail-panel.md) §C;本单元只定它放在哪、什么时候出现、模型调用前面加什么。
- **截至**:`traffic` / `calls --host` 的 `as_of`,即 段索引里最新一条调用的时间。
- **页头 / 页头区 / 说明行**:见 [1.2](1.2-shell-layout.md) §页头。说明行是表自己的第一行,放截至、覆盖、筛选这类只修饰这张表的话。

## Plan(选定方案 + 取舍)

**选定**:一张按 agent 分组的 host 表 → 点一行进 host 页 → 选一条请求看详情。

- 表的列沿用流量样张:host · 首次出现 · 请求 · 发出 · 收回 · 主要类别。按 agent 分组,agent 只写在组的第一行;不嵌套表。
- 点 host 进 host 页。原样张里表下面那张跨 host 的总历史列表、点表里的数字去筛它、搜索框,都由 host 页取代(理由:要的是点进某个 host 之后看它发过什么;见「砍掉的」)。
- 页头与页头区不放统计句,也不放说明句(这类话不出现在标题或小标题里,会干扰读者)。截至、覆盖、筛选说明放在表的说明行;合计放在表的最后一行。
- 「某个 agent 第一次连某个 host」作为事项列在总览页([1.7](1.7-overview-dashboard.md) §事项目录);本页只在「首次出现」那一格标「新」。
- 只读:不重发、不改包、不替 agent 发任何请求(不变式 1、D30)。

**D40③ 修订**:D40③ 写「专门的『agent 行为』视图(连了哪些 host、传了什么)是以后的功能」。上面那条要求把 host 下钻提进 v1:流量表、host 页、逐条请求详情(经 `calls --ref` 按需取单条)。异常标记、资源与上传的互链仍是以后。[2.6](2.6-detail-panel.md) §C 原先说 session 内非推理调用的体要显示就得有一个按需取单条的端点,「未做,留作 Extension」;由此定:host 页逐条看,端点是 `calls --ref`。这两处修订记在 D18c。

**取代**:旧看板会话选择器里的 `⚙ session-less` 分组与 `ctrlmode`(D9 的呈现)由本页取代。D9 的数据模型(`calls.class='control'`、`session_id` 为 NULL、`control_calls` 投影)不变。

**备选(未选)**:
1. 原型的三层嵌套(agent 块 → host 表 → 上传列表):嵌套难扫读;上传没有字段支撑。
2. 一张跨 host 的总历史列表(Burp 式),点表里的数字去筛:定稿要的是按 host 下钻;`calls --host` 按 host 取数,总列表与 host 页重复。
3. 把流量并进回放台(会话里列它的非模型请求):多数非模型请求不属于任何会话(D9),属于会话的也不是回放里的一步;按 host 看才回答「它连了谁」。
4. 页头写「最近 24 小时,N 个 agent 发出 X MB」:否决,统计句不进页头。

**取舍**:多一跳(表 → host 页),换来每页只回答一个问题,列表按 host 分页、有界。

## 一件事只说一处(MUST)

- **不写操作提示句**:「点一行,按这个 host 筛选下面的历史」「点开一个文件看逐字」这类句子不画;行本身的 `›` 与悬停态就是入口。
- **「新」只在 host 行的「首次出现」格**。
- **详情不挡住点来的那个数**:请求详情打开时,host 页列表的 时间 · 端点 · 类别 · 发出 · 收回 **MUST** 仍看得见:≥ 1440 px 详情是右侧一列;< 1440 px 详情从底部升起(占视口一半高),列表在它上方(依据:[1.2](1.2-shell-layout.md)「断点只在这一张表里定」与本条 MUST)。守卫:`test/web-v2/host-page.test.mjs` + Playwright(1280 / 1024,详情开着时这五列表头的盒子都在视口里且不被盖住)。
- **类别筛选在页头行**:`class=` 的 chip 与窗口控件同一行(路由里本来就有这个参数);数字区左移,host 列吃掉空白。

## 保真边界(必拒隐瞒 · 不变式 4)

1. **收回没记下不是 0**:D40 之前的记录、没带 `body_wire_bytes.resp` 的记录,收回写「未记录」;合计与部分未记录写「≥」并给条数。
2. **「新」是推测**:按已整理进统计的记录推,带「推测」;段索引没建全时会漏标或多标。
3. **截至**:两页的数字只到 `as_of`;之后采到的不在表里。说明行总是写「截至」。
4. **还分不了的读作「其他」**:本页不画未分类(§前置定义),所以没有任何仅模式类别规则的 agent,它的 `other` 也读「其他」。
5. **按 UA 推测的 agent**:旧采集的记录没有进程信息,agent 是按 UA 推测的(D37①:MUST 标「推断自 UA」)。`traffic` / `calls --host` 目前分不出是哪几行:不占说明行,「agent」列头带 ⓘ「旧采集的记录没有进程信息,agent 是按请求头推测的」;见 §OPEN。
6. **每侧的保真标注**:请求和响应各标各的,不用一句话盖住两边。例如 D40 之前的非 LLM 记录:请求侧「较早采集的记录,只存了长度」(D40④),响应侧「重新序列化」(解析后写回的 JSON,不是线上原字节)。规则与词归 [2.6](2.6-detail-panel.md) §C。
7. **没记下 host**:既没有连接的域名、也没有 Host 头的记录,写「没记下 host」,不并进别的 host。
8. **asight 改过或发起的请求(D30)**:N/A —— [5.1](5.1-intervention.md) 未落地,asight 现在不改包、不发请求。落地后,intervention 事件 MUST 在流量表的行、host 页的行与请求详情就地标出,不得让人误以为是 agent 原发(见 Extensions)。[1.6](1.6-cli.md)§1.3 的 `asight_added`(`off` 时在最后一条响应上加的 `Connection: close`)只在源记录里,`calls --host` 的行没有这一列,所以这一标注只在请求详情里出现(归 [2.6](2.6-detail-panel.md) §C)。

## Edge cases

- **没记下 host**:`traffic` 的 `host` 为空 → 「没记下 host」一行,计入合计,不能点(`calls --host` 还不能按「没有 host」查)。
- **认不出的 agent**:`traffic` 的 `harness` 为空或不在 chip 表里 → 保留图形 + 「未识别的 agent」。路由段用 `unknown`(与 `/api/classes` 的 `known_harnesses` 同一个 id),`calls --host` 收到 `harness=unknown` 时按 `calls.harness` 为空的行查(形状归 [4.4](4.4-server.md) `calls --host`)。
- **同一个 host,两个 agent**:两行,两张 host 页。host 不做大小写、端口的合并,照 `calls.host` 分组。
- **带会话头的非模型请求**:具名查询只要在记录里找到会话 id 就把它归进会话(`calls.class='llm'`、`session_id` 不为空),但它不是回放里的一步(会话里只计数,`meta.other`)。所以它的 `session_id` 不为空也不给回放链接。
- **只记日志的模型调用**:不是回放里的一步(回放的会话保真行说「N 次调用只记了日志」),不给回放链接;行上是「只记日志 ›」。
- **会话不在会话列表里**:回放链接的会话 id 来自 `traffic` / `calls`,会话列表来自 `sessions`,两边取 id 的规则可能不同;链过去时由 [1.2](1.2-shell-layout.md) 的 `#/session/<id>` 说「这个会话不在会话列表里」,不猜。
- **请求很多**:解密全部 TLS 之后一个 agent 可能连很多 host、一个 host 上万条请求。流量表照画 `traffic` 的全部行(行高固定);host 页按 `calls --host` 分页取。
- **体很大或是二进制**:`calls --ref` 按 [2.6](2.6-detail-panel.md) §C 的上限下发;截断就地说明。
- **`ref` 指不到记录**(源文件被移走、封存后找不到):`calls --ref` 回原因,详情写原因 + 「重试」,不显示空的体。`ref` 只能解析到采集根之内的记录(路径安全归 [4.4](4.4-server.md))。
- **端点里的查询串**:照存的样子原样显示;凭据遮挡只按 [2.6](2.6-detail-panel.md) §C 的请求头规则。查询串里带凭据的情况记在 Extensions。
- **[1.6](1.6-cli.md)的 `asight_added`**:只在请求详情里标(`calls --host` 的行没有这一列)。
- **时间窗与「新」**:「新」与时间窗无关;换窗口不会让它出现或消失。

## Risk / 回滚

- 两页是纯函数 + 只读端点。回退 = 撤掉 `src/web/v2/traffic/**` 与 `traffic`–`calls --ref` 的路由,数据不动。
- `calls --ref` 按 `ref` 回源:路径安全(只解析采集根内的记录)归 [4.4](4.4-server.md);本页不拼路径。
- 「新」依赖已入库的数据(技术细节语):「新」可能漏标或多标,所以带「推测」,也不进告警。
- 显示头与体会扩大同机多用户的暴露面:见影响面「安全」;遮挡默认开(归 [2.6](2.6-detail-panel.md) §C)。

## 砍掉的

| 元素 | 为什么 |
|---|---|
| 页头的合计句「最近 24 小时,N 个 agent 发出 X MB(612 次请求)」与页头副标题 | 统计句和这类说明不进页头;合计在表的最后一行 |
| 页面上的「新出现的」一段 | 移到总览页的事项「第一次连」;本页只在首次出现那一格标「新」 |
| 「可能来自第 N 步」(把请求按时间对到回放的某一步) | 没有字段;按时间对步是猜,记在 Extensions |
| 「上传的文件:N 个,共 X MB」、每个文件的名字与内容、分片合成一项、压缩包成员 | 没有字段:服务端不解析 multipart / tar,也不认分片;「文件」类别与 host 页里逐字的请求体已经能看到发出去的字节 |
| 跨 host 的总历史列表、点表里的数字去筛它、搜索框、「只看模型调用之外的」开关 | 由 host 页取代(要点进某个 host 之后看);`calls --host` 按 host 取数;搜索没有服务端参数;类别筛选已能只看某一类 |
| 列表里的方法与状态两列 | `calls` 没有这两列,`calls --host` 不给;方法、状态在请求详情里 |
| 非模型请求行上的回放链接 | 那条记录不是回放里的一步,链过去只会落到第 1 步 |
| 块头的「无分类规则 · 非模型流量显示为未分类」 | 本页不画未分类(§前置定义) |
| 观测到的 feature flags 账本(旧 `controlLedger`) | 没有这个需要;响应体在请求详情里逐字可看 |
| 会话选择器里的 `⚙ session-less` 分组与 `ctrlmode` | 由本页取代;D9 的数据模型不变 |
| 重发、复制为 curl | 本页只读(不变式 1、D30);复制动作归 [2.6](2.6-detail-panel.md) §C |
| 异常标记(三角、警告色) | 以后再做 |

## OPEN

- **按 UA 推测的 agent 在两页上分不出是哪几行**。D37① 要求没有 `proc` 的旧记录按 UA 推断时 MUST 标「推断自 UA」。会话一侧有 `sessions.extra.harness_inferred`,但 `calls` 没有逐条的推测标志,`traffic` / `calls --host` 的行也不带,所以流量表与 host 页分不出哪几行是推测的。要逐行标,需要 `calls` 存下这个标志,`traffic` / `calls --host` 的行带 `harness_inferred`(组里有一条是推测的就为真)。给 `calls` 加列是 [3.2](3.2-normalized-model.md) 的结构性改动,要先过 grep-spec 自对照。定下来之前,本页按流量表 §说明行 里的那句话就地写明;字段出现后自动改为逐行「推测」(按字段在不在判断)。在本单元跟踪。

## Extensions

- **异常标记**(推迟的那一项):以后,在 host 表与 host 页上标出值得看的请求。
- **资源与上传的互链**:回放里读进上下文的文件 ↔ 发出去的请求体(以后再做)。
- **请求 ↔ 回放的步**:把非模型请求按时间对到当时正在执行的那一步,标「推测」;需要服务端给出对应关系。
- **未分类与回放链接的字段**:给 C.5 的 `classes` 加「未分类」的条件字段、给 `calls` 行加会话键,之后本页才画「未分类」与「在回放中打开 ›」;动手前先走 grep-spec 自对照。
- **上传文件视图**:服务端解析 multipart / tar、认出分片之后,在 host 页列出文件名、大小与逐字内容。
- **查询串里的凭据遮挡**:端点的查询串里带 key 时也按凭据处理。
- **asight 改过或发起的请求**(D30):[5.1](5.1-intervention.md) 落地后,intervention 事件在流量表的行、host 页的行与请求详情就地标出,原始与改后各看一份。
- **没记下 host 的记录也能下钻**:`calls --host` 能按「没有 host」查之后。
- **从会话进流量**:回放的会话概况里给「这段时间的流量 ›」,按 agent 与会话的时间段筛。
