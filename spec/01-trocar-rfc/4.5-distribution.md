# trocar · RFC 4.5 — 跨平台安装 + 分发 / release

> **这是什么**:把这台单机研究仪器变成**可在 macOS、Linux、Windows 上一键装、跑、卸**、并经 **npm 包 `trocar-cli` + GitHub Release** 分发的工具。装:支持平台矩阵 · 信任面的平台中立原则 · 分发形态(D23)· 本机发布流程与 release 检查 · 边界守卫。
> **受众**:人(核对「单机 / 单用户 / loopback / 改包只出于操作者意图(D30)四条边界在分发后仍不破」)+ agent(据此实现跨 OS 安装 + 本机发布流程)。
> **Source-decision**:承 [0.0-overview](0.0-overview.md) **D23**(分发/release 策略)+ D1(个人研究仪器 + 产品化留缝)+ D55 · D57(证书由 `install` 装、`uninstall` 撤:每台机器自己生成的根装成用户级根,根够不到的形态由证书载体补,`on` / `off` 只管引流)。
> **不含 → 去哪查**:采集源机制 → [4.1](4.1-capture-sources.md);本地服务的 loopback/只读边界 → [4.4](4.4-server.md);技术栈(Node/`.mjs`,无原生依赖)→ D18。

---

## Goal

让 trocar 在 macOS、Linux 与 Windows 上都能:① 一条命令装起(`npm i -g trocar-cli`)· ② `trocar install` 在本机生成根、装进用户级信任库(OS 的框即同意),根够不到的形态放证书载体;`trocar on` 只接引流(D55 · D57)· ③ 采集→存储→查询→看板端到端跑通 · ④ 一条命令干净卸载(零残留;Linux 采集器的能力助手是整机的(D36),另要一步 sudo 移除,见 §C)。分发经 **npm 主渠道** + **GitHub Release 挂同一个 tarball**,由维护者在本机发布(§分发 (B))。

**贯穿约束(分发后仍 MUST 成立)**:每个安装是**单机 · 单用户 · loopback · 改包只出于操作者意图(D30)** —— 分发**只是把同一台单机仪器复制到更多机器**(D36:或同一台机器上几个系统用户各装一套,共用一个不存状态的能力助手,每套仍只服务一个用户),**MUST NOT** 借此长出多用户 / 云端分享 / 对外暴露(Non-Goal + [4.4](4.4-server.md) 只绑环回;违反=**必拒**)。

## Definitions

- **可移植缝**:整条链 `采集器 → D10 信封 → 段与段索引 → 具名查询 → server → 前端` 中,**只有采集器的 `arch/<os>/`**(引流、进程身份、自启、控制面、根的密钥保管与用户级信任库;见 [4.6](4.6-process-collector.md) / [4.8](4.8-win-collector.md) / [4.9](4.9-macos-collector.md))碰 OS。信封往后全是纯 Node、无原生插件 → **平台无关,零改**。
- **支持平台矩阵(v1)**:`darwin`(arm64/x64)· `linux`(x64/arm64)· `win32`。Windows 采集器见 [4.8](4.8-win-collector.md),`install` 把根装进 `CurrentUser\Root`,Windows 的确认框即同意;macOS 采集器见 [4.9](4.9-macos-collector.md),`install` 把根装进登录钥匙串的用户信任,系统的密码框即同意;两者的模型见 [4.11](4.11-collector-model.md)(D55 · D57)。
- **分发形态(D23)**:npm/npx 主渠道 + GitHub Release tarball 副本;**预编译单文件二进制(SEA)= Extension**(见文末)。

## 信任面的平台中立原则(必拒违反 · D55 · D57)

采集器 CA 由 `install` 装、`uninstall` 撤,从不随 `on` / `off`(D55①)。根每台机器自己生成;macOS / Windows 把它装成**用户级**根(macOS 登录钥匙串的用户信任、Windows `CurrentUser\Root`;整机一项,按指纹认,OS 的框即同意),根的私钥不能导出(D57②)。根够不到的形态,证书交给它自己读的东西:配置键、安装目录包装、插件,由描述符选([4.11](4.11-collector-model.md) §2);登录环境不加任何变量(D56⑨)。Linux 的证书载体见 [4.6](4.6-process-collector.md) §身份与信任。装与按指纹撤都在 `arch/<os>/`;**管理员域与机器级信任库不做**(macOS 管理员域)。**绝不全机弱化 TLS**:这是 [4.1](4.1-capture-sources.md) 采集安全#3 的平台中立形态,精神跨 OS 不变,机制按 OS 落。


> **D55· D57**:代价写明——证书在时,本用户所有读用户级信任库的程序都信任这张 CA;私钥每台机器自己生成(D55⑤)。macOS / Windows 上私钥拿不走,但本用户名下的程序能借 trocar 的签名助手(macOS)或直接调用这把密钥(Windows)签出被信任的证书,也能删掉它;怀疑被用过时,`uninstall` 再 `install`(D57②)。Linux 的私钥是 0600 的文件,被偷的后果到 `uninstall` 为止。


## 分发 / release(D23)

**(A · 渠道)**:npm 包 **`trocar-cli`**,命令 `trocar`(`package.json` 的 `bin`)。包名带 `-cli`,是因为 npm 以「与已有包名太像」为由拒绝 `trocar`;命令名不受影响(D68①)。常用装法 `npm i -g trocar-cli`;只跑一次某条命令用 `npx trocar-cli <command>`。同一个 tarball 连同 `SHA256SUMS` 挂在 GitHub Release 上,`npm i -g <tarball>` 装起来与从 registry 装一样。第一个发到 npm 的 trocar 是 `0.2.0`:registry 上已有的 `0.0.x` 只是占名用的空包,所以 `0.2.0` 最晚在仓库公开的那个小时内发出,随后 `npm deprecate trocar-cli@"<0.2.0" "name reservation; install trocar-cli@latest"`。
- **为何最省**:Node CLI 跨平台白送(Node 消化 OS 差异);读取侧只用 Node 自带能力(文件 + JSON),**没有要为每个平台编译的 `.node`** → 包是平台无关的纯 JS 包(macOS 的几个预编译部件见 §E,随包拷贝)。
- **许可证**:FSL-1.1-ALv2(Functional Source License 1.1,未来许可证 Apache-2.0):源码可读可用,不许把它放进与 trocar 竞争的商业产品或服务里提供给别人;每个发布的版本在发布满两年后转为 Apache-2.0。`LICENSE` 随包发出,`package.json` 的 `license` 写同一个标识。例外只有 `src/collector/arch/linux/bpf/` 里内核侧的 eBPF 程序:许可 GPL-2.0-only OR MIT(每个文件的 SPDX 头,与它的许可串 `Dual MIT/GPL` 一致),因为内核只让许可兼容 GPL 的程序用它要的内核 helper;README 的 License 一节写明。
- **包里有什么**:`package.json`、`README.md`、`LICENSE`、`bin/`、`src/`(含 §E 的预编译二进制与它们的源文件,以及入库的看板构建产物 `src/web/board/`,D75③),别的都不进包;看板源码 `web/` 不进包。没有运行时依赖(D18),没有 lifecycle 脚本(D65①,见下)。

> **`npm install` / `npx` 只放代码与 `trocar` 这个命令(D65①,必拒违反)**:包里**没有 lifecycle 脚本**;装包不生成根、不碰信任库、不注册登录自启、不起守护进程、不写任何 agent 的配置。依据:**npm ≥ 7 不跑卸载脚本**(npm 文档 "A note on a lack of npm uninstall scripts"),所以装包阶段装上的任何东西,卸包时永远撤不回来 → 违「卸载不留残」(不变式 5([0.0](0.0-overview.md) §核心不变式));`--ignore-scripts` 很常见,行为会按机器而异;全局装可能以 root 跑,那是另一个用户的信任库与自启(D36);信任与自启要的是 OS 自己的框(D55① · D61),不许从一次包安装里弹出来。机器上的状态**全部**由 `trocar install` 装、`trocar uninstall` 撤(§C · §D)。**看板随 `install` 一起到位**(D65② · D66):看板由守护进程托管,而 `install` 注册自启并把守护进程拉起来,所以装完就一直在;`trocar board` 只是印出带口令的网址并打开浏览器,没有要用户自己起的服务进程。`install` 之前 `trocar board` 就说要先跑 `trocar install`。

**(B · 本机发布)**:CI 与发布都不用 GitHub Actions;门在本机([0.1](0.1-engineering-rules.md) §4),发出去的 tarball 就是过了本机门的那一个。步骤与顺序写在 [`docs/RELEASING.md`](../../docs/RELEASING.md):
1. macOS、Windows、Linux 上各跑一次全新 HOME 的全量 `npm test`,加 `npm run test:build`(入库的看板构建产物与 `web/` 一致,D75③);
2. `npm run release:pack`(先跑下面的 release 检查,再写出 `dist/<tarball>` 与 `dist/SHA256SUMS`),每个 OS 上从这个 tarball 装起做一次冒烟,在干净的机器、虚拟机或空闲的用户账号上,从不在自己在用 trocar 的那个上;
3. `npm run release:check` 再过一次,`dist/SHA256SUMS` 核对通过、HEAD 仍是打包时的提交:发出去的就是冒烟过的那个 tarball,不再打包;
4. 打带注释的 tag `v<version>`;
5. `npm publish dist/<tarball>`,用维护者自己的 npm 账号与 2FA 一次性码(包设了 `npm access set mfa=publish`,每次发布都要一次性码,泄露的 token 发不了);
6. 推 tag;
7. `gh release create --verify-tag`,挂 tarball 与 `SHA256SUMS`,正文指向 [`CHANGELOG.md`](../../CHANGELOG.md) 的这一节;
8. 在一台干净的机器上从 registry 装起核对。

发坏了的版本:`npm deprecate` 它并发一个补丁版本,从不 `npm unpublish`(撤掉的版本号不能再用,已装的人也拿不到解释)。预发布版本用 `npm publish --tag next` 发出,确认后 `npm dist-tag add trocar-cli@<version> latest` 转正。

**已知限制**:没有 npm provenance(它要 CI 的身份令牌,而发布不经 CI);§F 的安全网(D65⑤)还没做,所以 `trocar install` 要从全局装的那份跑,不从 `npx` 缓存里的那份跑。

**release 检查**:`node scripts/release.mjs check|pack`(即 `npm run release:check` / `release:pack`)。退出码:0 全部通过(`pack` 还已写出 tarball 与 `SHA256SUMS`);1 有检查没过,或打包失败;2 用法错。每个没过的检查在 stderr 印一行 `release: <检查 id>: <原因>`。检查 id 是闭集:

| id | 通过的条件 |
|---|---|
| `branch` | `git fetch origin main --tags` 之后,当前分支是 `main` 且 HEAD 等于 `origin/main` |
| `clean` | `git status --porcelain` 什么都不印(未跟踪的文件也算:它们会被打进包) |
| `unpublished` | `npm view <name>@<version> version --json` 说没有(E404)或什么都不印;印出版本号算没过;别的错误也算没过(查不到不等于没占用) |
| `tag` | 不存在 tag `v<version>` |
| `license` | 根目录有 `LICENSE` 且在打包清单里,`package.json` 的 `license` 非空 |
| `private` | `package.json` 没有 `private: true` |
| `lifecycle` | `package.json` 的 `scripts` 里没有 npm 的任何 lifecycle 名字(`prepare` `prepack` `postpack` `prepublish` `prepublishOnly` `publish` `postpublish` `preinstall` `install` `postinstall` `preuninstall` `uninstall` `postuninstall` `preversion` `version` `postversion` `dependencies`) |
| `files` | 打包清单里每个路径要么是 `package.json`、npm 总会带上的 `README*` / `LICENSE*`,要么在某个 `files` 条目之下;没有 `*.ndjson` |
| `bin` | 每个 `bin` 目标都在打包清单里且带执行位 |
| `native` | `src/collector/arch/darwin/native.mjs` 的 `NATIVE` 里每个文件都在打包清单里、位于 `src/collector/arch/darwin/native/` 之下且带执行位 |
| `pins` | 每个原生文件在盘上的 sha256 等于同一模块 `pins()` 给的值(钉住的值只写在那一处) |
| `notes` | `CHANGELOG.md` 有 `## [<version>]` 一节,链到至少一份 `docs/release-notes/*.md`,且它链到的文件都在 |

`pack` 先跑同一组检查:有没过的就退出 1,不写 tarball 也不写 `SHA256SUMS`;都过了就 `npm pack --pack-destination dist`,再写 `dist/SHA256SUMS`,一行 `<tarball 字节的 sha256 十六进制>  <tarball 文件名>`(`sha256sum` 的格式)。

**(C · 版本 / 卸载)**:`trocar --version` 报版本;`trocar uninstall` 一步撤掉证书与 trocar 自己,采集数据默认保留(D39)。什么时候拒绝、按什么顺序撤、哪些例外保留,见 [1.6](1.6-cli.md) §3.6;macOS / Windows 的撤法见 [4.11](4.11-collector-model.md),Linux 见 [4.6](4.6-process-collector.md) §安装清单与卸载。Linux 采集器的卸载分两级(D36):`trocar uninstall` 按用户撤销、不要 sudo;能力助手是整机的,另由一步 sudo 移除,移除前报告本机还有哪些用户的实例在用它。两级都做完才算零残留。`trocar update` 把 trocar 换到最新代码(D67,[1.6](1.6-cli.md) §5.5):git 仓库装的自己拉代码;npm 装的由用户跑 `npm i -g trocar-cli@latest`,再跑 `trocar update` 把守护进程换到新代码上、在新代码上再跑 `install` 与 `on`(守护进程已自己换到新代码上时也一样,看安装清单的 `install.code`);从 0.1.0 起,新版本接手旧版本留下的 `~/.trocar`。

**(D · 开机自启 · D39 · D61)**:`trocar install` 注册**用户级**自启并拉起守护进程,`trocar uninstall` 撤销;`on` / `off` 不碰自启(D61:开关跨开关机不变),**绝不写全机启动项**(与信任面的平台中立原则同精神)。装/撤对称:Linux = 用户级 systemd 单元(`arch/linux/unit.mjs`);macOS = 用户级 LaunchAgent `~/Library/LaunchAgents/com.trocar.collector.plist`([4.9](4.9-macos-collector.md) §4);Windows = 计划任务 `\trocar\collector`([4.8](4.8-win-collector.md))。控制入口 = CLI `trocar install` / `uninstall`([1.6](1.6-cli.md))。

**(E · 原生部件 · macOS / Windows · D57)**:macOS 的签名助手(`trocar-sign-helper`)、读启动环境的 `procenv` 和列本用户 TCP 套接字的 `socktable` 是预编译好的通用二进制(ad-hoc 签名),随仓库提交,测试钉住 sha256;`scripts/build-darwin-native.sh` 只在一次专门的提交里重编,同一提交改钉住的值;`npm pack` 只拷贝,不重编。`install` 把签名助手拷进 `~/.trocar/collector/bin/`(`procenv` 与 `socktable` 从包里的路径跑);已装的签名助手哈希不同时,只在交互运行的 `install` 里替换([4.11](4.11-collector-model.md) §3 ⑮)。Windows 的安装目录包装在 `install` 时用系统自带的 `csc.exe` 编译。

**(F · 安全网:卸包与 `npx` 缓存 · D65⑤)**:用户没先 `trocar uninstall` 就 `npm uninstall`(或 `npx` 的缓存被清),机器上会留下一个指向不存在的代码的自启项。要的三件事:自启项经 `~/.trocar/bin/` 里的一个小启动器起;启动器发现包不在了就跑独立的 `trocar-off`(别把 agent 留在一扇死门上)并把自启项退役,而不是崩着被反复重拉;`install` 拒绝从 `npx` 缓存路径注册自启。记为阶段 5 的分发项,本轮不做。

## Out-of-scope

- **bytes 什么意思 / 存储 / 查询 / 服务** → [3.1](3.1-adapter-contract.md)/[4.2](4.2-storage-etl.md)/[3.5](3.5-query-layer.md)/[4.4](4.4-server.md);本单元只管「装到机器上 + 分发」。
- **多用户 / 账号 / 云端分享 / 对外暴露** = Non-Goal(同一台机器上几个系统用户各装一套不算,见 D36);分发**只复制单机仪器**,不给这些能力(违反=必拒)。
- **拦截 / 修改 / 重发的授权与入口** → [5.1](5.1-intervention.md) / D30。
- **系统安装包当生命周期、自带运行时的桌面壳**:`.dmg` / `.pkg` / MSIX / deb / rpm / AppImage / Flatpak 都没有以该用户身份跑 `trocar uninstall` 的卸载钩子,守不住不变式 5(同 D65 不用 npm 生命周期脚本的理由);Electron / Tauri 自带运行时和第二个后端,与守护进程托管的看板重复,违 D18 零运行时依赖,mac 上自动更新还要 Developer ID。

## 验收(可跑 check)

1. **单机边界不因分发松动**:装完起 server 仍只绑 `127.0.0.1`(承 [4.4](4.4-server.md) server gate);非环回接口连不上。
2. **零残留**:先 `off`、再 `uninstall` 之后,HOME 与 OS 状态等于 `install` 之前的快照:CA 不在任何信任库、私钥不在、各 harness 的证书项与代理入口撤净、被测程序直连;没 `off` 时、或还有持有者时,`uninstall` 拒绝、快照不变。macOS / Windows 另核对:根的密钥不在;Kimi 的真程序放回原处(包装已被官方安装器盖掉时只删 `.trocar-real`);证书文件里带标记的一段撤净,用户之后加的内容留着。采集器:Linux 上按用户卸载与移除能力助手两级都做完后零残留;撤不掉的入口连同它的改前副本、它指向的合并包与安装清单保留到下次卸载(D39③);Linux 上还有加载过合并包的 agent 活着时,要等它退出再跑一次按用户卸载;OpenCode 的 npm install 残留只报不删;细项见 [4.6](4.6-process-collector.md) 验收 S10。
3. **release 检查**:从一组每项检查都能过的事实出发,任意弄坏其中一个事实,恰好那一个检查 id 没过、退出码 1;一个都不弄坏时退出码 0。
4. **release 打包**:有检查没过时退出 1,不写 tarball 也不写 `SHA256SUMS`;都过了时写出 `dist/SHA256SUMS`,恰好一行 `<tarball 字节的 sha256 十六进制>  <tarball 文件名>`(`sha256sum` 的格式)。
5. **README 只叫人装本包**:README 里每个叫读者用 `npm i -g` / `npm install -g` / `npx` 装或跑的包,名字都等于 `package.json` 的 `name`(可带版本号或 dist-tag 后缀)。
6. **包里是构建好的看板**:`npm pack --dry-run` 列出的文件里有 `src/web/board/` 下的文件,没有任何 `web/` 下的文件(D75③)。

## Extensions

- **预编译单文件二进制(SEA / `pkg`)**:产 `trocar-{darwin,linux,win}-{arch}` 挂 Release,下载即跑、无需 Node。**坑(记明)**:单文件要跟着 Node 运行时按平台各打一份、随 Node 版本重打,故 v1 走 npm、二进制留此。
- **包管理器渠道**:Homebrew tap(mac/linux)/ 其他;皆在 npm 主渠道稳定后。
- **`update` 自己跑 npm**:npm 装的那份由 `trocar update` 直接跑 `npm i -g`。现在不做:`update` 拒绝 root([1.6](1.6-cli.md) §1.5),而全局 npm 前缀常要管理员权限。
- **经 CI 的 provenance**:发布改由 CI 带身份令牌跑,`npm publish --provenance`。现在门与发布都在本机,没有 CI。
- **桌面外壳(菜单栏 / 托盘)**:一个只当守护进程客户端的小外壳,由 `install` 放下、`uninstall` 拿走,进同一份装机清单;看板照旧在浏览器里开(D66)。外壳读 `GET /control/status`,显示各 harness 的开关与采集失败(D38,失败弹系统通知);「Open board」带令牌打开看板;写只走 `/control` 的 on / off,不做 `install` / `uninstall`(D66④)。**图标可以隐藏,也可以再显示**:外壳菜单里的「隐藏图标」只收起图标、外壳照常运行;再次打开这个 app(macOS 的 Launchpad / Spotlight,Windows 的开始菜单)就把图标放回;这个选择存在 `~/.trocar/` 下,随 `uninstall` 删掉。外壳不另占自启项:守护进程每次起来时拉起它(文件不在就跳过),所以外壳被删不留指向空处的自启项。三个系统:macOS 是一份预编译、ad-hoc 签名的 Swift `.app`,入库并钉 sha256(同 §E 的原生小件),`install` 复制到 `~/Applications/trocar.app`;Windows 由 `install` 用系统自带的 `csc.exe` 编出托盘程序(同 Kimi 安装目录包装),放每用户开始菜单快捷方式,并登记 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\trocar`,卸载命令就是 `trocar uninstall`(拒绝条件不变);Linux 在 `~/.local/share/applications` 放一个跑 `trocar board` 的 `.desktop` 文件。不要管理员、不要付费签名或公证:文件是 `install` 在本机写的,不带 `com.apple.quarantine` / Mark-of-the-Web,Gatekeeper 与 SmartScreen 不检查。**坑(记明)**:macOS 把 `.app` 拖进废纸篓不跑任何代码,卸载仍然只有 `trocar uninstall`;外壳没了时 `status` 照实报、`install` 重新放回,证书与 agent 配置不跟着外壳走。排在一行安装器之后。
