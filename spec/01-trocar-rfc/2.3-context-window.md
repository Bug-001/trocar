# trocar · RFC 2.3 — 忠实上下文回放部件(★ 招牌)

> **服务意图(A2)**:意图 ①(逐字回放某步的完整上下文——这是 AC-1 逐字 diff 的**落点**)+ 兼作意图 ② 的**宿主**(块级「缓存标记」/「每次都变 · 不影响缓存」、前缀变了时的**变化线**;数值真相来自 [3.3](3.3-cache-model.md),缓存状态在步头的「缓存」按钮里,归 [2.2](2.2-call-turn-card.md))。
> **受众**:人(核对"这就是模型这一步真收到的每一比特")+ agent(据此从 [3.2](3.2-normalized-model.md) 的 `call_blocks`/`block_contents` 渲染,**不回退到 provider 专属分支**)。
> **前置**:块数据 = [3.2](3.2-normalized-model.md)(`call_blocks` 有序 + `block_contents` 去重 + `text_ref` 回源);块语义 / `faithfulness` 由 [3.1](3.1-adapter-contract.md) 的 adapter 定;cache 徽章 / 断点真相由 [3.3](3.3-cache-model.md) 定;中栏白名单、落点与提问卡的装配 = [1.4](1.4-central-board.md);步头、缓存判定与「对比」菜单 = [2.2](2.2-call-turn-card.md);词与标记 = [1.5](1.5-states-aesthetics.md) §看板词表 · §标记;「第 N 步」的编号 = [1.2](1.2-shell-layout.md) §编号:步与调用;承 demo `linearContext`/`ctxBlock`/`ctxBody`/`rawContentText`。

## Goal
把一条 call 的上下文摊平成**一列有序 block 卡**,严格 assembly order **tools → system → messages**,每块一卡(role/kind/预览 + 保真标 + 缓存标记),点开即逐字看该块全文。这个窗口(回放台中栏的 `#ctxwin`,[1.4](1.4-central-board.md))**就是**模型这一步真收到的每一比特——**无"不在列表中"、无另开的 raw 列**;窗口 = 真相本身。它是 AC-1 逐字 diff 的落点。承 demo v11 单窗口验证,泛化到跨 provider(承 3.1/3.2)。

看板 v2 成为产品看板(D18c)起再加两条:窗口只在**有证据**时才说「逐字」;这一步的前缀和缓存对比步不同时,才画一条**变化线**说从哪里起变了。要求是:这一步的前缀和上一步不一样了,才说什么地方变了。

窗口末尾另起一段**这一步的回复**(§这一步的回复):模型对这一步的回答,与请求块分开、不算进「模型收到的每一比特」,AC-1 的逐字 diff 对象仍是请求块。跟随最新时最新的回复因此就在读者看的地方(会话末尾的回复没有下一次请求可以带着它)。

## 前置定义(Definitions)
- **块定义与位置属性**:这一步的列表由它车道的 `lane` 读物化出来([3.5](3.5-query-layer.md) §会话读:父步列表 + `ops`),列表里每个 `bid` 对应一条定义 `def`(`fh`、`ref`、`sec`、`role`、`kind`、`label`、`cc`、`ff`、`head`、`preview`、`chars`、`bytes`、`resKey`、`r`;寻址不到时 `unaddressable` 与 `inline`),每个位置另有 `attrs{query?, volatile?}`。本单元说「块的某字段」都指这两样;`def.ref` 就是 [3.2](3.2-normalized-model.md) 的 `text_ref`。
- **block 卡(`.cblk`)**:列表里一个位置的可视卡;默认折叠(只显头),点开才画正文格。
- **格(cell)**:块正文的那一个件(`replay/cell.mjs : cellBodyHtml(cell, mode)`,`cell = {bid, ref?, inline?, r, ff, chars, preview}`);请求块、回复行、原始数据面板的请求参数与抽屉([2.6](2.6-detail-panel.md))都经它画。两种模式见 §两种模式。
- **渲染规格 `r`**:`{as, tone?, title?, f?}`,查询工作进程按每个不同的定义算一次(`src/view/render-kind.mjs : renderOf()`)、随投影持久;Readable 模式只按它画。
- **块行**:block 卡的那一个行组件(行头 + 正文,`blocks.mjs : blockRowHtml()`);请求块与回复行都经它画。
- **回复行**:这一步的回复的一部分(思考 / 正文 / 一次工具调用)画成的块行;它不是请求块(§这一步的回复)。
- **段(section)**:`tools | system | messages` 三段之一(归一化;Codex `instructions`→system、`input[]`→messages,承 [3.2](3.2-normalized-model.md))。每段一个段头:段名与块数归 [1.4](1.4-central-board.md),大小与保真归本单元。
- **提问卡**(原「turn 分组」):messages 段内按"人类提问 ▸ 到下一条提问之前的块"聚成的可折叠卡(承 demo `messageTurns`/`.cwturn`);装配与折叠记忆归 [1.4](1.4-central-board.md),卡头归 [2.2](2.2-call-turn-card.md)。
- **保真标(faithfulness marker)**:块**不能证明逐字**时就地贴的可见标记(见 [3.2](3.2-normalized-model.md) 枚举 `verbatim|metadata|opaque|summarized|omitted|truncated`;判法见 §保真标:证明规则)。
- **证得逐字**:块的 `def.ref` 回到的字节的哈希就是它的 `bid`,且 `def.ff` 缺省或为 `verbatim`(判法见 §保真标:证明规则)。
- **缓存标记 / 每次都变**(原「cache 徽章」):块上的「缓存标记」(请求在这一块声明的 `cache_control` 位置)与「每次都变 · 不影响缓存」(`volatile` 块),从 canonical 列渲染。
- **缓存对比步**:服务端比缓存用的那一步——同一 lane 里前一个没失败的调用。
- **内容对比步**:用户选来比内容的那一步;默认就是缓存对比步。
- **变化线**:这一步的前缀和缓存对比步不同时,画在第一个变了的块前面的一条线。
- **调用保真行**:一条调用整体的保真事实(上下文缺了前序、没采全……),在窗口顶上说一次。
- **窗口行**:这一步没有一块能回到原始字节时,在窗口顶上说一次。
- **手里的车道**:客户端已经拿到 `lane` 回答、能物化出各步列表的车道;别的车道是**未到手**的(§车道未到手)。

## Plan(选定方案 + 取舍)
**选定**:**单一忠实窗口 + 逐字懒加载 + 徽章从 canonical 列渲染**。窗口只持有这一步物化出的块定义与位置属性(§前置定义);正文在点开时按 `def.ref` 经 `block` 读回源**懒加载**([3.5](3.5-query-layer.md) §会话读),按 `bid` 只取一次。看板 v2 起再定三件:
1. **保真按证明规则标**:证得逐字的块不写字;一段全部证得时,段头写一次「以下逐字」;其余每块写自己的可见标。(Q9 选 c;证明规则见下。)
2. **窗口里的缓存只剩变化线**:前缀变了才画,说从哪里起、和第几步不同、原因;命中多少、过期重建、服务商一侧的矛盾、失败等状态都在步头的「缓存」按钮里([2.2](2.2-call-turn-card.md))。
3. **两个对比步分开**:变化线对的是缓存对比步;块上的「新」和移除的块对的是内容对比步。

**备选(未选)**:① **双栏**(左渲染视图 + 右原始 JSON 列)——demo v0 试过,注意力撕裂,且"渲染视图 + 独立 raw"结构诱导"渲染即真相"误判;② **每块预存全文进前端**——违反 [3.2](3.2-normalized-model.md)"本表不存全文、`text_ref` 回源"、且 `content_hash` 去重失效、内存爆;③ **每块一个绿色「逐字」标**(本单元旧写法)——一屏上百个同样的标,把真正要看的非逐字标淹掉;旧实现还在缺 `faithfulness` 时默认当逐字,没有证据也写了「逐字」;④ **每一步都画缓存标记槽、写缓存状态**(旧写法与 v2 原型)——否决:命不命中不值得在这么紧凑的空间里占篇幅;⑤ **和参考步相同的段折成一行、画水位线**(重构提议)——沿用既有设计,中栏放整个上下文,保持平铺。
**取舍**:窗口零全文冗余 + 逐字锚(`text_ref`)不飘 → 展开的每一个字符都可回到源 bytes,AC-1 天然成立。证明规则让「逐字」只在有证据时出现;代价是块正文打开后回来的不是逐字时,段头的「以下逐字」要当场撤回(§保真标)。

## 部件结构(承 demo)

### 有序摊平:tools → system → messages(必拒乱序)
读 `call_blocks`(按 `seq`)→ 依次渲染。demo `linearContext(request)` 现解析出此序;**产品改从 [3.2](3.2-normalized-model.md) 的 `call_blocks.seq` 读**(见「跨 provider 泛化」)。assembly order MUST 与线上装配序一致——**乱序即谎报 AC-1**。守卫:`test/dissect/cc.test.mjs`「dissectBlocks walks tools → system → messages with contiguous seq」+ `test/web-v2/ctxwin.test.mjs`(段序与 `data-bi` 递增,[1.4](1.4-central-board.md) 验收 #1)。

### block 卡:折叠头 + 懒展开体
- **头(`.cbh`)**:`role` 徽 · `kind` tag(如 `def`/`thinking`/`action · <tool>`/`observation · error`/`say`/`system-reminder`)· **preview**(≤90 字符、折空白;承 demo `preview=slice(0,90)`)· 缓存标记 / 每次都变 · **「新」(D17②)** · 字符数(写「字符」)· 保真标(只在不能证明逐字时)。头的这些词是服务端的 `def.head{role, tag, label}` 与 `def.preview`,原样当数据显示;系统块的名字 = 服务端的 `def.label`,也当数据显示。前端 MUST NOT 按 provider 分支另起名字(不变式 3;守卫 `test/web-v2/no-provider-branches.test.mjs`)。行头键盘可达(`role="button"`、`tabindex="0"`、`aria-expanded`),Enter / Space 与点击同样开合。
- **「新」(承 D17②)**:该块的 `def.fh` **不在内容对比步**列表各块的 `fh` 里(且这一位置不是 `volatile`)→ 块左边一条安静的墨色竖线 + 「新」——它是本步新增的内容(= 重发 Δ 的组成),与步头「组成」按钮里的增长 Δ([2.2](2.2-call-turn-card.md))呼应;复用块**不标**,保持安静。这一 lane 的第一次调用不标(没有对比步);内容对比步所在的车道还没到手时也不标——两种情况都不是"全都是新的"。demo `ctxBlock(b,i,prevKeys)`。逐块级「哪个块最重(段内占比)/ ↺复用×N」是 Extensions(承 draft),v0 先给最锋利的「新 vs 复用」二分。守卫:`ctxwin.test.mjs`。
- **体(`.cbc`)**:折叠的行没有正文 DOM;首次展开时按 §两种模式 画格(`cell.mjs : cellBodyHtml()`),正文按 `def.ref` 经 `block` 读取。**tools 段体 = 逐字 schema(D15,新 trace)**——展开见完整 `description` + `input_schema`;**D15 前的旧 trace 回落元数据摘要**(见保真标)。取回失败时正文写原因、下次打开重取(守卫 `test/web-v2/block-load.test.mjs`)。

### 两种模式(D70)
每个打开的格有两种模式:**Raw**(默认)与 **Readable**。依据:D70(每个格两种模式:一种是原始字节,按 JSON 格式化;一种是富文本,按块类型或输出类型画);[1.4](1.4-central-board.md) 的 AC-1(逐字是默认,不可改);不变式 3 · 4。

**Raw**:存下的字节,排版后呈现。
- **排版规则**(`replay/jsonlay.mjs`,纯函数,对正文扫一遍):字符串外,在 `{`、`[`、`,` 之后与 `}`、`]` 之前插入换行加缩进(2 × min(深度, 12) 个空格),**只在线上那里没有空白时插**,已经排好版的 JSON 原样显示;`:` 后不插空格,所以 `"command":"ls"` 仍是一段,浏览器查找字节片段照样命中。字符串内逐字照抄、转义照样可见,每个 `\n` 转义(反斜杠加 n,原样保留)之后插一个换行,JSON 包着的工具输出与文件列表因此在默认视图里按行读。不是一个 JSON 值的正文逐行处理:一行从它第一个 `{` 或 `[` 起若剩下的部分解析得出就排版,否则原样照抄;回复的 SSE 区间因此每个 `data:` 的 JSON 都排了版、帧格式照样可见,没有 SSE 分支。
- **插入的每个字符**都在 `<span class="lay" aria-hidden="true">` 里,`user-select: none`;逐字的部分是不带属性的文字节点。
- **契约**:格的文字去掉 `.lay` === 字节。这就是 AC-1 的检查(验收 #1)。
- **确切复制**:`.cellraw` 上的 `copy` 监听沿格的文字节点走、跳过 `.lay`,把选区两端换成偏移 a、b,写入 `bytes.slice(a, b)`;每个浏览器都给出确切字节。
- **标签**:工具栏写「Raw · line breaks added for reading」,悬停「Line breaks and indents shown here are not in the bytes. Copy and selection give the exact bytes.」。块的保真标(◐ 重新序列化等)两种模式都在。

**Readable**:按渲染规格 `r` 画(`replay/kinds.mjs : renderKind(r, value, {budget}) → {html, more}`),渲染器是闭集,不认识的 `as` 按 `text` 画:

| `as` | 画法 |
|---|---|
| `text` | 正文字体的 pre-wrap;思考变淡 |
| `markdown` | 子集:标题、列表、围栏(按 `code`)、行内代码、强调、竖线表格(格内横向滚动)、引用;源里的 HTML 当文字显示;链接是文字加 URL,从不是锚 |
| `code` | 等宽、不折行、格内横向滚动,可选行号栏(提出来的行号保留源的编号),`title` 作说明;ANSI 转义显示成可见的 `␛[…` |
| `shell` | `$` 加命令;argv 数组只为显示按 shell 引号拼起来;说明字段是淡色说明,其他输入键在下面按 `kv` 画 |
| `diff` | 补丁逐行解析(`+`、`-`、`@@`、`***`);编辑对(旧串 + 新串)按 Myers 行 diff(D ≤ 256、每侧 ≤ 2,000 行,在切片预算内),超出任一上限时画「Before」「After」两栏;`+` `−` 是真字符,不只靠颜色;只有统一视图 |
| `json` | 每个对象与数组一个原生 `<details>`/`<summary>`,子节点在第一次 `toggle` 时才建;首次画开 2 层、最多 200 个节点;超过 100 项的数组分成每组 100 项的嵌套 `<details>`(原生展开,不是加载控件) |
| `kv` | `<dl>` 网格,480 px 以下堆叠;每个值是一个子格,按自己嗅出的类别画 |
| `media` | 图片(只 png、jpeg、gif、webp)用已经取到的 base64 建 Blob URL 显示:不再请求、不走网络;宽高从图片头读出预留空间,`decoding=async`,alt 写类型、尺寸与大小;条目淘汰时撤销 Blob URL;SVG 按 `code` 显示;PDF 显示类型与大小加一个保存动作;URL 来源的图片当文字显示、从不加载 |
| `sections` | 标签名作小标签,每段正文按自己嗅出的类别画 |
| `opaque` | 「Encrypted reasoning · signature N bytes」 |
| `parts` | 子块按各自的 `r` 画 |
| `tone: 'error'` | 任何类别外面加错误的边框与颜色 token |

- 每个 Readable 格带一行固定文字「Readable · drawn from the bytes, not the bytes」,旁边是闭集词表里的类别词(D58:「shell command」「diff」「file」「JSON tree」等)。
- **画不了时**(截断的 JSON、坏的 base64、畸形补丁):退回 `text`,就地写「Could not render as <kind>; shown as text」;源被截断的从不被「补全」。
- **安全**:渲染器只经 `esc()` 拼 HTML,只用固定的元素集:`pre`、`code`、`span`、`div`、`dl`/`dt`/`dd`、`table`/`tr`/`td`/`th`、`details`/`summary`、`img[src^=blob:]`、`button`;别的元素与属性一律不出现。
- **颜色**:`--diff-add-bg`、`--diff-del-bg`、`--diff-hunk`、`--err`、`--err-bg`、`--j-key`、`--j-str`、`--j-num`、`--j-lit` 定义在 `:root`,两个深色选择器下各重定义一次(同 `css/replay.css`);每对文字 / 背景在两个主题里都 ≥ 4.5:1。手机宽度下 Raw 与 `text` 用 `pre-wrap; overflow-wrap: anywhere`,`code` 与 `diff` 在格内横向滚动、从不让页面横向滚动。

**状态**:
- **桌面默认**:Raw 或 Readable,存 `localStorage['trocar.cellView']`,每次读写都包 try/catch,存储不可用时就是 Raw;跨步、跨会话保持。
- **逐格覆盖**:内存里 `Map<bid, mode>`,LRU 500,按会话分开记(会话缓存里每个桌面一份,1.2 §路由「离开再回来」;换到别的会话不带过去,回到缓存里的会话照旧,桌面被挤出时丢掉它那份,依据:D71③ 留住读者的视图状态);按内容 id 记,所以一个翻成 Readable 的工具结果在后面每一步重发时都还是 Readable。
- 翻转桌面默认时清空逐格覆盖,只重画打开的格。没有按段的范围。

tools/system 段:块平铺。messages 段:按提问卡分组、可折叠,默认展开最新一张(承 demo `turnOpen`/`lastTurnCall`;D12 折叠记忆归 [1.4](1.4-central-board.md))——长会话不淹没当前步。和对比步相同的段 MUST NOT 折成一行(中栏放整个上下文;守卫 `ctxwin.test.mjs`,[1.4](1.4-central-board.md) 验收 #8)。

### 保真标:证明规则(保真边界 · 必拒隐瞒)
承不变式 4([0.0](0.0-overview.md) §核心不变式):凡块非逐字,UI MUST 就地标,MUST NOT 让人误以为看到完整线上真相。看板 v2 起「逐字」本身也要有证据。

**证明规则(MUST)**:
- 一块**证得逐字** ⇔ 它的 `def.ref` 回到的字节的哈希就是它的 `bid`,且 `def.ff` 缺省或为 `verbatim`。工具块同一条规则(D15 前的旧 trace 的 `ff` 是 `metadata`)。
- **首个携带者**:`bid` 盖住的是这一调用自己的确切区间(按哈希,或按线程项的同一性、按字节前缀 `memcmp` 证明相等),所以显示首个携带这些字节的记录里的那段,对这一调用就是逐字。技术细节写「Same bytes as this call's block, read from the first record that carried them (step k · record X).」(k、X 当数据)。
- 证得的块不写可见字,只带 `data-ff="verbatim"` 与读屏文字(「<行头>,逐字」)。一段里每块都证得时,段头写一次「以下逐字」。
- 其余每块写自己的可见标,一块最多一个([1.5](1.5-states-aesthetics.md) §标记):已知的非逐字值、未知值、缺值、`unaddressable` 都算。**MUST NOT 在没有证据的块上写「逐字」**:缺 `ff` 不等于逐字。
- 块正文打开后,`block` 回来 `bytes: null`(`errors` 里有 `where: <ref>` 的一条)或 `fidelity ≠ verbatim` 时,这一块当场补上可见标,它所在的段当场撤掉「以下逐字」。唯一的例外:调用带 `wire.reqEncoding` 时回来的 `fidelity:'decoded'`——那是解压后的确切文字,调用保真行已经说过一次,不撤。
- 模型这一步的回复用同一规则:回复块的 `def.ref` 是 `resp.raw::<a>-<b>` 区间时它证得逐字(那是流式回复的字节);没有区间之前标「◐ 解析后的回复」,永不没凭据就写逐字(§这一步的回复)。

守卫:`test/web-v2/fidelity-marks.test.mjs`(验收 #2)。证明规则见下。

逐值(词在 `labels/replay.mjs`,按 [3.2](3.2-normalized-model.md) 的闭集与 `block` 回答的 `fidelity` 取;一块同时有几条时,按下表从上往下取第一条):
- **`verbatim`(tools 段 · D15 默认)**:采集逐字存完整 `description` + `input_schema`(承 `capture.mjs`);adapter([3.1](3.1-adapter-contract.md) `linearContext`)派生 `descChars`/`props` 供折叠头显示、`verbatim=true`;体展开渲染完整 schema。有 `def.ref` 时它证得逐字:块上不写字,只带 `data-ff`(仍纳入 AC-1);没有 `def.ref` 时按下面「不能回源」标。
- **`metadata`(tools 段 · 仅旧 trace 回落)**:D15 之前的 trace 只有 `name + type + input_schema_props(参数名) + description_chars`,**schema 文本不留**。此时 `def.ff` 是 `metadata`,块上写可见的「◐ 只有元数据」;体里写工具名、参数名、「描述 N 字符(schema 文本没有存)」,再加一句「只有元数据:完整的 JSON schema 没有被采集,模型收到的是完整 schema」。**必拒**把它渲染得像逐字 schema。
- **`opaque`**:加密 reasoning(Codex `encrypted_content`)/ `redacted_thinking` → 块上写「◐ 加密,没有明文」,体显占位(demo:`[redacted_thinking]`),MUST NOT 冒充空文本或伪造明文。
- **`summarized`/`omitted`/`truncated`**:源侧被客户端摘要 / 省略 / 截断的块 → 就地标其性质:「◐ 客户端的摘要,不是原文」/「◐ 源头省略了」/「◐ 源头就截断了」。
- **未知值**(不在上面的枚举里):「◐ 保真未知」,值本身进技术细节。
- **打开后回来的不是逐字**:`bytes: null` →「◐ 取不到字节」,体写原因,定位串进技术细节;`fidelity:'reserialized'` →「◐ 重新序列化过,不是线上字节」;`fidelity` 为空或是别的值 →「◐ 保真未知」。
- **没有 `def.ref`(`unaddressable`)**:「◐ 不能回源」,服务端给的原因进技术细节;体是 `def.inline` 带来的文字,上方一行「这段文字是块里带来的,不是从原始采集里逐字切出来的」。窗口行出现时,这一标不逐块重复(窗口级的事说一次,[1.5](1.5-states-aesthetics.md) §标记),读屏文字照带。
- **显示剪裁 ≠ 源截断(需分清)**:打开的格按 §两种模式 的切片显示,剪裁状态写「Showing N of M characters」——**全文仍在源里可回**,「Copy bytes」复制全部;这与 `ff=truncated`(源本身就没抓全,「◐ 源头就截断了」)是**两码事**,UI 措辞 MUST 区分"只显示了一部分"与"线上真相本就不全"。剪裁是显示状态,不是保真标([1.5](1.5-states-aesthetics.md) K-07)。守卫:`test/web-v2/render-verbatim.test.mjs`「a text over DISPLAY_CLIP chars is clipped to a prefix of the source and says the full length」+ `test/web-v2/cell-modes.test.mjs`(验收 #11)。

### 读与画:车道、播放头、归约前沿(D69)
窗口的数据只来自 [3.5](3.5-query-layer.md) §会话读:骨架行(`session`)、这一步车道的列表与定义(`lane`)、正文(`block`)。页只是传输分块(≤ 1 MB,看板自己接着取),没有正文预算,所以没有「这一步不在当前这一页」的态,任何状态都没有加载控件,也不出现「loading」这个词。依据:D69(不显示加载步骤、不造成界面卡顿);不变式 4(空框不冒充内容、失败都说原因)。

**车道未到手**(例如跳进一个从没取过的子代理):
- 最多 150 ms 内回放台什么都不变;热的车道读通常在这之内到,行直接换上,没有中间帧。
- 过了 150 ms,步头、调用保真行、用量、缓存格与组成条换成新的一步——它们来自这一步的骨架行,客户端一直拿着;行区保留各段的框,按组成定好大小,没有文字,`aria-busy="true"`。车道一到就填进去。
- 车道在空闲时预取:它的轨道滚进视野或被悬停时。

**播放头是调用,不是下标**:播放头、选中与打开的行按 `rid`(行再加 `bid`)拿着;「第 92 / 233 步」这类步号只在显示时由 rid 推出([1.2](1.2-shell-layout.md) §编号:步与调用)。一条排在播放头之前的晚到行只改计数,不改显示的内容;重新分车道时播放头跟着它的调用走。内容对比步(`diffRef`)也按 rid 记。

**窗口按 `bid` 打补丁**:行以 `bid` 为键;相邻的一步从两份列表的最长公共前缀起删掉旧行、补上新行,打开的格只要 `bid` 还在就保留它的 DOM、不重画;补丁后的窗口与整份重画的窗口相同。只有落点规则触发时才 `scrollIntoView`([1.4](1.4-central-board.md) §打开一步时落在哪)。

**快速拖动**(拖着 scrubber、按住方向键):目标合并成每个动画帧最多画一次,中间的步从不画;一步要的网络(打开的行的正文、未到手的车道)只在播放头停住 100 ms 之后才问。这一步自己的读同一时刻至多一个 `lane` 与一个 `block` 在路上,新目标用 `AbortController` 中止为旧目标发的读;它们和后台的读都经下面的加载器。画一步只用手里已有的正文,正文一律由这条停住后的读去取(跟随最新带进来的那一步除外,见 C3)。

**加载器**(依据:D71②③;实测历史按轮询节拍每 1.5 s 才取一页,一个 46 MB 的会话要 60–73 s,深链 `?step=500` 一页页往回走 36 s):除了轮询自己的 `session --since`,回放台的每个读(`lane`、`block`、`session --before`)都经一个优先队列,同一时刻至多 3 个在路上,不跟轮询节拍——一个读完,排着的下一个立刻发。次序:`block` 最先;然后播放头这一步缺的车道读;然后锚车道的账本链([3.5](3.5-query-layer.md) §手里车道的页);然后锚车道的旧页(`lane --to <prev>`)与会话骨架的旧页(`session --before <手里最早的行>`)两条链,各自背靠背、彼此并行,取到 `prev` 为 `null`、`more` 为假;然后别的手里车道的旧页。读者的动作(换步、跳转、深链、悬停轨道)把它要的读提到最前;轮询带来的车道读(增量碰到的车道)也经它,排在 `block` 之后。手里的部分在每条车道上总是从尖端起连续的一段(3.5 的页只能从手里的边缘接着取),所以「播放头那一页、前后页、这一章其余、其余从新到旧」在今天的读协议上就是上面这个次序。

**点名的一步不在手里**(深链 `?step=k`、Home、跳到手里那段之前的一步):已经画好的台原样不变,没画过的台是 ⑧ 的空框;加载器把通向它的两条旧页链排在别的车道之前,它的骨架行与车道一到,播放头直接落在它上面。中间那些步从不画,不出现加载控件,URL 一直写着点名的那一步。依据同上条与本节「车道未到手」。

**正文预取**:播放头在一步上停住 100 ms,用一次多 ref 的 `block` 读取锚车道上它前后各 8 步(手里的步)回复部分里还没缓存、也不在路上的正文,和这一步自己缺的正文同在这一次读里;所以 ±8 步之内换步不再等正文。正文缓存按字数有界(`cell.mjs : bodyCache`),只在内存(D27)。依据:D71②;实测每步一次 `block` 读。

**三个面板按键打补丁**:大纲、资源名录与原始数据面板和窗口一样画成按键的单元(`core/units.mjs`),换一步只增删改变了的单元,不整栏重建;相邻一步在资源名录里增删改的节点 ≤ 64 个。依据:D71②(换一步的活随它对上一步的差分走);实测资源名录每步 +731 / −731 个节点。

**抽取或归约没追上**(回答带 `pending`,[3.5](3.5-query-layer.md) §访问模式「归约前沿」):回放台画已有的部分,会话头的状态行写「Reading this session for the first time · N %」或「Catching up · N new calls」,没有控件;每次轮询带来的下一部分是普通的 `since` 增量。一次回答在页面上的活按画出来的量有界,不随它带来的行数涨:增量按步序二分插进手里的行、分片应用、片间让出;轨道与刻度只看刷子窗里的那一段(按时间二分找到),不逐条扫整条车道;会话信息弹出层里要扫全场调用的数在它打开时才算;换一步时窗口在这一步的任务里画,大纲、资源名录与原始数据面板在紧接着的下一个任务里画(连着几步只画最后那一步的),「只见到名字」按路径后缀的集合查、不两两比;所以一次回答带来的行再多,跟随、拖动与跳车道的任务也不随它变长(换一步本身画一步长对话的窗口时也一样,见下面「长对话的窗口」)。依据:不显示加载步骤、不造成界面卡顿;D64②;实测首读折叠期间跟随、拖动与跳车道各有 50–86 ms 的长任务。


**长对话的窗口**(一步上千个块):换一步时窗口的活按变了的行加一屏算,不按这一步的块数涨。依据:不显示加载步骤、不造成界面卡顿;D6、D18(虚拟化)、D64②;实测真实会话上每次 ← 约 18 ms 花在窗口上,约 7k 个节点。五条:
1. 一步的列表在桌面每变一次之后只物化一次(`model.mjs : stepOf()` 按 rid 记,任何 `apply*` 改了桌面就作废);行的画法按定义与它的几个标记记住,不变的行不重画。
2. 折着的提问卡只画卡头,不画它的行;卡打开时才画。折着的行今天就是 `display:none`:看不见、查找不到、选不中,所以什么都没少。跳转按数据找目标(`s.curFlat` 的下标、这一步的 `cacheBreak.idx`),先把目标所在的卡打开、所在的组画出来(`ctxwin.mjs : ensureRow()`),再滚过去;读者点的跳转照旧写进 D12 的折叠记忆。
3. 卡头变了(它的块数每步都涨)就地改卡头和属性,卡里已画的行不搬家、不重建。
4. 打开的卡里的行按组画:组界落在键的哈希 % 50 = 0 的行前,一组最多 200 行,所以插入或删掉一行只动一组;变化线与删去的块列表跟着它们的行走。这一步自己的任务画:已经画过的组、有打开的行的组、变化线所在的组、落点所在的组,再按离落点(没有落点时离窗口顶上那一行)由近到远画到行预算为止。其余的组是占位:高度 = 行数 × 一行不在屏上时的行距(收起的行带 `content-visibility: auto`,不在屏上时按它的预设高度排版,所以换上真行时排版不动),`aria-busy="true"`,没有文字、没有控件,里面从不放打开的行。之后每个任务画一组、组间让出;新的一次重画取消旧的那一轮、从自己的开始。落点的 `scrollIntoView` 在它的组画出来之后才跑。
5. 一轮画完时窗口的 DOM 等于整份重画:浏览器查找、选择、复制、Tab 顺序、`v` / `Shift+V` / `c` 与格都和今天一样;任何时候都不出现加载控件或「loading」(§读与画)。

**读失败**:最后一次画好的回放台留着,不清空;按 [1.5](1.5-states-aesthetics.md) K-29 就地写原因。手里的步在它车道的新回答到手之前一直留着(回答到了才按 3.5 的 from 规则截掉、换上),所以一次失败的 `lane` 读不会让已经画好的步变成空框。轮询里的 `lane` 读失败:那条车道留到下一次轮询再读,会话头写「未刷新 · 原因」并按 K-29 退避。播放头这一步的车道或打开的行的正文读失败:窗口里在那一处写 K-29 的一句(「This step could not be read.」)+「重试」,原因在折叠的技术细节里,不画 `aria-busy` 空框;按轮询的节奏再问。依据:不变式 4(空框不冒充内容、失败都说原因)、D38、K-29。

### 这一步的回复
请求的三段之后(有请求、解析得出的步上),`#ctxwin` 以一段「这一步的回复」收尾。回复行是格:这一步 `lane` 回答里的 `reply: [bid]`,每个 `bid` 一行,定义与请求块同形;停止原因取 `detail.norm.stop_reason`。最新一次调用的回复随它那一步到达,不等下一次调用带着它。它和上面的请求块是同一种视觉语言:一个段头,下面是块行。
- **段头**:「回复」,与请求的段头同一字级;写停止原因(服务商给的原值,等宽,不翻译)与回复的保真标,整段只写一次,不逐行写。保真按 §保真标:证明规则 最后一条:回复块带 `resp.raw::<a>-<b>` 区间时不标,否则「◐ 解析后的回复」;回复字节只存了一部分时「◐ 回复没采全」;永不没凭据写逐字。
- **回复行**:思考、正文、每一次工具调用各一行,次序 思考 → 正文 → 工具调用。每行经块行组件画(与请求块同一个):role `assistant` · kind(词取同一张块头词表:思考、消息、工具调用 · <工具名>)· 一行预览(`def.preview`)· 字符数;同样的开合(点击与键盘)、同一个格(§两种模式)。**Raw** = 这一块的 `resp.raw::<a>-<b>` 区间,即流式回复的字节,工具栏标明它是流式回复(SSE 帧照样可见);**Readable** = 拼好的回复块,按它的 `r` 画。
- **回复行不是请求块**:不带 `data-bi` / `data-rk`,不进段头的块数与大小,不带「新」、缓存标记、每次都变或逐块保真标,不参与变化线与移除列表,不进 AC-1 的逐字 diff,大纲([2.5](2.5-outline-nav.md))不数它们。
- **默认开合**:打开第一种有的部分——正文行;没有正文时工具调用行;都没有时思考行;其余收起(行上有预览)。所以跟随最新落在这一段时([1.4](1.4-central-board.md) §打开一步时落在哪),最新的回复不点就能读。读者的开合按 `bid` 记,在同一步的重画之间保留,换步复位。
- **失败的步**:段里只有一行「这次调用失败,没有回复」,服务端的原因进技术细节([2.6](2.6-detail-panel.md) §A)。
- **一条规则,两种画法**:回复的各部分、停止原因、保真标与失败原因由一个纯函数给出(`replay/rawpanel.mjs : replyOf()`,读这一步的 `reply` 定义与 `detail`);原始数据面板([2.6](2.6-detail-panel.md) §A)用它画紧凑行,窗口用它画块行,两处的正文是同一个格。
- 依据:跟随最新时会话末尾的回复必须看得见(所以有这一段),回复的格式要与上面的请求一致(所以和上面同一种行与格),[1.5](1.5-states-aesthetics.md) 一套视觉语言,D70①。

### 缓存标记 · 每次都变(意图 ② 的块级钩子)
- **「缓存标记」**:`call_blocks.cache_control` 非空(看板上是 `def.cc`)→ provider 声明的显式缓存位置(Anthropic `cache_control`);可缓存前缀存到**含本块**为止(承 demo tooltip)。悬停写声明的值(当数据)与「缓存怎么处理这个标记,各服务商不同」。不叫「缓存断点」([1.5](1.5-states-aesthetics.md) §看板词表)。
- **「每次都变 · 不影响缓存」**:`call_blocks.volatile=true`(看板上是这一位置的 `attrs.volatile`)→ 该块每 call 变 bytes 却被排除出 cache key(CC 的 `x-anthropic-billing-header` nonce:`cch=…`/`cc_prev_req=…`,cache-hit 仍 ~100%)。
- **两个标 MUST 从 canonical 列(`cache_control`/`volatile`)渲染,MUST NOT 在前端重嗅 provider 专属正则**(如 billing-header 匹配)——那属 adapter([3.1](3.1-adapter-contract.md))职责。demo 已守此缝:provider 检测在分析层 `linearContext`(填 `b.volatile`/`b.cc`),前端 `ctxBlock` 只读 `b.volatile`/`b.cc`;产品把检测**下沉进 CC adapter**、前端保持只读 canonical 列。**破此缝(往通用视图塞 provider 分支)= 需 RFC 才放行**(不变式 3)。守卫:`no-provider-branches.test.mjs`「wire words: cached_tokens and the billing "cch=" marker are caught」与「src/web/v2 outside mock/ carries no provider, tool, harness-id or host literal」+ `ctxwin.test.mjs`(验收 #3)。

### 变化线(取代 cache-break 标记槽与 why 行)
- **何时画(MUST)**:`cacheBreak.cause ∉ QUIET_CAUSES`(`append`、`first-call`、`volatile-nonce-only`;`replay/analysis.mjs` 的那一份清单,问题道 [1.3](1.3-timeline-tracks.md) 也读它)。失败的步也画——它说的是内容变了,不是缓存。别的时候不画;锚 `#cachebrk` 也只在线存在时有。
- **画在哪**:这一步列表第 `cacheBreak.idx` 个位置的块前面(归约里算的帧哈希 `fh` 最长公共前缀长度,[3.5](3.5-query-layer.md) §会话读;跳过 volatile 块)。**窗口只负责"在哪画",不自算断点**:位置来自 [3.3](3.3-cache-model.md) 的同一套结构定位,数值真相取真实 usage、非 byte-diff。**必拒**在本部件用纯 byte-diff 臆测断点(demo v11 已证会撒谎)。那个块在一张折着的提问卡里时,线也在那张卡里;打开一步时落在线上归 [1.4](1.4-central-board.md)(落点)。
- **写什么**:「从这里起和第 K 步不同 · <原因> · 结构估计」。K = 缓存对比步(§两个对比步),按 [1.2](1.2-shell-layout.md) §编号:步与调用 写成主对话的第 K 步。<原因> 用 [2.2](2.2-call-turn-card.md) §缓存判定那张原因词表(`labels/replay.mjs`,键是 `src/view/analyze.mjs : CAUSE_META` 的闭集),不显示服务端的英文 `causeLabel`。线的悬停与读屏文字再写「第一个不同的块:<行头>」。
- **压缩**(`cause:'compaction'`):「从这里起和第 K 步不同 · 对话被压缩:以下整段重写 · 结构估计」;压缩是推断出来的(骨架行的 `compactionInferred`)时加「推测」([1.5](1.5-states-aesthetics.md) K-13)。
- **「结构估计」(MUST)**:线上必带,悬停「按块的结构比对得出,不是服务商真实的缓存边界;权威值是 查询层的散度点」(承 [3.2](3.2-normalized-model.md):128「结构估计,非真实边界」)。自动缓存的服务商(这一步没有一块带 `def.cc`)时「结构估计」旁再写「结构参考,非真实边界」——这条规则与守卫归 [1.4](1.4-central-board.md)(验收 #12)。
- **不写**:首个不同字节的偏移(服务端 `byteOffset` 今天是 UTF-16 下标,不是字节,D17①);归属与修法(`attribution` / `fixHint`);任何缓存状态(读写多少、复用、过期重建、服务商一侧的矛盾)。这些在步头的「缓存」按钮里([2.2](2.2-call-turn-card.md))。
- **线下的移除列表**:内容对比步里有、这一步没有的块(`keyDiff().removedBlocks`,volatile 不算),有一块以上时在线下写「第 K' 步里有、这一步没有的块:N 个 ▸」(K' = 内容对比步),默认收起;展开后每块一行,行头与保真标同正常块,正文按它的 `def.ref` 回源(同一个格)。压缩时这就是被换掉的历史。
- **承 D17①「为什么 + 是不是你的锅」**:「为什么」(原因)留在线上;「是不是你的锅」(归属)进「缓存」按钮。原因 MUST 从 canonical 列读(看板上是 `cacheBreak.cause`,查询层里是散度点的原因,[3.2](3.2-normalized-model.md)),窗口 MUST NOT 自跑 byte-diff / provider 正则(承上「不自算断点」)。
- 守卫:`ctxwin.test.mjs`(验收 #7:线的位置等于服务端的 `cacheBreak.idx`);前端不跑 byte-diff 靠收尾审查。原因与写法的取舍见下。

## 两个对比步(本单元定义;词见 [1.5](1.5-states-aesthetics.md) §看板词表)

### 缓存对比步
- **是哪一步**:服务端比缓存用的那一步——同一 lane 里前一个没失败的调用,由归约定([3.5](3.5-query-layer.md) §会话读)。
- **确切指针** = 骨架行的 `cacheBreak.refRid`;第 K 步由这个 rid 推出([1.2](1.2-shell-layout.md) §编号:步与调用)。前端只读它(`replay/analysis.mjs : cacheRefOf()`),不自己往前找;骨架行在每一步上都有,所以车道未到手时 K 也写得出。
- **谁用它**:变化线的「第 K 步」;步头「缓存」按钮与 ≈ 多花(`breakCost`,[2.2](2.2-call-turn-card.md));问题道的旗([1.3](1.3-timeline-tracks.md))。
- lane 的第一次调用没有缓存对比步(`cacheBreak.firstCall`)。

### 内容对比步
- **是哪一步**:用户选来比内容的那一步;默认 = 缓存对比步;参考步可选任意步。
- **怎么选**:步头的「对比 ▾」菜单按钮(不是悬停):默认项 / 选一步…;不是默认时按钮写「对比第 K 步 ×」,「新」的图例写第 K 步。控件归 [2.2](2.2-call-turn-card.md),放在步头。选定的步按 `rid` 存在回放台状态里(`diffRef`),跨 scrub 保留,直到按 ×;playhead 走到第 K 步本身时,这一步按默认比。
- **它管什么**:块上的「新」;变化线下的移除列表;「组成」按钮里的增长 Δ([2.2](2.2-call-turn-card.md))。
- **它所在的车道未到手时**:取那条车道(§车道未到手);到手之前不标「新」、不画移除列表(不是"全都新",也不是"没有新")。

### 步间 diff
现状(承 demo,v2 已补齐):窗口对**内容对比步**做块级 `fh` 集差(`replay/analysis.mjs : keyDiff()`)——「新」标本步新增块(`fh` 不在对比步)+ 变化线下列出移除的块;对比步可选任意步。demo 时代的两个局限已补上:① 参考步**硬钉上一步**;② **只标加项、不标移除**——compaction/改写下被删/重写的 message 块**不在本步**故不可见,漏报真实变更。
**规则**:**移除感知 + 任意参考步**的步间 diff。数据 = **两步物化列表的 `fh` 集差**(added = 本步有而参考步无;**removed = 参考步有而本步无**;volatile 位置不计)。键是帧哈希 `fh` 不是 `bid`:`bid` 哈希的逐字节点带着 `cache_control`,而整份重发的线上缓存标记只挂在最后一条消息上(真实采集:83 条消息的调用只有第 82 条带标记),下一步那条旧消息失去标记、`bid` 就变了;`fh` 不含缓存标记,所以只挪了标记的块既不标「新」、也不进移除列表。`bid` 照旧管身份、按它取定义与正文([3.5](3.5-query-layer.md) §会话读 id)——**廉价**(hash 集合运算,**零字节读**,承 [4.2](4.2-storage-etl.md) 去重存储 + D24)。参考步默认缓存对比步、可选任意步。**MUST NOT** 前端跑 byte-diff 臆测(承本节「不自算断点」);removed 块的全文按需经 `def.ref` 回源。compaction 下 removed 集 = 被换血的历史,显式列出(在变化线下)。守卫:`test/web-v2/analysis.test.mjs`「keyDiff: added and removed key sets; volatile blocks never count; a compaction pair removes blocks」+ `ctxwin.test.mjs`(验收 #6);不跑 byte-diff 靠收尾审查。

## Edge cases
- **空 / 无请求步**(probe 或中断的 call):不崩;没有请求与请求解析不出两态及其措辞归 [1.4](1.4-central-board.md)(白名单 ⑥⑦)与 [1.5](1.5-states-aesthetics.md) K-05。
- **超长块**:切片显示 + 剪裁状态写全量字符数;「Copy bytes」复制全部;全文回源可得(§两种模式 切片与剪裁)。
- **compaction**:整窗自然换血(内容变即整列换)——是**同一 session 内换血、不是 fork**(承 [3.4](3.4-session-identity.md));变化线落在第一个变了的块前(tools+system 幸存,通常是首个 message 块;保留了第一条提问的压缩落得更后,`cacheBreak.idx`)。
- **首 call `cache_read>0`**:跨 session 暖前缀(tools+system 跨会话字节相同),如实显示、不当异常(承 [3.3](3.3-cache-model.md));`first-call` 是安静原因,不画变化线,说法在「缓存」按钮里([2.2](2.2-call-turn-card.md))。
- **`tool_result.is_error`**:行头带服务端 `head.tag` 里的 `· error`(承 demo `blockHead`,今天在 `src/view/blockmeta.mjs : blockHead()`)。
- **块头 tag 的词**:`head.tag` 里的 kind / role 是 harness 无关的闭集,`labels/replay.mjs` 给一张词表(英文,D58①;指令 / 对话 / 工具调用 / 工具结果 / 系统提醒 / 错误 这些语义各一个词);不认识的值进技术细节,外面写「原因未知」;这张表进 `labels-complete` 断言(2026-10-08 审查;原「映射留 Extensions」作废)。
- **巨量块(500+)**:收起的行没有正文 DOM,`.cblk` 与提问卡 `.cwturn` 带 `content-visibility: auto`;折着的提问卡不画行,打开的卡按组画、先画落点附近一屏,其余组在之后的任务里一组一组补上(§读与画「长对话的窗口」)。
- **失败步之后**:缓存对比步跳过失败的那一步,变化线写更早的第 K 步;失败的步本身内容变了也画线(缓存上它不算断开,[2.2](2.2-call-turn-card.md))。
- **只差 volatile 块**:`volatile-nonce-only`,不画变化线,volatile 块不标「新」。
- **跳到 `#cachebrk` 落空**:这一步没有变化线(过期重建、命中偏低这类缓存断开没有内容变化)→ 按 [1.4](1.4-central-board.md) 的落点走。
- **打开的块取正文失败**(网络、5xx):正文写原因、下次打开重取(不记住失败),该块补「◐ 取不到字节」,所在段撤回「以下逐字」。
- **窗口行的原因不止一种**:服务端的 `unaddressable` 原因去重后全部进技术细节;窗口行的句子不变。

## Risk / 回滚
本部件是**纯渲染函数**(归一化行 → DOM),用固化真实记录回归;失败回退上一绿点。**最大风险 = 徽章 / 保真回退到前端嗅 provider 特征**(违反不变式 3/4,必拒;守卫 `no-provider-branches.test.mjs` 与 `fidelity-marks.test.mjs`)——回滚策略:徽章降级为**只读 canonical 列**(`cache_control`/`volatile`/`faithfulness`),宁可少显不可前端瞎猜。
- **证明规则的撤回**:段头先写「以下逐字」、正文回来不是逐字再撤。按今天的 `classifyFidelity()`,带 `def.ref` 的块回来只会是 `verbatim` 或 `decoded`,所以撤回只在服务端定位与回源结果不一致时发生;它 MUST 当场发生,不等下一次重画(`fidelity-marks.test.mjs`)。回滚:证明规则只能收紧(更少地写「逐字」),不能放宽回旧的默认。
- **变化线说错第几步**:K 只来自 `cacheBreak.refRid`;回滚是只画线不写 K,不回到每步都写缓存状态。
- **Readable 画错**:渲染器只是读法,Raw 永远在、是默认;回滚是把出错的 `as` 退回 `text`,不加按工具名的分支。

## Extensions
- `faithfulness=summarized` 的展开:并排"客户端摘要 vs 若有原文"(DeepSeek compaction)。
- `resource_ref` 点击**浮现资源内容**(与 [2.4](2.4-resource-explorer.md) 联动,承 demo `viewResource`)。
- 服务端给出 UTF-8 字节偏移后,变化线的悬停里再写「第一个不同的字节在这一块的第 N 字节」(D17①)。
- 不是默认的内容对比步、这一步又没有变化线时,移除的块的落点(例如「对比」菜单里,[2.2](2.2-call-turn-card.md))。
