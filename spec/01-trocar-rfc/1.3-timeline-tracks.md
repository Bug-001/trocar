# trocar · RFC 1.3 — 排轴(时间轴 · 多轨)

> **服务意图(A2)**:主要意图 ②——把每步上下文的**体量 + 组成 + cache 命中**编码成可扫视的轨道(承 [3.3](3.3-cache-model.md));并承意图 ①——**按步轴本身就是 scrub 的对象**(时间轴 = 回放的骨,喂 [1.4](1.4-central-board.md))。这是"行为回放为骨 · cache 为叠加层"(D2)在轴上的兑现。
> **受众**:人(在轴上一眼定位"哪步爆上下文 / 哪步 cache 断了"再点进去)+ agent(据此把 [3.2](3.2-normalized-model.md) 的 `calls`/`usage`/`cache_events` 渲成轨)。
> **前置**:步序与 lane 来自 [3.2](3.2-normalized-model.md)(`calls.seq`/`calls.lane`/`calls.compaction`);cache 数值真相来自 [3.3](3.3-cache-model.md);subagent lane = 父血缘、compaction ≠ fork 见 [3.4](3.4-session-identity.md);轨道**部件实现**(柱/tick/缩放/hover/click→card)在 [2.1](2.1-track-widget.md)。「第 N 步」的编号规则在 [1.2](1.2-shell-layout.md) §编号;lane 的词、归哪一行、算进哪个花费桶,以 [2.1](2.1-track-widget.md) 的 lane 种类表为准;缓存判定、缓存断开判定、多花与每步估价的函数在 [2.2](2.2-call-turn-card.md)(`web/legacy/core/metrics.mjs`);缓存对比步在 [2.3](2.3-context-window.md)。

## Goal
用一条**按步 LLM 调用**的横轴,把一条 session 编码成:主轨上方 **问题道** = 哪几步缓存断开、哪几步调用失败 · **主轨** = 每步一柱(柱高 = 上下文体量,柱内多色段 = 类型组成;可切到「花费」视图,柱高 = 这一步的 ≈ 估价)· 主轨下 **缓存迹线** = 每步缓存状态 · 可折叠的**叠加轨**(子 agent · 后台调用 · token 计数)。各轨**共享同一 /N 步轴**、左对齐,让"问题、体量、组成、cache、叠加轨上的调用"在同一时刻纵向对齐、互为注解。

## 前置定义(Definitions)
- **步轴(step axis)**:横轴单位 = 主 lane 的第 N 次 call(`calls.seq`),**非墙钟等距**——scrub 的最小单位。N 柱等宽,每柱占 `1/N`。一步 = 主对话的一次模型调用,界面写「第 N 步」(编号见 [1.2](1.2-shell-layout.md) §编号);别的 lane 的调用不是步。
- **主轨 context 柱(context bar)**:主 lane 每步一柱;柱高 ∝ 该步 `usage.total_input`(真·上下文体量)。
- **段组成(composition)**:一柱内按类型(tools/system/user/assistant/thinking/tool_use/tool_result/image)堆叠的多色段——**比例是估算(保真边界,见下)**。
- **缓存迹线(cache trace)**:主轨正下方一行,与柱 1:1 同轴。每步在它那一列画一段水平线,高度按该步的缓存状态:有用量时按命中率分三档(高 / 中 / 低),相邻两步的线段竖着连起来;「没有用量」画虚线段;「含义不确定」用与三档都不同的线型;失败步那一列不画线,迹线在那里断开。状态判定见 [2.2](2.2-call-turn-card.md) §缓存判定。
- **叠加轨(overlay lane / rail)**:主 lane 之外的调用,按 [2.1](2.1-track-widget.md) 的 lane 种类表归成三行:「子 agent」「后台调用」「token 计数」,各占一行,可折叠展开。
- **共享网格(shared grid)**:每行 = 固定左 **gutter**(轨道标题)+ 右 **plotting lane**(柱/格/tick)。gutter 定宽,plotting lane 弹性;主轨、缓存迹线、每条叠加轨同宽 gutter → 列对齐。
- **问题道(problem lane)**:主轨正上方一行。每个缓存断开的步一面旗,每个失败的步一个 ×;压缩的步画一个小的中性记号(读屏文字「压缩」,不是旗)。行名本身是翻页导航「问题 k/n」。
- **视图切换**:主轨的两种画法——「上下文大小」(默认,柱高 = 真实输入总量)与「花费」(柱高 = 这一步的 ≈ 估价)。问题道、缓存迹线、叠加轨不随之变。
- **提问刻度**:主轨下方一行细刻度,每次提问开始的那一步一根。只在服务端给出提问事件时画。行名「第 K / P 次提问」(§提问刻度)。

## Plan(选定方案 + 取舍)
**选定:一条 /N 步轴 · 三类轨共享网格 · 主轨骨 + cache/叠加为层。**
- 横轴锚定**主 lane 的 call 序**(非墙钟),N 柱 flex 等宽各占 `1/N`;叠加轨上的旁路事件用 `xOf(ts)→(i+frac)/N` 绝对定位,落到对应主柱的**左沿**——柱(等距)与 tick(时间插值)**收敛到同一 /N 轴**。
- 布局用 CSS grid `grid-template-columns: <gut> 1fr`,`<gut>` 在 `#saw` 与 `#rails` 取同一值(demo:140px);轨道标题进 gutter(省水平宽度),每类 lane 的说明(取 [2.1](2.1-track-widget.md) lane 种类表的说明词)**放在标题的悬停里**。
- 主轨 = 回放的骨(点它 = scrub 到该步,承 [1.4](1.4-central-board.md));缓存迹线贴着主轨(每步随手可读命中);其余 lane 是**可勾选叠加层**,想看行为看骨、想看 cache/旁路才勾亮。

**备选(未选)**:① **墙钟等距轴**——旁路事件绝对准,但主柱会被密集调用挤成不可 scrub 的乱麻,且"按步"才是 agent 的决策单位;② **每类轨各一条独立时间轴**——各自缩放不再对齐,失去"同一时刻纵向对照"这一核心价值;③ **cache 作独立主视图(与行为并列可切换)**——违反 D2(一条主线承载两目的),回放台撕裂。
**取舍**:牺牲叠加轨的墙钟精度(tick 落到最近主步的左沿,是"对齐到步"不是"对齐到毫秒"),换来三轨恒定对齐 + 单一 scrub 对象。旁路事件的精确墙钟仍在 card/detail 里如实给。

## 轴与网格(对齐不变式)
- **列对齐(MUST)**:主轨、缓存迹线、坐标轴、每条叠加轨 MUST 是同一 grid 的行,共享**同一 gutter 宽**;plotting lane 起点因此逐行对齐。gutter 宽由 [1.2](1.2-shell-layout.md) 定义,1.3 MUST NOT 各行自算宽度。问题道与提问刻度同样是这个 grid 的行。守卫:`test/web-v2/trace.test.mjs`(验收 #1)+ Playwright 对应项。
- **/N 收敛(MUST)**:主柱按 flex 均分 `1/N`;叠加轨 tick 按 `xOf(ts)=(i+frac)/N` 定位。二者 MUST 引用**同一个 N = 主 lane call 数**与**同一 `xOf`**——换算不一致 = 轨间错位(视觉撒谎)。同 `ts` 的旁路事件落到主柱 i 的左沿(`frac=0`)。问题道的旗、×、「压缩」与提问刻度按步序号落在同一列。守卫:`test/web-v2/lanes.test.mjs` + `trace.test.mjs`(验收 #2)。
- **窗内步少时收窄(MUST)**:刷选窗里的步数 n 少到每柱会宽于柱宽上限(约 24 px + 1 px 间隙)时,所有细节行——主柱、缓存迹线、问题道、提问刻度、每条叠加轨、坐标轴——**一起**收窄到 n × 上限、靠左,/N 对齐因此不变;全程概览条不收窄,仍占满整行。实现只有一处:窗变时在 `#leftpage` 写一个 CSS 变量(窗内柱数),各细节行的图区按它取最大宽;刷选窗能放多少柱仍按未收窄的图区宽算。上限只限最大宽,不改每柱的最小像素预算。守卫:`test/web-v2/browser/replay-shots.test.mjs`「at 1280 × 800 the step bar is one row …」(Playwright:步最少的会话,每条细节行宽 ≤ 窗内柱数 × 上限,全程概览条不收窄;截图 `replay-fewsteps`)。
- 坐标轴行只标步号「第 1 步」…「第 N 步」(步标,非时刻);播放头的标签写「第 N 步」(主对话序号)。墙钟在柱/ tick 的 tooltip 与 card 里给。播放头是一根 `--cursor` 的竖线,穿过排轴与叠加轨的每一行;它的步号标签在坐标轴行上,底色 `--tag`、字色 `--tag-ink`(D77④)。

## 排布
- 迹线屏上自上而下:图例行(视图切换在最左,接着组成的说明、缓存迹线的图例、「显示第 a–b 步」与「采样显示」)· 章行 · 坐标轴(播放头的步号标签在这一行)· 问题道 · 主轨 · 缓存迹线 · 提问刻度 · 叠加轨 · 全程。图例行在最上面:先读懂颜色与线型再看数据(主 agent 定,依据 D77① 选定的原型)。
- 主轨尽量高,但默认状态下 1280 × 800 时 `#ctxwin` 仍要占可用高度的 50% 以上([1.2](1.2-shell-layout.md) §上下文窗的高度,那条 MUST 先于主轨的高度)。
- 上下文大小视图下,主轨的道名格自上而下列播放头那一步每种内容类型的占比,写「≈ 41%」:来源是那一步骨架行的 `comp`,次序与柱的堆叠同一个 `CT_ORDER`,色块同图例;是估算,带 ≈(§主轨 的保真边界 MUST 照旧);那一步没有 `comp` 时不列。花费视图下道名格不列数(§一件事只说一处)。依据:§主轨 段组成 = 估算;[2.2](2.2-call-turn-card.md)「组成」也按占比说(主 agent 定)。

## 问题道
- **位置**:主轨正上方一行,与柱同一 /N 轴、同一视窗 `[lo,hi)`。
- **旗(缓存断开)**:每个 `isBreak(step, ref)` 为真的主对话步一面旗。判定是 [2.2](2.2-call-turn-card.md) §缓存判定的那一个谓词(本单元不另写判据);`ref` 是 [2.3](2.3-context-window.md) 的缓存对比步。旗高 ∝ √(≈ 多花),≈ 多花取 [2.2](2.2-call-turn-card.md) 的 `breakCost()`;算不出(NULL)时固定高度,不是 0。悬停与读屏文字:「第 N 步缓存断开 · ≈ 多花 $x」,算不出时「第 N 步缓存断开 · 多花算不出」;按块结构比出的断开(缓存判定里的"内容变了"那一条)再加「结构估计」。
- **×(调用失败)**:每个失败的主对话步一个 ×。失败 = 缓存判定的第一条(`error` 有值)。读屏文字「第 N 步调用失败(<errMsg>)」,`errMsg` 照服务端原样。失败步不是缓存断开,不画旗。
- **「压缩」**:见下节「主轨」的 compaction 条。它是中性的说明,不是旗,不算进问题数。
- **翻页(行名即导航)**:行名写「问题 k/n」+ ‹ ›。n = 旗数 + × 数(两者不会落在同一步);k = 播放头所在那个问题的序号;播放头不在问题步上时行名写「N 个问题」(N = n),不写「问题 —/n」。‹ › 把播放头移到上一个 / 下一个问题步,打开那一步时落在哪里照 [1.4](1.4-central-board.md) 的规则(有变化线就落在变化线)。n = 0 时只写「问题」,不画 ‹ ›(做不了的控件不画)。
- **安全审查不进问题道**:安全审查调用的标记只画在后台调用行(见「叠加轨」),不算进 n。
- 旗、×、「压缩」都可聚焦,读屏文字如上。
- 守卫:`trace.test.mjs`(验收 #9、#10、#15)。

## 主轨 context 柱 + 段组成
- **柱高 = 真值**:`h ∝ step.total_input / peak`(peak = 本 session 各步 `total_input` 最大值)。`total_input` = canonical `usage`(`input_uncached + cache_read + cache_write`,见 [3.2](3.2-normalized-model.md))——**真·上下文体量,非估算**。
- **段组成 = 估算(保真边界 · 必拒隐瞒)**:柱内按 8 类(tools/system/user/assistant/thinking/tool_use/tool_result/image,映射 [3.2](3.2-normalized-model.md) 的 `block_contents.section/role/kind`)堆叠着色。demo 用**各类 char 数作 token 占比代理**(`callComp` 每 call 算一次、缓存在 step 上)——**段的相对比例是估算,不是逐字 token 计量**。承不变式 4([0.0](0.0-overview.md) §核心不变式):UI MUST 就地标注"组成为估算(按字符占比)";MUST NOT 让人误读段比例为精确 token 分布。provider 均不给 per-block token,故产品沿用估算,但**标注不可省**。v2 的就地标注 = 图例行的「颜色 = 内容类型(按内容大小估算)」,上下文大小视图下常驻。守卫:`trace.test.mjs`(验收 #4)。
- 色板固定复用(段颜色 = 图例 = [2.3](2.3-context-window.md) 回放里同类块的强调色),跨轨/跨视图同色同义。
- **错误步**:失败的步(判定同问题道的 ×)→ 柱降为固定矮柱,不画组成(体量无意义);同一列的问题道画 ×,读屏文字「第 N 步调用失败(<errMsg>)」。守卫:`trace.test.mjs`(验收 #10)。
- **compaction 标在该步**:`calls.compaction=true`(骨架行的 `compaction`)的步,在它这一列的问题道上画一个小的中性记号(无可见文字,ink-3),不是旗;「压缩」一词(`compactionInferred` 为真时加「推测」)由它的悬停与读屏文字承载:「第 N 步对话被压缩:历史被重写,整个上下文重新写入」(推测时加「(推测)」)。compaction 是**同一 session 内换血**(标在该步),MUST NOT 渲成 fork/新轴(承 [3.4](3.4-session-identity.md) 的 compaction ≠ fork)。守卫:`trace.test.mjs`(验收 #5)。
- **峰值**:主轨左上角写本会话主对话的峰值(上下文大小视图如「159k」,花费视图如「≈ $2.19」;数值为虚构示例)。

## 视图切换:上下文大小 / 花费
- 图例行左端一个两段的分段控件「上下文大小 | 花费」,默认「上下文大小」。
- **上下文大小**:上节的柱。
- **花费**:主轨改名「花费」,柱高 ∝ 这一步的 ≈ 估价 / 主对话各步估价的最大值,不分颜色。估价 = 用量 × 单价,与步头的 ≈ $ 是同一个函数([2.2](2.2-call-turn-card.md),`core/metrics.mjs`),单价按模型名里最长的家族键匹配(`/api/pricing`)。峰值与悬停都带「≈」;按家族键匹配时悬停加「按 <键> 的单价」。
- **算不出的步画斜纹,不画 0 高的柱**:没有这个模型的单价 → 悬停「没有这个模型的单价」;没有返回用量 → 悬停「没有返回用量,算不出」。失败步照上节画固定矮柱 + ×。图例行这时写「柱高 = 这一步的估价(用量 × 单价)· 斜纹 = 算不出」。
- 估价不是账单:「本地估价(用量 × 单价),不是账单」这一句的 MUST 归 [2.2](2.2-call-turn-card.md);本视图只引用它的数,并保证 MUST NOT 把未知画成 $0。守卫:`trace.test.mjs`(验收 #14)。

## 缓存迹线(承 3.3)
- 主轨正下方一行,与柱 **1:1 同轴**,每步一段。每一段的画法按 [2.2](2.2-call-turn-card.md) 的 `cacheState(step, ref)` 定,先命中的先算:
  - **失败**:那一列不画线(迹线断开),悬停「缓存 失败」。失败步 MUST NOT 画成"没命中"。
  - **没有用量**:那一列画中位的一段虚线,悬停「缓存 —」+「没有返回用量,算不出(不是 0%)」。
  - **含义不确定**(该步 `wire.cacheSemanticsKnown === false`):用与三档都不同的线型画,图例有「含义不确定」一项;悬停「缓存 N%?」+「这个服务商的缓存数字含义不确定」。
  - **其余**:按 `hit_ratio` 三档定这一段的高度:**高 = 命中复用 ≥0.7 · 中 = 部分 ≥0.3 · 低 = 冷/断 <0.3**;悬停「缓存 N%」。颜色与线型取 [1.5](1.5-states-aesthetics.md) 的 token,本单元不定色值。
  - 守卫:`trace.test.mjs`(验收 #3、#10、#11、#12)。
- **数值取真实 usage(必拒臆测)**:`hit_ratio = cache_read/total_input` 来自 canonical `usage`/`cache_events`(承 [3.3](3.3-cache-model.md) 真相规则),MUST NOT byte-diff 结构猜。守卫:`trace.test.mjs`(验收 #3、#7)。
- **保真边界(自动缓存 provider)**:迹线上的**数值**(命中率)三家都真;但 OpenAI/DeepSeek 无声明断点,"在哪断"仅 `structural_divergence`(结构参考,非权威)——若 UI 在迹线上暗示断点位置,MUST 标「结构参考,非真实边界」(与 [1.4](1.4-central-board.md) 同一句)。Anthropic 有 `declared_breakpoints` = 真实断点,可如实标。v2 的 缓存迹线与问题道都只标到"哪一步",不画一步之内的断点位置;按块结构比出的断开由问题道的悬停标「结构估计」。守卫:标「结构估计」由 `trace.test.mjs`(验收 #9)守;"不在步内画位置"暂无可红的断言,靠收尾审查。
- **保真边界(canonical,不漏适配缝 · 需 RFC 才破)**:1.3 MUST 读 canonical(`usage.cache_read`/`cache_events.hit_ratio`),MUST NOT 直读 provider 原生字段名(如 Anthropic `cache_read_input_tokens`)——那会把适配缝漏进前端(不变式 3)。demo 前端目前直读原生字段,是 v0 债,产品化必须收进 canonical。v2 只读服务端收敛后的 `steps[].usage {read, create, fresh, out}`。守卫:`test/web-v2/no-provider-branches.test.mjs`(扫描 `web/legacy` 里的原生用量字段名,如 `cache_read_input_tokens`、`prompt_tokens`)。

## 提问刻度
- **行名**:「第 K / P 次提问」。K = 播放头那一步的提问序号:主对话车道 `lane` 回答 `events` 里步序不晚于这一步的最后一个 `type:'user'` 项的 `k`,手里的页没有走到那一项时不知道 K。P = 主对话最后一个 `type:'user'` 事件的 `k`:head 的 `cols` 里最后一个带「提问」标志的格所盖的步都在手里时取它们 user 事件的最大 `k`,否则不知道 P。都知道 →「第 K / P 次提问」;只知道 P →「P 次提问」;只知道 K →「第 K 次提问」;都不知道 →「提问」。K 与 P 不随客户端手里有几页而变:都取服务端在 mark 处编的 `k`([3.5](3.5-query-layer.md) §会话读),不数手里有几个事件。依据:不变式 4(主 agent 定)。
- 只在主对话 lane 有提问事件(`session` 回答的 `events` 里 `lane` 是主对话车道、`type === 'user'` 的项)时画;没有时这一行不出现,也不写「第 K 次提问」。Anthropic 线格式之外的会话今天没有这些事件。
- 事件带记录 id `rid`([3.5](3.5-query-layer.md) §会话读),先经 `replay/lanes.mjs : stepRef()` 换成主对话的步序号再定位([1.2](1.2-shell-layout.md) §编号);刻度落在那一步的列上。
- 悬停「第 K 次提问」+ 提问开头:K 是主对话车道 `lane` 回答的 `events` 里同一 `rid` 那一项的 `k`,开头是它的 `preview`(照原样截短)。装着这一步的那一页不在手里时,悬停只写这一步的步号,不写 K、不写开头(依据:不变式 4;D69;[3.5](3.5-query-layer.md) §会话读:刻度从骨架画,K 与开头随车道的页来,不在手里时不猜)。

## 叠加轨(overlay lanes)
- **行与词**:主 lane 之外的 lane 按 [2.1](2.1-track-widget.md) 的 lane 种类表归行:`subagent` → 「子 agent」行;`monitor`(安全审查)、`notify`(通知摘要)、`titlegen`(生成标题)、`quota`(保活检查)、`aux`(其他后台调用)、`probe`(harness 自己标出的预热请求)以及任何别的 kind → 「后台调用」一行;`probes`(count_tokens 请求,不是 lane)→ 「token 计数」一行,用**迷你柱**按 token 高度画,而非圆点 tick。词全取自那张表(`labels/replay.mjs : LANE_KIND`),服务端的 `lanes[].icon` 不用。canonical lane 集 = `main|subagent|monitor|aux|probe`([3.2](3.2-normalized-model.md));notify/titlegen/quota 是 `aux` 子类。
- **勾选/折叠显示**:每条轨标题可折叠(gutter 内 ▸/▾);**subagent 扇出(>1 条)默认收进一条折叠组轨**(review/eval fan-out 会淹没主轨),展开才逐条列;只有一条子 agent 时它自己就是那一行,同样默认折起。后台调用行默认折起。产品的"勾选叠加轨"(见 [1.1](1.1-product-definition.md)/[00](0.0-overview.md) 模块图)与此同义 = 显隐叠加层。子 agent 调用再多,横轴仍是主对话的步,子 agent 仍只占折起的一行。
  - 子 agent 行名「子 agent N 个」(N = 子 agent lane 数)。展开后每个子 agent 一行:任务开头(车道头的 `task`;没有时照原样显示 `label`)· 「调用 N 次」(车道头的 `count`)· ≈ $(该 lane 各调用的估价之和,有调用没单价时加「起」)。行名放不下时省略,悬停给全名与 lane 种类说明。展开的组最多占视口高的约 40%,超出的在组内滚动,不把上下文窗挤出页面。折起时图区画什么见 [2.1](2.1-track-widget.md)。
  - 后台调用行名「后台调用 N 次」(N = 归入这一行的各车道头的 `count` 之和,全量)。折起时只画失败调用的 ×;安全审查的标记要等服务端把 `flagged` 解析对(见下)。展开后按 [2.1](2.1-track-widget.md) 逐种一行。
  - token 计数行名「token 计数 N 次」(N = `probes.count`,全量)。
- **行名悬停**:每行的用途说明取 [2.1](2.1-track-widget.md) 词表里的说明,挂在标题悬停里,不占水平宽度。
- **保真边界(probe)**:`probe` 是 `count_tokens` 量测调用,**非对话 payload**——它测的是"若此刻发出会多大",UI MUST 标「token 计数:不生成回复、不计费」,MUST NOT 混入对话步计数。token 计数行的标识 MUST NOT 与任何 `lanes[].kind` 相同(服务端的 `probe` lane 是预热请求,归后台调用行;二者撞名会让一行的 tick 打开另一行的调用)。守卫:`trace.test.mjs`(验收 #6、#16)。
- **安全审查的标记**:今天服务端的 `flagged` 把以标签开头的复审几乎都判成「标记」,是解析毛病。服务端改好之前([4.4](4.4-server.md) §看板 v2 需要的补充 `flagged`),排轴上任何地方都不画安全审查的标记,也不显示标记数;改好之后,`flagged === true` 的调用在折起的后台调用行上画一个标记,`null` 不画。复审结论的原文在调用抽屉里照原样给([2.6](2.6-detail-panel.md) §B)。守卫:`trace.test.mjs` + `board-real.test.mjs`(验收 #15)。
- **跨轨联动(承回放骨)**:hover 一个安全审查或 token 计数的 tick → 主轨点亮它"复审到第几步"的柱(reviewed)+ 一条括号;括号按时间推断,标「推测」(规则归 [2.1](2.1-track-widget.md))。点任一叠加轨的 tick → 播放头移到时间最近的主对话步,这一步标「约在第 N 步」,并在调用抽屉([2.6](2.6-detail-panel.md) §B)里打开该调用;抽屉里它叫「<lane 词> · 第 k 次调用」(k = 它在本 lane 里的序号,[1.2](1.2-shell-layout.md) §编号)。此联动让叠加轨解释主轨,是"层注解骨"的具体形态。

## overview+detail brush 导航(D13 · focus+context)
大 session 下"一屏 N 柱"不可读,但**撕裂 /N 对齐 = 视觉撒谎**(不变式贯穿本模块)。选定**经典 overview+detail(focus+context)**:排轴主体(`#saw`+`#rails`+缓存迹线+ticks)= **detail(focus)**,只渲当前视窗 `[lo,hi)` 内的 call;其正下方一条全-session **overview 概览条(context)**,上盖一个可拖拽/拉宽的**半透明 brush**,brush 覆盖的步区间 **就是** detail 的显示区间。这是 D13 定的导航式。
- **detail 重标定(MUST · 承 /N 收敛)**:视窗 `[lo,hi)`(`0≤lo<hi≤N`,整步边界)下,detail 的 `xOf_view(i)=(i-lo)/(hi-lo)`;主柱、缓存迹线那一列、叠加轨 tick、坐标轴刻度 MUST **全部**引用同一 `xOf_view` 与同一 `[lo,hi)`——**同轴锁步**(错位=撒谎)。柱轴的"等宽 1/(hi-lo)"与 tick 轴的时间插值仍收敛到同一 view 轴(/N 收敛不变式在视窗内继续成立)。
- **overview 概览条(context)**:横跨整条 session `[0,N)`;**step 少(≤阈,demo N≤~60)= 每 call 一柱**(高 ∝ `total_input`,承主轨语义,可读逐柱);**step 多 = 降采样 streamline**(桶聚合成折线/面积),MUST 就地标「**采样显示**」(承保真边界不变式 4——概览非逐柱真相,MUST NOT 让人误读为每步)。overview 高度小(缩略),不重复段组成/cache 细节,只给"哪里高、哪里断"的地形。
- **brush 视口(MUST)**:overview 上一个半透明矩形 = 当前 `[lo,hi)` 映射到 `[lo/N,hi/N]`。**拖 brush 体 = 平移**(`[lo,hi)` 整体滑,宽不变);**拖 brush 左/右沿 = 缩放**(改单边,`hi-lo` 变)。拖动 MUST 实时驱动 detail 重渲(或等价 transform),二者恒一致——**brush 位置 = detail 视窗**是本导航的核心不变式。视窗有下限(`hi-lo≥1`)与钳位(`[0,N]`)。
- **playhead 同步(MUST)**:playhead(承 [1.4](1.4-central-board.md))落在 overview 上按 `pos/N` 定位、恒可见(即使当前 detail 视窗未含它——让人知道"回放点在视窗外的哪边");detail 内若 playhead 在 `[lo,hi)` 则照常高亮,否则贴最近边并给"在窗外"提示。scrub 到窗外的步 SHOULD 自动把 brush 平移到含该步(follow 模式;承 1.4 状态机)。
- **取舍**:overview 牺牲逐柱精度(多 step 时降采样)换全局地形恒可见 + 单一拖拽同时给缩放(拖沿)与平移(拖体);detail 保住逐柱 + /N 锁步。不需水平滚动条,并且给"我在整条 session 的哪一段"的 context——这正是 focus+context 之名。demo 现"最多显示 200MB"是 [4.4](4.4-server.md) 的 v0 有界尾读(读取上限),与本导航(显示视窗)正交;**如何在不撑爆内存下显示更长 session** = 后续 RFC 的显示层优化(虚拟化 [D6]/分页 [(A)]/cache 表 [4.3]),本模块保证语义,不认领存储优化。

本节四条 MUST 的守卫:`lanes.test.mjs` 「narrowed window rescales and culls」、`saw-window.test.mjs`(整个文件)与 `trace.test.mjs`(验收 #8);拖拽手势在 Playwright 里验。v2 的概览条在 N ≤ 60 时逐步一柱,60 < N ≤ 240 时逐步一点的折线(不是采样,不标),N > 240 时按桶合并,这时才标「采样显示」。

## 章(D71④)

依据:D71④(不同压缩段分开放,柱状图两侧的箭头去上一个 / 下一个压缩);D13;[1.4](1.4-central-board.md) #5「压缩不建新轴」。

- **章** = 主对话轴上两次压缩之间的步:第 0 章从第一步起,第 k 章从第 k 次压缩那一步起,到下一次压缩之前止;推测的压缩(`compactionInferred`)同样分章。章的边界来自 head 的 `chapters`([3.5](3.5-query-layer.md) §会话读「`session --head`」),与骨架行的 `compaction` 一致。
- **细节视窗落在播放头的章里**:detail 的 `[lo, hi)` 取自播放头所在章的步区间;一章多于一屏画得下的步数(`barsThatFit()`)时,按上节的视窗策略围着播放头截。刷子的平移与缩放照旧,只是不跨章界;播放头走出本章(←/→、点概览、深链、跟随)时视窗换成新章。
- **‹ ›**:柱行两侧各一个箭头,键 `[` / `]`([1.2](1.2-shell-layout.md) §键盘):‹ 落在上一章的最后一步,› 落在下一章的第一步(也就是那次压缩);第一章的 ‹ 与最后一章的 › 禁用、不隐藏、不挪位。
- **标签**:柱行上写这是第 k 章、共 n 章,与它的步号区间 a–b;起点是推测的压缩时就地标推测;‹ › 的悬停说明点名上一次 / 下一次压缩(步号与时间)。词住 `labels/replay.mjs`。
- **概览条**照旧覆盖整条会话 `[0, N)`,在每章的起点画一道刻度;刷子仍 = detail 视窗。
- **手里还没有行的步**按 head 的 `cols` 画柱(高度、最大组成、标志位),行到手时换成真柱,柱数与位置不变;`bucket` > 1 时 `cols` 只用于概览,细节视窗总是逐步一柱、从行画。
- **不变的**:D13 的 focus+context、一个 N、一个 `xOf`、步号是全会话的、[1.4](1.4-central-board.md) #5——章只是视窗的取法加一组导航。守卫:验收 #18。

## Edge cases
- **N 巨大(长 session)**:柱宽 `1/N` 趋近 0 → **v1(D13):overview+detail brush 导航**(见上节)——detail 只渲视窗 `[lo,hi)` 内的柱(逐柱可读),overview 概览条给全局地形 + brush 缩放/平移;overview 多 step 时降采样 streamline 并标「采样显示」,token 计数行仍最多画 300 根并标全量计数。页面 body 不横滚(承下条),detail 也不靠横滚——靠 brush 收窄视窗。1.3 保证语义(视窗内等宽、全轨对齐)不因降采样/视窗切换破。
- **叠加轨事件早于/晚于主轴端点**:`xOf` 钳到 `[0,~1)`;越界事件贴端点,tooltip 给真实墙钟,不外溢柱区(承页面 body 不横滚)。
- **单步 session(N=1)**:一柱占满、缓存迹线一格;轴标「第 1 步」。
- **无叠加轨**:叠加轨区只写「这个会话只有主对话」,主轨 + 缓存迹线独立成立。
- **cache 字段缺失**(DeepSeek `cache_write=NULL`)→ `hit_ratio` 仍由 `cache_read/total_input` 得;带容 NULL,MUST NOT 拿 0 冒充(承 [3.2](3.2-normalized-model.md))。守卫:`trace.test.mjs`(悬停里写缓存的数为「—」)+ [2.2](2.2-call-turn-card.md) 的 `stepbar.test.mjs`(四个数)。
- **compaction 后柱高骤降**:合法(换血),照真显示,不当异常/不误建 fork。
- **没有主对话的会话**:轴锚在服务端排第一的那条 lane 上,图例行写「这个会话没有主对话,时间轴按<lane 词>的调用排」;轴与播放头写「第 k 次调用」(轴标,不带 lane 词;步头带,见 [1.2](1.2-shell-layout.md)),不写「第 N 步」([1.2](1.2-shell-layout.md) §编号);问题道照常画。
- **车道未到手的步**:骨架行覆盖整场会话,带 `ts`、`ctx`、`comp`、`usage`、`cacheBreak`、`error`、`status`、`compaction`、`rec.request.model`,所以柱、缓存迹线那一列、问题道、花费柱照常画;只有上下文窗等车道到手([2.3](2.3-context-window.md) §读与画)。
- **`usage` 可为 null 之前**:失败调用的 `usage` 是四个 0,没有用量按 `norm.usage` 为空认;服务端可能给失败调用 `gt:'provider-contradiction'`,按缓存判定的先后,失败先命中,不画旗。
- **子 agent 调用远多于主对话步**:轴仍是主对话;子 agent 行折起时不展开几百根 tick,展开后按 [2.1](2.1-track-widget.md) 的抽样规则画。

## Risk / 回滚
排轴是**纯投影**(归一化表 → SVG/DOM),无副作用:换编码方案回退渲染层即可,源真相(NDJSON)与派生表不受影响。cache 三档阈值(0.7/0.3)是显示参数,可独立调而不动数据层。段组成估算若日后有 per-block token 真值,替换 `callComp` 的 char 代理即可、标注同步收紧;在此之前**估算标注 MUST 常驻**(守卫:验收 #4)。问题道只调用 [2.2](2.2-call-turn-card.md) 的谓词,谓词改错时旗会和步头、会话信息弹层一起错,`metrics.test.mjs` 先红;要回退问题道,删这一行即可,主轨与 缓存迹线不受影响。
