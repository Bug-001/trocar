> **服务意图(A2)**:意图 ①(多条并行 lane 在同一时间基上定位每一次调用、click 跳回放台同刻 → 看懂 agent 行为)为主;意图 ②(cache 叠加轨 / 资源轨都是本部件的实例 → 看懂上下文/缓存工程)为其复用底座。这是 2.x 里最底层的**通用轨道原语**,上面所有 track 皆其实例。**lane 种类表**(每种 lane 的词、归哪一行、算进哪个花费桶)也归本单元,[1.2](1.2-shell-layout.md)、[1.3](1.3-timeline-tracks.md)、[2.6](2.6-detail-panel.md) 引用它。

## Goal

一套**与 provider/harness 无关**的轨道部件:一条 lane 内按 `xOf(ts)` 把每次调用定位成一个 **tick**(点事件)或一根**迷你柱**(token 计数行的单值柱,高度=量级);整条轨可 hover/click 取**最近的调用**(不止渲染出的点);click→选中,把回放台的播放头跳到同刻,并在调用抽屉里打开这次调用;安全审查 / token 计数行 hover→高亮"大约审到会话第几步"的复审括号(按时间推断,标「推测」)。**为何独立成件**:cache 叠加轨、资源轨、安全审查、子 agent 轨、token 计数行——形态各异但交互同构;抽出一个 kind 驱动皮肤的原语,加一种轨只加 lane 种类表一行,不碰前端主干(承不变式 3)。v0 原型(`renderRails` / `renderTicks` / `railbody` / `xOf` / `highlightRange`)最先实现该设计;产品实现在 `web/legacy/replay/{lanes,rails,timeline}.mjs`。

## 前置定义(Definitions)

- **lane(车道)**:一条时间平行轨,承一路同类调用。归一化 `calls.lane`(见 [3.2](3.2-normalized-model.md)):`main`(会话骨,即 anchor)/ `subagent` / `monitor` / `aux` / `probe`。看板载荷 `lanes[].kind` 另把 `aux` 细分成 `notify` / `suggest` / `titlegen` / `quota` / `websearch` / `webfetch`(渲染期投影,D8)。`probe` lane 是 harness 自己标出的**预热请求**,不是 count_tokens。
- **lane 种类表**:`web/legacy/labels/replay.mjs : LANE_KIND`,按 `lanes[].kind` 给出词、归哪一行、算进哪个花费桶、行名悬停的说明。见下文「lane 种类表」。
- **anchor(锚轨)**:`main` 车道;它的调用时间戳序列 `anchorTs` 定义**整块时间基**——其余所有轨都投影到这条轴上。没有 `main` 时锚在服务端排第一的 lane 上([1.3](1.3-timeline-tracks.md) Edge cases)。
- **tick**:一次调用在轨内的点标记(`.tick`),`left = xOf(ts)`。失败的调用画 ×(`.errtick`)。
- **token 计数行**:由 `probes`(count_tokens 请求,**不是 lane**;载荷 `{count, series:[{ts, tokens, retention}]}`)建的一行。它的标识不是任何 `lanes[].kind`。
- **迷你柱**(DOM 里仍是 `.pbar`):token 计数行里的单值竖柱,`left = xOf(ts)`、`height ∝ tokens`(这次 count_tokens 量到的完整上下文大小)。
- **组行**:[1.3](1.3-timeline-tracks.md) 定的「子 agent」「后台调用」两行,各收进若干 lane;本部件提供它们折起与展开的画法和命中。
- **复审括号**:安全审查或 token 计数 hover / 选中时,在主轨上刷出的"这次调用大约看到第几步"的括号(`turnsReviewed(ts)` = `anchorTs` 中 ts ≤ 该调用 ts 的步数)。按时间推断,不是解析出来的。

## Plan(选定方案 + 取舍)

**选定**:**一个通用 lane-track 原语 · kind 驱动皮肤 · 抽样渲染 + 全量命中**。
- 形态由 `lane.kind` 决定,不由 provider/harness 决定:词、归哪一行、皮肤(样式类 `k-<kind>`,颜色取 [1.5](1.5-states-aesthetics.md) 的 token)都查 lane 种类表;服务端的 `lanes[].icon`(emoji)不用。失败的调用画 ×;安全审查的标记(`.tick.flag`)要等服务端把 `flagged` 解析对([4.4](4.4-server.md) §看板 v2 需要的补充 `flagged`)才画。token 计数行独用迷你柱,高 = tokens。
- 定位统一走 `xOf(ts)`(见「时间基」),一条轨 = 一个 `.railbody`。
- **token 计数行最多画 300 根迷你柱**(`MAX=300, step=ceil(n/MAX)`,每 `step` 取一),但**整行的 hover/click 命中全部 `probes.series`(取 x 最近)**,行名的数取 `probes.count`——于是 691 次只画 ~300 根、却每次都可达(见「保真边界」)。

**备选(未选)**:① **每次调用一个 DOM 节点全量渲染**——691+ token 计数(或上万 tick)直接灌进 DOM,滚动/hover 卡死(D6 已选虚拟化,正为治此);② **每种 lane 各写一套专用轨部件**——harness/provider 专属渲染分支漏进前端主干(**违反不变式 3 · 需 RFC 才放行**)。

**取舍**:通用部件 + kind→皮肤 → 加 harness / 加 lane 种类只加 lane 种类表一行,**前端主干 git diff = 0**(直服 AC-3);抽样渲染 + 全量命中 → 高吞吐下每次调用仍可选中,代价是**视觉非 1:1**——就地标「采样显示」,行名写全量计数(保真边界)。

## 部件构成(落地细节 · 承 demo)

**① 时间基 `xOf(ts) → [0,1)`**。以 anchor(`main`)的调用时间戳 `anchorTs` 为节点做**分段线性**插值:落在第 `i`、`i+1` 步之间 → `(i+frac)/n`;早于第一步 → `0`,晚于最后一步 → 钳到 `(n-1)/n + 0.999/n`。**关键**:轴不是线性墙钟,而是**会话自身的事件时间**——于是任一轨的 tick 恰好落在它"发生在哪一步前后"的位置下方,多轨天然对齐。`left`/`height` 以 `%`/`px` 定位,不动 DOM 数量。v2 的 `xOf(anchorTs, view, ts)` 是纯函数,`anchorTs` 与视窗都是参数。

**② 轨渲染 `renderTicks(lane)`**。非 token 计数的轨:`lane.calls` 中落在视窗内的逐个出 `.tick`,`left:(xOf*100)%`;悬停「<lane 词> · 第 k 次调用 · <时间>」+ 上下文大小,失败的写「调用失败」并画 ×(失败的判定同 [2.2](2.2-call-turn-card.md) 缓存判定的第一条)。token 计数行:抽样后出 `.pbar`,`height=max(1, round(tokens/peak*24))`px——**柱高即上下文规模**,一眼看出上下文随会话涨缩;悬停「token 计数 · <tokens> token · <时间>」。

**③ 整条命中 `nearestByX(lane, anchorTs, view, f)`**(取代 demo 的局部闭包 `nearestX`,v2 已导出)。`railbody` 上 mousemove/click 把光标 x 归一到 `[0,1]`,遍历**当前视窗内**(`pos(ts)∈[lo,hi)`,D13 裁窗)的 `lane.calls` 取 `|xOf(c.ts) − f|` 最小者;窗内一个候选也没有时才退回全量。即使该调用是被抽样跳过、未画出的迷你柱,只要在窗内也能命中并打开。**全窗时候选=全量 → "抽样显示但全量可达"不破**;收窄视窗时可达性随之收窄(窗外靠平移 brush 够到),但**计数真值恒全量**(见保真边界)。

**④ 选中 + 跳回放台 `selectTick(s, lane, i)`**。pin `selTick={laneId,i}`、加 `.sel`;若是安全审查或 token 计数 → 画复审括号,否则清;`follow=false`,播放头 = `nearestByTs(anchor, c.ts)`,重渲会话骨 + 逐字上下文窗 + outline。**→ 轨 tick 是通往回放台中栏的导航控件**(下游 [1.4](1.4-central-board.md) / [2.2](2.2-call-turn-card.md) / [2.3](2.3-context-window.md));这一步在轴上写「约在第 N 步」([1.2](1.2-shell-layout.md) §编号)。并 `openDetail` 在调用抽屉([2.6](2.6-detail-panel.md) §B)里打开这次调用;这次调用的车道未到手时,抽屉先画骨架行里的元数据,车道一到就填进去([2.3](2.3-context-window.md) §读与画)。

**⑤ 复审括号 `highlightRange(s, lane, i)`**(只对安全审查与 token 计数行;预热请求、子 agent、别的后台调用不画)。`k=turnsReviewed(ts)`,把会话骨(**按全局 `data-i` < k**)标 `.reviewed`、`#reviewbracket` 宽设 **`(k−view.lo)/(view.hi−view.lo)` 钳 [0,1]**(承 D13 `xOfView` 视窗锁步;全窗 `{0,N}` 退化为 `k/n`)。括号末端写「推测」,悬停与读屏文字「按时间推断:这次调用发出时,主对话已到第 k 步」。回答"这次安全审查 / token 计数这一刻大约覆盖到会话的第几步"。

**⑥ 折叠 / 分组**(与 [1.3](1.3-timeline-tracks.md) 协作)。
- **子 agent**:子 agent lane 默认都折起;多于一条时收进一个组行,展开才逐条列,每条也可单独折起。折起时图区只画这些 lane 里失败调用的 ×。
- **后台调用**:lane 种类表归到后台调用组行的各 lane 收进一个组行,默认折起;行名的数 = 这些 lane 的 `calls.length` 之和(全量,不随视窗与折叠变)。折起时图区只画失败调用的 ×,`flagged` 之后再加 `flagged === true` 的安全审查标记。展开后每条 lane 一行(行名 = lane 词 + 「N 次」),画法同 ②–⑤。
- **token 计数行**单独一行,默认展开(画迷你柱),可折起。
- **折起的行**:画出来的 × 与标记点得到(打开那次调用);整行命中只在展开时有——任何调用展开一次即可达,计数始终全量。
- 分组**布局策略**(有哪几行、行序、窄屏怎么收)属 [1.3](1.3-timeline-tracks.md) 与 [1.2](1.2-shell-layout.md) §窄屏,本部件只提供单行与组行的收合渲染与命中。

**⑦ overview+detail brush 部件**(承 [1.3](1.3-timeline-tracks.md) 的 D13 导航,DOM/手势落在本件)。两部分:
- **overview 概览条渲染**:横跨全 `[0,N)`,**恒为整个会话**;`N≤OVW_BARCAP`(=60)逐步出缩略柱(高 ∝ `total_input`);`60<N≤240` 逐步一点的折线(不是采样,不标);`N>240` 才按桶合并、挂「采样显示」(承保真边界)。overview 自有一套 `xOfOv(i)=i/N` 定位,与 detail 的 view 轴解耦。
- **brush + view 窗**:模块态 `view={lo,hi}`(整步,`0≤lo<hi≤N`)。**初始视窗**:整个会话放得下时 `{0,N}`;放不下(一屏只画得下 K 步,`K = barsThatFit(宽)`)时取以最新一步结尾的最后 K 步;URL 的 `?step=` 指向更早的步时取围着它的 K 步。拖宽 brush 超过 K 时,正被拖的那条边停住,另一条不动;「全部」(双击)在放不下时取围着播放头、放得下的那一段。detail 的 `xOf` **读 view**:`xOfView(ts)=(pos(ts)-lo)/(hi-lo)`(`pos(ts)`=原分段线性步位),越界钳 `[0,1)`;柱/tick/迷你柱/缓存迹线/坐标轴 MUST **全部**经此同一 `xOfView`(锁步,承 1.3 /N 收敛)。守卫:`lanes.test.mjs` 「narrowed window rescales and culls」+ [1.3](1.3-timeline-tracks.md) `trace.test.mjs`(其验收 #2、#8)。brush DOM 盖在 overview 上,`left=lo/N`、`width=(hi-lo)/N`;Pointer Events:**拖体 = 平移**(`lo,hi` 同增减、宽守恒)、**拖左/右 handle = 缩放**(改单边,`hi-lo≥1`),`setPointerCapture`,钳 `[0,N]`,拖动即 `setView` → 重渲 detail(承 divider 同款防御:没有 `setPointerCapture` 时 try/catch 静默)。`setView` 单一入口改 `view` 并触发 detail 重渲 + brush 位置回写(**brush 位置 = detail 视窗**恒一致)。
- **窗外 tick 必须剔除,不得钳堆(必拒违反 · 承 1.3 锁步)**:排轴既已裁到 `[lo,hi)`,叠加轨的 tick/迷你柱 **MUST 同样只渲 `pos(ts)∈[lo,hi)` 的调用**——窗外事件 MUST 被剔除,**MUST NOT** 靠 `xOfView` 钳到端点而堆在窗沿(那会让"窗外某处"伪装成"窗沿这一步",轨与柱撕裂 = 视觉撒谎)。`nearestByX` 命中同样只在窗内候选中取近(全窗时=全量 → 全量可达不破);**计数真值(行名的「N 次」等)仍取全量,不随视窗变**——**可达性按视窗收窄(平移即可够到窗外),但计数与源真相恒全量**(承 [3.2](3.2-normalized-model.md) 与本件保真边界)。守卫:`trace.test.mjs`(窗外剔除)+ `lanes.test.mjs` 「narrowed window rescales and culls」+ 验收 #7。
- **拖拽期不得毁 brush(SHOULD)**:brush 元素承载 pointer capture 与拖拽闭包;live 轮询触发的 overview 重建 SHOULD 在拖拽进行中**只回写 brush 位置、不重建 overview 背景**(`brushDragging` 门控),拖拽结束再重建——否则一次轮询会把正在拖的 brush 换掉、静默中断拖拽。
- **playhead 在 overview 恒可见**:overview 上在 `(playhead+0.5)/N` 画标;`selectTick`/scrub 到 `view` 外的步时 SHOULD `setView` 平移含之(follow;承 [1.4](1.4-central-board.md))。

## 保真边界(承不变式 4,[0.0](0.0-overview.md) §核心不变式 · 必拒隐瞒)

- **token 计数抽样显示**:渲染的迷你柱数 ≤ 300 ≠ token 计数真数。**MUST** 用全量 `probes.count` 标计数(行名「token 计数 N 次」;会话信息弹层与别处用到这个数时同样取全量),UI **MUST NOT** 让人以为只有画出来的那些;hover/click **MUST** 命中全部 `probes.series`;抽样时就地标「采样显示」;`probes.series` 比 `probes.count` 少(有的 count_tokens 没有返回大小)时,行名悬停说出差多少、它们没有画。规则:**抽样只降视觉密度,绝不降计数真值与可达性**。守卫:`trace.test.mjs`(≤ 300 与全量计数)+ `lanes.test.mjs`(验收 #2、#3)。
- **组行的计数**:后台调用组行与子 agent 组行的数取全量(各 lane `calls.length` 之和 / lane 数),不随折叠、视窗变。守卫:`lanes.test.mjs`(验收 #12)。
- **tick/迷你柱是派生投影**:位置/柱高是 `ts`/`tokens` 的可视化投影,**非逐字 bytes**。本部件是**导航索引**,不承 AC-1 逐字回放——逐字上下文在 [2.3](2.3-context-window.md)、逐字用量在 [2.2](2.2-call-turn-card.md) 的步头缓存弹出层、原文在调用抽屉([2.6](2.6-detail-panel.md) §B)。
- **复审括号是推测**:`turnsReviewed` 按**墙钟 ts** 数步(ts ≤ 该调用的主对话步数),是"覆盖范围"的**按时间的近似**,**非解析自安全审查载荷里的对话**;真·逐字审查内容在调用抽屉逐字展开。UI **MUST** 在括号上就地标「推测」,**MUST NOT** 写成精确的「审了第 1–k 步」。守卫:`lanes.test.mjs`(验收 #5)。

## Edge cases

- **空轨**:`lane.calls.length===0` → `railbody` 命中 guard 直接 return,不挂事件、不出 tick;`nearestByX` 返回 −1,`selectTick` 对 −1 什么都不做(不开抽屉)。
- **ts 越界**:早于/晚于会话窗 → `xOf` 钳到 `[0, 0.999]`,不溢出轨。
- **单/极短会话**:`n` 小 → `xOf` 仍除 `n`,tick 挤在轨左侧但可命中(nearest 仍解析)。
- **同刻突发**:多 tick 撞同一 x → 视觉重叠;`nearestByX` 仍解析出单一最近的调用(交互不歧义),视觉重叠可接受。
- **失败的调用**:没有用量 → 画 ×,照样可点;迷你柱高走 `max(1,…)` 兜底,不塌成 0 高不可点。
- **token 计数恰 ≤ 300**:`step=1`,不抽样,渲染 = 全量,不标「采样显示」。
- **count_tokens 没有返回大小**:不进 `probes.series`,不画、点不到;行名的数照算(`probes.count`),行名悬停说出差数。
- **不认识的 kind**:词「Unnamed background call」,归后台调用组行、算后台调用桶,kind 原样进技术细节;前端不用改就能显示,但要给它一个正式的词,先走影响面的 grep-spec 闸。
- **没有主对话的会话**:锚在服务端排第一的 lane;轴写「第 k 次调用」(轴标,不带 lane 词;步头带),不写「第 N 步」([1.2](1.2-shell-layout.md) §编号、[1.3](1.3-timeline-tracks.md) Edge cases);复审括号照 `anchorTs` 数。
- **车道未到手的调用**:轨上照画(骨架行覆盖整场会话,`ts` 都在);选中时抽屉先画骨架行里的元数据,车道到手后填进块([2.3](2.3-context-window.md) §读与画),没有加载控件(D69)。
- **子 agent 调用远多于主对话步**:轴仍是主对话;子 agent 组行折起时只画 ×,展开后每条 lane 一行。
- **Codex/DeepSeek lane**:同一部件、kind 驱动,**无 provider 分支**(适配缝守在 3.1/3.2,不漏进本件)。

## Risk / 回滚

纯渲染 + 交互部件,**不采集、不发请求、不写源**——不变式 1 平凡成立。`MAX=300` 是密度调参:改它只变渲染密度,**不动计数真值与可达性**(二者恒全量),故非保真风险。回滚 = rev 本部件渲染函数;上游 `calls.lane`/`ts` 数据与其余面板不受影响。加 kind→皮肤 = 加 lane 种类表一行,可回退;加 lane 枚举须先过 spec 闸(见影响面)。第一期 `src/web/index.html` 仍是旧看板,撤掉 `/` → `/v2/` 的跳转([4.4](4.4-server.md) `/` 的静态托管)即回到旧的轨道实现。

## 砍掉的

| 元素 | 为什么 |
|---|---|
| 头部统计里的 token 计数数(眼睛符号 + 数) | 统计性的话和数不进标题与小标题;全量计数改由 token 计数行的行名与会话信息弹层([1.2](1.2-shell-layout.md))给 |

| 「计数探针」这个名字 | 统一叫「token 计数」,与 D40 类别同词 |
| 服务端英文 `note` / `label` 当行名悬停 | 行名悬停用 lane 种类表的说明;`note` 照原样留在调用抽屉([2.6](2.6-detail-panel.md) §B) |
| 安全审查的标记与行名上的标记数(服务端重新解析之前) | 今天的 `flagged` 把以标签开头的结论几乎都判成「标记」,画出来就是误报 |
| 行名上的失败数(警告符号 + 数) | 失败在图区画 ×;次数在会话信息弹层 |
| 子 agent 组行的「N 条 lane · N 次调用」与行内说明句 | 行名用「子 agent N 个」([1.3](1.3-timeline-tracks.md));说明进行名悬停 |
| 精确的复审范围(「审了第 1–275 步」这类) | 服务端不算;按时间推断的括号保留,标「推测」 |
| 「这个会话里没有别的 lane」 | 由 [1.3](1.3-timeline-tracks.md) 的「这个会话只有主对话」取代 |
| 「采样显示」后面的英文尾巴 | 只写「采样显示」 |
