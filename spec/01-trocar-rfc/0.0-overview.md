## 顶部意图(A1)

给「造 agent 基建的人」一台**透明示波器**:把任意 agent 应用真正发给大模型的**每一比特**(完整上下文 + 流式回复 + usage)按步回放、逐层拆解,让你——

- **意图① 看懂 agent 的行为**:这一步到底往上下文加了什么、为什么这么决策。
- **意图② 看懂它的上下文与缓存工程**:上下文怎么拼、缓存命中在哪断、什么随每步变化。

个人研究仪器优先深度洞察;架构按「采集 / 存储 / 分析 / 前端 / harness 适配」解耦,为日后产品化留缝。全套产品叙事见 [1.1](1.1-product-definition.md)。

## 核心不变式(违反 = 一票否决)

后果分级词:**必拒** > **需 RFC 才放行** > **SHOULD**。每条「必拒」就近写明靠什么兜底(哪条测试会红);没有守卫的规则不许贴「必拒」。

1. **改包只出于操作者意图(D30)**:拦截 / 修改 / 重发每一次都 MUST 来自本机操作者的显式操作或其显式配置的规则;无操作者意图时原样转发。原始与改后各存一份逐字 + 一条 intervention 事件。
2. **逐字源真相**:采集到的原始 bytes(NDJSON)是唯一源真相;段索引(`~/.trocar/index/`)是可删、可重建的投影(D59)。派生层不得覆盖 / 丢失 / 有损改写原始。源文件上只许追加、同设备 rename(D27③)、封存(D35 · D60:逐条核对通过之后才删明文)。
3. **适配缝不漏进前端(需 RFC)**:加线格式 = 一个 dissector;加 harness = 描述符数据(从 [4.11](4.11-collector-model.md) 的原语里选,D57⑥)+ 读取侧一行 + 一行 chip;不改前端主干、不塞 provider 专属分支。
4. **保真边界写明**:凡未逐字保真的(元数据、截断、只记日志级)数据层与 UI 就地标注;采集失败不得静默(D38:每次留带原因的持久记录并上看板);trocar 改过或发起的请求 MUST 标明。
5. **开关必须干净(用户验收线)**:`on` = 之后新建的 agent 连接逐字被采;`off` = agent 路径上没有 trocar 的任何东西、看到真实上游证书、零新记录;在途流收尾完整;快切 / 崩溃 / 重启 / 卸载不留残、不断 agent。由专门套件验证,不靠目测(D48)。`on` / `off` 只碰第 1 类代理条目、开关文件和 trocar 自己的东西(证书归 `install` / `uninstall`,D55①);`off` 撤销 `on` 在这些上的一切改动;用户在 `on` 期间对无关字段的改动原样保留;用户改了代理或证书键本身,以新值为准。
6. **只读感知系统代理(D43 · D49)**:读 agent 自己的代理和系统代理,接续用户原有代理链;不识别、不显示 VPN 产品;不往任何 VPN / 代理软件里写东西。

## Non-Goals(全局 · 越界即自我否决)

- 没有本机操作者的显式操作时改包,或用被测程序的凭据发请求(D30)。
- 多用户 / 账号 / 云端分享(指一套实例服务多个用户;同一台机器上几个系统用户各装一套、各用各的不在此列,见 D36)。
- 面板自演化工作流(D7,单独立项)。
- 动系统代理,或接管整机流量(D31)。
- 实时告警 / 生产监控(这是研究仪器,非运维监控)。

## 术语速查

- **harness**:一个 agent 应用;v1 七个(D37):Claude Code · Codex · OpenCode · Kimi Code · DeepSeek `dsh` · Hermes · Z-Code。按进程身份认(`proc.agent`,D31),不按 UA。
- **provider**:旧称,D37 起拆成两条轴——**线格式**(按端点与 body 认:Anthropic Messages / OpenAI Responses(HTTP 或 WebSocket)/ OpenAI Chat Completions;归一化列 `provider` 存的是它)与**厂商**(按上游 host 认:Anthropic / OpenAI / DeepSeek / Moonshot / Z.ai …;cache 语义与价格随厂商)。
- **session**:某 harness 一次任务的全部上下文流——trocar 的**核心对象**。
- **归一化模型**:四种线格式忠实落进的统一表(见 3.2)。
- **采集源**:拿到字节的机制——[4.6](4.6-process-collector.md) 的按进程采集器(Linux 驱动模式,macOS / Windows 代理模式,D43)。
- **门**:trocar 在本机开的代理端口,一组 agent 共用一个(D47,[4.11](4.11-collector-model.md))。
- **开关文件**:trocar 自己目录里的文件,每个 harness 一个,写着门的地址;这个 harness on 时建,off 时删。
- **第 1 类 / 第 2 类入口**:第 1 类是 trocar 写进 agent 自己配置里的代理;第 2 类是开关文件,由 `install` 放的钩子读。都由 `on` 写、`off` 撤(D57③)。
- **证书载体**:根够不到的形态,证书交给它自己读的东西:配置键、安装目录包装、插件;由 `install` 放、`uninstall` 撤(D57①)。
- **安装目录包装**:`install` 把 agent 的真程序挪进同目录的 `.trocar-real`(文件名不变),原位放的包装;没有开关文件时只加证书变量,其余原样执行真程序。

- **根 / 中间证书**:根每台机器自己生成,`install` 装成用户级根,到 `uninstall` 都不换;macOS / Windows 上守护进程每次启动用根签一张 7 天的中间证书,叶证书由它签(D57②)。
- **持有者**:on 期间启动、还活着、可能读过入口的进程(闲着的也算);`off` 之后它们仍经门,门只转发([4.11](4.11-collector-model.md) §3 ②)。
- **代理链**:agent → 门 → 上游;上游是这个 agent 没有 trocar 时本来会用的代理,按 [4.11](4.11-collector-model.md) §1 的五步取(D57④)。
- **逐字忠实 vs 元数据**:原始 bytes 逐字存 = 忠实;只存名字/大小/计数 = 元数据。保真边界 UI 必标(见上「核心不变式」第 4 条)。
