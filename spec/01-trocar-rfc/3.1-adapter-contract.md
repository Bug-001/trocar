# trocar · RFC 3.1 — 适配层契约(★★ 产品的心脏)

> **服务意图(A2)**:跨切意图「适配层通用」(AC-3)——它是让整套产品 harness-无关的**接缝**;同时喂 ①(产出 blocks 供回放)与 ②(产出 canonical usage 供 cache 叠加)。
> **受众**:人(核对这道缝是否真解耦)+ agent(据此实现每个 dissector)。
> **前置**:输出目标 = [3.2](3.2-normalized-model.md) 的表;采集源(怎么拿到 bytes)见 [4.1](4.1-capture-sources.md),与本层**正交**。

## Goal
定义每个 `(provider × harness)`(D37 读作「线格式 × harness 约定」)都走的**统一 dissector 面**:吃一条原始捕获记录,吐跨 provider 的 canonical 块与 usage([3.2](3.2-normalized-model.md))。一个线格式一个 dissector;`src/dissect/registry.mjs : wireFormatOf()` 认出记录的线格式,`boardDissectorFor()` 取它的 dissector。加线格式 = 加一个 dissector + registry 一行;加 harness = 加约定数据(D37,见下文 §深度优先拆积木);都**不碰前端主干、不碰其它 dissector**。

## Definitions
- **dissector**(本单元标题里的 adapter):把某种线格式(D37)的原始流量拆成 canonical 块与 usage 的模块。与**采集源**正交——源管"怎么拿到 bytes"(采集器,见 4.1 / 4.6),dissector 管"bytes 什么意思"。
- **原始记录**:采集源写出的**统一信封**——**canonical 定义单一权威在 [4.1](4.1-capture-sources.md) §统一原始信封**(承本文件命名):核心 `{ts, endpoint, method, req_headers(逐字), req_body(逐字), resp(SSE 重建或 JSON body)}` + 观测元数据 `{id, ts_request/ts_response_start/ts_response_end, duration_ms, is_llm_call, capture, auth_mode}`(见 D10)。字段名以本文件(`req_headers/req_body/resp`)为准,4.1 定义完整形状、dissector 据此单一消费——**MUST NOT 两处各定义一套**。

## Plan(选定方案 + 取舍)
**选定**:每个线格式一个 dissector + 一张 registry;`wireFormatOf(record)` 只按线上稳定信号(端点与 body 形状,MUST NOT 按 UA;harness 取自信封 `proc.agent`,session 信号见 3.4)给出**唯一一个**线格式,或 `null` = 未识别;该线格式的 dissector 解析。
**备选(未选)**:① 单个巨型 if/else 解析器(provider 分支混在一处)——违反"适配缝不漏进前端/彼此"(不变式 3([0.0](0.0-overview.md) §核心不变式)),加 harness 就改核心;② 每 provider 一个完全独立的管线到独立表——丢掉归一化,前端要认三套。
**取舍**:registry + 统一 dissector 面 = 加线格式是"加一个 dissector + registry 一行",加 harness 只加约定数据(D37),核心与前端零改动。

## 接口契约(每个 dissector 对象)

平铺车道的线格式(OpenAI Responses / Chat Completions / Responses over WebSocket)各是 `src/dissect/registry.mjs` 的 `BOARD` 表里一个对象;共享的抽取与归约(`src/view/extract.mjs`、`src/view/reduce.mjs : flatFold()`)只调下表的字段,不按线格式分支。Anthropic 线由多车道分析器装配(`src/view/analyze.mjs : linearContext()`,跨记录拼接经 `MULTI_LANE_CONTEXT` = `CC_THREADS`),不在 `BOARD` 里;它的块键是 `CC_SECTIONS` 的 id(`blockKeysOf('anthropic')`)。

| 字段 | 输入 → 输出 | 用途 |
|---|---|---|
| `id` | — → 线格式 id | 与 `wireFormatOf()` 的返回值同名;call 行按它记线格式,`boardDissectorOf(id)` 按它取回对象 |
| `blockKeys` | — → 请求顶层键表 | 成块的顶层键;其余每个顶层键由 `nonBlockKeysOf()` 逐个列出(Invariants「未映射字段」) |
| `boardFlat(req)` | 请求体 → 有序 canonical 块 | **assembly order**(tools→system→messages);Codex `instructions`→system、`input[]`→messages |
| `normResp(rec)` | record → 归一化回复(`usage` / `stop_reason` / `id` …) | 回复块与 usage;usage MUST 映射到 [3.2](3.2-normalized-model.md) 的 canonical 角色,provider 字段名不外泄 |
| `replyParts(rec)` | record → 每个回复块在 `resp.raw` 里的字节段;事件区间的部分带事件数 `events` | 回复块回源(D69 · D70,下文) |
| `reqCounts(req)` | 请求体 → 派生计数 | 看板头与原始卡读 |
| `ctxTokens(norm)` | 归一化回复 → 输入 token 数 | 时间轴条的上下文大小 |
| `failed(norm, rec)` | → bool | 调用失败:终止消息说失败,或采集里没有终止 |

上下文跨记录的线格式另带钩子(`RESPONSES_WS`):`prepare`(→ 拼接计划器)、`admits(rec)`(这条记录是不是一次调用)、`laneOf(rec)`、`agentOf(rec)`、`stitchOf(rec)`;HTTP 的两个对象带 `messageCount(req)`(压缩判定比较的消息数,3.4),没有时读 `req.message_count`。

- **块带逐字 span(D19)**:每块的 `text_ref` 指向它在 `req_body` 里的原始序列化字节(采集所见,**非 key 规范化**):`src/dissect/json-scan.mjs : scanJson()` 给出 span,Anthropic 线的块 span 由 `src/dissect/cc-spans.mjs : blockSpans()` 按位置对齐到块上;块身份 `src/view/extract.mjs : bidOf()` 打在这些逐字字节上(没有 span 的块才用键序规范化的 JSON,它们本来就不是逐字块)。**键序规范化(`canonJSON`,`src/view/analyze.mjs`)仅供 [3.3](3.3-cache-model.md) `divergence_cause` 分类(判 json-key-reorder/tool-array-reorder),MUST NOT 进块身份**——否则 key-reorder 类 cache-break 会塌进去重、变不可见(**必拒**;兜底 `test/view/prefix-proof.test.mjs` #12:只差空白或数字写法的 tools schema 不算逐字相同)。bounded-prefix 只许用于内存态启发式(见 [4.3](4.3-parse-index-cache.md))。

- 三层归属(§3.2 心智模型):dissector 是 **server-side 分析层**,坐在采集(4.1)与查询(3.5)之间。访问模式:**只读**原始 NDJSON 记录,吐 canonical 块;MUST NOT 改原始。
- 依赖:输出契约 = [3.2](3.2-normalized-model.md);读它的是看板的抽取与归约(`src/view/extract.mjs`、`src/view/reduce.mjs`)与具名查询([3.5](3.5-query-layer.md))。
- **回复块也回源(D69 · D70)**:每个回复块带 `<raw_ref>::<field>::<a>-<b>` 指针,指向本记录回复里它自己的那段字节(语法唯一出处 `src/raw/refs.mjs`,[4.2](4.2-storage-etl.md) §回源指针;`field` 在 HTTP 流式回复是 `resp.raw`,在 WebSocket 是该块所在的服务端消息 `resp.messages.<j>`);这段字节单独解析就得到这一块,各块按顺序就是归一化的回复。段怎么取:
  - **JSON 节点**:线上把整个输出项作为一个 JSON 值送达时,块的段是它自己的 JSON 节点,路径 = 输出项的路径 + 块在项内的路径(`itemToBlocks` 给的 `sub`),与请求侧 `input[i].content[ci]` 同一条规则:message 的每个 content part 各是一块、各有一段,单 part 的 message 的段也是那个 part,不是整项;`reasoning` 项只是一块,段是整项自己的节点(`sub` 为空)。Responses over WebSocket:节点在关闭该项的服务端消息 `response.output_item.done` 里,路径 `['item', ...sub]`;逐项看:没有消息关闭的项(哪怕同一回复的别的项有)在 `response.completed` 里,路径 `['response', 'output', i, ...sub]`,按 `output` 的次序与关闭的项排在一起。Responses over HTTP SSE:节点在关闭该项的事件 `response.output_item.done` 的 data 载荷里(载荷是整项的一个 JSON 值),路径 `['item', ...sub]`;没有关闭事件到达的项在终止事件(`response.completed` / `incomplete` / `failed`)的 data 里,路径 `['response', 'output', i, ...sub]`;区间 = data 在 `resp.raw` 里的起点 + 节点在载荷里的区间。
  - **事件区间**(其余情形:Anthropic 与 Chat Completions 的 SSE;Responses SSE 中送达整项的那个事件的 data 不是单独一行 `data:` 里的一个 JSON 值):按块键归组的事件,段从组的第一个事件开头到最后一个事件结尾,解析这些事件得到这一块。一个区间只装得下一块时才给;组里有多块,或组的事件与别的块交错时,没有段并写明原因(不变式 4)。Responses 的整项根本没有送达(没有关闭事件,终止事件也不带它)时不出块,写明原因。
  - message 没有 `content` 键或 `content` 为 null 时与 `content: []` 一样不出块,请求侧与回复侧相同(两侧都经 `itemToBlocks`)。
  - **`view` 与 `events` 从哪来(不新写拼装)**:`block` 回答的 `view`([3.5](3.5-query-layer.md) §会话读)的正文就是这份拼好的块:`src/view/extract.mjs : replyBlocks()` 对每种线格式都拼得出(Anthropic SSE、Responses SSE 与 WebSocket、Chat Completions、普通 JSON),`blockAt(rec, ref)` 按 ref 找到它,`src/view/render-kind.mjs : viewOf()` 给出 `{r, body}`。`events` 是这一部分由多少个流事件拼成:`streamParts` 里按块键归组的事件数(`keysOf` 给空的事件不算,如 ping),只放进有事件区间、一块一段的部分(`replyPart` 带上,`replyBlocks` 放到 flat,`blockAt` 原样给);JSON 节点没有这一项。拼好的块不丢字段:Anthropic 流以 `content_block_start` 的整块打底,补上 citations 与任意块的 `input_json`;Chat 的 refusal 与数组内容、Responses 的输出数组都进块;图片的 data URL 拆成数据,URL 进 `source.url`。
- **adapter = dissector(D25 · 「Wireshark for agents」)**:这个「原始 bytes → canonical blocks」的接口**就是** dissector;加线格式 = 写一个 **JS-module dissector**(非嵌入式 DSL;D37:加 harness 不写 dissector)。**看板与具名查询 MUST 共用同一 dissector**(都经 `wireFormatOf()` 取),不各有一套解析器。单一 CC dissector 模块 [src/dissect/cc.mjs](../../src/dissect/cc.mjs) = **唯一** CC block 模型源(声明式 `CC_SECTIONS` 分类/布局 + `dissectBlocks(req)` 装配序走查 + 共享 `resourceRef`/`isVolatile`/`blockKind`/`faithfulness`/`sysLabel`/`parseBashReads`);它有两个**投影**,按位置对齐:看板的 `linearContext()`([src/view/analyze.mjs](../../src/view/analyze.mjs))出块,`src/dissect/cc-spans.mjs : blockSpans()` 给每块叠加 D19 逐字字节 span;board-intake `hydrateForBoard`([src/view/extract.mjs](../../src/view/extract.mjs))把 D10 `req_body` 串喂进看板投影(tools 逐字 `input_schema`)。provider 专属(response 形状 / turn 判定 / tool 抽取)全落各自 dissector,**不进 [3.2](3.2-normalized-model.md) 共享 schema**(承 D25)。每个线格式一个同形 dissector,两个投影不动。

## 深度优先拆积木(§3.3)
**D37 起 dissector 按线格式拆成四个**。harness 约定分两半,都是数据、不进 dissector 的解析逻辑:采集侧是描述符数据(D57⑥:进程名、已知 host、代理入口、证书载体、信任来源),在 `src/collector/harness/*.mjs`,形状见 [4.11](4.11-collector-model.md) §2(Linux 的字段见 [4.6](4.6-process-collector.md));读取侧(session 键、请求类别头如 `x-codex-turn-metadata`、观测者效应)是 `src/dissect/harnesses.mjs` 里每个 harness 一行——`src/dissect/` 是叶子([0.1](0.1-engineering-rules.md) §2),dissector、D35 封存器(`src/raw/`)、段索引与看板都能 import,采集器不需要它。各是可独立构建 / 验证的积木:
1. **Anthropic Messages · CC adapter**→ 验证 AC-1/AC-2 通路。D37:dsh、Z-Code 默认,以及 Kimi / OpenCode / Hermes 配成 anthropic 时也走它,MUST 不依赖 CC 专属标记也能拆;dsh 的 `tool_addition` / `tool_removal` 块要认,顶层 `dsh_session_log` / `dsh_plugin_packages` 逐字保留,但不算模型上下文块。**Message Threads**(上下文放在服务端;Claude Code 2.1.304 起实测):链头请求带 `thread:{type:'create'}`,`system` / `tools` / `messages` 都完整;续接请求带 `thread:{type:'continue', previous_message_id}`(= 前一环**回复**的 message id,即 SSE `message_start.message.id`),`messages` 只有增量(一条 user + 常见一条 role=`system` 的 text),`system` 只剩不进 cache 键的 billing header(`isVolatile`),`tools` 多为空或不带、偶尔整份重发。是否拼接只看 `thread.type === 'continue'`,MUST NOT 按模型、版本或 beta 头判断;dissector 在整个 session 的记录里按回复 id 找前一环(主线与每个子 agent 各一条链、交错到达、到达序可与 ts 不同),拼出模型实际收到的上下文:messages = 前一环拼好的 messages ⧺ 前一环的 assistant 回复 ⧺ 本次增量;system = 本次自带含可缓存块的 system 时用它,本次不带 system 时沿用链上的整份,否则沿用链上的 system、本次的易变块原位顶替继承来的易变块;tools = 本次自带非空时用它,否则沿用链上的。前一环的回复不完整(错误信封、被截断、有没解析的 SSE 事件、没有内容块)或前一环自己是 `partial` 时,本次及其后继都是 `partial`,缺什么写明是哪条记录、什么原因(不变式 4、D38);前一环是 `server_edited` 时沿链传下去;`thread.type` 既不是 `create` 也不是 `continue` 时不当完整的链头,记 `partial` 并写明原因。不带 `thread` 的调用(附带请求、小模型调用)照旧是全量。role=`system` 的消息与其中的 `tool_addition`(中途加工具)是上下文块,加进来的工具定义计入工具数,`tool_removal` 去掉的从中减掉。车道归类读拼好的上下文;子 agent 车道按链分,不按到达顺序猜。
2. **OpenAI Responses over HTTP · Codex adapter**(Responses API;`instructions`+`input[]`→归一化;显式 fork/thread)。`src/dissect/openai.mjs` = OpenAI/Codex dissector,与 CC dissector 同形(声明式 `OPENAI_SECTIONS` + `boardFlat`/`dissectBlocks` + `normResp`;usage 经 `src/model/schema.mjs : mapUsage()`),把 Responses(`instructions`→system、`input[]`→messages:message/function_call/function_call_output/reasoning、`tools[]`→tools)映射进**同一跨-provider block 词表**(text/tool_use/tool_result/thinking,服务端工具的 `server_tool_use` 与 `*_tool_result`;认不出的 Responses `input[]` 项是 `json` 块、逐字呈现,MUST NOT 读成 assistant 说的一段话),board 零改动即渲 Codex;`reasoning` 项不论带哪些键(`summary`、`content`、`encrypted_content`,`content` 为空或缺也一样)都是一块 `thinking`,role 为 assistant,文字 = `summary` 与 `content` 里各段文字,段与段之间空一行,MUST NOT 走 message 那条路,请求侧与回复侧相同(都经 `itemToBlocks`);没有文字时(只有密文,或什么都没有)→`opaque`(不变式 4);usage 从 SSE `response.completed` 重建;session 身份 = `session-id`/`thread-id` 头(=`prompt_cache_key`)。守卫:`test/web-v2/ac1-real-server.test.mjs`(AC-1,七形集)。
3. **OpenAI Responses over WebSocket**(新 · Codex 内建 `openai` provider 默认):带 `previous_response_id` 的 `response.create` 只有 `input` 是增量,instructions / tools / `prompt_cache_key` 每次重发;不带它的就是全量(Codex 新连接的首条;OpenCode 的实验 WebSocket 每条都全量)。是否拼接只看有没有 `previous_response_id`,MUST NOT 按消息在连接里的位置判断(否则 OpenCode 的上下文会被重复计入);dissector 沿 `previous_response_id` 拼出模型实际收到的上下文;`generate:false` 的预热逐字记、lane `probe`、不算一轮,但进拼接链;按 `response.create` 与终止消息命名并校验逻辑调用。终止消息与 [4.6](4.6-process-collector.md) §传输与帧级记录 里 Codex 的 harness 数据一致:`response.completed` / `response.failed` / `response.incomplete` / `error`,其中 `response.incomplete` 结束被打断的一轮。调用打开期间的其他客户端消息(如 `response.interrupt`)在信封的 `req_extra_messages` 里,归入同一调用、不另算一轮,MUST 可见、不静默丢(同下文「未映射字段」)。
4. **OpenAI Chat Completions**(新 · Kimi、Hermes 默认,OpenCode / Z-Code 按配置):`reasoning_content` 字符串→reasoning 块;Kimi 的 `thinking` / `builtin_function` 与 `choices[0].usage`;**先对真实抓包核对再硬编码**(待数据决策 DS)。

每个都用 AC-3 验证:新增该 dissector,canonical 块与 usage 产出,前端主干不变(判据见 [1.1](1.1-product-definition.md) AC-3)。

## Invariants（MUST）
- dissector MUST NOT 丢失/改写原始记录(逐字源真相)。
- usage MUST 全部落 canonical;每块 MUST 带 `faithfulness`;非 verbatim MUST 标(opaque=Codex 加密 reasoning;metadata=旧 v0 trace 的工具定义[pre-D15]、only-seen 名字、D40 之前的非 LLM 请求体与「只记日志」的调用(D40 起非 LLM 请求体逐字)——**D15 后 tools schema 逐字=verbatim,纳入 AC-1**,per-block badge 区分)。
- `wireFormatOf()` 认不出的记录(返回 `null`),以及已知线格式里不是一次调用的记录(`admits` 为假),MUST 记进「未识别」并计数(`src/view/reduce.mjs : unknownSummary()`),MUST NOT 静默丢弃,也 MUST NOT 套别的线格式的词表渲染。
- **未映射字段 MUST 可见、MUST NOT 静默丢**(承不变式 2、4([0.0](0.0-overview.md) §核心不变式)):每个 dissector 声明请求里成块的顶层键(`blockKeys`;Anthropic 线是 `CC_SECTIONS` 的 id,都经 `blockKeysOf()` 取),`src/view/extract.mjs : nonBlockKeysOf()` 把**其余每个顶层键**逐个列出(带指向它逐字值的 `ref`,短标量另带值),原始记录整条可看(`raw_ref`);块内的键随块的逐字字节一起呈现(D19)。判据是"块键 ∪ 列出的非块键 == 请求顶层的全部键"。**永不为了'干净'而丢字段**——不认识就列出,不是删掉。
- **跨记录拼接与「不完整」(D37)**:拼接复原只在 dissector 里做(看板与查询共用,D25),MUST NOT 在 `src/view/extract.mjs` / `src/view/reduce.mjs` 加 WebSocket 分支(D25 记下的渗漏方向)。拼出来的块字节确实逐字,仍标 `verbatim`;整条 call 另标 `context_state`([3.2](3.2-normalized-model.md)):前序记录都在 = `reconstructed`,缺任一条 = `partial`。信封顶层带 `partial:true` 的调用(采集端看到这条连接上有缺口,[4.6](4.6-process-collector.md) §传输与帧级记录)同样读成 `partial`;dissector 能证明它不依赖缺失的消息时(如不带 `previous_response_id` 的全量调用)才收窄。信封的 `ws_truncated`(调用超上限)与 `req_encoding_error`(压缩请求体采集端没解码)不改 `context_state`,在该调用上就地标「已截断」「压缩请求体未解码」;信封带 `req_content_encoding`、`req_body` 为 `null` 时,读取侧按它先自己解 `req_body_b64`,解出来就照常拆块,解不出才标。CC Message Threads 同理:锚点记录都采到就沿链拼成 `reconstructed`;锚点没采到、或服务端继承的部分(如 system / tools)从已采记录还原不出,才标 `partial`。服务端**删改**上下文(CC / Kimi 的 `context_management` / `clear_at`)是另一回事——模型看到的比线上少——只在响应报告确实应用了编辑时标 `server_edited`;只声明而没应用的不标。`partial` / `server_edited` MUST NOT 显示成完整(不变式 4)。

## Out-of-scope
采集机制(4.1)、表 DDL(3.2)、前端(2.x)、cache 语义(3.3)。

## 验收(可跑 check）
- 实现 CC + 第二个 dissector,各喂真实记录 → canonical 块与 usage 产出且 AC-1/AC-2 过;前端主干不变(AC-3,判据见 [1.1](1.1-product-definition.md))。
- 喂一条认不出的记录 → 记进「未识别」并计数,不崩不丢、不渲染。
- **未映射兜底**:对记录,块键 ∪ `nonBlockKeys` 的键 == 请求顶层的全部键,每个非块键的 `ref` 解析回它的逐字值;往请求塞一个新顶层键 → 它出现在 `nonBlockKeys` 里,无一静默丢。
- **块词表**:服务端工具的调用与结果拆成 `server_tool_use` / `*_tool_result` 块;认不出的 Responses `input[]` 项拆成 `json` 块,不出 assistant 文本(守卫 `test/dissect/vocab.test.mjs : "Responses items: kind / role by the type suffix and call_id, each block a verbatim sub-value of req_body"`)。

## Edge cases
- 流中断/半包:dissector 的 `failed()` 判为失败,不当成功。
- Codex reasoning 加密(opaque)、CC 工具定义(**D15 后 verbatim;仅 pre-D15 老 trace = metadata**,带 per-block badge):`faithfulness` 如实标,回放 UI 据此提示"非逐字"(仅对真正非 verbatim 的块)。
- **D37 待核(实验室)**:Kimi / Hermes 真实 Chat Completions 包体与 `openai.mjs` 现有 chat 识别是否吻合。

## Risk / 回滚
每个 dissector 一个 `git commit` 积木;失败回退上一绿点(`git revert`)。dissector 是纯函数(记录→块)→ 可离线用固化的真实记录做回归,零副作用。

## Extensions
新线格式:实现本接口(一个 dissector);新 harness:描述符数据(D57⑥,[4.11](4.11-collector-model.md) §2)+ 读取侧 `src/dissect/harnesses.mjs` 一行 + 注册表 `src/off/harness-names.mjs` 一行与它的图标文件(D76);都不改他 dissector。

**自动适配(auto-adapt · [5.1](5.1-intervention.md))**:在本契约上加一层**自动侦测启发式**——从原始流量猜 provider 线格式 + harness 约定,少写/免写手工 dissector 就点亮面板。它**只读**(更聪明的观测),与拦截 / 修改能力(D30)互不依赖,可独立推进。**约束**:auto-detect MUST 只读、只猜、可被人工 dissector 覆盖;侦测结果是**派生推断**,UI MUST 标「自动推断,可能不准」(承不变式 4);`nonBlockKeys`(见 D7 钩子)是它的天然信号源。

**D7 自演化钩子**:`nonBlockKeys` 不只是保真兜底,更是下游自演化设施(D7,单独立项)的**触发输入**——新 agent/API 一来,它带的、没有 dissector 认识的请求顶层键自动出现在该调用的 `nonBlockKeys` 里。本层只**保证信号可见**(逐键列出、可回源),不计数、不建聚合视图,也不实现自演化本身。
