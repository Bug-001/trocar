## Goal
给 [2.3](2.3-context-window.md) 的忠实窗口配一个**本步(playhead 当前 call)上下文的目录**:工具定义组(逐工具)/ 系统提示组(逐块 + 缓存标记与「每次都变」的字形 + 字符数)/ 提问组(列这一步上下文里的人写提问)/ 有变化线时一行「跳到变化处」,点任一条即跳到窗口对应块;跳到**折叠 turn 里**的块会先展开该 turn 再定位。outline **只管"本步上下文结构"**——资源在整条 session 里的进出生命周期已拆到右页资源管理器([2.4](2.4-resource-explorer.md)),二者 MUST NOT 混(守卫:验收 #3)。承 demo 单 harness 验证,泛化到跨 provider(承 [3.1](3.1-adapter-contract.md)/[3.2](3.2-normalized-model.md))。

## 前置定义(Definitions)
- **outline / `#ctxnav`**:看板左侧的目录容器,随 playhead 重渲(scrub 即换),头写「这一步的输入」(承 demo `navz`;步号在步头 [2.2](2.2-call-turn-card.md),这里不重复)。**作用域 = 本步单 call**,非跨 session。
- **nav 组(`navGroup`)**:一个可折叠分组(head:组名,资源组另带计数;body:子条列表),开合态存 `s.navOpen`(承 demo `Set(['sys',…])`,系统提示默认展开;与 [2.4](2.4-resource-explorer.md) 的资源组共用这个集合和这个壳)。
- **子条**:一个可跳条目,画成 `<button>`(键盘可达);`data-jumpfi=<flat index>` 指向窗口里对应 `.cblk` 的块序。
- **提问行**:提问组内一条 = 这一步上下文里的一条**人写提问**,来自服务端填的 `flat[].query`(今天由 `src/view/blockmeta.mjs : blockQuery()` 认定:剥掉 `<system-reminder>` 后仍非空的 `user·text` 块;[4.4](4.4-server.md) `sessions` 的 `title_source` 起按 harness 表里各自的规则认,并给 `flat[].queryBasis`)。前端不从正文推断。点它跳到该提问块。
- **「跳到变化处」行**:非分组的单行,只在这一步有变化线时出现(变化线判定归 [2.3](2.3-context-window.md)),点它跳窗口的 `#cachebrk`。它取代旧文的 cache-break 行(那一行在计数位显本步命中 %,已删,见 §砍掉的)。
- **「第 N 步起」**:提问行尾的步号,说这条提问从主对话第几步起进入上下文;点它把 playhead 移到那一步。只在主对话的提问事件(主对话车道 `lane` 回答的 `events` 里 `type:'user'` 的项)按 §画什么 的规则配得上时才写;那一项所在的页不在手里时配不上(不写 N)(依据:不变式 4;D69;[3.5](3.5-query-layer.md) §会话读)。

## Plan(选定方案 + 取舍)
**选定**:**看板内嵌左栏目录 · 三组(工具定义 / 系统提示 / 提问)+ 有变化线时一行「跳到变化处」 · 条目从服务端的块列生成 · 点条跳窗口(折叠 turn 先展开)。** outline 与忠实窗口共处一个 `<main>`、读**同一份** `flat[]` 序(`s.curFlat`),故 `data-jumpfi` 与窗口 `.cblk[data-bi]` 天然对齐,跳转不飘。竖栏与窄屏下拉从同一份条目表画(`outlineEntries()`),两处不会说得不一样。
**备选(未选)**:① **独立第四栏**(与左右页并列)——挤占回放骨主舞台、且目录与其索引的窗口分屏,注意力割裂(违 [1.2](1.2-shell-layout.md) 的左右页 B 布局);② **把资源生命周期也塞进本栏**(demo v0 曾如此)——"本步结构"与"跨 session 进出"两种时间尺度混在一栏,读者分不清"这一步有什么" vs "整条 session 里这文件何时进出",故 B-split 拆去 [2.4](2.4-resource-explorer.md);③ **目录即渲染真相**(在 outline 里展开块全文)——那是窗口([2.3](2.3-context-window.md))的职责,outline 塞全文会诱导"目录=真相"误判、且与窗口重复;④ **保留 cache-break 行显本步命中 %**(旧文)——同一个数在步头的「缓存」按钮里已有一处(命不命中不值得在这么紧凑的空间里占篇幅,一个悬停展开的按钮就够);⑤ **把提问组做成整条会话的章节目录**(界面重构稿:每条提问写步段,被压缩掉的提问折成一行灰字)——作用域从"这一步"扩到整条会话;被压缩掉的提问不在这一步的上下文里,要拼别的步的数据;步段的末端要靠下一条提问推,分页或压缩后推不准。只留由事件直接给出的「第 N 步起」。
**取舍**:outline 是**导航投影**(preview/计数),不是回放层——零全文冗余、与窗口读同序 → 跳转永不错位;逐字真相只在窗口([2.3](2.3-context-window.md))。

## 部件结构(承 demo)

### 定位:看板内嵌左栏(必拒做成第四栏)
`#ctxnav` 长在 `#leftpage` 的 `<main>` 内、中栏(步头 + `#ctxwin`)之左(承 [1.2](1.2-shell-layout.md):`<main>` = outline `#ctxnav` + `#maindiv` 边界 + 中栏)。它**不是**与左右页并列的独立栏——它是回放骨里的目录侧条。**outline↔中栏边界可调**:`#ctxnav` 列宽由 `#maindiv` 拖拽控制(CSS 变量 `--outline-w` + `localStorage['trocar.v2.split.outline']`,默认宽与夹取范围见 [1.2](1.2-shell-layout.md) §回放台 B 布局,承 Q1;handler/夹取/持久化归 [1.2](1.2-shell-layout.md),本模块只认领"outline 是被拖宽的那一列")。窄于 900 px 时竖栏收起,同一份条目进步头([2.2](2.2-call-turn-card.md))里的下拉「输入 ▾」(断点归 [1.2](1.2-shell-layout.md) §窄屏;按钮名为)。守卫:验收 #10 + [1.2](1.2-shell-layout.md) 的 `test/web-v2/replay-layout.test.mjs`。

### 作用域:本步上下文(随 scrub 重渲)
outline 描述的是 **playhead 当前 call** 的上下文结构:playhead 一动,`s.renderNav()` → `renderOutline()`(承 demo `setPlayhead → renderContextNav`),scrub 到别步即整栏换。无 call 的步(probe / 中断)→ 整栏清空(承 demo `if(!call){ nav.innerHTML='' }`;v2 的 `outlineHtml()` 返回空串)。**MUST NOT** 把跨 session 的资源进出画进本栏(那是 [2.4](2.4-resource-explorer.md) 的"across the session")。守卫:验收 #3、#9。

读本 call 的有序块 `flat[]`(放在 `s.curFlat`):客户端按 `lane` 步的 `ops` 物化出块 id 列表,每个 `bid` 配上它的定义与这一位置的 `attrs`([3.5](3.5-query-layer.md) §会话读,D69),按 `sec` 分组。从上到下:

- **工具定义组**:逐工具列名;MCP 工具在名字后带「MCP」(`flat[].mcp`)。点条跳该工具定义块。空 → 「这一步没有工具定义」。
- **系统提示组**:逐系统提示块,列 `label` + 缓存标记字形(`cc` 非空 = 请求在这一块声明了缓存位置)/「每次都变」字形(`volatile` = 每次请求都变的块)+ 字符数(写「1.2k 字符」,`core/fmt.mjs : kf()`)(承 demo `sysKids`)。字形取 `core/icons.mjs`,可访问名与悬停字用 [2.3](2.3-context-window.md) 块上的同一组词(「缓存标记」「每次都变 · 不影响缓存」)。徽标 MUST 从 canonical 列(`cache_control`/`volatile`,在 `flat[]` 上是 `cc`/`volatile`)读,**MUST NOT 在前端重嗅 provider 专属正则**(billing-header 等)——那属 adapter([3.1](3.1-adapter-contract.md))职责(**破此缝 = 需 RFC 才放行**,不变式 3;判据同 [2.3](2.3-context-window.md) 徽章)。守卫:验收 #4 + `test/web-v2/no-provider-branches.test.mjs`。空 → 「这一步没有系统提示」。
- **「跳到变化处」行**:单行,只在这一步有变化线时出现;出现与否 MUST 与窗口画不画变化线用同一判定(骨架行的 `cacheBreak.cause` 不在 `QUIET_CAUSES` 里;`QUIET_CAUSES` 只在 `replay/analysis.mjs` 定义一次,判定归 [2.3](2.3-context-window.md)),**MUST NOT 在本栏用 byte-diff 或自己的块比对臆测断点**(demo 已证 byte-diff 会撒谎,见 [2.3](2.3-context-window.md))。失败的一步照样出现(变化线说的是内容,不是缓存)。本行不写命中率、不写缓存状态(那在步头的「缓存」按钮里,[2.2](2.2-call-turn-card.md))。守卫:验收 #6。
- **提问组**:按块序列出这一步上下文里每个带 `flat[].query` 的对话块(`replay/analysis.mjs : humanTurns()`);预览 = 服务端给的 `query`(已折空白、至多 90 字)。`flat[].queryBasis === 'guess'` 的行带「推测」(悬停「这条是不是人写的提问,是推测的」);`sessions` 的 `title_source` 之前没有这个字段,不标。空 → 「这一步的上下文里没有认得出的提问」。点条跳该提问块。
- **「第 N 步起」的配法**:只在 playhead 所在 lane 是主对话时写。取主对话 lane 的 `events[]` 里 `type:'user'`、步序不晚于当前步的项(事件带 `rid`),按出现顺序排;提问行按块序排;两边从最后一条往前一一配对,每一对要折掉空白以后较短的一方是另一方的开头(事件 `preview` 至多 200 字,`query` 至多 90 字)才算配上;某一对配不上,这一行和它前面的行都不写步号。N = `stepRef(event.rid)`;`stepRef()` 换不出「第 N 步」时不写。**MUST NOT** 在配不上时猜一个步号(不变式 4)。没有提问事件的线(lane `outline:false`;`resources` 可为 null 之前即 `events[]` 里没有 `type:'user'` 项)一律不写,也不写"没有"。点「第 N 步起」把 playhead 移到那一步(`s.jumpTo()`,经 lane 的 `giLocal`),落点按 [1.4](1.4-central-board.md) §打开一步时落在哪。守卫:验收 #7。

### 跳转联动:目录 → 窗口(折叠 turn 先展开)
点子条 → `jumpToBlockIndex(s, fi)`:**先 `openTurnFor(el, s, fi)`**——若该块落在 messages 段某**折叠 turn** 内(`messageTurns()` 切出的提问卡;开合按 D12 的折叠记忆,`replay/fold.mjs : turnIsOpen()`),先把该卡置开(`setFold()`,这是用户自己点的,写进折叠记忆)、把它所在的组画出来(`ensureRow()`,[2.3](2.3-context-window.md) §读与画「长对话的窗口」)并重渲窗口,再把目标 `.cblk` 展开、`scrollIntoView(center)` 并短暂高亮(承 demo)。「跳到变化处」行走 `jumpToAnchor(s, 'cachebrk')`,经等页队列(`replay/jump.mjs : createJumpQueue()` · `anchorJump('cachebrk')`):变化线不在 DOM 里(在折着的提问卡里或还没画的组里)时先按这一步的 `cacheBreak.idx` 把它画出来(`ctxwin.mjs : ensureRow()`,卡的打开同样写进折叠记忆);这一步的正文还没送到时,等那一页落地后跳一次,用户再动就作废(`jumpDecision()`)。**这是 outline 的核心价值:目录条与窗口块序同源(读同一 `flat[]`),点条必落对块。**守卫:验收 #2、#11。

### 与资源生命周期的拆分(B-split · 承 2.4)
demo 里 `renderContextNav` 一函数**双填**:`#ctxnav`(本步目录)+ `#resexp`(跨 session 资源生命周期 `lifecycleNav`)。**产品拆:本模块(2.5)只出 `#ctxnav` 目录;`#resexp` 的资源生命周期归 [2.4](2.4-resource-explorer.md)**(v2:`replay/resources.mjs : renderResources()`;回放台的 `s.renderNav()` 依次调两者)。`navGroup()`、`data-navtoggle` 开合、`jumpToResourceBlock()` / `jumpToStepAndBlock()` 等是放在 `outline.mjs` 里的共用工具函数,[2.4](2.4-resource-explorer.md) 调用它们,但 2.5 只 wire 自己的 `#ctxnav`(`wireOutline()`)。**资源条 MUST NOT 漏进 outline**(守卫:验收 #3)。

## 跨 provider 泛化(承 3.1/3.2)
demo 只跑 Anthropic、且每步现解析 `linearContext(call.rec.request)`、cache % 直读 Anthropic 原生字段名(`cache_read_input_tokens` 等)。**产品改从归一化块列渲染**:分组读 `flat[].sec`(tools/system/messages;Codex `instructions`→system、`input[]`→messages 已由 dissector 归一,`src/dissect/openai.mjs : boardFlat()` / `boardFlatChat()`)、`role`/`kind`/`label`/`name`/`mcp`/`cc`/`volatile`/`query`;「跳到变化处」读服务端的 `cacheBreak.cause`(闭合枚举,与线格式无关)。→ **加 provider 只加 adapter,本栏零改**(AC-3:前端主干 = `web/legacy/` 中除 `core/chips.mjs` 与 `assets/harness/` 以外的文件,[1.1](1.1-product-definition.md))。「第 N 步起」靠的提问事件今天只有 Anthropic 线有(openai 线的 `events` 除压缩外为空),那时只是不写步号;前端不按线格式分支。

## 保真边界(承不变式 4,[0.0](0.0-overview.md) §核心不变式 · 必拒隐瞒)
outline 显示的是**派生导航投影**——`label` / 提问预览(服务端剥掉注入内容、折空白、至多 90 字)/ 字符数 / 计数,**非线上 payload 逐字**;它是**导航层**,同会话头([1.2](1.2-shell-layout.md))。逐字真相在窗口([2.3](2.3-context-window.md))。故:
- 工具定义组只列**名字**——因为 outline 是**导航投影**(逐字 schema 在 [2.3](2.3-context-window.md) 窗口),**非**因为没采集;D15 后 schema 逐字捕获(`faithfulness=verbatim`,仅 pre-D15 老 trace = metadata)。**MUST NOT** 让工具条看着像完整工具定义。守卫:验收 #5。
- 提问预览是截断/折空白的**摘要**,**MUST NOT** 让人误以为是块全文;点条落窗口才见逐字(且非 verbatim 块在窗口就地标 faithfulness)。守卫:验收 #5。
- 无需在每条 outline 逐字标注(它本就是导航投影),但 **MUST NOT 让这些投影看起来像线上原始字段**。守卫:验收 #5 + 收尾审查。
- 认不准的东西不写成事实:`queryBasis:'guess'` 的提问行带「推测」;「第 N 步起」配不上就不写;正文还没送到、解析不出来的一步,组下不列条目,只给一行原因,不写 0(守卫:验收 #7、#8、#9)。

## Edge cases
- **无 call 的步**(probe / 中断):`#ctxnav` 清空,不崩(承 demo)。
- **车道未到手**:工具定义计数用骨架行的 `tools`,系统提示与提问组画定好大小的空行,车道一到就填进去([2.3](2.3-context-window.md) §读与画);「跳到变化处」仍按骨架行的 `cacheBreak.cause` 判,点了等车道到手再跳一次。不写 0、没有加载控件。
- **请求体解析不出来 / 没有请求**:计数写「—」,一行原因,与窗口的代替态一致([1.4](1.4-central-board.md))。不写 0。
- **纯 system-reminder 的 user 块**:服务端不给它 `query`(`blockQuery()` 剥完为空)→ 该块在窗口存在、却不在 outline 列出。组头不带计数(§只做导航),这类块只在窗口里。
- **`sessions` 的 `title_source` 之前的非 CC 线**:`blockQuery()` 今天对每条线都只剥 `<system-reminder>`,Codex 这类线开头注入的上下文可能被列成一条提问;`sessions` 的 `title_source` 起按 harness 的规则认,认不准的带「推测」([4.4](4.4-server.md))。前端不为此分支。
- **无工具 / 无系统提示 / 无提问**:各组写「这一步没有工具定义」/「这一步没有系统提示」/「这一步的上下文里没有认得出的提问」,不空手。
- **没有提问事件的线**(openai 线,或 `resources` 可为 null 标了 `outline:false` 的 lane):提问行照样列(来自 `query`),只是不写「第 N 步起」,也不写"没有"。
- **没有主对话 lane 的会话**:轴落在第一条 lane 上([1.2](1.2-shell-layout.md) Edge cases),不写「第 N 步起」。
- **超长工具列表 / 超多系统提示块**:分组折叠可扛;视口虚拟化留 Extension。
- **compaction 步**:outline 只反映该步(compaction 后)的本步结构;「跳到变化处」落在说对话被压缩的那条变化线上;被压缩掉的提问不在这一步的上下文里,不列;"context resets"事件条属 [2.4](2.4-resource-explorer.md) 的 `#resexp`,**不在本栏**(compaction ≠ fork,承 [3.4](3.4-session-identity.md))。
- **第一次调用**(`cacheBreak.cause` 为 `first-call`,包括跨 session 暖前缀、`cache_read>0` 的情形):没有变化线,也就没有「跳到变化处」;缓存怎么说归 [2.2](2.2-call-turn-card.md)(承 [3.3](3.3-cache-model.md))。
- **失败的一步**:内容变了照样有「跳到变化处」(变化线说的是内容);失败本身在步头与迹线屏上说([2.2](2.2-call-turn-card.md) / [1.3](1.3-timeline-tracks.md))。

## Risk / 回滚
本栏是**纯渲染函数**(块列 → nav DOM),用真服务端上的固化记录回归;失败回退上一绿点。**最大风险 = 目录与窗口块序失同步(`data-jumpfi` 对不上 `.cblk[data-bi]`)→ 跳错块**:回滚策略 = 强制 outline 与窗口读**同一份** `flat[]` 序,不各自解析;或 **徽标回退到前端嗅 provider 特征**(违不变式 3,必拒;守卫 `no-provider-branches.test.mjs` + 收尾审查)→ 降级为只读 canonical 列,宁可少显不可前端瞎猜。**次要风险 = 「第 N 步起」配错**(提问在后面的步里被 harness 改写):规则只在文字相合时写,配不上就整段不写;真出错时回退 = 去掉步号,提问行仍能在窗口里跳。

## 砍掉的

| 元素 | 为什么 |
|---|---|
| cache-break 行与它的命中 %(旧 Definitions、旧 §三组 + cache-break 行、旧验收 #1) | 同一件事在步头「缓存」按钮里说一次就够(见 Plan 备选 ④);有变化线时改留一行「跳到变化处」 |
| 头里的步号「#N」 | 步头已写「第 N / M 步」 |
| 组头与子条的表情符号(`⚙` `▤` `💬` `⚡` `🗣` `🔌`) | 界面不用表情符号([1.5](1.5-states-aesthetics.md));MCP 写成「MCP」 |
| 各处自己拼的组名与空态句(`tools` / `system` / `messages` / `no tools in view` / `no plain-text user turns in view`) | 一律按闭集取 `labels/**` 的词(英文,D58①),页面里不写字面量 |
| 正文未送到时的「N 条消息」元数据行与「载入后显示块数」 | 大纲只列能跳的东西;消息条数不是提问数,放在提问组旁会被读成提问数;页面落地后本栏自己换成正常态 |
| 提问的步段、序号、当前提问的强调竖线(界面重构稿) | 步段的末端要靠下一条提问推,压缩后推不准;当前提问总是最后一行;只留由事件直接给出的「第 N 步起」 |
| 被压缩出上下文的提问折成的灰色一行(界面重构稿) | 它们不在这一步的上下文里;要列出来得拼别的步的数据,大纲只管这一步 |

## Extensions
- outline 内**过滤/搜索**(按名/段跳大列表);一键 collapse-all。
- **scroll-spy**:窗口滚动时 outline 高亮当前可见块(双向同步)。
- 长工具/长 system 列**视口虚拟化**。
- 提问行挂**提问卡的动作摘要**([2.2](2.2-call-turn-card.md) 的「调用 N 次工具 · 思考 · 工具结果」,承 `messageTurns()` 的 `acts`),目录即见该提问之后干了什么。
- 提问组计数改为"提问数 vs 块数"可切换(收敛上述 edge-case 的计数歧义)。
- 服务端直接给提问块带上它第一次出现的步(提问块与提问事件的显式关联),「第 N 步起」就不必按文字配对。
