# trocar · RFC 1.12 — agent-native:skill set 与公开流程

> **这是什么**:用户的 agent 怎么用 trocar、怎么修 trocar、怎么把改动安全地发出去。一组随代码发版的 skill,产品里只多一个只读命令 `trocar skill`,其余机械部分是公开仓里的四个脚本:`side-board`、`contract-check`、`board-walk`、`pr-check`。
> **受众**:用户(知道自己的 agent 能做什么、哪些东西绝不会离开这台机器、边界在哪);agent(据此实现 `src/cli/skill.mjs` 与 `scripts/`,并按 skill 干活)。
> **决策**:D81(① agent 自己能用、能修 trocar · ② 流量审计就是一个 skill · ③ 不做 extension)· D59(读数据只有 `trocar query`)。
> **前置**:命令表、退出码、输出通道、`--json` 的形状 = [1.6](1.6-cli.md);具名查询 = [3.5](3.5-query-layer.md);看板的路由 = [1.2](1.2-shell-layout.md);看板的细节标准只住 `skills/trocar-ux/SKILL.md`([1.5](1.5-states-aesthetics.md) 指向它);段与记录 = [4.2](4.2-storage-etl.md);看板的服务面 = [4.4](4.4-server.md);进包的文件 = [4.5](4.5-distribution.md);提交规则与收尾清单 = [0.1](0.1-engineering-rules.md) §4 · §6。
> **不在这里**:skill 的正文(住 `skills/<name>/SKILL.md`,英文);`trocar skill` 的命令形状在 [1.6](1.6-cli.md) §5.6,本单元只写它和 skill set 的关系。

## Goal

一个用 trocar 的人说「trocar 这里不对劲」,他的 agent 能走完三段,不需要这个项目的任何私有工具:

1. **自己 debug**:对照契约查每个部分,出报告,问用户下一步。
2. **产出可靠代码**:在公开仓的 clone 里用合成数据写先红后绿的测试,改代码,过门禁。
3. **审查并发出去**:审 diff、查漏洞并修、脱敏,用户同意后开 PR。

硬要求只有一条:**真实会话的内容和截图绝不离开这台机器**。PR 只说功能改动。

另有两件事用同一套东西:做或审看板的一个屏(`trocar-ux`);弄清 agent 到底发了什么(`trocar-audit`)。

## 前置定义(Definitions)

- **skill set**:`skills/` 下的五份 skill,每份一个 `SKILL.md`,标准 Agent Skills 格式(front matter 写 `name`、`description`),不带 `references/` 或 `scripts/` 子目录。随代码发版,所以打印出来的永远和装着的 trocar 同一版本。skill 只写流程、命令和 spec 节的链接,不抄规则。
- **出站内容**:离开这台机器的全部字节:提交内容(`base..HEAD` 每个提交的新增行与累计 diff 的新增行)、提交对象的信息与额外头、文件路径、作者与提交者、分支名、PR 或 issue 的标题、正文。之后的评论回复、追加的 push、force-push、`gh pr edit` 也都是出站内容,每次都先过 `pr-check` 再问用户。
- **公开内容**:base 上全部跟踪文件里已有的文字。已经在公开仓里的就是公开的。
- **采集**:这台机器上 `trocar query` 与 `trocar raw` 读得到的东西。没装 trocar 的贡献者没有采集,跑脚本时用 `--cli` 指一个 CLI(§4)。
- **数据分层**(`trocar-debug`、`trocar-pr`、`trocar-audit` 共用):

| 层 | 内容 | 规矩 |
|---|---|---|
| 无内容 | `status` `doctor` `segments` `overview` `traffic` `classes`,contract-check 的结果 | 随时读。它们也带用户名、路径和 host,不贴进出站内容 |
| 有内容 | `block`、会话标题、真实数据上的看板截图 | 只读症状涉及的部分;截图放系统临时目录,结束时删 |
| 绝不 | `trocar raw` 的输出和 `calls --reveal` 进 agent 上下文(请求头里有逐字的 OAuth token) | 比字节只比哈希,经管道,不打印 |

## Plan(选定方案 + 取舍)

**选定**(D81①):产品里只多 `trocar skill`,只列出和打印,不写任何文件;放文件归用户的 agent,一条重定向就够,各家目录由 agent 自己知道。开发抽象成一组 skill,`trocar-debug` 只是入口。脱敏靠 `trocar-pr` 加 `scripts/pr-check.mjs`:「这段文字是否逐字来自真实会话」靠 agent 自觉判断不了,要拿它和采集比对,这件事只能机械地做。脚本只在 clone 里有,不是产品功能。失败即拒绝,唯一的放行是用户明确同意之后的 `--accept-partial`(§6)。

**备选(未选)**:

- `trocar contribute` 产品命令:把一段只有贡献者才走的流程放进每个用户的产品里;agent 把控流程就够。
- `trocar skill add / rm`:往 agent 目录写文件,而 agent 目录的文件进上下文,等于 trocar 改了被测程序看到的东西(观察者效应);`uninstall` 还要多一条例外。
- `trocar skill show`:`trocar skill <name>` 已经是它。
- 流量异常检测器、extension 系统:见 D81 ② ③。

**边界**:

- agent 不跑脚本时本机拦不住。这是用户定的把控方式,兜底是维护者收 PR 时重跑通用规则(文件、密钥、家目录形状、形状);PR 模板要求 agent 写的 PR 附脚本输出的 `hash`。
- 改写过的转述,逐字比对查不出。对策是 PR 模板没有「用户当时在做什么」这一栏,`trocar-pr` 要求 agent 跑过之后再读一遍。
- 维护者重跑时用的是他自己的采集,比不了别人的 captured-*。
- `pr-check` 不联网:`origin/main` 是本地的远端跟踪 ref,有人亲手把它挪到未公开的提交上,比不出来。
- 拆开写的 token 只有跨行能比出,字符串拼接比不出。hex 编的二进制和单行 base32 编的二进制解出来是噪声,比不中也不拒;折行的 base64、base32 才拒(§6.1 secrets)。

## 1. skill set

| skill | 什么时候用 | 做什么 |
|---|---|---|
| `trocar-debug` | 入口:trocar 哪里不对劲 | 第一步 clone 公开仓;跑 contract-check、board-walk,读 `web/` 对照截图,出报告,问用户下一步 |
| `trocar-fix` | 确认有缺陷,要改 | 在 clone 里用合成数据写先红后绿的测试,改代码,过门禁,一次全新上下文复核 |
| `trocar-pr` | 改好了要发出去;审别人的 PR | 审 diff、查漏洞、跑 `pr-check`、给用户看、再跑一次、开 PR |
| `trocar-ux` | 做或审任何一个屏 | 看板的细节标准,唯一的家 |
| `trocar-audit` | 想知道 agent 到底发了什么 | 流量审计(D81②),报告只留在对话里,不走 PR |

**`trocar-pr` 的次序**:审 diff(0.1 §6 与契约)→ 查漏洞(看板口令与 Host / Origin、只绑回环、文件权限、路径穿越、命令注入、证书与私钥、`off` 的保证、日志里的凭据;改动引入的就修;已有的漏洞停下,走 `SECURITY.md` 私下报告,不开公开 PR)→ 跑 `pr-check` → 给用户看文件清单、标题、正文、将公开的身份、比到的时间范围(`coverage` 的 `from` `to`)、`hash`,等用户明确说可以 → 再跑一次,`hash` 和用户看过的不同就回到上一步 → `gh`。开了之后,任何追加 push、force-push、`gh pr edit` 都先过 `pr-check` 再问用户。GitHub 保留 PR 正文的每个历史版本,所以必须发之前就干净。审别人的 PR 时不做发布,也不在装着采集的机器上跑对方分支里的任何东西(采集里有逐字的 OAuth token):`pr-check` 用自己 main 的 clone 里那份,cwd 指向对方的 worktree(脚本的 git 走 cwd,代码走脚本所在的 clone,采集走已装的 `trocar`);对方的测试与 npm 脚本不跑,动到 `src/web/board/` 的 PR 在没有采集的隔离环境重建。

**`trocar-audit` 答五个问题**:每个 agent 的流量去了哪、这个窗口比上个窗口多了哪些 host;非模型流量发了什么、量对不对得上这个 agent 该做的事;有没有 secret 形状的东西去了不该去的 host(只数数,不打印值);钱和缓存浪费在哪;哪些看不到(盲隧道、只记日志的类别、采集失败)。每一步都问「这对一个正常工作的 agent 说得通吗」,可疑的明确指出,标明是事实还是怀疑,给出怎么核实。不打分,不下定论。只读现有查询。

## 3. `scripts/side-board.mjs`

把 clone 里的看板跑在合成或真实数据上,不碰装好的守护进程。用真 `createServer` 加 `createQueryService`。

```
node scripts/side-board.mjs --synthetic [--bytes <n>] [--board-dir <dir>] [--url-file <file>]
node scripts/side-board.mjs --real [--board-dir <dir>] [--url-file <file>]
```

- `--synthetic`:临时 HOME,demo 会话加 `scripts/gen-dataset.mjs` 的数据。
- `--real`:只读连 `~/.trocar`。侧 home 在临时目录:除 `index` 外每个顶层目录一条链接(Windows 用 junction,普通账号就能建)、每个文件一份拷贝(文件符号链接在 Windows 上要提权;拷贝中消失的文件跳过),`index` 复制(跟随链接、去掉 `ctx`),工作进程只写临时目录。真实 `~/.trocar` 下任何字节和名字不变。这份逻辑是导出的 `sideHome(realHome, dest)`,`test/query/real-session.test.mjs` 共用它。
- **两种模式都只放 GET**,其余一律 405,覆盖 `/control/*`、`/api/*`、静态面(主 agent 定,依据:0.1 §5 只读数据面;`--synthetic` 下放过 POST 也会跑真控制动词,去掉分支代码更少)。
- **起工作进程之前把 `HOME` / `USERPROFILE` 设成侧 home**(主 agent 定,依据:`trocarHome()` 读 `os.homedir()`,工作进程继承环境)。所以侧看板的采集页不是这台机器的真状态,`docs/reproduce.md` 写明。
- `--board-dir <dir>`:发这份构建(`createServer({ webDir })`)。`--url-file <file>`:把带口令的地址写进文件(`SEQ_REAL` 读它,`test/web-v2/browser/seq/real.test.mjs`),不印到别处。不给时 stdout 恰一行地址。
- Ctrl-C 收工,删临时目录,退出 0。

## 4. `scripts/contract-check.mjs`

把能机械判定的契约都判了,只经 `trocar` CLI。不跑改状态的命令,不碰原始记录;经守护进程的读会写派生层(索引、投影),那是守护进程自己的。

```
node scripts/contract-check.mjs [--json] [--sample <n>] [--cli <path>]
```

输出 `{ok, checks:[{id, part, status, expected, observed, contract}]}`,`status` 取 `pass` `fail` `skip`;不带 `--json` 是一屏文字。退出 0 全过,1 有 `fail`。**只含计数、id 和 sha256,绝不含内容**。全部用不变量表达,期望值来自 spec([1.6](1.6-cli.md) §1.2 · §1.3 · §4.1 · 附录 C,[3.5](3.5-query-layer.md)),`contract` 写这条的出处。

默认用已装的 `trocar`(PATH 上),`--cli <path>` 明确指定才用别的:`.mjs`、`.js` 用 node 跑,其余直接执行。找不到 CLI:stderr 说明,退出 2。clone 的代码不当 CLI 用:clone 与已装版本的 `INDEX_V` 不同时,它会把封存段索引写进真实 `~/.trocar/index`,两个版本抢索引。解析只有 `scripts/lib/trocar-cli.mjs` 一处,`pr-check` 共用(主 agent 定,依据:平台缝收口一处);Windows 的 `trocar.cmd` 只能经 shell 起,含 `[\w.:+=@/\\-]` 之外字符的参数不交给 shell(会话 id 来自采集)。测试的替身经 `--cli` 进来,并替 `status` / `doctor` 作答,这两个读机器,0.1 §3 不许测试碰真 OS。

| `part` | 查什么 | 口径 |
|---|---|---|
| `query` | 每个查询都能答,`errors[]` 列全 | C.5 |
| `json` | 每个命令 `--json` 只有一个文档,退出码符合 §1.3 | §1.2 |
| `records` | `segments` 的记录数与 `trocar raw <段>` 对得上 | 比换行结尾的行数:末尾没有换行的半行不是记录(主 agent 定,依据:[4.2](4.2-storage-etl.md) 一行一条记录,`scripts/gen-dataset.mjs` 就留这样一行);`writing` 态的段比 `>=` |
| `bytes` | `block` 的字节与原始记录哈希相等(不变式 2) | 抽样 `--sample <n>`;只比 sha256,经管道,字节不进输出;压缩的请求体先过读取侧的 `expandRequestBody` 再比 |
| `numbers` | `sessions`、`session`、`lane`、`overview`、`classes`、`traffic` 之间同一个数相等 | `meta` 比 `calls logged probes other harness`,列表有 `title` 时也比 `title` 的 sha256(`title_sha256`,标题是有内容的数据,原文不进输出);`title_source` 不比。比较前后 `as_of` 不同 = 数据在长,该条 `skip` 带原因,不重试(主 agent 定,依据:只读检查不能让数据停下) |
| `since` | `session --since` 增量合起来等于整读 | [3.5](3.5-query-layer.md) |
| `recognition` | 各 harness 的识别覆盖,id 为 `recognition/<harness>` | 判红只看 unparsed、`unknown.records`、落进 `aux` 车道的调用;inferred、incomplete 只放进 `observed`(主 agent 定,依据:不变式 4,它们是如实标注,合成数据里本来就有) |

## 5. `scripts/board-walk.mjs`

```
node scripts/board-walk.mjs --board <file> --out <dir> [--session <id>] [--width <n>] [--height <n>] [--theme <light|dark>]
```

`--board` 是 `trocar board --json` 的输出,或 `side-board --url-file` 写的一行地址。`board --json` 的 `url` 不带口令,脚本自己读 `token_file`,口令不经过 agent,不进任何输出。用 clone 的 `playwright-core` 和系统 Chrome。

- 走 `web/src/router.ts` 的每个路由。**只按无障碍角色和通用属性走,不绑 class 名**,桌面重写后也不用改:展开每个 `[aria-expanded]`、`summary`;把每个可滚动区滚到底;把每个 `[role=separator]` 拖到两端。
- 记录:没有效果的控件、滚动后标题或关闭不在视口内、页面错误、控制台错误、失败请求、横向溢出。不判内容、版式和命名,那归 `trocar-ux` 的读者。控件在输出里叫 role 加序号(`name`,如 `button#3`),不带元素文字;页面错误与控制台错误截到 200 字符(主 agent 定,依据:它们可以带采集内容)。
- 每类动作有上限,超过的在 `skipped` 写明跳过了多少,不静默。
- 只读:拦掉所有非 GET 请求,被拦的记进 `errors.requests`。
- 输出 `<out>/walk.json` 与每屏一张 PNG。URL 里的口令绝不进输出。
- 退出 0 没发现问题,1 发现了问题,2 用法错、没有 `playwright-core` 或 Chrome,或走不下去(看板连不上、`--out` 写不了)。走不下去时不写 `walk.json`,stderr 是去掉地址与口令后的原因。

## 6. `scripts/pr-check.mjs`

```
node scripts/pr-check.mjs --before <time> --title <file> --body <file> [--base <ref>] [--accept-partial] [--cli <path>] [--json]
node scripts/pr-check.mjs --issue --before <time> [--title <file>] --body <file> [--base <ref>] [--accept-partial] [--cli <path>] [--json]
```

- `--before` 必填:agent 自己的对话也可能在被采集,它写的文字都会进采集,所以只比这个时间之前的记录。给晚了只会多拒;给早了比不到最近的采集,见「失败即拒绝」。
- `--body` 恒必填;`--title` 只在 `--issue` 时可省,评论回复没有标题(主 agent 定,依据:出站内容的定义)。
- `--base` 默认 `origin/main`,必须是 HEAD 的祖先且不等于 HEAD;`refs/remotes/origin/main` 存在时还必须等于它或是它的祖先:base 之前的提交不再被判,base 的树还要拿来豁免(§6.3),所以它只能是已经公开的提交(主 agent 定,依据:拿不准就拒绝)。不满足是一条 `base` finding,退出 1,不做 §6.3 的减法,`why` 让人 rebase 到 `origin/main` 而不是换 `--base`(主 agent 定,依据:判它要读 git,退出 2 只给读任何东西之前的错,解析不了的 ref 本来就是 1)。`--issue` 不记这条 finding:出站内容不含 git,在 `main` 上回评论时 base 就是 HEAD;但 base 不是公开的提交时同样不减。没有 `origin/main` 的仓库只判祖先。
- `--issue`:出站内容不含 git,只查标题和正文。
- `--cli <path>`:与 §4 同一份解析,给测试和退路用。
- `--accept-partial`:见「失败即拒绝」。
- 退出 0 过,1 拒绝,2 用法错(缺必填、坏时间、找不到 CLI;2 之前什么都不读)。

输出 `{ok, hash, findings:[{rule, where, why}], accepted:[{rule, where, why}], coverage:{scanned_bytes, opaque_bytes, after_bytes, total_bytes, from, to}, leaving:{files, commits, identity, branch}}`。`leaving` 是要给用户看的清单。`coverage`:`scanned_bytes` 是比到的记录的字节,解不开的记录只算进 `opaque_bytes`,`after_bytes` 是因为在 `--before` 或之后而跳过的字节(整段跳过的也算),`total_bytes` 是 `from` 早于 `--before` 的段的字节,`from` `to` 是实际比到的时间范围,也给用户看。

`hash` = 全部出站字节的 sha256,加上这次是在什么条件下判的:`--base` 解析出的 commit、`--before` 的毫秒值、用没用 `--accept-partial`、`accepted` 的 `rule` `where` `why`(排序后)、`coverage` 的 `scanned_bytes` 与 `opaque_bytes`。`--before` 固定时这两个数对写定的记录不变;`after_bytes` 和 `total_bytes` 随新记录增长,不进 hash。用户同意的是这份比对结果,第二次比到的东西少了或多放行了什么,hash 就不同,`trocar-pr` 回到让用户看的那一步。PR 模板里写 hash 的那一行不进 hash:否则写进正文 hash 就变,`trocar-pr` 的第二次比对永远不过。只认模板原句加一个 64 位十六进制值,这行写了别的字照进 hash。

**不回显**(主 agent 定,依据:D81① 与硬要求):`findings` 只有位置和规则,绝不回显匹配到的值。`where` 永远不含路径文字:`<短 sha>:file#<n>[:<行>]`,`n` 是 `leaving.files` 的下标;路径本身也是出站内容,这样路径里的值也不会经 `findings` 回显。`why` 是每条规则的常量句。

**失败即拒绝**(D81①):读 git 失败是一条 `unreadable` finding,放行不了。采集没比完是 `partial` finding(`where` 是 `capture`),有这几种:

- `trocar query` 给不出文档;
- 某段 `raw` 读不出或中断,或退出 0 却给得比 `query segments` 报的 `bytes` 少(正在写的段不比);
- `opaque_bytes` 大于 0;
- 采集里有记录,却一条也没比到:全部记录都不早于 `--before`,或比得到的段读不了;
- `after_bytes` 大于 0,且 `--before` 比现在早 7 天以上:一次改动的工作时长到不了这么久,更早的 `--before` 只会让最近的采集比不到(主 agent 定,依据:拿不准就拒绝);
- 列表答 `title_source: pending` 的行,`session --head` 也给不出标题。

全新安装没有任何采集不算:captured-* 自然为空,`coverage` 全 0,输出写明比了 0 字节。

**`--accept-partial`** 是唯一的放行,只有用户看过 `coverage` 并明确同意才用。它把 `partial` finding 移进 `accepted`,`ok` 只看 `findings`;别的规则放行不了。用没用它写进 `hash`,放行了什么写进 `accepted`。

### 6.1 规则

- **files**:新增或修改的图片、视频、PDF、压缩包、采集格式(`.ndjson`、封存段后缀、`.har`、`.pcap`)、任何 git 判为二进制的文件一律拒,按扩展名与 numstat `-` 判,截图因此发不出去。`test/fixtures/` 也不例外,合成数据在测试里生成。SVG 不算图片,走文字规则(主 agent 定,依据:harness 图标是 `.svg`,D76,一律拒会挡住加 harness),但只放行自成一体的矢量:每个碰到它的提交里,整份 SVG(不只是新增行,改名过来的也算)解过 HTML 实体后带 `data:`、任何前缀的 `<image` `<feImage` `<img`、`src=`、不指向 `#` 的 `url(` 或 `href=`,按图片拒。Git LFS 同属这条:指针文件的内容和 `.gitattributes` 新增行里的 `filter=lfs` 都拒,指针过了检查,真正上传的字节没过。`src/web/board/**` 例外:二进制只放行 HEAD 树里的那一份(blob 等于 HEAD 的),中间提交里的一律拒;改到时跑一次 `npm run test:build`,不等于重建结果就拒。`test:build` 比的是工作区,所以 `web/` 与 `src/web/board/` 在工作区里和 HEAD 有任何不同(改动、删除、未跟踪、被忽略的文件)就直接拒,不构建,重建的输入才等于要发出去的树;cwd 不是脚本自己的 clone 时不跑(`package.json` 是对方的代码,§1),直接拒,说明要在隔离环境重建。

  文字里的图片同属这条:任何出站文字里 `image/` 类型的 `data:` 地址一律拒,大小写、JSON 转义的斜杠、`\uXXXX`、HTML 实体(`&#NN;` `&#xHH;` `&colon;` `&sol;` `&Tab;` `&NewLine;`)、`data:image/` 中间夹的空白都算。一处匹配从 `data:` 到这一行的末尾,`<`、空格、引号都在匹配里,这样 §6.3 比的才是整个地址;PR 的标题和正文、评论(`--title`、`--body`,含 `--issue`)里的 Markdown 图片 `![...]` 和 `<img` 拒。提交内容里的 Markdown 图片和 `<img` 不拒,文档里引用仓库里的 SVG 是正常的。这几样走 §6.3 的豁免,改已有文档时不误伤。
- **secrets**:已知 token 形状(`sk-ant-`、`sk-`、`sk_live_`、`rk_live_`、`ghp_`、`gho_`、`ghs_`、`ghu_`、`ghr_`、`github_pat_`、`glpat-`、`AIza`、`hf_`、`npm_`、`xox?-`、`AKIA`、JWT、PEM 与 PGP 私钥头)、裸的 `Bearer <值>`、`Authorization`、`x-api-key`、`x-goog-api-key`、`Cookie`、`Set-Cookie`、`api_key`、`password` 后跟值、高熵长串(≥ 40 字符、大小写加数字混合)。在原文、解了 `\uXXXX` 与 HTML 实体的文字上跑,token 形状还在去掉换行的文字上跑。`FAKE` 独立成段的放行,前后都不是字母数字(0.1 §4),真 token 后面贴一个 `FAKE` 不算。`package-lock.json` 的 integrity 和 `src/web/board/**` 不查高熵。

  **编码过的内容**反过来解(`scripts/lib/encoded-text.mjs`,出站侧是小数据):单行 ≥ 64 字符的纯字母表串,以及连续 ≥ 3 行等宽(末行可短)、每行 ≥ 16 字符的纯字母表块,连起来按 hex、base32、base64 解码,带 gzip / zlib 魔数的再过 `decodeContent`。解出来是文字就作为派生 source 进窗口表和词比对;解不出文字的折行块算 `secrets`,hex 除外(哈希清单解出来就是噪声),单行的由高熵规则管。
- **identity**:`os.userInfo().username`、`os.hostname()`、`USER`、`LOGNAME`、`USERNAME`、`COMPUTERNAME`、`git config user.name`(作者字段本身除外);任何家目录路径形状 `/Users/<x>/`、`/home/<x>/`、`C:\Users\<x>\`(Windows 反斜杠与 JSON 转义写法都算),`<x>` 是 `me you user alice bob test runner someone` 之外的就拒;提交邮箱必须是 GitHub noreply,否则拒并给改法。
- **captured-facts**:`trocar query sessions`(全部分页)的 `project_path`、`project_slug`、`session_id`、`title`(列表答 `pending` 的行经 `session --head` 取:`pr-check` 读的是已装的 CLI,不能假定它的列表答得出);`trocar query traffic` 的 host;`trocar query segments` 的段名。记录 id 含段名,段名命中即覆盖 `<段>:<序号>` 形状。短于 4 个字符的词跳过。
- **captured-text**:出站文字(每个提交的新增行,加上 `base..HEAD` 的累计 diff 的新增行:两个提交各加一半时 HEAD 的文件里就有整段)和采集有一段**归一化后 ≥ 60 字节**的相同内容就拒,约 12 个英文词或 20 个汉字(主 agent 定,依据:字节窗口是比对的实际单位,skill 的说法跟着它)。默认扫完全部采集,经 `trocar raw <段>` 流过,不打印。只比 `ts` 早于 `--before` 的记录,`ts` 从行首取(信封第一个键),取不到就当要比(只会多拒);整段比 `--before` 新的跳过。滚动哈希,出站窗口进一张开放寻址的 typed array 表,不用 Set 逐字节查。目标吞吐 ≥ 50 MB/s。每条记录比两样:
  - 行本身。
  - 行上的文字比不到的内容(`scripts/lib/record-text.mjs`,只用读取侧现成的纯函数,不写 provider 知识):base64 的体(`req_body_b64`、`resp.raw_b64`、WebSocket 的 `{b64}` 消息;压缩的按 `req_content_encoding` 或响应头的 `content-encoding` 过 `decodeContent`,上限取推理调用的 256 MiB,不看调用类别);流式回复(`resp.kind` 是 `sse`,或 WebSocket 信封),按 `wireFormatOf` 认出的线格式过读取侧的 `normResp` 把增量拼起来,比 `text`、`thinking`、`tools`;请求体里 ≥ 64 字符的 base64 串,解出来是文字的(文本附件),和出站侧同一个函数打开,解出来不是文字的(图片)没有可比的文字,不算解不开。出错信封读 `resp.partial`。

  解不开的记录整行算 `opaque_bytes`,能比的部分照比:解压失败或超上限、`{b64, decode_error}` 与解压失败的首条消息(`wsIncompleteOf` 的 `undecoded`)、没有线格式认领的流、`content-type` 是流式(`ndjson`、`jsonl`、`stream`,`octet-stream` 除外)却没走 SSE 的回复(增量拼不起来)、不是 JSON 的行。采集里本来没有的不算解不开:`body_retention:'log'`、`{omitted_bytes}`、超上限截掉的部分。段尾没有换行的半行不是记录(§4),守护进程崩溃时会留下一行:解析不了的半行只比行文字,字节算进 `scanned_bytes`,不算解不开,半行里的 base64 不打开;解析得了的照普通记录比。
- **shape**:每提交 ≤ 400 行(不计 `package-lock.json`、`test/fixtures/`、`src/web/board/`)、有正文(只有 trailer 不算)、无 `\x00-\x08`;提交内容、提交信息、标题、正文必须是合法 UTF-8(GB18030 这类编码不比,直接拒,比支持编码省);分支里的合并提交直接拒,要求 rebase。

**读的是将要发出去的对象**:git 全程关掉替换引用(`GIT_NO_REPLACE_OBJECTS`),diff 带 `--no-relative`;提交信息和提交对象里的额外头都从 `git cat-file commit` 的字节来,`gpgsig` 只比文字、不查高熵。

### 6.2 归一化

**归一化** = 每个字符先 NFKD 再取第一个字母或数字的小写(全角、NFC 与 NFD 一处解决,组合符和谚文的中声、终声丢掉),其余丢掉;JSON 转义解掉(反斜杠串后的 `n` `t` `r` `"` `/` 跳过,`uXXXX`、`u{…}`、`xHH` 解成字符);`%HH` 解成字节再按 UTF-8 读,解不成合法 UTF-8 时 `%` 只是标点;`&#NN;` `&#xHH;` 解成字符,`&name;` 当标点。出站文字和采集过**同一个**函数(`scripts/lib/text-windows.mjs`)。

captured-facts 与 identity 的词在出站文字里也过这个函数再比子串(主 agent 定,依据:一个归一化盖住大小写、JSON 转义、`\uXXXX`、跨行、标点变体,不为每种写法写分支;这个方向多拒才是对的,§6.3 的方向相反)。家目录形状是唯一要正则的,在原文和解了 `\uXXXX` 的文字上跑。

### 6.3 通用豁免

**已经在公开仓里的就是公开的。** captured-text 的窗口先减去 base 上全部跟踪文件的窗口;identity 与 captured-facts 的命中词在 base 的跟踪文本文件的**原文**里作为整词出现过才放行:大小写不敏感,词的各段之间可隔标点,词的两端不接字母数字,二进制 blob 不算。base 里字母碰巧连成这个词(归一化后才相同)不算公开,短用户名几乎在哪都能拼出来(主 agent 定,依据:拿不准就拒绝)。files 里文字中的图片,命中的那一段原文在 base 的跟踪文本文件里逐字节出现过、后面不接字母数字就放行,不过归一化:`![x](u)` 归一化后只剩两个字母,哪里都有(主 agent 定,依据:拿不准就拒绝)。逗号后面没有内容的 `data:` 匹配只是地址的开头,不走豁免,直接拒。`--issue` 也一样:不看 git 指的是出站内容不含 git,base 能解析且满足 §6 的公开条件时照样减,否则不减,只会多拒(主 agent 定,依据:豁免是通用规则)。

### 6.4 不做

`--warn`、白名单文件、对 `partial` 之外任何规则的放行;比到一半就停的预算选项。

- 维护者侧重跑 `pr-check` 通用规则的固定做法,需要时写进 `CONTRIBUTING.md`,不做服务。

- `board-walk` 的动作集按 ARIA 角色加宽(如 `[role=tab]`),不绑某一屏。
