# trocar · RFC 1.12 — agent-native:skill set 与公开流程

> **这是什么**:用户的 agent 怎么用 trocar、怎么修 trocar、怎么把改动安全地发出去。一组随代码发版的 skill,产品里只多一个只读命令 `trocar skill`,其余机械部分是公开仓里的四个脚本:`side-board`、`contract-check`、`board-walk`、`pr-check`。
> **受众**:用户(知道自己的 agent 能做什么、哪些东西绝不会离开这台机器、哪些挡不住);agent(据此实现 `src/cli/skill.mjs` 与 `scripts/`,并按 skill 干活)。
> **决策**:D80(agent 自己能用、能修 trocar)· D81(流量审计就是一个 skill)· D82(不做 extension)· D59(读数据只有 `trocar query`)。
> **前置**:命令表、退出码、输出通道、`--json` 的形状 = [1.6](1.6-cli.md);具名查询 = [3.5](3.5-query-layer.md);看板的路由 = [1.2](1.2-shell-layout.md);看板的细节标准只住 `skills/trocar-ux/SKILL.md`([1.5](1.5-states-aesthetics.md) 指向它);段与记录 = [4.2](4.2-storage-etl.md);看板的服务面 = [4.4](4.4-server.md);进包的文件 = [4.5](4.5-distribution.md);提交规则与收尾清单 = [0.1](0.1-engineering-rules.md) §4 · §6。
> **不在这里**:skill 的正文(住 `skills/<name>/SKILL.md`,英文);`trocar skill` 的命令形状在 [1.6](1.6-cli.md) §5.6,本单元只写它和 skill set 的关系。

## Goal

一个用 trocar 的人说「trocar 这里不对劲」,他的 agent 能走完三段,不需要这个项目的任何私有工具:

1. **自己 debug**:对照契约查每个部分,出报告,问用户下一步。
2. **产出可靠代码**:在公开仓的 clone 里用合成数据写先红后绿的测试,改代码,过门禁。
3. **审查并发出去**:审 diff、查漏洞并修、脱敏,用户同意后开 PR。

硬要求只有一条:**真实会话的内容和截图绝不离开这台机器**。PR 只说功能改动。

另有两件事用同一套东西:做或审看板的一个屏(`trocar-ux`);弄清 agent 到底发了什么(`trocar-audit`)。

## 前置定义(Definitions)

- **skill set**:`skills/` 下的五份 skill,每份一个 `SKILL.md`,标准 Agent Skills 格式(front matter 写 `name`、`description`),不带 `references/` 或 `scripts/` 子目录。随代码发版,所以打印出来的永远和装着的 trocar 同一版本。skill 只写流程、命令和 spec 节的链接,不抄规则。
- **出站内容**:离开这台机器的全部字节:`base...HEAD` 每个提交的路径、新增行、提交信息、作者与提交者,分支名,PR 或 issue 的标题,正文。之后的评论回复也是出站内容。
- **公开内容**:base 上全部跟踪文件里已有的文字。已经在公开仓里的就是公开的。
- **采集**:这台机器上 `trocar query` 与 `trocar raw` 读得到的东西。没装 trocar 的贡献者没有采集。
- **数据分层**(`trocar-debug`、`trocar-pr`、`trocar-audit` 共用):

| 层 | 内容 | 规矩 |
|---|---|---|
| 无内容 | `status` `doctor` `segments` `overview` `traffic` `classes`,contract-check 的结果 | 随时读。它们也带用户名、路径和 host,不贴进出站内容 |
| 有内容 | `block`、会话标题、真实数据上的看板截图 | 只读症状涉及的部分;截图放系统临时目录,结束时删 |
| 绝不 | `trocar raw` 的输出和 `calls --reveal` 进 agent 上下文(请求头里有逐字的 OAuth token) | 比字节只比哈希,经管道,不打印 |

## Plan(选定方案 + 取舍)

**选定**(D80):产品里只多 `trocar skill`,只列出和打印,不写任何文件;放文件归用户的 agent,一条重定向就够,各家目录由 agent 自己知道。开发抽象成一组 skill,`trocar-debug` 只是入口。脱敏靠 `trocar-pr` 加 `scripts/pr-check.mjs`:「这段文字是否逐字来自真实会话」靠 agent 自觉判断不了,要拿它和采集比对,这件事只能机械地做。脚本只在 clone 里有,不是产品功能。失败即拒绝,没有覆盖开关。

**备选(未选)**:

- `trocar contribute` 产品命令:把一段只有贡献者才走的流程放进每个用户的产品里;agent 把控流程就够。
- `trocar skill add / rm`:往 agent 目录写文件,而 agent 目录的文件进上下文,等于 trocar 改了被测程序看到的东西(观察者效应);`uninstall` 还要多一条例外。
- `trocar skill show`:`trocar skill <name>` 已经是它。
- 流量异常检测器、extension 系统:见 D81 · D82。

**挡不住的,写明**:

- agent 不跑脚本,本机拦不住。这是把控权交给 agent 的代价。兜底:维护者收 PR 时重跑通用规则(文件、密钥、家目录形状、形状);PR 模板要求 agent 写的 PR 附脚本输出的 `hash`。
- 改写过的转述,逐字比对查不出。对策是 PR 正文模板里根本没有「用户当时在做什么」这一栏,`trocar-pr` 要求 agent 跑过之后再读一遍。
- 采集很大时按字节预算从新到旧扫,比不完。比到哪写进 `coverage`,不足全量时 agent 要告诉用户。
- 只留了压缩字节的响应(解压超上限,`raw_b64`)和解压失败的 WebSocket 消息(压缩帧留在 `ws_raw`,[4.6](4.6-process-collector.md) §传输与帧级记录)比不到字面,`coverage` 照算它们。HTTP 请求体不在此列,见 §6.1 captured-text。
- 维护者重跑时用的是他自己的采集,别人的 captured-* 他比不了。

## 1. skill set

| skill | 什么时候用 | 做什么 |
|---|---|---|
| `trocar-debug` | 入口:trocar 哪里不对劲 | 第一步 clone 公开仓;跑 contract-check、board-walk,读 `web/` 对照截图,出报告,问用户下一步 |
| `trocar-fix` | 确认有缺陷,要改 | 在 clone 里用合成数据写先红后绿的测试,改代码,过门禁,一次全新上下文复核 |
| `trocar-pr` | 改好了要发出去;审别人的 PR | 审 diff、查漏洞、跑 `pr-check`、给用户看、再跑一次、开 PR |
| `trocar-ux` | 做或审任何一个屏 | 看板的细节标准,唯一的家 |
| `trocar-audit` | 想知道 agent 到底发了什么 | 流量审计(D81),报告只留在对话里,不走 PR |

**`trocar-pr` 的次序**:审 diff(0.1 §6 与契约)→ 查漏洞(看板口令与 Host / Origin、只绑回环、文件权限、路径穿越、命令注入、证书与私钥、`off` 的保证、日志里的凭据;改动引入的就修;已有的漏洞停下,走 `SECURITY.md` 私下报告,不开公开 PR)→ 跑 `pr-check` → 给用户看文件清单、标题、正文、将公开的身份、`hash`,等用户明确说可以 → 再跑一次,`hash` 和用户看过的不同就回到上一步 → `gh`。GitHub 保留 PR 正文的每个历史版本,所以必须发之前就干净。审别人的 PR 时不做发布,也不在装着采集的机器上跑对方分支里的任何东西(采集里有逐字的 OAuth token):`pr-check` 用自己 main 的 clone 里那份,cwd 指向对方的 worktree(脚本的 git 走 cwd,CLI 和代码走脚本所在的 clone);对方的测试与 npm 脚本不跑,动到 `src/web/board/` 的 PR 在没有采集的隔离环境重建。

**`trocar-audit` 答五个问题**:每个 agent 的流量去了哪、这个窗口比上个窗口多了哪些 host;非模型流量发了什么、量对不对得上这个 agent 该做的事;有没有 secret 形状的东西去了不该去的 host(只数数,不打印值);钱和缓存浪费在哪;哪些看不到(盲隧道、只记日志的类别、采集失败)。每一步都问「这对一个正常工作的 agent 说得通吗」,可疑的明确指出,标明是事实还是怀疑,给出怎么核实。不打分,不下定论。只读现有查询。

## 3. `scripts/side-board.mjs`

把 clone 里的看板跑在合成或真实数据上,不碰装好的守护进程。用真 `createServer` 加 `createQueryService`。

```
node scripts/side-board.mjs --synthetic [--bytes <n>] [--board-dir <dir>] [--url-file <file>]
node scripts/side-board.mjs --real [--board-dir <dir>] [--url-file <file>]
```

- `--synthetic`:临时 HOME,demo 会话加 `scripts/gen-dataset.mjs` 的数据。
- `--real`:只读连 `~/.trocar`。侧 home 在临时目录:除 `index` 外每个顶层目录一条链接(Windows 用 junction,普通账号就能建)、每个文件一份拷贝(文件符号链接在 Windows 上要提权;拷贝中消失的文件跳过),`index` 复制(跟随链接、去掉 `ctx`),工作进程只写临时目录。真实 `~/.trocar` 下任何字节和名字不变。这份逻辑是导出的 `sideHome(realHome, dest)`,`test/query/real-session.test.mjs` 共用它。
- **两种模式都只放 GET**,其余一律 405,覆盖 `/control/*`、`/api/*`、静态面(主 agent 定,依据:0.1 §5 只读数据面;`--synthetic` 下放过 POST 也会跑真控制动词,去掉分支代码更少)。
- **起工作进程之前把 `HOME` / `USERPROFILE` 设成侧 home**(主 agent 定,依据:`trocarHome()` 读 `os.homedir()`,工作进程继承环境)。所以侧看板的采集页不是这台机器的真状态,`docs/reproduce.md` 写明。
- `--board-dir <dir>`:发这份构建(`createServer({ webDir })`)。`--url-file <file>`:把带口令的地址写进文件(`SEQ_REAL` 读它,`test/web-v2/browser/seq/real.test.mjs`),不印到别处。不给时 stdout 恰一行地址。
- Ctrl-C 收工,删临时目录,退出 0。

## 4. `scripts/contract-check.mjs`

把能机械判定的契约都判了,只读,只经 `trocar` CLI。

```
node scripts/contract-check.mjs [--json] [--sample <n>] [--cli <path>]
```

输出 `{ok, checks:[{id, part, status, expected, observed, contract}]}`,`status` 取 `pass` `fail` `skip`;不带 `--json` 是一屏文字。退出 0 全过,1 有 `fail`。**只含计数和 id,绝不含内容**。全部用不变量表达,期望值来自 spec([1.6](1.6-cli.md) §1.2 · §1.3 · §4.1 · 附录 C,[3.5](3.5-query-layer.md)),`contract` 写这条的出处。

`--cli <path>` 跑这个 CLI 而不是 clone 的,默认 `bin/trocar.mjs`(主 agent 定,依据:查已装的 trocar 是真实用途;测试的替身也走它,并替 `status` / `doctor` 作答,这两个读机器,0.1 §3 不许测试碰真 OS)。

| `part` | 查什么 | 口径 |
|---|---|---|
| `query` | 每个查询都能答,`errors[]` 列全 | C.5 |
| `json` | 每个命令 `--json` 只有一个文档,退出码符合 §1.3 | §1.2 |
| `records` | `segments` 的记录数与 `trocar raw <段>` 对得上 | 比换行结尾的行数:末尾没有换行的半行不是记录(主 agent 定,依据:[4.2](4.2-storage-etl.md) 一行一条记录,`scripts/gen-dataset.mjs` 就留这样一行);`writing` 态的段比 `>=` |
| `bytes` | `block` 的字节与原始记录哈希相等(不变式 2) | 抽样 `--sample <n>`;只比 sha256,经管道,字节不进输出;压缩的请求体先过读取侧的 `expandRequestBody` 再比 |
| `numbers` | `sessions`、`session`、`lane`、`overview`、`classes`、`traffic` 之间同一个数相等 | `meta` 比 `calls logged probes other harness`;`title` / `title_source` 不比:没有守护进程时 `sessions` 是 `pending`,`session.meta` 已有标题,C.5 允许(主 agent 定,依据 C.5)。比较前后 `as_of` 不同 = 数据在长,该条 `skip` 带原因,不重试(主 agent 定,依据:只读检查不能让数据停下) |
| `since` | `session --since` 增量合起来等于整读 | [3.5](3.5-query-layer.md) |
| `recognition` | 各 harness 的识别覆盖,id 为 `recognition/<harness>` | 判红只看 unparsed、`unknown.records`、落进 `aux` 车道的调用;inferred、incomplete 只放进 `observed`(主 agent 定,依据:不变式 4,它们是如实标注,合成数据里本来就有) |

## 5. `scripts/board-walk.mjs`

```
node scripts/board-walk.mjs --board <file> --out <dir> [--session <id>] [--width <n>] [--height <n>] [--theme <light|dark>]
```

`--board` 是 `trocar board --json` 的输出,或含 `url` 字段的文件。用 clone 的 `playwright-core` 和系统 Chrome。

- 走 `web/src/router.ts` 的每个路由。**只按无障碍角色和通用属性走,不绑 class 名**,桌面重写后也不用改:展开每个 `[aria-expanded]`、`summary`;把每个可滚动区滚到底;把每个 `[role=separator]` 拖到两端。
- 记录:没有效果的控件、滚动后标题或关闭不在视口内、页面错误、控制台错误、失败请求、横向溢出。不判内容、版式和命名,那归 `trocar-ux` 的读者。
- 每类动作有上限,超过的在 `skipped` 写明跳过了多少,不静默。
- 输出 `<out>/walk.json` 与每屏一张 PNG。URL 里的口令绝不进输出。

## 6. `scripts/pr-check.mjs`

```
node scripts/pr-check.mjs --before <time> --title <file> --body <file> [--base <ref>] [--budget <bytes>] [--json]
node scripts/pr-check.mjs --issue --before <time> [--title <file>] --body <file> [--base <ref>] [--budget <bytes>] [--json]
```

- `--before` 必填:agent 自己的对话也可能在被采集,它写的文字都会进采集,所以只比这个时间之前的记录。给晚了只会多拒,不会漏放。
- `--body` 恒必填;`--title` 只在 `--issue` 时可省,评论回复没有标题(主 agent 定,依据:出站内容的定义)。`--base` 默认 `origin/main`。`--budget` 见 captured-text。
- `--issue`:出站内容不含 git,只查标题和正文。
- 退出 0 过,1 拒绝,2 用法错(缺必填、坏时间;2 之前什么都不读)。

输出 `{ok, hash, findings:[{rule, where, why}], coverage:{scanned_bytes, total_bytes, from, to}, leaving:{files, commits, identity, branch}}`。`hash` = 全部出站字节的 sha256;`leaving` 是要给用户看的清单。

**不回显**(主 agent 定,依据:D80 与硬要求):`findings` 只有位置和规则,绝不回显匹配到的值。`where` 永远不含路径文字:`<短 sha>:file#<n>[:<行>]`,`n` 是 `leaving.files` 的下标;路径本身也是出站内容,这样路径里的值也不会经 `findings` 回显。`why` 是每条规则的常量句。

**失败即拒绝**(D80):`trocar query` 给不出文档、读 git 失败、某段 `raw` 读不出、一条压缩的请求体解不出 = 一条 finding(`why` 说读不到),不当成空。字节预算截断不算失败,只写进 `coverage`。

### 6.1 规则

- **files**:新增或修改的图片、视频、PDF、压缩包、采集格式(`.ndjson`、封存段后缀、`.har`、`.pcap`)、任何 git 判为二进制的文件一律拒,按扩展名与 numstat `-` 判,截图因此发不出去。`test/fixtures/` 也不例外,合成数据在测试里生成。`src/web/board/**` 例外:改到时跑一次 `npm run test:build`,不等于重建结果就拒;cwd 不是脚本自己的 clone 时不跑(`package.json` 是对方的代码,§1),直接拒,说明要在隔离环境重建。SVG 不算图片,走文字规则(主 agent 定,依据:harness 图标是 `.svg`,D76,一律拒会挡住加 harness;SVG 里嵌的 base64 由高熵规则挡)。
- **secrets**:已知 token 形状(`sk-ant-`、`sk-`、`ghp_`、`gho_`、`ghs_`、`xox?-`、`AKIA`、JWT、PEM 私钥头)、`Authorization:` 或 `x-api-key` 后跟值、高熵长串(≥ 40 字符、大小写加数字混合)。含 `FAKE` 的放行(0.1 §4)。`package-lock.json` 的 integrity 和 `src/web/board/**` 不查高熵。
- **identity**:`os.userInfo().username`、`os.hostname()`、`USER`、`LOGNAME`、`USERNAME`、`COMPUTERNAME`、`git config user.name`(作者字段本身除外);任何家目录路径形状 `/Users/<x>/`、`/home/<x>/`、`C:\Users\<x>\`(Windows 反斜杠与 JSON 转义写法都算),`<x>` 是 `me you user alice bob test runner someone` 之外的就拒;提交邮箱必须是 GitHub noreply,否则拒并给改法。
- **captured-facts**:`trocar query sessions`(全部分页)的 `project_path`、`project_slug`、`session_id`、`title`(`title_source` 是 `pending` 时列表还不知道标题,不等于没有:取 `trocar query session --id <id> --head` 的 `meta.title`,那里也是 `pending` 就算读不到,主 agent 定,依据 D80 失败即拒绝与 C.5);`trocar query traffic` 的 host;`trocar query segments` 的段名。记录 id 含段名,段名命中即覆盖 `<段>:<序号>` 形状。短于 4 个字符的词跳过。
- **captured-text**:出站文字和采集有一段**归一化后 ≥ 60 字节**的相同内容就拒,约 12 个英文词或 20 个汉字(主 agent 定,依据:字节窗口是比对的实际单位,skill 的说法跟着它)。采集经 `trocar raw <段>` 流过,不打印。记录把请求体存成 base64 时(`req_body_b64`,[4.6](4.6-process-collector.md) §记录),行上的文字比不到内容:同一条记录再比它背后的字节,压缩体过读取侧唯一的 `expandRequestBody`(上限取推理调用的 256 MiB,不看调用类别),没有 `req_content_encoding` 的直接比解出的 base64。解不出 = 一条 finding,不算比过(主 agent 定,依据 D80 失败即拒绝)。只比 `ts` 早于 `--before` 的记录,`ts` 从行首取(信封第一个键),取不到就当要比(只会多拒);整段比 `--before` 新的跳过;新段优先;字节预算 `--budget` 默认 2 GB,实际比到哪写进 `coverage`。滚动哈希,出站窗口进一张开放寻址的 typed array 表,不用 Set 逐字节查。目标吞吐 ≥ 50 MB/s。
- **shape**:每提交 ≤ 400 行(不计 `package-lock.json`、`test/fixtures/`、`src/web/board/`)、有正文(只有 trailer 不算)、无 `\x00-\x08`。
- **合并提交**:和父提交都不同的文件里,哪个父提交都没有的行(`git show -c`)就是这个合并新写的,解决冲突时写入的内容在此;这些行和路径走上面全部规则,行数算进 400。一行都没写的合并只有信息和作者,不要求正文(主 agent 定,依据:它的内容都已随父提交判过)。

### 6.2 归一化

**归一化** = 只留字母和数字(Unicode),小写,JSON 转义解掉(反斜杠串后的 `n` `t` `r` `"` `/` 跳过,`uXXXX` 解成字符)。出站文字和采集过**同一个**函数(`scripts/lib/text-windows.mjs`)。

captured-facts 与 identity 的词也过这个函数再比子串(主 agent 定,依据:一个归一化盖住大小写、JSON 转义、`\uXXXX`、跨行、标点变体,不为每种写法写分支)。家目录形状是唯一要正则的,在原文和解了 `\uXXXX` 的文字上跑。

### 6.3 通用豁免

**已经在公开仓里的就是公开的。** captured-text 的窗口先减去 base 上全部跟踪文件的窗口;identity 与 captured-facts 的命中词在 base 的跟踪文件里出现过就放行。`--issue` 也一样:不看 git 指的是出站内容不含 git,base 能解析时照样减,解析不了(不在仓库里)就不减,只会多拒(主 agent 定,依据:豁免是通用规则)。

### 6.4 不做

override 开关、`--warn`、白名单文件;给 `pr-check` 一个 `--cli`(拿替身就能让它什么都查不到,等于覆盖开关)。没有 trocar 采集时 captured-* 两条自然为空,`coverage` 全 0,这不是失败。`trocar` 在、但查询失败是失败。

## Extensions

- 维护者侧重跑 `pr-check` 通用规则的固定做法,需要时写进 `CONTRIBUTING.md`,不做服务。
- contract-check 的 `part` 随 spec 增长:新增的查询或命令只要 C.5 有形状,就在 `query` / `json` 里自动走到。
- `board-walk` 的动作集按 ARIA 角色加宽(如 `[role=tab]`),不绑某一屏。
