# trocar · RFC 2.4 — 资源管理器(Resource Explorer)

> **服务意图(A2)**:意图 ②(资源随每步**进出上下文** = 上下文工程的一半,承 [0.0-overview](0.0-overview.md) 对齐闸 ② = 1.3+3.3+**2.4**)为主;兼意图 ①(这一步引入了哪个文件 / 能力 = 行为线索)。它是回放骨(2.3)之外、把「一条 session 的资源生命周期」摊平到右页的横向仪器。
> **受众**:人(看某 session 里文件 / 能力 / 目录的进出、命中、evict);agent(据 [3.2](3.2-normalized-model.md) `resource_events` 渲染右页,**不碰 provider/harness 分支**)。
> **前置**:数据源 = [3.2](3.2-normalized-model.md) `resource_events` 表(由 [3.1](3.1-adapter-contract.md) `parseResources` 填、[3.5](3.5-query-layer.md) 查);内容回源 = `block_contents`/`call_blocks`(via `resource_ref`);渲染宿主 = [1.2](1.2-shell-layout.md) 右页上部;文件内容显示在 [2.6](2.6-detail-panel.md) 右下 panel;定位跳转落到 [2.3](2.3-context-window.md) 的上下文块。v2(产品看板,D18c)里:「第 N 步」的编号规则在 [1.2](1.2-shell-layout.md) §编号;界面用词以 [1.5](1.5-states-aesthetics.md) §看板词表 为准;「记录里没有资源信息」这一态在 [1.5](1.5-states-aesthetics.md) 的状态矩阵(K-21);服务端的 `resources:null` 由 [4.4](4.4-server.md) §看板 v2 需要的补充 `resources` 可为 null 给出。

## Goal
把一条 session 里所有**被观测到进出上下文的资源**(文件 / 目录 / 链接 / MCP / skill / 自动加载的 scaffold / 只被看到名字的路径)按生命周期摊在**右页**,让人一眼答:*这个 agent 到底打开过哪些文件、哪些只是「看到名字」、什么时候被 compaction 换血 evict、现在这一步哪些还 live。* 双交互:单击卡片 → 把中央看板 scrub 到它进入的那步并高亮对应块;单击文件名 / 👁 → 右下 panel 显示该资源的**逐字内容**。v0 原型的 `lifecycleNav` / `viewResource` / `renderResourceView` 已实现此设计,数据由 `extractResources` / `extractSeenPaths` 产出——本模块把它从「CC 单 harness 原型」定成「读归一化 `resource_events` 的 provider-agnostic 部件」。

v2 里这两个动作是:点资源的名字,在右下面板看它的内容;点这一行的「第 N 步读入…」,回放台跳到它读入的那一步并高亮那个块。界面不用 emoji,名字与文字见下文「v2 界面:元素与来源」。

## 前置定义(Definitions)
- **resource**:一次 call 的上下文里因 agent 动作而进入 / 驻留的外部实体——文件 / 目录 / 链接 / MCP / skill / image / document / 自动 scaffold。生命周期粒度 = `resource_events`(3.2)。
- **segment(驻留段)**:一个资源的一次 `enter → evict` 存续区间;compaction 会给所有 live 资源打 evict,之后再被引用 → 新起一段(`reinject`)。一个资源可有多段。
- **load(范围读)**:对已 resident 资源的一次带 `range` 的读(如 `Read L1–200`、`head 50`);挂在资源上,不新起段。
- **scaffold(加载态上下文)**:非 agent 显式打开、而由 harness **自动注入**的上下文(CC 的 `CLAUDE.md` / `MEMORY.md`,经 `<system-reminder>` 出现)。
- **capability(能力)**:非文件类可调用资源(MCP server / skill / image / document)。
- **only-seen name(只见其名)**:出现在**工具结果 / 散文里**、但 agent **从未 Read/Write/Edit** 的路径——**只有名字、无内容**(保真边界)。答「它真用了文件 X,还是只是瞥见了名字」。
- **默认展开的两组 · 「其他 N 项」**(v2):名录打开时只展开「读过的文件」「载入的说明文件」两组;其余四组(只见到名字、工具与能力、目录与链接、上下文压缩)收在一行「其他 N 项」里,N = 收在里面的各组条数之和(账本里出现词表没有的 `kind` 时,里面多一组「其他资源」,见 Edge cases)。组仍然都在,只是默认收起。
- **生命周期文字**(v2):每行用一句话说这个资源在播放头这一步的处境,如「第 5 步读入 · 在上下文中」「第 77 步读入 · 第 381 步压缩时移出」(数字为虚构示例)。它取代旧看板的 `live` / `✂#N` / `pend` 徽标。

## Plan(选定方案 + 取舍)
**选定**:右页一列**按 display-group 折叠**的生命周期清单;数据只读归一化 `resource_events`,**分组是渲染期对 `kind` 的投影**,状态(live/evicted/pend)是**播放头相对**实时算的。六组:「读过的文件 · 只见到名字(未读) · 载入上下文(脚手架) · 能力(skill/MCP) · 目录与链接 · 上下文重置(压缩/摘要)」(2026-10-08 审查:去 emoji 与英文)。
**备选(未选)**:① 把资源做成时间轴上的**叠加轨**(1.3)而非右页清单——轨适合「密度/命中随步变化」,但「这条 session 一共碰过哪些文件、各自哪段 live」需要一个**可扫的名录**,轨表达不了纵览;故资源在 1.3 有轨(叠加层)、在 2.4 有名录(右页),两者互补不重复。② 把 `only-seen` 混进 `files opened`——会让「看到名字」冒充「打开过」,违反保真边界;故独立成组并标「names」。③ 在部件里按工具名(`Read`/`Bash`/`mcp__`)现算资源——**需RFC 违反**:那是 harness 专属逻辑,MUST 留在 adapter `parseResources`(3.1),部件只读归一化事件(见影响面)。守卫:`test/web-v2/no-provider-branches.test.mjs`(扫描 `src/web/v2` 里的工具名字面量,见验收 #5)。
**取舍**:分组 = 渲染期对细粒度 `kind` 的**投影**(不是新增 schema 枚举),schema 保持 provider-中立的细 kind;状态播放头相对算 = 无需为每步存一份资源快照,scrub 即时反映。

**2026-10-08 修订(D18c:v2 成为产品看板)**:
- 六组都保留,数据与分组规则不变。v2 默认只展开「读过的文件」「载入的说明文件」,其余四组收进「其他 N 项」(界面细节)。
- 组名、行里的标记与按钮改用文字(英文,D58①),不用 emoji;旧看板的 `live` / `✂#N` / `pend` 徽标改为生命周期文字。
- 不显示资源大小:资源账本里没有大小字段;skill 的 `loads[].range` 是服务端写的英文说明,不是大小。
- 记录里没有资源信息的线格式(今天 openai 系线格式的 lane 给空列表):服务端给 `resources:null` + `resources_note:'no-ledger'` 后写「这个 agent 的记录里没有资源信息」;在那之前,空列表写「没有资源记录(这个 agent 可能不提供)」——空列表不等于"没有资源"(承不变式 4,[0.0](0.0-overview.md) §核心不变式)。
- 看板读的是 `src/view/analyze.mjs` 的内存账本,不是 `resource_events` 表;这个现状缺口照旧记着(见「涉及源文件与接口」末尾)。

## 右页结构与生命周期(substance)
渲染入口 `renderContextNav()` 做 **B 拆分**:「这一步的上下文」的 outline 留在看板(`#ctxnav`,见 [2.5](2.5-outline-nav.md)),「整段会话」的资源名录进右页(`#resexp`,标题「资源 · 整段会话」)。`lifecycleNav()` 生成六组,每组一个可折叠 `navGroup`(带 count)。

v2 的落点:`#ctxnav` 由 `replay/outline.mjs : renderOutline()` 写(归 [2.5](2.5-outline-nav.md)),`#resexp` 由 `replay/resources.mjs : renderResources()` 写,区名「资源 · 整个会话」;每组一个可折叠的组头(`navGroupHtml()`,带条数),后四组外面再包一层「其他 N 项」。名录读回放台锚定的那条 lane(有主对话时就是主对话)的账本:那条车道的 `lane` 回答的 `resources`、`seen`、`events`([3.5](3.5-query-layer.md) §会话读)。

**分组与来源(demo → 归一化映射;v2 文字)**:

| 组(v2 文字) | v2 默认 | 旧看板组名 | demo `kind` | 归一化 `resource_events.kind` | 看板读的字段(锚定 lane) | 每行显示(v2) |
|---|---|---|---|---|---|---|
| 读过的文件 | 展开 | 📂 files opened | `file` | `file` | `resources[kind=file]` | 相对路径 · 生命周期文字 |
| 载入的说明文件 | 展开 | 🧠 loaded context | `scaffold` | `kind='scaffold'`(D8) | `resources[kind=scaffold]` | 服务端给的名字 · 「第 N 步载入」(名字点开看逐字内容 · scaffold 是真驻留块) |
| 只见到名字 | 「其他 N 项」里 | 👁 only seen (names) | `seenFiles`(旁路) | `event='seen'`(D8) | `seenFiles[]` | 路径名字块 · 悬停「见过 K 次 · 第一次在第 N 步」(**只有名字**) |
| 工具与能力 | 「其他 N 项」里 | 🧩 capabilities | `capability` | `mcp` / `skill` / `image` / `document` | `resources[kind ∈ {skill, capability}]` | 名字 · skill 带生命周期文字,其余「第 N 步出现」(名字点开看:skill=逐字 body · MCP=工具元数据 · image/doc=回源定位) |
| 目录与链接 | 「其他 N 项」里 | 🔗 dirs & links | `dir` / `link` | `dir` / `link` | `resources[kind ∈ {dir, link}]` | 「目录」/「链接」· 路径或地址 · 「第 N 步出现」 |
| 上下文压缩 | 「其他 N 项」里 | ✂ context resets | events | `calls.compaction`(3.2/3.4) | `events[type ∈ {compaction, summarize}]` | 「第 N 步 · 压缩:X → Y 条消息」/「第 N 步 · 摘要(输出 K token)」 |

> 服务端给的是记录 id `rid`([3.5](3.5-query-layer.md) §会话读),步号经 `replay/lanes.mjs : stepRef()` 换成**lane-局部**序显示(子 agent lane 各自从 1 数)。v2 写「第 N 步」,按 [1.2](1.2-shell-layout.md) §编号:锚定 lane 是主对话时 N = 主对话里的序号 + 1;会话没有主对话时写「第 k 次调用」,不写「第 N 步」。

**播放头相对状态(files opened;v2 里工具与能力组的 skill 同样算)**:对每个文件,遍历其 segments 相对当前 `playhead`——
- **live**:存在一段 `enter ≤ playhead < evict`(未 evict 段 evict 视作 +∞)→ 绿 `live` 徽标。v2:「第 N 步读入 · 在上下文中」。
- **✂ evicted**:最后一段已在 `#N` 被 evict → `✂#N` 徽标(evict 来自 compaction,承 [3.4](3.4-session-identity.md):compaction 是同 session 换血、**不是 fork**)。v2:「第 N 步读入 · 第 M 步压缩时移出」,淡色,只有名字加删除线(生命周期那句不划);M 那一步的压缩是推测出来的(该步的压缩事件 `inferred` 为真)时加「推测」。
- **pend(未来)**:`enter > playhead`,本步还没进上下文 → `pend` 灰态;`only-seen` chip 同理标 `future`。v2:「第 N 步读入」,淡色(播放头还没到);只见到名字的名字块第一次出现在播放头之后时同样淡色。

v2 的 N 取第一段的进入步(也是定位的目标),M 取最后一段的移出步(承 Edge cases「多段驻留」)。函数是 `replay/lanes.mjs : resState()`。

状态随 scrub 实时翻转——这正是「资源随每步进出上下文」的可见化,直接喂意图 ②。

## 双交互(承 demo point 4)
每个卡片挂**两个正交 affordance**,MUST 不互相吞事件:
1. **单击卡片体 → 定位看板**:`data-navstep`(+ 可选 `data-navres`=resKey)→ `jumpToStepAndBlock(step, resKey)`:`setPlayhead(step)` 把中央看板 scrub 到资源**进入的那步**,再在 [2.3](2.3-context-window.md) 上下文窗按 `data-rk` 找到那个块、展开、滚动居中、高亮 2s。让「名录项 ↔ 回放骨里的实体块」双向锚定。
2. **单击名字或「只见到名字」的行 → panel 显示逐字内容**:`data-view`/`viewstep`/`viewlabel` → `viewResource(step, resKey, label)`:先 `setPlayhead(enter步)`(把资源 live 的那次 call 装进上下文),置 `viewPin`,`renderResourceView()` 在当前 call 的 flat 上下文里**按 resKey 找块**(fallback:按 `input.file_path` 或「块文本包含 label」匹配),把该块**逐字 bytes** 渲成 `<pre>`;右下 panel 头显「文件 <path>」与「✕ 回到调用原始数据」回退键(点 ✕ 清 `viewPin` 回到调用原始面板)。
   - **此 affordance 覆盖所有有内容可回源的组,MUST 统一(承本次需求)**:`files opened`(Read 兄弟 `tool_result` / Write·Edit `input`)、`loaded context`(scaffold = 逐字 system-reminder 块,resKey `scaffold::<label>` 由 [3.1](3.1-adapter-contract.md)/`msgResKey` 挂上)、`capabilities` 的 `skill`(逐字 SKILL.md body)与 `mcp`(该 server 上线的工具**元数据**列表)——名字皆为 `.viewname`、点击即 `viewResource`,与 `files` 同款。**MUST NOT 让同类项一部分点开预览、一部分只定位**(交互不一致 = 本次修的坑)。
   - **保真边界随内容分档(必拒隐瞒)**:MCP 预览按 per-block badge 分档——**D15 trace 逐字**(标「✓ full schemas captured verbatim」)、**旧 v0 trace 仅元数据**(标「metadata only · schema 非逐字」),不得把工具名冒充完整 schema、也不得把旧 trace 元数据冒充逐字;`image` = 不透明二进制(仅 media_type 元数据)、`document`/未驻留项在本 call 无可回源块时,`renderResourceView` MUST 落**诚实兜底**「not resolvable in this call — click the card to locate」而非静默空白或伪造内容(承不变式 4)。逐字的:`skill` body、`scaffold`、**D15 后的 tools/MCP schema**;`image` 恒不透明。

**v2 落点(2026-10-08)**:
- 两个动作各是一个按钮,都能用键盘聚焦:名字是看内容的按钮(`data-view`,读屏名「看 <名字> 的内容」,点了调 `viewResource()`),生命周期文字是定位的按钮(`data-navstep` + `data-navres`,读屏名「跳到第 N 步」,点了调 `jumpToStepAndBlock()`);行里其他空白处点了也是定位(卡片体)。`replay/resources.mjs : wireResources()` 先认 `[data-view]` 并 `stopPropagation()`,再认 `[data-navstep]`,一次点击只做一件事。旧看板的 👁 按钮去掉:名字本身就是看内容的入口。守卫:验收 #4。
- 「MUST 统一」在 v2 = 读过的文件、载入的说明文件、工具与能力三组里,每一行的名字都带 `data-view`;只见到名字、目录与链接、上下文压缩三组没有可回源的内容,只定位。守卫:验收 #4。

## 保真边界(必拒隐瞒 · 承不变式 4)
本部件展示的多处**非逐字线上真相**,MUST 就地标注:
1. **only-seen = 只有名字、无内容**:`seenFiles` 是对**工具结果 / 散文**里路径样 token 的**启发式正则抽取**(`extractSeenPaths`:须含 `/` 或已知扩展名、剥尾标点、每文本 cap、`acceptPath` 滤版本号/代码标识符/技术名)。它 **MAY 漏 MAY 误收**,且**不含文件内容**。UI MUST 标「names / 非逐字」,MUST NOT 让它冒充「打开过」或「文件内容」。
2. **resource ledger 是派生推断,非 provider 声明**:provider 不发「资源事件」;整个生命周期是 trocar **从观测到的 tool_use / result bytes 推断**的分析层(如 usage/cache 之于原始 usage)。**底层块 bytes 是逐字源真相**(回源可 diff),**这一层的 enter/evict/kind 分类是 trocar 的解释**。UI SHOULD 让人可回源核对(交互 1 的定位即回源锚)。
3. **view 面板截断**:超长内容按显示上限截断(demo `clip(…, 6000)`;上下文窗 `ctxBody` 为 20000)。截断处 MUST 显 `… (N chars total)` 之类标记 = truncated 保真边界。
4. **capability 内容分档(D15)**:MCP/tool 的 schema **D15 后逐字**(view 见完整 `input_schema`)、**旧 v0 trace 仅元数据**(demo `ctxBody`:旧 trace `description: N chars (schema text not retained)`);view 一个 capability 按 per-block badge 标 `verbatim`/`metadata`,**MUST NOT** 显空 pre 冒充完整定义、**MUST NOT** 把旧 trace 元数据冒充逐字。
5. **scaffold 路径为重建显示**:`scaffoldPath()` 把 `CLAUDE.md`/`MEMORY.md` 拼成推测的绝对路径(用 `project_path`/`project_slug`)——是**便于人识别的重建**,非线上原样字符串。

**v2 怎么标、靠什么守**:
1. 只见到名字:组名「只见到名字」+「推测」+ ⓘ(文字见上节);名字块不带 `data-view`,点了只定位,永远不打开内容。守卫:验收 #3。
2. 是 SHOULD:定位就是回源的锚,不另加元素。
3. 钉住面板的正文与上下文窗同用 `fillBody()`,20000 字符的显示剪裁与「…(共 N 字符,这里只显示前 20000)」这句标记归 [1.5](1.5-states-aesthetics.md) 的 K-07(守卫 `test/web-v2/render-verbatim.test.mjs`,[1.5](1.5-states-aesthetics.md) 验收 #3)。
4. 能力分档按 [2.3](2.3-context-window.md) 的证明规则(见上节 v2 落点)。守卫:验收 #3。
5. v2 不重建路径:显示服务端给的名字(如 `CLAUDE.md`),`scaffoldPath()` 只在旧看板。前端代码里出现 harness 约定文件名会被 `no-provider-branches.test.mjs` 的词表(`claude` 一词)拦下。守卫:验收 #5。

## Edge cases
- **多段驻留**:文件 enter→(compaction)evict→再引用 reinject。segments 多段;状态取「是否有任一段覆盖 playhead」;徽标显最后一段的 evict。v2:N 取第一段的进入步,M 取最后一段的移出步。
- **entered-earlier / evicted 不在本 call**:view 在当前 call flat 里找不到块 → panel 显「这次调用里找不到唯一对应的块——点资源卡定位它」引导用交互 1 定位。MUST NOT 静默空白。v2 文字见「双交互」的 v2 落点;这一步正文还没载入时说「还没载入」,不说「找不到」。守卫:验收 #3。
- **only-seen 洪水**:一次 grep 喷几百路径 → per-text cap(结果 80 / 散文 40)+ 折叠「▼ all N / ▲ fewer」;不让单结果淹没名录。v2:先列 40 个,「显示全部 N 个」/「收起」;服务端不设上限,所以组头的条数是确切的(依据:不变式 4;[3.5](3.5-query-layer.md) §会话读)。
- **绝对 vs 相对同文件**:同一被打开文件的绝对/相对写法去重(路径边界后缀匹配),但**同名异目录**(`src/index.js` 开、`test/index.js` 只见)MUST 保留为不同项。守卫:验收 #9。
- **capability 定位**:skill/MCP 卡片把 ledger label 反解回块 resKey(`skill: X → skill::X`、`MCP: Y → mcp::Y`)才能定位到上下文块;解不出则只 setPlayhead 不高亮。v2 不反解(那是在前端解析服务端名字的格式),只用 `resKey` 或 `kind::label`;MCP 因此只定位到步、不高亮,见「涉及源文件与接口」末尾的 v2 缺口。
- **空 session / 无资源**:六组全空 → 显「还没有资源记录」占位,不留空白右页。v2 分两种:`resources:null` →「这个 agent 的记录里没有资源信息」;空列表且没有只见到名字 →「没有资源记录(这个 agent 可能不提供)」。守卫:验收 #7。会话一次调用都没有时右页的空态归 [1.2](1.2-shell-layout.md)。
- **一个会话里有多种线格式**:同 id 的 lane 合并时,只要有一种线格式给了账本,合并结果就是列表,`null` 只在每一种都没有账本时保留(`resources` 可为 null 要改 `mergeViews()`,今天它把 `null` 并成 `[]`)。这时列表只覆盖给了账本的那部分调用,界面今天不标这一点——记为缺口,等 [3.4](3.4-session-identity.md) 按 (harness, id) 区分会话时一并处理。
- **未知 `kind`**:账本里出现词表没有的 `kind`(服务端新增了一种资源),不丢:列进「其他 N 项」里的「其他资源」,悬停给 `kind` 原值。守卫:验收 #10。

## Risk / 回滚
- 渲染是**纯函数**(`resource_events` + playhead → HTML),用固化真实 trace 回归;改分组/状态逻辑不动数据层,可独立回退到上一绿点(render gate)。v2 的 `resourcesHtml()` 同样是纯函数(锚定 lane + 播放头 → HTML),回退只动 `replay/resources.mjs` 与 `labels/replay.mjs`。
- 检出误差(only-seen 漏/误收、kind 误分)属 adapter(3.1)范畴,回滚在那边;本部件对坏数据 MUST 优雅降级(标注 + 占位),不 throw。守卫:验收 #10。
- `resources` 可为 null 只把平铺 lane 的 `[]` 改成 `null`;前端按字段在不在判断,服务端回退时界面退回「没有资源记录(这个 agent 可能不提供)」,不会报错。

## 砍掉的

| 元素 | 为什么 |
|---|---|
| 组名与行里的 emoji(📂 👁 🧠 🧩 🔗 ✂ 🗜 📁 📄)与英文组名 | 界面不用 emoji([1.5](1.5-states-aesthetics.md));组与行用文字(英文,词住 `labels/**`) |
| 看内容的 👁 按钮 | 名字本身就是看内容的按钮,不要两个入口;定位用行里的生命周期文字 |
| 英文徽标 `live` / `✂#N` / `pend` / `resident` | 改为生命周期文字 |
| 文件大小(「3.1k 字符」)与按大小排序 | 资源没有大小字段;从块里现算只在那一步正好在当前页时成立 |
| skill 的驻留大小(显示 `loads[].range`) | 那是服务端写的英文说明,不是大小字段;要看正文点名字;`loads` 是否为空仍用来判断「只看到调用」 |
| 「该适配器未提供资源账本」+ 把 `resources_note` 当文字显示 | `resources` 可为 null 后 `resources_note` 是闭集代码 `no-ledger`,文字由前端词表给 |
| 「本会话没有追踪到资源」 | 空列表不等于"没有资源";改为「没有资源记录(这个 agent 可能不提供)」 |
| 重设计稿里的「读过的文件:这个 agent 暂不提供 ⓘ」 | 换成上面两种有依据的说法 |
| 钉住态按 `input.file_path` 或 label 文字去猜块 | 只按服务端的 `resKey` 找;猜错就是把别的块冒充成资源内容 |
| 旧看板的 `scaffoldPath()` 路径重建 | 那是按一个 harness 的习惯拼出来的路径;v2 显示服务端给的名字 |
| 前端反解 `MCP: <名>` 成块键 | 在前端解析服务端名字的格式;等服务端给 `resources[].resKey`(Extensions) |

## Extensions
- **only-seen 跨 session 聚合**:把「只见其名」(`event='seen'`,D8)接入跨 session「哪些文件被瞥见但从未打开」聚合(3.5 全表)。
- 资源 **diff 视图**:相邻两步「新进 / 被 evict」的资源增量,和 cache-break(3.3)对齐看「context 换血带走了哪些文件」。
- 人工纠正被误分类/误检的资源(记为下游,非 v1)。
- 更多 harness 的 resource 语义(Codex 的文件/工具、DeepSeek 的读)照 3.1 `parseResources` 加,本部件零改动。
- 服务端给每个资源带 `resKey`(与块的 `resKey` 同一套键):MCP 能力行就能定位并看工具元数据,补上「涉及源文件与接口」末尾的 v2 缺口。
- 服务端给资源大小(读入那一刻的字节数)后,行里再显示大小、组内可按大小排序。
- 资源与上传文件的互链(不是现在)。
