# trocar · RFC 1.4 — 中央看板(★ 招牌视图)

> **服务意图(A2)**:意图 ①(看懂 agent 行为)——中央看板是 trocar **回放台的中心与骨**(首页是总览页 [1.7](1.7-overview-dashboard.md);D18c 把 D2 的「首页」改为总览页,D2 的「回放为骨 · cache 为叠加」管回放台):把某一步真正发给模型的**完整上下文逐字回放**在正中;顺带承意图 ②——这一步的前缀和缓存对比步不同时,窗口里画一条变化线说哪里变了,缓存命中的状态在步头的「缓存」按钮里(数值真相承 [3.3](3.3-cache-model.md))。它是对齐闸里 ①=1.4+[2.2](2.2-call-turn-card.md)+[2.3](2.3-context-window.md) 三模块中的**装配者**,兑现 [1.1](1.1-product-definition.md) 的 AC-1(逐字忠实)。
> **受众**:人(核对"我这一步看到的就是线上真相,不是某 SDK 抽象过的对话")+ agent(据此装配 board、按步 scrub 驱动、把叠加轨事件挂回同一时间线)。
> **前置**:装配序与块模型/保真字段承 [3.2](3.2-normalized-model.md)(`call_blocks` 顺序 · `block_contents.section/role/kind/faithfulness`);缓存的数值真相承 [3.3](3.3-cache-model.md);步头与它的按钮、缓存判定、提问卡头是 [2.2](2.2-call-turn-card.md);块级渲染部件、变化线、两个对比步、保真标的证明规则是 [2.3](2.3-context-window.md);左内嵌 outline 是 [2.5](2.5-outline-nav.md);scrub 来源(时间轴)是 [1.3](1.3-timeline-tracks.md);外壳(侧栏 · 页头 · 回放台布局)、会话头与「第 N 步」的编号是 [1.2](1.2-shell-layout.md);词表、标记与数据规则是 [1.5](1.5-states-aesthetics.md);session 导航语义承 [3.4](3.4-session-identity.md)。

## Goal

给一条 session 的**任一步**呈现一个**唯一的、忠实的上下文窗口**——回放台正中一栏,按装配序 `tools → system → messages`(界面上叫工具定义 → 系统提示 → 对话)逐字回放这一步真正送给模型的全部输入,左侧内嵌该窗口的 outline。**按步 scrub**(←/→/Home/End 或时间轴点击)即换到另一步的窗口。保真边界**就地标**在块上;这一步的前缀和缓存对比步不同时,窗口里只多一条变化线,说从哪里起变了;缓存命不命中不占窗口,放在步头的「缓存」按钮里,悬停才展开(命不命中不值得在这么紧凑的空间里占篇幅,一个悬停展开的按钮就够)。不另开"原始 JSON 对照栏"——**窗口本身就是 ground truth**(承 demo `renderContextWindow`:"no separate raw column")。

> **永久核心不变式(非 near-term 妥协)**:中央看板对**原上下文的逐字忠实呈现是本产品的立身之本**,不是过渡态优化。**AC-1**(窗口重建 = 源 bytes,`diff=0`)是**永久核心验收**;凡非逐字处 MUST 就地标保真边界(不变式 4);**tools schema 亦须逐字**(见 **D15**,不再是 metadata 例外)。测试 / 验收 / 后续 RFC / **D7 自演化**MUST 持续守住这条——任何以「够用 / near-term」为由降解忠实呈现 = **必拒**。

守卫(必拒 · test):真服务端上是 `test/web-v2/ac1-real-server.test.mjs`(验收 #7);服务端一半 `test/query/projection.test.mjs`(3.5 #22:每个定义按 `ref` 取回的字节哈希成它的 `bid`);显示一半 `test/web-v2/render-verbatim.test.mjs`(原始格的文字去掉 `.lay` 排版段之后 = 字节,[2.3](2.3-context-window.md) §两种模式);非逐字处的就地标见验收 #4。

## 前置定义(Definitions)

- **中央看板(中栏)**:回放台正中的那一栏 = 步头([2.2](2.2-call-turn-card.md))+ 当前 playhead 步的**唯一忠实上下文窗口**(`#ctxwin`);左边内嵌 outline。界面上不用「中央看板」作屏名,屏名与词见 [1.5](1.5-states-aesthetics.md) 的看板词表。
- **步 / playhead / scrub**:一步 = 主对话里的一次模型调用(「第 N 步」只数主对话,规则见 [1.2](1.2-shell-layout.md) §编号;子 agent 与后台调用叫「调用」,在调用抽屉里看,[2.6](2.6-detail-panel.md) §B);playhead = 当前停在哪步;scrub = 在时间轴上移动 playhead。scrub 是中栏的唯一驱动信号。
- **提问卡**(原 TURN):对话段里以一条**人类提问**开头、延续到下一条提问前的一组块——承载该轮的 assistant 调用(`thinking / tool_use / text`)与回答它的 `tool_result`。哪一块是人类提问由服务端认出(位置属性 `attrs.query`),前端不从正文推断。中栏把对话分组成可折叠的提问卡;卡头写什么归 [2.2](2.2-call-turn-card.md)。
- **骨 vs 叠加**:骨 = 忠实回放(承 D2);叠加 = 变化线、块上的保真标与「新」标、勾选轨带进来的定位——**叠在同一条回放上,不撕成两块屏**。缓存命中的数值不叠在窗口里,在步头的「缓存」按钮里。
- **变化线 · 缓存对比步 · 内容对比步**:定义与措辞归 [2.3](2.3-context-window.md),词见 [1.5](1.5-states-aesthetics.md) 词表。变化线对的是缓存对比步;块上的「新」对的是内容对比步。
- **保真边界(faithfulness)**:块的 `verbatim / metadata / opaque / summarized / omitted / truncated`([3.2](3.2-normalized-model.md));非 verbatim 的 MUST 就地标(承不变式 4,[0.0](0.0-overview.md) §核心不变式)。守卫:`test/web-v2/fidelity-marks.test.mjs`(归 [2.3](2.3-context-window.md),验收 #4)。

## Plan(选定方案 + 取舍)

**选定(承 D2:行为回放为骨 · cache 为叠加层 · 一条主线)**:中栏 = 步头 + **每步一个忠实上下文窗口**,`tools→system→messages` 装配序;对话按提问分组成折叠的提问卡;保真边界**内联**在块流里;前缀变了才画变化线;缓存状态在步头的按钮里;compaction 自然换掉整窗;左内嵌 outline;按步 scrub 驱动。

**备选(未选)**:
- ① **忠实窗口 + 另一栏原始 JSON 对照**——冗余且诱导"窗口是渲染稿、JSON 才是真相"的误读;demo 已否决(窗口即真相,无独立 raw 列)。
- ② **两块并列可切换的 board**(行为一块 / cache 一块)——违反 D2"一条主线承载两目的,首页不撕裂"(D18c 起这里的「首页」读作回放台);cache 是叠加不是并列主线。
- ③ **messages 拉平成一长条块列**(不分提问)——百块成墙、看不出"哪条提问触发了哪串 tool_use/result",丢掉提问卡结构。
- ④ **中栏放步骤卡 + 问题带,没变的段折成一行**(看板 v2 原型)——否决:中栏堆这么多东西没有重心,看不出要表达什么;中栏就该放整个上下文。
- ⑤ **缓存三态标内联在窗口里**(旧版的 `⚡` 标)——在紧凑的中栏里占地方;用户同日要求改成按钮悬停,窗口只在前缀变了的地方说哪里变了。

**取舍**:一条回放同时喂 ①②——想看行为读骨,想看缓存读步头的按钮,前缀变了的地方窗口里有变化线;提问卡把"墙"折成"每条提问一张卡",默认只展开最新一张,历史卡折叠但一键可开。**代价**:中栏的交互态(哪些卡展开、outline 展开、滚到哪)是 UI 局部状态,须定清 scrub 时如何演化(见下 §折叠语义、§打开一步时落在哪)。

### 中栏只放两样东西(本单元定 · MUST)

### 打开一步时落在哪(本单元定 · MUST)

playhead 换到一步,这一步的块第一次画出来时(车道未到手的,等车道到了再算,[2.3](2.3-context-window.md) §读与画),窗口 MUST 滚到变化线;没有变化线就滚到第一个带「新」的块;两者都没有就停在顶部。这一步是「跟随最新」把 playhead 带过来的(包括打开会话时落在最新一步、读者打开「跟随最新」;读者拖到某步、跳转、URL 指定的步都不算)时,MUST 改落在 ⑨「这一步的回复」:跟着最新看的人要看的是模型刚回了什么。⑨ 与 ③ 同画,不需要再往下退。落点只改滚动位置,MUST NOT 改块的顺序(装配序不变)。同一步之后的重画(跟随最新带来的新数据、展开一个块)不再滚动。落点在一张折着的提问卡里时,这一次显示把那张卡打开,但不写进 D12 的折叠记忆——那里只记用户自己的开合。守卫:`test/web-v2/ctxwin.test.mjs`(`landingTarget()` 的断言)+ `test/web-v2/browser/replay-shots.test.mjs`「turning follow latest on from an earlier step lands the window on the newest reply」(落点在换步那次重画里跑,所以「是不是跟随带来的」要在重画之前定),验收 #10。

### 装配序 · 逐字回放(骨)
窗口严格按 [3.2](3.2-normalized-model.md) `call_blocks.seq` 铺:`tools → system → messages`。每段一个段头(「工具定义」「系统提示」「对话」+ 块数;大小、「以下逐字」等其余内容归 [2.3](2.3-context-window.md),占比与估算的 token 数在步头的「组成」按钮里,[2.2](2.2-call-turn-card.md))。每块一张可折叠行(`ctxBlockHtml()`):头显 role · kind 标签 · 短预览 · 字符数(写「字符」);点开惰性画成格(`cell.mjs : cellBodyHtml()`,Raw 默认、Readable 一键之遥;字节经 `block` 按 `bid` 只取一次;长的按切片显示并写全文多少字符,两种模式、切片与措辞归 [2.3](2.3-context-window.md) §两种模式)。system/messages 的正文 MUST 是**线上原始字节**(承 AC-1);block 的 `section/role/kind` 全部读归一化字段,**board MUST NOT 按 provider 分支**(适配缝不漏进前端,需 RFC 才可破 · 承不变式 3)——跨 provider 的块渲染细节下沉到 [2.3](2.3-context-window.md)。守卫:原始字节 → `ac1-real-server.test.mjs`(验收 #7);不按 provider 分支 → `test/web-v2/no-provider-branches.test.mjs`「web/legacy outside mock/ carries no provider, tool, harness-id or host literal」+ `ac1-real-server.test.mjs` 在七个 harness 的生成集上走同一条渲染路径(验收 #6)。

### messages → 提问卡(骨的可读结构)
`messageTurns()`:一块带 `attrs.query` 的对话块开一张提问卡,延续到下一条提问;没有提问打头的前缀块归入一张「接着上一轮」卡。`attrs.query` 由服务端在抽取时填(`src/view/blockmeta.mjs : blockQuery()`,今天对所有线剥掉 `<system-reminder>` 后仍非空才算;按 harness 的规则见 [4.4](4.4-server.md) `sessions` 的 `title_source`),前端不从正文推断。卡头(「提问」标 · 提问预览 · 「调用 N 次工具 · 思考 · 工具结果」 · 「N 块」)归 [2.2](2.2-call-turn-card.md)。**默认只展开最新一张**(末张),历史卡折叠。

**折叠语义(已定 D12)**:提问卡的折叠态**按其 anchor 块 `content_hash` 记忆**(3.2 去重 / cache-break 键)——用户展/折一张卡 → 该 hash 进持久集(localStorage);**跨 scrub 存活**:渲某步时,每张卡的开合 = 查其 anchor hash(在集里则按用户态,否则默认「末张展开、余折叠」);compaction 改写上下文 → 新 hash → 该卡自然当作新的(正确)。另给「全部展开 / 全部折叠」便捷。**不靠卡的序号**(序号跨步会漂移);demo 的 `turnOpen`+`lastTurnCall` reset-on-scrub 是 v0 雏形,产品升级为 content_hash 记忆。v2 落在 `replay/fold.mjs`:键 `trocar.v2.turnfold`,最多记 2000 条,超出丢最旧的。守卫:`test/web-v2/fold.test.mjs`(验收 #2)。

### 缓存:变化线在窗口里,状态在步头(叠加,承 [3.3](3.3-cache-model.md))
数值真相取**真实 usage**、非 byte-diff 臆测(承 3.3 MUST)。守卫:[2.2](2.2-call-turn-card.md) 的缓存判定(`test/web-v2/metrics.test.mjs`、`test/web-v2/stepbar.test.mjs`)。
- 块级标(来源是归一化字段,渲染归 [2.3](2.3-context-window.md)):「缓存标记」(请求声明的缓存位置落在此块,如 Anthropic `cache_control`)、「每次都变 · 不影响缓存」(volatile 块:每次调用字节都变却不入缓存键,如 CC 的计费随机数)。
- **变化线**(代替旧的 `⚡` 三态标):这一步的前缀和缓存对比步不同(`cacheBreak.cause` 不在 `QUIET_CAUSES` 里)时,窗口在第一个变了的块之前画一条线,说从这里起和哪一步(缓存对比步)不同、原因,并标「结构估计」;别的时候不画。它的措辞、锚 `#cachebrk` 与其下可展开的移除列表归 [2.3](2.3-context-window.md)。
- **缓存状态**(复用、过期重建、服务商一侧的矛盾、失败、没有用量……)不写在窗口里,在步头的「缓存」按钮里,悬停、聚焦或点击才展开;判定顺序、措辞与 ≈ 多花归 [2.2](2.2-call-turn-card.md)。
- **保真规则(必拒违反)**:volatile 块 MUST 被变化线的位置计算跳过(`cacheBreak()` 遇 volatile 块直接 `continue`,不因随机数变字节误画变化线);缓存状态 MUST 源自 usage,MUST NOT 用纯 byte-diff 冒充边界(demo 已证 byte-diff 会撒谎)。变化线的位置是按块键比出来的,属结构估计;不显示字节偏移(服务端的 `byteOffset` 今天是 UTF-16 下标,不是字节,D17①)。守卫:`ctxwin.test.mjs`(验收 #3:只差一个 volatile 块的两步经归约(`src/view/reduce.mjs : reduce()`)得 `volatile-nonce-only`,不画变化线,volatile 块不标「新」)+ [2.2](2.2-call-turn-card.md) `metrics.test.mjs`(状态只从 usage 来)。

### 保真边界 · 就地标(叠加,承不变式 4)
每块按 [2.3](2.3-context-window.md) 的证明规则标,**MUST NOT 让人误以为看到的是完整线上真相**:证得逐字的块(`def.ref` 回到的字节的哈希就是它的 `bid`,且 `def.ff.faithfulness` 缺省或为 `verbatim`)不写字,只带 `data-ff` 与读屏文字;一段的块全部证得逐字时,段头写一次「以下逐字」;其余每块都带自己的可见标——已知的非逐字值、未知值、缺值、`unaddressable` 都算;打开后 `block` 回来的不是逐字,该块立刻补标、段头撤掉「以下逐字」。规则细节、措辞与守卫归 [2.3](2.3-context-window.md)(`test/web-v2/fidelity-marks.test.mjs`,验收 #4)。各类的含义不变:
- **tools 段保真(D15)**:新 trace **逐字**存完整 schema(`verbatim`,展开见 `input_schema`,纳入 AC-1);仅 D15 前的旧 trace 回落 `metadata`(只 `name + params + descChars`),块上可见「只有元数据」(措辞归 [2.3](2.3-context-window.md))。
- **opaque(保真边界)**:`thinking.signature`、`reasoning.encrypted_content` 等不可读密文——标 opaque,不冒充明文。
- **truncated(保真边界)**:超显示上限的长块——标出全文多少字符,提示非全文。
- **summarized(保真边界)**:compaction/客户端摘要产物(如 DeepSeek 客户端摘要)——标 summarized,区别于线上逐字。

一条调用整体的保真事实(跨记录拼接缺了前序、服务端改过上下文、请求 / 消息 / 回复没采全)在调用保真行里说一次,整窗不能回到原始字节在窗口行里说一次,不逐块重复;两行都归 [2.3](2.3-context-window.md)。调用保真行属必拒(把缺了前序的上下文显示成完整,[0.1](0.1-engineering-rules.md) §5),守卫 `fidelity-marks.test.mjs`(验收 #9)。

### compaction 自然换整窗
compaction = 同一 session 内换血(**非 fork**,承 [3.4](3.4-session-identity.md))。它使这一步的对话前缀被摘要重写 → 窗口内容自然整体不同于上一步;变化线落在第一个变了的块之前——工具定义与系统提示存活,所以它在对话段里,一般是首个对话块,压缩保留了第一条提问时会更靠后(`cacheBreak.idx`);变化线上写明对话被压缩,移除列表可展开(措辞归 [2.3](2.3-context-window.md))。中栏**无须**为 compaction 特判分支,它是回放的自然结果;不建新轴、不当 fork([1.3](1.3-timeline-tracks.md))。守卫:`ctxwin.test.mjs`(验收 #5)+ `test/view/board-compaction.test.mjs`「a compaction call names compaction as its cache-break cause on a flat lane」。

### 左内嵌 outline + 勾选叠加轨 hook
中栏左侧内嵌**本步上下文的 outline**([2.5](2.5-outline-nav.md)):工具定义 / 系统提示 / 提问各组,点击跳到窗口内对应块(必要时先展开其所在提问卡);有变化线时多一行「跳到变化处 ›」。缓存命中率不进 outline(在步头的「缓存」按钮里)。**资源生命周期(跨步)MUST NOT 挤进 outline**——它属右页资源管理器(承 demo B-split;守卫随 [2.5](2.5-outline-nav.md) 的验收 #3,v2 上落在 `test/web-v2/outline.test.mjs`)。勾选叠加轨([1.3](1.3-timeline-tracks.md))上选中一条调用的 tick → 打开调用抽屉([2.6](2.6-detail-panel.md) §B),playhead 落到时间上最近的一步(标「约」,[1.2](1.2-shell-layout.md) §路由);安全审查复核的步段由轨道按时间推断标出(推测,[2.1](2.1-track-widget.md)),窗口不为此加元素。

### 按步 scrub 驱动
唯一驱动 = playhead。`setPlayhead()` → 重渲染步头、窗口与 outline;←/→ 单步、Home/End 跳首末(焦点在输入框或列表里时不翻步,[1.2](1.2-shell-layout.md) §键盘);换步时打开的行按 `bid` 留着:还在新一步里的保持打开、不重画(窗口按 `bid` 打补丁,[2.3](2.3-context-window.md) §读与画)。scrub 是纯函数式重放(同一 playhead 同一记录 → 同一窗口),无副作用写回源。

## 一件事只说一处(MUST)

- **两个字节数写在一起,只写一次**:这一步的「内容 X · 线上 Y」是一行(两个数的区别本身要说清),原始数据面板里不再写第二遍线上字节。
- **缓存断开只说两处**:步头的结论句(带「跳到变化处」)与段尾那一行(它贴着它所说的那些块);「缓存」按钮里的命中 / 未缓存数不在中栏再铺一遍,会话级的计数只在会话信息弹出层。
- **「对比」只有一个标**:控件的当前值就是它的标签,旁边不再写一次默认值。
- 中栏之左的大纲只做导航(§左内嵌 outline):**不放任何与中栏重复的计数**(工具定义多少个、系统提示多少块、命中多少)。

**D64 的那条线**:换一步 ≤ 50 ms(从点到这一步画完,p50 与 p95 都算,会话里任何一步都算),阈值与记法在 D64 一处;换步时每个面板各有自己的渲染签名,签名没变的面板不重画;手里的车道上换步不发请求,未到手的车道按 [2.3](2.3-context-window.md) §读与画 在播放头停住之后才问;打开着的会话按自己的计时器每 1.5 s 一轮的 live-poll([4.4](4.4-server.md) §live-poll:head 一次条件读、两份尾各一次 Range)不是换步,落在换步期间也照常发(主 agent 定;依据:4.4 §live-poll 的间隔表,计时器的相位取决于上一轮的耗时,与换步无关),所以「换步不发请求」数的是这几轮以外的请求,且换步的那段时间里至少要有一轮,才验得到这一点。守卫:`test/web-v2/browser/step-perf.test.mjs`、`test/web-v2/ctxwin-patch.test.mjs`(补丁后的窗口 = 整份重画)。

## Edge cases
- **无请求的步**(被中断的调用等,`rec` 为 null):窗口显式写「这一步没有采集到请求」,非报错、非空白(承 demo)。守卫:验收 #11。
- **请求体解析不出来的步**(`unparsed`):窗口写「这一步的请求解析不出来,没有上下文可以显示;原始记录原样在盘上」,服务端的 `errMsg` 原样放进技术细节;不画三段(不能读成"模型什么都没收到")。守卫:验收 #11。
- **超大 session**:窗口只画当前步的列表,由它车道的投影归约物化出来([3.5](3.5-query-layer.md) §会话读);提问卡折叠 + 惰性正文控 DOM 量;长块按切片显示并写全文字符数([2.3](2.3-context-window.md) §两种模式)。车道未到手的步先保留已画的行,再画它自己骨架里的元数据与按组成定好大小的空框;车道按页拿着,没有「不在这一页」的步([2.3](2.3-context-window.md) §读与画)。
- **首步 cache_read>0**:跨 session 暖前缀(tools+system 跨会话字节相同),合法,不当异常:不画变化线、不算缓存断开,步头「缓存」按钮的说明带一句暖前缀说明(措辞归 [2.2](2.2-call-turn-card.md) 缓存判定,守卫 `stepbar.test.mjs`)(承 [3.3](3.3-cache-model.md))。
- **跨 scrub 折叠记忆(已定 D12)**:按提问卡 anchor `content_hash` 记忆(非序号),跨 scrub + 重载存活;compaction 新 hash → 新卡回默认态。边角:两张提问文本完全相同的卡会共享 hash → 共享折叠态(罕见,可接受;需要时用 hash+序号消歧)。
- **落点没有目标**:没有变化线、也没有「新」块(如和对比步完全一样的重试)→ 停在顶部,不猜。
- **纯自动缓存 provider(OpenAI/DeepSeek)**:无声明的缓存位置 → 「缓存标记」不出现,变化线上的「结构估计」MUST 就近注「结构参考,非真实边界」(同一行里)(承 [3.3](3.3-cache-model.md))。判据是这一步没有一个块带 `def.cc`,不按服务商名分支(不变式 3)。守卫:验收 #11。

## Risk / 回滚
中栏是**纯函数重放**(记录 + playhead → DOM),无写回源(源真相不可被 UI 覆盖 · 不变式 2)。渲染逻辑改动用 T0 / T1 跑 `ac1-real-server.test.mjs` 与 `ctxwin.test.mjs` 回归即验;折叠 / 变化线 / 落点改动可独立回退,不影响存储层。**不变式 1 红线**:中栏只渲**被观测**流量;回放里的 token 计数请求(count_tokens)是**被测 harness 自己发的、trocar 只经采集源观测**(见 [2.6](2.6-detail-panel.md) §B)。任何由 trocar **主动发起**请求(量上下文再展示等)= 必拒,MUST NOT 进 v1 中栏;窗口只经本机服务端的 `/api/session`、`/api/block` 读。守卫:收尾审查([0.1](0.1-engineering-rules.md) §6 第 1 条)。
