# trocar · RFC 1.7 — 总览页

> **服务意图(A2)**:意图 ①② 的入口,并承担 D38「采集失败在看板上看得到」:打开 trocar 第一眼就知道采集正不正常、有没有要处理的事、最近花了多少。
> **受众**:人(打开 trocar 的第一屏:采集状态、要处理的事、这段时间的用量与估价)+ agent(据此实现采集卡、事项表与统计卡,知道每个元素读哪个字段、读不到时怎么说)。
> **前置**:外壳、路由、页头规则与 agent chip 在 [1.2](1.2-shell-layout.md);词表、标记、状态矩阵、数据规则与轮询在 [1.5](1.5-states-aesthetics.md);采集页与采集记录在 [1.9](1.9-capture-page.md);缓存判定、估价与多花的算法在 [2.2](2.2-call-turn-card.md);统计与流量的具名查询在 [3.5](3.5-query-layer.md);端点在 [4.4](4.4-server.md)。决策:D14(估价)、D18c(看板 v2 成为产品看板、总览页是首页)、D24(跨会话统计走具名 SQL)、D38(采集失败不静默)、D40(保存级别与大小)。

## Goal

本单元的由来:统计性的话不出现在标题或小标题里(会干扰读者),overall 的统计结果归一个 dashboard;侧栏也不直接放「有什么报错」「有什么新闻」,这些事项归 dashboard,点 dashboard 里的事项进到相应的子页去处理。

总览页回答三个问题,一屏放下:

1. **采集正常吗?** 采集卡永远有一句话说清现状(D38②④),不留空、不靠「没有记录」让人猜。
2. **有没有要我处理的事?** 一张事项表,每条点进去就是处理它的那一页;没有未读、不推送、不能「标为已读」(Non-Goal「实时告警 / 生产监控」,D38⑦)。
3. **这段时间我的 agent 干了多少、花了多少?** 统计卡给出会话数、模型调用数、≈ 花费、主对话缓存命中、缓存断开;数字只出自具名查询(D24),写明截至哪一刻。

页头与侧栏不放这些统计或结论([1.2](1.2-shell-layout.md) 页头规则);它们只在本页的卡片里,以及回放台会话头的信息按钮里(单个会话的,[1.2](1.2-shell-layout.md))。

## 前置定义(Definitions)

- **总览页**:看板首页,侧栏第一项「总览」,路由 `#/overview`(空 hash 与 `#/` 同),见 [1.2](1.2-shell-layout.md) §路由。
- **采集卡**:总览页第一张卡。一行状态(永不留空)+ 一个链接「去采集 ›」。它是 D38④ 那句「永不留空的采集健康指示」在新信息架构里的落点(D18c 修订 D38④ 的界面落点;另一处是采集页的采集服务行,[1.9](1.9-capture-page.md))。
- **事项**(界面上叫「要处理的事」):一条可点的句子,说一件现在仍成立、需要用户去某一页处理的事,点了进对应页。事项从数据算出,不存、不记「已看过」;条件不再成立时它自己消失。
- **统计窗**:页头的 「24 小时 · 7 天 · 全部」,路由参数 `window`(默认 `24h`)。它**只管统计卡**:算的是「最后一次调用落在窗内的会话」,每个这样的会话整段计入(具名查询的口径,[3.5](3.5-query-layer.md))。事项与统计窗无关:失败只看最近 24 小时(D38⑦),其余事项是现在的状态;「只列最近 24 小时」进卡题的 ⓘ,不写成常驻行(2026-10-08 审查)。
- **截至时刻(`as_of`)**:段索引里最新一条调用的时间。统计卡带它。

## Plan(选定方案 + 取舍)

**选定**:总览页是首页,也是侧栏第一项。页面自上而下:采集卡与「要处理的事」并排 → 统计卡(含按 agent 分的表,页脚一行盘上占用)→ 最近的会话。还没采到会话时只出采集卡、各 agent 的开关与「开始使用」卡(§首次使用)。**总览上没有设置控件**(明暗归 1.11 外观),也不重复存储页与价格页的整段话(ux R1–R3)。统计只出自具名查询 `GET /api/overview`;最近的会话是一张列表,出自 `/api/sessions`,不算统计。

**备选(未选)**:
- **会话库做首页,总览只是一个页签**:侧栏不写状态之后,打开 trocar 看不到采集失败,只能从「列表是空的」去猜,违 D38②。
- **统计写进页头或副标题**(原型的「8 次运行,共 ≈ $… 起;…」):否决,统计不进标题与副标题(见 Goal)。
- **内容区顶部一条全站横条**,在采集服务停了或 trocar 挡住 agent 网络时出现:相关的东西归 dashboard;D38② 已由首页 = 总览页与采集页满足(不设横条)。
- **统计在浏览器里由 `/api/sessions` 的会话元数据加出来**:跨会话聚合按 D24 走具名查询;会话元数据里也没有用量、模型与缓存(只有调用次数)。

**取舍**:统计走具名查询的段索引,代价是它只到段索引里最新一条调用为止——统计卡写明「截至 <时刻>」,不假装实时。事项全部从现有字段算出、不存状态,代价是同一件事只要还成立就一直在表里;用每类条数上限把表压短。

**缓存断开与它的多花不在本页**:它要按相邻调用的块结构算散度点,而 `overview` 只读段索引(D59③ · [3.5](3.5-query-layer.md) §访问模式),算不出全窗的断开数。每个会话的缓存断开与多花在回放里:步头与会话头([2.2](2.2-call-turn-card.md) · [1.2](1.2-shell-layout.md)),数据出自 `session`。「最贵的会话」同理:按会话的费用排序要逐会话的用量,超出 `usage.coverage` 的覆盖就是猜,本页不写。


**估价规则**(D14,承 [2.2](2.2-call-turn-card.md) §花费):
- 所有钱数带 ≈,悬停「本地估价(用量 × 单价),不是账单」。
- 有用量的调用所在的行,模型匹配不到单价 → 这一行不计入,合计加「起」;同时计入「没有单价」的模型数。
- 某行 `no_usage > 0`(没返回用量、也没失败的调用)→ 合计加「起」。失败的调用(`failed`)没有用量、不计价,不让合计变「起」(同 [2.2](2.2-call-turn-card.md) 缓存判定第 1 条)。
- 按族键匹配的价格,悬停写「按 <键> 的单价」。
- 一个可计价的都没有 → 「≈ —」+「没有单价」,不写 `$0`。
- `usage.coverage` 没读完窗内的用量 → 所有钱数加「起」(写在数前的下限)并就地写明还差多少:文档带 `calls_read` 与 `calls_in_window` 两个数时按调用算(`calls_read < calls_in_window`,写「还有 N 次调用的用量在读,稍后刷新」),否则按会话那一对(`sessions_read < sessions_in_window`,写「读了 R / T 个会话的用量,稍后刷新」)。命中从不加「起」:窗内一部分调用算出的比例不是下限。停下的原因用话说,从不印它的码(`reason`;不变式 4 + D58②)。`sessions_read` 为 0 时 `usage.rows` 为空:≈ 花费按上条出「≈ —」、命中出「—」,不写 `$0` 或 0%,同样写明覆盖(用量旁注还没补齐时会这样,见 [3.5](3.5-query-layer.md) §访问模式)。

**没有库、库太旧、端点不在**:
- `overview` 回 `sessions.total: 0`、`usage.rows: []` → 「这段时间里没有会话」,不列一排 0。
- `overview` 端点不存在(只在它落地之前的中间提交里)→ 整张统计卡不画。
- 价表读不出 → ≈ 花费、≈ 多花 写「—」+「价表读不出」加原因类(K-29),服务端原文在技术细节;命中与断开照常。

- **MUST(D24 · 需 RFC 才放行)**:统计卡里的每个数(包括会话数与模型调用数)只出自 `overview`;不得在浏览器里用 `/api/sessions` 加总。守卫:`test/web-v2/overview.test.mjs` 「统计只出自 `overview`:源里多了会话而段索引还没追上时,统计不变,最近的会话变」。

## 验收(可跑 check)


**本模块新测 MUST 断言**(`test/web-v2/overview.test.mjs`,除非另写):

1. **采集卡永不留空**:对每种采集状态——`ok`、`failing`、`off`、`not-running`(含 `signal`)、`not-responding`、`unknown`(有原因、没原因)、`residue`、`not-installed`、端点 503、过期(假时钟跳过两个周期)、`read_errors`、没见过的 `state`——状态行非空、与「采集卡」表里的话一致、不含 `undefined` / `NaN` / `Invalid`。
2. **事项按触发出现**:每一类只在触发字段在时出现,`href` 等于「点了去」那一列;O1 同一 agent 只一条、不带 agent 的条件归 O1′;O2 由 `manifest_error` 引起时只出 O4;O4 只有 `result` 行(安装成功、没有说明)时不出,`outcome:'failed'` 时出「上次安装没成功」,`prior-value` 行不算;O5 的两种说法各有夹具;O3 的原始层组用「封存或读取出错」开头,只有 `raw.problems`、没有 24 小时内的 `raw.failures` 时不出;O9 在 `window=all` 也只看最近 24 小时,新建的库与新出现的 harness 不出;某类超过 5 条时显示 5 条 +「另有 N 条 ›」。
3. **不说假的「没有」**:采集卡状态不是 `ok` / `off` / `not-installed` 的每个夹具,事项至少一条;任一端点失败(500、断开、503)时没有「没有要处理的事」,有「… 没读到,下面可能不全」。
4. **统计窗只动统计卡**:同一组数据,路由 `window=24h` / `7d` / `all` 三次,事项列表逐字相同,统计卡的请求带对应的 `since`(`all` 不带)、数字随之变;每次改窗只多一次 `overview` 读,页头的切换在回答之前就已移到新窗,先发后到的旧窗回答不进统计卡。打开后不等任何回答,页头与各卡已画出(没回答的卡带「读取中」);慢读同时在途不超过两个。
5. **统计的算法**:在构造的 `overview` 行上,统计卡的数 = `core/metrics.mjs` 的结果;命中只算主对话行;任一主对话行 `cache_known:false` → 「N%?」;没单价的行让合计「起」并计入「没有单价」;`no_usage > 0` → 「起」;只有失败调用不「起」;覆盖不全时钱数「起」而命中不变;全无单价 → 「≈ —」;多花在 `create_null` 为 0、全部、部分三种情况分别用写缓存价、未缓存输入价、算不出;缓存断开带「结构估计」;卡里有「截至 <as_of>」;任何位置都没有用 0 顶替的未知。
6. **统计只出自 `overview`**:往源目录加一个会话、段索引还没追上:统计卡的数跟着 `overview` 的 `as_of`,不在浏览器里补算;最近的会话里出现它;`overview` `harnesses[]` 缺一个 `/api/sessions` 里有的 harness 时出覆盖说明。
8. **没有告警语义**:总览页的 DOM 里没有 `role="alert"`、`aria-live`、未读数、关闭 / 忽略按钮、角标元素;除统计窗切换、技术细节展开与读失败时的「重试」之外没有别的按钮(首次使用之外不画开关;任何时候都不画安装、重启)。
9. **只读**:挂载本页并走完一次轮询,记录到的每个请求都是 `GET`,路径都在 `/api/` 下;首次使用时只有点了开关才发 `POST /control/harness` 或 `/control/setup`。
10. **首次使用**:没有会话 → 只有采集卡、各 agent 一行(开关或 Set up)与开始使用卡;**页面上没有 Install 与 Uninstall 按钮,也没有灰掉的控件**;临时 HOME 里写入第一个会话后两个 `/api/sessions` 周期内转成正常页面(转实时本身归 1.5 的 `test/web-v2/empty-state.test.mjs`)。

## Edge cases

- **库落后于源**:统计卡写「截至 13:58」,最近的会话里却有 14:02 的会话。这是两条路(D24)的正常现象,不是错;统计卡不去「补」实时的数。
- **同一会话 id 下有几个 harness 的记录**(会话目前只按 id 区分):按 agent 分的表会把这个会话算进每个 harness,各行会话数之和可能大于总数;总数按不同的 `session_id` 算,不重复。
- **只用深链接的人**:直接打开 `#/replay/…` 的人不经过总览页;那一页的会话保真行在会话时段内有采集失败时会说(归 [1.2](1.2-shell-layout.md)),采集页也一直有。
- **采集状态过期而别的端点正常**:采集卡写「? 未刷新 · 截至 T」,事项按最后一次读成的状态算,并加「采集状态截至 T」。
- **一大批新 host**:O9 每类最多 5 条,其余折成「另有 N 条 ›」。
- **模型名为空**:那一行按没有单价算。
- **时钟**:服务端只绑环回,和浏览器在同一台机器上,O9 的「最近 24 小时」用浏览器时钟与 `traffic` 的时间比,两者同源。
- **采集关着(`off`)**:是用户自己的选择,不是事项;采集卡写「关着 · 自 T 起」。

## Risk / 回滚

- 纯呈现 + 只读端点,不碰源 NDJSON 与派生表(不变式 2)。回滚 = 默认路由改回会话库、拿掉本屏;数据无损。回滚本屏时 D38 在 v2 上只剩采集页一处落点,打开 trocar 时就看不到失败了(违 D38②),所以须同时在首页恢复一处永不留空的采集状态。
- **把查询的数当实时**:靠「截至」与第 14、15 条的两路一致测试兜底。
- **事项变成噪音**:一直成立的说明(安装说明、残留)会一直在表里。靠每类上限;上限与触发条件要改,走 grep-spec 自对照。
- **采集卡与采集页说两种话**:同一个 `captureVerdict()`;第 1 条测试与 [1.9](1.9-capture-page.md) 的 `test/web-v2/capture-page.test.mjs` 都读它。

## Extensions

- **按天的趋势**(模型调用、≈ 花费、主对话缓存命中):要一个按天分组的具名查询([3.5](3.5-query-layer.md))。
- **时长**:段索引里还没有每次调用的耗时,要先给段索引加一列,`overview` 才给得出;首字时间只在原始记录里,还没有端点。
- **事项按 agent 筛选**:事项多到上限常被触发时再做。
