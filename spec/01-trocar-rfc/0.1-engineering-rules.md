# trocar · RFC 0.1 — 工程规则

> **这是什么**:写码、写测试、提交、评审时**不允许什么**,以及每条规则靠什么兜底。PR 或设计有争议,先查这里。
> **与 0.0 的分工**:核心不变式在 [0.0](0.0-overview.md)「核心不变式」;本文是这些不变式落到工程层的推论。两处冲突以 0.0 为准,同一 PR 修本文。
> **前置**:[0.0-overview](0.0-overview.md) 决策表。架构、数据结构与管线 → [0.2](0.2-architecture-overview.md)。

等级:**必拒** > **需 RFC** > **SHOULD**。每条必拒都标了守卫:`test` = 违反会让某条测试变红;`审查` = 没有自动守卫,靠 §6 清单在收尾时逐条过。

---

## 0. 总纲

1. **数据结构先于代码**。说不清改动读写的是 [0.2 §2](0.2-architecture-overview.md) 里哪个结构,就还没想清楚。
2. **原始字节是唯一源真相**。段索引、看板载荷、缓存都能从原始记录重建,反过来不行。封存文件是 NDJSON 行字节的无损容器,随时可逐字还原、逐条 sha256 校验(D35)。(不变式 2)
3. **改包只出于操作者意图**。没有本机操作者的显式操作或显式配置的规则,trocar 原样转发,不主动发请求、不改包;每次修改 / 重发都留审计记录,原始与改后都存。(不变式 1 · D30)
4. **provider 知识只在 dissector / adapter 里**。共享层和前端不写 provider 分支;加线格式 = 加一个 dissector,加 harness = 描述符数据(`src/collector/harness/<name>.mjs`,从 [4.11](4.11-collector-model.md) §2 的原语里选,描述符里没有函数;D57⑥)+ 读取侧数据表里的一行(session 键等,在 `src/dissect/`)+ harness 注册表一行与它的图标文件(`src/off/harness-names.mjs` · `src/off/harness-icons/`,D76)。插件模板、安装目录包装、PAC 是共用的原语,不属任何 harness。(不变式 3 · D25)
5. **不知道就显示不知道**。不拿全零 usage、默认归给 CC、空态冒充「还没采集」这类合理值顶替未知。(不变式 4)
6. **碰用户机器的动作必须用户级、对称可逆**,撤销时只撤自己写的部分。(采集安全 · D22 · D39)
7. **零运行时依赖**:运行时不依赖任何第三方包;后端用 `node:http`;看板用的库全是 devDependencies,只以构建好的 `src/web/board/` 进包。(D18 · D59③ · D75)
8. **spec 先于实现**:同一 PR 里先改 spec 再改代码。

## 1. 命名

| 项 | 规则 | 例 |
|---|---|---|
| 源文件 | kebab-case `.mjs` | `door-identity.mjs` |
| 测试 | `test/<模块>/<主题>.test.mjs`,用例标题写成一句行为描述 | `test/view/provider-unknown.test.mjs` |

## 2. 代码与依赖

- Node ≥ 22(`package.json` 的 `engines`),ESM;Node 侧是纯 JS(无 TypeScript、无转译),内置模块写 `node:` 前缀。`web/src/` 是 strict 的 TypeScript(`.tsx`),只做类型检查(`npm run typecheck`),外加 ESLint 的 react-hooks 规则(`npm run lint`),由 Vite 构建(D75)。
- 仓库没有 formatter;唯一的 linter 是只管 `web/src/` 的 ESLint。各文件分号与引号风格不一:**跟随所在文件**,不做全仓格式化。SHOULD。
- 注释写「为什么」和踩过的坑(参考 `src/paths.mjs` 顶部)。改动推翻了注释里的理由,同步改注释。SHOULD。
- **一个外部事实只写一处(禁止硬编码)**。外部事实 = 绝对路径、端口、版本号、发版日期的分界、实测得来的外部形状(管道名、别的程序会读的文件名)。实测事实住在拥有它的那个模块里,并写明出处(实验室 run、官方文档);别的模块 import 它,不再抄一份。`src/off/` 只许 import `node:*` 与自己,所以两边都要的事实放在 `src/off/`,采集器去 import(例:`src/off/pem.mjs` 的 `SYSTEM_BUNDLES` 与解析 `osBundle`)。harness 的身份与展示事实(代码 id、读取侧 id、命令行别名、展示名、官方图标)同理只写在 `src/off/harness-names.mjs` 的注册表行里,图标的出处与商标归属只写在 `src/off/harness-icons/SOURCES.md`(D76);命令行、`trocar-off`、读取侧与看板都由它推导。`arch/<os>/` 下按平台各写一份的孪生逻辑,spec 本来就允许,不算重复([4.8](4.8-win-collector.md):67、[4.9](4.9-macos-collector.md) §1)。harness 的匹配规则按进程名认、不写安装路径(D51),要覆盖该 harness 的所有版本、所有 CPU 架构与所有装法,实测到的那条路径只当测试样本。某个形态用哪种证书载体(`root` · `config-key` · `wrapper` · `plugin`,D57①)也是实测事实,只写在该 harness 的描述符里(macOS / Windows 在 `proxyMode`,[4.11](4.11-collector-model.md) §2;Linux 在 `cert` 字段,D55⑥),只由带实测证据的数据 PR 改,别的模块读它。进程名、路径、键名、主机名同样只写在描述符里。**必拒** · test `test/ci/hardcode.test.mjs`(守卫 1:同一个绝对路径 / loopback 端口 / `x.y.z` 版本字面量在 `src/` 里只许出现一次,注释不计;守卫 2:harness 的进程名单只写名字,不含路径分隔符、版本号、架构;解释器名必须带参数模式,参数模式不含版本号与架构;`harness/darwin|win32` 里没有身份数据)。扫描器看不见的种类:SHOULD。
- 新增运行时依赖 = 改 D18 → **需 RFC**。前端的库与工具是 devDependencies,钉精确版本并带 lockfile(D75③);`playwright-core` 也是钉死版本的 devDependency,真浏览器测试靠 `TROCAR_PLAYWRIGHT` 显式开启。
- **依赖方向**(下层不 import 上层;前端只走 HTTP):
  - `src/capture/` 只依赖 node 内置和 `src/paths.mjs`;
  - `src/dissect/` 是叶子:只 import 自己目录、`node:*` 与 harness 注册表 `src/off/harness-names.mjs`(它什么也不 import,D76),这样看板和查询才能共用(守卫 `test/dissect/leaf.test.mjs`);
  - `src/raw/`(D35 封存器与封存文件读取)只依赖 node 内置、`src/paths.mjs` 和 `src/dissect/`;`query`、`server.mjs` 可以 import 它,`capture` 不可以;
  - `identity / model` → `query` → `server.mjs` → `src/cli/`(`bin/trocar.mjs` 只调 `src/cli/main.mjs`);`view` 用 `dissect`;`src/cli/legacy-commands.mjs`(`serve` / `etl` / `shard` / `raw` 的函数体)在这些之上,只被 `src/cli/commands.mjs` 的命令表分派;
  - `src/health/`(D38 采集健康:原因码与事件的闭集、读盘与折叠)只依赖 node 内置、`src/paths.mjs`、`src/raw/`(读封存了的 `flows/`)和 `src/off/proc.mjs`(进程的身份与是否活着:`off` 判活读的同一份,不留两份;D39);`src/collector/`、`src/cli/`、`server.mjs` 可以 import 它。它不是 D24 的两条数据路径之一(不读信封、不跑 SQL),只读采集运行元数据;
  - `src/collector/` 可以 import `src/raw/closed.mjs`(记录存储换日时 `markClosed`,4.6 §日志体积预算「已关闭」),`src/raw/` 不 import 它;
  - `web/` 只 import `web/` 里的文件、devDependencies 里的库,以及在 `src/` 内 import 闭合、不 import 任何 `node:*` 的 `src/` 模块(它们被打包进构建产物,[4.4](4.4-server.md) §静态面);`web/` 下 Vitest 收的组件测试(`*.test.tsx`,D75④)不进构建产物,不受这一条约束,只要求每个相对说明符解析到存在的文件(与 `test/web-v2/` 相同),所以可以 import `test/` 下的夹具;`web/legacy/` 不 import 任何 npm 包;`src/` 从不 import `web/`(test `test/web-v2/imports.test.mjs`);
  - `src/off/`(`trocar off` 的撤销,D39⑤)只 import `node:*` 与它自己目录里的文件,好生成只用内置模块的独立副本 `~/.trocar/bin/trocar-off`;`src/collector/`、`src/cli/` 可以 import 它(`src/health/` 只取 `proc.mjs`,见上条),它不 import 任何别的 src 模块。本条守卫:test `test/off/imports.test.mjs`(源码)、`test/off/standalone.test.mjs`(生成的副本,[1.6](1.6-cli.md) V11);
  - `src/collector/` 里的 `core/` · `arch/<os>/` · `harness/` 三分([4.6](4.6-process-collector.md) §结构):test `test/collector/layering.test.mjs`;`arch/`、`harness/` 之外只有两个入口可以 import 它们 —— 接线的 `daemon.mjs` 和只读命令用的小入口 `net-deps.mjs`(4.8 W39);`src/netenv/`(只读探测本机网络环境,[4.7](4.7-netenv.md))不 import `arch/` 与 `harness/`,`core/` 里的纯模块(如 `core/codes.mjs`、`core/config-read.mjs`)可读(同一个 test)。
  其余依赖方向的守卫:审查。
- **现存偏离**(已知债,新代码不要加深):`view/reduce.mjs` 的 Anthropic 路径(`foldOf` 按 `fmt === 'anthropic'` 选 `anthropicFold()`,不走注册表的 `BOARD` 表)还留着 anthropic 字面,与 D25「共享层零 provider 分支」不符。

## 3. 测试

- 入口 `npm test`。主线要求 0 失败;等待实现的红灯 / `todo` 测试不进 `main`(§4「`main` 里不留 TODO」)。
- 另两个入口(D75③④):`npm run test:web`(Vitest + Testing Library,只收 `web/` 下的 `*.test.tsx`,测组件契约)· `npm run test:build`(`test/web/board-build.test.mjs`,由 `TROCAR_BUILD_CHECK=1` 开启:把 `web/` 重建到临时目录,与入库的 `src/web/board/` 逐文件逐字节比对)。两者都要 devDependencies;平常的 `npm test` 不要,没开 `TROCAR_BUILD_CHECK` 时构建检查写明原因跳过。
- **测试必须能变红**。读到零条记录也打勾的检查等于没检查。新断言 SHOULD 先拿坏输入确认它会红。
- **不碰真实机器**:信任库操作走注入的 runner;涉及 HOME 的用例在 `test/helpers/tmp.mjs` 的 `tmpDir()` 沙箱里跑。**必拒** · test `test/helpers/no-real-os.test.mjs`。**自动守卫**:`npm test` 预载 `test/helpers/no-real-os.cjs`,真的 `launchctl` / `systemctl` / `security` / `certutil` / `loginctl` / `reg.exe` / `defaults` / `csc.exe`,以及 trocar 自己的原生部件与脚本 `trocar-sign-helper` / `procenv` / `custody.ps1`(D57;经 `node:child_process` 或 `src/off/exec.mjs`)在测试进程里一律抛 `ESANDBOX`,桩只能放在临时目录里;被调用方吞掉的拒绝让进程退出 1(`test/helpers/no-real-os.test.mjs`)。
- **夹具是已采原始字节**:`test/fixtures/*.ndjson` 不许手改;要新形状就加夹具,或用 `samples/gen-demo-capture.mjs` 生成。**必拒** · 审查。
- **渲染测试要覆盖产品 D10 信封**,不能只喂 v0 夹具。2026-07-20 审计里「GUI 没接上后端」那一类缺陷,根因就是渲染测试只跑旧夹具。test `test/view/envelope-drift.test.mjs`。
- 实现 spec 覆盖的行为时,把该单元「验收」清单逐条变成待办:落断言 / 指认已有测试 / `N/A + 理由`,三选一。

### 好测试的标准

新测试按这八条写,旧测试遇到再改。

| # | 标准 |
|---|---|
| G1 | **断言用户可观测的结果**:文件字节、退出码、记录内容、对外协议字段。不断言到达结果的路径(调用顺序、实现结构、模块导入),这样重构不会让它变红。 |
| G2 | **输入沿领域的变化轴生成,断言不变量。** 变化轴:版本、架构、安装前缀、大小写、含空格或中文的路径、CRLF、已有用户配置、已有代理。不变量:往返一致、幂等、只碰允许的键、`off` 之后字节相同。 |
| G3 | **替身与真实对端共享一份契约,双向对账**:同一组契约断言既对 fake 跑也对 real 跑。平台模拟只许用真实平台会出现的形状。 |
| G4 | **期望值来自独立来源**:spec、真实采集的字节、手算。不来自被测代码,也不来自另一份实现(旧实现同样不行)。 |
| G5 | **错误路径断言「用户能自救」**:有稳定的原因码或退出码,有填好实际值的修复命令。不要求逐字措辞。 |
| G6 | **外部世界的事实**(路径、版本、端口、产品清单)放在带出处的数据里(见 §2)。测试验证「规则覆盖这一类」,并用生成的变体验证外推;实测样本只当回归种子。 |
| G7 | **在任何干净 checkout 上都能跑。** 依赖私有夹具、浏览器或 VM 的断言,要么有公开的合成替代,要么在门禁里显式报缺口。skip 不算绿。 |
| G8 | **单位价值的成本低**:失败时一屏内能定位;一次无害重构最多让一处变红;不测死代码,不测文档排版。 |

### 约定

等级沿用本文开头:**必拒** 都点名了守卫,其余 SHOULD。

| # | 约定 | 等级 | 守卫 |
|---|---|---|---|
| 1 | 机器输出带原因码而非自然语言;测试对人话只断言其中的实体(路径、名字、数字) | SHOULD | — |
| 2 | 每个 fake 配一套契约测试,同一组断言对 fake 与 real 各跑一遍 | 必拒(只管新增的 fake;现有的 `fakeDaemon` 等是已知债) | 审查 §6 第 13 条 |
| 3 | 平台模拟只用真实平台会产出的形状;读者在一个点上校验形状 | 必拒 | test `test/off/win32-control.test.mjs`(win32 的 `control.json` 必须是命名管道,`off` 拒绝别的形状)· 审查 §6 第 14 条。原计划的扫描「win32 测试不许出现 unix socket」因噪声太大放弃,换成这一处单点形状校验 |
| 4 | 测试走公开入口;不加只为测试的导出 | SHOULD | 审查(§6 第 16 条)(计数守卫已有意删掉:它因计数而红、不因行为而红;没有守卫的规则不贴必拒) |
| 5 | 调用序列 / 命令串的 `deepEqual` 只用在顺序本身是契约的地方,并注明 spec 出处 | SHOULD | — |
| 6 | 外部事实按 §2 处理;测试对各种形态应当生成变体 | 匹配规则必拒;变体生成器 SHOULD | test `test/ci/hardcode.test.mjs` 守卫 1–2 |
| 7 | 不钉计数、不在测试里重述列表 | 新增的计数钉必拒;重述列表 SHOULD | test `test/ci/hardcode.test.mjs` 守卫 3(名单内的文件只许缩减) |
| 8 | 关键不变量用枚举、生成式或蜕变式断言 | SHOULD | — |
| 9 | 不测死代码;从产品入口不可达的模块不许存在 | 必拒 | test `test/ci/reachable.test.mjs` |
| 10 | skip 不算绿:`npm test` 报出的 skip 要在 PR 正文里按原因列出 | SHOULD | — |
| 11 | 重构提交不改期望值;确要改,说明为什么该断言是契约 | 必拒 | 审查 §6 第 12 条 |
| 12 | 按接缝定期做变异抽查 | SHOULD | — |

开关的通用契约测试(D48)在 [4.6](4.6-process-collector.md) S14–S16 与 [4.11](4.11-collector-model.md) CM15 / CM32 里规定;macOS / Windows 的单元层是 `test/collector/contract/switch-contract.test.mjs`(按描述符生成)；整机跑法不属于本仓的单元测试,其中残留的判定固定只在一处做(配合 §5「治残留而不判失败」)。

## 4. 提交与变更规则

**分支生命周期**(按顺序):

1. **在仓库外的 worktree 里开分支**(如 `<outside-the-checkout>/<task>`)。不在主 checkout 上开发:那里可能有在跑的采集和不入库的本地数据。
2. 只在该分支上开发。每完成一个可独立验证的积木就 commit,失败回退到上一个绿点。
3. **三道门都过**:`npm test`(单元,全新 HOME:`HOME=$(mktemp -d) npm test`;加 `npm run test:web` 与 `npm run test:build`)· 回归(bug 修复带一条复现它的测试)· 整机 E2E(采集器在测试机上跑,看板走浏览器)。命令与结果(过 / 败 / 跳过与理由)写进 PR 正文。
4. 自审 diff;非小改动再请一个没有本分支上下文的人按 §6 审。写的人不给自己打分。
5. 开 PR:正文必填,写清改了什么、为什么、怎么验证的。
6. **合入只由人执行**:写代码的一方不自合、不直推 `main`;推功能分支,push ≠ merge。依赖还没合入的 PR 时可以在它的分支上叠加:PR 正文第一行写「先合 #N」,合入顺序写清楚,上一个合入后核对下一个的 base 已转成 `main`。
7. 合入后删掉源分支和 worktree。

- **测试门在本机跑**:`npm test`(单元,用全新的 HOME:`HOME=$(mktemp -d) npm test`;加 `npm run test:web` 与 `npm run test:build`)· 回归(bug 修复带一条复现它的测试)· 整机 E2E(采集器在测试机上跑,看板走浏览器)。命令与结果(过 / 败 / 跳过与理由)写进 PR 正文。
- **每个提交 ≤ 400 行**(不计 `package-lock.json`、新增夹具与构建产物 `src/web/board/`;构建产物在最后一个改动 `web/` 的提交之后单独一个提交重建,那里的冲突一律重新构建解决,从不手改),且能单独验证;一组相关改动合成一个 PR。单个文件或单份文档拆不到 400 行内时,在 PR 说明里写明理由。
- **每个 PR 带测试**;bug 修复必须带回归测试。只改文档的 PR 除外。
- **`main` 里不留 TODO**:要么做完,要么属于设计未定——写进对应 spec 单元的 OPEN 段落。
- 改 [0.2 §2](0.2-architecture-overview.md) 列出的任何数据结构(信封字段、段索引列、block 词表、看板载荷字段)都是 structural 变更:先按 §6 第 17 条做 grep-spec 自对照,并在 PR 正文里单独点出。从 0.1.0 起,改 `~/.trocar` 下的状态格式(安装记录、`ingress.json`、`state.json`、`classes.json`、`update.json`、原始段)同样是 structural 变更,而且新版本的 `install` / `update` 要认旧格式(D67④)。

## 6. 收尾审查清单

没有自动守卫的规则都落在这里。收尾时逐条给「过 / 不过 / N/A」(编号稳定,别处按号引用):

1. 有没有不经操作者意图就发请求或改包的路径;修改 / 重发是否都留了审计记录,原始与改后是否都存。
2. 采集端有没有加 session 或 provider 逻辑。
3. 读取失败有没有被折叠成空结果;未知有没有被合理值顶替。跨记录拼接的 call 缺前序记录时是否标 `partial`;采集引起的客户端行为变化是否标 `observer_effect`(D37)。
4. 碰用户机器的动作是否用户级、对称可逆、只撤自己写的部分。要 root / 管理员的项按项标明、由操作系统的提权提示去做,不要 root 的项绝不用 root 做(D53);macOS / Windows 上 `install`、`on`、`off`、`uninstall` 都没有要管理员的项(D57)。Linux 的能力助手(D36):一次 sudo 安装、可对称移除、不持有任何用户状态;只对调用者 uid 的进程生效(uid 取自 `getuid()`,不收调用者给的 uid)、只装内嵌的 BPF 对象。**证书(D55 · D57)**:只由 `install` 装、`uninstall` 撤,`on` / `off` 不碰;根每台机器自己生成,CN 与旧 MITM CA 不同、不读写旧 `~/.trocar/ca`;只装进用户级信任库这一项、按指纹认,从不写机器级信任库。**密钥保管**:macOS / Windows 的根私钥不在盘上、不能导出(macOS 登录钥匙串 + 签名助手,Windows 不可导出的 CNG 密钥),中间证书的私钥只在内存;Linux 的私钥在 `~/.trocar/collector/ca/`、0600。**证书载体**([4.11](4.11-collector-model.md) §2):每个形态只走描述符写明的载体;用户已让设置指向自己的文件时只在文件末尾追加带标记的一段,设置本身不动,包管理器或系统的文件不碰;替换语义的设置只指向该 harness 自己的合并包,合并包只取用户 CA 文件里的证书块(私钥等别的块不进 `~/.trocar`);登录环境不加任何变量(`environment.d`、rc 里的 `export`、`launchctl setenv`、`HKCU\Environment`;唯一保留 Linux 上 Kimi 的 rc PATH 一行),不用 `NODE_OPTIONS`、`SSL_CERT_DIR`、全局 `SSL_CERT_FILE`。**安装目录包装**:只放在用户自己目录里的单个原生可执行文件上;没有开关文件时参数、输入输出、退出码与真程序一字不差;`uninstall` 时哈希还是 trocar 的才放回真程序。**钩子**(包装、DeepSeek 插件、OpenCode 路由插件):不读不改请求和响应的字节、除了门不连别处、不写 agent 配置;没有开关文件时除了加根之外与没有 trocar 相同;加不上根时不交给门。**标记**:macOS / Windows 不用按 pid 的信任标记([4.11](4.11-collector-model.md) §3 ⑦);Linux 的插件只在加上了 CA 时写 pid 标记,引擎读标记时核对启动时间。**开关文件**只在 `~/.trocar/collector/switch/` 下,每个 harness 一个,0600。能写注释的入口是否带哨兵注释;安装前是否列出每个要改的文件;安装清单是否先写后改、每个文件一条日志、不内嵌用户文件内容;用户文件的改前副本只在 `~/.trocar/backup/`(目录 0700、文件 0600,`.env` 里有 API key)、验证还原后删(D39③);引擎是否只终结取自该进程自己代理配置的 `https://` 代理的外层 TLS、别的代理 host 透传(操作者显式选 `all` 的进程除外);宿主进程树里不是 agent 的连接只转发;不经信任路径的连接是否透传;卸载是否按倒序撤(Linux 见 [4.6](4.6-process-collector.md) 的五步,macOS / Windows 见 [4.11](4.11-collector-model.md) §1)、有没有整文件回滚、有没有重启进程。Linux 另核对:Kimi 的 shim 目录只有 `kimi`;判活只看清单与 `/proc`;dsh 的 patch 文件、shell rc 也按「撤一个文件的规则」撤。新采集器不往任何 VPN 软件里写。
