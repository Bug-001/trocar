# trocar · RFC 3.3 — cache 抽象(★ 两层模型)

> **服务意图(A2)**:意图 ② —— 看懂 agent 的上下文/缓存工程;跨 provider 对比三家 cache 设计。
> **受众**:人(核对这抽象够不够表达三家)+ agent(据此算 [3.2](3.2-normalized-model.md) 的 `cache_events`)。
> **前置**:provider cache 事实见 [3.2](3.2-normalized-model.md) 映射表;数值真相 = 真实 response usage,非臆测。

## Goal
一个 cache 模型,**用真实 usage** 表达三种截然不同的 cache 设计:Anthropic 显式断点、OpenAI 自动前缀、DeepSeek 自动磁盘——放进同一个叠加层,让人横向对比。

## Plan(选定方案 + 取舍）
**选定:两层。**
- **Tier 1 · 通用且权威**:每 call 从 canonical `usage` 得 `{cache_read, cache_write, input_uncached}` + `hit_ratio = cache_read/total_input`。三家都有,**这是叠加层的数值真相**。
- **Tier 2 · provider 能力(“在哪/为什么”)**:
  - Anthropic:**声明的 `cache_control` 断点位置**(真实,来自线上)→ `declared_breakpoints`;`break_kind=explicit-breakpoint`。
  - OpenAI:无声明断点;记 `prompt_cache_key`(路由提示);`break_kind=automatic-prefix`。
  - DeepSeek:无任何声明;`break_kind=automatic-disk`。
  - 三者都可选附 **trocar 结构性散度**(`structural_divergence_seq` = 相对上一 call 首个不同块),但 **MUST 标为"结构参考,非真实边界"**。

**备选(未选)**:① 只 Tier 1(纯 usage 数字)——丢掉 Anthropic 真实断点这一独有信息、也没法解释"为什么这步没命中";② 纯结构 byte-diff 定断点——会**撒谎**(billing nonce 每 call 变 bytes 却 100% 命中;TTL 过期时 bytes 相同却 read=0)。
**取舍**:Tier 1 保证跨 provider 数值真相;Tier 2 在 provider 真声明处给"在哪断",在自动缓存处诚实降级为"结构参考"。

## 真相规则（MUST）
- **数值取真实 usage,不 byte-diff 臆测**。
- 跳过 `volatile` 块(如 CC 的 billing nonce)——bytes 变但不入 cache key。
- `cache_read>0` → 前缀真复用;`cache_read=0` 但结构前缀相同 → **缓存条目 TTL 过期、被重建**(`cache_write>0`),不是"没缓存"。
- 自动缓存(OpenAI/DeepSeek)的结构散度**非权威**:真实边界受路由(`prompt_cache_key`)、量化(1024/128)、非确定性(DeepSeek best-effort)影响;UI 就近标注。

## 前缀分叉定位（★ D17① · 深化 `structural_divergence_seq`）

把 Tier 2 的散度从「前缀在**哪**断」推到「**哪个块 / 哪个字节**断了 + 是不是你的锅」。兑现研究痛点 #2(最密簇 ~7/33、最锋利楔子):SDK 回 200、看得到没命中却永远不知道**哪个块/字节**断了共享前缀——现有工具只复述 provider 报的 cached-token 计数,无人 byte-diff 请求 N vs N-1。全程**离线派生于已采集字节**(不变式 1),复用 [3.2](3.2-normalized-model.md) 的 `content_hash` 去重与 `volatile` 标记(`src/cache/cache-events.mjs : divergence()`)。

**定位算法(over 3.2 去重,权威定义)**:对**同 lane 相邻**两个 `class='llm'` call(N−1、N),按 `call_blocks.seq` 取各自 `content_hash` 序列,逐位比较、**跳过 `volatile` 块**:
- 首个 `content_hash` 不同、且**非 volatile** 的位 = `structural_divergence_seq`——cache 相关的真分叉点。
- 首个 `content_hash` 不同(**不跳** volatile)的位 = `raw_divergence_seq`——`raw < structural` ⇔ 一个 cache-无关块(如 CC billing nonce)先变了但被正确排除,用于「为何这个先变的块不算断点」注释。
- 无真分叉 ⇒ `structural = min(prevLen,curLen)`(纯 append,新内容是追加的尾)。
- **块内字节定位**:对首个真分叉块,经 `text_ref` 取其与 N−1 同位块的**逐字源字节**(回 NDJSON,**非 `preview`**)做字节 diff,给首个不同字节偏移 `divergence_byte_offset` + 短上下文——回答「整块换了,还是块内一个 JSON key 重排 / 一个 id 变了」。整块新增或首 call ⇒ NULL。

**保真标注(不变式 4)**:`structural_divergence_seq`、`raw_divergence_seq`、`divergence_byte_offset` 皆为**结构估计**,MUST 就近标「结构参考,非 provider 真实 cache 边界」(承本文件真相规则)。数值命中率仍取真实 usage;结构与数值冲突时 usage 优先。

## 分叉成因分类（cause taxonomy · D17①「为什么 + 是不是你的锅」）

定位到「哪个块/字节」后,据**只读判据**归因,落 `cache_events.divergence_cause`,附归属与 `fix_hint`——这是 trocar 独占的锋利面(别的工具只给命中率数字),也让下游 debugger-agent 能自动点名 root-cause。

| divergence_cause | 判据(可跑) | 归属 | fix_hint |
|---|---|---|---|
| `append` | 无真分叉(structural=prev 块数),前缀 hash 全等 | 预期无害 | 无(正常轮次) |
| `volatile-nonce-only` | `raw < structural` 且真分叉落在尾部(先变块 `volatile`) | provider 排除 · 无害 | 确认该块确被排出 cache key(标 `volatile`) |
| `compaction` | **`calls.compaction=true`(analyze 的消息数骤降判据)= 权威** | harness(你) | compaction 必废前缀;评估触发阈值/时机 |
| `tool-array-reorder` | 分叉块 `section=tools` 且集合相同、序不同 | 你的锅 · 可修 | 固定 tools 数组序(消除非确定性) |
| `json-key-reorder` | 块结构规范化(键序无关)后相同、原始字节序不同 | 你的锅 · 可修 | 稳定序列化 JSON key 序 |
| `content-changed` | 共享前缀内某块**就地**变了(非上列任一) | 复核 | 查在位编辑 / 非确定性序列化;**也是"首个 message 块变但非 compaction"的归宿** |
| `breakpoint-out-of-window` | Anthropic:`declared_breakpoints` 位置 > structural,或一轮 >N 块把断点挤出可缓存窗 | 你的锅 · 可修 | 收敛单轮块数 / 重放断点位置 |
| `mid-turn-retry` | 同 seq 位重复 call + `error`/`stop_reason` 提示重试 | harness/网络 | 幂等重试、避免前缀漂移 |
| `model-or-route-change` | `model` 变 / OpenAI `prompt_cache_key` 变 | 你的锅 · 配置 | 固定路由键;换模型自然重建 |
| `unknown` | 以上皆不匹配 | 待定 | 落 `extra` 待自演化(D7) |

**compaction 判据**:「首个 `messages` 块 hash 变而 tools+system 全等」这一结构启发式在真实 CC session 上会误报(CC 往首个 user 轮**重注入 scaffolding**、fork 等都会改首个 message 却非 compaction)。故 compaction 判据 MUST 以 **`calls.compaction`(消息数骤降)为权威**;裸「首个 message 块变」→ `content-changed`(结构定位仍给 `divergence_byte_offset`)。`cacheBreak(prev,cur,{compaction})` 把 analyze 的 drop 判定作 hint 传入即此意。

**判定归属**:`append` / `volatile-nonce-only` / `compaction`(经 hint) / `tool-array-reorder` / `json-key-reorder` / `content-changed` 纯从相邻两 flat 块序 + `calls.compaction` 可判。`breakpoint-out-of-window` / `mid-turn-retry` / `model-or-route-change` 依赖 provider 断点规则 / 错误 / 模型字段,判定逻辑属 adapter([3.1](3.1-adapter-contract.md)),由 adapter 传入 `causeOverride`(只细化 `content-changed`,不覆盖具体成因)。

**保真标注(不变式 4)**:`divergence_cause` 是**结构推断**,MUST 标「推断成因」;判「无害」(`append`/`volatile-nonce-only`)MUST 有真实 usage 佐证(`cache_read>0`);结构判据与 usage 冲突时 **usage 优先**。

## 地面真相验证（★ D17④ · 独立字节真相护城河）

**主张**:trocar 逐字捕获出站 bytes ⇒ 能**独立于 provider 自报 usage** 证明「本 call 的 cache-相关前缀与上一 call **逐字一致**」。产品判据 = 两 call 的 `prefix_sha256`(前缀逐字源字节 SHA256、跳 `volatile`)在较短前缀处相等。有了这个独立真相,读到 `cache_read=0` 时可交叉判定:

| ground_truth_flag | 判据(有可复用前缀 idx>0 时) | 语义 |
|---|---|---|
| NULL | `cache_read>0` | 前缀真复用,正常 |
| `ttl-rebuild` | `cache_read=0 & cache_write>0`,前缀逐字一致 | 缓存条目 TTL 过期、被重建——**非**矛盾(承本文件真相规则) |
| `provider-contradiction` | `cache_read=0 & cache_write=0/NULL`,前缀逐字一致 | 可复用前缀**既没读也没写** ⇒ 疑点在 provider 侧(误缓存/误计费,研究痛点 #9) |

**两种「真相」的严格措辞(不变式 4,MUST 如此、MUST NOT 越权)**:`prefix_sha256` 是**逐字字节事实**(权威、可独立复算),它证明的是「**我的出站前缀**逐字一致」;它**不**声称「provider 真的缓存了这段」(provider 内部仍黑箱)。故 `provider-contradiction` 的语义严格是「**我的出站字节无可指摘 ⇒ 疑点在 provider 侧**」,UI/报告 MUST 如此措辞,**MUST NOT 反过来断言「provider 一定错」**。数值真相仍 = 真实 usage。**不自动重发(不变式 1)**:只对已采出站字节做 hash 比对,绝不为验证而重发。

**实现判据**:`prefix_sha256` MUST 是对 NDJSON 逐字源字节切片的真 SHA256(`prefixSha256`,在 `src/cache/cache-events.mjs` 里算),不得用相邻 call 的 `content_hash` 序列代替——那样退化为 hash-of-hashes、失去「独立地面真相」资格;拿不到逐字字节切片时,marker 就近标 `结构估计(独立字节校验见 prefix_sha256)`。看板上「可复用前缀逐字一致」的标(`prefixByteIdentical` → `gt`)在 [0, idx) 上逐位比较每块**逐字源切片**(`def.ref` 回到的字节)切掉 `cache_control` 成员后的 SHA-256:`cache_control` 成员连同它一侧的分隔逗号按它在该 JSON 节点里的字节区间切掉,其余字节一个不改;volatile 位置跳过;[0, idx) 里任何一块拿不到逐字切片(`unaddressable`、保真不是逐字,或 `wire.contextState` 为 partial / server_edited)→ 标为假、不出 `gt`。它只做相等比较、不显示摘要值,不用 `content_hash`,也不用 `fh`:`fh` 的帧文字是重新组装的(tools = name + 描述 + 重新序列化的 schema,系统块是解码后的文字),两步帧文字相同不等于字节相同,空白、转义、数字写法的差别都被抹掉。切掉 `cache_control` 的依据:标记的位置不改变前缀里的内容(整份重发每步把标记挪到最后一条消息,照样命中缓存),不切则几乎每步都失去 `gt`。依据 = 不变式 4(「逐字」只说给逐字证得的字节)与上一句同一条理由(地面真相来自逐字源字节);另一种取法是看板的标改称「结构一致」、不喂 `gt`。

## 跨 provider cache 保真标签（D17 · write-charged vs free）

把 `break_kind` 三态与**写侧计费语义**并列成保真标签,避免叠加层横比时把三家**不可比**的数字当可比(承研究痛点 #3):

| 保真标签 | Anthropic | OpenAI(Codex) | DeepSeek | Bedrock(Extensions) |
|---|---|---|---|---|
| `break_kind` | explicit-breakpoint | automatic-prefix | automatic-disk | (随底座模型) |
| `cache_write_billing` | **charged**(`cache_creation_input_tokens` 计费) | **free**(自动前缀,无独立写费) | **none**(无写概念,`cache_write=NULL`) | **excluded**(`inputTokens` **排除** cache) |
| `hit_ratio` 分母 | `total_input`(含 write) | `total_input` | `hit/(hit+miss)` | 须显式排除 cache 段 |

跨 provider 聚合命中率/真成本 **MUST 带此标签**;`none`/`excluded` **MUST NOT** 被渲染成 `0` 参与求和(承 [3.2](3.2-normalized-model.md)「`cache_write=NULL` MUST NOT 填 0 冒充」)。

**D37 · 上表按厂商读**:Tier 1 的 usage 字段名按线格式映射([3.2](3.2-normalized-model.md));Tier 2 的 `break_kind` / `cache_write_billing` 与单价按**厂商**(上游 host)取——例如 dsh 用 Anthropic 线格式,cache 却是 DeepSeek 的自动缓存。不认识的厂商这两列填 NULL 并标「厂商缓存语义未知」,MUST NOT 借 Anthropic 语义;2.2 的单价表按 (厂商, 模型) 取,厂商 = `calls.vendor`([3.2](3.2-normalized-model.md))。`breakKindFor(vendor, wireFormat)` 按 `calls.vendor` 查表,dsh 不借 Anthropic 的 `break_kind`;下面 OPEN 列的组合按它的推荐默认填 NULL + 标未知(`src/cache/cache-events.mjs` 的 `VERIFIED_WIRES`:DeepSeek 一行只在 Chat Completions 线格式上成立,经 Anthropic 端点的 DeepSeek 即 dsh 因此是 NULL + 未知),守卫 `test/cache/cache-vendor.test.mjs`。**OPEN**:Moonshot(Kimi)、Z.ai(GLM)、经 Anthropic 端点的 DeepSeek、OpenRouter / Nous(Hermes 辅助模型)的 cache 语义 mock 证明不了,首次真实抓包核对后补列(推荐默认:先 NULL + 标未知)。

## 验收(可跑 check)
- **AC-2**:`cache_events`+`usage` 每 call 与线上 usage 数值一致;三 `break_kind` 各取一真实例,叠加层渲染正确。
- Anthropic:`declared_breakpoints` 与线上 `cache_control` 块位置吻合;billing nonce 块被判 `volatile` 不误触发散度。
- TTL 场景:构造 `cache_read=0 & cache_write>0 & 结构前缀相同` → UI 显示"过期重建"而非"未复用"。
- **AC-divergence(D17①)**:构造相邻两 flat 块序,`cacheBreak` 对每 `divergence_cause` 打出正确码——`append`(byteOffset=NULL)、`tool-array-reorder`、`json-key-reorder`(byteOffset 指向块内首个不同字节)、`content-changed`、`volatile-nonce-only`;`{compaction:true}` hint 把结构上的 `content-changed` 覆盖为 `compaction`,裸结构**不**臆断 compaction。真实 CC session 回归:`compaction` 计数 == analyze 的 `stats.compactions`。marker 渲染带 `结构估计` 保真标 + 可执行 `fix_hint`,`append` 不画 why 行。
- **AC-groundtruth(D17④)**:`groundTruth(brk,read,create)` 对有可复用前缀(idx>0)的 call:`read>0`→NULL、`read=0&write>0`→`ttl-rebuild`、`read=0&write=0`→`provider-contradiction`;首 call / 整窗重算(idx=0)→NULL。marker 的 `provider-contradiction` 文案只把疑点指向 provider(措辞含「suspect provider…not your prefix drift」)、标 `cmc-bad` + `结构估计`,`ttl-rebuild` 不被误标为矛盾。真实 session 回归无假阳(全 NULL)。
- **看板的前缀逐字标**(#12):构造两步,只挪 `cache_control` → 标为真、`gt` 照常;tools schema 只差空白 / 数字写法 → 标为假、无 `gt`;[0, idx) 里有 `unaddressable` 块 → 标为假。

## Edge cases
- 首 call `cache_read>0`(跨 session 暖前缀,tools+system 跨会话字节相同)——合法,如实显示,不当异常。
- DeepSeek 同输入两次 hit/miss 不同(非确定性磁盘缓存)——如实、标"best-effort"。
- OpenAI 前缀 <1024 tok → `cached_tokens=0` 即便重复——标"低于最小可缓存长度"。
