# trocar · RFC 2.2 — 步头 · 提问卡 · 调用详情卡

> **服务意图(A2)**:意图 ①(看懂 agent 行为)与 ②(上下文与缓存工程)。回放台中栏顶上一行**步头**:这是第几步、什么时候、哪个模型;这一步的缓存、内容组成、估价各藏在一个按钮后面,悬停、聚焦或点击才展开。对话段里每条提问一张**提问卡**,一眼看出这一轮做了什么。子 agent 与后台调用的一次调用,在调用抽屉里是一张**调用详情卡**。本单元还拥有一个算数模块 `core/metrics.mjs`:缓存判定、缓存断开、多花、估价都只在这里算,步头、会话信息按钮、时间轴、总览页都用它。
> **受众**:人(核对每个数从哪来、哪些是估的、哪些是结构估计,而没有冒充线上真相)+ agent(据此实现步头、三个弹出层、提问卡头、调用详情卡与 `core/metrics.mjs`)。
> **前置**:回放台布局、步的编号(「第 N 步」只指主对话)、弹出层约定、键盘、窄屏在 [1.2](1.2-shell-layout.md);中栏只放步头与 `#ctxwin`、提问卡的折叠(D12)在 [1.4](1.4-central-board.md);块行、变化线、两个对比步(缓存对比步 / 内容对比步)、保真标的证明规则、调用保真行在 [2.3](2.3-context-window.md);lane 种类的词、归行与花费分桶在 [2.1](2.1-track-widget.md);调用抽屉的外壳在 [2.6](2.6-detail-panel.md) §B;词表与标记在 [1.5](1.5-states-aesthetics.md);用量真相在 [3.3](3.3-cache-model.md) Tier 1;服务端补充 `sessions` 的 `title_source` / `usage` 可为 null / 按步的用量字段 / `cacheBreak.refRid` / `flagged` 在 [4.4](4.4-server.md)。决策:D12(折叠记忆)、D14(单价是可编辑配置,估价不进归一化模型)、D17②(段权重与增长)、D18c(看板 v2 成为产品看板)、D37(按厂商计价,仍是 GAP)。

## Goal

回放台中栏只放两样东西:步头与这一步的整个上下文([1.4](1.4-central-board.md))。步头一行讲清「第几步 · 什么时候 · 哪个模型」,外加三个读数按钮(这一步的上下文、缓存、估价,按钮上就是读数):

- **缓存**:这一步的缓存是什么情况(一句话)、四个用量数、断开时多花多少;
- **组成**:这次请求的内容多大、四段各占多少、比对比的那一步多了多少、主要多在哪;
- **≈ $**:这一步的本地估价,以及按哪个单价算的。

按钮上只有一个读数;解释、明细和判断都在按钮后面的弹出层里,不占中栏的地方(命不命中不值得在这么紧凑的空间里占篇幅,一个悬停展开的按钮就够)。

对话段的每条提问一张提问卡,卡头一行:提问的开头 · 「调用 N 次工具 · 思考 · 工具结果」 · 「N 块」;点开就是这一轮的块([2.3](2.3-context-window.md))。子 agent 与后台调用的一次调用在调用抽屉里是一张调用详情卡:它是哪类调用、回了什么、用了多少、估价多少、输入是哪些块。

步头、提问卡与调用详情卡都只读、不拥有真相:块的字节归 [2.3](2.3-context-window.md),用量真相归 [3.3](3.3-cache-model.md),原始回复与请求参数归 [2.6](2.6-detail-panel.md) §A。

## 前置定义(Definitions)

- **步头**:回放台中栏的第一个子元素(`#stepbar`,吸顶)。只描述当前这一步,不写会话级统计(会话统计在 [1.2](1.2-shell-layout.md) 会话头的信息按钮里)。
- **三个按钮**:步头上的「缓存」「组成」「≈ $」。每个是一个弹出层按钮,行为按 [1.2](1.2-shell-layout.md) §弹出层(悬停 300 ms、聚焦、点击打开,Esc 与点外面关闭,`role="dialog"`,里面的链接可聚焦)。按钮上的字分两行:上行是名字,下行是这一步的读数;本单元写的「缓存 73%」「≈ $0.12」这类按钮字就是这两行连读。解释、明细、链接都在弹出层里。
- **对比按钮**:步头上的「对比」菜单按钮(不是悬停弹出层),选内容对比步([2.3](2.3-context-window.md))。
- **提问卡**:对话段里以一条人类提问开头、延续到下一条提问前的一组块(分组函数 `messageTurns()`,哪一块是提问由服务端的 `flat[].query` 定,[1.4](1.4-central-board.md))。本单元定卡头写什么;卡体是 [2.3](2.3-context-window.md) 的块行;折叠按 D12([1.4](1.4-central-board.md) §折叠语义)。
- **调用详情卡**:主对话以外的一次调用(子 agent、后台调用、token 计数)在调用抽屉([2.6](2.6-detail-panel.md) §B)里显示的内容。种类与它的词来自 [2.1](2.1-track-widget.md) 的 lane 种类表(`labels/replay.mjs : LANE_KIND`)。
- **动作摘要**:提问卡头上「调用 N 次工具 · 思考 · 工具结果」这一段,由这一轮各块的 canonical `kind` 数出来(`tool_use` / `server_tool_use` 的个数,有没有 `thinking`,有没有 `tool_result`)。是从块派生的摘要,不是新事实。
- **缓存判定**:`core/metrics.mjs : cacheState(step, ref)`,按固定先后给出一步的缓存状态(8 种,见 §缓存判定);`isBreak(step, ref)` 为真 = **缓存断开**。`ref` = 这一步的缓存对比步([2.3](2.3-context-window.md))。
- **估价(花费)**:Σ(canonical 用量 × 本地单价)。是本地估算,不是账单,不是线上事实(D14,§花费)。
- **多花**:一次缓存断开比起"照常复用缓存"大约多花的钱,`core/metrics.mjs : breakCost(step, ref, priceRow)`(§多花怎么算)。是估算,而且它的前提(前面没变 / 变了)是结构估计。
- **结构估计**:看板侧按块的结构(块键与看板侧前缀哈希)比出来的结论;权威值是 查询层按相邻调用 `content_hash` 算出的散度点([3.5](3.5-query-layer.md),[3.2](3.2-normalized-model.md))。

## Plan(选定方案 + 取舍)

**选定:中栏顶上只留一行步头,数字收进三个按钮;提问卡保留;调用详情卡进调用抽屉;命中、估价、断开、多花只在一个模块里算。**

- 步头是一行,不是一张卡。它和窗口之间没有别的东西([1.4](1.4-central-board.md) 的中栏白名单)。
- 缓存的状态句、四个用量数、多花,只在「缓存」按钮里出现一次;原始数据面板不再列用量([2.6](2.6-detail-panel.md) §A)。
- D17② 的段权重与增长 Δ 算法不变,两个 MUST 标跟着数字一起进「组成」按钮。
- 提问卡按原设计保留(沿用既有设计,中栏放整个上下文),只把 emoji 换成文字词(界面语言是英文,D58①)。
- 子 agent 的一次调用在调用抽屉里看,没有它自己的回放。
- `core/metrics.mjs` 是唯一算命中、估价、断开、多花的地方;步头、会话信息按钮([1.2](1.2-shell-layout.md))、时间轴的问题道与花费视图([1.3](1.3-timeline-tracks.md))、总览页的统计([1.7](1.7-overview-dashboard.md))都调它。

**备选(未选)**:
① 重设计稿里钉在中栏顶上的「步骤卡」(进来 / 模型 / 问题带 / 用量四段)——否决:中栏堆这么多东西没有重心,看不出要表达什么。
② 段权重条、增长行、缓存行写在窗口头上——同上,中栏只放整个上下文。
③ 卡自己渲染块的全文(把摘要和逐字揉进一条渲染路径)——卡一改文案就可能改掉块的字节,直接威胁 AC-1,还把 [2.3](2.3-context-window.md) 的职责撕进来。
④ 卡直接读 provider 原生字段拼摘要——加一个 provider 就要在卡里加分支,违反不变式 3([0.0](0.0-overview.md) §核心不变式;需 RFC 才放行)。

**取舍**:数字退到按钮后面,换来中栏只有上下文;代价是要多一次悬停才看到缓存与估价。问题道([1.3](1.3-timeline-tracks.md))上的旗与会话信息按钮把"哪一步该看"指出来,所以不会漏看。

## 缓存判定

## 多花怎么算

`core/metrics.mjs : breakCost(step, ref, priceRow)`,只对 `isBreak()` 为真的步算:

- `ref` = 缓存对比步([2.3](2.3-context-window.md):这条线上前一次没失败的调用;骨架行的 `cacheBreak.refRid` 给出确切的那一条调用,归约里定)。
- 少读的缓存 token:missed = max(0, (ref.read + ref.create) − step.read)。
- 单价差(美元 / 百万 token,取自按 `step` 的模型匹配到的那一行价,最长单价键优先):step.create 是数 → 写缓存单价 − 读缓存单价;否则 → 未缓存输入单价 − 读缓存单价。
- ≈ 多花 = missed × 单价差 ÷ 10⁶。
- 用到的值里有 NULL(`ref.read`、`ref.create`、`step.read`),或这个模型没有单价 → 结果为 NULL,写「多花算不出」并给原因:「服务商没有返回写缓存数」/「没有这个模型的单价」/「价表读不出」。所以 OpenAI 线上的断开(`usage` 可为 null 之后 `create` 为 NULL)今天都算不出:上一步留下的可缓存部分不知道(见 Extensions)。
- 多花只在回放里算(本单元的步头与会话头):它要相邻调用的块结构,`overview` 只读段索引,给不出断开数([1.7](1.7-overview-dashboard.md) §统计 · [1.6](1.6-cli.md) C.5)。

**MUST(不变式 4 · 必拒)**:多花算不出时写「算不出」与原因,MUST NOT 写 $0;算得出时带「≈」,而且因为它的前提是结构估计,弹出层的状态句已带「结构估计」。守卫:`metrics.test.mjs`「breakCost: missed tokens × (write or uncached − read); any NULL or no price → null, never 0; the price is the step's model's longest key」。

## 花费(本地估价 · 保真边界)

- **算法(D14)**:一次调用的估价 = (`fresh` × 未缓存输入价 + `out` × 输出价 + `create` × 写缓存价 + `read` × 读缓存价)÷ 10⁶(`core/metrics.mjs : costOf()`,价表一行 = [输入, 输出, 写缓存, 读缓存] 美元 / 百万 token)。`create` 为 NULL 的那一项不计(服务商没有写缓存这回事),不填 0 冒充。
- **单价从哪来**:`/api/pricing`(`src/view/pricing.mjs : loadPricing()`,可编辑配置 `pricing.json` / `TROCAR_PRICING`,D14),前端由 `replay/pricing.mjs : createPricingLoader()` 取一次并记住取不到的原因。按 `steps[].rec.request.model` 查价:先找完全同名的键,再找模型名里出现的最长的键(`core/metrics.mjs : priceMatch()`);按后者查到时写「按 <键> 的单价」。一个键都不出现 → 「没有这个模型的单价」,不猜。
- **不计价的情况**:失败的调用(状态 1)、没有用量的调用(状态 2)、token 计数(它不生成回复、不计费)。失败的调用不让会话合计变「起」;没有用量与没有单价的调用让合计变「起」。
- **会话合计**(给 [1.2](1.2-shell-layout.md) 的会话信息按钮):`core/metrics.mjs : sessionTotals()` 按 [2.1](2.1-track-widget.md) 的花费分桶分成主对话 / 子 agent / 后台调用三桶,三桶之和等于合计;另给没有单价的调用数、没有用量的调用数、按单价键近似的键名。措辞归 [1.2](1.2-shell-layout.md)。
- **按厂商计价(D37)仍是 GAP**:D37 要按厂商(`calls.vendor`,按上游 host)取价,不认识的厂商不估价。今天看板按模型名的单价键取价;`steps[].wire.vendor` 已经随每一步下发(旧格式与不认识的 host 为 null),但没有按厂商分的价表;默认价表只有 Anthropic 的三个家族键,所以其他模型的步都写「没有这个模型的单价」。要补的是价表的形状与服务端(写缓存价可为空),记在 Extensions,本单元不定。

**MUST**:
- **MUST(D14 · 不变式 4 · 必拒隐瞒)**:每个钱数带「≈」,「≈ $」弹出层写「本地估价(用量 × 单价),不是账单」;MUST NOT 让人当成账单;不知道的从不写 $0。守卫:`stepbar.test.mjs`「≈ $: local estimate, recomputable as usage × price, labelled 按 <键> 的单价 when matched by a key; unknown is ≈ —, never $0」+ `test/web-v2/call-card.test.mjs`(调用详情卡同一规则)。

## 保真边界一览(哪些不是逐字 · 界面必标)

| 元素 | 保真等级 | 真相在哪 | 就地怎么标 |
|---|---|---|---|
| ≈ $、≈ 多花、会话合计 | 本地估价(不是线上事实) | 线上没有金额;canonical 用量 × 本地单价 | 「≈」+「本地估价(用量 × 单价),不是账单」;部分算不出写「起」 |

## Edge cases

- **没有提问打头的一轮**(只有工具结果续跑):卡写「接着上一轮」,不当成提问。
- **超长提问**:预览截到 90 字;调用详情卡里的长块按 [2.6](2.6-detail-panel.md) §B 的规则原位折起(写明大小),不拿描述去替代原文。
- **失败或半途中断的调用**:缓存判定第 1 种,步头「缓存 失败」、「≈ —」,弹出层一句失败原因;不显示伪造的用量与估价。回复没采全另由调用保真行说([2.3](2.3-context-window.md))。
- **没有用量**(某服务商某步没回用量):「缓存 —」「≈ —」,MUST NOT 写 0;会话合计变「起」。
- **用量在、输入为 0**:按没有用量那一种处理,句子换成「用量里没有输入数,算不出(不是 0%)」。
- **第一次调用读到了缓存**(`read > 0`):是跨会话的暖前缀,合法,不算断开;状态句带那句说明(承 [1.4](1.4-central-board.md))。
- **只有每次都变的块变了**(`volatile-nonce-only`):不算断开,不画变化线;状态句说明不影响缓存。
- **缓存对比步前面有失败的调用**:对比的是更早那一步没失败的调用;对比菜单的默认项写出第 K 步。
- **内容对比步的车道未到手**:多花照算(用量在骨架行上);增长等那条车道到手(弹出层打开时取,没有控件)。
- **压缩**:状态句写「对话被压缩(推测)…」(确认的压缩不加「推测」),增长不报增量;它也是缓存断开,问题道另有「压缩」字样([1.3](1.3-timeline-tracks.md))。
- **服务商不报写缓存数**(`create:null`):四个数里写「—」;估价那一项不计;多花算不出。
- **价表读不出 / 还没回来**:「≈ —」与原因;缓存判定照常。
- **会话没有主对话**(只有 token 计数或只有子 agent):锚在排第一的 lane 上([1.5](1.5-states-aesthetics.md) K-04),步头写「<lane 词> · 第 k / M 次调用」,缓存 / 组成 / ≈ $ 按钮随这条 lane 的数据画;做不了的控件不画。
- **步头放不下**(中栏最窄 360 px):先省略模型名(全名在说明气泡),模型名缩到八个字符还放不下才换行,三个读数按钮(上下文 / 缓存 / 估价)换到步头下一行;时间是短词,整个画出、从不省略(省到一两个字母就什么也没说);步号与 ‹ ›、「对比」菜单、三个读数按钮也永不省略。1280 宽(中栏约 626 px)时 MUST 一行放下:换行吃掉上下文窗的高度,1280 × 800 下真数据量到 0.47,破了 [1.2](1.2-shell-layout.md) §上下文窗的高度的 50%(依据 1.2 那条 MUST:步头不换行)。守卫:`test/web-v2/browser/replay-shots.test.mjs` 1280 × 800 一例。
- **token 计数与预热请求**:前者不计费、没有回复;后者是服务端的一种 lane,照常计价;两者不混。

## Risk / 回滚

步头、提问卡头与调用详情卡都是纯读的渲染(`/api/session` → DOM),没有副作用;`core/metrics.mjs` 是纯函数。回退:按提交回到上一个绿点。缓存判定或多花的算法一改,问题道、会话信息按钮、总览页会一起变——这是一个模块的本意,回退时也一起回退。单价表的改动只影响估价显示,可单独回退;因为都标了「本地估价」,不污染真相层。

## Extensions

- 步头或调用详情卡上更多可选的数(推理 token 单列、耗时、`stop_reason`),照 canonical 列加,不加 provider 分支;耗时今天还不在段索引里(原 `calls.duration_ms`,看板的步上没有。
- 按厂商计价(D37):价表按厂商分、写缓存价允许为空,服务端给出;那时「没有这个模型的单价」可以细分成「不认识的厂商」。
- 服务商不报写缓存数时的多花:要先定"上一步留下的可缓存部分"怎么算(比如上一步的全部输入),才能给 OpenAI 线的断开估一个数;定之前写「算不出」。
- 原因的修法句:服务端按闭集的原因码给出修法后,可以在「缓存」弹出层加一行(词由 `labels/**` 按码取)。
- 单价表的编辑界面与跨模型的成本对比(挂 [1.11](1.11-settings.md) 与 [3.5](3.5-query-layer.md) 的跨会话分析);单价仍是可编辑配置,估价 MUST NOT 进归一化模型(D14)。
- 新 harness / 新 provider:canonical 落齐就复用同一个步头与同一张卡,前端主干不改(AC-3)。
