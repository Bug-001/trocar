# trocar · RFC 2.6 — Call details · 调用抽屉 · 请求详情

> **服务意图(A2)**:意图 ①(看懂 agent 行为)为主——给「回放骨([2.3](2.3-context-window.md))之外」的三样东西各一个宿主:*当前这一步的原始线上事实*(窗口里回复之后的 Call details:能回源的原始回复字节、请求参数、传输、采集对客户端的影响)、*主对话之外的每一次调用*(调用抽屉)、*一条请求的头与逐字体*(请求详情部件,流量的 host 页用它);兼意图 ②(原始回复字节是步头「缓存」按钮里那四个用量数的回源处,数在 [2.2](2.2-call-turn-card.md),字节在这里)。
> **受众**:人(在骨之外深看某一步的原始回复与请求参数 / 某一次子 agent 或后台调用 / 流量里的一条请求);agent(据 `session` 的行与车道头、`lane` 的步与块定义、`block`([3.5](3.5-query-layer.md) §会话读)、[4.4](4.4-server.md) `calls --ref` 渲染,**不碰 provider/harness 分支**)。
> **前置**:数据 = [3.5](3.5-query-layer.md) §会话读:`session` 的行(`rid`、`wire`、`error` / `errMsg` / `status`、`unparsed`、`rec`、`respIncomplete`)、车道头与 `probes`;这一步车道步(`lane` 读)的 `reply`(回复各部分的块 id,定义在同一个回答的 `defs` 里)与 `detail`(`norm{stop_reason, usage}`、`respRefs`、`nonBlockKeys`、`extraMessages`、`wire`);字节回源 = `block`;单条请求 = [4.4](4.4-server.md) `calls --ref`;渲染宿主 = 上下文窗([1.4](1.4-central-board.md) ⑩⑪)+ 视口底缘的调用抽屉(`#detail`);调用抽屉由 [2.1](2.1-track-widget.md) / [1.3](1.3-timeline-tracks.md) 的 tick 与 [1.2](1.2-shell-layout.md) 的 `call=` 路由打开,卡里写什么归 [2.2](2.2-call-turn-card.md) 调用详情卡;lane 种类的词归 [2.1](2.1-track-widget.md);块的保真标(证明规则)、调用保真行、格的两种模式与车道未到手归 [2.3](2.3-context-window.md);请求详情的宿主是 [1.10](1.10-traffic.md) 的 host 页;凭据的存储处置权威在 [4.1](4.1-capture-sources.md) §凭据处置;词与标记归 [1.5](1.5-states-aesthetics.md)。

## Goal
给「忠实回放骨(2.3)+ 步头(2.2)」之外的三类观测一个统一宿主,MUST 不撕裂主线、不往通用视图塞 provider 分支(守卫:`test/web-v2/no-provider-branches.test.mjs`、`test/web-v2/harness-seam.test.mjs`):
1. **Call details**:窗口里回复之后的两项,随播放头说**当前这一步(主对话)的线上事实**——一行看得见的采集对客户端的影响,一行默认折着的请求参数、能回源的原始回复字节、调用打开期间客户端又发的消息与传输。回复各部分在窗口的回复行([2.3](2.3-context-window.md));用量的四个数与估价不在这里,在步头([2.2](2.2-call-turn-card.md))。
2. **调用抽屉(`#detail`)**:从视口底缘滑起,**深看主对话之外的一次调用**——子 agent、后台调用(安全审查、通知摘要、生成标题、保活检查、预热请求……)或一次 token 计数;卡的内容是 [2.2](2.2-call-turn-card.md) 的调用详情卡,输入逐块回源。
3. **请求详情部件**:一条请求(任何类别,模型调用也算)的请求行、头、逐字体、每侧的保真标注与凭据类头的遮挡;[1.10](1.10-traffic.md) 的 host 页用它,经 `calls --ref` 按需取单条。

## 前置定义(Definitions)
- **Call details**:上下文窗里回复之后默认折着的一项,列播放头所在**主对话这一步**能回源的线上事实。它和步头([2.2](2.2-call-turn-card.md))同指一步、不同 surface:步头给数(用量、估价、缓存判定、组成),Call details 给字节(原始回复、参数)。
- **主对话之外的调用**:`lanes[].kind ≠ main` 的模型调用。种类、词、归行与花费分桶只按 [2.1](2.1-track-widget.md) 的 lane 种类表(`labels/replay.mjs : LANE_KIND`)。**token 计数**(`probes`,count_tokens)不是 lane、也不是模型调用,但它在 token 计数叠加轨上的 tick 同样在调用抽屉里打开。
- **调用抽屉**:视口底缘滑起的可关闭层,显示主对话之外的一次调用的调用详情卡([2.2](2.2-call-turn-card.md))与它的输入块。
- **请求详情部件**:一条记录(推理或非推理)的请求行、头、体与每侧标注的渲染部件(`web/src/screens/traffic/RequestView.tsx`,视图数据由 `request-model.mjs : detailModel()` / `requestView()` 给),数据 = `calls --ref` 的单条记录,形状同 `src/view/control-wire.mjs` 的 `ctl`。
- **control-plane(session-less)**:harness 在会话周边发的**无 session 归属**调用——CC 侧无 `x-claude-code-session-id`(承 [3.4](3.4-session-identity.md) 身份信号)。多为**非 LLM 调用**。数据模型见 §C 末的 D9 注;呈现已移到流量页([1.10](1.10-traffic.md)),不再是会话选择器里的分组(D18c)。
- **凭据类头**:判据只写在 [4.1](4.1-capture-sources.md) §凭据处置「凭据类头」(与服务端 `src/capture/redact.mjs : isSecretHeader()` 同一个判据,4.1 的「涉及」表写明它用于识别与查询文档的遮挡)。都是 HTTP 通用名与通用的词尾,不是某个 provider 的知识。

## Plan(选定方案 + 取舍)
**选定:窗口里一项折着的 Call details + 一个可关闭的调用抽屉 + 一个请求详情部件(由流量 host 页托管)**;三者都只读,都**只读装配后的字段与 `calls --ref` 的记录**,lane 判定与类别划分留在服务端(`src/view/analyze.mjs` 的 lane、读取侧 harness 表推出的 D40 `traffic_class`),本部件只渲染结果。
- Call details 不做独立的面板,而是窗口里折着的一项:回复已经在窗口里说过一遍,只有它有的事实跟在回复后面,不占常驻版面(D80)。
- Call details 只放**能回源的字节**:用量四个数、缓存判定与估价移到步头的「缓存」「≈ $」按钮([2.2](2.2-call-turn-card.md)):命不命中不值得在这么紧凑的空间里占篇幅,一个悬停展开的按钮就够。
- 深看用**滑起层**(`#detail`,`position:fixed` 底缘 `translateY`)而非侧栏第三列:主对话之外的调用是**偶发点开、看完即走**的深读,滑起 +「关闭」/ `Esc` dismiss 比常驻列更省版面(承 [1.2](1.2-shell-layout.md) 版面预算)。
- 会话之外的流量不再是会话选择器里的模式切换(`ctrlmode`),而是流量页的 host 下钻([1.10](1.10-traffic.md));请求详情是那里的部件:在流量页点进某个 host,就能看到这个 host 具体发过什么。
- 凭据类头逐字存(4.1),每份查询文档默认遮挡、按头名点了才取那一个值(显示时遮挡凭据类的头,点「显示」才露;服务端默认遮挡、`calls --ref` 带 `reveal=<头名>` 取一个值,依据见 §保真边界 2)。

**备选(未选)**:① 把主对话之外的调用也画进中央回放骨——会把「主对话」与「侧线」混成一锅,违反 D2「行为回放为骨」的单主线;故侧线在 [1.3](1.3-timeline-tracks.md) 有叠加轨、在此有深看,骨只留 main。③ control-plane 混进会话列表按时间排——session-less 流会淹没真会话,且诱人误以为它们是某会话的一部分。④ 保留旧的 control 模式(会话选择器里的 `⚙ session-less` 组 + `ctrlmode` 分类列)——侧栏已把互不相交的东西分开,会话之外的流量在流量页,保存设置在设置页(D18c)。⑤ 用量四个数在面板与步头各放一份——同一事实两处显示。⑥ 凭据类头逐字显示——定稿是显示时遮挡、点了才露。
**取舍**:Call details 折着 = 回复只说一遍,事实一点就到;深看滑起 = 深度可达又不常占版面;流量下钻 = 会话之外的请求可查但不污染回放台;遮挡是显示上的默认,不是隔离(见 §保真边界 2)。

## A. Call details:这一步的线上事实

窗口里回复之后的两项([1.4](1.4-central-board.md) ⑩⑪):一行看得见的采集影响,一行默认折着的 Call details。用量的四个数与估价不在这里,在步头([2.2](2.2-call-turn-card.md));回复各部分在窗口的回复行([2.3](2.3-context-window.md) §这一步的回复)。模型:`web/src/screens/replay/call-details.mjs : callDetailItems(row, st)`,纯函数。

| 元素 | 屏上(例,虚构) | 来源 | 规则 |

## B. 调用抽屉:`#detail`(`openDetail`)
从视口底缘滑起的可关闭层(`#detail.open`;`translateY(101%)` ↔ `none`),按 `lanes[].kind` 上色边(`k-<种类>` 类名),**深看主对话之外的一次调用**。入口:[2.1](2.1-track-widget.md) / [1.3](1.3-timeline-tracks.md) 上点一个叠加轨的 tick(`replay/rails.mjs : selectTick()` → `openDetail(el, s, lane, i)`),或 [1.2](1.2-shell-layout.md) 路由的 `call=<记录 id>` 指向一次非主对话调用。dismiss:「关闭」或 `Esc`(`core/keys.mjs` 发出的 `v2:escape`,[1.2](1.2-shell-layout.md) §键盘)。

| 元素 | 屏上(例,虚构) | 来源 | 规则与守卫 |
|---|---|---|---|
| 卡 | 标题行、说明、回复或审查结论、用量与估价、技术细节 | [2.2](2.2-call-turn-card.md) §调用详情卡 | 卡里写什么归 2.2(守卫 `test/web-v2/call-card.test.mjs`);标题行的 lane 词取 [2.1](2.1-track-widget.md) `LANE_KIND`,服务端的 `lanes[].icon` 不用 |
| 回到主对话 | 「← 回到第 12 步」 | `replay/lanes.mjs : nearestByTs()` → `stepRef()` | 点了播放头移到那一步(按时间找的最近一步,标题行写「约在第 N 步」,[1.2](1.2-shell-layout.md) §编号);抽屉不关 |
| 关闭 | 「关闭」 | 固定文字;`v2:escape` | 关掉时清选中的 tick 与复审括号(`closeDetail()`) |
| 输入 | 「输入 · 14 个块」+ 每块一行:角色 · 种类 · 名字或预览 · 保真标 · 大小 | 这次调用车道步的列表与块定义(`lane` 读,[3.5](3.5-query-layer.md) §会话读)→ `block` | 点开是一格;见下 |
| token 计数的输入 | 「请求体不在会话里,到 流量 页按「token 计数」类别逐条看(保存级别:全部)」 | `probes.series[].retention` | 三种:全部 / 只记日志 / 较早采集的记录,只存了长度;流量 host 页能逐条看(按类别「token 计数」,[1.10](1.10-traffic.md)) |

**输入块**(承 `replay/detail.mjs : inputHtml()`):
- 每个块一行,点开是一格(`cell.mjs : cellBodyHtml()`,[2.3](2.3-context-window.md) §两种模式):Raw 默认,Readable 一键之遥,字节经 `block` 按 `bid` 只取一次(取失败的行再点时重取);切片与剪裁同上下文窗,抽屉没有自己的剪裁。块数 ≤ 40 时,短块(≤ 600 字符)自动打开;更多块时都不自动打开。
- 大小带单位:有 `chars` 写「字符」,只有 `bytes` 写「字节」,都没有写「大小未知」,从不写 0。不透明块(线上没有明文)写「不透明 · 线上没有明文」,不给一个像量出来的 0。
- 折叠标签写明被折的是什么:**证得逐字的块写「逐字 · N 字符 · 点开」,其余写它自己的保真标**(证明规则归 [2.3](2.3-context-window.md))。
- 不按 harness 知识从体里切块(旧看板把安全审查输入里的对话副本就地折起,靠的是 CC 的标签;v2 按块定义逐块列,输入长了就按块折)。
- 这次调用的车道未到手 → 按 [2.3](2.3-context-window.md) §读与画 画元数据与空框,没有载入控件;列表为空 → 「这次调用没有输入块」。

> 深看的输入 MUST 逐字(AC-1);超长体折叠而非改写。输出是归一化后的回复,不是逐字,MUST 带「◐ 解析后的回复」(规则归 [2.3](2.3-context-window.md),卡上的位置归 [2.2](2.2-call-turn-card.md))。折叠标签 MUST 写明被折的是什么,只有证得逐字的块写「逐字」。守卫:`test/web-v2/drawer.test.mjs`(新建)。

- **两种 probe 不混**:token 计数来自 `probes.series`(不是 lane),预热请求是服务端的 lane `probe`。抽屉按调用的来源选卡,MUST NOT 按 `kind === 'probe'` 这个共用字样选(今天 `replay/lanes.mjs : buildLanes()` 给 token 计数造的 lane 也叫 `kind:'probe'`,改名归 [2.1](2.1-track-widget.md);卡的规则归 [2.2](2.2-call-turn-card.md))。守卫:`drawer.test.mjs`。
- **子 agent 的调用在这里看**:没有子 agent 的单独回放(`&sub=` 砍掉,[2.2](2.2-call-turn-card.md))。
- **安全审查**:结论照原样给,不画任何标记、不出计数(规则与卡上的位置归 [2.2](2.2-call-turn-card.md) / [2.1](2.1-track-widget.md))。真实数据上的核对在本单元验收 #9。
- **token 计数是被测 harness 自己发的 `count_tokens` 调用,trocar 只经采集源观测、绝不代发**(不变式 1,[0.0](0.0-overview.md) §核心不变式:没有操作者动作时 trocar 不发请求)。守卫:收尾审查([0.1](0.1-engineering-rules.md) §6 第 1 条)。

## C. 请求详情部件(`RequestView`)
一条请求的详情,由 [1.10](1.10-traffic.md) 的 host 页托管(选中一行 → 右栏或抽屉,断点归 [1.2](1.2-shell-layout.md) §窄屏)。数据是 [4.4](4.4-server.md) `calls --ref` `GET /api/calls?ref=?ref=<raw_ref>` 回的一条记录,体已按显示上限重塑(`src/view/control-wire.mjs : controlRecordWire()` 的 `ctl`)。本部件只管详情本身。

**单条请求端点**:`calls --ref`(D18c):host 页逐条看。session 之内与之外的非推理调用、token 计数、模型调用都一样能看(`calls --host` 的列表不按 session 过滤)。

| 元素 | 屏上(例,虚构) | 来源 | 规则与守卫 |
|---|---|---|---|
| 请求行 | 「POST /v1/example · 200」 | `calls --ref` 记录的 `method` · `endpoint` · `resp.status` | 照原样,等宽;状态为空 → 「—」 |
| 类别与保存级别 | 「telemetry · log only」 | `calls --ref` `ctl.traffic_class` → `core/classes.mjs`;`ctl.retention` | 级别只在「只记日志」时写 |
| 域名 | 「连接的域名 `api.example.test`」;不一致时并排「请求里写的域名 `example.test`」,上方一行「连接的域名和请求里的域名不一致」 | `calls --ref` `ctl.host` · `ctl.hostHeader` · `ctl.hostDiffers` | 反代记录的 `host` 是上游、`Host` 头是客户端连反代的地址,按构造就不同,服务端不置 `hostDiffers`(不是信号);SNI / Host 两个词放进技术细节 |

**请求与响应体(D40)**:请求体逐字显示,不再写「request body isn't decoded」。文本按原文显示在 `<pre>` 里,超长只折不改,折叠标签写明「逐字 · N 字节」;二进制(`req_body_b64` 不带 `req_content_encoding`,或 `raw_b64`)显示「二进制 · N 字节 · 逐字存为 base64」与前 4 KiB 的十六进制;压缩体先由服务端按 `req_content_encoding` 解,解不出才标「压缩请求体未解码」;每个体旁给出 `body_wire_bytes`。**显示上限(审查 2026-10-07 补记)**:服务端只下发每个文本体的前 1 MiB 字符(`BODY_SHOW_CHARS`,不劈开代理对)、二进制体的前 4 KiB 作十六进制(`HEX_SHOW_BYTES`);超出时就地写「已截断显示 · 前 N / 共 M 字符」与「其余在源记录里」。这不是改写 —— 不发,不是改 —— 但它让「逐字显示」到 1 MiB 为止;更大的体要看全就得读源记录。另显示 `host`(SNI)与 `req_headers.host`,两者不同时并排标出(反代记录除外:那里 `host` 是上游、`Host` 头是客户端连反代的地址,按构造就不同,不是信号)。**不是整个体的体 MUST 说明白**(审查 2026-10-07,不变式 4):请求体被截在上限(`req_truncated`)或没传完(`req_partial`)、回复被截在上限,就地标「已截断」/「不完整」(`ctl.labels` 的 `req-incomplete`、`resp-truncated`),并写「只存了前 N / 共 M 字节」,折叠标签写「前缀,不是完整的体」而不是「逐字」;D40 之前 `raw_chars` 为 0 的记录(GET 没有体)显示「没有体」,不是「只存了长度」。守卫:服务端 `test/view/control-wire.test.mjs`(见 §验收「已有闸」);界面 `test/web-v2/host-model.test.mjs`。

## Edge cases
- **无请求体的步**:探针 / 中断 call → 窗口写「这一步没有采集到请求」,没有 Call details。
- **深看与 scrub 交互**:`#detail` 开着时 scrub 主线——`#detail` 是独立层,不随主线 playhead 变(它锚在被点的那次调用);但 Call details 随 scrub 换成新一步的,二者互不干扰。那次调用的车道到了之后抽屉按选中的 tick 重画(`replay.mjs : refreshDrawer()`)。
- **v0 记录**:`respRefs[].ref` 为空带 `why`、`nonBlockKeys` 为空(请求不是原文字符串)——原始回复写「没有可回源的字节」,请求参数写「这条记录没有可回源的请求参数」,回复带「◐ 解析后的回复」。
- **WebSocket 调用**:回复按消息分成多条 `respRefs`;调用打开期间客户端又发的消息(如打断)在 `extraMessages`,MUST 列出。
- **两种 probe**:服务端 lane `probe`(预热请求)与前端从 `probes.series` 造的 token 计数今天同叫 `kind:'probe'`;抽屉按来源分,不按这个字样(§B)。
- **服务商的值**:停止原因、线格式、厂商都是原值;不认识的厂商写「不知道」,不猜。
- **请求详情 · 读不到**:`calls --ref` 回原因(ref 不在采集根内、源文件不见了、记录读不出 `ctl.error`)→ 写原因 +「重试」,不显示空的体(这一层归 [1.10](1.10-traffic.md))。
- **同名的头出现两次 / 值是数组**:照存的样子逐个列出;凭据类的每一个都遮挡。
- **查询串里带凭据**:端点照存的样子显示;遮挡只按请求头名单(见 Extensions)。
- **DeepSeek / Codex 没有 control-plane 对应**:session-less 的流量是 harness 相关的——流量页对空的 host 表优雅降级([1.10](1.10-traffic.md)),本部件不硬编任何端点的存在性。

## Risk / 回滚
- 渲染是**纯函数**(这一步的装配字段 + playhead → 项;`calls --ref` 的一条记录 → HTML),用 T0 / T1 回归;改 Call details、抽屉、请求详情不动数据层,可独立回退到上一绿点。
- 请求详情显示头与体:遮挡默认开;若服务端的遮挡出错(漏遮),前端的同一份名单仍会遮(两层);回退 = 撤掉 `calls --ref` 路由,数据不动。

## Extensions
- **调用抽屉的跨 provider 泛化**:Codex 子 thread / DeepSeek 侧调用的 lane 一旦经 adapter 归一化,抽屉**零改动**即适用(AC-3)。

- **原始响应里的用量对象高亮**:服务端给出用量在原始回复里的位置(`usage_span`),Call details 高亮,和步头的四个数对着看;前端不认字段名。
- **模型调用的「复制为 curl」**:服务端在步上给出方法、host 与头之后再做;凭据类头一律换成占位。
- **查询串里的凭据遮挡**:端点的查询串里带 key 时也按凭据处理(与 [1.10](1.10-traffic.md) 同一条)。
- **trocar 改过或发起的请求**(D30):[5.1](5.1-intervention.md) 落地后,请求详情就地标出,原始与改后各看一份。
- **control-plane 跨 session 聚合**([3.5](3.5-query-layer.md) 全表):「这段时间观测到哪些 feature flags 变过」——session-less 流量的历史视图(记为下游,非 v1;入口会在流量页)。
