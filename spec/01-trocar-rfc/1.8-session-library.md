# trocar · RFC 1.8 — 会话库(Session Library)

> **服务意图(A2)**:意图 ①(看懂 agent 行为)的入口——在采到的所有运行里找到要看的那一次,一键进回放台。它本身不回答「这一步发生了什么」,只负责让人最快走到那一步。
> **受众**:人(要打开某一次运行:按时间、agent、项目或一句话找);agent(据此实现 `src/web/v2/library/**`,只读 `/api/sessions`,不碰 harness 分支)。
> **前置**:外壳、路由、页头规则、agent 标识与图标 = [1.2](1.2-shell-layout.md);看板词表、标记、状态矩阵、数据规则 = [1.5](1.5-states-aesthetics.md);会话怎么认、合成键、子 agent 血缘 = [3.4](3.4-session-identity.md);`/api/sessions` 的形状、人类标题的来源、新增字段 `sessions` 的 `title_source` / `sessions` 的多 harness 字段 = [4.4](4.4-server.md);按 harness 的开关与本机网络环境字段 = [1.6](1.6-cli.md)。

## Goal

会话库是一张会话表:一行是一次运行,点一下进回放台。它回答一个问题:**「我要看哪一次运行?」**

两条要求管着本单元:统计句不进标题和小标题(会干扰读者,overall 的统计归 dashboard);界面上的每个字都要接得上真实数据(接不上线的文字与不干净的尾巴一律砍掉)。所以会话库只放能从 `/api/sessions` 读出来的东西;花费、缓存、断开这类统计放在总览页([1.7](1.7-overview-dashboard.md))和回放台会话头的信息按钮里([1.2](1.2-shell-layout.md) §会话头)。

## 前置定义(Definitions)

- **会话库**:路由 `#/sessions` 上的屏,侧栏和页头里叫「会话」。
- **会话行**:`/api/sessions` 里的一个会话(`sessions[]` 一项)占一行,两行字:上行是标题与数字,下行是 agent 与行标。
- **工具行**:表格最上面的一行控件(搜索、Agent、项目、排序、生效的筛选)。它属于表格本身,不属于页头。
- **说明行**:表格自己的说明行,只在有事实要说时出现:列表读得全不全、上次读失败了。它是 [1.2](1.2-shell-layout.md) §页头 规定的「说明放进它所说明的那张表」的落点。
- **行标**:会话行下行里的短标记——「含子 agent」「只记日志 N」「只有 token 计数」「推测」「会话边界是推测的」「多个 agent」。只在为真或大于 0 时出现。
- **标题规则**:一行显示什么标题,取 `title`,没有时写「未命名会话」(见 §标题规则)。
- **高亮行**:键盘作用的那一行,记在路由参数 `sel` 里,从回放台回来时落回它。
- **模型调用**:词表([1.5](1.5-states-aesthetics.md) §看板词表)的词:会话里的每一次推理调用,含子 agent 与后台调用;不含 token 计数,也不含只记日志的调用。会话库只说「模型调用」,从不说「步」。

## Plan(选定方案 + 取舍)

**选定**:一张虚拟滚动的两行式会话表,数据只来自 `/api/sessions`(形状见 [1.6](1.6-cli.md) C.5 `sessions`;`sessions` 的多 harness 字段 `harnesses[]` 按在不在画)。搜索、筛选、排序、分组都在浏览器里对这份列表做。没有一个统计数字:会话表是列表,不是汇总(D24:跨会话汇总只走具名 SQL,那是总览页的事)。

**备选(未选)**:
1. 每行加估价、缓存命中、缓存断开、时长四列,并能按花费 / 断开排序(原型的做法)——`/api/sessions` 的会话元数据里没有这些字段;逐行去取 `/api/session` 太重,走具名查询又会让同一张表里一半是实时源数据、一半是「截至上次入库」的数字。统计归 dashboard。每个会话的花费在回放台会话头的信息按钮里。
2. 会话库做首页——侧栏不写状态之后,首页若不是总览页,一打开 trocar 就看不见采集失败(D38②)。首页是总览页([1.7](1.7-overview-dashboard.md))。
3. Agent 筛选做成带数字的小标签(原型的做法)——页头区不放数字([1.2](1.2-shell-layout.md) §页头);改成不带数字的菜单。
4. 服务端全文搜索——不加端点;搜索只在标题、项目名、会话 id 里找。

**取舍**:列表全在浏览器里筛,换来零新端点、筛选即时、URL 可分享;代价是只能搜元数据。下面这些是界面层决定:默认时间窗是「全部」;按「最近」排序时才按天分组;Agent 筛选是不带数字的菜单;工具行放在表格里;说明行的内容与 ◐ 标;空态只读一次采集健康并写「截至」;本单元「砍掉的」整张表。

### 空、载入、读不出

这几种状态替代表格内容;工具行仍在。词与次序归 [1.5](1.5-states-aesthetics.md) 状态矩阵,本单元给出会话库这一屏的落法。

| 状态 | 显示 | 来源 | 判定 |
|---|---|---|---|
| 载入 | 「正在载入…」 | 固定文字 | 第一次读还没回来 |
| 读不出(手里没有旧列表) | 「读不出会话列表:服务返回 <状态码>」或「连不上 trocar 服务」+「重试」+「▸ 技术细节」(`error` 原文) | `/api/sessions` 的 HTTP 状态 / `{error}` / 连接错误 | 从没成功读过;MUST NOT 写成「还没有会话」([4.4](4.4-server.md) `GET /api/sessions` 行;守卫:验收断言 9) |
| 还没有会话 | 第一行「还没有会话」;第二行是采集状态的那句话 +「截至 HH:MM:SS」+「去采集 ›」(→ `#/capture`) | `/api/status` 顶层 `health` 经 `core/capture-verdict.mjs` 得到的句子(词归 [1.5](1.5-states-aesthetics.md) / [1.9](1.9-capture-page.md),例如「采集服务已停止 · 最后记录于 09:12」);采集服务在采时第二行是「采集在进行,运行一次 agent 就会出现在这里」;采集状态读不出时是「读不到采集状态」,原因只进折叠的技术细节(K-29) | 读成功且一个会话都没有 |
| 筛选后为空 | 「没有符合筛选的会话」+「清除筛选」 | 固定文字 | 有会话,但筛选后一个不剩 |
| 筛选的 agent 没在被采集 | 在上一行之前加「<agent 名> 现在没在被采集 · 去采集 ›」(→ `#/capture?h=<id>`) | `status` `harnesses[h].desired === 'off'` 或 `harnesses[h].captured === false`([1.6](1.6-cli.md) C.3);`harnesses[h].reason` / `why`,以及 `critical[]` 里 `harness` 经 `harnessKey()` 等于它的项;采集服务整个没在采时改用采集服务那句话 | 筛选后为空、`h` 正好点了一个 agent、且上述任一条成立 |

`/api/status` 只在**进入**「还没有会话」或「筛选后为空且点了 agent」状态时读一次,句子后写「截至」那一刻;会话库不轮询它(只有总览页、采集页、采集记录轮询采集健康,见 [1.5](1.5-states-aesthetics.md))。第一个会话到来时,`/api/sessions` 的轮询把空态换成列表,不留残余([1.5](1.5-states-aesthetics.md) 空态转实时)。

若回放台把读者送回会话库并带一句话(归 [1.2](1.2-shell-layout.md) §路由),这句话用 toast 显示一次,不写进页头或表格。

## 一件事只说一处(MUST)

- 被截断的单元格(标题、项目、host)**MUST** 带 `title`。
- 守卫:`test/web-v2/library.test.mjs`(只有页头一个时间窗控件;每个被截断的单元格有 title)。
- 本页不写会话数、估价与单价提示,也不画「正在跑」的颜色条(依据:本单元 Goal、Plan「没有一个统计数字」、砍掉的(计数、「进行中」)与 [1.5](1.5-states-aesthetics.md) §数据规则)。

## 标题规则

按顺序取第一个有的:

1. `sessions[].title` 不为 `null` → 原样显示;它从哪来由 `title_source` 说(`harness-local-store` = agent 自己的本地存储,不是采集到的线上字节,[4.4](4.4-server.md) §人类标题的来源;`wire` = 采集到的字节),写进悬停。
2. 否则 → 「未命名会话」。会话 id 只在悬停里,不拼进标题。

标题不带「推测」标:文档里没有说标题是猜的字段([1.5](1.5-states-aesthetics.md) §数据规则),看板也不自己再推一遍。依据:[1.6](1.6-cli.md) C.5 `sessions` 是形状的权威(标题只有 `title` 与 `title_source`)与 D24。

会话库不显示同名会话的猜测([1.2](1.2-shell-layout.md) §会话头 的「确证血缘与同名猜测要视觉区分」只约束显示同名猜测的地方,这里不显示)。

## 搜索、筛选、排序、分组

- **搜索**:不分大小写的子串匹配,范围 = 标题(`title`)、项目名、`session_id`。
- **Agent**:可多选;一个会话的 `harness`(`sessions` 的多 harness 字段 之后是 `harnesses[]` 里任一个)在所选之内就算匹配。路由里的 id 先过 `harnessKey()`,所以从采集页带来的 1.6 命令行 id(`claude-code` 这类,[1.6](1.6-cli.md))与读取侧 id 等价。未识别的 agent 用 `h=-` 表示,能单独筛出来,从不悄悄丢掉。
- **项目**:按 `project_slug` 等值筛。
- **时间窗**:`last_ts` 落在窗内(含边界)才算;`last_ts` 为空的会话只在「全部」里。与总览页的统计窗同一种算法(会话的最后一次调用落在窗里)。
- **排序**:「最近」= `last_ts` 新的在前,没有时间的排最后;「模型调用」= `calls` 大的在前,相同时按最近。
- **分组**:只在「最近」排序下,按 `last_ts` 的本地日期分「今天」「昨天」「更早」,没有时间的放「没有时间」组。

**路由参数**:路由与参数表归 [1.2](1.2-shell-layout.md) §路由。本屏用 `q`、`h`(可带多个 agent,写法按 1.2)、`project`、`window`(`24h` / `7d` / `all`,缺省 `all`)。另有两个会话库自己的状态参数:`sort`(`calls`;缺省是最近)与 `sel`(高亮行,`<project>::<id>`),由 1.2 §路由 一并登记。只写与缺省不同的参数;读到不认识的值退回缺省。改筛选用替换式写 URL(不是一次导航)。

## 保真边界(不变式 4)

1. **标题是便利标签**:`title_source:'harness-local-store'` 的 `title` 来自 agent 自己的本地记录,不是采集到的字节([4.4](4.4-server.md) §人类标题的来源:MUST 标为便利标签)。落点 = 「会话」列头的 ⓘ 与每行标题的悬停,来源句按 `title_source` 写。守卫:验收断言 2。
2. **推测要标出来**:UA 推出的 agent(「推测」)、合成键归组的会话(「会话边界是推测的」),都在行上可见,不只在悬停里。守卫:验收断言 2、4。
3. **只说「有」,不说「没有」**:`has_subagent` 今天只认 Claude Code 的请求头;别的 harness 即使有子 agent 也是 `false`。所以只在为真时标「含子 agent」,从不显示「不含」。守卫:验收断言 4。
4. **模型调用数不偷算**:`calls` 不含只记日志的调用和 token 计数;两者分别用「只记日志 N」「只有 token 计数」说出来。守卫:验收断言 1、4。
5. **列表读全了没有要说**:读不全(文档的 `errors[]` 非空)落说明行,每条的 `where` · `reason` 进「技术细节」——不把「没读到」说成「没有」(D38,[4.4](4.4-server.md) `GET /api/sessions` 行)。守卫:验收断言 8、9。
6. **一行只代表一个会话 id**:服务今天只按会话 id 归组,几个 harness 的记录碰巧同 id 时会并成一行,行上只显示第一个带 `proc` 的记录的 agent。`sessions` 的多 harness 字段 之后标「多个 agent」;之前这一行不加标(`provider:'mixed'` 说的是几种线格式,不是几个 agent,不能拿来推)。按 (harness, id) 归组是 [3.4](3.4-session-identity.md) 的后续。守卫:验收断言 5。
7. **不显示「进行中」**:没有字段说一个会话还在跑;按最后活动时间猜会在采集停了之后照样亮。守卫:收尾审查(本屏没有这个元素,`labels/library.mjs` 里没有这个词)。

**D64 的那条线**:从点一行到回放台画出这一步 ≤ 0.5 s(p50 与 p95 都算),阈值与记法在 D64 一处;打开时并行取这一页的会话、单价与采集状态,先到的先画,`GET /api/session` 一条就够画出第一屏。守卫:`test/web-v2/browser/` 的浏览器套件(阈值读 `test/web-v2/perf-lines.mjs : BOARD_LINES`,D64)。

## Edge cases

- **`last_ts` 为空**:最后活动写「—」;只在「全部」里;排在最后;归「没有时间」组。
- **`calls` 为 0、`probes` 为 0**(会话里只有非模型调用的记录):写「0」,不加标;打开后回放台显示 [1.5](1.5-states-aesthetics.md) 的「会话里没有模型调用」状态。
- **`calls` 为 0、`logged` 大于 0**:写「0」加「只记日志 N」;悬停说明这 N 次不算进模型调用数。
- **很长的标题**:一行放不下时在末尾省略,不从字中间截;全文在悬停里。
- **两个会话同名**:不做同名猜测;悬停里的会话 id 区分它们。
- **路由带来未知的 agent id**(比如旧链接):照样筛;筛空时那一行写「未识别的 agent」并跟着那个 id。
- **`sel` 指向列表里没有的会话**:高亮第一行。
- **轮询时有人在打字**:搜索框不被改写;打开着的项目下拉不被重建。
- **采集状态读不出**(`status` 不带 `health`、`errors` 里有 `capture health`):空态第二行写「读不到采集状态」,不留空(K-29:原因不在正文,在技术细节)。
- **几千个会话**:虚拟列表只画看得见的行;筛选是一次线性扫描。
- **时钟偏了**:`last_ts` 晚于现在时按「刚刚」显示,归「今天」组。

## Risk / 回滚

- 会话库是 `/api/sessions` 加路由参数的纯函数,出问题可单独退回上一个绿点;不碰服务端数据。
- 读取健康从横幅改成说明行,风险是丢掉某个事实:断言 8 保留旧横幅测试的每一条,外加新的「未计数」「其余没读的」两条。
- 组名行比会话行矮:`core/vlist.mjs` 的 `rowHeight` 可以是数字(定高)或按行取高度的函数,用前缀和定位行;会话库的滚动计算用同一份高度。
- `sessions` 的 `title_source` 在大存储上的读时补算有开销(风险与界限在 [4.4](4.4-server.md));补算回来之前会话库显示「未命名会话」,补算后下一次轮询换上。
- Agent 筛选从带数字的小标签改成菜单,多点一下;换来页头区没有数字。

## Extensions

- **每个会话的统计列**:若以后要在会话库里看花费或断开,走具名查询(D24),列头写「截至 as_of」,与实时列表分开标;先过 grep-spec 自对照。
- **更多 harness 的标题与项目**:各 harness 自己的本地标题来源经 adapter 提供中立的「标题」([4.4](4.4-server.md) Extensions);项目可取查询 `sessions.cwd`(今天只有 Claude Code 的请求体里有)。
- **开始时间与时长**:会话元数据加 `started_ts` 后再加列。
- **「进行中」**:只有当采集器给出「会话仍开着」的事实字段时才加。
- **按 (harness, id) 归组**:[3.4](3.4-session-identity.md) 与 `src/view/board.mjs` 的后续;落地后「多个 agent」这个标就很少出现了。
- **更多 harness 的子 agent 识别**:把 Codex、dsh、Z-Code 的子 agent 线索折进 `has_subagent`,本屏不改。
