# trocar · RFC 4.1 — 采集源与统一原始信封

> **服务意图(A2)**:跨切「适配层通用」(AC-3)的**最上游**——采集源是「拿到 bytes」的那一端,把各 harness 的真实流量喂进 ①(逐字上下文/回复供回放)与 ②(真实 usage 供 cache 叠加)。也是 [1.1](1.1-product-definition.md) 六要素#5「委派代价」的承载点:把采集委派给采集器,须配 `trocar doctor` 的「测试」兜底。
> **受众**:人(核对四问——**是否真在抓 · 抓得对 · 凭据没漏 · 没弱化全机 TLS**)+ agent(据此实现采集源)。
> **前置**:输出 = **统一原始信封**,交 [3.1](3.1-adapter-contract.md) adapter 解释、[4.2](4.2-storage-etl.md) 存储;身份信号见 [3.4](3.4-session-identity.md);采集安全的**单一权威 = 本文件 §采集安全**。与 adapter **正交**:源管「怎么拿到 bytes」,adapter 管「bytes 什么意思」。

> **采集器(D31 · D32 · D37)**:唯一的采集源是按进程透明采集器([4.6](4.6-process-collector.md)),七个 harness 全走它;信封契约(§统一原始信封)由它与读取侧共用,4.6 只追加字段;WebSocket 信封另改了 `req_body` / `resp` 在 WS 上的含义(见 [3.2](3.2-normalized-model.md) §D37 结构性变更)。

> **D40(2026-10-07)**:非 LLM 调用不再是保真例外——请求体与 LLM 同一规则逐字存,统一经 `buildEnvelope`;每个 (harness, 流量类别) 可由操作者设成 `full` 或 `log`(只记日志),并显示各自占多大;4.6 采集器默认解密已信任 agent 进程的全部 TLS。下文各处已按 D40 改,见 [0.0](0.0-overview.md) D40 行。

## Goal
定义**采集源的产物契约**:无论拿到字节的机制是什么(Linux 的内核改写、Windows / macOS 的引擎代理入口),都向下吐**同一个统一原始信封**,使 trocar 其余层对「抓的哪个 harness、跑在哪个平台」**无感**。唯一的采集源是按进程透明采集器([4.6](4.6-process-collector.md))。**无操作者意图时观测唯一**:采集源不 originate 请求、不改写流量、不用被测程序 token 发起调用(不变式 1([0.0](0.0-overview.md) §核心不变式),**必拒违反**);拦截 / 修改 / 重发只出于本机操作者的显式操作([5.1](5.1-intervention.md),D30)。

## Definitions
- **采集源(capture source)**:拿到字节的机制 + 把它写成统一信封的模块。现只有一个:按进程透明采集器([4.6](4.6-process-collector.md));引流机制按平台分:Linux = 驱动模式(eBPF),Windows / macOS = 代理模式(引擎自己当本地代理,D47)。
- **统一原始信封(envelope)**:一次上游交互的归一记录形状 `{ts, endpoint, method, req_headers, req_body, resp}`(承 [3.1](3.1-adapter-contract.md));采集器写、读取侧读,`capture` 标签说明引流方式。
- **采集目标(capture target)**:被识别出且已确认信任 trocar CA 的 agent 进程的连接(D31);D40 起默认解密它的全部 host(`auto` 是操作者可选的收窄,[4.6](4.6-process-collector.md) §引擎「解密策略」)。其余进程的连接不经引擎。
- **采集点(steer point)**:把被测流量精准引到引擎的地方——Linux = 内核对该进程 `connect` 的改写,Windows / macOS = 该 agent 自己的代理入口(写进它的配置)指向引擎的回环门,**非整机系统代理**。

## Plan(选定方案 + 取舍)

**选定**:**按进程透明采集器是唯一的采集源**(D31 · D37),七个 harness 全走它;信封统一,引流机制随平台走([4.6](4.6-process-collector.md) / [4.8](4.8-win-collector.md) / [4.9](4.9-macos-collector.md))。

**取舍**:机制随平台分化,但**向下的信封统一** → 上层(3.1/4.2/前端)对平台与 harness 无差别,「适配缝」在采集端也不漏(不变式 3,**需 RFC 才放行**才能破)。

## 凭据处置

**决定**:采集**逐字存储**请求头,包括 `authorization` / `x-api-key` / `cookie` /
`proxy-authorization`。

**理由**(两条,第二条是产品自身的一致性问题):
1. **部署面**:trocar 是**单用户 · 本机 · loopback**的个人研究仪器,凭据在本机上已由文件系统保护;
   为它维护一条改写防火墙属于「节外生枝」。
2. **保真**:trocar 的全部意义是展示**真正上过线的字节**,而 `<redacted>` 恰恰是对这些字节的**改写**。
   脱敏让采集在自己最核心的那一层变得**非逐字**,与不变式 2/4 的精神相抵。

**红线是文件权限。** 字节里有活凭据,故唯一成立的保证是「除属主外无人可读」(对文件成立;D36 起同一台机器上可能有别的系统用户,共用 `127.0.0.1` 的看板 / API 会把采集再暴露给他们,缺口见 [4.4](4.4-server.md) OPEN):
- 采集文件 MUST 以 **0600** 创建(采集器的记录存储 `createRecordStore`,`src/collector/core/record/store.mjs`,用 `open(…, 'a', 0o600)` + `fchmod`,
  兼顾已存在的 0644 文件——0644 即全机可读)。封存文件、封存用的临时文件、`trocar raw export` 的输出同样带凭据,MUST 在 open 时就以 0600 创建(D35)。
- `trocar doctor` 的**硬失败(exit≠0)**是
  **「有采集文件可被 group/other 读取」**(④b · `qFilePerms`;D35 起扫描面 MUST 含封存文件与默认导出目录 `~/.trocar/export/`,并有测试;[1.6](1.6-cli.md) R2 的备份目录 `~/.trocar/backup/` 同样在内:里面是用户配置文件的原样,常含令牌)。退出码按 [1.6](1.6-cli.md) R4:失败 = 1(文案「采集文件可被他人读取」);**零条记录、没核任何文件、有文件的权限读不出来、有采集文件没读完整 = 无法判定 = 3**,既不是过也不是失败(「核到零条」报「过」会让人以为权限已经核过);已发现的失败压过判不了。
- ③ 退化为**如实报告**:有多少条记录带凭据(**不判失败**),外加保留「空扫描不得认证任何事」守卫。

**查询文档遮挡值**(见 [2.6](2.6-detail-panel.md) §保真边界 2):`calls`、`session` 等每份查询文档把凭据类头(`SECRET_HEADERS`)的值置空,头对象与原始头 `req_head_raw` / `resp_head_raw` 都是(头名保留);`calls` 带 `ref` + `reveal=<头名>` 给出那一个值。存储逐字不变;`trocar raw` 照存的字节给出。

**MUST NOT**:把凭据用于任何请求 —— 不变式 1([0.0](0.0-overview.md) §核心不变式) 的 token 条款**不受本决策影响**,
凭据怎么用见 **D30**:只有本机操作者显式触发的「改后转发」与「重发」会带着被测程序的凭据发出,且逐次审计;除此之外 trocar 不以任何方式使用这些凭据。本决策只改**存储**,不改**使用**。

**已知残余风险(如实记录,非借口)**:[4.4](4.4-server.md) §服务形状「反 DNS-rebind 门」记载的 DNS-rebind 攻击面,能从 `/api/*` 拉出整份逐字语料。凭据入库,同类缺陷的爆炸半径就是「密钥泄漏」而不止「对话泄漏」。反 rebind 门
(Host allowlist + Origin 校验)是该风险的**唯一**屏障,`test/server-rebind.test.mjs` MUST 保持绿。
另:`~` 常处于 iCloud / Time Machine 备份范围内,凭据会随备份离开本机。

## 采集安全(违反=必拒)

1. **只解密采集目标(必拒)**:采集器 MUST 只 TLS-解密识别出且已确认信任 trocar CA 的 agent 进程的连接(D31;D40 起默认解密该进程的全部 host,`auto` 是操作者可选的收窄,[4.6](4.6-process-collector.md) §引擎「解密策略」);其余进程的连接一律不经引擎,识别出但不解密的连接盲透传。扩大到未识别的进程 = 必拒。
2. **精准引流,不动整机系统代理(必拒)**:Linux 由内核只改写识别出的 agent 进程的 `connect`(驱动模式);Windows / macOS 由该 agent 自己的代理入口指向引擎的回环门(代理模式)。MUST NOT 把整机流量路由进引擎,MUST NOT 动系统代理、开 TUN(D31 · D43,Non-Goal)。
3. **CA 只进用户级信任库、绝不全机弱化 TLS(必拒 · 平台中立原则)**:采集器 CA 由 `install` 装、`uninstall` 撤,`on` / `off` 不碰(D55)。macOS / Windows:`install` 把每台机器自己生成的根装进用户级信任库(OS 的框即同意),根的私钥不能导出,见 D57 与 [4.11](4.11-collector-model.md)。Linux:`node:crypto` 自签的 `~/.trocar/collector/ca/`(私钥 0600),信任入口见 [4.6](4.6-process-collector.md) §身份与信任。机器级信任库要用户自己提权,trocar MUST NOT 写(`/etc/ssl/certs`、`update-ca-certificates`、LocalMachine\Root、System 钥匙串等)。

## 自检(`trocar doctor`)

每个采集源配一个**「测试」**兜底(1.1 六要素#5「把委派代价压到最小」):`trocar doctor` 回答四问——是否真在抓 · 抓得对 · 凭据没漏 · 没弱化全机 TLS——即 §验收 的可跑 check 的 CLI 化(`src/capture/selftest.mjs`);其余几问供人核对(承 §受众:人)。「凭据没漏」的硬红线是 ④b「采集文件仅属主可读」(§凭据处置);③ 只如实报告有多少条记录带凭据。

> **保真边界(UI MUST 就地标注)**:① `req_headers` 全部逐字(含 `authorization` 等,保护手段是文件权限,见 §凭据处置),不标;② SSE 的 `resp.raw` 是解压后的原文(未压缩的回复即线上字节;带 `content-encoding` 的回复,线上字节在 `resp.wire_b64`,没有它的记录标「压缩回复只存了解压后的文本」),`kind:'sse'` 的重建体(text / thinking / tool_use / usage……)与 `raw_sse` 是派生的。**重建器是 Anthropic 事件形状**;对其不识别的 provider(OpenAI **Responses**/Codex)重建结果为空,其 blocks 由 [3.1](3.1-adapter-contract.md) OpenAI dissector 从 `raw_sse` 重建;③ `tools` 现逐字采集(D15),但 **D15 之前的旧 trace** 仍只有元数据 → UI 每块标 `verbatim`/`metadata` 区分;D40 之前的非 LLM 调用只有 `{raw_chars}`,标「本条采于 D40 之前,只存了长度」;D40 起非 LLM 逐字,只有操作者设为 `log` 的类别没有体,标「只记日志」;④ 没留载荷的 WebSocket 帧(`log` 级与 D40 之前的记录)标「非逐字」,超 64 MiB 的调用标「已截断」,采集端解不出的压缩请求体标「压缩请求体未解码」([4.6](4.6-process-collector.md) §传输与帧级记录、§记录);⑤ JSON 响应体(LLM 与非 LLM 都一样)存的 `body` 是解析后的对象,写盘时重序列化,不是线上原字节:空白、数字写法、超出 2^53 的整数、重复的键、整数形的键序都可能变。**D40 审查起**:线上原文与 `JSON.stringify(body)` 不等时,同一个 `resp` 里另存 `raw` = 线上原文(`parseJsonReply`,`src/capture/request-body.mjs`);相等时不重复存。读取侧有 `raw` 就显示 `raw`、不再显示重序列化的版本,看板对它不带「非逐字」标。**D40 审查之前的记录**没有 `raw`、也没有 `body_wire_bytes`:读取侧就地标「JSON · 重新序列化,非线上原字节」(`resp-json-reserialized`,不变式 4)。这些 MUST NOT 让人误以为看到的是完整线上真相(不变式 4,**必拒隐瞒**)。

## Edge cases
- **压缩响应**(br/gzip/deflate):观测侧解压(`decodeContent`)后重建,**客户端仍收原始压缩字节**。
- **非采集目标**:未识别的进程不经引擎;识别出但不解密的连接(未信任、策略外、负缓存……)原样透传,只在 `flows/` 留元数据(采集安全#1;[4.6](4.6-process-collector.md) §引擎)。
- **非 LLM / 控制面流量**(telemetry、registry、account、会话同步、上传下载):信封 `is_llm_call=false`;D40 起请求体与 LLM 同规则逐字,响应同 LLM;UI 不标「非逐字」,只在截断、未解码、只记日志时各标各的。D40 之前的旧记录只有 `{raw_chars}`,标「本条采于 D40 之前,只存了长度」(`raw_chars` 为 0 的除外:那是没有体的调用,如 GET `domain_info` / 列会话,没有丢任何东西,读成空体、不标)。别的 host 上的辅助模型调用是推理;**session 内的非推理调用(`probe` / `other`)的体存在采集记录里,看板只在 probe 详情里说明体在哪,不显示体**(见 [2.6](2.6-detail-panel.md) §C)。
- **大的非 LLM 体**(文件上传、更新包下载):超 64 MiB 只存前缀,标「已截断」,`body_wire_bytes` 给出线上全长;二进制存 base64,一行约是体的 4/3。
- **类别认不出**:落 `other`,默认 `full`;漏写一条模式不丢数据,只是归错类。
- **并发多 session 同 harness**:采集源只吐信封不判身份;归并靠 [3.4](3.4-session-identity.md) 的线上信号,与本层正交。

## Risk / 回滚
- 采集器是**旁路观测**,关闭 = `trocar off`(撤引流与信任入口),被测程序直连,**零残留**(见 [4.6](4.6-process-collector.md) §开关语义;代理模式下 `on` 期间启动的 agent 重启前仍连着引擎的门、只转发,是 [0.0](0.0-overview.md) D39① 登记的例外)。
- 加一个采集机制**不改信封契约** → 不碰 adapter/前端(AC-3 在采集端的对应)。
- **非显然坑**:MUST NOT 未经用户同意重启 Desktop / 停在跑的采集(会杀会话、丢采集)。
