# trocar · RFC 4.3 — 解析 / 索引 / 缓存

> **服务意图(A2)**:意图 ①② 的**性能使能层**——让大 session 在 scrub 与跟随下,忠实回放(①)与 cache 叠加(②)仍**即时**,不因"反复解析卡顿"退化到不可用。本模块是 [0.0-overview](0.0-overview.md) **D5 的动因**(每 poll 全量重解析的痛)与 **D6**(轻框架 + 虚拟化)的落点。
> **受众**:人(核对缓存**不会**变成第二源真相)+ agent(据此实现派生缓存、失效键、窗口保留)。
> **前置**:索引(去重键)= [3.2](3.2-normalized-model.md) 的 `content_hash`(**本模块承之、不另定**);查询、分页、增量页、温缓存与堆预算的契约 = [3.5](3.5-query-layer.md) §访问模式(**权威**,本单元只说缓存怎么键、怎么失效);解析动作本身(adapter)= [3.1](3.1-adapter-contract.md),原始记录与段索引 = [4.2](4.2-storage-etl.md);实现符号:`warmCache`(`src/query/warm.mjs`)/ `createAssembler().bodyOf` / `cacheBreak` / `playheadSig`。

## Goal
在**原始记录与段索引(4.2)与前端部件(2.x)之间**架一层**派生缓存 + 窗口保留**,使"某步的摊平块列表、每 call 类型构成、相对上一 call 的 cache-break、一页答案"这类**贵**的产物**算一次复用、只为页上的调用留正文、可从源重建**。核心约束:缓存是**可重建的派生投影**,原始 NDJSON(源)**永不被它覆盖或绕过**(承不变式 2);缓存命中与不命中答出的文档逐字节相同([3.5](3.5-query-layer.md) §谁执行它)。

## Definitions
- **派生产物(derived artifact)**:非源真相、可由原始记录重算的中间结构。① 摊平块列表 `flat`(`linearContext` 的 tools→system→messages 有序块);② 每 call 类型构成 `comp`(UTF-8 字节占比,token 占比的廉价代理;折叠时由 `compBuckets` 算好、随每个调用的 meta 下发,看板的 `callComp` 取它);③ cache-break 散度点(`cacheBreak`,同车道相邻 call 首个不同块);④ 会话骨架(折叠后每个调用的轻量 meta,[3.5](3.5-query-layer.md) §内存有界);⑤ 答过的答案字节串。
- **记忆化(memoization)**:落在**守护进程的查询工作进程**里(D63;没有守护进程时在提问的进程里,同一份代码)。每份缓存的键都是它依赖的东西的**身份**(段文件的 stat、记录 id、会话的段索引行、解析出的块对象、名字声明的 `version(ctx)`),不是时间也不是条数;全部缓存共用 [3.5](3.5-query-layer.md) §内存有界 的一个堆预算(`heapBudget()`),在计算之前让位。
- **失效键**:一个廉价的身份,身份没变则跳过整轮重折或重画。服务端:段文件的 (大小, mtime, ctime)、会话读的段索引行、名字的 `version(ctx)`;看板:`lastCheapSig` / `lastRenderSig` / `playheadSig`(`src/web/v2/replay/replay.mjs`)。
- **索引(index)**:跨 call 复用块的去重键 = [3.2](3.2-normalized-model.md) 的 `content_hash`;**本模块只消费,不重定义**。
- **窗口保留(window retention)**:逐步的 cache-break 与前缀链要拿每个调用与同车道上一条比,所以**每个调用都折**(按步序摊平、比完);折完只留轻量 meta,**只有页上的调用带正文**,其余标 `paged_out`。负载随页窗口涨,不随会话涨。

## Plan(选定方案 + 取舍)

**选定:三件套 = 按身份键的派生记忆化 · 承 3.2 的去重索引 · 窗口保留 + 分页(承 D6)。**
1. **按身份键的记忆化**:段索引行按段文件的 stat 记,回读的记录按记录 id 记,会话骨架按会话的段索引行记(长了就接着折新行),页正文按调用对象记在骨架里,答案按请求与 `version(ctx)` 记,块的字节数 / 键文本 / hash 键 / 资源引用按解析出的块对象记;看板按签名跳过重读与重画。缓存**只装可重建的**,miss 即从段与段索引重算。
2. **索引承 [3.2](3.2-normalized-model.md)**:**cache-break 是相邻 call 的块键序列 diff**,折叠时由查询算好(`src/view/analyze.mjs : cacheBreak()`),随调用的 meta 下发,**不在前端逐块比全文**。
3. **窗口保留 + 分页(承 D6)**:每个调用都折、只留 meta;页上的调用由 `bodyOf()` 从它的记录现算正文;跟随时用增量页只取变了的部分([3.5](3.5-query-layer.md) §访问模式「增量页」);长 block 体默认折叠、首次展开懒填;超长内容**显示截断**并标(见「保真边界」)。

**备选(未选)**:
- ① **每 poll 全量重解析**(D5 的痛):每 1.5 s 从头折整场会话 → 大 session 每次轮询 O(会话) 的 CPU,且重画抹掉用户刚展开的块。
- ② **只摊平当前 + 前一 call**:逐步的 cache-break 与前缀链要每个调用都与同车道上一条比,时间轴的每一格都要它,只摊平两条给不出这些。
- ③ **服务进程内按 `call_id` 键的 LRU**:页上的调用之外没人要它的 `flat`;骨架、页正文与答案字节按身份记,命中直接省掉整轮折叠,按调用记只省一小部分。
- ④ **把派生产物持久化**:车道基线与链计划是折叠的中间态,落盘要很多代码;`flat` / `break` 是视图态,塞进中心契约([3.2](3.2-normalized-model.md))会让 schema 随 UI 抖动(见 Extensions)。

**取舍**:缓存只承载"可重建"的派生;源只有原始记录。两层靠身份键(时间对齐)与 `content_hash`(内容对齐)咬合。**任何派生产物 MUST 可被丢弃后从原始记录逐字重建**——这是它不成为第二源真相的凭证(必拒违反;兜底:验收 #3)。

## 三件套的具体机制

### 1 · 按身份键的记忆化 + 失效键
- **服务端的缓存与它们的键**(都在查询工作进程里,共用一个堆预算;键都是身份,所以没有"过期但没被发现"的条目):

  | 缓存 | 键 | 落点 |
  |---|---|---|
  | 段索引行 | 段文件的 (大小, mtime, ctime)(`statKey()`);整份行表从第一个动了的段起重建,哪个段都没动时交回同一个冻结的数组 | `src/query/index-build.mjs`(`warmCache`);`src/query/rows.mjs` |
  | 回读的记录 | 记录 id(记录只追加、从不改写,不变式 2,所以键不带戳) | `src/query/records.mjs` |
  | 会话骨架 | 会话的段索引行(`rowsKey()`);行变多就接着折新行,按 [3.5](3.5-query-layer.md) §缓存按依赖失效 只重折晚到记录所在的车道 | `src/query/named/session.mjs` |
  | 页正文 | 骨架里按调用对象记的 `bodyOf()` 结果,按字节有上限、计进骨架的堆代价 | `src/view/board.mjs : sessionFold()` |
  | 答案字节 | 请求(名字、参数、缩进、gzip)+ 名字的 `version(ctx)`(只读段索引行) | `src/query/answers.mjs` |
  | 块的派生 | 解析出的块对象(按契约只读,`src/dissect/request-body.mjs`)→ 字节数、键文本、hash 键、资源引用,WeakMap | `src/view/blockmeta.mjs`;`src/view/analyze.mjs` |
  | 封存段的读者 | 一次同步读里打开的封存段共用一个帧缓存与一个行缓存,这次读让出时关掉 | `src/query/records.mjs` |

  读失败的结果从不被记住;`errors` 多于版本自带的索引问题的答案不进答案缓存。
- **看板的签名跳过整轮**(`src/web/v2/replay/replay.mjs`):`lastCheapSig`(会话列表里这一会话的调用数与末条时间 + 页窗口)相同 → 不发这次读;`lastRenderSig` 相同 → 不重画,只刷新头部;`playheadSig`(播放头那几块面板画的东西)相同 → 窗口、提纲、资源与原始面板不重画。签名 MUST 覆盖"会改变画出结果的一切最小充分信号";签名**过窄**(漏掉一种变更)= 显示旧字节 = **谎报 AC-1(必拒)**;过宽只损性能。读失败时两个签名都清空,下一次照读。
- **UI 局部态跨重画存活**:展开的块集(`openBlocks`)、展开的 turn(`turnFold`)在答案到来、签名命中或重画时 MUST 存活;只在播放头换到另一个调用或换会话时清 `openBlocks`——否则跟随时每 1.5 s 把用户正在读的块折回去。

### 2 · 索引:content_hash 去重 → cache-break 是相邻键序列 diff(承 [3.2](3.2-normalized-model.md)/[3.5](3.5-query-layer.md))
- **cache-break 是一句 diff**:同车道相邻 call 的块键序列比对,首个不同位置 = 结构散度点(`cacheBreak(prevFlat, curFlat)`)。查询在折叠时算好,散度点须与 [3.3](3.3-cache-model.md) 的 `structural_divergence_seq` 一致,且**MUST 标"结构参考,非真实 cache 边界"**(数值真相取真实 usage,见 [3.3](3.3-cache-model.md))。
- **跳过 `volatile` 块**:cache-break 比对 MUST 跳过 volatile 块(CC billing nonce:bytes 每 call 变但不入 cache key),否则每 call 误触发散度。
- **保真边界(bounded-prefix hash)**:`blkKey`(`src/view/analyze.mjs`)对块前 **4096 字符**取 hash(O(1)/块,与块大小无关)——这对"廉价内存 cache-break 启发式"足够,但**MUST NOT** 用作 [3.2](3.2-normalized-model.md) 去重 PK(两个仅前缀相同的长块会碰撞、丢差异)。**产品的 `content_hash` = 全内容抗碰撞 hash;bounded-prefix 只许用于内存态启发式**——算法全局钉死在 [3.1](3.1-adapter-contract.md) `parseBlocks`。

### 3 · 窗口保留 + 虚拟化(承 D6)
- **每个调用都折,只留 meta**:`createAssembler().push()` 按步序把每条记录折进它的车道,与同车道上一条比完前缀链与 cache-break 就放手块,只留 meta;页上的调用由 `bodyOf()` 从它的记录现算正文(结果记在骨架里,下一次轮询只算页上新出现的)。页窗口与正文预算见 [3.5](3.5-query-layer.md) §分页;页外的调用带 `paged_out:true` 与 meta 闭集 `PAGED_META`。
- **块体懒填 + 折叠**:block 卡默认只渲头,首次展开经 `text_ref` 回源懒填全文(`toggleCtxBlock()` → `fillBody()` 的 `dataset.filled` 门,承 [2.3](2.3-context-window.md) 的懒加载);取失败的不算填过,下次展开再取。
- **大结果分页 / 游标 / 增量**:跨 session 聚合与会话回放都走 [3.5](3.5-query-layer.md) 的分页契约;跟随一场在长的会话走增量页,不一次拉全表。

## 保真边界(必拒隐瞒 · 承不变式 2、4([0.0](0.0-overview.md) §核心不变式))
- **缓存是派生,永不覆盖源**:任何缓存条目 MUST 可丢弃后从原始 NDJSON **逐字重建**;缓存层 MUST NOT 成为唯一副本、MUST NOT 有损改写。
- **显示截断就地说**:超长 block 体按显示上限截断(`src/web/v2/replay/blocks.mjs` 的 `DISPLAY_CLIP` 字符,`clipText()`:截成源的前缀并说出全长)——这是**显示态截断,非数据丢失**:源 bytes 完整、可回源取全。未标即让人误判"看到的是全文"(违反不变式 4)。
- **廉价代理标注**:`comp` 用 UTF-8 字节占比作 token 占比代理(非真实 token 数),UI 呈现处 SHOULD 注明"字节占比,非 token"。
- **缓存 miss 不得供旧/错**:键是身份,身份没变才复用;**MUST NOT** 在数据已变时供旧缓存(供旧字节 = 谎报 AC-1,必拒)。

## Out-of-scope
- 块**怎么被解析出**(adapter)→ [3.1](3.1-adapter-contract.md);**查询 / 分页 / 增量页契约与堆预算** → [3.5](3.5-query-layer.md);段与段索引 → [4.2](4.2-storage-etl.md)。
- cache **数值真相 / break_kind** → [3.3](3.3-cache-model.md);块卡**渲染** → [2.3](2.3-context-window.md);时间轴柱**绘制** → [2.1](2.1-track-widget.md)。
- 传输 = 服务端 API(**D11**)与守护进程的查询工作进程(D63)。

## 影响面
上游读原始记录与段索引([4.2](4.2-storage-etl.md))+ [3.5](3.5-query-layer.md) 查询;下游供所有 [2.x](2.3-context-window.md) 部件的即时渲染。改失效键 / 缓存粒度 = 改性能与正确性接缝;改去重键语义 = 触 [3.2](3.2-normalized-model.md) 中心契约 → **走 [0.1](0.1-engineering-rules.md) 的 grep-spec 自对照闸(需 RFC)**。

## 验收(可跑 check)
上表六条的守卫测试都在 `npm test` 里、保持绿:
1. **记忆化 ≡ 重算**:任何缓存命中的答案与清空缓存后重算的逐字节相同;读失败从不被记住。
2. **窗口保留**:每个调用都折出 meta;只有页上的调用带正文;负载随窗口而不随会话涨。
3. **可从源重建(派生非源)**:删掉全部派生(段索引、缓存)后答案逐字段相等。
4. **失效键正确**:(a) 同一步的答案 → 签名命中 → 不重画,展开的块存活;(b) 追加一条记录 → 下一次查询包含它。
5. **cache-break via index**:散度点与 [3.3](3.3-cache-model.md) `structural_divergence_seq` 一致,`volatile` 块被跳过。
6. **截断标注 + 可回源**:显示截断就地说全长,回源可取完整 bytes。

## Edge cases
- **超大 session(数千 call)**:堆预算、骨架接着折、窗口保留与增量页兜住;连骨架都放不进预算时按 [3.5](3.5-query-layer.md) §内存有界 截断并在文档的 `truncated` 写明。缓存逐出只损花费:miss 时从原始记录重算。
- **live 追加与并发**:轮询期间段在长——段文件的 stat 变了 → 段索引行重建 → 会话的行变了 → 骨架接着折、答案缓存的版本不再相同;记录 id(`<段>:<序号>`)只追加不复用,所以按 id 记的回读不带戳。
- **compaction 步**:message_count 骤降触发的换血(见 [3.4](3.4-session-identity.md)),cache-break 在此步落到**首个 messages 块**(tools+system 存活),缓存 MUST 反映此结构跳变,不复用跨 compaction 的旧散度。
- **DeepSeek `cache_write=NULL`**:cache-break 是纯结构 diff、与 usage 无关,NULL 不影响本层;数值叠加容 NULL 由 [3.3](3.3-cache-model.md)/[3.5](3.5-query-layer.md) 负责。

## Risk / 回滚
本层是**纯派生**(原始记录 → 缓存),零副作用于源。缓存 / 失效逻辑改动用固化真实记录回归;**最大风险 = 失效键漏检导致供旧字节**——由验收 #1、#4 守;一旦怀疑,**MUST 优先牺牲缓存命中率保正确**(关掉缓存全量重算是安全默认)。
