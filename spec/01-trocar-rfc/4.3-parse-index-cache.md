# trocar · RFC 4.3 — 解析 / 索引 / 缓存

> **服务意图(A2)**:意图 ①② 的**性能使能层**——让大 session 在 scrub 与跟随下,忠实回放(①)与 cache 叠加(②)仍**即时**,不因"反复解析卡顿"退化到不可用。本模块是 [0.0-overview](0.0-overview.md) **D5 的动因**(每 poll 全量重解析的痛)与 **D6**(轻框架 + 虚拟化)的落点。
> **受众**:人(核对缓存**不会**变成第二源真相)+ agent(据此实现上下文投影、派生缓存与失效键)。
> **前置**:索引(去重键)= [3.2](3.2-normalized-model.md) 的 `content_hash`(**本模块承之、不另定**);查询、会话读、温缓存与堆预算的契约 = [3.5](3.5-query-layer.md) §访问模式 与 §会话读(**权威**,本单元只说投影与缓存怎么存、怎么键、怎么失效);解析动作本身(adapter)= [3.1](3.1-adapter-contract.md),原始记录与段索引 = [4.2](4.2-storage-etl.md);实现符号:`warmCache`(`src/query/warm.mjs`)/ `src/query/projection.mjs` / `extract()` · `reduce()` · `listOf()`(`src/view/extract.mjs`)。

## Goal
在**原始记录与段索引(4.2)与前端部件(2.x)之间**架一层**派生投影 + 派生缓存**,使"每条记录的块与调用事实、每条车道每步的块 id 列表、相对上一 call 的 cache-break、一份答案"这类**贵**的产物**每条记录只抽取一次、每条车道按需归约、可从源重建**。没有页,也没有正文预算:一步的块列表由投影物化,块正文由 `block` 按 ref 回源([3.5](3.5-query-layer.md) §会话读)。核心约束:投影与缓存都是**可重建的派生**,原始 NDJSON(源)**永不被它们覆盖或绕过**(承不变式 2、D59②);命中与不命中、有投影与没有投影答出的文档逐字节相同([3.5](3.5-query-layer.md) §谁执行它)。

## Definitions
- **派生产物(derived artifact)**:非源真相、可由原始记录重算的中间结构。① **上下文投影**(§4):每条调用记录抽取一次得到的块定义与调用行,按会话落盘;② **归约**:按步序把会话的成员调用行归到车道,得出每步的块 id 列表、cache-break、资源、事件与骨架行([3.5](3.5-query-layer.md) §会话读 的行闭集),它的逐调用产出按会话落盘成折叠日志(§4);③ 每 call 类型构成 `comp`(UTF-8 字节占比,token 占比的廉价代理;每个块定义按桶算一次,归约时累加,随骨架行下发);④ 答过的答案字节串。
- **记忆化(memoization)**:落在**守护进程的查询工作进程**里(D63;没有守护进程时在提问的进程里,同一份代码)。每份缓存的键都是它依赖的东西的**身份**(段文件的 stat、记录 id、会话的段索引行、名字声明的 `version(ctx)`),不是时间也不是条数;全部内存缓存共用 [3.5](3.5-query-layer.md) §内存有界 的一个堆预算(`heapBudget()`),在计算之前让位。
- **失效键**:一个廉价的身份,身份没变则跳过整轮。服务端:段文件的 (大小, mtime, ctime)、会话读的段索引行、名字的 `version(ctx)`;投影:会话的成员 id 集(§4 有效性);看板:相邻步只按 `bid` 打补丁,不重建窗口。
- **索引(index)**:跨 call 复用块的去重键 = [3.2](3.2-normalized-model.md) 的 `content_hash`;**本模块只消费,不重定义**。投影里的 `bid` 是逐字字节的身份([3.5](3.5-query-layer.md) §会话读),只在投影与会话读里用,不是去重 PK。

## Plan(选定方案 + 取舍)

**选定:抽取一次 · 按车道归约 · 不分页。**
1. **抽取一次,落进投影**:每条调用记录被抽取一次(`extract()`):块定义(`bid`、帧哈希 `fh`、ref、区、角色、渲染规格与归约要的事实)与一条调用行(相对某个更早调用的块 id 列表 + 每调用事实)。结果追加进该会话的上下文投影(§4);之后的读都从投影出发,不再回读记录体。
2. **按车道归约**:`reduce()` 按步序把成员调用行归到车道,物化每步的块 id 列表(`listOf()`),同时算出 cache-break(本步 `fh` 序列与同车道上一条成功调用的最长公共前缀,承 [3.3](3.3-cache-model.md))、资源、事件与骨架行。归约按调用写进该会话的折叠日志(§4),冷开从折叠日志读、不重折;会话长了只归约新成员。
3. **页只是传输分块**:`session` 只发骨架行,`lane` 发 ops 与块定义,`block` 按 ref 发正文([3.5](3.5-query-layer.md) §会话读);`session` 与 `lane` 按 ≤ 1 MB 原始字节的页传,看板自己接着取。没有页上 / 页外之分,也没有正文预算;负载随看的车道与展开的块涨,不随会话涨。

**备选(未选)**:
- ① **每 poll 全量重解析**(D5 的痛):每 1.5 s 从头折整场会话 → 大 session 每次轮询 O(会话) 的 CPU,且重画抹掉用户刚展开的块。
- ② **只在内存里折、不落盘**:工作进程闲 120 s 就退(D63),每次冷开都要从头抽取整场会话(实测 6.6k 调用的会话从头折 50.8 s);投影让冷开只付载入加归约。
- ③ **把块定义塞进中心契约([3.2](3.2-normalized-model.md))**:渲染规格与归约事实是视图态,塞进去会让 schema 随 UI 抖动。

**取舍**:投影、折叠日志与缓存只承载"可重建"的派生;源只有原始记录。两层靠身份键(时间对齐)与逐字字节的 `bid`(内容对齐)咬合。**任何派生产物 MUST 可被丢弃后从原始记录逐字重建**——这是它不成为第二源真相的凭证(必拒违反;兜底:验收 #3)。

## 机制

### 1 · 按身份键的记忆化 + 失效键
- **服务端的缓存与它们的键**(内存里的都在查询工作进程里,共用一个堆预算;键都是身份,所以没有"过期但没被发现"的条目):

  | 缓存 | 键 | 落点 |
  |---|---|---|
  | 段索引行 | 段文件的 (大小, mtime, ctime)(`statKey()`);整份行表从第一个动了的段起重建;只是最新的段长了时,行表与会话分组只追加它的新行(一场会话的位置表与成员数组在原处长,不为每张新行表复制),哪个段都没动时交回同一张只读的行表 | `src/query/index-build.mjs`(`warmCache`);`src/query/row-table.mjs`(每段一份列存与访问器);`src/query/rows.mjs` |
  | 回读的记录 | 记录 id(记录只追加、从不改写,不变式 2,所以键不带戳) | `src/query/records.mjs` |
  | 上下文投影(盘上) | 会话 id;每一行的有效性按成员 id(§4) | `src/query/projection.mjs` |
  | 归约状态 | 会话的段索引行(`rowsKey()`)与归约前沿;行变多就只归约新成员,按 [3.5](3.5-query-layer.md) §缓存按依赖失效 只重归约晚到记录所在的车道;盘上的那份是折叠日志(§4),按投影的实例 id 认 | `src/view/reduce.mjs : reduce()`;`src/query/fold-log.mjs`;`src/query/named/session.mjs` |
  | 答案字节 | 请求(名字、参数、缩进、gzip)+ 名字的 `version(ctx)`(只读段索引行) | `src/query/answers.mjs` |
  | 块的派生 | 解析出的块对象(按契约只读,`src/dissect/request-body.mjs`)→ 字节数、键文本、hash 键、资源引用,WeakMap;只在抽取时用 | `src/view/blockmeta.mjs`;`src/view/analyze.mjs` |
  | 封存段的读者 | 封存段读者的文件描述符在这次读让出时关掉;读者的表按文件身份跨同步读留着(至多 `SHARED_FILES` 份,重开时核对身份);解出的帧与重建的行按文件身份(dev:ino:大小:mtime)+ 帧号 / 记录号跨读留着(48 + 16 MiB,堆外),工作进程闲置时清空(3.5 §冷路径) | `src/query/records.mjs` |

  读失败的结果从不被记住(唯一的例外是折叠日志里归约读不回块的失败成员行,它带码进每个回答的 `errors`,见 [3.5](3.5-query-layer.md) §读不全不静默);`errors` 多于版本自带的索引问题的答案不进答案缓存。
- **看板按 id 打补丁**:窗口的行按 `bid` 键;相邻一步从两份列表的最长公共前缀起删掉旧行、补上变了的行、追加新行,不重建整个窗口([2.3](2.3-context-window.md))。补丁后的窗口 MUST 与从头画出的同一步逐字相同:漏补一种变更 = 显示旧字节 = **谎报 AC-1(必拒;兜底:验收 #4a)**。
- **UI 局部态跨补丁存活**:展开的块集(`openBlocks`)、展开的 turn(`turnFold`)在增量到来与补丁时 MUST 存活;只在播放头换到另一个调用或换会话时清 `openBlocks`——否则跟随时每 1.5 s 把用户正在读的块折回去。

### 2 · 索引:content_hash 去重 → cache-break 是相邻帧哈希序列的公共前缀(承 [3.2](3.2-normalized-model.md)/[3.3](3.3-cache-model.md))
- **cache-break 是一句 LCP**:同车道相邻 call 的块帧哈希 `fh` 序列比对,首个不同位置 = 结构散度点。归约时算好,散度点须与 [3.3](3.3-cache-model.md) 的 `structural_divergence_seq` 一致,且**MUST 标"结构参考,非真实 cache 边界"**(数值真相取真实 usage,见 [3.3](3.3-cache-model.md))。
- **跳过 `volatile` 块**:cache-break 比对 MUST 跳过 volatile 块(CC billing nonce:bytes 每 call 变但不入 cache key),否则每 call 误触发散度。volatile 是位置属性,放在调用行的 `attrs` 里,不进按字节键的定义。
- **保真边界(bounded-prefix hash)**:`blkKey`(`src/view/analyze.mjs`)对块前 **4096 字符**取 hash(O(1)/块,与块大小无关)——只许用于内存态启发式,**MUST NOT** 用作 [3.2](3.2-normalized-model.md) 去重 PK(两个仅前缀相同的长块会碰撞、丢差异)。**产品的 `content_hash` = 全内容抗碰撞 hash**——算法全局钉死在 [3.1](3.1-adapter-contract.md) `parseBlocks`;投影的 `bid` 与 `fh` 都取全部字节。

### 3 · 抽取一次 · 按车道归约 · 虚拟化(承 D6)
- **每条记录抽取一次**:工作进程按写入次序(`pos`)抽取会话成员,结果追加进投影;抽取前沿、后台切片与 `pending` 见 [3.5](3.5-query-layer.md) §访问模式。抽不出的记录,它的调用行带 `unparsed` 与原因,不当成好的落盘,下次打开再抽。抽取先取每个块的 `bid`([3.5](3.5-query-layer.md) §会话读 的规则),只给会话还没有定义的块建定义(`fh`、`vh`、预览、渲染规格、事实),请求块与本车道上一条请求同位置、同区同角色且逐字节相同时直接继承它的 `bid`(同一输入的同一哈希;上一条请求的请求体与它各块的位置和 `bid` 留在 `src/view/extract.mjs` 的链尾缓存里,`TAIL_HEAP` 按字节封顶,工作进程闲置时放掉),否则哈希一次;`fh` / `vh` 只对新块算(依据:D71②;原始行每条验一次已是线上字节的约 1.39 倍,每块再哈希一次合计约 2.5 倍,过不了 §4 门槛的 2 倍;实测给每个块建定义占首次折叠的 25 %)。
- **一步的列表由投影物化**:`listOf(rid)` 从调用行的基准列表按位置补丁、再追加,物化出这一步的块 id 列表;`lane` 回答在回答时由物化出的列表算 ops([3.5](3.5-query-layer.md) §会话读),所以投影里存哪种基准只影响压缩,不影响答案。
- **块体按 ref 懒取 + 折叠**:block 卡默认只渲头与定义里的预览,首次展开经 `block --ref` 回源取全文(承 [2.3](2.3-context-window.md));取失败的不算取过,下次展开再取。
- **会话回放的读**:跨 session 聚合走 [3.5](3.5-query-layer.md) 的列表分页;会话回放走 §会话读 的 `session` / `lane` / `block`,跟随时只取 `since` 增量与被增量碰到的车道。

### 4 · 上下文投影(D69)
依据:D69;D59②(`index/` 下只放可重建的投影);不变式 2、4;D38;要加载或更新的东西尽量增量、尽量少,trocar 运行时保持轻量。

- **路径**:`~/.trocar/index/ctx/<sha256(会话 id) 的前 32 位十六进制>.ndjson`,权限 0600,只追加。
- **行**:每行一个 JSON 对象,类型由它唯一的顶层键决定:
  - `{v: PROJ_V, id}`:文件头,第一行;`PROJ_V` 是 `src/query/projection.mjs` 里的一个常量,`id` 是建这份投影时取的随机实例 id(折叠日志靠它认自己属于哪份投影)。
  - `{d:{…}}`:一个块定义,会话里每个不同的 `bid` 一行;只取决于块的字节、区与角色,位置属性(`query`、volatile、继承的渲染字段)不进定义。
  - `{c:{…}}`:一条调用行,每条调用记录一行,带记录 id 与写入位置 `pos`、相对某个更早调用的块 id 列表、回复块的 `bid` 与每调用事实。行的位置属性只写本行的差分相对它的 base 引入或改了的位置:`k` 及之后带属性的位置、`patch` 的位置,以及 `k` 之前属性与 base 物化出的属性不同的位置(值不同写新值,base 有而本行没有写 `null`);没有 base 的行(关键帧)写全部带属性的位置。读的一侧沿 base 链物化位置属性,与块 id 列表同一条链:base 的属性只留 `k` 之前的,再叠上本行的(`null` 删除)。续接调用的 base 是前一环,差分直接取「前一环的列表 + 前一环的回复 + 本条自己的块」,不逐位重建前一环已有的。依据:D71②(工作随差分走);实测(调用行合计 111.9 MB,每行 5.3 KB)。
  - `{t:{…}}`:一条暂存的调用行——排在一个抽取失败的成员之后抽出的行;打开时读到第一条 `t` 行就停,下次追加之前从那里截掉,所以读回来的永远是一次走过某个前缀的那些行。
  - `{b:{brk:[prevBid, curBid], cause, byteOffset}}`:要两份正文才分得出的 cache-break 原因,算过一次就记下。
  - `{s:{k, v}}`:在多条行里重复出现的值(车道事实、调用属性、线格式标签)只写一次,`k` 是它内容的哈希,行里在原位置写 `{"$s": k}`;读回时同一个值在留着期间是同一个对象。
  投影只记每个定义、行与共享值在文件里的位置,用到时读回那一行;最近用过的行与共享值按它们行的字节数留几 MiB,所以投影占的堆不随会话的行数涨(下面「抽取按构造有界」)。
- **折叠日志**:`~/.trocar/index/ctx/<同一个哈希>.fold.ndjson`,权限 0600,只追加,只由工作进程写;它是归约的产出,冷开读它就不必重折。每行一个 JSON 对象,类型由它唯一的顶层键决定:文件头 `{v: FOLD_V, pid}`(`FOLD_V` 是 `src/query/fold-log.mjs` 里的一个常量,`pid` = 投影头的 `id`);调用行(骨架行、它的骨架事件、它在 `lane` 回答形下的车道事件、它的账本增量,`p` = 同一 rid 上一行的偏移);`gone` 行(不再是调用的 rid);车道头行(最新的为准,带 `p`);车道 gone 行;条目行(不是调用的成员:只记日志的、探针、没有解析器认的记录的事实);失败成员行(抽取失败的成员,与归约要回读却读不回块的成员,后者见 [3.5](3.5-query-layer.md) §读不全不静默);每个折叠步之后一条前沿行 `{f, n, pb}`(`pb` = 那时投影的字节数)。调用行只在它的字节与该 rid 最新的一行不同时才写。依据:[3.5](3.5-query-layer.md) §访问模式「内存有界」的本意(骨架就是归约状态,定义的全文不常驻);本节「门槛」;实测(把投影留在堆里的工作进程约 11.5k 条调用处 OOM;一场 12.6k 条调用的真实会话整份折叠一次 2.6–3.6 s、每条调用常驻 10–16 KB);D69;不变式 2、4;D38;要加载或更新的东西尽量增量、尽量少,trocar 运行时保持轻量。
- **旁索引**:投影与折叠日志各有一份二进制旁索引,存它们在堆里的行索引:`~/.trocar/index/ctx/<同一个哈希>.idx` 与 `<同一个哈希>.fold.idx`,权限 0600。只由工作进程写:闲置时写,折叠中每折过 max(256, 已折条数 / 8) 条调用也写一次(先写投影的,再写折叠日志的;投影的不写——它有 `t` 行或写不进——时两份都不写);先写临时文件,再在同一目录里 rename 换上。键 = 它那份文件的实例 id(投影头的 `id`;折叠日志的另加 `FOLD_V` 与它覆盖到的最后一条前沿行的 `pb`)加它覆盖的字节长度。内容 = 覆盖长度以内每类行的键 → 该行的偏移与长度、折叠日志的前沿行,以及折叠日志在覆盖长度处的步序列(调用的步序、每条调用的车道与 `user` / 压缩事件计数)。打开 = 载入旁索引,再按本节的规则只扫它覆盖长度之后的字节。实例 id 或版本对不上、覆盖长度超出文件、`pb` 超出投影的字节数、或读不出 → 忽略它(整扫一遍),下一次闲置时重写;旁索引从不被信、也不留 note。本地那条路读旁索引、从不写。投影里有 `t` 行时两份旁索引都不写。**折叠日志的旁索引另带归约状态**(`src/view/reduce.mjs` 的 `snapshot()`,头里记 `REDUCE_V` 与折它时的截断),只在状态是写进这份文件日志的活归约、日志止于一条前沿行时带;状态按车道、按资源、按不同块各一份,加 [3.5](3.5-query-layer.md):48 计入堆界的每条调用的定宽骨架列(步序时刻、行摘要、车道槽位、工具映射份额),没有一项随上下文大小或存储字节涨。会话长过了日志前沿的工作进程从它续:状态覆盖到日志的最后一条前沿 → 恢复归约、只折前沿之上的成员,不重建;覆盖得更短(写完旁索引之后、下一次写之前进程被杀)→ 把日志截回到它覆盖的长度(截在一条前沿行之后,旁索引照旧有效)再恢复。本地那条路只在状态覆盖到前沿时用它,否则照旧在内存里重建。`REDUCE_V` 或截断对不上、读不出 → 当没有状态,从头重建,不留 note。**投影的旁索引另带抽取上下文**(`src/view/extract.mjs` 的 `createExtractContext`),截到它覆盖的行:每条车道提示的最后一条调用(行槽位),每个可续接调用按它的 link 记成一张数表(`num52(scope\nlink)` → 该行的槽位;命中时读那一行核对,撞号的进一个小 Map;同一 link 取写入序最早的那行),加它覆盖的行数与投影实例 id。带它打开的上下文只对覆盖之后的行记账,不重读每一行;实例 id 对不上、覆盖的行多于投影现有的行(尾巴被截)、或读不出 → 当没有,照旧逐行记账。数表的底是堆外的定型数组([3.5](3.5-query-layer.md):48),所以本节「抽取按构造有界」不变。依据:D71③;实测(活会话冷开的第一个回答为重读每一行花 713 ms)。依据:D71③(离开再回来不重读已读的部分);[3.5](3.5-query-layer.md) §访问模式「读一场大会话的设计界」④;实测(长过前沿的会话每次重开从头重建归约:主线程忙 7.45 s、进程 CPU 14–16 s);几何间隔使首折的写是 O(n log n) 字节而非 O(n²)。 旁索引其余规则的依据:本节「门槛」;D64;不变式 2(删掉旁索引只多花一次扫描)。
- **写者只有查询工作进程**。本地 CLI 那条路(没有守护进程应答时,[1.6](1.6-cli.md) §4.1)读投影与折叠日志,缺的成员抽取并归约,新行追加进进程外的内存 arena(`src/query/line-file.mjs`),盘上一个字节都不写;它的 V8 堆与工作进程的同样有界,缺的那些行记成外部内存;答案与工作进程在同一 `mark` 处的相同。
- **有效性**:记录不可变、封存前后 id 不变,所以一行在它的记录 id 仍是该会话成员(按段索引)时一直有效;不再是成员的 id 的行被忽略;成员里投影没有的 id 被抽取。
- **重建**:文件头的 `PROJ_V` 对不上,文件中间有一行坏了,或一条行指向文件里没有的共享值 → 删掉整份重建,在该次答案的 `errors` 里留一条 `projection-rebuilt`(`level:'note'`)。只有末行被撕裂(写到一半进程退出)→ 下次追加之前截掉它,不算重建。答案不取决于投影的字节,所以重建前后答案相同。折叠日志:头的 `pid` 与投影的 `id` 不符、`FOLD_V` 对不上或中间有一行坏了 → 删掉重建,留一条 `projection-rebuilt`(`level:'note'`);撕裂的末行截掉;打开时截回到最后一条 `pb` ≤ 投影整行长度的前沿行。从折叠日志答出的与新折一遍的逐字节相同。
- **回收**:工作进程空闲时删掉成员已全部不在的会话的投影,连同它的折叠日志与两份旁索引;全部投影、折叠日志与旁索引的总大小上限是一个固定值 512 MiB(`projection.mjs` 的 `gcProjections()`),超了从最久没打开的会话起删,被删的会话下次打开时重建一次。**正开着的与正在跟随的会话(`keepKeys`)从不被删**,哪怕它一份就超过上限;调用方不给仍是成员的会话集(`liveKeys`)时一个都不删、报错(不知道谁还活着就不删)。依据:D69②(投影是可删的派生层,删掉只损一次重建)、D62「附近的查询 ≤ 50 ms」与界面不显示加载步骤、不造成卡顿的要求——上限若随盘上原始数据按 10 % 缩,真机 Mac 上会把正在跟随的那场会话的投影删掉(实测:它一份 187 MB,10 % 只有 37.5 MB),跟随中的每次回答都会重抽。
- **门槛**(在参考会话与真实的活会话上量;依据:D69①③——看板首屏只画骨架加一条在握车道,整份文档的归约不在首屏的路上;D62(随机访问 ≤ 0.5 s、附近 ≤ 50 ms);D64①;界面不显示加载步骤、不造成卡顿;在一场 10,428 条调用的真实活会话上的实测:整份文档冷开 0.83 s、答完留堆 98.9 MB(其中打开的投影 79.4 MB、文档 32.5 MB),抽取峰值 391 MB 撑满 384 MB 的老生代,与此前一次工作进程 OOM 同类):
  - **冷开 ≤ 0.3 s、留堆 ≤ 40 MB(6,600 条调用处)约束的是看板画首屏要的东西**:`session` 的骨架回答加一条在握车道的一页 `lane`,从工作进程闲置退出后重开一场已投影的会话算起,冷开读两份旁索引、再只读它们覆盖之后的行,不折叠(依据:本节「旁索引」);留堆 = 强制 GC 之后、减去段索引与模块载入后的基线。整份文档的归约(把每条调用的全部事实一次归约成一份文档)不受这两条约束,它只须守 [3.5](3.5-query-layer.md) §访问模式「内存有界」的堆预算:放得进就答、放不进按那里的阶梯截断,工作进程不因它退出。
  - **抽取按构造有界**:抽取的峰值堆不随会话长度涨——只留骨架行、几条链尾的上下文与正在抽的一块(3.5 §内存有界)。判据:在生成的会话与用户的活会话上,用工作进程的堆上限跑抽取,峰值堆低于该上限的一半,会话长度翻倍时峰值只多出按调用计的位置索引(每条调用一个定量,不随上下文的大小涨;允许量写在守卫 `test/view/extract-heap.test.mjs` 里)。
  - **哈希按线上字节有界**:一场会话从抽取到答出(工作进程的折叠到第一个 `session` 回答),进程里 `node:crypto` 哈希读的全部字节(抽取、原始行校验、投影、封存件的帧索引尾,全进程口径)≤ 2 × 该会话的线上字节(每条成员记录的请求体字节,加回复块切出的那份回复原文的字节:`resp.raw` 是字符串时取它,否则取回复体的 JSON)。在生成的整段重发(`http`)与续接(`threads`)会话、段都已封存、从冷的帧缓存起,由守卫 `test/query/process-hash.test.mjs` 断言;真实活会话上的同口径数与全量首折 ≤ 60 s 在下面验收 8 里量。依据:D71②(每步的工作量随差分走,不随上下文长度走)。
- **盘满**:投影或折叠日志写不进去时,这次请求在内存里照样抽取、归约、照样答;每个失败期留一条带原因的持久记录 `projection-write-failed`(D38),答案不变。
- **不落盘的**:答案、任何看板态。

## 保真边界(必拒隐瞒 · 承不变式 2、4([0.0](0.0-overview.md) §核心不变式))
- **投影与缓存是派生,永不覆盖源**:上下文投影与任何缓存条目 MUST 可丢弃后从原始 NDJSON **逐字重建**;它们 MUST NOT 成为唯一副本、MUST NOT 有损改写。投影只存块的 ref 与预览,正文永远按 ref 回源。
- **显示截断就地说**:超长 block 体按显示上限截断(`src/web/v2/replay/blocks.mjs` 的 `DISPLAY_CLIP` 字符,`clipText()`:截成源的前缀并说出全长)——这是**显示态截断,非数据丢失**:源 bytes 完整、可回源取全。未标即让人误判"看到的是全文"(违反不变式 4)。
- **廉价代理标注**:`comp` 用 UTF-8 字节占比作 token 占比代理(非真实 token 数),UI 呈现处 SHOULD 注明"字节占比,非 token"。
- **缓存 miss 不得供旧/错**:键是身份,身份没变才复用;**MUST NOT** 在数据已变时供旧缓存(供旧字节 = 谎报 AC-1,必拒)。

## 验收(可跑 check)
上表八条的守卫测试都在 `npm test` 里、保持绿(下列 1–7);下列 8 在真实数据上量:
1. **记忆化 ≡ 重算**:任何缓存命中、任何投影或折叠日志出发的答案(含在任何一点被杀后从旁索引的归约状态续的)与清空缓存与投影后重算的逐字节相同;读失败从不被记住。
2. **抽取一次**:每条记录只抽取一次并持久化;一步的列表由投影物化。
3. **可从源重建(派生非源)**:删掉全部派生(段索引、投影、缓存)后答案逐字段相等。
4. **失效键正确**:(a) 相邻步补丁后的窗口 = 从头画出,展开的块存活;(b) 追加一条记录 → 下一次查询包含它。
5. **cache-break via index**:散度点与 [3.3](3.3-cache-model.md) `structural_divergence_seq` 一致,`volatile` 块被跳过。
6. **截断标注 + 可回源**:显示截断就地说全长,回源可取完整 bytes。
7. **上下文投影与折叠日志**:§4 的路径、行、有效性、重建、撕裂末行、写者、回收与上限、盘满各一个用例;折叠日志的路径与 0600、行、有效性与截回、`projection-rebuilt`、本地 arena 盘上不写、回收、盘满各一个用例;旁索引的经它打开 ≡ 整扫、过期或别家的不用、回收、本地那条路不写各一个用例;旁索引里的归约状态:被杀后续到底 ≡ 一次建完(含版本不符)、重开的工作进程只折新成员各一个用例。
8. **门槛**(§4):首屏的冷开与留堆、抽取峰值堆不随会话长度涨、哈希读的字节 ≤ 2 × 线上字节与全量首折 ≤ 60 s,在生成的会话与真实的活会话上各量一次,数字与探针一并记下;超了照 D64⑥ 报、不放宽。`npm test` 里 N/A:计时与堆峰值在全量套件的负载下不是契约(同 [3.5](3.5-query-layer.md) §访问模式「读一场大会话的设计界」),契约部分(答案不取决于投影、按预算让位)由 #1、#7 守;哈希字节不受负载影响,在生成的会话上由 `test/query/process-hash.test.mjs` 守。

## Edge cases
- **超大 session(数千 call)**:投影、归约只算新成员、`session` 只发骨架行、`lane` 按 ≤ 1 MB 的页发,兜住;连归约状态都放不进预算时按 [3.5](3.5-query-layer.md) §内存有界 截断并在文档的 `truncated` 写明。缓存逐出只损花费:miss 时从投影或原始记录重算。
- **live 追加与并发**:轮询期间段在长——段文件的 stat 变了 → 段索引行重建 → 会话的行变了 → 新成员被抽取进投影、归约只算新成员、答案缓存的版本不再相同;记录 id(`<段>:<序号>`)只追加不复用,所以按 id 记的回读不带戳。
- **compaction 步**:message_count 骤降触发的换血(见 [3.4](3.4-session-identity.md)),cache-break 在此步落到**首个 messages 块**(tools+system 存活),缓存 MUST 反映此结构跳变,不复用跨 compaction 的旧散度。
- **DeepSeek `cache_write=NULL`**:cache-break 是纯结构 diff、与 usage 无关,NULL 不影响本层;数值叠加容 NULL 由 [3.3](3.3-cache-model.md)/[3.5](3.5-query-layer.md) 负责。

## Risk / 回滚
本层是**纯派生**(原始记录 → 投影、折叠日志与缓存),零副作用于源;投影与折叠日志是仅有的落盘部分,删掉它们只损一次重建。缓存 / 失效逻辑改动用固化真实记录回归;**最大风险 = 失效键漏检导致供旧字节**——由验收 #1、#4、#7 守;一旦怀疑,**MUST 优先牺牲缓存命中率保正确**(删掉投影、关掉缓存全量重算是安全默认)。
