# trocar · RFC 1.5 — 关键状态 + 审美

> **服务意图(A2)**:①②**共享的呈现层横切**——不新增功能,而是定义所有 1.x/2.x 视图**在边界数据下如何退化**(关键状态)与**长什么样**(审美);把"招牌视觉"钉成一套跨视图一致的视觉语言,直接支撑 ①(逐字看板)②(多色排轴叠加)。
> **受众**:人(核对每个边界态都有明确、不误导的处理)+ agent(据此实现渲染退化分支与主题 token,不各视图自造)。
> **前置**:外壳(侧栏 · 页头 · 回放台布局)在 [1.2](1.2-shell-layout.md);排轴在 [1.3](1.3-timeline-tracks.md);中央看板在 [1.4](1.4-central-board.md);各屏在 [1.7](1.7-overview-dashboard.md)–[1.11](1.11-settings.md);状态里"是不是空/错/多"的判定字段来自 [3.2](3.2-normalized-model.md)(`faithfulness`/`error`/`compaction`)与 [3.4](3.4-session-identity.md)(`confidence`)。语法来源 = [0.0-overview](0.0-overview.md) D2(行为回放为骨·cache 叠加)/ D6(借 Perfetto/时间旅行/LLM-obs);观感来源 = D77。

## Goal
三件事,一处定死:
1. **关键状态矩阵**:枚举"数据不理想"的态(空 / 超长 / 多 harness / 采集出错 / 中断错误 / compaction / 不能证明逐字 / 缺字段 / 做不了的操作),各给**一个确定的、不误导人的退化处理**——尤其:非逐字的地方 MUST 就地标(承不变式 4,[0.0](0.0-overview.md) §核心不变式)。
2. **审美维度**:明暗双态的**语义色 token**、等宽/无衬线**排版分工**、以及"招牌视觉 = 多色排轴 + 逐字看板"的视觉语汇——让三家 provider 的 session 在**同一镜头**下同构呈现。
3. **看板词表、标记与数据规则**:界面上只用一套词;保真标记只有几种,长相固定;每个界面元素都有真实来源,没有来源的砍掉。

看板(`web/`,D75)是产品看板。观感按 D77,招牌语法保留;状态处理沿用 demo 与旧看板跑通的做法。

## 前置定义(Definitions)
- **关键状态(key state)**:渲染管线必须显式分支的**边界数据形态**(≠ 正常态)。每个态 = 触发条件 + 退化处理 + 保真标注。
- **语义色 token**:颜色只经 `:root` 上的自定义属性,分面、迹线屏、线、字、动作、状态、迹线、数据、格、品牌十组(名单见 §审美维度)。色**不硬编码**,只经 token;亮暗两套值切换。值的唯一出处是 `web/legacy/css/base.css` 的 token 块,取值依据 D77。
- **内容类型配色**:上下文块**按 kind 固定映射到数据色**(与 [3.2](3.2-normalized-model.md) `block_contents.kind` 对齐),排轴堆叠柱与图例色块共用:`tools=--ct-tools(石板蓝)· system=--ct-system(薰衣草)· user=--ct-user(蓝)· assistant=--ct-assistant(青绿)· thinking=--ct-thinking(兰紫)· tool_use=--ct-tooluse(橄榄)· tool_result=--ct-result(暖灰)· image / other / 未载入=--ct-hatch(斜纹)`。`--ct-result` 仍是最大、最不说明问题的那一段的安静色;取暖灰而不取中性灰,因为中性灰在深色迹线屏上读成「空 / 停用」,又与 `--ct-tools` 的石板蓝和斜纹太近(主 agent 定,依据:D77① 选定的原型用它;§审美维度 7 的 ≥ 3:1 在迹线屏与 `--raised` 上都成立)。数据色只进图表和图例色块;上下文窗里块的左边不画类型色,类型用文字写在行头。样式表里每个 `.ct-<kind>` 只取这里给它的 `--ct-*`,不经旧名别名(`--amber` `--pink` `--accent` `--dim` `--dimmer` 是状态、动作与字的颜色,不是数据色)。
- **标记**:就地说明「你看到的不是全部 / 不是测出来的」的几种小记号(§标记)。
- **来源**:一个界面元素的数据出处(§数据规则)。
- **标签表**:`web/legacy/labels/` 里把闭集的值换成界面词的表(界面词是英文,§看板词表 · §数据规则)。
- **灯**:一个 8 px 的圆点(套件类 `.lamp`,哪里都是这一个大小),颜色 = 状态 token(坏 / 注意 / 留意;`ok` 的状态点与不点灯的灰点也是它),在它那一行里上下居中;放在总览采集卡的卡头、行首的灯槽与迹线屏的问题道里;正常不点灯。

## Plan(选定方案 + 取舍)
**选定**:**状态退化集中在渲染层的少数分支函数**(v2:回放台的空态与无请求态、`core/capture-verdict.mjs` 的采集状态、`core/ui.mjs : mark()` 的标记;落点见 §涉及源文件与接口),**审美全经 CSS 变量 + 语义类**(无内联颜色)。明暗:`:root` 存亮色默认 → `@media (prefers-color-scheme: dark)` 下 `:root:not([data-theme="light"])` 换暗色 → `[data-theme="dark"|"light"]` 手动覆盖**两向都赢** OS 偏好(承 artifact 主题规范)。切换器在 设置 · 外观([1.11](1.11-settings.md))。
**备选(未选)**:① 每视图各自处理空/错态——退化不一致、漏标保真;② 单一主题硬编码色——换主题要改各处、且盲人;③ 沿用 v0 原型或旧视觉设计稿的观感——D77 取代;④ 暗色默认——亮色是默认,暗色跟随系统或手动切换;⑤ ◐ 用注意色(界面重构文档 §6.3 的首稿)——注意色只给能修的事,◐ 说的是源头或用户自己的设置,所以用墨 2。
**取舍**:集中分支 + token 化让"加一个态 / 换一套色"是**一处改动**;`data-theme` 覆盖层留出手动切换钩子而不锁死 OS 联动。**代价**:换皮动到全部样式表;旧 token 名(`--fg` `--dim` 一类)在 `base.css` 里留别名,只给还没移植的回放台的样式表用,回放台移植时删。

## 采集状态(D38:状态集、次序与写法)

**来源**:`/api/status` 顶层的 `health` 一个字段(`src/health/read.mjs : captureHealth()` 在采集器与原始层上折出的判词,形状见 [1.6](1.6-cli.md) C.3)、`health.read_errors`,加上轮询的时钟。看板只读这一个 `health`,既不在浏览器里再折一次、也不从别的字段再推一遍(依据:D24「一个判断只在一处做出、命令行与看板读同一份文档」与本单元「判定字段由服务端烘焙,不在浏览器里嗅探」)。`health` 不在时按 K-28(字段缺席 → 不知道)。写法只有一处:`core/capture-verdict.mjs : captureVerdict()`,字在 `labels/common.mjs`。总览采集卡([1.7](1.7-overview-dashboard.md))、采集页采集服务行([1.9](1.9-capture-page.md))、会话库空态([1.8](1.8-session-library.md))都调它,说法不会两样。

次序 = `?`(读不到)> `✗` > `⚠` > `?`(不知道)> `○` > `✓` > `–`,下表从坏到好排(同服务端的 `RANK`)。这些符号只是 spec 里的简称,界面上用下表的字加灯或状态点,不画 ⚠ 这类表情字符。表中的字不带主语:放在本身没写「采集服务」的地方(总览采集卡的标签、会话库空态)时前面加「采集服务」。

| 次序 | `health.state` | 界面上的字 | 灯 / 点 |
|---|---|---|---|
| `?` | 读不出(`status` 不带 `health`、`errors` 里有 `capture health`,[4.6](4.6-process-collector.md) F9;看板记作 `{unreadable}`) | 「读不到采集状态」;服务端给的原因进技术细节(K-29) | 不点灯;字里已说不知道 |
| `✗` | `not-running` | 「已停止 · 最后记录于 T」;有 `signal` 时接「 · 因 <signal>」 | 坏 |
| `✗` | `not-responding` | 「没响应 · 最后心跳 T」 | 坏 |
| `⚠` | `failing` | 「采集有问题:」接下面几项中大于 0 的,用「;」隔开——「N 个 agent 没有完整在采」(N = `status` `harnesses` 里 `captured` 不为真的,按 `harnessKey()` 去重)·「另有 K 项问题还在」(K = 不带 agent 的当前条件)·「24 小时内失败 M 组」(M = `failures.groups` 里 `level:'problem'` 的组数) | 注意 |
| `?` | `unknown` | 「不知道:<原因>」;`lock` 读不出也落在这里 | 不点灯 |
| `?` | 没见过的 `health.state` | 「不知道采集状态(<state 原样>)」;`state` 等宽进技术细节 | 不点灯 |
| `○` | `off` | 「关着 · 自 T 起」 | 不点灯 |
| `✓` | `ok` | 「在采 · 自 T 起」 | 状态点(`--ok`) |
| `–` | `residue` | 「未安装 · 留着 N 项改动」 | 注意 |
| `–` | `not-installed` | 「未安装」 | 不点灯 |
| 后缀 | `health.read_errors > 0` | 任一状态后接「 · 读不全」 | — |
| 覆盖 | 连续两个轮询周期没取到 | 「? 未刷新 · 截至 T」;从没取到过「? 未刷新 · 截至 —」;第一次回答之前「读取中」 | 不点灯 |

`lock` 读不出记作不知道、「· 读不全」后缀、好坏次序。

- **永不留空**:总览采集卡与采集页采集服务行任何时候都显示上表的一行。要求与测试归 [1.7](1.7-overview-dashboard.md)(`test/web-v2/overview.test.mjs`)与 [1.9](1.9-capture-page.md)(`test/web-v2/capture-model.test.mjs`)。
- **只在总览与采集页**:侧栏不写状态([1.2](1.2-shell-layout.md));不设全站横条。采集停了、trocar 挡住了 agent 的网络,都作为总览页最前面的「要处理的事」出现,也在采集页上([1.7](1.7-overview-dashboard.md) · [1.9](1.9-capture-page.md))。
- **健康是保真披露,不是告警**:不推送、不弹窗、不出声、不记「已看过」、没有未读与角标(Non-Goal,D38⑦;守卫归 [1.7](1.7-overview-dashboard.md))。只有失败类让它变成「采集有问题」;预期类(策略外 host 等)只在采集记录的技术细节里计数。WebSocket 调用上的「不完整」「已截断」「未解码」是逐调用的就地标注,采集状态按类来分([4.6](4.6-process-collector.md) 验收 F5):解不出、写失败、因出错丢了数据消息是失败类,让它变成「采集有问题」;单次调用在 64 MiB 上限处被截是预期类,只在那次调用上标「已截断」。
- **会话里的缺口**:采集出错的时段与会话时间重叠时,会话保真行写「这段时间采集出过错,可能缺调用(推测)· 采集记录 ›」;只在会话落在失败组的窗口(`failures.since` 起)之内时写,从不写「没有缺口」。它取代旧文按 pid 与时间映射、在 `#truncbar` 就地说明的 SHOULD,标推测(pid 会复用)。要求与测试归 [1.2](1.2-shell-layout.md) §会话保真行(`test/web-v2/session-head.test.mjs`)。
- **轮询(MUST)**:总览、采集、采集记录三页在显示、且页面可见时,每 **5 s** 读一次 `/api/status`(间隔的主人是 [4.4](4.4-server.md) §live-poll:`status` 没有 ETag,是最贵的一次轮询,D62④),窗口重新获得焦点时立刻读一次,**页面隐起来时暂停**,与回放台的「跟随最新」无关;上一次请求没回来时不叠第二个;连续两个周期没取到 → 「? 未刷新 · 截至 T」。其他页要采集状态时只在打开时读一次(回放台:会话里的缺口;会话库:空态的原因)。三页都用 `web/src/ui/poll.ts : useStatusQuery`(TanStack Query,D75①),周期与退避是 `INTERVAL` / `backoffMs`。守卫 `web/src/ui/poll.test.tsx`。
- **按 harness 的开关(D39)**:`status` `harnesses` 在时,有开有关记作开着,写「在采 · M / N 个 agent 开着」(M = 期望态为开的 harness 数,N = 记了期望态的 harness 数);全部关着时 T 取各 harness 最晚的 `updated_at`(服务端算进 `health.since`;形状见 [1.6](1.6-cli.md) §1.5 与 [4.4](4.4-server.md))。

## 格的固定说法

格(上下文窗的块、回复行、请求参数、调用抽屉的输入,[2.3](2.3-context-window.md) §两种模式)与会话读取状态的几句固定说法。它们说的是「显示的是什么、不是什么」,本身就是保真边界的一部分(不变式 4),所以把意思写在这里;界面上的英文原文住 `labels/replay.mjs`,测试不断言措辞。依据:D69 · D70。

| 说法 | 在哪 | 意思 |
|---|---|---|
| 「Raw · line breaks added for reading」 | 打开的格在 Raw 模式时的工具栏 | 显示的是逐字字节,只多了排版用的换行与缩进(`.lay`,不进复制) |
| 「Readable · drawn from the bytes, not the bytes」 | 每个 Readable 格的一行 | 这是按字节画出来的样子,不是字节本身 |
| 「Readable view」 | 台的默认是 Readable 时的段头(代替「以下逐字」);翻转后的读屏播报 | 这一段显示的是画出来的样子 |
| 「Raw view」 | 翻转后的读屏播报 | 回到逐字字节 |
| 「Showing N of M characters」 | 格的剪裁状态 | 只显示了一部分,全文在源里 |
| 「Showing the first 2,000,000 of N characters · Copy bytes copies all」 | 到了每格上限时的剪裁状态 | 同上,并说明复制给的是全部字节 |
| 「Could not render as <kind>; shown as text」 | 渲染器处理不了输入时,就地 | 退回文字,源没有被「补全」 |
| 「Copied N bytes」 | 复制后的读屏播报 | 复制的是 N 个逐字字节 |
| 「Reading this session for the first time · N %」 | 会话头的读取状态([1.2](1.2-shell-layout.md) §会话头) | 服务端第一次抽取这场会话,已抽到 N % |
| 「Updating to this version · N%」 | 同上 | 版本变更的重读,已走到 N %(`read / total`);有新调用时后接「· 12 new calls appear when it finishes」(1 条:「· 1 new call appears when it finishes」) |
| 「Catching up · 12 new calls」/「Catching up · 1 new call」 | 同上 | 抽取在追这么多条新调用(`pending.calls`) |

**类别词**(闭集,按渲染规格的 `as` 取,Readable 格的工具栏里;不认识的 `as` 按 `text`):`text`「text」· `markdown`「markdown」· `code`「file」· `shell`「shell command」· `diff`「diff」· `json`「JSON tree」· `kv`「fields」· `media`「media」· `sections`「sections」· `opaque`「encrypted reasoning」· `parts`「parts」。`tone: 'error'` 不改类别词。

## 数据规则

**每个元素都有真实来源,否则砍掉(MUST)**。屏幕上画的每个元素——文字、数字、控件、链接——都在它所属的单元里登记**来源**,只能是下面五种之一:
- 今天就有的字段路径(端点 + 字段);
- 「[需服务端] S#」:本系列在 [4.4](4.4-server.md) / [3.5](3.5-query-layer.md) 里写明的服务端补充;
- 「」:`feat/cli-binary-switch` 加的字段,照 [1.6](1.6-cli.md)§9.4 写代码,不合入、不依赖那条分支;
- 「[见 4.8]」:点名开启、提权、重启,界面**不画控件**;
- 「固定文字」:`labels/` 里的固定词。

都不是的,砍掉,列进该单元的「砍掉的」表。字段缺席时显示诚实的缺席态(本文件矩阵)或不画——不猜、不写 0。按字段在不在判断,不按版本判断。守卫:`test/web-v2/no-mock.test.mjs`(没有 mock 传输层、没有场景切换,归 [1.2](1.2-shell-layout.md))、各屏单元在真服务端上的验收、`test/web-v2/state-matrix.test.mjs`;某个元素有没有登记来源,靠收尾审查对照各单元的来源表与代码。

- **spec 标记不上屏(MUST)**:「[需服务端]」与所有「[待 …]」只在 spec 里出现。守卫归 [1.2](1.2-shell-layout.md):`test/web-v2/no-mock.test.mjs` 断言 `web/legacy/**` 的字符串里没有「暂时」「待接口」「[待」「建设中」「真服务端」。
- **做不了的控件不画(MUST)**:状态写成文字,确切命令放技术细节;不写「暂时不能…」这类句子,不画灰掉的控件。守卫:`test/web-v2/state-matrix.test.mjs`(K-25、K-26、K-27 的 DOM 里没有对应控件)、[1.9](1.9-capture-page.md) `test/web-v2/capture-model.test.mjs`、[1.11](1.11-settings.md) `test/web-v2/settings-model.test.mjs` #7 #11(改不了的级别只是文字、带一条命令)与 `web/src/screens/settings/StorageScreen.test.tsx` V6(405 之后级别变成文字)。
- **标签表只按与 harness 无关的闭集取键(MUST;按 harness 取键的表 = 破适配缝,需 RFC 才放行)**:`web/legacy/labels/` 里的表只认这些闭集——缓存原因与归因、lane 种类、D40 的流量类别(`core/classes.mjs`)、trocar 自己的 D38 码(`src/health/codes.mjs` 的 `CODES_BY_PART`,去掉 harness 自定义的那部分)、`wire.contextState` 与 `*Incomplete`、1.6 的通用原因码。

- **完整性**:每张标签表等于它对应的服务端闭集(测试可以两边都引入;前端引入的 `src/` 模块会打包进看板,必须在 `src/` 内 import 闭合、不 import 任何 `node:*`,[4.4](4.4-server.md) §静态面、[0.1](0.1-engineering-rules.md) §2);只在 `feat/cli-binary-switch` 上有的闭集(`STATUS_REASONS`、`NET_CODES`)缺席时 `t.skip('<name> absent: PR #45 not merged')`,导出一出现就自动开跑;harness 自定义的码不在 `labels/**` 里,随文字到达。表里没有的值照原样放进技术细节,外面写一句通用的「原因未知」。守卫 `test/web-v2/labels-complete.test.mjs`。

## Edge cases
- **空 + live 轮询(MUST)**:空态下照常读数据(总览:`/api/sessions` 与采集状态;会话库:`/api/sessions`),第一条数据到了 MUST 无缝转正常态,不重载;状态切换 MUST 清净残留(不留上一个会话的会话头、行、卡)。守卫 `web/src/screens/overview/OverviewScreen.test.tsx`(总览)· `test/web-v2/empty-state.test.mjs`(会话库与回放台)。
- **装了采集以外的来源**:没装采集,但来源目录里有会话(例如拿别处的采集文件起服务)→ 各屏照常显示会话,总览采集卡写「未安装」;不出开始使用卡。
- **错误柱同时 compaction**:× 与「压缩」可并存(失败优先占视觉,「压缩」仍标)。
- **超长 + 多 subagent**:两态叠加时组轨折叠优先,避免道区被 fan-out 淹没。
- **主题切换瞬时(MUST)**:切换器(设置 · 外观)只切 `data-theme` 属性、不重跑 render(纯样式)。偏好在首帧前读出;`localStorage` 读不到或抛错时跟随系统。守卫 `test/web-v2/theme.test.mjs`。
- **页面隐藏后回来**:轮询在页面隐藏时停,回到可见时立刻读一次;「未刷新」只按可见期间漏掉的周期算,不在回来的那一刻误报。守卫 `web/src/ui/poll.test.tsx`。
- **D40 之前的非 LLM 记录(MUST NOT 误读)**:请求只存了长度,响应常是解析后重新序列化的 JSON(当时 telemetry 的响应只是一个计数)。两侧各标各的(K-23),MUST NOT 让人误读成"看到了上报内容",也 MUST NOT 用一句话盖住两侧。要求与测试归 [2.6](2.6-detail-panel.md) §C(`test/web-v2/host-model.test.mjs`);真数据(T1)上的核对归 [1.10](1.10-traffic.md)。
- **表里没有的码**:原样放进技术细节,外面写「原因未知」;不丢,不猜。

## Risk / 回滚
状态退化与配色是**纯呈现**,不碰源真相(NDJSON)与归一化表——回滚任一态/主题只改渲染层,数据无损;换皮集中在 `css/base.css` 的 token 块,退回只换一组值。风险点:**漏标保真**(剪裁/元数据/不完整/只记日志未标)= 违反不变式 4 → 由 `state-matrix.test.mjs`、`fidelity-marks.test.mjs`、`render-verbatim.test.mjs` 兜底,回归即挡;**把不知道读成 0** → 由 `state-matrix.test.mjs` 的 K-15 / K-16 / K-24 挡;**换皮后某对颜色读不清** → 由 `contrast.test.mjs` 挡;**字号放大后回放台变挤**(步头一行、窗口占一半高、会话头不切半个字)→ 由 `replay-shots.test.mjs` 的三条挡。
